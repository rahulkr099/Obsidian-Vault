# Lesson 1.4 — ESLint, Prettier & TypeScript Code Quality

Now we'll make sure our project has **consistent, safe, and readable code** before we start adding database and authentication logic.

Think of this layer as:

```text
You write code
      ↓
TypeScript
      ↓
ESLint
      ↓
Prettier
      ↓
Clean code
```

There are three different jobs here:

|Tool|Main job|
|---|---|
|**TypeScript**|Finds type-related bugs|
|**ESLint**|Finds problematic coding patterns|
|**Prettier**|Formats code consistently|

---

# 3. Install Prettier

From the root:

```bash
cd ~/Projects/ai-lms
```

Install:

```bash
pnpm add -Dw prettier
```

`-D` means development dependency.

`-w` means install it at the workspace root.

Check:

```bash
pnpm exec prettier --version
```

---

# 4. Create Prettier Configuration

Create:

```bash
touch prettier.config.js
```

Use:

```js
export default {
  semi: true,
  singleQuote: true,
  trailingComma: 'all',
  printWidth: 100,
};
```

Our project now follows:

```text
Single quotes
Semicolons
Trailing commas
100-character line width
```

For example:

Instead of:

```ts
const user = { name: "Rahul", email: "rahul@example.com" }
```

Prettier gives:

```ts
const user = {
  name: 'Rahul',
  email: 'rahul@example.com',
};
```

# 8. Why `typescript-eslint`?

ESLint doesn't understand TypeScript-specific syntax by itself.

`typescript-eslint` provides the bridge:

```text
TypeScript
    ↓
typescript-eslint
    ↓
ESLint
```

It lets ESLint understand things like:

```ts
type User = {
  id: string;
};
```

---

# 9. Create ESLint Configuration

Create:

```bash
touch eslint.config.js
```

We'll use ESLint's modern **flat config** format.

Start with:

```js
import js from '@eslint/js';
import eslintReactHooks from 'eslint-plugin-react-hooks';
import eslintReactRefresh from 'eslint-plugin-react-refresh';
import tseslint from 'typescript-eslint';

export default tseslint.config(
  {
    ignores: ['**/dist/**', '**/build/**', '**/node_modules/**'],
  },

  js.configs.recommended,

  ...tseslint.configs.recommended,

  {
    files: ['apps/web/**/*.{ts,tsx}'],
    plugins: {
      'react-hooks': eslintReactHooks,
      'react-refresh': eslintReactRefresh,
    },
    rules: {
      ...eslintReactHooks.configs.recommended.rules,
      'react-refresh/only-export-components': 'warn',
    },
  },
);
```

This is our initial configuration.

We'll improve it as the project grows.

# 11. Fix Rather Than Disable

Suppose ESLint tells you:

```text
'foo' is assigned a value but never used
```

Don't immediately write:

```ts
// eslint-disable-next-line
```

Instead ask:

> Why is this variable here?

Delete it if unnecessary.

Use suppression only when there's a real reason.

# 13. Why TypeScript Is Not ESLint

This distinction is important.

### TypeScript

Checks:

```text
wrong types
missing properties
invalid function arguments
incorrect return types
```

Example:

```ts
const age: number = 'twenty';
```

TypeScript complains.

---

### ESLint

Checks coding patterns:

```text
unused variables
bad patterns
problematic React usage
code quality issues
```

Example:

```ts
const unusedValue = 123;
```

ESLint can complain.

---

### Prettier

Doesn't care about logic.

It simply says:

> "I'll format this code consistently."

# 18. A Better Backend TypeScript Setup

Let's make sure the backend doesn't accidentally compile things outside `src`.

Our backend:

```text
apps/api/
├── src/
└── tsconfig.json
```

Use:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"]
}
```

This means:

```text
src/
 ↓
TypeScript compiler
 ↓
dist/
```

# 22. Prettier vs ESLint

A common mistake is trying to make ESLint handle formatting.

I recommend keeping the responsibilities separate:

```text
Prettier
   ↓
Formatting

ESLint
   ↓
Code quality

TypeScript
   ↓
Type safety
```

This makes the setup easier to understand.
