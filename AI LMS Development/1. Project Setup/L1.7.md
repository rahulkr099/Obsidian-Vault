# Lesson 1.7 — Environment Configuration

Now we'll clean up one of the most important parts of the project:

> **How does our application know its environment-specific configuration without hardcoding secrets?**

Right now we have things like:

```text
DATABASE_URL
PostgreSQL credentials
API URL
JWT secrets
AI API key
Redis URL
```

We need a proper system before authentication and AI development begin.

Prisma 7 uses `prisma.config.ts` for Prisma CLI configuration, and environment variables can be loaded with `dotenv`. ([Prisma](https://docs.prisma.io/docs/orm/reference/prisma-config-reference?utm_source=chatgpt.com "Reference documentation for the prisma config file | Prisma Documentation"))

---

# 1. The Problem We're Solving

Imagine you write:

```ts
const databaseUrl =
  "postgresql://ai_lms:password@localhost:5432/ai_lms";
```

This is bad.

Why?

Because when you deploy:

```text
Development
localhost
      ↓
Production
cloud database
```

the code itself shouldn't change.

Instead:

```text
Same code
   │
   ├── Development → .env
   │
   ├── Testing     → test environment
   │
   └── Production  → deployment secrets
```

This is the basic idea behind configuration management.

---

# 2. Environment Variables

Node exposes environment variables through:

```ts
process.env
```

For example:

```ts
const port = process.env.PORT;
```

Node officially provides `process.env` for accessing environment variables, and modern Node also has built-in dotenv support. ([Node.js](https://nodejs.org/api/environment_variables.html?utm_source=chatgpt.com "Environment Variables | Node.js v26.5.1 Documentation"))

We'll still use `dotenv` explicitly because it works cleanly with our Prisma 7 setup. Prisma's documentation recommends loading `.env` with `import "dotenv/config"` in `prisma.config.ts`. ([Prisma](https://docs.prisma.io/docs/orm/reference/prisma-config-reference?utm_source=chatgpt.com "Reference documentation for the prisma config file | Prisma Documentation"))

# 6. Important Difference: `VITE_`

Vite exposes environment variables to browser code only when they use the `VITE_` prefix.

So:

```env
VITE_API_URL=...
```

can be used by React.

But:

```env

```

must **never** be placed in the frontend.

The browser should never receive:

```text

JWT_ACCESS_SECRET
JWT_REFRESH_SECRET
AI_API_KEY
```

Think:

```text
Frontend
├── VITE_API_URL       ✅
│
└── DATABASE_PASSWORD  ❌
```

# 12. Generate Strong Secrets

Don't manually invent production JWT secrets like:

```text
secret123
```

Use the terminal.

For example:

```bash
openssl rand -base64 48
```

You'll get a random value.

Use one value for:

```env

```

Generate another:

```bash

```

for:

```env

```

For development this is already a much better habit.

# 14. First Version of `env.ts`

```ts
import 'dotenv/config';

const requiredEnv = (name: string): string => {
  const value = process.env[name];

  if (!value) {
    throw new Error(`Missing required environment variable: ${name}`);
  }

  return value;
};

export const env = {
  NODE_ENV: process.env.NODE_ENV ?? 'development',

  PORT: Number(process.env.PORT ?? 4000),

  DATABASE_URL: requiredEnv('DATABASE_URL'),

  JWT_ACCESS_SECRET: requiredEnv('JWT_ACCESS_SECRET'),

  JWT_REFRESH_SECRET: requiredEnv('JWT_REFRESH_SECRET'),

  CORS_ORIGIN: process.env.CORS_ORIGIN ?? 'http://localhost:5173',

  REDIS_URL: process.env.REDIS_URL ?? '',

  AI_API_KEY: process.env.AI_API_KEY ?? '',
};
```

Now we have one place responsible for environment configuration.

---

# 15. Why `requiredEnv()`?

Suppose you accidentally deploy without:

```text
DATABASE_URL
```

Without validation, you might get a confusing error somewhere deep inside Prisma.

Instead:

```text
Application starts
       ↓
env.ts
       ↓
DATABASE_URL missing
       ↓
❌ Fail immediately
```

You'll see:

```text
Missing required environment variable: DATABASE_URL
```

This is called **fail-fast configuration**.

It's a very useful backend engineering practice.

# 16. Be Careful With `Number()`

We wrote:

```ts
PORT: Number(process.env.PORT ?? 4000),
```

This is fine for a first version, but:

```env
PORT=hello
```

would produce:

```text
NaN
```

We don't want that.

Let's improve it.

---

# 17. Add Number Validation

Create:

```ts
const requiredNumber = (name: string): number => {
  const value = process.env[name];

  if (!value) {
    throw new Error(`Missing required environment variable: ${name}`);
  }

  const parsed = Number(value);

  if (!Number.isInteger(parsed) || parsed <= 0) {
    throw new Error(
      `Environment variable ${name} must be a positive integer`,
    );
  }

  return parsed;
};
```

Then:

```ts
PORT: requiredNumber('PORT'),
```

Now:

```env
PORT=4000
```

works.

But:

```env
PORT=hello
```

fails immediately.

# 18. Final `env.ts`

Our current version:

```ts
import 'dotenv/config';

const requiredEnv = (name: string): string => {
  const value = process.env[name];

  if (!value) {
    throw new Error(`Missing required environment variable: ${name}`);
  }

  return value;
};

const requiredNumber = (name: string): number => {
  const value = requiredEnv(name);
  const parsed = Number(value);

  if (!Number.isInteger(parsed) || parsed <= 0) {
    throw new Error(
      `Environment variable ${name} must be a positive integer`,
    );
  }

  return parsed;
};

export const env = {
  NODE_ENV: process.env.NODE_ENV ?? 'development',

  PORT: requiredNumber('PORT'),

  DATABASE_URL: requiredEnv('DATABASE_URL'),

  JWT_ACCESS_SECRET: requiredEnv('JWT_ACCESS_SECRET'),

  JWT_REFRESH_SECRET: requiredEnv('JWT_REFRESH_SECRET'),

  CORS_ORIGIN: process.env.CORS_ORIGIN ?? 'http://localhost:5173',

  REDIS_URL: process.env.REDIS_URL ?? '',

  AI_API_KEY: process.env.AI_API_KEY ?? '',
};
```

This is already much safer than scattering `process.env` throughout the backend.

# 22. Prisma's `env()` vs Our `env.ts`

Don't confuse these two.

### Prisma:

```ts
env('DATABASE_URL')
```

comes from:

```ts
import { env } from 'prisma/config';
```

It is for Prisma's configuration.

### Our application:

```ts
env.DATABASE_URL
```

comes from:

```ts
import { env } from './config/env.js';
```

It is our application configuration object.

So:

```text
Prisma CLI
   ↓
prisma/config env()

Application
   ↓
our config/env.ts
```

# 24. Don't Print Secrets

Never do this:

```ts
console.log(process.env);
```

or:

```ts
console.log(env);
```

because your terminal/logging system could expose:

```text
DATABASE_URL
JWT_ACCESS_SECRET
AI_API_KEY
```

Instead, if debugging:

```ts
console.log({
  nodeEnv: env.NODE_ENV,
  port: env.PORT,
});
```

Only print non-sensitive information.

# 29. One Very Important Rule

Frontend environment variables are **not secrets**.

Anything like:

```env
VITE_API_URL=...
```

will eventually be available to browser code.

So:

```text
VITE_API_URL       ✅ public
VITE_APP_NAME      ✅ public
VITE_FEATURE_FLAG  ✅ public
```

but:

```text
VITE_DATABASE_PASSWORD   ❌
VITE_JWT_SECRET          ❌
VITE_AI_API_KEY          ❌
```

Never put secrets in `VITE_*`.

# 30. Docker Environment Variables

Now let's improve our `docker-compose.yml`.

Instead of:

```yaml
environment:
  POSTGRES_USER: ai_lms
  POSTGRES_PASSWORD: ai_lms_dev_password
  POSTGRES_DB: ai_lms
```

use:

```yaml
environment:
  POSTGRES_USER: ${POSTGRES_USER}
  POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
  POSTGRES_DB: ${POSTGRES_DB}
```

Then create:

```text
docker/.env
```

But there's a subtle issue.

Docker Compose automatically reads a root-level `.env` by default, and we don't want to create a confusing collection of `.env` files.

For this project, let's keep the local Compose configuration straightforward:

```text
ai-lms/
├── .env
├── docker-compose.yml
├── apps/
│   ├── api/
│   └── web/
```

However, because our backend's `.env` is currently inside `apps/api`, Compose won't automatically use those values.

So let's make a deliberate choice:

### Root `.env`

Infrastructure configuration:

```env
POSTGRES_USER=ai_lms
POSTGRES_PASSWORD=ai_lms_dev_password
POSTGRES_DB=ai_lms
```

### `apps/api/.env`

Application configuration:

```env
NODE_ENV=development
PORT=4000
DATABASE_URL="postgresql://ai_lms:ai_lms_dev_password@localhost:5432/ai_lms?schema=public"
...
```

This is a little repetitive, but it's explicit and easy to understand for a learning project.

# 🧠 The Main Lesson

The most important concept today is:

```text
                    Configuration
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
           Docker     Backend    Frontend
              │          │          │
              ▼          ▼          ▼
          PostgreSQL   env.ts     env.ts
```

And remember this rule:

> **Code should describe how the application works. Environment variables should describe where and with what configuration it runs.**

That separation will make deployment dramatically easier later.
