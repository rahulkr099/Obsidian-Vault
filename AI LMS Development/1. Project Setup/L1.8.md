                       │ HTTP

```text

   ↓

```

```http

```

Then:

```text
Express
   ↓
Route
   ↓
Controller
   ↓
Service
   ↓
Prisma
   ↓
PostgreSQL
```

PostgreSQL returns:

```text
courses
```

Then the response travels back:

```text
PostgreSQL
   ↓
Prisma
   ↓
Service
   ↓
Controller
   ↓
Express
   ↓
React
   ↓
Browser
```

This is the architecture you should start thinking in.

# 3. Repository Layer

Create:

```bash
touch src/modules/courses/course.repository.ts
```

Add:

```ts
import { prisma } from '../../config/prisma.js';

export const courseRepository = {
  findAll() {
    return prisma.course.findMany({
      orderBy: {
        createdAt: 'desc',
      },
    });
  },

  count() {
    return prisma.course.count();
  },
};
```

The repository's job is:

> **Talk to the database.**

It shouldn't know anything about HTTP.

So this is good:

```text
Repository
   ↓
Prisma
   ↓
PostgreSQL
```

But this would be bad:

```ts
res.json(...)
```

inside the repository.

The repository should never know what an HTTP response is.

# 5. Controller Layer

Create:

```bash
touch src/modules/courses/course.controller.ts
```

Add:

```ts
import type { Request, Response } from 'express';

import { courseService } from './course.service.js';

export const courseController = {
  async getCourses(_req: Request, res: Response) {
    const courses = await courseService.getCourses();

    res.json({
      success: true,
      data: courses,
    });
  },

  async getCourseCount(_req: Request, res: Response) {
    const count = await courseService.getCourseCount();

    res.json({
      success: true,
      data: {
        count,
      },
    });
  },
};
```

The controller handles:

```text
HTTP
 ↓
Service
 ↓
HTTP response
```

That's it.

# 19. Create a Course Page

Create:

```bash
mkdir -p src/pages
touch src/pages/CoursesPage.tsx
```

Add:

```tsx
import { useEffect, useState } from 'react';

import {
  courseService,
  type Course,
} from '../services/course.service';

function CoursesPage() {
  const [courses, setCourses] = useState<Course[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const loadCourses = async () => {
      try {
        const response = await courseService.getCourses();

        setCourses(response.data);
      } catch {
        setError('Failed to load courses');
      } finally {
        setLoading(false);
      }
    };

    loadCourses();
  }, []);

  if (loading) {
    return <p>Loading courses...</p>;
  }

  if (error) {
    return <p>{error}</p>;
  }

  return (
    <section className="mx-auto max-w-6xl px-6 py-12">
      <h1 className="text-3xl font-bold">Courses</h1>

      <div className="mt-8 grid gap-6 md:grid-cols-2 lg:grid-cols-3">
        {courses.map((course) => (
          <article
            key={course.id}
            className="rounded-xl border border-slate-800 p-6"
          >
            <h2 className="text-xl font-semibold">{course.title}</h2>

            <p className="mt-3 text-slate-400">
              {course.description}
            </p>
          </article>
        ))}
      </div>
    </section>
  );
}

export default CoursesPage;
```

# 28. One Problem With Our Current Frontend

We currently have:

```tsx

```

for fetching server data.

This works.

But imagine we eventually have:

```text

Lessons

```

You would end up writing lots of:

```tsx

```

manually.

That's why we're going to introduce **TanStack Query** later.

Our eventual flow will be:

```text

   ↓

   ↓

   ↓
Backend
```

TanStack Query will handle:

```text

```

We'll do this during the frontend foundation phase.

# 29. Another Important Problem

Our API currently returns the entire Prisma course object.

That's okay for a demo.

But eventually we should **not blindly return database records**.

For example:

```text
Prisma model
       ↓
Database object
       ↓
API response
```

Instead:

```text
Database
   ↓
Repository
   ↓
Service
   ↓
DTO / Response mapper
   ↓
API
```

Why?

Because your database might contain:

```text
internal fields
private fields
security information
relationships
timestamps
```

that the client shouldn't see.

We'll introduce DTOs/response schemas during the backend foundation phase.

# 30. Another Important Problem: Error Handling

Currently:

```ts
async getCourses() {
  return courseRepository.findAll();
}
```

If Prisma throws an error:

```text
PostgreSQL error
     ↓
Prisma error
     ↓
Service
     ↓
Controller
```

our current controller doesn't properly handle it.

Later we'll use:

```text
asyncHandler
       +
AppError
       +
global error handler
```

so errors become predictable:

```json
{
  "success": false,
  "error": {
    "code": "DATABASE_ERROR",
    "message": "..."
  }
}
```

This will be part of **Phase 2**.
