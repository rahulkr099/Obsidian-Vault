# Lesson 10.10 — Quiz & Assessment UI

Now we connect the **Phase 9 Assessment Engine** with the React + TypeScript frontend.

We've built:

```text
10.8 → Course Builder
10.9 → Course Player
```

Now:

```text
10.10 → Quiz & Assessment UI
```

The important idea is:

> **Phase 9 owns the assessment logic. Phase 10 builds the student-facing React experience for using it.**

So we should **not create another assessment engine** here.

The flow becomes:

```text
Course Player
     ↓

     ↓
Quiz UI
     ↓
Assessment API
     ↓
Attempt
     ↓
Questions
     ↓
Answers
     ↓

     ↓

     ↓
Results
```

# 5. Assessment Types

We should define the frontend types based on the Phase 9 API contract.

For example:

```ts
export type QuestionType =
  | "single_choice"
  | "multiple_choice"
  | "true_false"
  | "short_answer";
```

Then:

```ts
export interface Quiz {
  id: string;
  title: string;
  description?: string;
  totalQuestions: number;
  timeLimit?: number;
  passingScore?: number;
}
```

A question:

```ts
export interface QuizQuestion {
  id: string;
  type: QuestionType;
  question: string;
  options?: QuizOption[];
  points: number;
}
```

Option:

```ts
export interface QuizOption {
  id: string;
  text: string;
}
```

# 6. Important: Don't Put Correct Answers in the Client

This is a major security rule.

The API should **not** send:

```json
{
  "question": "What is React?",
  "correctAnswer": "A"
}
```

to the browser before the student submits.

Otherwise:

```text
Browser
 ↓
DevTools
 ↓
Network response
 ↓
Correct answers
```

Game over. 😄

The frontend should receive:

```json
{
  "id": "q1",
  "question": "What is React?",
  "options": [
    {
      "id": "a",
      "text": "A JavaScript library"
    },
    {
      "id": "b",
      "text": "A database"
    }
  ]
}
```

The backend owns the correct answer.

# 17. Answer State

The student might answer:

```text
Question 1 → A
Question 2 → C
Question 3 → A,B
Question 4 → unanswered
```

Represent it cleanly:

```ts
type AnswerValue =
  | string
  | string[]
  | null;

interface AnswerState {
  [questionId: string]: AnswerValue;
}
```

Then:

```text
answers
│
├── q1 → "a"
├── q2 → "c"
├── q3 → ["a", "b"]
└── q4 → null
```

# 19. Autosave Answers

For a serious LMS, answer persistence matters.

Imagine:

```text
Student answers 8 questions
 ↓
Browser crashes
```

We don't want:

```text
Everything lost.
```

Instead:

```text
Answer selected
 ↓
Local state
 ↓
Debounced mutation
 ↓
Backend saves answer
```

For example:

```text
Question 1
Answer A
 ↓
save

Question 2
Answer C
 ↓
save
```

Don't call the API for every tiny UI render.

# 24. Timer

If the quiz has:

```text
timeLimit = 15 minutes
```

we display:

```text
14:59
```

The timer should be based on the **server attempt start/deadline**, not simply:

```ts
let remaining = 15 * 60;
```

Why?

Because the student can:

```text
refresh
close browser
change tabs
reopen
```

The backend should remain authoritative.

---

# 25. Timer Architecture

Backend:

```text
attemptStartedAt
attemptDeadline
```

Frontend:

```text
server deadline
      ↓
local countdown
```

For example:

```ts
const remaining =
  attemptDeadline - Date.now();
```

But account for server/client clock differences appropriately.

The frontend timer is primarily a display.

The backend must enforce the deadline.

# 27. Prevent Timer Cheating

Don't rely on:

```text
setInterval(() => {
  seconds--;
}, 1000);
```

as the source of truth.

A student can manipulate browser JavaScript.

Instead:

```text
Backend deadline
      ↓
Frontend display
      ↓
Backend validates submission time
```

This is another example of:

> **The client is not trusted.**

# 29. Don't Calculate the Score in React

Avoid:

```ts

  correctAnswers / totalQuestions * 100;
```

The browser doesn't own:

```text

grading rules
negative marking
partial credit
passing rules
```

Phase 9's assessment engine owns that.

React displays the result returned by the backend.

```text

             ┌─────────┼─────────┐

                  ↓              ↓
                Active        Submitting
                  │              │

                  ↓              │

                  │

```

This state-machine thinking becomes extremely useful for complex UI.

# 48. Don't Make the Quiz UI Too Fancy

A quiz is a concentration environment.

Avoid:

```text
❌ excessive animations
❌ distracting gradients
❌ giant illustrations
❌ unnecessary popups
❌ aggressive sounds
```

Focus on:

```text
✓ readability
✓ clear progress
✓ obvious answers
✓ reliable saving
✓ clear timer
✓ easy navigation
```
