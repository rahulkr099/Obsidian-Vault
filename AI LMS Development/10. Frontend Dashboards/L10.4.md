# Lesson 10.4 — Design System & Reusable Components

Now we move from **authentication architecture** into something you'll use throughout the entire frontend:

> **A reusable UI system for the AI LMS.**

If we don't do this properly, by the time we reach the student dashboard, instructor dashboard, admin dashboard, quizzes, and AI tutor, we'll have dozens of slightly different buttons, cards, inputs, modals, and tables.

Our goal is:

```text
One component
     ↓
Reusable everywhere
     ↓
Consistent UI
     ↓
Easier maintenance
     ↓
Faster development
```

Your uploaded source already has a `common` component area containing reusable pieces such as `Navbar`, `Footer`, `IconBtn`, `RatingStars`, `ConfirmationModal`, and tab-related components.

We'll take that idea further and create a proper **TypeScript design system**.

# 5. First Rule — Components Need Contracts

Since we're using TypeScript, every reusable component should have a clear contract.

For example:

```tsx
interface ButtonProps {
  children: React.ReactNode;
  variant?: "primary" | "secondary" | "danger";
  disabled?: boolean;
  loading?: boolean;
  onClick?: () => void;
}
```

This tells us:

```text
Button
├── children       required
├── variant        optional
├── disabled       optional
├── loading        optional
└── onClick        optional
```

That's much better than:

```tsx
function Button(props: any)
```

---

# 6. Building Our Button

Create:

```text
src/components/ui/Button.tsx
```

A basic implementation:

```tsx
import type { ButtonHTMLAttributes } from "react";

type ButtonVariant =
  | "primary"
  | "secondary"
  | "danger"
  | "ghost";

interface ButtonProps
  extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: ButtonVariant;
  loading?: boolean;
}

export function Button({
  children,
  variant = "primary",
  loading = false,
  disabled,
  ...props
}: ButtonProps) {
  return (
    <button
      disabled={disabled || loading}
      {...props}
    >
      {loading ? "Loading..." : children}
    </button>
  );
}
```

Notice something important:

```tsx
extends ButtonHTMLAttributes<HTMLButtonElement>
```

This means our component can still accept normal button properties:

```tsx
type
disabled
aria-label
name
value
onClick
```

That's a powerful TypeScript pattern for reusable components.

---

# 7. Why Not Create Every Prop Manually?

We could write:

```tsx
interface ButtonProps {
  children: React.ReactNode;
  onClick?: () => void;
  disabled?: boolean;
  type?: string;
}
```

But then we'd have to manually add every HTML button property.

Instead:

```tsx
ButtonHTMLAttributes<HTMLButtonElement>
```

gives us the standard button API.

This is a pattern you'll use frequently in professional React + TypeScript projects.

# 10. Input Component

Create:

```text
Input.tsx
```

Use native input attributes:

```tsx
import type {
  InputHTMLAttributes,
} from "react";

interface InputProps
  extends InputHTMLAttributes<HTMLInputElement> {
  label?: string;
  error?: string;
}

export function Input({
  label,
  error,
  ...props
}: InputProps) {
  return (
    <div>
      {label && (
        <label>
          {label}
        </label>
      )}

      <input {...props} />

      {error && (
        <p>{error}</p>
      )}
    </div>
  );
}
```

Now:

```tsx
<Input
  label="Email"
  type="email"
  placeholder="Enter your email"
/>
```

And:

```tsx
<Input
  label="Course Title"
  error="Title is required"
/>
```

# 15. Card Composition

Instead of making one giant Card component with 50 props, we can eventually support:

```text

├── CardHeader
├── CardContent
└── CardFooter
```


# 16. Why Composition Is Better

Avoid:

```tsx

  title="Course Progress"
  description="..."
  footer="..."
  showButton
  buttonText="Continue"
  ...
/>
```

That component becomes difficult to maintain.

Instead:

```tsx
<Card>
  <CardHeader>
    ...
  </CardHeader>

  <CardContent>
    ...
  </CardContent>
</Card>
```

React is very good at composition.

Use it.

# 42. `cn()` Utility

When using Tailwind heavily, conditional classes become annoying.

We'll create:

```text
src/utils/cn.ts
```

Conceptually:

```ts
export function cn(
  ...classes: Array<
    string | false | null | undefined
  >
) {
  return classes
    .filter(Boolean)
    .join(" ");
}
```

Then:

```tsx
<div
  className={cn(
    "rounded-lg",
    isActive && "border-primary"
  )}
/>
```

Later we can use a more robust class-merging utility if needed.

# 🧠 Lesson 10.4 — Key Takeaways

Remember these five ideas:

```text
1. Build reusable primitives.

2. Use TypeScript to define component contracts.

3. Prefer composition over giant components.

4. Separate UI components from feature components.

5. Design components around real states:
   loading, error, empty, disabled, active, etc.
```

The most important architecture is:

```text
             PAGE
               ↓
           FEATURE
           COMPONENT
               ↓
          COMMON COMPONENT
               ↓
             UI
               ↓
         Design Tokens
```

For example:

```text
StudentDashboard
      ↓
CourseCard
      ↓
Card + Badge + Avatar + Button
```

That's the foundation that will let us build the rest of the AI LMS without turning the React codebase into a collection of duplicated UI.
