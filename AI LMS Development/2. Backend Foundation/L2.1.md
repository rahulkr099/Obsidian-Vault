# 📚 Phase 2 Roadmap

I'm keeping the number of lessons relatively short, as we did in the earlier backend lessons.

## Module 2.1 — API & Error Architecture

### Lesson 2.1 — Standard API Response

We'll establish a consistent response format:

```json
{
  "success": true,
  "data": {}
}
```

and:

```json
{
  "success": false,
  "error": {
    "code": "COURSE_NOT_FOUND",
    "message": "Course not found"
  }
}
```

You'll learn:

- API response conventions
    
- success responses
    
- error responses
    
- HTTP status codes
    
- why consistency matters
    

---

### Lesson 2.2 — AppError + Global Error Handler

We'll create:

```text
src/
└── errors/
    ├── AppError.ts
    └── errorHandler.ts
```

Instead of:

```ts
throw new Error('Course not found');
```

we'll eventually do:

```ts
throw new AppError(
  'Course not found',
  404,
  'COURSE_NOT_FOUND',
);
```

Then:

```text
Controller
    ↓
Service
    ↓
AppError
    ↓
Global Error Handler
    ↓
HTTP Response
```

This is one of the most important backend patterns in the project.

---

### Lesson 2.3 — Async Handler + Thin Controllers

We'll remove repetitive:

```ts
try {
  ...
} catch (error) {
  next(error);
}
```

from every controller.

We'll build:

```text
asyncHandler()
```

and make controllers remain small:

```ts
export const getCourse = asyncHandler(async (req, res) => {
  const course = await courseService.getCourse(req.params.id);

  res.json({
    success: true,
    data: course,
  });
});
```

# Module 2.4 — Observability

We'll add structured logging.

Instead of:


```text

   ↓

   ↓
```

### Lesson 2.9 — Pagination, Filtering & Sorting

This becomes important very quickly.

Bad:

```http
GET /courses
```

returning:

```text
50,000 courses
```

Instead:

```http
GET /api/v1/courses?page=1&limit=20
```

We'll implement:

```text
Pagination
Filtering
Sorting
Searching
```

For example:

```http
GET /api/v1/courses
    ?page=2
    &limit=20
    &level=BEGINNER
    &sort=createdAt
    &order=desc
```

And return metadata:

```json
{
  "success": true,
  "data": [],
  "meta": {
    "page": 2,
    "limit": 20,
    "total": 145,
    "totalPages": 8
  }
}
```

# Module 2.7 — Abuse Protection

### Lesson 2.11 — Rate Limiting

We'll add rate limits based on endpoint sensitivity.

For example:

```text
Normal API
    ↓
100 requests / minute
```

Authentication:

```text
/login
    ↓
much stricter
```

AI:

```text
/ai/chat
    ↓
special limits
    ↓
because AI calls cost money
```

This is particularly important for our AI LMS.

An attacker shouldn't be able to do:

```text
POST /api/v1/ai/chat
POST /api/v1/ai/chat
POST /api/v1/ai/chat
...
```

and generate a huge AI bill.
