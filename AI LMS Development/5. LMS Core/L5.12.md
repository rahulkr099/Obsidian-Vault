# 5. AI Provider Abstraction

Don't scatter provider-specific code everywhere.

Bad:

```ts
const response = await openai.chat.completions.create(...);
```

inside:

```text
TutorService
QuizService
SummaryService
```

Now every service depends directly on one provider.

Instead:

```ts
interface AIProvider {
  generate(request: GenerateRequest): Promise<GenerateResponse>;

  stream(
    request: GenerateRequest
  ): AsyncIterable<GenerateChunk>;
}
```

Then:

```text
TutorService
     ↓
AIProvider
     ↓
OpenAIProvider
```

Later:

```text
AIProvider
   ├── OpenAIProvider
   ├── AnotherProvider
   └── LocalModelProvider
```

Your business logic doesn't need to change.

---

# 6. Why This Matters

Suppose tomorrow you want to change:

```text
Provider A
```

to:

```text
Provider B
```

Without abstraction:

```text
20 files
 ↓
change provider code
```

With abstraction:

```text
AIProvider
   ↓
replace implementation
```

This is classic dependency inversion.

You aren't building an AI-specific trick.

You're applying standard backend engineering.

# 8. Tutor Service

Conceptually:

```ts
async function answerQuestion(input: TutorInput) {
  const conversation =
    await conversationRepository.get(input.conversationId);

  await authorizationService.assertCanAccess(
    input.userId,
    conversation.courseId
  );

  const query =
    await queryService.prepare(input.question, conversation);

  const chunks =
    await retrievalService.retrieve({
      courseId: conversation.courseId,
      query,
    });

  const context =
    contextBuilder.build(chunks);

  const prompt =
    tutorPrompt.build({
      question: input.question,
      context,
    });

  return aiProvider.stream(prompt);
}
```

Notice what isn't here:

```text
OpenAI SDK details
SQL vector query
HTTP streaming details
```

Those belong elsewhere.

That's good architecture.

# 31. AI Provider Failure

What happens if the provider is unavailable?

Don't return:

```text

```

with no explanation.

Your service should distinguish:

```text

AI_RATE_LIMITED
AI_TIMEOUT
AI_INVALID_RESPONSE
AI_VALIDATION_FAILED
```

Then the frontend can display an appropriate message.

> "The Tutor uses course-scoped RAG and source attribution to ground responses in authorized course material."

That's technically defensible.

Similarly:

Don't say:

> "The AI understands the entire course."

Say:

> "The system retrieves semantically relevant course chunks and provides them as context to the LLM."

This precision matters in interviews.

# 48. How to Explain Your AI Architecture in an Interview

If an interviewer asks:

> **"How does your AI Tutor work?"**

You can answer:

> "The Tutor is implemented as a course-scoped RAG pipeline. When a student asks a question, the backend validates authorization and creates an embedding for the query. We search course-specific lesson chunks stored in PostgreSQL with pgvector, apply metadata and similarity filters, and select the most relevant chunks. Those chunks are passed to the LLM as untrusted reference context. The model generates a grounded response, which we stream to the client and persist along with source metadata. We also track latency, token usage, retrieval results, and prompt/model versions for evaluation and observability."

That is a **strong backend-oriented answer**.

---

# 49. How to Explain Why RAG

Interviewer:

> "Why did you use RAG instead of fine-tuning?"

Answer:

> "Course content changes frequently, so I wanted the knowledge layer to be updateable without retraining the model. With RAG, instructors can update course content, reprocess the affected chunks and embeddings, and the Tutor can retrieve the latest authorized material at runtime."

That's a very good engineering explanation.

---

# 50. How to Explain pgvector

Interviewer:

> "Why PostgreSQL with pgvector?"

Answer:

> "The LMS already uses PostgreSQL for relational data, so pgvector lets us keep course, lesson, document, and vector data in a familiar database ecosystem. It also simplifies metadata filtering and authorization because the knowledge chunks remain closely connected to relational course data."

That's a much stronger answer than:

> "Because pgvector is popular."

---

# 51. How to Explain Evaluation

Interviewer:

> "How do you know your RAG system works?"

Answer:

> "I maintain a golden evaluation dataset containing representative course questions. I evaluate retrieval separately using metrics such as Recall@5, and evaluate generated answers for correctness, relevance, and groundedness. I also track production metrics like latency, token usage, errors, and user feedback. When changing prompts, embedding models, chunking, or retrieval logic, I run the evaluation set to detect regressions."

That's real AI engineering.
