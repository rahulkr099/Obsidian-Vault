# Lesson 8.2 — Vector Search

In **8.1**, we learned:

> **Embedding = representing text as numbers so we can compare its meaning.**

Now we answer the next question:

> **How do we find the course content that is most similar to a student's question?**

That's the job of **vector search**.

---

# 1. What Is Vector Search?

Vector search means:

> Find vectors that are most similar to a given query vector.

Our basic flow is:

```text
Student Question
       ↓
   Embedding
       ↓
   Query Vector
       ↓
  Vector Search
       ↓
Most Similar Vectors
       ↓
Relevant Course Content
```

For example:

```text
Student:
"What is normalization in DBMS?"
```

becomes something like:

```text
[0.21, -0.43, 0.78, ...]
```

Our database already contains:

```text
Chunk 1 → [0.19, -0.40, 0.75, ...]
Chunk 2 → [0.82,  0.12, -0.31, ...]
Chunk 3 → [0.23, -0.38, 0.72, ...]
```

Vector search determines that:

```text
Query
  ↓
Chunk 1  ← very similar
Chunk 3  ← very similar
Chunk 2  ← not very similar
```

and returns the most relevant chunks.

---

# 2. Why Can't We Just Compare the Text?

Suppose the student asks:

```text
"What is a foreign key?"
```

The course material says:

```text
"A foreign key establishes a relationship
between records in two relational tables."
```

The exact words aren't identical.

A simple keyword search might not understand that these two sentences are strongly related.

Vector search works differently:

```text
"What is a foreign key?"
             ↓
          Vector A


"A foreign key establishes a relationship
between records in two relational tables."
             ↓
          Vector B
```

If A and B are close in vector space:

```text
Similarity(A, B) → High
```

we consider the content relevant.

---

# 3. The Vector Space Mental Model

Imagine we only had two dimensions.

```text
                Programming
                     ↑
                     |
          Python     |     JavaScript
                     |
                     |
 Database ------------+------------- Web
                     |
                     |
                  Cooking
                     ↓
```

Now imagine:

```text
"relational database"
```

and

```text
"SQL database tables"
```

are located relatively close together.

Whereas:

```text
"chocolate cake recipe"
```

would be far away.

Real embeddings don't use 2 dimensions.

They might have hundreds or thousands of dimensions.

But the idea is the same:

```text
Similar meaning
      ↓
Closer vectors
      ↓
Higher similarity
```

---

# 4. Similarity vs Distance

You'll hear two related ideas:

### Similarity

> How similar are two vectors?

Higher usually means:

```text
More relevant
```

### Distance

> How far apart are two vectors?

Lower usually means:

```text
More similar
```

So:

```text
High similarity
      ≈
Low distance
```

Don't get confused when different vector databases use different terminology.

---

# 5. Cosine Similarity

One of the most common ways to compare vectors is **cosine similarity**.

The formula is:

```text
              A · B
cos(θ) = ───────────────
         ||A|| × ||B||
```

Where:

```text
A · B
```

is the dot product.

And:

```text
||A||
```

is the magnitude/length of vector A.

You don't need to memorize the formula yet.

The important concept is:

> Cosine similarity compares the **direction** of two vectors.

---

# 6. Why "Direction"?

Imagine:

```text
A ─────────────→
B ───────→
```

They point in almost the same direction.

So they're considered similar.

But:

```text
A ─────────────→

B ←─────────────
```

They point in opposite directions.

So they're very different.

The angle between vectors is important.

```text
Small angle
    ↓
High cosine similarity

Large angle
    ↓
Low cosine similarity
```

---

# 7. Simple Cosine Similarity Example

Let's use very small vectors so we can understand the mathematics.

Suppose:

```text
A = [1, 0]
B = [1, 0]
```

They point exactly in the same direction.

Therefore:

```text
cosine similarity = 1
```

That's maximum similarity.

Now:

```text
A = [1, 0]
B = [0, 1]
```

They're perpendicular.

Their cosine similarity is:

```text
0
```

And:

```text
A = [1, 0]
B = [-1, 0]
```

They point in opposite directions.

Their cosine similarity is:

```text
-1
```

So, mathematically:

```text
-1 ───────── 0 ───────── 1
Opposite    Unrelated    Same direction
```

In many modern embedding systems, the exact range and interpretation can depend on how vectors/models are handled, so don't treat a particular numeric threshold as universal.

---

# 8. Dot Product

Another important similarity measure is the **dot product**.

For:

```text
A = [a₁, a₂, a₃]

B = [b₁, b₂, b₃]
```

the dot product is:

```text
A · B =

a₁b₁ + a₂b₂ + a₃b₃
```

Example:

```text
A = [2, 3]
B = [4, 5]
```

Then:

```text
A · B

= (2 × 4) + (3 × 5)

= 8 + 15

= 23
```

Dot product is important because vector search systems often support it as a distance/similarity operator.

---

# 9. Euclidean Distance

Another common metric is **Euclidean distance**.

Think about normal physical distance.

```text
A ●

       ● B
```

How far apart are A and B?

For two-dimensional vectors:

```text
A = (x₁, y₁)
B = (x₂, y₂)
```

the distance is:

```text
√((x₂-x₁)² + (y₂-y₁)²)
```

For example:

```text
A = (0, 0)
B = (3, 4)
```

Distance:

```text
√(3² + 4²)

= √25

= 5
```

So:

```text
Smaller distance
      ↓
More similar
```

---

# 10. The Three Metrics You Should Know

For this phase, remember these three:

|Metric|Basic idea|
|---|---|
|Cosine similarity|Compare vector direction|
|Dot product|Multiply corresponding values and sum|
|Euclidean distance|Physical/geometric distance|

Think:

```text
Cosine
   ↓
Angle / direction

Dot Product
   ↓
Vector multiplication

Euclidean
   ↓
Geometric distance
```

We'll encounter these concepts when working with PostgreSQL and pgvector.

# 11. Top-K Search

Suppose we have **10,000 course chunks**.

The student asks:

```text
"What is normalization?"
```

We don't want to send all 10,000 chunks to the LLM.

Instead:

```text
10,000 chunks
      ↓
Vector Search
      ↓
Rank by relevance
      ↓
Top 5
```

This is called **Top-K retrieval**.

If:

```text
K = 5
```

we retrieve the five best matches.

For example:

```text
Rank   Chunk                  Score
------------------------------------
1      Normalization intro    0.94
2      1NF and 2NF            0.91
3      Functional dependency  0.87
4      3NF                     0.84
5      BCNF                    0.81
```

These can then become context for the LLM.

---

# 12. Why Top-K Matters

Suppose we retrieve:

```text
Top 1
```

Maybe we don't get enough information.

If we retrieve:

```text
Top 100
```

we might give the LLM too much irrelevant information.

So there's a tradeoff:

```text
Too little context
       ↓
Missing information

Too much context
       ↓
Noise + higher cost + weaker focus
```

Therefore:

```text
Good retrieval
      =
Relevant + sufficient context
```

We'll learn how to tune this later.

---

# 13. Metadata Filtering

This is **extremely important for your LMS**.

Suppose the database contains:

```text
Course A
 ├── Lesson 1
 ├── Lesson 2
 └── Lesson 3

Course B
 ├── Lesson 1
 ├── Lesson 2
 └── Lesson 3
```

A student is currently studying:

```text
Course A
```

They ask:

```text
"What is normalization?"
```

We don't want the system to retrieve:

```text
Course B → Normalization
```

if the student doesn't have access to that content.

So we can combine:

```text
Metadata filtering
+
Vector similarity
```

Conceptually:

```text
Search vectors WHERE:

courseId = currentCourseId

AND

vector is similar to query
```

This gives us **scoped semantic search**.

---

# 14. Course-Level Filtering

Our eventual query might conceptually look like:

```text
Course:
Database Management System

Question:
"What is normalization?"
```

First:

```text
Filter:
courseId = 123
```

Then:

```text
Vector similarity
```

Then:

```text
Top-K
```

So:

```text
All LMS Content
      ↓
Course Filter
      ↓
Relevant Vectors
      ↓
Similarity Ranking
      ↓
Top-K
```

This is much better than searching the entire database blindly.

# 15. Lesson-Level Filtering

We can go even deeper.

Suppose the student is inside:

```text

```

We could search:

```text
courseId = 123

```

Then:


So our retrieval hierarchy becomes:

```text
All LMS
   ↓

   ↓

   ↓
```

This will be especially useful for your **lesson-aware AI Tutor**.

Let's imagine we have:

```text
Chunk 1:
"Normalization reduces redundancy..."

Chunk 2:
"Primary keys uniquely identify rows..."

Chunk 3:
"Foreign keys establish relationships..."

Chunk 4:
"JavaScript functions accept parameters..."
```

Each chunk has an embedding.

```text
Chunk 1 → Vector 1
Chunk 2 → Vector 2
Chunk 3 → Vector 3
Chunk 4 → Vector 4
```

Student asks:

```text
"Why do databases use normalization?"
```

We create:

```text
Question
   ↓
Query Embedding
   ↓

```

Then:

```text
Query Vector
      │
      ├── compare → Vector 1 → 0.94
      ├── compare → Vector 2 → 0.61
      ├── compare → Vector 3 → 0.55
      └── compare → Vector 4 → 0.12
```

Result:


# 17. Similarity Scores Are Not Universal "Truth"

This is an important professional habit.

Suppose you see:

```text
0.92
```

Don't automatically assume:

```text
92% semantic correctness
```

That's not what the score necessarily means.

A similarity score is primarily useful for:

```text
Ranking candidates
```

and sometimes:

```text
Filtering candidates
```

The meaning of a specific score depends on:

- embedding model
    
- similarity metric
    
- normalization
    
- dataset
    
- query type
    
- retrieval setup
    

So don't blindly write:

```text
if score > 0.80:
    definitely relevant
```

without evaluating your actual system.

---

# 18. Similarity Threshold

Sometimes Top-K isn't enough.

Suppose the user asks:

```text
"What is quantum entanglement?"
```

but our LMS only contains:

```text
DBMS
Operating Systems
JavaScript
Computer Networks
```

The search might still return _something_ because something will usually be more similar than everything else.

That doesn't mean it's relevant.

So we can introduce a threshold:

```text
Query
 ↓
Vector Search
 ↓
Similarity score
 ↓
Is it relevant enough?
```

Conceptually:

```text
Score ≥ threshold
     ↓
Use result

Score < threshold
     ↓
Treat as insufficient retrieval
```

But again, the threshold must be evaluated experimentally.

---

# 19. Retrieval Failure

This is a major RAG design issue.

Imagine:

```text
Student:
"Explain quantum entanglement."
```

Your LMS contains no information about it.

A bad RAG system might retrieve unrelated content and confidently answer.

A better system can recognize:

```text
No sufficiently relevant content found.
```

Then the AI might respond:

```text
"I couldn't find this topic in your course
material. I can still explain the general
concept if you'd like."
```

That is much safer than pretending the course contains information it doesn't.

---

# 20. Vector Search Is Not RAG

This distinction is very important.

### Vector Search

```text
Question
   ↓
Embedding
   ↓
Search
   ↓
Relevant chunks
```

### RAG

```text
Question
   ↓
Embedding
   ↓
Vector Search
   ↓
Relevant chunks
   ↓
Context construction
   ↓
LLM
   ↓
Generated answer
```

So:

```text
Vector Search
      ↓
is one important component of
      ↓
RAG
```

RAG is the larger architecture.

---

# 21. Vector Search vs Normal Database Search

Your PostgreSQL database can already perform queries such as:

```sql
SELECT *
FROM lessons
WHERE title ILIKE '%normalization%';
```

That's keyword/text matching.

Vector search is different:

```text
Query
 ↓
Embedding
 ↓
Vector similarity
 ↓
Relevant semantic content
```

A mature search system can eventually combine both.

For example:

```text
Keyword Search
      +
Vector Search
      ↓
Hybrid Search
```

We'll discuss hybrid retrieval more as your RAG architecture develops.

# 25. Important Interview Question

### "Why use vector search instead of keyword search?"

A good answer:

> Vector search represents both the query and stored content as embeddings and retrieves content based on semantic similarity. This allows the system to find relevant information even when the query and document don't use the exact same words.

For example:

```text
Query:
"How do I reduce duplicate data?"

Document:
"Normalization reduces data redundancy."
```

Keyword matching may struggle.

Semantic retrieval can recognize the relationship.

---

# 26. Another Interview Question

### "What is Top-K retrieval?"

Answer:

> Top-K retrieval means selecting the K highest-ranked results from a similarity search.

For example:

```text
K = 5
```

means:

```text
Return the 5 most relevant chunks.
```

---

# 27. Another Important Question

### "Why combine metadata filtering with vector search?"

Because vector similarity alone doesn't understand application-level permissions or context.

For your LMS:

```text
Vector similarity
       +
courseId filter
       +
lessonId filter
       +
access control
```

can ensure that retrieval stays relevant and within the student's allowed context.

This becomes particularly important for **multi-course and multi-user systems**.

# 🧠 Lesson 8.2 Cheat Sheet

```text
Vector Search
→ Finds vectors similar to a query vector.

Cosine Similarity
→ Compares the direction/angle between vectors.

Dot Product
→ Multiplies corresponding vector values and sums them.

Euclidean Distance
→ Measures geometric distance between vectors.

Top-K
→ Returns the K highest-ranked results.

Similarity Threshold
→ Helps reject results that aren't relevant enough.

Metadata Filtering
→ Restricts retrieval using fields such as courseId/lessonId.

Semantic Search
→ Search based on meaning rather than exact keywords.

Vector Search ≠ RAG
→ Vector search is one component of a larger RAG pipeline.
```

The core idea to remember is:

```text
                 STUDENT QUESTION
                        ↓
                  Query Embedding
                        ↓
                   Query Vector
                        ↓
             ┌─────────────────────┐
             │   Vector Search     │

             │        ↓            │
             │ Similarity          │
             │        ↓            │

             │        ↓            │
             │ Top-K               │
```
