# Lesson 0.5 — API Design

Now we connect our **database design** to the application.

Our API will be the communication layer between:

```text
React Frontend
      │
      │ HTTP / JSON
      ▼
┌──────────────────┐
│   REST API       │
│  Express + TS    │
└────────┬─────────┘
         │
         ▼
     Services
         │
         ▼
    PostgreSQL
```

We'll use:

- REST
    
- JSON
    
- HTTP methods
    
- `/api/v1` versioning
    
- consistent response formats
    
- authentication
    
- RBAC
    
- pagination
    
- filtering
    
- validation
    
- centralized errors
    

---

# 1. API Versioning

Our API starts with:

```text
 /api/v1
```

So instead of:

```http
GET /courses
```

we use:

```http
GET /api/v1/courses
```

Why?

Because eventually we may need:

```text
 /api/v1/courses
 /api/v2/courses
```

without immediately breaking older clients.

For a college project this may look like a small detail, but it's a good professional habit.

# 3. HTTP Methods

We'll follow normal REST conventions.

|Method|Purpose|
|---|---|
|`GET`|Read|
|`POST`|Create|
|`PATCH`|Partially update|
|`PUT`|Replace|
|`DELETE`|Delete|

For our LMS, we'll mostly use:

```text
GET
POST
PATCH
DELETE
```

We don't need `PUT` everywhere.

# 4. Authentication API

### Register

```http
POST /api/v1/auth/register
```

Request:

```json
{
  "name": "Rahul",
  "email": "rahul@example.com",
  "password": "********"
}
```

Response:

```json
{
  "success": true,
  "data": {
    "user": {
      "id": "123",
      "name": "Rahul",
      "email": "rahul@example.com",
      "role": "STUDENT"
    }
  }
}
```

Don't return:

```text
password
passwordHash
```

ever.

# 10. Create Course

```http

```

```json
  "description": "Learn backend development...",
  "categoryId": "cat_123",
  "level": "INTERMEDIATE"

```

Authorization:

```text

     ↓
INSTRUCTOR or ADMIN?
     ↓
Create
```

Student:

```text
POST /courses
       ↓

```

---

# 11. Update Course

```http
PATCH /api/v1/courses/:courseId
```

Example:

```http
PATCH /api/v1/courses/123
```

Important:

```text
Instructor
   ↓
Does course 123 belong to this instructor?
   │
   ├── Yes → allow
   └── No  → 403
```

Admin can update any course according to our permissions.

---

# 12. Delete / Archive Course

Instead of immediately destroying a course:

```http
DELETE /api/v1/courses/:courseId
```

we can internally archive it:

```text
status = ARCHIVED
```

This protects historical data.

We can later decide whether certain admin-only operations should actually hard-delete records.

```text

   ↓

   ↓
```

```text
   ↓

   ↓

   ↓
```

# 30. API Response Format

We should keep responses consistent.

### Success

```json
{
  "success": true,
  "data": {}
}
```

### Error

```json
{
  "success": false,
  "error": {
    "code": "COURSE_NOT_FOUND",
    "message": "Course not found"
  }
}
```

This is much cleaner than every controller returning a different format.

# 31. Pagination

Don't return 10,000 courses:

```http
GET /api/v1/courses
```

Instead:

```http
GET /api/v1/courses?page=1&limit=12
```

Response:

```json
{
  "success": true,
  "data": [],
  "pagination": {
    "page": 1,
    "limit": 12,
    "total": 87,
    "totalPages": 8
  }
}
```

We'll eventually implement pagination in a reusable way.

# 33. HTTP Status Codes

Learn these properly.

### `200 OK`

Successful GET/PATCH.

### `201 Created`

Successfully created:

```http
POST /courses
```

### `204 No Content`

Useful when there's no response body.

### `400 Bad Request`

Malformed request.

### `401 Unauthorized`

User is not authenticated.

Example:

```text
No valid access token
```

### `403 Forbidden`

User is authenticated but doesn't have permission.

Example:

```text
Student → create course
```

### `404 Not Found`

Resource doesn't exist.

### `409 Conflict`

Example:

```text
Already enrolled
```

### `422 Unprocessable Entity`

Can be used for semantically invalid input depending on your API convention.

### `429 Too Many Requests`

Rate limit exceeded.

### `500 Internal Server Error`

Unexpected server error.

---

# 34. One Important Distinction

This is commonly asked in interviews:

### 401

> **Who are you?**

```text
Not authenticated.
```

### 403

> **I know who you are, but you aren't allowed to do this.**

```text
Authenticated but unauthorized.
```

Example:

```text
Student
   ↓
POST /courses
   ↓
403 Forbidden
```

But:

```text
No token
   ↓
POST /courses
   ↓
401 Unauthorized
```

Remember this.
