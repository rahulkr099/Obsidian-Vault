# 6. Install Tailwind CSS

Now we'll add Tailwind.

From:

```text
apps/web
```

install:

```bash
pnpm add tailwindcss @tailwindcss/vite
```

Then configure the Vite plugin in:

```text
apps/web/vite.config.ts
```

Conceptually:

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});
```

Then in your main CSS file:

```css
@import "tailwindcss";
```

For example:

```text
src/index.css
```

can become:

```css
@import "tailwindcss";

* {
  box-sizing: border-box;
}

html,
body,
#root {
  min-height: 100%;
}

body {
  margin: 0;
}
```

This uses the current Tailwind setup rather than the older Tailwind v3 configuration style.

### `components/`

```text

├── layout/

```

Examples:

```text

```

### `features/`

Business features.

This is probably the **most important frontend directory**.

```text

├── auth/
├── courses/
├── learning/
├── progress/
├── quizzes/
```

### `hooks/`

### `lib/`

Configured external libraries.

For example:

```text

├── axios.ts

```

### `pages/`

Route-level pages.

Eventually:

```text

├── LoginPage.tsx
```

For example:

```text
├── auth.service.ts
├── course.service.ts
└── ai.service.ts
```

Although as the project grows, we'll probably keep much of the feature-specific API code inside `features/`.

---

### `types/`

Shared frontend-only types.

For example:

```text

```

Later, some types can come from our shared workspace package.

---

### `utils/`

Small generic helpers.

Examples:

```text

```

Don't turn this into a "miscellaneous everything" folder.

# 14. TypeScript Configuration

Vite already gives us TypeScript.

Check:

```bash
cat apps/web/tsconfig.app.json
```

Our goal is to keep TypeScript reasonably strict.

Eventually we want:

```json
{
  "compilerOptions": {
    "strict": true
  }
}
```

Why?

Because we want TypeScript to catch things like:

```ts
const userId: string = undefined;
```

before they become runtime bugs.

---

# 15. Don't Use `any` Everywhere

Avoid:

```ts
const user: any = ...
```

Prefer:

```ts
type User = {
  id: string;
  name: string;
  email: string;
  role: "STUDENT" | "INSTRUCTOR" | "ADMIN";
};
```

Later:

```ts
const user: User = ...
```

This is one of the reasons we're using TypeScript instead of plain JavaScript.

---

# 16. Environment Variables

Eventually our frontend needs:

```text
VITE_API_URL
```

For example:

```env
VITE_API_URL=http://localhost:4000/api/v1
```

Notice the `VITE_` prefix.

Vite exposes only variables intended for the client through that prefix.

### Important:

Never put secrets here.

Bad:

```env
VITE_AI_API_KEY=secret
```

The browser can access `VITE_*` values.

Our AI API key belongs on the **backend**.

# 17. Frontend API Architecture

Eventually:

```text
React Component
      ↓
Feature Hook
      ↓
API Service
      ↓
Axios
      ↓
Express API
```

For example:

```text
CoursePage
    ↓
useCourse()
    ↓
courseService.getCourse()
    ↓
GET /api/v1/courses/:id
```

This keeps API calls out of random components.

# 19. Zustand

Similarly, we don't need to install Zustand today.

```text

```

```text

    ↓

    ↓
```
