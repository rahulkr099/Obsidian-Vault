# 8. CourseCard Shouldn't Fetch Data

This is important.

Don't do:

```tsx
<CourseCard courseId="123" />
```

and then make `CourseCard` call the API.

Instead:

```tsx
<CourseCard course={course} />
```

The parent owns the data.

Why?

Because then:

```text
CourseCard
```

is reusable.

It doesn't care whether the course came from:

```text
Home
Catalog
Search
Student Dashboard
Wishlist
```

# 14. Debounced Search

We don't want this:

```text
r → API
re → API
rea → API
reac → API
react → API
```

That's five requests.

Instead:

```text
User typing
     ↓
Wait 300–500ms
     ↓
Search API
```

This is called **debouncing**.

We'll use the `useDebounce` hook from our architecture.

Conceptually:

```tsx
const debouncedSearch =
  useDebounce(search, 400);
```

Then:

```text
search
 ↓
debounce
 ↓
API
```

This is a small optimization that makes the catalog feel much better.

# 34. Query Parameters

A URL such as:

```text
/courses?search=react&level=beginner&page=2
```

is valuable because the state is represented in the URL.

That means:

```text
User searches
   ↓
URL changes
   ↓
Refresh
   ↓
Search still exists
```

It also allows users to share a filtered catalog URL.

We'll use React Router's search parameter tools:

```tsx
useSearchParams()
```

Conceptually:

```tsx
const [searchParams, setSearchParams] =
  useSearchParams();
```

Then:

```tsx
searchParams.get("search");
```

# 37. Course API Service

Create:

```text
src/services/course.service.ts
```

Conceptually:

```ts
interface GetCoursesParams {
  search?: string;
  category?: string;
  level?: CourseLevel;
  page?: number;
  limit?: number;
  sort?: string;
}

export const courseService = {
  async getCourses(
    params: GetCoursesParams
  ) {
    const response = await api.get(
      "/courses",
      { params }
    );

    return response.data;
  },

  async getCourse(courseId: string) {
    const response = await api.get(
      `/courses/${courseId}`
    );

    return response.data;
  },
};
```

Now the page doesn't care how Axios works.

```ts
  },
};
```

The important part is that the UI uses:

```text
Course type
     ↓
CourseCard
     ↓
CourseGrid
```

instead of random untyped objects.

# 🧠 Lesson 10.5 Takeaways

The important concepts from this lesson are:

```text
1. Public pages should be composed from reusable components.

2. CourseCard should be a reusable presentation component.

3. Course data should come from typed API/service layers.

4. Search, filtering, sorting, and pagination should be
   handled by the backend for scalable datasets.

5. Use URL query parameters for shareable catalog state.

6. Debounce search input to avoid unnecessary requests.

7. Every API-driven page should handle:
   loading → success → empty → error.

8. Course details should be composed from smaller components.

9. Enrollment logic should live outside the presentation component.

10. Don't build the entire LMS inside one page component.
```

Our architecture now has a clear progression:

```text
10.1  Architecture
       ↓
10.2  Routing
       ↓
10.3  Authentication
       ↓
10.4  Design System
       ↓
10.5  Public LMS
       ↓
10.6  Student Dashboard
```
