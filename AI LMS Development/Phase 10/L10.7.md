# 1. Instructor vs Student

Don't make the mistake of treating the instructor dashboard as another student dashboard.

### Student

```text
Learn
 ↓
Courses
 ↓
Progress
 ↓
Quizzes
 ↓
Certificates
```

### Instructor

```text
Create
 ↓
Manage
 ↓
Publish
 ↓
Teach
 ↓
Analyze
 ↓
Improve
```

So the information architecture is different.

# 19. Important Security Rule — Revenue

Never calculate authoritative revenue on the frontend.

Don't do:

```ts
totalRevenue =
  course.price *
  course.students;
```

That's not reliable.

Revenue may depend on:

```text
discounts
refunds
taxes
platform fees
payment status
partial payments
currency
payout rules
```

The backend/database should provide the authoritative numbers.

Frontend displays them.

# 29. Dashboard API

Create:

```text
src/services/instructor.service.ts
```

Conceptually:

```ts
export const instructorService = {
  async getDashboard() {
    const response = await api.get(
      "/instructor/dashboard"
    );

    return response.data;
  },

  async getCourses(params: GetCoursesParams) {
    const response = await api.get(
      "/instructor/courses",
      { params }
    );

    return response.data;
  },

  async getStudents(params: StudentParams) {
    const response = await api.get(
      "/instructor/students",
      { params }
    );

    return response.data;
  },
};
```

Then:

```text
Instructor Dashboard
        ↓
useInstructorDashboard()
        ↓
instructorService
        ↓
API
```

# 30. Instructor Dashboard Hook

# 31. Don't Mix Server State With UI State

This distinction is important.

### Server state

```text
courses
students
revenue
reviews
analytics
```

comes from the backend.

### UI state

```text
sidebar open
modal open
selected tab
filter dropdown open
```

belongs to React/client state.

So:

```text
TanStack Query
→ server state

useState / UI store
→ client state
```

Don't put your entire backend database inside Zustand.

# 38. Permission Model

Eventually, roles may not be enough.

For example:

```text
Instructor
```

might have:

```text
course:create
course:update
course:publish
student:view
analytics:view
```

while another instructor might have limited permissions.

For now:

```text
role === "instructor"
```

is enough for our frontend route structure.

But keep the architecture flexible for future permission-based authorization.

---

# 39. Don't Trust Instructor IDs From the URL

Suppose someone manually opens:

```text
/instructor/courses/some-course-id/edit
```

The frontend shouldn't assume:

```text
"I'm an instructor, therefore I own this course."
```

The backend must check:

```text
Current user
     ↓
Course ownership
     ↓
Permission
```

So:

```text
Role authorization
+
Resource authorization
```

are different things.

This becomes particularly important in our security phase later.

# 🧠 Lesson 10.7 Takeaways

Remember these:

```text
1. Instructor and student dashboards have different goals.

2. Instructor dashboard = create + manage + analyze.

3. Reuse design-system components instead of duplicating UI.

4. Keep dashboard components separate from the course builder.

5. Server data belongs in TanStack Query.

6. Revenue and analytics should come from authoritative backend data.

7. Frontend role guards are not real authorization.
```
