# Backend Engineering — Requirements Analysis Notes

# Module 8 — Define the Scope

> **Goal:** Learn how to clearly define what is **included** and **excluded** from a project. A well-defined scope prevents wasted effort, endless feature requests (scope creep), and missed deadlines.

---

# Learning Objectives

By the end of this module, you should be able to:

- Understand what project scope is.
    
- Define what is in scope and out of scope.
    
- Prevent scope creep.
    
- Plan a realistic Minimum Viable Product (MVP).
    
- Communicate project boundaries clearly with stakeholders.
    

---

# 1. What is Project Scope?

**Project Scope** defines the boundaries of a project.

It answers two important questions:

1. **What are we building?**
    
2. **What are we NOT building?**
    

Think of scope as a contract between the development team and the stakeholders.

---

## Simple Definition

```text
Business Goal

↓

Project Scope

↓

Included Features

+

Excluded Features

↓

Development
```

Without a defined scope, projects become unpredictable.

---

# 2. Why is Scope Important?

Imagine a client asks for:

> "Build a Blog Platform."

You start building.

After one week, the client says:

- Add messaging.
    
- Add video streaming.
    
- Add AI recommendations.
    
- Add online courses.
    
- Add live chat.
    

Every new request increases:

- Development time
    
- Testing effort
    
- Complexity
    
- Cost
    

This is called **Scope Creep**.

---

# 3. What is Scope Creep?

**Scope Creep** is the uncontrolled addition of new features after the project has started.

Example:

Original scope:

```text
Register

↓

Login

↓

Create Posts

↓

Comments
```

Later additions:

```text
Messaging

↓

Video Calls

↓

AI Assistant

↓

Payments

↓

Social Feed
```

The project becomes much larger than originally planned.

---

# 4. In Scope vs Out of Scope

Example: Blog Platform

## In Scope

```text
User Authentication

↓

Create Posts

↓

Edit Posts

↓

Delete Posts

↓

Comments

↓

Likes

↓

Categories

↓

Search
```

---

## Out of Scope

```text
Video Streaming

↓

Messaging

↓

Payments

↓

Live Chat

↓

Podcast Hosting
```

Writing both lists prevents misunderstandings.

---

# 5. Scope Should Align with Business Goals

Business Goal:

```text
Allow writers to publish technical articles.
```

Question:

Does live video streaming help achieve this goal?

No.

Therefore:

```text
Live Streaming

↓

Out of Scope
```

Always compare new features against the business goal.

---

# 6. Define Functional Boundaries

Instead of saying:

```text
Users can manage posts.
```

Be specific.

Example:

Included:

- Create post
    
- Edit own post
    
- Delete own post
    
- Publish post
    
- Save draft
    

Not Included:

- Scheduled publishing
    
- Version history
    
- AI writing assistant
    
- Collaborative editing
    

Specific boundaries avoid confusion.

---

# 7. Define Technical Boundaries

Scope also applies to technical decisions.

Example:

Current Project:

```text
Backend API

↓

REST

↓

MongoDB

↓

JWT Authentication
```

Out of Scope:

```text
GraphQL

↓

Microservices

↓

Event Streaming

↓

Multi-region Deployment
```

This keeps the architecture manageable.

---

# 8. Define User Boundaries

Ask:

Which users are supported?

Example:

Included:

```text
Guest

↓

Reader

↓

Author

↓

Admin
```

Not Included:

```text
Moderator

↓

Editor

↓

Premium Member
```

Additional user roles can be added in future versions.

---

# 9. Define Platform Boundaries

Example:

Supported:

```text
Web Browser
```

Not Supported:

```text
Android App

↓

iOS App

↓

Desktop Application
```

This affects API design, testing, and deployment.

# 12. MVP (Minimum Viable Product)

An MVP contains only the essential features required to solve the core problem.

Example:

Business Goal:

```text
Allow writers to publish blogs.
```

MVP:

```text
Register

↓

Login

↓

Create Post

↓

Edit Post

↓

Publish

↓

Read Posts
```

Everything else can wait.

---

# 14. Scope Influences Architecture

Suppose your scope is:

```text
Single Backend

↓

REST API

↓

MongoDB
```

Architecture stays simple.

Now imagine you add:

- Messaging
    
- Notifications
    
- Live Streaming
    
- AI Recommendations
    

Architecture changes dramatically.

Scope determines architectural complexity.

# 16. Scope Influences API Design

Current Scope:

Authentication

```http
POST /auth/register

POST /auth/login
```

Posts

```http
GET /posts

POST /posts

PATCH /posts/:id

DELETE /posts/:id
```

Comments

```http
POST /posts/:id/comments
```

No APIs are created for excluded features.

# 17. Scope Document Example

A professional Scope Document often includes:

|Section|Example|
|---|---|
|Project Goal|Build a blogging platform|
|In Scope|Authentication, Posts, Comments|
|Out of Scope|Payments, Chat, AI|
|Users|Guest, Reader, Author, Admin|
|Supported Platforms|Web|
|Technical Stack|Node.js, Express, MongoDB|
|Timeline|12 weeks|

This document keeps everyone aligned.

# 18. Common Mistakes

## Mistake 1

Trying to build everything.

Start with the essentials.

---

## Mistake 2

Never saying "No."

Every feature request is not automatically accepted.

---

## Mistake 3

Mixing current features with future ideas.

Separate them clearly.

---

## Mistake 4

Changing scope without updating documentation.

Always keep the scope document current.

---

## Mistake 5

Ignoring business priorities.

A feature may be interesting but still outside the project's goals.

# 20. Interview Questions

### Q1. What is project scope?

**Answer:**

Project scope defines the boundaries of a project by specifying what features, users, platforms, and deliverables are included and excluded.

---

### Q2. What is scope creep?

**Answer:**

Scope creep is the uncontrolled expansion of project requirements after development has started, often leading to delays, increased costs, and additional complexity.

---

### Q3. Why should out-of-scope items be documented?

**Answer:**

Documenting out-of-scope items prevents misunderstandings, manages stakeholder expectations, and keeps the development team focused on agreed priorities.

---

### Q4. What is an MVP?

**Answer:**

A Minimum Viable Product (MVP) is the smallest version of a product that delivers the core value to users using only the essential features.

# Key Takeaways

- Project scope defines **what you will build** and **what you will not build**.
    
- A clear scope protects the project from unnecessary complexity.
    
- Scope should always align with the business goal.
    
- An MVP focuses on delivering the core value first.
    
- Future ideas should be documented separately instead of being added to the current release.
    

---

# Real-World Tip for Backend Engineers

When joining a company, one of the first things you'll hear is:

> **"Is this feature in scope for this sprint?"**

or

> **"This request is out of scope for the current release."**

Understanding scope helps you:

- Estimate work accurately.
    
- Plan APIs and database changes.
    
- Avoid unnecessary development.
    
- Communicate effectively with product managers and stakeholders.
    

This is a skill used every day in professional software teams.
