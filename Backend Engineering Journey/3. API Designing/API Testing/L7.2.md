# Why Manual Testing?

Even if your project has automated tests, you still need manual testing during development.

Imagine you're building a new endpoint:

```http
POST /api/v1/users
```

You don't want to write 20 automated tests before checking if the endpoint even works.

Instead, you:

1. Start your server
    
2. Send a request
    
3. See the response
    
4. Fix bugs
    
5. Repeat
    

This feedback loop is much faster.

- Test scripts

- Learning

## Bruno ⭐

A newer tool becoming popular among backend engineers.

Features:

- Stores collections as plain text files
    
- Git-friendly
    
- Offline
    
- No cloud account required
    
- Fast
    

Best for:

- Developers
    
- Open source projects
    
- Version control

# Organizing Requests Using Collections

Don't keep random requests everywhere.

Professional structure:

```
Blog API

├── Auth
│   ├── Register
│   ├── Login
│   └── Logout
│
├── Users
│   ├── Get User
│   ├── Update User
│   └── Delete User
│
├── Posts
│   ├── Create Post
│   ├── Update Post
│   ├── Delete Post
│   └── Get Posts
│
└── Comments
```

This organization helps your team understand the API quickly.

# Using Environments

Hardcoding URLs is a bad habit.

Instead of:

```text
http://localhost:5000/api/users
```

Use a variable:

```text
{{baseUrl}}/api/users
```

Development environment:

```
baseUrl

↓

http://localhost:5000
```

Production:

```
baseUrl

↓

https://api.example.com
```

Changing one variable updates every request.

---

# Example Login Workflow

### Step 1

Login request:

```http
POST /login
```

Response:

```json
{
    "token":"abc123xyz"
}
```

---

### Step 2

Save token into an environment variable.

```
accessToken = abc123xyz
```

---

### Step 3

Use it in future requests.

Header:

```http
Authorization: Bearer {{accessToken}}
```

Now all protected endpoints work without manually copying tokens.

# Writing Test Scripts

Both Postman and Bruno let you validate responses automatically.

Example checks:

- Status code is 200
    
- Response contains a token
    
- User ID exists
    
- Response time is acceptable
    

Conceptually:

```
IF

status == 200

AND

token exists

PASS

ELSE

FAIL
```

These scripts help detect regressions during development.

# Debugging Failed Requests

Suppose you receive:

```
401 Unauthorized
```

Check:

- Missing token?
    
- Expired token?
    
- Wrong Authorization header?
    
- JWT secret mismatch?
    
- Middleware issue?
    

---

Suppose you receive:

```
400 Bad Request
```

Check:

- Missing required fields?
    
- Wrong JSON format?
    
- Validation failure?
    
- Incorrect Content-Type?
    

---

Suppose you receive:

```
500 Internal Server Error
```

Check:

- Server logs
    
- Database connection
    
- Exception stack trace
    
- Unhandled promise rejection

# Using curl

Everything Postman does can also be done with `curl`.

Example:

```bash
curl -X POST http://localhost:5000/api/login \
-H "Content-Type: application/json" \
-d '{"email":"rahul@example.com","password":"secret123"}'
```

Backend engineers often use `curl` while working over SSH on remote servers.

❌ Hardcoding tokens

Instead:

```
Use variables.
```

---

❌ Creating duplicate requests

Instead:

```
Reuse collections.
```

---

❌ Ignoring response codes

Instead:

Always verify:

```
Status

Headers

Body
```

---

❌ Testing only success cases

Instead:

Test:

- Missing fields
    
- Wrong IDs
    
- Invalid JWTs
    
- Unauthorized users
    
- Empty payloads

# Best Practices

✅ Organize requests into collections.

✅ Use environment variables for URLs and tokens.

✅ Reuse authentication across requests.

✅ Test both valid and invalid inputs.

✅ Save frequently used IDs and tokens as variables.

✅ Keep collections version-controlled (especially with Bruno).

# Mini Exercise

Your API has these endpoints:

```
POST /register

POST /login

GET /profile

POST /posts

GET /posts/:id

DELETE /posts/:id
```

Create a testing workflow:

1. Register a new user.
    
2. Log in and save the JWT token.
    
3. Fetch the user's profile using the token.
    
4. Create a new post.
    
5. Retrieve the created post by its ID.
    
6. Delete the post.
    
7. Try fetching the deleted post and confirm it returns `404 Not Found`.
    

---

# Key Takeaways

- Manual testing is essential for fast development and debugging.
    
- Postman and Bruno are the two most important API testing tools to know.
    
- Organize requests into collections for maintainability.
    
- Use environment variables instead of hardcoding URLs or tokens.
    
- Test both successful and failure scenarios.
    
- Learn `curl` as a lightweight alternative, especially for server-side debugging.
    
- Manual testing complements automated testing—it does not replace it.
