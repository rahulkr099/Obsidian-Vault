# The Golden Rule

Professional backend engineers ask this question for every validation:

> **"Which layer is responsible for this?"**

Not:

> **"Where can I write this code?"**

This mindset leads to clean architecture.

# The Complete Validation Pipeline

Every request follows the same journey:

```text
Client

↓

Controller
(Request Validation)

↓

Service
(Business Validation)

↓

Repository
(Database Operations)

↓

Database
(Data Integrity)

↓

Response
```

Each layer has **one responsibility**.

---

# Example 1 — Register User

Endpoint:

```http
POST /auth/register
```

Request:

```json
{
    "name": "Rahul",
    "email": "rahul@example.com",
    "password": "secret123"
}
```

---

## Controller Validation

Checks:

- Name exists
    
- Email exists
    
- Email format is valid
    
- Password length
    
- Data types
    

If invalid:

```http
400 Bad Request
```

---

## Service Validation

Checks:

- Email already registered?
    
- Is registration currently allowed?
    
- Does the business require invitation-only registration?
    

If violated:

```http
409 Conflict
```

or

```http
403 Forbidden
```

---

## Repository

Simply performs:

```text
Create User
```

No business decisions.

---

## Database Validation

Checks:

- Email unique
    
- Required fields
    
- Valid schema
    

If duplicate:

Database rejects the insert.

# Why Validation is Layered

Imagine only using controller validation.

Bug:

```text
Controller

↓

Forgot validation

↓

Database stores bad data
```

Bad outcome.

---

Now imagine layered validation.

```text
Controller

↓

Service

↓

Database
```

If one layer misses something:

Another layer still protects the system.

# Common Beginner Mistakes

## ❌ Same Validation in Every Layer

Bad:

```text
Controller

↓

Check email exists

↓

Service

↓

Check email exists

↓

Repository

↓

Check email exists
```

One responsibility per layer.

---

## ❌ Business Logic in Controllers

Bad:

```text
Controller

↓

Only admin can publish
```

Move it to the service.

---

## ❌ Business Logic in Database

Bad:

```text
Database

↓

Only premium users can upload videos
```

Business policies belong in the service.

---

## ❌ Trusting Application Code Alone

Always keep database constraints.

Bugs happen.

# Validation Checklist

Before implementing any endpoint, ask yourself:

### Controller

- Is every input validated?
    
- Are route parameters valid?
    
- Are query parameters valid?
    
- Are headers valid?
    

---

### Service

- Are business rules enforced?
    
- Is authorization checked?
    
- Are related resources validated?
    
- Are workflow rules enforced?
    

---

### Repository

- Does it only access the database?
    
- Is business logic avoided?
    

---

### Database

- Are required fields enforced?
    
- Are unique constraints defined?
    
- Are indexes configured?
    
- Is schema validation enabled?
    

If all answers are **Yes**, your validation pipeline is in good shape.
