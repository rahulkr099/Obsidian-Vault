# Error Documentation

Every API should have one dedicated error section.

Example:

|Status|Meaning|
|---|---|
|400|Bad Request|
|401|Authentication required|
|403|Permission denied|
|404|Resource not found|
|409|Conflict|
|422|Business validation failed|
|500|Internal server error|

---

## Standard Error Response

```json
{
  "success": false,
  "error": {
    "code": "POST_NOT_FOUND",
    "message": "The requested post does not exist."
  }
}
```

Every endpoint should use the same format.

# Pagination Documentation

GET /posts?page=2&limit=10

{
  "data": [],

    "limit": 10,
    "totalPages": 8,
    "totalItems": 74

- Default page size
    
- Maximum limit
    
- Sorting
    
- Filtering

# Authentication Documentation

Document once.

Reuse everywhere.

Explain:

```text
Login

↓

Access Token

↓

Authorization Header

↓

Protected Endpoint
```

Avoid repeating the same explanation for every protected endpoint.

---

# Security Notes

Document important rules.

Example:

```text
Only the post owner or an administrator may update a post.
```

Another:

```text
Rate limiting is applied to login endpoints.
```

These notes prevent confusion.

# Common Beginner Mistakes

## ❌ No Examples

Developers shouldn't have to guess request formats.

---

## ❌ Missing Error Responses

Always document failure cases.

---

## ❌ Missing Authentication Notes

Protected endpoints should clearly state authentication requirements.

---

## ❌ Outdated Documentation

Documentation that doesn't match the API is worse than incomplete documentation because developers stop trusting it.

---

## ❌ Copy-Paste Descriptions

Write meaningful descriptions that explain the business purpose of each endpoint.

---

# Production Documentation Checklist

Before releasing an API, verify:

### Overview

Is the API purpose explained?

---

### Authentication

Is the authentication flow documented?

---

### Endpoints

Does every endpoint include:

- Purpose
    
- Parameters
    
- Request
    
- Response
    
- Errors
    
- Examples
    

---

### Error Handling

Is there a consistent error format?

---

### Pagination

Is pagination explained?

---

### Versioning

Is the current version documented?

---

### Security

Are authorization and rate-limiting rules described?

If every answer is **Yes**, your API documentation is ready for production.
