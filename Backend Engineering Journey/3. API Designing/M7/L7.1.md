# What is API Testing?

API testing verifies that:

```
Request
↓

API

↓

Response

is correct.
```

Testing checks:

- status code
    
- response body
    
- headers
    
- validation
    
- authentication
    
- database changes
    
- edge cases
    

---

# Why Not Just Test in Browser?

Browser testing only checks one path.

Professional engineers test:

```
Normal input

Invalid input

Missing fields

Unauthorized users

Database failures

Rate limiting

Expired tokens

Large payloads

Unexpected values
```

# Testing Pyramid

```
           /\
          /E2E\
         /------\
        /Integration\
       /------------\
      /   Unit Tests  \
     /________________\

```

# Why?

- expensive
    
- harder to maintain

# Best Practices

✅ Test every endpoint.

✅ Test both success and failure cases.

✅ Keep tests independent.

✅ Write readable test names.

✅ Automate repetitive testing.

✅ Run tests before every commit.

# Key Takeaways

- Testing proves your API behaves correctly.
    
- Manual testing is useful during development, but automated testing is essential for production.
    
- Test both happy paths and edge cases.
    
- The testing pyramid emphasizes many unit tests, fewer integration tests, and very few end-to-end tests.
    
- Good testing enables confident refactoring, safer deployments, and better teamwork.
