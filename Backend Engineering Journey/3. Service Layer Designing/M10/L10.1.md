# Module 10 — Transactions ⭐⭐⭐⭐⭐

> **Goal:** Learn when and why transactions are needed to keep your data consistent.

A transaction is used when **one business action performs multiple database operations**.

The rule is simple:

> **Either everything succeeds, or nothing changes.**

# Lesson 10.1 — Why Transactions Are Needed

> **Goal:** Understand why some business actions cannot be completed with a single database query.

---

# Simple Operation

Creating a post:

```text
Create Post

↓

Done
```

Usually, one database operation is enough.

No transaction needed.

---

# Multi-Step Operation

Publishing a post:

```text
Update Post

↓

Create Activity

↓

Update User Statistics

↓

Send Notification
```

Now multiple operations are involved.

---

# The Problem

Suppose this happens:

```text
Update Post

✅ Success

↓

Create Activity

✅ Success

↓

Update User Statistics

❌ Failed
```

Now your data is inconsistent.

- The post is published.
    
- The activity exists.
    
- The user statistics are wrong.
    

---

# The Solution: Transaction

A transaction treats all operations as **one unit**.

```text
All succeed

↓

Commit

----------------

One fails

↓

Rollback everything
```

No partial updates.

---

# Real Examples

### E-commerce

```text
Create Order

↓

Reduce Stock

↓

Create Payment
```

---

### Banking

```text
Withdraw Money

↓

Deposit Money
```

Money should never disappear because one step failed.

---

### Blog App

```text
Publish Post

↓

Create Activity

↓

Notify Followers
```

These operations should stay consistent.

---

# When Do You Need a Transaction?

Ask yourself:

> **Does this business action modify multiple pieces of data that must stay consistent?**

If **yes**, consider using a transaction.

---

# Interview Question

**Q:** When should you use a transaction?

**Good Answer:**

> Use a transaction when a business operation performs multiple related database changes that must either all succeed or all fail. Transactions prevent inconsistent data caused by partial updates.

---

# Key Takeaways

- Transactions protect **data consistency**.
    
- Use them for **multi-step business operations**.
    
- A transaction follows the **all-or-nothing** principle.
    
- Single database operations usually don't need a transaction.
