# Module 10 — Lesson 10.2: Multi-Step Business Workflows ⭐⭐⭐⭐⭐

> **Goal:** Learn how to recognize business workflows that should be executed as a single transaction.

A **workflow** is a sequence of related business steps.

If all the steps must stay consistent, they should usually be inside a transaction.

---

# Example 1 — Publish a Blog Post

Requirement:

> User publishes a post.

Workflow:

```text
Publish Post

↓

Update Post Status

↓

Create Activity

↓

Update User Statistics

↓

Notify Followers
```

This is **one business action** with multiple steps.

---

# Example 2 — Place an Order

Requirement:

> Customer places an order.

Workflow:

```text
Create Order

↓

Reduce Product Stock

↓

Create Payment Record

↓

Create Invoice
```

If one step fails, the workflow may become inconsistent.

---

# Example 3 — Banking

Requirement:

> Transfer ₹500.

Workflow:

```text
Withdraw ₹500

↓

Deposit ₹500

↓

Save Transaction History
```

These steps must succeed together.

---

# Think in Business Workflows

Don't think:

```text
Database Query 1

↓

Database Query 2
```

Think:

```text
One Business Action

↓

Multiple Steps
```

A transaction protects the **business action**, not just individual queries.

---

# Simple Rule

Ask yourself:

> **If Step 3 fails, should Steps 1 and 2 remain?**

If the answer is **No**:

```text
Use a Transaction
```

---

# When You Usually DON'T Need One

Example:

```text
Get User Profile

↓

Return Response
```

Or:

```text
Create Category
```

A single independent database operation usually doesn't require a transaction.

---

# Best Practices

✅ Think in **business workflows**, not database queries.

✅ Identify all related operations before coding.

✅ Use transactions only when consistency between multiple operations matters.

---

# Interview Question

**Q:** How do you know whether a workflow needs a transaction?

**Good Answer:**

> I look at the business workflow. If a single business action performs multiple related database operations and partial success would leave the system inconsistent, I use a transaction.

---

# Key Takeaways

- A workflow is a sequence of business steps.
    
- Transactions protect the **entire workflow**.
    
- Ask: **"Can partial success leave inconsistent data?"**
    
- If yes, use a transaction.
