# Module 10 — Lesson 10.3: Rollbacks & Failure Handling ⭐⭐⭐⭐⭐

> **Goal:** Understand what happens when a transaction fails and why rollbacks are essential.

The biggest benefit of a transaction is that it prevents **partial updates**.

---

# What is a Rollback?

A **rollback** means:

> **Undo every change made during the transaction.**

If one step fails:

```text
Rollback

↓

Database returns

to its previous state
```

---

# Example — Place Order

Workflow:

```text
Create Order

↓

Reduce Stock

↓

Create Payment
```

Suppose:

```text
Create Order

✅

↓

Reduce Stock

✅

↓

Create Payment

❌ Failed
```

Without a rollback:

```text
Order Exists

↓

Stock Reduced

↓

No Payment
```

The system is inconsistent.

---

# With a Rollback

```text
Create Order

↓

Reduce Stock

↓

Create Payment ❌

↓

Rollback

↓

Order Removed

↓

Stock Restored
```

The database looks as if nothing happened.

---

# Commit vs Rollback

If everything succeeds:

```text
Commit

↓

Save all changes
```

If anything fails:

```text
Rollback

↓

Undo all changes
```

---

# Real Example — Banking

Transfer ₹500:

```text
Withdraw ₹500

↓

Deposit ₹500
```

If the deposit fails:

Without rollback:

```text
Money Lost ❌
```

With rollback:

```text
Withdrawal Undone

↓

Balance Restored ✅
```

---

# Think Like This

A transaction has only **two possible outcomes**:

```text
Everything succeeds

OR

Nothing changes
```

There should never be a partial result.

---

# Best Practices

✅ Design for failures, not just success.

✅ Keep all related operations inside one transaction.

✅ Let the database handle commit and rollback.

---

# Interview Question

**Q:** What is the purpose of a rollback?

**Good Answer:**

> A rollback undoes all changes made during a transaction if any step fails. It ensures the database remains consistent by preventing partial updates.

---

# Key Takeaways

- **Commit** = Save all changes.
    
- **Rollback** = Undo all changes.
    
- Transactions guarantee **all-or-nothing** execution.
    
- Rollbacks protect data consistency when failures occur.
