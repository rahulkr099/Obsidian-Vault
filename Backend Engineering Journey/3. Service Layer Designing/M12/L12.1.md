# Lesson 12.1 — Business Errors vs System Errors

> **Goal:** Learn the difference between expected business failures and unexpected system failures.

---

# 1. Business Errors

These are **expected**.

Examples:

```text
Post not found

↓

User not authorized

↓

Already published

↓

Insufficient balance
```

They happen because of business rules.

The service should detect and report them.

---

# 2. System Errors

These are **unexpected**.

Examples:

```text
Database offline

↓

Network timeout

↓

Disk full

↓

Server crash
```

These are infrastructure problems, not business rules.

---

# Example

Requirement:

> Publish a post.

Business error:

```text
Post already published
```

System error:

```text
Database connection lost
```

Very different situations.

---

# Why Separate Them?

Business errors help the client understand **what went wrong**.

System errors help developers diagnose **why the system failed**.

---

# Best Practices

✅ Handle expected business failures in the **Service Layer**.

✅ Let unexpected system failures bubble up to the global error handler.

---

# Interview Question

**Q:** What's the difference between a business error and a system error?

**Good Answer:**

> A business error occurs when a business rule is violated, such as "post already published" or "user not authorized." A system error is caused by infrastructure issues like database failures or network problems. Services should explicitly handle business errors, while system errors are typically handled by global error handling.

---

# Key Takeaways

- **Business errors** = Expected rule violations.
    
- **System errors** = Unexpected infrastructure failures.
    
- Don't treat every error the same.
    
- Meaningful errors make applications easier to maintain and debug.
