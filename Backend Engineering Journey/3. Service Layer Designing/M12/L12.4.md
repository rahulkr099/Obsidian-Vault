# Module 12 — Lesson 12.4: Error Handling Best Practices ⭐⭐⭐⭐⭐

> **Goal:** Learn the practical rules professional backend engineers follow for error handling.

This lesson summarizes Module 12.

---

# Rule 1 — Throw Meaningful Errors

❌ Bad

```javascript
throw new Error("Something went wrong");
```

✅ Good

```javascript
throw new NotFoundError();

throw new ForbiddenError();

throw new ConflictError();
```

The error should clearly describe the problem.

---

# Rule 2 — Services Throw, Controllers Respond

Correct flow:

```text
Service

↓

Throw Error

↓

Controller

↓

Global Error Handler

↓

HTTP Response
```

Don't return HTTP responses from services.

---

# Rule 3 — Use a Global Error Handler

Instead of writing:

```text
Controller A

↓

Error Handling

---------------

Controller B

↓

Error Handling
```

Use:

```text
All Controllers

↓

Global Error Handler
```

One place.

One consistent response format.

---

# Rule 4 — Separate Business & System Errors

Business errors:

```text
NotFoundError

ForbiddenError

ConflictError
```

System errors:

```text
Database Failure

Network Timeout

Disk Full
```

Treat them differently.

---

# Rule 5 — Don't Hide Errors

❌ Bad

```javascript
try {
    ...
} catch (err) {
    return null;
}
```

The real problem disappears.

If you can't recover from an error, let it propagate to the global error handler.

---

# Professional Error Flow

```text
Request

↓

Controller

↓

Service

↓

Business Error?

↓

Yes

↓

Global Error Handler

↓

HTTP Response
```

---

# Common Mistakes

## ❌ Returning HTTP Responses from Services

Bad:

```javascript
return res.status(404).json(...);
```

A service should not know about Express.

---

## ❌ Catching Every Error

Only catch an error if you can:

- Recover from it
    
- Add useful context
    
- Clean up resources (for example, close a file)
    

Otherwise, let it bubble up.

---

## ❌ Exposing Internal Details

Bad response:

```text
MongoServerError:
Duplicate key...
```

Good response:

```text
Email already exists.
```

Log technical details internally, but return user-friendly messages.

---

# Interview Questions

### Q1. Who should throw business errors?

**Answer:**

> The Service Layer, because it contains the business rules.

---

### Q2. Who converts errors into HTTP responses?

**Answer:**

> The global error handler (or controller, if a global handler isn't used).

---

### Q3. Why use custom error classes?

**Answer:**

> They make errors meaningful, easier to identify, and easier to map to the correct HTTP status codes.
