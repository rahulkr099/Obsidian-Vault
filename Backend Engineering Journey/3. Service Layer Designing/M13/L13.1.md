# Lesson 13.1 — What is a Domain Service?

> **Goal:** Understand when logic deserves its own service.

---

## The Problem

Suppose `PostService` does this:

```text
Create Slug

↓

Upload Image

↓

Send Email

↓

Create Notification

↓

Save Post
```

`PostService` is doing too much.

---

## Better Design

Move reusable logic into dedicated services.

```text
PostService

↓

SlugService

↓

ImageService

↓

NotificationService
```

Now each service has **one responsibility**.

---

# Real Examples

Instead of putting everything in `UserService`:

```text
UserService

↓

Send Email

↓

Hash Password

↓

Generate OTP
```

Create:

```text
EmailService

PasswordService

OtpService
```

Each service focuses on one domain.

---

# Benefits

✅ Smaller services

✅ Easier testing

✅ Better code reuse

✅ Easier maintenance

---

# Interview Question

**Q:** What is a Domain Service?

**Good Answer:**

> A Domain Service contains reusable business logic that doesn't naturally belong to a single entity or service. It has one focused responsibility and can be used by multiple services.

---

# Key Takeaways

- Domain Services have **one responsibility**.
    
- Extract reusable business logic.
    
- Keep feature services focused.
    
- Avoid large "God Services."
