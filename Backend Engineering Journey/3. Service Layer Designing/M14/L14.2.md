# Module 14 — Lesson 14.2: Avoiding Circular Dependencies ⭐⭐⭐⭐⭐

> **Goal:** Learn how to prevent services from depending on each other in a loop.

A **circular dependency** happens when two or more services depend on each other.

This makes the application difficult to understand, test, and maintain.

---

# Bad Design

```text
PostService

↓

NotificationService

↓

PostService
```

Now:

- `PostService` needs `NotificationService`
    
- `NotificationService` needs `PostService`
    

This creates a cycle.

---

# Another Example

```text
UserService

↓

OrderService

↓

UserService
```

Again, both services depend on each other.

---

# Why Is This Bad?

Problems:

- Hard to test
    
- Tight coupling
    
- Difficult to maintain
    
- Can cause initialization issues
    

---

# Better Design

Keep the dependency in **one direction**.

```text
PostService

↓

NotificationService
```

`NotificationService` should not call `PostService` back.

Each service has a clear role.

---

# Share Data, Not Services

Instead of:

```text
NotificationService

↓

PostService

↓

Get post title
```

Pass the required data directly:

```text
NotificationService.send({
    userId,
    postTitle
})
```

The notification service gets everything it needs without depending on `PostService`.

---

# Simple Rule

Ask yourself:

> **"Will this create a dependency loop?"**

If **yes**, redesign the interaction.

---

# Best Practices

✅ Keep dependencies one-way.

✅ Pass data instead of calling back into another service.

✅ Let each service own its own responsibility.

---

# Interview Question

**Q:** What is a circular dependency?

**Good Answer:**

> A circular dependency occurs when two or more services depend on each other directly or indirectly. It increases coupling, makes testing difficult, and should be avoided by keeping dependencies one-directional and passing data instead of creating dependency loops.

---

# Key Takeaways

- Avoid service dependency loops.
    
- Keep dependencies **one-way**.
    
- Pass DTOs or data instead of calling services back.
    
- Loosely coupled services are easier to maintain.
