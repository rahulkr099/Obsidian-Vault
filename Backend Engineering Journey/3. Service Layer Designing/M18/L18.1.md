# Lesson 18.1 — What is Dependency Injection?

> **Goal:** Understand why services shouldn't create their own dependencies.

---

# The Problem

Suppose `PostService` creates its own repository.

```javascript
class PostService {
    constructor() {
        this.postRepository = new PostRepository();
    }
}
```

Now `PostService` is tightly coupled to `PostRepository`.

Problems:

- Hard to test
    
- Hard to replace
    
- Hard to maintain
    

---

# Better Design

Instead of creating the dependency, **receive it**.

```text
PostService

↓

PostRepository
(injected)
```

The service doesn't care **who created** the repository.

It only uses it.

---

# Real Example

```text
OrderService

↓

OrderRepository

↓

PaymentService

↓

NotificationService
```

All dependencies are **provided** to `OrderService` instead of being created inside it.

---

# Benefits

✅ Loose coupling

✅ Easier testing

✅ Easier replacement

✅ Better maintainability

---

# Interview Question

**Q:** What is Dependency Injection?

**Good Answer:**

> Dependency Injection is a design pattern where a class receives its dependencies from the outside instead of creating them itself. This reduces coupling and makes the code easier to test and maintain.

---

# Key Takeaways

- Don't create dependencies inside services.
    
- Inject dependencies from outside.
    
- DI promotes loose coupling.
    
- It's a core principle in modern backend frameworks.
