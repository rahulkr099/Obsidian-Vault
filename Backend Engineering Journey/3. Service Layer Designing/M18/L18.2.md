# Module 18 — Lesson 18.2: Constructor Injection ⭐⭐⭐⭐⭐

> **Goal:** Learn the most common way to implement Dependency Injection.

The most common DI technique is **Constructor Injection**.

Instead of creating dependencies inside a class, pass them through the constructor.

---

# ❌ Without Constructor Injection

```javascript
class PostService {
    constructor() {
        this.postRepository = new PostRepository();
    }
}
```

Problems:

- `PostService` decides which repository to use.
    
- Hard to replace with a mock during testing.
    
- Tightly coupled.
    

---

# ✅ With Constructor Injection

```javascript
class PostService {
    constructor(postRepository) {
        this.postRepository = postRepository;
    }
}
```

Now someone else creates the repository and passes it in.

```javascript
const postRepository = new PostRepository();
const postService = new PostService(postRepository);
```

This is **Constructor Injection**.

---

# Visual Flow

```text
Application

↓

Create PostRepository

↓

Inject into PostService

↓

Use PostService
```

`PostService` doesn't care who created the repository.

---

# Real Example

```text
OrderService

↓

OrderRepository

↓

PaymentService

↓

NotificationService
```

All three dependencies are injected into `OrderService`.

---

# Why Constructor Injection?

Suppose tomorrow you switch from MongoDB to PostgreSQL.

Old:

```text
PostRepository
```

New:

```text
PostgresPostRepository
```

`PostService` doesn't change.

Only the injected dependency changes.

---

# Best Practices

✅ Inject dependencies through the constructor.

✅ Don't create dependencies with `new` inside services.

✅ Keep services independent of concrete implementations.

---

# Interview Question

**Q:** Why is constructor injection preferred?

**Good Answer:**

> Constructor injection makes dependencies explicit, reduces coupling, and makes it easy to replace real implementations with mocks or different implementations without changing the service.

---

# Key Takeaways

- Constructor injection is the most common DI pattern.
    
- Services receive dependencies instead of creating them.
    
- Dependencies become easy to replace.
    
- Constructor injection improves flexibility and maintainability.
