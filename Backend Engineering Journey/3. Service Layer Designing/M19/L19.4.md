# Module 19 — Lesson 19.4: Service Testing Best Practices ⭐⭐⭐⭐⭐

> **Goal:** Learn the practical rules for writing professional unit tests for services.

This lesson summarizes Module 19.

---

# Rule 1 — Test the Service, Not the Database

✅ Good

```text
PostService

↓

Mock Repository
```

❌ Bad

```text
PostService

↓

Real MongoDB
```

Unit tests should isolate the service.

---

# Rule 2 — Mock External Dependencies

Replace:

- Repositories
    
- EmailService
    
- PaymentService
    
- NotificationService
    

with mocks.

```text
OrderService

↓

Mock PaymentService

↓

Mock Repository
```

---

# Rule 3 — Test Business Rules

Instead of testing:

```text
findById()
```

Test:

```text
Can Publish?

Can Delete?

Can Refund?
```

Focus on business behavior.

---

# Rule 4 — Test Both Success & Failure

Example:

```text
Draft Post

↓

Publish Successfully
```

```text
Already Published

↓

ConflictError
```

Both scenarios matter.

---

# Rule 5 — Keep Tests Independent

Every test should run independently.

```text
Test A

↓

Pass

---------------

Test B

↓

Pass
```

One test should never depend on another.

---

# Common Mistakes

### ❌ Testing the Database

That's an **integration test**, not a **unit test**.

---

### ❌ Testing Multiple Business Rules in One Test

Bad:

```text
Authorization

+

Validation

+

Transactions
```

One test should verify **one behavior**.

---

### ❌ Poor Test Names

Bad:

```text
test1()
```

Good:

```text
shouldThrowConflictWhenPostAlreadyPublished()
```

The test name explains the expected behavior.

---

# Interview Questions

### Q1. Why mock repositories?

**Answer:**

> To isolate the service from the database so the unit test focuses only on business logic.

---

### Q2. What should a service unit test verify?

**Answer:**

> Business rules, authorization, validation, workflows, success cases, failure cases, and edge cases.

---

### Q3. What's the difference between a unit test and an integration test?

**Answer:**

> A unit test isolates one component using mocks. An integration test verifies that multiple components, such as services and the database, work correctly together.
