# Lesson 2.1 — The Journey of an HTTP Request

> **Goal:** Understand how a request travels through every layer of your backend and what each layer contributes.

Think of your backend like a company.

A customer places an order.

The receptionist receives it.

The manager decides what should happen.

The warehouse fetches the product.

The delivery team sends it.

Each person has a different responsibility.

Your backend works the same way.

---

# The Complete Journey

Suppose a user wants to publish a blog post.

The frontend sends:

```http
POST /posts/123/publish
```

The request travels like this:

```text
Client
   │
   ▼
Router
   │
   ▼
Middleware
   │
   ▼
Controller
   │
   ▼
Service
   │
   ▼
Repository
   │
   ▼
Database
```

Let's understand every stop.

---

# Step 1 — Client

The client could be:

- React application
    
- Mobile app
    
- Postman
    
- Another backend service
    

Example:

```javascript
await axios.post(
    "/posts/123/publish",
    {},
    {
        headers: {
            Authorization: "Bearer token"
        }
    }
);
```

The client only knows:

> "I want to publish this post."

It doesn't know your business rules.

---

# Step 2 — Router

The router receives the URL.

```javascript
router.post(
    "/posts/:id/publish",
    authenticate,
    postController.publishPost
);
```

Responsibilities:

- Match URL
    
- Match HTTP method
    
- Choose controller
    
- Execute middleware
    

The router never talks to the database.

---

# Step 3 — Middleware

Middleware executes before the controller.

Example:

```text
Request

↓

Verify JWT

↓

Rate Limit

↓

Logging

↓

Validate Request

↓

Controller
```

Examples of middleware:

```text
Authentication

Authorization (simple route-based)

Logging

CORS

Rate Limiter

Helmet

Input Validation

File Upload

Request Timing
```

Notice:

Middleware handles **cross-cutting concerns**.

---

# Step 4 — Controller

The controller is the bridge between HTTP and your application.

Example:

```javascript
async function publishPost(req, res) {

    const result = await postService.publishPost({
        userId: req.user.id,
        postId: req.params.id
    });

    res.json(result);

}
```

Responsibilities:

- Read request
    
- Call service
    
- Return response
    

Nothing else.

---

# Step 5 — Service

The service contains business knowledge.

Example:

```text
Find post

↓

Verify owner

↓

Verify draft

↓

Generate slug

↓

Publish

↓

Create notification

↓

Return result
```

The service answers questions like:

- Can this happen?
    
- Should this happen?
    
- What happens next?
    

---

# Step 6 — Repository

Repository communicates with MongoDB.

Example:

```javascript
findById()

findBySlug()

create()

update()

delete()
```

Repository should never contain business rules.

It simply performs data access.

---

# Step 7 — Database

MongoDB stores information.

It doesn't know:

- Why a post is published
    
- Why an order is cancelled
    
- Why a coupon expires
    

It simply stores data.

---

# Following a Real Request

Let's trace the entire request.

## User clicks Publish

↓

```http
POST /posts/123/publish
```

↓

Router matches:

```javascript
router.post(...)
```

↓

Middleware verifies token

↓

Controller extracts:

```javascript
req.user.id

req.params.id
```

↓

Controller calls:

```javascript
postService.publishPost(...)
```

↓

Service asks repository:

```javascript
findById()
```

↓

Repository queries MongoDB

↓

MongoDB returns post

↓

Repository returns post

↓

Service checks:

```text
Is owner?

Already published?

Generate slug?

Update status?
```

↓

Repository saves changes

↓

Service returns updated post

↓

Controller sends:

```javascript
res.status(200).json(post)
```

↓

Frontend receives success.

# Data Flow

Notice the direction.

```text
Request

↓

Controller

↓

Service

↓

Repository

↓

MongoDB

↓

Repository

↓

Service

↓

Controller

↓

Response
```

The response travels back through the same layers.

# Important Principle

Every layer only knows about the layer immediately below it.

Example:

```text
Controller

↓

Service

↓

Repository
```

The controller should **not** skip the service.

Bad:

```text
Controller

↓

Repository
```

Because business logic gets bypassed.

---

# Visual Mental Model

Imagine building a house.

The homeowner talks to the architect.

The architect talks to the engineer.

The engineer talks to the workers.

The homeowner never gives instructions directly to the workers.

Similarly:

```text
Client

↓

Controller

↓

Service

↓

Repository
```

Each layer communicates through the proper channel.

# Why This Matters

Imagine later you add:

- GraphQL API
    
- Mobile App
    
- Admin Panel
    
- Background Worker
    

All of them can reuse the same service.

```text
REST Controller
          │
GraphQL Resolver
          │
Cron Job
          │
CLI Command
          │
          ▼
     PostService
          │
          ▼
    Repository
```

This is one reason services are so valuable.

# Common Beginner Mistakes

## Skipping the Service

Bad:

```text
Controller

↓

Repository
```

Business rules disappear.

---

## Database Queries in Middleware

Bad:

```javascript
authenticate()

↓

Post.findById()
```

Authentication middleware shouldn't start handling application logic.

---

## Returning HTTP Responses from Services

Bad:

```javascript
return res.status(404).json(...)
```

Services should never know Express exists.

They should return data or throw errors.

---

## Repositories Calling Controllers

This should never happen.

Architecture should always flow downward.

---

# Interview Insight

Suppose you're asked:

> "Why not call the repository directly from the controller?"

A strong answer:

> "The Service Layer protects business rules. If controllers access repositories directly, business logic becomes duplicated across controllers, making the application harder to maintain, test, and extend."

---

# Key Takeaways

- Every request flows through a sequence of layers, each with a specific responsibility.
    
- Controllers translate HTTP requests into service calls.
    
- Services implement business rules and workflows.
    
- Repositories isolate database access.
    
- Layers should communicate only with the layer directly below them.
    
- Following this flow makes your backend easier to test, maintain, and scale.

# Mini Exercise

For each action below, identify the layer responsible.

|Action|Layer|
|---|---|
|Match `POST /posts/:id/publish` to a handler|?|
|Verify the JWT token|?|
|Read `req.params.id`|?|
|Decide whether the user owns the post|?|
|Retrieve the post from MongoDB|?|
|Update the post document|?|
|Return `200 OK` with JSON|?|

**Answers:**

- Match the route → **Router**
    
- Verify JWT → **Middleware**
    
- Read `req.params.id` → **Controller**
    
- Check ownership → **Service**
    
- Retrieve the post → **Repository**
    
- Update the post → **Repository**
    
- Return `200 OK` → **Controller**
