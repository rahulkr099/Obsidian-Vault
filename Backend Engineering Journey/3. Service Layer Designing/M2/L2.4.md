# The Universal Backend Architecture

Almost every backend feature follows the same pattern.

```text
HTTP Request
      │
      ▼
Router
      │
      ▼
Middleware
      │
      ▼
Controller
      │
      ▼
Service
      │
      ▼
Repository
      │
      ▼
Database
```

The feature changes, but the architecture remains the same.

# Example 1 — Blog Application

## Feature

> Publish a blog post.

---

## Request Flow

```text
Client
   │
   ▼
POST /posts/:id/publish
```

↓

Router

```javascript
router.post(
    "/posts/:id/publish",
    authenticate,
    postController.publishPost
);
```

↓

Controller

```javascript
await postService.publishPost({
    userId: req.user.id,
    postId: req.params.id
});
```

↓

Service

```text
Find post

↓

Check ownership

↓

Check draft status

↓

Generate slug

↓

Update publishedAt

↓

Update status

↓

Create activity log

↓

Notify followers
```

↓

Repository

```text
findById()

update()
```

↓

MongoDB

---

## Responsibilities

|Layer|Responsibility|
|---|---|
|Router|Map endpoint|
|Middleware|Authenticate user|
|Controller|Read request & return response|
|Service|Publishing workflow|
|Repository|Database operations|

# Example 2 — URL Shortener

## Feature

> Create a custom short URL.

---

## Flow

```text
Client

↓

POST /urls
```

↓

Controller

↓

URLService

↓

UserRepository

↓

Check premium plan

↓

URLRepository

↓

Check alias uniqueness

↓

Generate nanoid (if needed)

↓

Save URL

↓

Return result

---

## Business Rules

Notice these belong in the service:

```text
Premium users may choose aliases.

↓

Alias must be unique.

↓

Expiration date is valid.

↓

Maximum URLs per free user.
```

None of these belong inside the controller.

# Example 3 — Todo Application

## Feature

> Mark a task as completed.

---

## Flow

```text
Controller

↓

↓

TodoRepository.findById()

↓

Validate owner

↓

Validate task status

↓

Update completedAt

↓

TodoRepository.update()

↓

Controller returns response
```

---

## Business Rules

Examples:

```text
Completed task cannot be completed again.

↓

User must own task.

↓

Update completedAt timestamp.

↓

Log activity.
```

These belong in the service.

# A Professional Folder Structure

A clean Node.js project often looks like this:

```text
src/
│
├── routes/
│     post.routes.js
│     user.routes.js
│
├── controllers/
│     post.controller.js
│     user.controller.js
│
├── services/
│     post.service.js
│     user.service.js
│     auth.service.js
│
├── repositories/
│     post.repository.js
│     user.repository.js
│
├── models/
│     Post.js
│     User.js
│
├── middleware/
│     auth.js
│     validation.js
│
├── utils/
│     slug.js
│     logger.js
│
└── app.js
```

As your project grows, this structure remains organized because every file has a clear responsibility.

# Adding a New Feature

Suppose your manager asks:

> "Users can now archive blog posts."

Where should the work happen?

### Router

```text
POST /posts/:id/archive
```

↓

Controller

```javascript
postService.archivePost(...)
```

↓

Service

```text
Check ownership

↓

Check current status

↓

Archive post

↓

Log activity
```

↓

Repository

```text

```

# Thinking Like a Backend Engineer

Whenever a new requirement arrives:

Example:

> Users can restore archived posts.

Don't start coding immediately.

Instead, ask:

### Step 1

What is the business rule?

```text
Only archived posts can be restored.
```

↓

Service

---

### Step 2

Which data is needed?

```text
Post

User
```

↓

Repositories

---

### Step 3

Which endpoint exposes it?

```text
POST /posts/:id/restore
```

↓

Router + Controller

This thought process leads to cleaner code.

# Common Beginner Mistakes

## Mistake 1

Adding database queries to controllers.

```javascript
const post = await Post.findById(id);
```

Use a service instead.

---

## Mistake 2

Putting business rules in middleware.

```text
If premium user...

If order shipped...
```

These belong in the service.

---

## Mistake 3

Creating one giant service.

Bad:

```text
AppService
```

Good:

```text
AuthService

PostService

CommentService

UserService
```

Each service has one domain.

---

## Mistake 4

Repositories sending emails.

Repositories should only access the database.

# Module 2 Key Takeaways

Remember these five rules:

1. **Controllers handle HTTP, not business rules.**
    
2. **Services contain business logic and workflows.**
    
3. **Repositories only access the database.**
    
4. **Dependencies always flow downward.**
    
5. **Every new feature should fit into the same layered architecture.**
    

These principles will serve you in almost every backend project, whether you're building a **Blog App, URL Shortener, Todo App, E-commerce platform, LMS, Hospital Management System, or Banking application**.
