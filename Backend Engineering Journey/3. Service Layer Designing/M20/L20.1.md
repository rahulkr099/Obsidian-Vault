# Lesson 20.1 — Avoid Unnecessary Database Queries

> **Goal:** Learn how to reduce expensive database operations.

---

# Bad Example

Suppose you need a post and its author.

❌

```text
Get Post

↓

Query Database

↓

Get Author

↓

Query Database

↓

Get Category

↓

Query Database
```

Too many database calls.

---

# Better

Use one optimized query when possible.

```text
Get Post

↓

Load Related Data

↓

Return Result
```

One efficient query is often better than many small queries.

---

# Another Bad Example

```text
Loop

↓

Query Database

↓

Loop

↓

Query Database
```

This is a common performance problem.

---

# Better

```text
One Query

↓

Process in Memory
```

Fetch the data once, then work with it.

---

# Why Reduce Queries?

Every database query has a cost:

- Network latency
    
- Database processing
    
- Resource usage
    

Fewer queries usually mean faster responses.

---

# Best Practices

✅ Fetch only the data you need.

✅ Avoid querying inside loops.

✅ Reuse data you've already loaded.

---

# Interview Question

**Q:** Why should you minimize database queries?

**Good Answer:**

> Database queries are relatively expensive compared to in-memory operations. Reducing unnecessary queries improves response time, lowers database load, and makes the application more scalable.

---

# Key Takeaways

- Database queries are expensive.
    
- Avoid repeated queries.
    
- Don't query inside loops.
    
- Load data efficiently.
