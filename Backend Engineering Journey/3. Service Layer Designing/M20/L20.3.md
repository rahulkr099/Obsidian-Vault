# Module 20 — Lesson 20.3: Caching & Reducing Repository Calls ⭐⭐⭐⭐⭐

> **Goal:** Learn how to avoid repeatedly fetching the same data from the database.

One of the easiest ways to improve performance is:

> **Don't query the database if you already have the data.**

---

# The Problem

Suppose `PostService` needs the same user three times.

❌ Bad

```text
Get User

↓

Repository

↓

Get User Again

↓

Repository

↓

Get User Again

↓

Repository
```

Three database queries.

---

# Better

```text
Get User Once

↓

Store in Memory

↓

Reuse
```

One database query.

---

# Example

Requirement:

> Publish a post.

Workflow:

```text
Load User

↓

Load Post

↓

Reuse User Data

↓

Complete Workflow
```

Don't reload the same user again.

---

# Application Cache

Frequently accessed data can be stored in a cache.

```text
Request

↓

Cache?

↓

Yes → Return Data

↓

No

↓

Database

↓

Store in Cache
```

Examples:

- User profile
    
- Categories
    
- Product list
    
- Application settings
    

---

# Repository Calls

❌ Bad

```text
Repository.findById()

↓

Repository.findById()

↓

Repository.findById()
```

Same request.

Same data.

---

✅ Better

```text
Repository.findById()

↓

Reuse Result
```

---

# Common Cache Technologies

Professional applications often use:

- **Redis**
    
- In-memory cache
    
- CDN (for static content)
    

The Service Layer simply asks for data; the caching layer decides where it comes from.

---

# Best Practices

✅ Load data once and reuse it.

✅ Cache frequently read data.

✅ Avoid repeated repository calls in the same workflow.

---

# Interview Question

**Q:** How can you reduce unnecessary repository calls?

**Good Answer:**

> By loading data once and reusing it within the same workflow, and by caching frequently accessed data. This reduces database load and improves application performance.

---

# Key Takeaways

- Don't fetch the same data repeatedly.
    
- Reuse loaded data during a workflow.
    
- Cache frequently accessed data.
    
- Fewer repository calls improve scalability.
