# Rule 1 — Minimize Database Queries

❌ Bad

```text
Loop

↓

Database Query

↓

Loop

↓

Database Query
```

✅ Better

```text
One Optimized Query

↓

Process in Memory
```

---

# Rule 2 — Use Batch Operations

Instead of:

```text
Insert One

↓

Insert One

↓

Insert One
```

Use:

```text
insertMany()
```

The same idea applies to:

- `updateMany()`
    
- `deleteMany()`
    

---

# Rule 3 — Avoid Duplicate Repository Calls

❌ Bad

```text
findUser()

↓

findUser()

↓

findUser()
```

✅ Good

```text
findUser()

↓

Reuse Result
```

Load once. Reuse many times.

---

# Rule 4 — Cache Frequently Used Data

Good candidates:

- Categories
    
- Settings
    
- User profiles
    
- Frequently viewed products
    

```text
Cache

↓

Database

↓

Response
```

The cache reduces database load.

---

# Rule 5 — Keep Services Efficient

A service should:

- Minimize database calls
    
- Avoid unnecessary work
    
- Use transactions only when needed
    
- Delegate responsibilities to other services
    

---

# Common Mistakes

### ❌ Query Inside Loops

```text
Loop

↓

Query

↓

Loop

↓

Query
```

This is one of the most common backend performance issues.

---

### ❌ Loading Unused Data

Don't fetch:

- Every column
    
- Every document
    
- Every relationship
    

Load only what the business workflow needs.

---

### ❌ Premature Optimization

Don't optimize everything from day one.

First:

- Build correctly.
    
- Measure performance.
    
- Optimize actual bottlenecks.
    

---

# Interview Questions

### Q1. What is the biggest performance mistake in backend development?

**Answer:**

> Executing unnecessary database queries, especially querying inside loops (the N+1 query problem), which significantly increases response time.

---

### Q2. How do you improve service performance?

**Answer:**

> By reducing database queries, using batch operations, reusing loaded data, caching frequently accessed information, and designing efficient workflows.

---

### Q3. Should you optimize everything immediately?

**Answer:**

> No. First build a correct solution, measure performance, identify bottlenecks, and then optimize the parts that actually need improvement.

# Practice Exercise

Design an efficient workflow for:

> **Show a user's dashboard** (profile, latest posts, unread notifications).

A good design:

```text
DashboardService

↓

Load User Once

↓

Get Latest Posts

↓

Get Unread Notifications

↓

Combine Response
```

Avoid:

```text
Load User

↓

Load User Again

↓

Load User Again
```

Reuse data whenever possible.
