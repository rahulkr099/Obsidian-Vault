# Module 3 — Lesson 3.2: Service Responsibilities

> **Goal:** Learn what belongs inside a service and why the Service Layer is considered the **heart of a backend application**.

If controllers are the **face** of your backend (HTTP), then services are the **brain**.

---

# What is a Service?

A service contains your application's **business logic**.

It answers questions like:

- Can this action be performed?
    
- What rules should be applied?
    
- What should happen next?
    

A service doesn't know anything about:

- Express
    
- `req`
    
- `res`
    
- HTTP status codes
    

It only knows **business rules**.

---

# Responsibilities of a Service

A service should do the following.

### 1. Enforce Business Rules

Example:

> Only the owner can publish a post.

```text
Find post

↓

Check owner

↓

Publish
```

This belongs in the service.

---

### 2. Coordinate Workflows

Example:

Publishing a post.

```text
Update Post

↓

Create Activity

↓

Notify Followers

↓

Update Search Index
```

One business action may involve multiple steps.

The service coordinates them.

---

### 3. Call Repositories

A service doesn't query MongoDB directly.

Instead:

```javascript
const post = await postRepository.findById(postId);
```

The repository handles the database.

---

### 4. Call Other Services

Example:

```text
OrderService

↓

PaymentService

↓

NotificationService
```

This is perfectly fine.

---

# What a Service Should NOT Do

## ❌ Read HTTP Requests

Bad:

```javascript
req.body.title
```

The service should never see `req`.

Instead:

```javascript
await postService.createPost({
    title,
    content,
    authorId
});
```

---

## ❌ Return HTTP Responses

Bad:

```javascript
res.status(404).json(...)
```

Instead:

```javascript
throw new NotFoundError("Post not found");
```

The controller (or global error handler) decides the HTTP response.

---

## ❌ Define Routes

Bad:

```javascript
router.post(...)
```

Routes belong in the router.

---

# A Real Example

## Controller

```javascript
async function publishPost(req, res) {

    const post = await postService.publishPost({
        userId: req.user.id,
        postId: req.params.id
    });

    res.json(post);

}
```

---

## Service

```javascript
async function publishPost({ userId, postId }) {

    const post = await postRepository.findById(postId);

    if (!post) {
        throw new NotFoundError("Post not found");
    }

    if (post.author.toString() !== userId) {
        throw new ForbiddenError("Not allowed");
    }

    if (post.status === "published") {
        throw new BadRequestError("Already published");
    }

    post.status = "published";
    post.publishedAt = new Date();

    return await postRepository.save(post);

}
```

Notice:

The service contains **all the business decisions**.

---

# Good Service Design

A service should expose **business capabilities**, not HTTP actions.

Good:

```javascript
createPost()

publishPost()

archivePost()

restorePost()

deletePost()
```

Bad:

```javascript
post()

get()

put()

delete()
```

These are HTTP concepts, not business concepts.

---

# Keep Services Focused

Bad:

```text
UserService

↓

Login

Reset Password

Send Email

Generate Invoice

Upload Image
```

Good:

```text
AuthService

UserService

EmailService

FileService
```

Each service has one clear responsibility.

---

# Service Flow

```text
Controller

↓

PostService

↓

PostRepository

↓

MongoDB
```

The service sits between the HTTP layer and the database layer.

---

# Best Practices

✅ Services receive **plain data**, not `req` or `res`.

✅ Services contain business rules.

✅ Services coordinate repositories and other services.

✅ Services throw meaningful errors instead of returning HTTP responses.

✅ Keep each service focused on one domain.

---

# Interview Question

**Q:** Why do we use a Service Layer?

**Good Answer:**

> "The Service Layer centralizes business logic. It keeps controllers thin, prevents code duplication, improves testability, and allows business rules to be reused across different interfaces such as REST APIs, GraphQL, or background jobs."

---

# Key Takeaways

- The **Service Layer is the brain** of your backend.
    
- It contains **business rules and workflows**.
    
- It communicates with repositories and other services.
    
- It should not know anything about HTTP or Express.
    
- Well-designed services make applications easier to maintain, test, and extend.

## Mini Exercise

Decide whether each task belongs in the **Service**.

|Task|Service?|
|---|---|
|Check whether a user owns a post|?|
|Read `req.params.id`|?|
|Generate a slug|?|
|Return `201 Created`|?|
|Coordinate `PostRepository` and `NotificationService`|?|

**Answers:**

- Check ownership → ✅ Service
    
- Read `req.params.id` → ❌ Controller
    
- Generate a slug → ✅ Service
    
- Return `201 Created` → ❌ Controller
    
- Coordinate `PostRepository` and `NotificationService` → ✅ Service
