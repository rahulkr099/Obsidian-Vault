# Lesson 5.1 — Designing Good Service Methods

> **Goal:** Learn how to name and design service methods like a professional backend engineer.

---

# What is a Service Interface?

A service interface is simply the **public methods** that other parts of your application can call.

Example:

```javascript
postService.createPost()

postService.publishPost()

postService.archivePost()

postService.deletePost()
```

Think of it as the **API of your Service Layer**.

---

# Design Around Business Actions

Your methods should describe **what the business is doing**, not what HTTP is doing.

### ✅ Good

```javascript
createPost()

publishPost()

archivePost()

restorePost()

resetPassword()

enrollStudent()

placeOrder()
```

These names match real business actions.

---

### ❌ Bad

```javascript
post()

put()

updateData()

execute()

process()

handle()
```

These names are too generic.

When another developer reads:

```javascript
await postService.publishPost(...)
```

they immediately understand the purpose.

---

# One Method = One Business Capability

Bad:

```javascript
managePost(action)
```

Example:

```javascript
managePost("publish")

managePost("archive")

managePost("delete")
```

Problems:

- Large `if-else` or `switch` blocks
    
- Hard to test
    
- Hard to extend
    

---

Better:

```javascript
publishPost()

archivePost()

deletePost()
```

Each method has one clear responsibility.

---

# Keep Methods Focused

Bad:

```text
registerUser()

↓

Create user

↓

Send email

↓

Generate invoice

↓

Upload avatar

↓

Create subscription

↓

Create analytics
```

Too many unrelated responsibilities.

---

Better:

```text
registerUser()

↓

Create user

↓

Generate verification token

↓

Call EmailService
```

Additional work (like analytics) can be handled by specialized services or events later.

---

# Design by Domain

Organize methods by the domain they belong to.

### PostService

```javascript
createPost()

updatePost()

publishPost()

archivePost()

deletePost()
```

---

### AuthService

```javascript
login()

logout()

refreshToken()

changePassword()

resetPassword()
```

---

### OrderService

```javascript
placeOrder()

cancelOrder()

refundOrder()
```

Notice that each service owns one business area.

---

# Think About the Future

Suppose someone asks:

> "Can users schedule blog posts?"

You don't modify:

```javascript
updatePost()
```

Instead, add a new business capability:

```javascript
schedulePost()
```

Your interface grows naturally.

---

# Common Beginner Mistakes

### ❌ Using HTTP verbs

```javascript
post()

put()

delete()
```

Those belong to HTTP, not your business domain.

---

### ❌ Creating huge methods

```javascript
handleUser()
```

Nobody knows what it actually does.

---

### ❌ Mixing domains

```javascript
UserService

↓

login()

sendEmail()

createInvoice()

uploadImage()
```

Split responsibilities into focused services.

---

# Interview Question

**Q:** How do you design service methods?

**Good Answer:**

> I design service methods around business capabilities rather than HTTP operations. Each method should have one clear responsibility, use descriptive names like `publishPost()` or `placeOrder()`, and remain focused on a single business action.

---

# Key Takeaways

- A service interface is the set of methods your Service Layer exposes.
    
- Name methods after **business actions**, not HTTP actions.
    
- Keep each method focused on **one responsibility**.
    
- Organize services by **business domain**, not by technical tasks.
    
- A clean service interface makes the code easier to understand, test, and extend.
