# Module 5 — Lesson 5.2: Method Parameters & DTOs ⭐⭐⭐⭐⭐

> **Goal:** Learn how to pass data into services professionally using DTOs (Data Transfer Objects).

This is a small topic, but it's a hallmark of clean backend architecture.

---

# The Beginner Approach

Many beginners write:

```javascript
await postService.createPost(req);
```

or

```javascript
await postService.createPost(req, res);
```

This works.

But it creates a problem.

Your service now depends on **Express**.

---

# Why Is This Bad?

Imagine tomorrow your application also has:

- GraphQL
    
- Background Jobs
    
- CLI Commands
    
- Unit Tests
    

These don't have `req` and `res`.

Your service becomes difficult to reuse.

---

# The Professional Approach

Pass only the data the service actually needs.

Instead of:

```javascript
await postService.createPost(req);
```

Use:

```javascript
await postService.createPost({
    title,
    content,
    authorId
});
```

Now the service doesn't care where the data came from.

---

# What is a DTO?

DTO stands for:

> **Data Transfer Object**

A DTO is simply a **plain JavaScript object** that carries data between layers.

Example:

```javascript
{
    title: "Learning Service Layer",
    content: "...",
    authorId: "123"
}
```

That's it.

No methods.

No database logic.

Just data.

---

# Controller Example

```javascript
async function createPost(req, res) {

    const post = await postService.createPost({
        title: req.body.title,
        content: req.body.content,
        authorId: req.user.id
    });

    res.status(201).json(post);

}
```

The controller extracts data from HTTP.

The service receives clean business data.

---

# Service Example

```javascript
async function createPost({
    title,
    content,
    authorId
}) {

    // Business logic

}
```

Notice:

No `req`.

No `res`.

No Express.

---

# Why Use an Object Instead of Multiple Parameters?

Instead of:

```javascript
createPost(
    title,
    content,
    authorId,
    categoryId,
    tags,
    image
);
```

Use:

```javascript
createPost({
    title,
    content,
    authorId,
    categoryId,
    tags,
    image
});
```

Benefits:

- Easier to read
    
- Easier to extend
    
- Less chance of mixing parameter order
    

---

### Multiple Parameters ❌

updateUser(

Hard to remember the order.

### DTO ✅

# DTO Flow

```text
HTTP Request
      │
      ▼
Controller
      │
Extract Data
      │
      ▼
DTO
      │
      ▼
Service
```

The DTO is the bridge between the Controller and the Service.

---

# Common Beginner Mistakes

## ❌ Passing `req`

```javascript
postService.createPost(req);
```

---

## ❌ Passing `req.body`

```javascript
postService.createPost(req.body);
```

This is better than passing `req`, but it still hides where the data comes from and may include fields the service doesn't need.

Better:

```javascript
postService.createPost({
    title: req.body.title,
    content: req.body.content,
    authorId: req.user.id
});
```

Now the service receives exactly what it needs.

---

## ❌ Too Many Parameters

```javascript
registerUser(
    name,
    email,
    password,
    phone,
    address,
    role
);
```

Prefer:

```javascript
registerUser({
    name,
    email,
    password,
    phone,
    address,
    role
});
```

---

# Interview Question

**Q:** Why do you pass a DTO instead of the Express `req` object?

**Good Answer:**

> A DTO keeps the Service Layer independent of Express. The service only receives the data it needs, making it reusable, easier to test, and usable from different entry points like REST APIs, GraphQL resolvers, background jobs, or CLI commands.

---

# Best Practices

✅ Pass **one object** to service methods.

✅ Include only the required fields.

✅ Keep DTOs as plain data objects.

✅ Let the controller translate HTTP into a DTO.

---

# Summary

|Bad ❌|Good ✅|
|---|---|
|`service(req)`|`service({ ... })`|
|Depends on Express|Framework-independent|
|Many positional parameters|Single DTO object|
|Harder to test|Easier to test|
|Less reusable|Highly reusable|

# Mini Exercise

Which design is better?

### Option A

```javascript
await authService.login(
    email,
    password
);
```

### Option B

```javascript
await authService.login({
    email,
    password
});
```

**Answer:** ✅ **Option B**

Using a DTO is more readable, easier to extend (for example, adding `otp` or `rememberMe` later), and avoids parameter-order mistakes.
