# Module 5 — Lesson 5.3: Designing Service Methods ⭐⭐⭐⭐⭐

> **Goal:** Learn how to design the workflow inside a service method before writing code.

Once you've identified the business action, the next step is to design **what the service should do**.

Don't code yet.

Think about the workflow.

---

# Example — Blog App

## User Story

> User publishes a blog post.

Business action:

```text
publishPost()
```

Now design the workflow.

```text
publishPost()

↓

Validate ownership

↓

Validate draft

↓

Update status

↓

Set publishedAt

↓

Return updated post
```

Notice:

This is exactly what your roadmap shows.

Requirement

---

# A Good Service Design

A service method should answer:

1. **What should be validated?**
    
2. **What should change?**
    
3. **What should be returned?**
    

Example:

```text
publishPost()

↓

Validate

↓

Update

↓

Return
```

Simple and predictable.

---

# Common Beginner Mistake

Starting with code:

```javascript
async function publishPost() {
   // Start coding...
}
```

Professional approach:

```text
Design workflow

↓

Review business rules

↓

Then code
```

Planning first usually leads to cleaner implementations.

---

# Interview Question

**Q:** Before implementing a service method, what should you design?

**Good Answer:**

> I first design the business workflow by identifying the validation steps, business actions, state changes, and expected result. Once the workflow is clear, I implement the service method.

---

# Key Takeaways

- A service method is a **workflow**, not just a function.
    
- Design the workflow before writing code.
    
- Think in steps like **validate → update → return**.
    
- A well-designed workflow makes implementation much easier.
