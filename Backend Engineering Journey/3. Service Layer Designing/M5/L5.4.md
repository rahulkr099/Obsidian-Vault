# The Professional Workflow

Whenever you receive a new feature, follow this sequence:

```text
User Story

↓

Business Action

↓

Service Method

↓

Workflow

↓

Implementation
```

Don't jump directly to code.

---

# Example 1 — Blog App

### User Story

> User publishes a blog post.

### Step 1 — Business Action

```text
Publish Post
```

### Step 2 — Service Method

```text
publishPost()
```

### Step 3 — Workflow

```text
Validate ownership

↓

Validate draft

↓

Update status

↓

Set publishedAt

↓

Return updated post
```

Now you're ready to implement.

# A Reusable Design Pattern

For most backend features, you can think like this:

```text
User Story

↓

Business Action

↓

Validate

↓

Perform Action

↓

Return Result
```

You'll use this pattern repeatedly across projects.

---

# Common Beginner Mistake

Requirement:

> User resets password.

Immediately writing code:

```text
Code

↓

Fix bugs

↓

Add missing rules
```

Professional approach:

```text
User Story

↓

Business Action

↓

Workflow

↓

Code
```

Planning first reduces rework.

---

# Interview Question

**Q:** How do you convert a user story into backend design?

**Good Answer:**

> I identify the main business action, design a service method around it, define the workflow step by step, and only then implement the code. This keeps the service aligned with business requirements and makes the logic easier to maintain.

|**User Story**|What does the user want?|
|**Business Action**|What business action is happening?|
|**Service Method**|What should the method be called?|

|**Implementation**|How do I write the code?|
