# Lesson 6.1 — The Three Levels of Validation

> **Goal:** Understand that not all validation belongs in one place.

A professional backend validates data at **three different levels**.

```text
HTTP Request
      │
      ▼
Request Validation
      │
      ▼
Business Validation
      │
      ▼
Database Validation
```

Each layer has a different purpose.

---

# Level 1 — Request Validation

Question:

> **"Is the request format correct?"**

Examples:

- Required fields
    
- Email format
    
- Password length
    
- Data types
    
- Maximum string length
    

Example:

```json
{
  "email": "rahul@example.com",
  "password": "secret123"
}
```

Checks:

```text
✓ Email exists

✓ Email format is valid

✓ Password exists

✓ Password has at least 8 characters
```

These checks happen **before** your service is called.

Usually using:

- Joi
    
- Zod
    
- Express Validator
    

---

# Level 2 — Business Validation

Question:

> **"Is this action allowed?"**

Examples:

```text
User already enrolled?

↓

Coupon expired?

↓

Post already published?

↓

User owns this resource?
```

These rules belong in the **Service Layer**.

Example:

```javascript
if (post.status === "published") {
    throw new BadRequestError();
}
```

This isn't about data format.

It's about business behavior.

---

# Level 3 — Database Validation

Question:

> **"Can the database store this data safely?"**

Examples:

- Unique email
    
- Unique username
    
- Required database fields
    
- Foreign key constraints (SQL)
    
- Schema constraints
    

Example (Mongoose):

```javascript
email: {
    type: String,
    unique: true
}
```

Even if your application has checks, the database should still protect important constraints.

Imagine user registration.


Notice that each validation has a different responsibility.

# Common Mistake

Many beginners put everything in one place.

Example:

```text
Controller

↓

Validate email

↓

Check duplicate email

↓

Business rules

↓

Database queries
```

The controller becomes too large.

Instead:

```text
Controller

↓

Request Validation

↓

Service

↓

Business Validation

↓

Repository

↓

Database Validation
```

Much cleaner.

# Interview Question

**Q:** Why do we validate at multiple layers?

**Good Answer:**

> Because each layer protects against different problems. Request validation checks input format, the Service Layer enforces business rules, and the database enforces data integrity. Together they create a robust and maintainable system.

---

# Key Takeaways

- **Request Validation** → Is the input well-formed?
    
- **Business Validation** → Is the action allowed?
    
- **Database Validation** → Can the data be stored safely?
    
- Don't put every validation in the controller.
    
- Each validation layer has a unique responsibility.

# Mini Exercise

Classify each validation.

|Validation|Layer|
|---|---|
|Email format|?|
|User already owns the post|?|
|Username must be unique|?|
|Password must be at least 8 characters|?|
|Coupon has expired|?|

**Answers:**

- Email format → **Request Validation**
    
- User already owns the post → **Business Validation**
    
- Username must be unique → **Database Validation** (and often checked in the service for a better user experience)
    
- Password must be at least 8 characters → **Request Validation**
    
- Coupon has expired → **Business Validation**
