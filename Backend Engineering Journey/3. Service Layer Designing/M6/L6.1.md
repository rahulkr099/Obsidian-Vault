# Lesson 6.1 — What is a Service Interface?

> **Goal:** Learn what a Service Interface is and why you should design it before coding.

---

## Think Before Coding

Before writing:

```javascript
async function publishPost() {
    ...
}
```

First design the interface.

Example:

```text
PostService

↓

createPost()

updatePost()

publishPost()

archivePost()

deletePost()

restorePost()

getPost()

listPosts()
```

This is your **Service Interface**.

---

# What Does a Service Interface Represent?

It represents the **business capabilities** of a module.

Example:

### PostService

```text
createPost()

publishPost()

archivePost()

deletePost()
```

Everything related to **posts**.

---

### AuthService

```text
login()

logout()

refreshToken()

resetPassword()
```

Everything related to **authentication**.

---

### OrderService

```text
placeOrder()

cancelOrder()

refundOrder()
```

Everything related to **orders**.

---

# Why Design the Interface First?

Without planning:

```text
Start Coding

↓

Keep Adding Methods

↓

Messy Service
```

With planning:

```text
Design Interface

↓

Review Methods

↓

Implement
```

Your service stays clean and organized.

---

# Common Beginner Mistake

Creating methods while coding:

```text
create()

doWork()

handle()

process()
```

These names don't explain the business capability.

Instead:

```text
createPost()

publishPost()

archivePost()
```

The method names clearly describe what the service does.

---

# Interview Question

**Q:** What is a Service Interface?

**Good Answer:**

> A Service Interface is the set of public business methods exposed by a service. It defines what operations the service supports before worrying about how those operations are implemented.

---

# Key Takeaways

- Design the **service interface before implementation**.
    
- The interface represents **business capabilities**.
    
- Group related actions into the same service.
    
- Clear interfaces lead to cleaner implementations.
