# Lesson 7.1 — What is a DTO?

> **Goal:** Understand what a DTO is and why we use it.

---

## DTO = Data Transfer Object

A DTO is simply a **plain object** used to transfer data between layers.

Example:

```javascript
{
  authorId: "u123",
  title: "Learning Service Layer",
  content: "..."
}
```

That's it.

No methods.

No business logic.

No database queries.

Just data.

---

# Why Do We Need DTOs?

Without a DTO:

```text
Controller

↓

Service(req)

↓

Repository
```

The service now depends on **Express**.

---

With a DTO:

```text
Controller

↓

Service(dto)

↓

Repository
```

The service only receives the data it needs.

---

# Example

❌ Bad

```javascript
await postService.createPost(req);
```

---

✅ Good

```javascript
await postService.createPost({
    authorId: req.user.id,
    title: req.body.title,
    content: req.body.content
});
```

Now the service doesn't know anything about Express.

---

# Benefits

✅ Reduces coupling

✅ Easier to test

✅ Framework independent

✅ Cleaner service methods

---

# Interview Question

**Q:** Why shouldn't a service receive `req`?

**Good Answer:**

> A service should be independent of Express. By passing a DTO instead of `req`, the service only receives the data it needs, making it reusable and easier to test.

---

# Key Takeaways

- DTO = **Data Transfer Object**.
    
- A DTO is a plain object containing only data.
    
- Controllers create DTOs.
    
- Services consume DTOs.
    
- Never pass `req` or `res` into a service.
