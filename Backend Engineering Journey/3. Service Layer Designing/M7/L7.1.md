# Lesson 7.1 — Authentication vs Authorization

> **Goal:** Understand the difference between authentication and authorization and where each belongs.

---

# Two Different Questions

Although they sound similar, they answer different questions.

### Authentication

Authentication asks:

> **Who are you?**

Example:

```text
User logs in

↓

Verify JWT

↓

Identify user

↓

Attach req.user
```

If successful:

```javascript
req.user = {
    id: "123",
    role: "author"
};
```

Authentication usually happens in **middleware**.

---

### Authorization

Authorization asks:

> **What are you allowed to do?**

Example:

```text
Can this user publish this post?

↓

Does this user own the post?

↓

Is this user an admin?
```

These are **business rules**.

They belong in the **Service Layer**.

---

# Complete Flow

```text
Client

↓

Authentication Middleware

↓

Controller

↓

Service
(Authorization)

↓

Repository
```

Notice:

Middleware proves **who the user is**.

The service decides **whether the action is allowed**.

---

### Authentication

```text
↓

User exists?
```

Middleware handles this.

---

### Authorization

```text
Does user own the post?

↓

Is post a draft?
```

The service handles this.


# Why Authorization Belongs in Services

Bad:

```javascript
if(post.author !== req.user.id){

}
```

inside the controller.

Problem:

If another controller needs the same rule, you'll duplicate code.

Better:

```javascript
await postService.publishPost({
    userId,
    postId
});
```

The service performs the ownership check once.

---

# Authentication vs Authorization

|Authentication|Authorization|
|---|---|
|Who are you?|What can you do?|
|Verify identity|Verify permissions|
|Middleware|Service|
|JWT, Session|Ownership, Roles, Permissions|

---

# Common Beginner Mistakes

## ❌ Putting Authorization in Middleware

Example:

```text
Does user own post?
```

Middleware doesn't know your business rules.

Ownership depends on application data.

The service should decide.

---

## ❌ Trusting the Frontend

Bad:

```javascript
if(req.body.isAdmin){

}
```

Never trust the client.

Always verify permissions on the server.

---

## ❌ Skipping Ownership Checks

Requirement:

> User edits a blog post.

Always ask:

```text
Does this user own the post?
```

If not, reject the request.

---

# Interview Question

**Q:** What's the difference between authentication and authorization?

**Good Answer:**

> Authentication verifies the user's identity, usually through JWTs or sessions, and is commonly handled by middleware. Authorization determines whether the authenticated user is allowed to perform a specific action, which is a business rule handled in the Service Layer.

---

# Best Practices

✅ Authentication in **middleware**.

✅ Authorization in **services**.

✅ Never trust frontend permission checks.

✅ Always verify ownership and roles on the server.

---

# Key Takeaways

- Authentication answers **"Who are you?"**
    
- Authorization answers **"What are you allowed to do?"**
    
- Authentication belongs in middleware.
    
- Authorization belongs in the Service Layer because it's a business rule.
