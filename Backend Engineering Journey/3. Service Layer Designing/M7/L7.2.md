# Module 7 — Lesson 7.2: Request DTOs ⭐⭐⭐⭐⭐

> **Goal:** Learn how controllers convert HTTP requests into clean Request DTOs.

A **Request DTO** contains only the data a service needs to perform a business action.

---

# The Flow

```text
HTTP Request

↓

Controller

↓

Request DTO

↓

Service
```

The controller acts as a translator.

---

# Example — Blog App

Client sends:

```json
{
    "title": "Service Layer",
    "content": "..."
}
```

Controller creates a DTO:

```javascript
const dto = {
    authorId: req.user.id,
    title: req.body.title,
    content: req.body.content
};

await postService.createPost(dto);
```

The service receives only what it needs.

---

# Bad Approach

Passing the entire request:

```javascript
await postService.createPost(req);
```

Problems:

- Service depends on Express
    
- Harder to test
    
- Receives unnecessary data
    

---

# Good Approach

Pass only the required fields:

```javascript
await postService.createPost({
    authorId,
    title,
    content
});
```

Simple and reusable.

---

# Best Practices

✅ Pass **only** the fields the service needs.

✅ Use meaningful property names.

✅ Keep DTOs free of business logic.

---

# Interview Question

**Q:** What is a Request DTO?

**Good Answer:**

> A Request DTO is a plain object created by the controller that contains only the data required by the service. It isolates the Service Layer from HTTP-specific objects like `req`.

---

# Key Takeaways

- Controllers build Request DTOs.
    
- Services receive DTOs instead of `req`.
    
- DTOs should contain only relevant business data.
    
- This keeps services clean, reusable, and easy to test.
