# Module 7 — Lesson 7.2: Ownership & Role-Based Access Control (RBAC) ⭐⭐⭐⭐⭐

> **Goal:** Learn the two most common authorization patterns used in backend applications: **Ownership** and **Role-Based Access Control (RBAC).**

Almost every backend application uses one or both of these.

---

# Pattern 1 — Ownership

Ownership means:

> **A user can only access or modify resources they own.**

Examples:

- Edit your own blog post
    
- Delete your own todo
    
- View your own profile
    
- Update your own order
    

---

# Example — Blog App

Requirement:

> Only the author can edit a post.

Service:

```text
Find post

↓

Compare authorId with userId

↓

Allow or reject
```

Example code:

```javascript
if (post.author.toString() !== userId) {
    throw new ForbiddenError(
        "You don't own this post."
    );
}
```

This check belongs in the **Service Layer**.

---

# Pattern 2 — Role-Based Access Control (RBAC)

RBAC means:

> Permissions are based on the user's role.

Example roles:

```text
Admin

Editor

Author

Customer

Support
```

Each role has different permissions.

---

# Example

Requirement:

> Only admins can delete users.

Service:

```javascript
if (user.role !== "admin") {
    throw new ForbiddenError();
}
```

Simple and clear.

---

# Ownership vs RBAC

|Ownership|RBAC|
|---|---|
|Based on resource owner|Based on user role|
|"Is this yours?"|"Are you an admin?"|
|Compare IDs|Compare roles|

---

# Owner OR Admin

Many applications combine both.

Requirement:

> A post can be deleted by:
> 
> - its owner
>     
> - or an admin
>     

Service logic:

```text
Owner?

↓

Yes → Allow

↓

No

↓

Admin?

↓

Yes → Allow

↓

No

↓

Reject
```

Example:

```javascript
const isOwner =
    post.author.toString() === user.id;

const isAdmin =
    user.role === "admin";

if (!isOwner && !isAdmin) {
    throw new ForbiddenError();
}
```

This is extremely common.

# Where Should These Checks Live?

Correct architecture:

```text
Controller

↓

Service

↓

Ownership Check

↓

Role Check

↓

Repository
```

Not:

```text
Controller

↓

if(user.role...)

↓

Repository
```

Authorization is business logic.

---

# Common Beginner Mistakes

## ❌ Checking Roles in the Frontend

```javascript
if(user.role === "admin") {
    showDeleteButton();
}
```

This is fine for the UI.

But it is **not security**.

The backend must perform the same check.

---

## ❌ Trusting Request Data

Bad:

```javascript
if(req.body.role === "admin")
```

The client can send anything.

Always use the authenticated user's role from your backend.

Example:

```javascript
req.user.role
```

---

## ❌ Duplicating Checks

Bad:

```text
Controller A

↓

Owner check

Controller B

↓

Owner check

Controller C

↓

Owner check
```

Better:

```text
PostService

↓

Single ownership check
```

One implementation.

Many callers.

# Professional Design

Suppose you're building a URL Shortener.

Requirement:

> Users can edit only their own URLs.

Service:

```javascript
async function updateUrl(dto) {

    const url =
        await urlRepository.findById(dto.urlId);

    if (
        url.userId.toString() !== dto.userId
    ) {
        throw new ForbiddenError();
    }

    // Update URL

}
```

Simple.

Reusable.

Secure.

---

# Interview Question

**Q:** Where should ownership checks be implemented?

**Good Answer:**

> Ownership checks are business rules, so they belong in the Service Layer. The controller should simply pass the authenticated user's ID to the service, and the service decides whether the action is allowed.

---

# Best Practices

✅ Use **ownership** when resources belong to individual users.

✅ Use **RBAC** when permissions depend on roles.

✅ Combine **Owner OR Admin** when needed.

✅ Never trust the frontend for authorization.

✅ Keep authorization logic inside services.

# Mini Exercise

Choose the correct authorization strategy.

|Requirement|Strategy|
|---|---|
|User edits their own profile|?|
|Only admins manage users|?|
|Customer views their own order|?|
|Admin or owner deletes a post|?|
|Teacher grades assignments|?|

### Answers

- User edits their own profile → **Ownership**
    
- Only admins manage users → **RBAC**
    
- Customer views their own order → **Ownership**
    
- Admin or owner deletes a post → **Ownership + RBAC**
    
- Teacher grades assignments → **RBAC**
