# Module 7 — Lesson 7.3: Response DTOs & Internal DTOs ⭐⭐⭐⭐⭐

> **Goal:** Learn the difference between Request DTOs, Response DTOs, and Internal DTOs.

By now you know about **Request DTOs**.

There are two more types you'll commonly see in professional projects.

---

# 1. Request DTO

Moves data **into** the service.

```text
Controller

↓

Request DTO

↓

Service
```

Example:

```javascript
{
    userId,
    title,
    content
}
```

---

# 2. Response DTO

Moves data **out of** the service.

```text
Service

↓

Response DTO

↓

Controller
```

Example:

Instead of returning the complete database document:

```javascript
{
    _id,
    title,
    content,
    author,
    __v,
    internalNotes
}
```

Return only what the API needs:

```javascript
{
    id,
    title,
    authorName,
    publishedAt
}
```

This is a **Response DTO**.

---

# Why Use Response DTOs?

Reasons:

- Hide internal fields
    
- Keep API responses consistent
    
- Prevent exposing sensitive information
    

Example:

Never return:

```text
password

refreshToken

internalFlags
```

---

# 3. Internal DTO

Sometimes one service calls another.

Example:

```text
PostService

↓

NotificationService
```

Instead of passing the whole post object:

```javascript
notificationService.send(post);
```

Pass only what is needed:

```javascript
notificationService.send({
    userId,
    postTitle
});
```

This is an **Internal DTO**.

---

# DTO Flow

```text
HTTP Request

↓

Request DTO

↓

Service

↓

Response DTO

↓

HTTP Response
```

Between services:

```text
PostService

↓

Internal DTO

↓

NotificationService
```

---

# Best Practices

✅ Request DTO → Input to services

✅ Response DTO → Output from services

✅ Internal DTO → Communication between services

✅ Pass only the required data

---

# Interview Question

**Q:** Why use Response DTOs instead of returning database models directly?

**Good Answer:**

> Response DTOs allow us to expose only the fields required by the client, hide internal or sensitive data, and keep API responses consistent even if the database schema changes.

---

# Key Takeaways

|DTO Type|Purpose|
|---|---|
|**Request DTO**|Data going into a service|
|**Response DTO**|Data returned from a service|
|**Internal DTO**|Data exchanged between services|

All three exist for the same reason:

> **Transfer only the data that is needed.**
