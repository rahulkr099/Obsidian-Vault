# Lesson 8.1 — The Three Levels of Validation

> **Goal:** Understand the three validation layers and the responsibility of each.

---

## Professional Validation Flow

```text
Client
   │
   ▼
Request Validation
   │
   ▼
Service
(Business Validation)
   │
   ▼
Repository
   │
   ▼
Database
(Database Validation)
```

Each layer answers a different question.

---

# 1. Request Validation

Question:

> **"Is the request data valid?"**

Examples:

- Required fields
    
- Email format
    
- Password length
    
- Data types
    

Example:

```text
Title is missing?

↓

400 Bad Request
```

Usually done with:

- Joi
    
- Zod
    
- Express Validator
    

---

# 2. Business Validation

Question:

> **"Is this action allowed?"**

Examples:

```text
User owns post?

↓

Already published?

↓

Coupon expired?

↓

Enough balance?
```

These are **business rules**, so they belong in the **Service Layer**.

---

# 3. Database Validation

Question:

> **"Can this data be safely stored?"**

Examples:

- Unique email
    
- Required fields
    
- Enum values
    
- Foreign key constraints (SQL)
    

Example:

```text
Email must be unique
```

The database is the final safeguard for data integrity.

---

# Quick Example

Requirement:

> User publishes a blog post.

### Request Validation

```text
Valid post ID?
```

---

### Business Validation

```text
User owns post?

↓

Post is still a draft?
```

---

### Database Validation

```text
Status must be one of:

draft

published

archived
```

---

# Best Practices

✅ Request Validation → Validate **input format**.

✅ Service Validation → Validate **business rules**.

✅ Database Validation → Protect **data integrity**.

---

# Interview Question

**Q:** Why do we validate at three different layers?

**Good Answer:**

> Each layer has a different responsibility. Request validation ensures the input is well-formed, the Service Layer enforces business rules, and the database guarantees data integrity. Together they make the application more secure and reliable.

---

# Key Takeaways

- Validation is **layered**, not centralized.
    
- Each layer answers a different question.
    
- Don't put all validation in controllers or services.
    
- The database should always enforce critical constraints.
