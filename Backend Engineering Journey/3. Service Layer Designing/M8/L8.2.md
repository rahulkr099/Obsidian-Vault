# Module 8 — Lesson 8.2: Request Validation vs Business Validation ⭐⭐⭐⭐⭐

> **Goal:** Learn exactly where a validation rule belongs.

This is one of the most common areas of confusion for backend developers.

A simple rule:

- **Request Validation** → _Can I understand this request?_
    
- **Business Validation** → _Can I allow this action?_
    

---

# Request Validation

Checks the **structure and format** of incoming data.

Examples:

```text
Email is required

↓

Password is at least 8 characters

↓

Title is not empty

↓

Price is a positive number
```

These checks **do not require a database**.

Usually done before the service is called.

---

# Business Validation

Checks the **business rules** of your application.

Examples:

```text
User owns the post

↓

Email already registered

↓

Post already published

↓

Product is in stock
```

These checks usually **require database queries**.

They belong in the **Service Layer**.

---

# Example — User Registration

### Request Validation

```text
✓ Email format

✓ Password length

✓ Name is required
```

---

### Business Validation

```text
✓ Email not already registered

✓ Registration is allowed
```

---

# Example — Publish Post

### Request Validation

```text
Post ID is provided
```

---

### Business Validation

```text
Post exists

↓

User owns post

↓

Post is still a draft
```

---

# Easy Decision Rule

Ask yourself:

### **Can I validate it without reading from the database?**

✅ Yes →

```text
Request Validation
```

❌ No →

```text
Business Validation
```

---

# Common Mistakes

## ❌ Checking Email Format in the Service

```javascript
if (!email.includes("@")) {
    ...
}
```

This belongs in **Request Validation**.

---

## ❌ Checking Ownership in Joi/Zod

Example:

```text
User owns this post?
```

Joi or Zod can't answer that.

It requires business knowledge and database access.

It belongs in the **Service Layer**.

---

# Comparison

|Request Validation|Business Validation|
|---|---|
|Email format|Email already exists|
|Required fields|User owns resource|
|Password length|Order already shipped|
|Data type|Coupon expired|

---

# Interview Question

**Q:** Why shouldn't business validation be done in Joi or Zod?

**Good Answer:**

> Joi and Zod validate the structure and format of incoming data. Business validation depends on application rules and often requires database queries, so it belongs in the Service Layer.

---

# Key Takeaways

- **Request Validation** checks the **shape** of the data.
    
- **Business Validation** checks the **rules** of the application.
    
- Request validation happens before the service.
    
- Business validation happens inside the service.
