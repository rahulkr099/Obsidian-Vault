# The Complete Validation Flow

Every request should flow through these stages:

```text
Client
   │
   ▼
Request Validation
   │
   ▼
Controller
   │
   ▼
Service
(Business Validation)
   │
   ▼
Repository
   │
   ▼
Database
(Database Validation)
```

Each layer has **one clear responsibility**.

---

# Example — User Registration

## Step 1: Request Validation

Checks:

```text
✓ Email format

✓ Password length

✓ Name provided
```

If any check fails:

```text
400 Bad Request
```

The request stops here.

---

## Step 2: Business Validation

The Service checks:

```text
Email already exists?

↓

Registration allowed?
```

If a rule fails:

```text
Throw Business Error
```

Example:

```text
ConflictError

ForbiddenError
```

---

## Step 3: Repository

The repository performs the database operation.

```text
Create User
```

No business rules.

---

## Step 4: Database Validation

The database checks:

```text
Unique email

↓

Required fields

↓

Schema constraints
```

If something was missed, the database rejects it.

# Professional Checklist

Whenever you build a feature, ask:

### Request Validation

```text
Is the request valid?
```

---

### Business Validation

```text
Is this action allowed?
```

---

### Database Validation

```text
Can this data be safely stored?
```

If all three answers are **Yes**, you're ready to perform the operation.

---

# Common Mistakes

## ❌ Everything in the Controller

```text
Controller

↓

Format checks

↓

Business rules

↓

Database queries
```

The controller becomes too large.

---

## ❌ Everything in Joi/Zod

Joi or Zod should validate:

- Structure
    
- Types
    
- Required fields
    

Not:

```text
User owns post?

Coupon expired?
```

Those belong in the Service Layer.

---

## ❌ No Database Constraints

Never assume:

```text
The service already checked it.
```

The database must still protect data integrity.

# Interview Question

**Q:** Explain the complete validation flow in a layered backend architecture.

**Good Answer:**

> First, request validation ensures the incoming data is well-formed. Next, the Service Layer validates business rules, such as ownership or business policies. Finally, the database enforces data integrity using constraints like uniqueness and required fields. Each layer has a separate responsibility, making the application more reliable and maintainable.
