# Module 9 — Lesson 9.3: Owner vs Admin Rules ⭐⭐⭐⭐⭐

> **Goal:** Learn the common authorization pattern where **either the resource owner or an admin** can perform an action.

This is one of the most frequently used authorization rules in real applications.

---

# The Rule

Instead of allowing **only the owner**, many applications allow:

```text
Owner

OR

Admin

↓

Allow
```

Otherwise:

```text
Reject
```

---

# Example — Blog App

Requirement:

> Delete a post.

Who can delete it?

```text
Post Owner

OR

Admin
```

Workflow:

```text
Find post

↓

Owner?

↓

Yes → Delete

↓

No

↓

Admin?

↓

Yes → Delete

↓

No → Forbidden
```

---

# Example — E-commerce

Requirement:

> Cancel an order.

Rules:

```text
Customer

↓

Own order

OR

Admin
```

---

# Example — LMS

Requirement:

> Delete a course.

Rules:

```text
Course Creator

OR

Admin
```

---

# Why Is This Useful?

Imagine an inappropriate blog post.

The owner can delete it.

But if the owner doesn't, an **admin** should still be able to remove it.

This provides operational control without taking ownership away from users.

---

# Where Does This Rule Belong?

```text
Controller

↓

Service

↓

Owner?

↓

Admin?

↓

Repository
```

The service decides whether the action is allowed.

---

# Common Mistakes

## ❌ Only Checking Ownership

```text
Owner?

↓

No

↓

Reject
```

Now even administrators can't perform administrative tasks.

---

## ❌ Only Checking Admin

```text
Admin?

↓

No

↓

Reject
```

Now normal users can't manage their own resources.

---

# Best Practice

Think of the rule as:

```text
Owner?

↓

Yes → Allow

↓

No

↓

Admin?

↓

Yes → Allow

↓

No → Reject
```

Simple, readable, and easy to reuse.

---

# Interview Question

**Q:** How would you allow both the resource owner and administrators to delete a resource?

**Good Answer:**

> The Service Layer first checks whether the authenticated user owns the resource. If not, it checks whether the user has the admin role. If either condition is true, the action is allowed; otherwise, the service throws a `ForbiddenError`.

---

# Key Takeaways

- **Owner OR Admin** is a common authorization pattern.
    
- Check ownership first, then admin privileges.
    
- Keep the logic in the **Service Layer**.
    
- Reject the request if neither condition is met.
