# Module 9 — Lesson 9.4: Authorization Best Practices ⭐⭐⭐⭐⭐

> **Goal:** Learn the practical rules professional backend engineers follow when implementing authorization.

This lesson summarizes Module 9.

---

# Rule 1 — Keep Authorization in the Service

✅ Good

```text
Controller

↓

Service

↓

Authorization Check

↓

Repository
```

❌ Bad

```text
Controller

↓

Authorization Check

↓

Service
```

Authorization is a **business rule**, so it belongs in the **Service Layer**.

---

# Rule 2 — Never Trust the Frontend

The frontend may hide a button:

```text
Delete Button Hidden
```

That's good for **user experience**.

But it's **not security**.

Always verify permissions in the backend.

---

# Rule 3 — Authenticate First

Always follow this order:

```text
Authentication

↓

Authorization

↓

Business Action
```

You can't decide what a user can do until you know **who they are**.

---

# Rule 4 — Reuse Authorization Logic

Instead of repeating ownership checks in multiple services:

```text
PostService

↓

Owner Check

---------------

CommentService

↓

Owner Check
```

Extract common logic when appropriate.

Example:

```text
PermissionService
```

or

```text
Authorization Helper
```

This reduces duplication.

---

# Rule 5 — Fail Early

Instead of:

```text
Update Database

↓

Check Permission
```

Do:

```text
Check Permission

↓

Update Database
```

Reject unauthorized requests before making changes.

---

# Professional Authorization Flow

```text
Request

↓

Authentication

↓

Controller

↓

Service

↓

Authorization

↓

Repository
```

This keeps responsibilities clear.

---

# Common Mistakes

## ❌ Authorization in Middleware

Middleware is ideal for:

- JWT verification
    
- Session validation
    

Business rules like:

```text
User owns post?
```

belong in the Service Layer.

---

## ❌ Trusting Client Data

Never trust:

```text
userId

role

isAdmin
```

sent by the client.

Use the authenticated user's information from the server.

---

## ❌ Returning Sensitive Information

If authorization fails:

Return a proper error such as:

```text
ForbiddenError
```

Don't expose internal implementation details.

# Interview Questions

### Q1. Where should authorization logic live?

**Answer:**

> Authorization is a business rule, so it belongs in the Service Layer. Controllers should only pass the authenticated user's information to the service.

---

### Q2. Why isn't hiding a button enough?

**Answer:**

> Because users can still call the API directly. The backend must always enforce authorization, regardless of what the frontend shows.

---

### Q3. What is the correct order?

**Answer:**

```text
Authenticate

↓

Authorize

↓

Execute Business Action
```
