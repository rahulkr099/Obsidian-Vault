```text
Users

Comments

```

Each collection gets its own repository.

---

# UserRepository

Responsible only for user data.

```text
UserRepository

create()

findById()

findByEmail()

findByUsername()

update()

delete()

count()
```

Should NOT contain:

```text
publishPost()

createComment()

likePost()
```

Those belong elsewhere.

---

# PostRepository

Responsible for post data.

```text
PostRepository

create()

findById()

findBySlug()

findPublished()

findDrafts()

findByAuthor()

search()

update()

delete()

count()
```

Notice that every method manages **posts only**.

# Repository Responsibilities

```text
UserRepository
       │
       ▼
User Data
```

```text
PostRepository
       │
       ▼
Post Data
```

```text
CommentRepository
       │
       ▼
Comment Data
```

Each repository owns one entity.

---

# Service Layer Composition

Suppose a user publishes a post.

The Service coordinates:

```text
PostService

↓

PostRepository

↓

UserRepository

↓

ActivityRepository
```

Workflow:

```text
Find Post

↓

Publish Post

↓

Update Author Statistics

↓

Create Activity Log
```

Repositories never call each other.

---

# Another Example

Deleting a user.

The Service coordinates:

```text
Delete User

↓

Delete Posts

↓

Delete Comments

↓

Delete Likes
```

Repositories only execute data operations.

│

│

│   ├── like.repository.js

# Common Mistakes

### ❌ One Repository Does Everything

```text
BlogRepository

↓

Users

Posts

Comments

Likes

Categories
```

Too many responsibilities.

---

### ❌ Controllers Access Repositories

```text
Controller

↓

Repository
```

Always go through the Service Layer.

---

### ❌ Repository Contains Business Rules

Bad:

```text
publishPost()

approveComment()

banUser()
```

These belong in services.

---

# Best Practices

✅ One repository per entity.

✅ Keep repositories independent.

✅ Let services coordinate workflows.

✅ Use clear, business-friendly method names.

✅ Keep repositories focused on data access.

---

# Key Takeaways

- Every major entity should usually have its own repository.
    
- Repositories own data access, not business workflows.
    
- The Service Layer coordinates multiple repositories.
    
- A clean repository structure makes large applications easier to maintain and extend.
