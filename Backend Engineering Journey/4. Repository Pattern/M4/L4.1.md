# Lesson 4.1 — Filtering, Searching & Sorting

## 🎯 Learning Objectives

By the end of this lesson, you will understand:

- Why repositories should build database queries.
    
- Common mistakes when designing search APIs.

# Why Do We Need Advanced Queries?

Basic CRUD is enough for simple applications.

Real-world applications need much more.

Examples:

Blog App

```text
Search posts

↓

Filter by category

↓

Filter by author

↓

Sort by newest

↓

Sort by popularity

↓

Show only published posts
```

If your repository only has:

```text
findAll()
```

it quickly becomes useless.

---

# Understanding the Three Concepts

## 1. Filtering

Filtering removes records that don't match specific conditions.

Example:

```text
All Posts

↓

Category = "Node.js"

↓

Published = true
```

Only matching posts are returned.

---

## 2. Searching

Searching looks for keywords.

Example:

```text
Keyword

↓

"repository"

↓

Find posts containing "repository"
```

Unlike filtering, search usually performs partial text matching.

---

## 3. Sorting

Sorting changes the order of results.

Examples:

```text
Newest First
```

```text
Oldest First
```

```text
Most Popular
```

No records are removed—only their order changes.

---

# Don't Create Too Many Methods

A beginner might design:

```text
findPublished()

findPublishedByAuthor()

findPublishedByCategory()

findPublishedByAuthorSorted()

findPublishedByCategorySorted()

findPublishedByAuthorSortedPaginated()
```

This doesn't scale.

---

# Better Design

Create one flexible method.

```javascript
findPublished(filters)
```

Example:

```javascript
findPublished({
    category,
    author,
    search,
    sort
});
```

One method handles many situations.

---

# Building Repository Interfaces

Instead of dozens of methods:

```text
findByAuthor()

findByCategory()

findByTag()
```

You can often design:

```javascript
search(filters)
```

or

```javascript
findPublished(filters)
```

This keeps your repository clean.

---

# Example: Blog Repository

```text
PostRepository

create()

findById()

findBySlug()

findPublished(filters)

search(filters)

update()

delete()
```

Notice how only **one search method** supports multiple use cases.

---

# Typical Filter Object

A clean filter object might look like:

```javascript
{
    search: "node",
    category: "Backend",
    author: "123",
    tag: "Express",
    sort: "latest"
}
```

The repository decides how to convert this into a database query.

The Service Layer doesn't care.

---

# Repository Responsibilities

The repository converts application filters into database queries.

Example:

```text
Filter Object

↓

Repository

↓

MongoDB Query
```

The service only sends the filters.

---

# Example Flow

```text
Controller

↓

Service

↓

Repository

↓

MongoDB
```

Controller:

```text
Reads query parameters
```

Service:

```text
Passes filters
```

Repository:

```text
Builds database query
```

# Sorting Examples

Repository interface:

```javascript
findPublished({
    sort: "latest"
});
```

Possible values:

```text
latest

oldest

popular

mostViewed
```

The service doesn't know whether MongoDB uses:

```javascript
.sort()

```

or PostgreSQL uses:

```sql
ORDER BY
```

The repository hides the implementation.

---

# Common Mistakes

## ❌ Too Many Methods

```text
findLatest()

findLatestByAuthor()

findLatestByCategory()

findLatestByTag()
```

This becomes impossible to maintain.

---

## ❌ Service Builds Database Queries

Bad:

```javascript
const filters = {
    category,
    status,
    author
};

Post.find(filters);
```

The service is now using Mongoose.

Instead:

```javascript
postRepository.findPublished(filters);
```

---

## ❌ Repository Contains HTTP Logic

Bad:

```javascript
if (req.query.sort === "latest")
```

Repositories should never access `req`.

The Controller reads HTTP requests.

The Service passes clean data.

Each layer has one responsibility.

---

# Best Practices

✅ Use one flexible method instead of many similar methods.

✅ Accept a filter object.

✅ Let the repository build database queries.

✅ Keep HTTP-specific code in controllers.

✅ Keep business decisions in services.

---

# Key Takeaways

- Filtering removes unwanted records.
    
- Searching finds matching keywords.
    
- Sorting changes the order of results.
    
- Repositories should accept **filter objects**, not expose database queries.
    
- Flexible repository methods are easier to maintain than dozens of specialized methods.
