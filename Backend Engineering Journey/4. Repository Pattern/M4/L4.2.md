# What is Pagination?

Pagination means **returning only a small portion of the data instead of everything**.

Imagine your Blog App has:

```text
100,000 Posts
```

Should your API return all of them?

No.

Instead:

```text
Page 1

↓

10 Posts
```

When the user clicks **Next**:

```text
Page 2

↓

Next 10 Posts
```

This is pagination.

---

# Why Do We Need Pagination?

Without pagination:

```text
Database

↓

100,000 Posts

↓

API

↓

Client
```

Problems:

- Slow queries
    
- High memory usage
    
- Large network responses
    
- Poor user experience
    

---

With pagination:

```text
Database

↓

10 Posts

↓

API

↓

Client
```

Much faster and more efficient.

---

# Pagination Belongs in the Repository

Bad:

```text
Service

↓

Gets 100,000 Posts

↓

Keeps First 10
```

The service wastes memory.

Good:

```text
Repository

↓

Database Returns Only 10 Posts
```

The database does the work.

---

# Offset Pagination

Offset pagination uses:

```text
Page Number

+

Limit
```

Example:

```text
Page = 1

Limit = 10
```

Returns:

```text
Posts 1–10
```

Next page:

```text
Page = 2

Limit = 10
```

Returns:

```text
Posts 11–20
```

---

# Repository Interface

```javascript
findPublished({
    page,
    limit
});
```

Example:

```javascript
postRepository.findPublished({
    page: 2,
    limit: 10
});
```

The repository handles the database-specific implementation.

---

# Offset Pagination Pros & Cons

### Advantages

✅ Easy to understand

✅ Easy to implement

✅ Great for admin dashboards

---

### Disadvantages

If new posts are added while browsing:

```text
Page 1

↓

New Post Added

↓

Page 2
```

The user may see duplicate or skipped posts.

Large offsets can also become slower on many databases.

---

# Cursor Pagination

Instead of page numbers, use a **cursor**.

Example:

```text
Last Post ID

↓

Cursor
```

Request:

```text
Give me the next 10 posts after this ID.
```

The database continues from that point.

---

# Repository Interface

```javascript
findPublished({
    cursor,
    limit
});
```

Example:

```javascript
postRepository.findPublished({
    cursor: "6890ab123...",
    limit: 10
});
```

The repository converts the cursor into a database query.

---

# Cursor Pagination Advantages

✅ Faster for large datasets

✅ No duplicate records

✅ Better for feeds

Examples:

- Facebook
    
- Instagram
    
- LinkedIn
    
- X (Twitter)
    

---

# Infinite Scrolling

Infinite scrolling is usually built on **cursor pagination**.

User scrolls:

```text
Load 10 Posts

↓

Scroll

↓

Load 10 More

↓

Scroll

↓

Load 10 More
```

The client keeps asking for the next cursor.

---

# Comparing Pagination Types

|Type|Best For|Drawback|
|---|---|---|
|Offset|Admin panels, tables|Slower for very large datasets|
|Cursor|Social feeds, APIs|More complex implementation|
|Infinite Scroll|Mobile apps, feeds|Requires cursor management|

---

# Repository Design

Instead of:

```text
findPageOne()

findPageTwo()

findPageThree()
```

Design one method:

```javascript
findPublished(options)
```

Example:

```javascript
{
    page,
    limit,
    sort,
    search,
    category
}
```

Or:

```javascript
{
    cursor,
    limit,
    sort
}
```

One flexible method supports many use cases.

---

# Pagination Metadata

A paginated response often contains more than just the records.

Example:

```text
Posts

↓

Current Page

↓

Total Pages

↓

Total Records

↓

Has Next Page
```

The repository can return:

```javascript
{
    data: [...],
    pagination: {
        page,
        limit,
        total,
        totalPages,
        hasNextPage
    }
}
```

This keeps pagination logic centralized.

---

# Common Mistakes

## ❌ Loading Everything

```javascript
const posts = await Post.find();

return posts.slice(0, 10);
```

Very inefficient.

Let the database return only the required records.

---

## ❌ Pagination in the Service

Bad:

```javascript
const posts = await repository.findAll();

return posts.slice(...);
```

Pagination belongs in the repository.

---

## ❌ Different Methods for Every Page

```text
findFirstPage()

findSecondPage()

findThirdPage()
```

Always use one flexible method.

```text
Controller

↓

Reads query parameters

```

The repository builds the query and returns:

```text
10 Posts

Pagination Metadata
```

---

# Best Practices

✅ Perform pagination inside the repository.

✅ Use one flexible repository method.

✅ Return pagination metadata.

✅ Prefer cursor pagination for large datasets and feeds.

✅ Use offset pagination for dashboards and admin panels.

---

# Key Takeaways

- Pagination improves **performance** and **user experience**.
    
- Repositories should handle all pagination logic.
    
- **Offset pagination** is simple and ideal for dashboards.
    
- **Cursor pagination** is faster and better for large or frequently changing datasets.
    
- Return both the data and useful pagination metadata to the caller.

In this module, you learned how to build **flexible query repositories**.

The design pattern is:

```text
Controller
      │
      ▼

      │
      ▼
Service
      │
      ▼
Repository
      │
      ▼
Filtering

```

A well-designed repository exposes **clean methods** like `findPublished(options)` or `search(filters)` while hiding all database-specific query logic.

This keeps your Service Layer simple, reusable, and independent of the database.
