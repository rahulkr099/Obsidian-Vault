# Module 8 — Advanced Repository Design

> **Goal:** Learn how to organize repositories in larger applications using **BaseRepository**, **Generic Repository Pattern**, and **Repository Composition** without creating unnecessary complexity.

# Lesson 8.1 — Generic Repository Pattern

## 🎯 Learning Objectives

By the end of this lesson, you will understand:

- What a Generic Repository is.
    
- What a BaseRepository is.
    
- When generic repositories are useful.
    
- When they become over-engineering.
    
- Best practices for reusable repositories.
    

---

# The Problem

Imagine your project has:

```text
UserRepository

PostRepository

CommentRepository

CategoryRepository

TagRepository
```

Each repository contains:

```text
create()

findById()

update()

delete()
```

You're writing the same CRUD code repeatedly.

This leads to code duplication.

---

# Introducing BaseRepository

Instead of repeating common CRUD methods, create a reusable base class.

```text
BaseRepository

↓

UserRepository

↓

PostRepository

↓

CommentRepository
```

The common logic lives in one place.

---

# What Goes Into BaseRepository?

Only operations that are **truly common**.

Examples:

```text
create()

findById()

update()

delete()

count()
```

Every repository can reuse these methods.

---

# What Stays in Child Repositories?

Entity-specific methods.

Example:

```text
PostRepository

↓

findBySlug()

findPublished()

findPopular()
```

```text
UserRepository

↓

findByEmail()

findByUsername()
```

These methods belong only to their specific repositories.

---

# Visual Architecture

```text
BaseRepository
       │
 ┌─────┼─────┐
 │     │     │
 ▼     ▼     ▼
User  Post Comment
Repo  Repo  Repo
```

Common code is shared.

Specialized code remains separate.

---

# Example Structure

```text
BaseRepository

├── create()

├── findById()

├── update()

├── delete()
```

Then:

```text
PostRepository

↓

findPublished()

↓

findBySlug()
```

Only unique functionality is added.

---

# Why Use a BaseRepository?

Benefits:

✅ Less duplicated code.

✅ Easier maintenance.

✅ Consistent CRUD methods.

✅ New repositories are quicker to build.

---

# The Danger of Over-Abstraction

Many beginners make this mistake:

```text
BaseRepository

↓

Everything
```

Eventually it contains:

```text
CRUD

Search

Analytics

Caching

Relationships

Transactions
```

Now every repository inherits unnecessary code.

This violates the **Single Responsibility Principle**.

---

# Keep BaseRepository Small

A good BaseRepository should contain only generic CRUD operations.

Avoid putting:

- Business logic
    
- Analytics
    
- Complex searches
    
- Entity-specific methods
    

inside it.

---

# Generic Doesn't Mean Universal

Bad idea:

```text
BaseRepository

↓

findPublished()
```

Not every entity has a "published" status.

This method belongs in `PostRepository`.

---

Another example:

```text
findByEmail()
```

Only `UserRepository` needs it.

Don't force every repository to inherit it.

---

Suppose your project has:


Common CRUD methods:


---

# Generic Repository vs Copy-Paste

Without BaseRepository:

```text
UserRepository

↓

200 Lines
```

```text
PostRepository

↓

210 Lines
```

Large portions are identical.

---

With BaseRepository:

```text
BaseRepository

↓

Reusable CRUD

↓

Small Child Repositories
```

Much cleaner.

---

# Common Mistakes

## ❌ Huge BaseRepository

Trying to solve every problem with inheritance.

---

## ❌ Putting Business Logic in BaseRepository

Bad:

```text
publishPost()
```

Business logic never belongs in BaseRepository.

---

## ❌ Entity-Specific Methods

Bad:

```text
findByEmail()
```

Only UserRepository should own this.

---

# Best Practices

✅ Keep BaseRepository small.

✅ Share only generic CRUD operations.

✅ Keep entity-specific methods inside child repositories.

✅ Avoid unnecessary abstraction.

---

# Visual Summary

```text
BaseRepository
      │
      ├── create()
      ├── findById()
      ├── update()
      └── delete()
            │
            ▼
   Entity-Specific Repository
      │
      ├── findPublished()
      ├── findByEmail()
      └── findPopular()
```

---

# Key Takeaways

- A **BaseRepository** reduces duplicated CRUD code.
    
- Only truly generic operations belong in the BaseRepository.
    
- Entity-specific methods should remain in their own repositories.
    
- Overusing abstraction can make your code harder to understand than simple duplication.
    
- Prefer **small, focused repositories** over one massive generic repository.
