# What is Integration Testing?

An integration test verifies that **multiple parts of your application work together correctly**.

Unlike a unit test:

```text
Service

↓

Mock Repository
```

An integration test uses:

```text
Route

↓

Middleware

↓

Controller

↓

Service

↓

Repository

↓

Database
```

Everything is connected.

---

# Unit Test vs Integration Test

## Unit Test

```text
Service

↓

Mock Repository

↓

Assertion
```

Fast.

Isolated.

---

## Integration Test

```text
HTTP Request

↓

Express

↓

Middleware

↓

Controller

↓

Service

↓

Repository

↓

Database

↓

HTTP Response
```

Closer to real user behavior.

# Why Integration Tests?

Suppose your service works.

Your controller works.

Your repository works.

But:

```text
Controller

↓

Wrong Service Function
```

Unit tests may still pass.

Integration tests catch these integration problems.

# Test Database

Never use:

```text
Production Database
```

Instead:

```text

```

Reasons:

- Safe
    
- Isolated
    
- Easy to reset
    
- No production data risk

# Common Beginner Mistakes

## ❌ Using Production Database

Never run integration tests against production data.

Always use a dedicated test database.

---

## ❌ Not Cleaning the Database

Bad:

```text
Test A

↓

Leaves Data

↓

Test B Fails
```

Clean the database between tests.

---

## ❌ Mocking Everything

If everything is mocked:

```text
Route

↓

Mocks

↓

Mocks

↓

Mocks
```

You're no longer performing an integration test.

---

## ❌ Ignoring Database State

Only checking:

```text
201 Created
```

isn't enough.

Also verify:

```text
Data Saved Correctly
```

---

## ❌ Testing Too Many Scenarios in One Test

Bad:

```text
Register

↓

Login

↓

Create Post

↓

Delete Post

↓

Update Profile
```

One integration test should focus on one behavior.

---

# Best Practices

- Use a dedicated test database.
    
- Test complete request flows.
    
- Clean the database after each test.
    
- Verify both responses and database state.
    
- Mock only external services.
    
- Keep tests independent.
    
- Cover success and failure cases.

# Interview Questions

### Q1. What is an integration test?

**Answer:**

An integration test verifies that multiple application components—such as routes, middleware, controllers, services, repositories, and the database—work together correctly.

---

### Q2. Why use a test database?

**Answer:**

A test database keeps tests isolated, prevents accidental modification of production data, and allows tests to start from a known state.

---

### Q3. What's the difference between a unit test and an integration test?

**Answer:**

A unit test verifies one component in isolation using mocks. An integration test verifies that multiple real components work together.

---

### Q4. Should integration tests use a real database?

**Answer:**

Yes, but it should be a dedicated **test database**, never the production database.
