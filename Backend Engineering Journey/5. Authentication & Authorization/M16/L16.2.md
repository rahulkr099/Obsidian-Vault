# Module 16 — Secure Session Management

# Lesson 16.2 — Logout, Token Revocation & Session Management

> **Goal:** Learn how professional backend applications manage user sessions, implement logout correctly, revoke tokens, and invalidate sessions securely.

One of the biggest misconceptions about JWT authentication is:

> **"Logout means deleting the JWT."**

That's **not true**.

JWT authentication is **stateless**, so logout is more than simply removing a token from the browser.

# What is a Session?

A session represents:

```text
Authenticated User

↓

Trusted Connection

↓

Application
```

As long as the session is valid,

the user can continue using protected APIs.

---

# JWT Authentication

Login:

```text
Login

↓

Access Token

↓

Refresh Token

↓

Authenticated Session
```

The session continues until:

- Logout
    
- Refresh token expires
    
- Refresh token revoked
    
- Account disabled
    
- Password changed (depending on your design)
    

---

# The Problem

Rahul logs in.

Server issues:

```text
Access Token

15 Minutes

────────────

Refresh Token

7 Days
```

Rahul clicks:

```text
Logout
```

Question:

Can the server magically destroy the JWT?

No.

JWTs are self-contained tokens.

Once issued, an access token remains valid until it expires unless you have additional revocation mechanisms.

---

# What Logout Actually Means

Logout usually means:

```text
Invalidate Refresh Token

↓

End Session
```

The short-lived access token naturally expires soon after.

The user can no longer obtain new access tokens.

---

# Browser Logout Flow

```text
Logout Request

↓

Authentication

↓

Find Session

↓

Revoke Refresh Token

↓

Clear Cookie

↓

Success
```

Notice:

The refresh token—not the access token—is the main focus.

---

# Why Revoke Refresh Tokens?

Without revocation:

```text
Refresh Token

↓

Still Valid

↓

New Access Token
```

Even after logout, a stolen refresh token could continue creating new access tokens until it expires.

---

With revocation:

```text
Refresh Token

↓

Revoked

↓

Rejected
```

The session truly ends.

---

# Refresh Token Rotation

Professional systems often use:

```text
Login

↓

Refresh Token A

↓

Refresh

↓

Refresh Token B

↓

Refresh

↓

Refresh Token C
```

Every refresh replaces the previous refresh token.

This limits the usefulness of stolen refresh tokens.

---

# Why Rotation Matters

Suppose an attacker steals:

```text
Refresh Token A
```

Meanwhile:

Rahul refreshes:

```text
Refresh Token A

↓

Refresh Token B
```

Later attacker uses:

```text
Refresh Token A
```

Server:

```text
Already Replaced

↓

Reject
```

Rotation reduces replay attacks.

Professional systems often perform:

Session lifetime is a business decision.

# Common Beginner Mistakes

## ❌ Only Deleting the Token on the Client

Bad:

```text
Logout

↓

Delete localStorage
```

If the refresh token remains valid, the session may still be recoverable.

---

## ❌ Never Revoking Refresh Tokens

Revocation is essential for secure logout.

---

## ❌ Using Long-Lived Access Tokens

Bad:

```text
Access Token

30 Days
```

Prefer short-lived access tokens.

---

## ❌ Never Rotating Refresh Tokens

Token rotation helps reduce the impact of stolen refresh tokens.

---

## ❌ Ignoring Password Changes

Password changes are a good opportunity to invalidate existing sessions.

---

# Best Practices

- Keep access tokens short-lived.
    
- Store refresh tokens securely.
    
- Revoke refresh tokens during logout.
    
- Rotate refresh tokens after use.
    
- Support logout from all devices.
    
- Invalidate sessions after password changes or account suspension.

# Interview Questions

### Q1. Why doesn't deleting a JWT log the user out?

**Answer:**

Deleting the JWT from the client only removes the local copy. Any valid refresh token may still be able to obtain new access tokens unless it has been revoked.

---

### Q2. Why are refresh tokens revoked during logout?

**Answer:**

Revoking the refresh token prevents the creation of new access tokens, effectively ending the authenticated session.

---

### Q3. What is refresh token rotation?

**Answer:**

Refresh token rotation replaces the current refresh token with a new one each time it is used. The old refresh token becomes invalid, reducing the risk of replay attacks.

---

### Q4. Why should sessions be invalidated after a password change?

**Answer:**

To ensure that previously authenticated devices or potentially compromised sessions cannot continue accessing the account using old credentials.

# 💡 Backend Engineering Tip

Think of authentication as having **two different lifetimes**:

```text
Access Token

↓

Short-Term Identity

────────────────────

Refresh Token

↓

Long-Term Session
```

The **access token** answers:

> _"Can this request access the API right now?"_

The **refresh token** answers:

> _"Can this user continue their session?"_

By keeping access tokens short-lived and managing refresh tokens carefully through revocation and rotation, you achieve both **strong security** and a smooth user experience.
