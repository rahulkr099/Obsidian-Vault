# What is an OTP?

OTP stands for:

```text
One-Time Password
```

It is a temporary code that:

- Can be used only once.
    
- Expires after a short time.
    
- Confirms that the user controls a second factor.
    

Example:

```text
482931
```

---

# OTP Login Flow

```text
Email

↓

Password

↓

Generate OTP

↓

Send OTP

↓

Verify OTP

↓

JWT
```

The user receives a code and enters it to complete authentication.

---

# Email OTP

Flow:

```text
Login

↓

Generate OTP

↓

Send Email

↓

User Enters OTP

↓

Verify

↓

Login
```

Advantages:

- Easy to implement
    
- No additional app required
    

Disadvantages:

- Depends on email delivery
    
- Less secure if the email account is compromised
    

---

# SMS OTP

Flow:

```text
Login

↓

Generate OTP

↓

SMS

↓

User Enters OTP

↓

Verify
```

Advantages:

- Familiar to users
    
- Works without installing an app
    

Disadvantages:

- SIM swap attacks
    
- SMS delivery delays
    
- Additional cost
    
- Depends on mobile network availability
    

Because of these limitations, many security-focused applications prefer authenticator apps or security keys over SMS when possible.

```text
↓

```

Example:


# OTP Verification

Flow:

```text
User Input

↓

Compare

↓

Stored OTP

↓

Match?

↓

Success
```

Then:

```text
Delete OTP
```

OTP should never be reusable.

# What is TOTP?

TOTP stands for:

```text
Time-Based One-Time Password
```

Unlike Email or SMS OTP,

the backend **doesn't send a code every login**.

Instead:

```text
Phone

↓

Generates Code

↓

Every 30 Seconds
```

No network request is required to generate the code.

---

# TOTP Setup

When enabling MFA:

Backend creates:

```text
Secret Key
```

```text

```

# QR Code Enrollment

Instead of asking the user to type the secret:

Backend generates:

```text
QR Code
```

User:

```text
Scan QR

↓

Authenticator App

↓

Secret Saved
```

The app now shares the same secret as the server.

# TOTP Generation

Both:

```text
Backend

────────────

Authenticator App
```

use:

```text
Secret Key

+

Current Time
```

Both independently generate:

```text
731942
```

No internet connection is needed to generate the code.

# Time Window

Codes usually change every:

```text
30 Seconds
```

Backend typically accepts a small time window (for example, one interval before or after the current one) to account for minor clock differences between devices.

# Email OTP vs TOTP

|Feature|Email OTP|TOTP|
|---|---|---|
|Internet required|✅|❌ (for code generation)|
|Email delivery|Required|Not required|
|Authenticator app|❌|✅|
|User experience|Simple|Slightly more setup|
|Security|Good|Better|

# SMS OTP vs TOTP

|Feature|SMS OTP|TOTP|
|---|---|---|
|Mobile network required|✅|❌ (for code generation)|
|SIM swap risk|Higher|Lower|
|Cost|Yes|No|
|Authenticator app|❌|✅|
|Recommended for high-security apps|Less preferred|✅|

# Common Beginner Mistakes

## ❌ Storing OTP Permanently

OTP should expire quickly and be deleted after successful use.

---

## ❌ Reusing OTP Codes

Each OTP should be valid for only one authentication attempt.

---

## ❌ Storing TOTP Secret Insecurely

The shared secret should be stored securely because anyone with the secret can generate valid codes.

---

## ❌ Ignoring Time Drift

Allow a small verification window for TOTP codes to handle clock differences.

---

## ❌ Believing SMS Is the Most Secure MFA

SMS improves security over passwords alone but has known weaknesses such as SIM swap attacks.

---

# Best Practices

- Prefer TOTP for high-security applications.
    
- Expire OTPs quickly.
    
- Use one-time verification.
    
- Store TOTP secrets securely.
    
- Allow a small time tolerance for TOTP verification.
    
- Provide secure recovery methods for users who lose their authenticator device.

# Interview Questions

### Q1. What is the difference between OTP and TOTP?

**Answer:**

OTP is typically generated by the server and delivered to the user (for example, by email or SMS). TOTP is generated independently by both the server and the authenticator app using a shared secret and the current time.

---

### Q2. Why do authenticator apps not need an internet connection?

**Answer:**

Because they generate codes locally using the stored secret and the current time, without contacting the server.

---

### Q3. Why is TOTP generally preferred over SMS OTP?

**Answer:**

TOTP is not vulnerable to SMS delivery issues or SIM swap attacks and does not require a mobile network to generate codes.

---

### Q4. Why should OTPs expire quickly?

**Answer:**

Short expiration times reduce the opportunity for attackers to reuse intercepted or stolen OTPs.

# 💡 Backend Engineering Tip

A good way to compare MFA methods is:

```text
Email OTP

↓

Easy to Build

↓

Moderate Security

────────────────────

SMS OTP

↓

Widely Used

↓

Better Than Password Alone

────────────────────

TOTP

↓

Authenticator App

↓

Strong Security

↓

Recommended for Production
```

As a backend engineer, you should know **all three** approaches, but for modern web applications, **TOTP with an authenticator app** is generally the preferred software-based MFA solution because it offers a strong balance of security, reliability, and user experience.
