# Recovery Codes

Professional applications generate:

```text
Recovery Codes
```

Example:

```text
X7A9-KP42

LMQ3-TZ81

R4NP-YQ65

...
```

Each code:

- Is used only once.
    
- Can replace the second authentication factor.
    
- Is generated when MFA is enabled.
    

---

# Recovery Flow

```text
Password

↓

Recovery Code

↓

Verify

↓

Login

↓

Generate New Recovery Codes
```

After using one:

```text
Delete Used Code
```

Recovery codes should never be reusable.

---

# Storing Recovery Codes

Never store:

```text
Plain Text
```

Instead:

```text
Recovery Code

↓

Hash

↓

Database
```

Treat recovery codes like passwords.

```text

↓
```


Better:

```text

↓
```

```text

↓
```

# Changing MFA Device

New phone:

```text
Verify Password

↓

Verify Current MFA

↓

Generate New Secret

↓

Scan QR Code

↓

Delete Old Secret
```

Never simply replace the secret without verifying the user's identity.

# Trusted Devices

Many applications offer:

```text
Remember This Device
```

Flow:

```text
Successful MFA

↓

Trusted Device

↓

30 Days

↓

Skip MFA
```

Use trusted devices carefully.

If:

- Password changes
    
- MFA settings change
    
- Suspicious activity detected
    

Trusted device status should be invalidated.

# Common Beginner Mistakes

## ❌ No Recovery Codes

Users can permanently lose access.

---

## ❌ Storing Recovery Codes in Plain Text

Recovery codes should be hashed before storage.

---

## ❌ Allowing MFA Removal Without Verification

Always require:

- Password
    
- Current MFA or recovery code
    

---

## ❌ Unlimited Recovery Code Usage

Recovery codes should be:

- One-time
    
- Removed immediately after use
    

---

## ❌ Never Invalidating Trusted Devices

Trusted devices should be revoked after important security changes.

---

# Best Practices

- Generate recovery codes during MFA setup.
    
- Hash recovery codes before storing them.
    
- Require verification before disabling MFA.
    
- Support trusted devices with expiration.
    
- Reauthenticate for sensitive actions.
    
- Design a secure account recovery process.

# Interview Questions

### Q1. Why are recovery codes important?

**Answer:**

Recovery codes allow users to regain access to their account if they lose access to their MFA device, without permanently locking them out.

---

### Q2. Should recovery codes be stored in plain text?

**Answer:**

No. They should be securely hashed before being stored, similar to passwords.

---

### Q3. Why should disabling MFA require verification?

**Answer:**

Because disabling MFA significantly reduces account security. The backend should verify the user's identity before allowing this action.

---

### Q4. What is a trusted device?

**Answer:**

A trusted device is a device that has successfully completed MFA and is temporarily allowed to skip future MFA prompts according to the application's security policy.
