# What is an Audit Log?

An audit log is a **permanent record of important events**.

Example:

```text
10:15 AM

Rahul

Logged In

IP: 192.xxx.xxx.xxx
```

Later:

```text
10:18 AM

Deleted Post #42
```

These records help explain:

- Who performed the action
    
- What happened
    
- When it happened
    
- Where it happened from
    

---

# Why Are Audit Logs Important?

Audit logs help with:

- Security investigations
    
- Compliance requirements
    
- Debugging
    
- User support
    
- Detecting suspicious activity
    

---

# Application Log vs Audit Log

### Application Log

Records how the application behaves.

Example:

```text
Server Started

Database Connected

Redis Connected

API Error
```

Used by developers.

---

### Audit Log

Records what users or administrators do.

Example:

```text
Login

Password Changed

Deleted User

Role Updated
```

Used for security and accountability.

---

# What Should Be Logged?

Good candidates include:

```text
Login

Logout

Password Change

Email Change

Role Change

MFA Enabled

MFA Disabled

Account Locked
```

Also:

```text
Permission Change

Delete User

Create User

Admin Action
```

Focus on **important security and business events**.

---

# What Should NOT Be Logged?

Never log:

```text
Passwords

JWT Secrets

Refresh Tokens

Client Secrets
```

Also avoid logging sensitive personal data unless absolutely necessary and appropriately protected.

Logs often have wider access than databases, so treat them carefully.

---

# Audit Log Structure

A useful audit record might include:

```text
Timestamp

User ID

Action

Resource

Status

IP Address

User Agent
```

Example:

```text
Time:
2026-08-04 10:15

User:
Rahul

Action:
DELETE_POST

Resource:
Post #42

Status:
Success

IP:
192.xxx.xxx.xxx
```

---

# Typical Audit Log Flow

```text
Request

↓

Authentication

↓

Authorization

↓

Business Logic

↓

Save Audit Log

↓

Response
```

The audit log is usually written after the action has been processed, recording whether it succeeded or failed.

---

# Login History

Professional applications often provide:

```text
Recent Logins
```

Example:

```text
Yesterday

Laptop

India

────────────

Today

Phone

India
```

Users can detect unfamiliar logins.

---

# Failed Login Attempts

Failed logins are also valuable.

Example:

```text
10 Failed Logins

↓

Same IP
```

This could indicate a brute-force attack.

Audit logs help detect these patterns.

---

# Admin Activity

Administrative actions should always be recorded.

Example:

```text
Admin

↓

Deleted User

↓

Reason Recorded
```

This creates accountability.

---

# Sensitive Changes

Always log:

```text
Password Changed

↓

MFA Disabled

↓

Email Changed

↓

Role Changed
```

These events are important during investigations.

---

# Log Integrity

Audit logs should be difficult to alter.

Bad:

```text
Delete Log

↓

No Evidence
```

Professional systems often:

- Restrict who can modify logs.
    
- Store logs separately from application data.
    
- Use append-only storage where possible.
    
- Back up important logs.
    

---

# Log Retention

Audit logs are usually kept for a defined period.

Example:

```text
90 Days

1 Year

7 Years
```

Retention depends on:

- Business needs
    
- Compliance requirements
    
- Storage costs

# Common Beginner Mistakes

## ❌ Logging Passwords

Never log passwords.

Even during development.

---

## ❌ Logging JWT Secrets

Secrets should never appear in logs.

---

## ❌ Only Logging Errors

Audit logs should include successful security events as well.

---

## ❌ Allowing Log Deletion

Audit logs should be protected from unauthorized modification.

---

## ❌ Forgetting Admin Actions

Administrative changes are among the most important events to audit.

---

# Best Practices

- Log important security events.
    
- Log administrative actions.
    
- Protect audit logs from tampering.
    
- Never log secrets.
    
- Keep timestamps accurate.
    
- Define an appropriate retention policy.
    
- Review logs regularly for unusual activity.

# Interview Questions

### Q1. What is an audit log?

**Answer:**

An audit log is a permanent record of important user and system actions used for security, compliance, investigations, and accountability.

---

### Q2. How is an audit log different from an application log?

**Answer:**

Application logs record how the application behaves (errors, startup, performance), while audit logs record important user and administrative actions.

---

### Q3. Should passwords or JWT secrets be logged?

**Answer:**

No. Sensitive credentials and secrets should never be stored in logs.

---

### Q4. Why are audit logs important?

**Answer:**

They help investigate incidents, detect suspicious activity, support compliance, and provide accountability for important actions.

# 💡 Backend Engineering Tip

Think of audit logs as your application's **security history**.

```text
User Action

↓

Authentication

↓

Authorization

↓

Business Logic

↓

Audit Log

↓

Future Investigation
```

If a security incident occurs weeks or months later, audit logs often become the most valuable source of evidence. That's why professional systems treat audit logging as a core security feature—not just an optional debugging tool.
