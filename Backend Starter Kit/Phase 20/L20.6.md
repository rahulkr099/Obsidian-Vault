# Lesson 20.6 — EJS Templates

In **20.5**, we learned the concept of email templates:

```text
Template + Data
      ↓
Rendered HTML
```

Your starter pack places templates inside:

```text
mail/
└── templates/
```

and specifically identifies **EJS templates** as Lesson 20.6.

Now we learn the actual EJS syntax and, importantly, the security difference between **escaped** and **unescaped** output.

---

# 1. What is EJS?

**EJS = Embedded JavaScript Templates.**

It lets us write HTML while inserting JavaScript values into it.

For example:

```ejs
<h1>Hello <%= name %></h1>
```

If:

```js
const data = {
    name: "Rahul"
};
```

the rendered result becomes:

```html
<h1>Hello Rahul</h1>
```

So:

```text
EJS template
     +
JavaScript data
     ↓
HTML
```

---

# 2. Why EJS is useful for emails

Our backend already has JavaScript data.

For example:

```js
const data = {
    name: user.firstName,
    verificationUrl
};
```

Instead of manually building HTML strings:

```js
const html =
    "<h1>Hello " +
    data.name +
    "</h1>";
```

we can write readable HTML:

```ejs
<h1>Hello <%= name %></h1>
```

This is much easier to maintain.

---

# 3. Basic EJS syntax

There are three pieces you should learn first:

```text
<%= value %>
<% JavaScript %>
<%- rawValue %>
```

They look similar, but they have **different purposes**.

---

# 4. `<%= value %>` — escaped output

This is the most important EJS syntax.

```ejs
<h1>Hello <%= name %></h1>
```

It means:

> Evaluate `name` and insert the result as **escaped HTML**.

Suppose:

```js
const name = "Rahul";
```

Result:

```html
<h1>Hello Rahul</h1>
```

Simple.

---

# 5. Why escaping matters

Suppose the value is:

```js
const name = "<script>alert('hello')</script>";
```

If we use:

```ejs
<%= name %>
```

EJS escapes the HTML-sensitive characters.

Conceptually, the output becomes something like:

```html
&lt;script&gt;alert('hello')&lt;/script&gt;
```

The browser/email renderer therefore treats it as text rather than HTML markup.

This is a major security feature.

---

# 6. Think of `<%=` as "safe output"

A useful mental model:

```text
<%= value %>
       ↓
"I want to display this value"
       ↓
Escape HTML
       ↓
Insert it
```

For user-controlled data, this is generally the form you should prefer.

For example:

```ejs
<p>Hello <%= name %></p>
```

Good.

---

# 7. `<% code %>` — execute JavaScript

Now consider:

```ejs
<% if (user) { %>
    <p>Hello <%= user.name %></p>
<% } %>
```

The syntax:

```ejs
<% ... %>
```

runs JavaScript but **doesn't directly output the result**.

For example:

```ejs
<% const greeting = "Hello"; %>

<p><%= greeting %></p>
```

The first line performs JavaScript logic.

The second line outputs the value.

---

# 8. Why would we need `<%`?

Sometimes a template needs small presentation decisions.

For example:

```ejs
<% if (showSupportLink) { %>
    <a href="<%= supportUrl %>">
        Contact Support
    </a>
<% } %>
```

Here:

```text
<% if (...) { %>
```

controls the template structure.

And:

```text
<%= supportUrl %>
```

outputs data.

---

# 9. Don't put business logic in EJS

This is very important.

Technically, EJS lets you run JavaScript.

That doesn't mean you should put your application's business logic there.

Bad:

```ejs
<%
    const user = await User.findById(userId);
    const token = generateResetToken(user);
%>
```

Don't do this.

The template should not become a mini backend.

Instead:

```text
Service
   ↓
Prepare data
   ↓
Template
   ↓
Display data
```

---

# 10. Correct separation

For example:

### Service

```js
const data = {
    name: user.firstName,
    verificationUrl
};
```

### Template

```ejs
<h1>Hello <%= name %></h1>

<p>Please verify your email.</p>

<a href="<%= verificationUrl %>">
    Verify Email
</a>
```

That's clean.

The service decides **what data exists**.

The template decides **how that data is presented**.

---

# 11. `<%- value %>` — unescaped output

Now we reach the dangerous one.

```ejs
<%- html %>
```

This means:

> Insert the value as raw/unescaped HTML.

For example:

```js
const html = "<strong>Hello Rahul</strong>";
```

Template:

```ejs
<div>
    <%- html %>
</div>
```

Result:

```html
<div>
    <strong>Hello Rahul</strong>
</div>
```

The `<strong>` remains HTML.

---

# 12. Why is `<%-` dangerous?

Suppose:

```js
const html = "<img src=x onerror=alert('XSS')>";
```

and you do:

```ejs
<%- html %>
```

You're explicitly telling EJS:

> Trust this string as HTML.

That's why unescaped output should be used carefully.

---

# 13. `<%=` vs `<%-`

Memorize this table:

|Syntax|Meaning|Escapes HTML?|
|---|---|---|
|`<%= value %>`|Output value|✅ Yes|
|`<% code %>`|Execute code|N/A|
|`<%- value %>`|Output raw HTML|❌ No|

This distinction is one of the most important things in today's lesson.

---

# 14. When should you use `<%=`?

For normal dynamic values:

```ejs
<p>Hello <%= name %></p>

<p><%= message %></p>

<p><%= supportEmail %></p>
```

Use:

```text
<%=
```

unless you have a clear reason not to.

---

# 15. When might `<%-` be appropriate?

There are legitimate situations.

For example, suppose **your application itself** generates trusted HTML:

```js
const trustedHtml = renderSomeTrustedComponent();
```

Then you may intentionally insert it:

```ejs
<%- trustedHtml %>
```

Another common use is reusable trusted template fragments/partials.

The key word is:

> **Trusted.**

You should know where that HTML came from.

---

# 16. Never blindly trust user input

Suppose:

```js
const bio = req.body.bio;
```

and the user submits:

```html
<img src=x onerror=alert('attack')>
```

Don't do:

```ejs
<%- bio %>
```

because you're explicitly inserting raw HTML.

Prefer:

```ejs
<%= bio %>
```

if the intended behavior is to display the content as text.

---

# 17. EJS with email links

Here's an important practical example.

Suppose:

```js
const verificationUrl =
    "https://example.com/verify?token=abc123";
```

Template:

```ejs
<a href="<%= verificationUrl %>">
    Verify Email
</a>
```

This is the normal pattern.

The dynamic URL is inserted through escaped output.

---

# 18. EJS with names

For:

```js
const name = "Rahul";
```

use:

```ejs
<h1>Hello <%= name %></h1>
```

Not:

```ejs
<h1>Hello <%- name %></h1>
```

There is no reason to treat a user's name as trusted HTML.

---

# 19. EJS with conditional content

Suppose we want to show a support message only when necessary.

```ejs
<% if (showSupportMessage) { %>

    <p>
        If you need help, contact support.
    </p>

<% } %>
```

And the data:

```js
const data = {
    showSupportMessage: true
};
```

The template decides the presentation condition.

But the service determines the data:

```text
Service
   ↓
showSupportMessage = true
   ↓
Template
```

---

# 20. EJS loops

EJS also supports loops.

For example:

```ejs
<ul>
    <% users.forEach(user => { %>

        <li>
            <%= user.name %>
        </li>

    <% }) %>
</ul>
```

If:

```js
const users = [
    { name: "Rahul" },
    { name: "Priya" },
    { name: "Amit" }
];
```

the output will contain three list items.

Again:

```text
<% ... %>
```

controls the JavaScript logic.

```text
<%= ... %>
```

outputs the data safely.

---

# 21. EJS isn't only for emails

EJS can be used for:

```text
Server-rendered HTML
Emails
HTML documents
Reports
```

But in our current architecture, we're specifically using it for:

```text
Email Templates
```

because our starter pack defines an email template/rendering layer.

# 22. EJS template example

Let's build a simple verification email.

```ejs
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>Verify Email</title>
</head>

<body>

    <h1>Hello <%= name %></h1>

    <p>
        Thanks for creating your account.
    </p>

    <p>
        Please verify your email address:
    </p>

    <p>
        <a href="<%= verificationUrl %>">
            Verify Email
        </a>
    </p>

    <p>
        If the button doesn't work, copy and paste this URL:
    </p>

    <p>
        <%= verificationUrl %>
    </p>

</body>
</html>
```

Notice that all dynamic values use:

```text
<%=
```

That's intentional.

# 23. Where does `name` come from?

The template doesn't magically know:

```text
name
verificationUrl
```

The renderer receives data.

Conceptually:

```js
const data = {
    name: user.firstName,
    verificationUrl
};
```

Then:

```text
data
 ↓
EJS renderer
 ↓
verification.ejs
 ↓
HTML
```

# 25. Template data should be explicit

Suppose your template requires:

```text
name
verificationUrl
```

Create:

```js
const templateData = {
    name: user.firstName,
    verificationUrl
};
```

This is better than:

```js
renderTemplate("verification", {
    ...user,
    verificationUrl
});
```

because the latter may accidentally expose unnecessary fields.

Explicit data is easier to understand and safer to maintain.

---

# 26. A useful convention

You can make the data contract obvious.

For example:

```js
const verificationEmailData = {
    name: user.firstName,
    verificationUrl
};
```

Then:

```js
renderTemplate(
    "verification",
    verificationEmailData
);
```

The relationship is immediately clear:

```text
verification.ejs
        ↕
verificationEmailData
```

---

# 27. EJS and security boundaries

Think of these three things differently:

```text
Trusted template
        +
Application-generated data
        +
User-controlled data
```

They don't have the same trust level.

For example:

```text
verification.ejs
→ trusted application code

verificationUrl
→ application-generated

user.name
→ potentially user-controlled
```

Therefore:

```ejs
<%= user.name %>
```

is appropriate.

And:

```ejs
<%- user.name %>
```

would be unnecessary and potentially dangerous.

---

# 28. EJS does not automatically make everything secure

Using EJS doesn't mean:

```text
"EJS = security"
```

Security depends on how you use it.

You still need to think about:

```text
Input validation
Output escaping
URL validation
Template trust
Sensitive data
Secrets
Authentication tokens
```

The template engine is just one part of the security boundary.

---

# 29. Don't expose secrets in emails

Be especially careful with:

```text
Passwords
Password hashes
API keys
SMTP credentials
Internal tokens
Database credentials
```

A password-reset link may contain a token, but you should design its lifecycle carefully.

Don't send unnecessary secrets just because a template can display them.

---

# 30. Email template security example

Bad:

```ejs
<p>Password: <%= password %></p>
```

Never send a user's password.

Better:

```ejs
<p>
    You can reset your password using the link below.
</p>

<a href="<%= resetUrl %>">
    Reset Password
</a>
```

The email provides a controlled action instead of exposing a secret.

# 31. EJS syntax cheat sheet

Keep this somewhere in your notes:

```text
<%= value %>
→ output escaped value

<%- value %>
→ output raw/unescaped value

<% code %>
→ execute JavaScript without direct output
```

Examples:

```ejs
<p><%= name %></p>
```

```ejs
<% if (showMessage) { %>
    <p>Welcome!</p>
<% } %>
```

```ejs
<%- trustedHtml %>
```

The third one requires special care.

# 32. Common beginner mistakes

### ❌ Mistake 1

Using:

```ejs
<%- name %>
```

for ordinary user data.

Use:

```ejs
<%= name %>
```

instead.

---

### ❌ Mistake 2

Putting database queries in EJS.

Don't.

---

### ❌ Mistake 3

Generating authentication tokens inside EJS.

Don't.

---

### ❌ Mistake 4

Passing the entire database document to the template.

Pass only the required data.

---

### ❌ Mistake 5

Treating all HTML as trusted.

Don't.

---

### ❌ Mistake 6

Putting complicated business logic in `<% %>`.

Keep templates focused on presentation.

# 36. Interview questions

### What is EJS?

EJS is a template engine that allows JavaScript data and logic to be embedded into HTML templates.

### What does `<%= %>` do?

It outputs a value with HTML escaping.

### What does `<%- %>` do?

It outputs a value without HTML escaping.

### What does `<% %>` do?

It executes JavaScript code without directly outputting it.

### Which syntax should normally be preferred for user data?

```text
<%=
```

because it escapes HTML.

### Should database queries be inside EJS?

No.

### Should business logic be inside EJS?

Keep it outside; templates should primarily handle presentation.
