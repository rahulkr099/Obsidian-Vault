# Lesson 9.4 — Joi Fundamentals

Now we move from **understanding validation** to actually **writing validation rules**.

In the previous lessons, we learned:

```text

9.2 → Client vs server validation
9.3 → Trust boundaries
```

Now:

```text
9.4 → How do we actually define validation rules?
```

For this, we'll learn **Joi**.

---

# 1. What is Joi?

Joi is a JavaScript library that lets us define rules for data.

Instead of manually writing:

```js
if (!email) {
    // error
}

if (typeof email !== "string") {
    // error
}

if (!email.includes("@")) {
    // error
}
```

we can describe the rules using a schema:

```js
const schema = Joi.object({
    email: Joi.string().email().required()
});
```

Think of Joi as a **rule builder**.

```text
Joi
 ↓
Define rules
 ↓
Validate data
 ↓
Valid / Invalid
```

---

# 2. Why do we need a validation library?

Without a library, imagine validating a signup request manually:

```js
if (!req.body.email) {
    return res.status(400).json({
        message: "Email is required"
    });
}

if (typeof req.body.email !== "string") {
    return res.status(400).json({
        message: "Email must be a string"
    });
}

if (!req.body.email.includes("@")) {
    return res.status(400).json({
        message: "Invalid email"
    });
}
```

Then password:

```js
if (!req.body.password) {
    // ...
}

if (typeof req.body.password !== "string") {
    // ...
}

if (req.body.password.length < 8) {
    // ...
}
```

Then name:

```js
if (!req.body.name) {
    // ...
}
```

It quickly becomes repetitive.

Joi lets us describe these rules declaratively.

---

# 3. Imperative vs declarative validation

This is a useful programming concept.

### Imperative

You tell JavaScript **how to check** everything:

```js
if (!email) {
    // ...
}

if (typeof email !== "string") {
    // ...
}
```

You're describing the procedure.

### Declarative

You describe **what the data should look like**:

```js
const schema = Joi.object({
    email: Joi.string().email().required()
});
```

You're describing the rules.

So:

```text
Manual validation
      ↓
"How should I check this?"

Joi schema
      ↓
"What should valid data look like?"
```

# 5. Your first Joi schema

Let's start extremely small.

Suppose we expect:

```json
{
    "name": "Rahul"
}
```

We can write:

```js
import Joi from "joi";

const schema = Joi.object({
    name: Joi.string()
});
```

This says:

> We expect an object containing a `name` field, and `name` should be a string.

That's all.

---

# 6. Understanding `Joi.object()`

Look at:

```js
Joi.object({
    name: Joi.string()
});
```

Break it apart:

```text
Joi
 │
 └── object()
       │
       └── name
             │
             └── string()
```

`Joi.object()` tells Joi:

> "The value I'm validating should be an object."

Inside it, we define the fields.

For example:

```js
const userSchema = Joi.object({
    name: Joi.string(),
    email: Joi.string(),
    age: Joi.number()
});
```

Conceptually:

```text
Object
├── name  → string
├── email → string
└── age   → number
```

---

# 7. What is a schema?

A schema is simply a **description of valid data**.

For example:

```js
const userSchema = Joi.object({
    name: Joi.string(),
    email: Joi.string(),
    age: Joi.number()
});
```

The schema describes:

```text
User
│
├── name → string
├── email → string
└── age → number
```

Important:

> A schema does not itself validate data.

It defines the rules.

We still need to give data to the schema.

---

# 8. The `validate()` method

Now we actually validate something.

```js
const data = {
    name: "Rahul"
};

const result = schema.validate(data);
```

Joi checks:

```text
data
 ↓
schema
 ↓
validation
```

The result contains information about whether validation succeeded.

Conceptually:

```js
{
    value: ...,
    error: ...
}
```

---

# 9. A valid example

Schema:

```js
const schema = Joi.object({
    name: Joi.string()
});
```

Data:

```js
const data = {
    name: "Rahul"
};
```

Then:

```js
const result = schema.validate(data);
```

The validation should succeed.

Conceptually:

```text
name = "Rahul"
      ↓
Is it a string?
      ↓
YES
      ↓
Valid
```

---

# 10. An invalid example

Same schema:

```js
const schema = Joi.object({
    name: Joi.string()
});
```

But:

```js
const data = {
    name: 123
};
```

Now:

```text
name = 123
    ↓
Is it a string?
    ↓
NO
    ↓
Validation error
```

So we can check:

```js
const { error, value } = schema.validate(data);

if (error) {
    console.log(error);
}
```

This is the basic Joi workflow.

---

# 11. `required()`

Now we need an important rule.

By default, a field isn't necessarily required just because it appears in the schema.

For example:

```js
const schema = Joi.object({
    name: Joi.string()
});
```

We're describing `name` as a string if supplied.

If we want:

> "The request MUST contain name."

we use:

```js
const schema = Joi.object({
    name: Joi.string().required()
});
```

Now:

```text
name missing
    ↓
INVALID
```

---

# 12. Understanding the chain

Look at:

```js
Joi.string().required()
```

Read it from left to right:

```text
Joi.string()
     ↓
The value must be a string
     ↓
.required()
     ↓
The value must be present
```

This style is called **method chaining**.

You'll see it everywhere in Joi.

---

# 13. Multiple fields

Let's create a simple signup schema:

```js
const signupSchema = Joi.object({
    name: Joi.string().required(),
    email: Joi.string().required(),
    password: Joi.string().required()
});
```

Now our expected structure is:

```text
Signup
├── name     → required string
├── email    → required string
└── password → required string
```

But notice:

> We haven't said that `email` must actually be an email.

We'll learn that in Lesson 9.8.

Right now we're just learning Joi fundamentals.

---

# 14. Adding more rules

We can chain more rules.

For example:

```js
const schema = Joi.object({
    name: Joi.string()
        .min(2)
        .max(50)
        .required()
});
```

This means:

```text
name
 ↓
must be a string
 ↓
minimum 2 characters
 ↓
maximum 50 characters
 ↓
must exist
```

Joi lets us describe this cleanly.

---

# 15. `min()` and `max()`

For strings:

```js
Joi.string().min(2)
```

means:

> String must have at least 2 characters.

And:

```js
Joi.string().max(50)
```

means:

> String must have at most 50 characters.

Together:

```js
Joi.string().min(2).max(50)
```

means:

```text
2 ≤ length ≤ 50
```

---

# 16. Number validation

Joi has different types.

For numbers:

```js
Joi.number()
```

Example:

```js
const schema = Joi.object({
    age: Joi.number()
});
```

Then:

```json
{
    "age": 22
}
```

can satisfy the number rule.

---

# 17. Integer validation

Sometimes we don't want any number.

For example:

```text
22.5
```

may not make sense for age.

We can use:

```js
Joi.number().integer()
```

Now:

```text
22
```

is valid.

But:

```text
22.5
```

is not.

---

# 18. Minimum and maximum numbers

We can also write:

```js
age: Joi.number()
    .integer()
    .min(18)
    .max(100)
    .required()
```

Now the rules are:

```text
age
 ↓
number
 ↓
integer
 ↓
>= 18
 ↓
<= 100
 ↓
required
```

That's much easier to understand than manually writing multiple `if` statements.

# 19. A complete beginner schema

Let's combine what we've learned.

```js
import Joi from "joi";

const userSchema = Joi.object({
    name: Joi.string()
        .min(2)
        .max(50)
        .required(),

    age: Joi.number()
        .integer()
        .min(18)
        .required(),

    email: Joi.string()
        .required()
});
```

Think of this as a contract:

```text
USER
│
├── name
│    ├── string
│    ├── min 2
│    ├── max 50
│    └── required
│
├── age
│    ├── number
│    ├── integer
│    ├── min 18
│    └── required
│
└── email
     ├── string
     └── required
```

# 20. Validate the object

Now:

```js
const data = {
    name: "Rahul",
    age: 22,
    email: "rahul@example.com"
};

const { error, value } = userSchema.validate(data);
```

Then:

```js
if (error) {
    console.log("Validation failed");
} else {
    console.log("Validation passed");
}
```

The basic workflow is:

```text
Schema
  +
Data
  ↓
validate()
  ↓
┌──────────────┐
│ error/value  │
└──────────────┘
```

---

# 21. What is `value`?

This is important.

When Joi validates data, the returned `value` represents the validated result.

For example:

```js
const { error, value } = userSchema.validate(data);
```

You shouldn't automatically assume:

```js
value === original data
```

because Joi can perform certain transformations depending on your schema/options.

This becomes especially important when we learn:

```text
9.17 → stripping unknown fields
9.18 → normalization
```

So think:

```text
input
  ↓
Joi
  ↓
validated value
```

---

# 22. What is `error`?

If the input doesn't satisfy the schema:

```js
const { error, value } = schema.validate(data);
```

then `error` contains information about what went wrong.

For example:

```text
name
 ↓
too short
 ↓
error
```

or:

```text
age
 ↓
not a number
 ↓
error
```

Later we'll learn how to transform these Joi errors into your API's standard error format.

---

# 23. `abortEarly`

Here's an important Joi option.

Suppose the user sends:

```json
{
    "name": "",
    "email": "hello",
    "age": 10
}
```

There are multiple problems.

We often want to know **all** validation problems instead of stopping after the first one.

We can use:

```js
schema.validate(data, {
    abortEarly: false
});
```

Conceptually:

```text
abortEarly: true
      ↓
Stop after first error

abortEarly: false
      ↓
Collect validation errors
```

For APIs, `abortEarly: false` is often useful because the frontend can receive multiple field errors in one response.

---

# 24. Example with `abortEarly: false`

```js
const schema = Joi.object({
    name: Joi.string().min(2).required(),
    age: Joi.number().integer().min(18).required()
});

const data = {
    name: "",
    age: 10
};

const { error } = schema.validate(data, {
    abortEarly: false
});
```

Now Joi can report problems with both fields rather than stopping at the first error.

Later, we'll transform those errors into something like:

```json
{
    "success": false,
    "message": "Validation failed",
    "errors": [
        {
            "field": "name",
            "message": "..."
        },
        {
            "field": "age",
            "message": "..."
        }
    ]
}
```

# 25. Joi is not middleware

This distinction is extremely important.

Joi is:

```text
Validation library
```

It is **not**:

```text
Express middleware
```

At this stage:

```text
Joi
 ↓
Defines and checks rules
```

Later we'll create:

```text
validate.middleware.js
```

which connects Joi to Express:

```text
HTTP request
      ↓
Validation middleware
      ↓
Joi schema
      ↓
Controller
```

So:

```text
Joi
=
validation engine

Middleware
=
Express request pipeline integration
```

---

# 26. Why separate schemas from middleware?

This is the architecture we're working toward.

```text
validations/
    auth.validation.js
```

contains rules:

```js
const signupSchema = Joi.object({
    // rules
});
```

while:

```text
middlewares/
    security/
        validate.middleware.js
```

contains the mechanism that executes those rules.

So:

```text
Schema
   ↓
"What is valid?"

Middleware
   ↓
"When/how should validation happen?"
```

This separation is powerful.

# 27. Example architecture

Eventually:

```js
// validations/auth.validation.js

export const signupSchema = Joi.object({
    name: Joi.string().required(),
    email: Joi.string().email().required(),
    password: Joi.string().required()
});
```

Then:

```js
// routes/auth.routes.js

router.post(
    "/signup",
    validate(signupSchema),
    authController.signup
);
```

The route doesn't need to know how Joi works internally.

That's good architecture.

# 29. Common beginner mistake #1

Writing:

```js
const schema = {
    name: Joi.string()
};
```

and expecting it to be a Joi schema.

That's just a normal JavaScript object.

You need:

```js
const schema = Joi.object({
    name: Joi.string()
});
```

The `Joi.object()` creates the Joi object schema.

---

# 30. Common beginner mistake #2

Thinking:

```js
const schema = Joi.object({
    name: Joi.string()
});
```

automatically validates everything.

It doesn't.

You still need:

```js
schema.validate(data);
```

Think:

```text
Define schema
     ↓
validate data
```

Two separate operations.

---

# 31. Common beginner mistake #3

Forgetting `required()`.

You write:

```js
email: Joi.string()
```

and think:

> "Email is required."

Not necessarily.

If you want the field to be mandatory:

```js
email: Joi.string().required()
```

Remember:

```text
type rule
    ≠
required rule
```

---

# 32. Common beginner mistake #4

Thinking Joi replaces all application rules.

Suppose:

```js
email: Joi.string().email().required()
```

passes.

That only tells us:

> The email has an acceptable format.

It does **not** tell us:

> This email isn't already registered.

That is business logic.

For example:

```text
Joi
 ↓
"Is this a valid email?"

Service
 ↓
"Does this email already belong to a user?"
```
