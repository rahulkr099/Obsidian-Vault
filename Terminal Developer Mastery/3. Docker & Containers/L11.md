# Backend Dockerfile

```docker
FROM node:22-slim

WORKDIR /app

COPY package*.json ./

RUN npm install --omit=dev

COPY . .

ENV NODE_ENV=production

EXPOSE 5000

CMD ["node", "src/server.js"]
```

---

# Better Backend Dockerfile (Multi-stage)

```docker
# Dependencies
FROM node:22 AS deps

WORKDIR /app

COPY package*.json ./

RUN npm ci

# Runtime
FROM node:22-slim

WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules

COPY . .

ENV NODE_ENV=production

EXPOSE 5000

CMD ["node", "src/server.js"]
```

This reduces unnecessary rebuilds and keeps runtime images cleaner.

---

# Frontend Dockerfile

```docker
# Build
FROM node:22 AS builder

WORKDIR /app

COPY package*.json ./

RUN npm ci

COPY . .

RUN npm run build

# Runtime
FROM nginx:alpine

COPY --from=builder /app/dist /usr/share/nginx/html

EXPOSE 80
```

The React build output is served by Nginx.

# Complete compose.yaml

```yaml
services:

  frontend:
    build: ./frontend
    ports:
      - "3000:80"
    depends_on:
      - backend

  backend:
    build: ./backend

    ports:
      - "5000:5000"

    environment:
      PORT: 5000
      NODE_ENV: production
      MONGODB_URI: mongodb://mongodb:27017/app
      REDIS_URL: redis://redis:6379

    depends_on:
      - mongodb
      - redis

  mongodb:
    image: mongo:8

    volumes:
      - mongo-data:/data/db

  redis:
    image: redis:8

volumes:
  mongo-data:
```

# Health Checks

Compose supports health checks.

```yaml
mongodb:
  image: mongo:8

  healthcheck:
    test: ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"]
    interval: 30s
    timeout: 10s
    retries: 5
```

Health checks help detect unhealthy containers.

# Security Improvements

Good:

- Use non-root users inside containers.
- Keep images updated.
- Pin image versions.
- Keep secrets out of images.
- Expose only required ports.
- Use minimal base images where practical.

# 💡 Senior Backend Engineer Insight

The `compose.yaml` you've learned is excellent for **local development**, but production deployments often have additional requirements:

- HTTPS termination with **Nginx** or **Traefik**
- Automatic SSL certificates
- CI/CD pipelines that build and push images
- External managed databases instead of containerized databases
- Monitoring and centralized logging
- Secrets management
- Backups and disaster recovery

For local development:

```
Developer
     │
docker compose up -d
```

For production:

```
Git Push
    │
CI/CD Pipeline
    │
Build Docker Images
    │
Push to Registry
    │
Deploy to Server
```

This separation between development and production is the workflow used by many professional engineering teams.
