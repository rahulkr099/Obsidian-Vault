# Module 3 — Lesson 6: Docker Networking 🌐

> **"Containers are isolated by default. Docker networking lets them communicate securely."**

One of Docker's biggest strengths is that containers can talk to each other **without exposing everything to the outside world**. This is how real applications are built—for example, an Express backend talking to MongoDB or Redis.

# Why Networking Matters

A typical MERN backend looks like this:

```
React
   │ HTTP
   ▼
Express API
   │ MongoDB Driver
   ▼
MongoDB
```

With Docker:

```
Browser
   │
localhost:3000
   │
React Container
   │
Express Container
   │
MongoDB Container
```

Each part runs in its own container.

---

# Containers Are Isolated

Suppose you run:

```bash
docker run -d nginx
```

This container has:

- Its own filesystem
- Its own processes
- Its own network namespace

It **cannot automatically communicate** with another container.

---

# Docker Network Drivers

Docker provides several network drivers.

|Driver|Purpose|Common Use|
|---|---|---|
|bridge|Default network|Single-host applications ⭐⭐⭐⭐⭐|
|host|Uses host networking|High-performance services|
|none|No networking|Security/testing|
|overlay|Multi-host networking|Docker Swarm|
|macvlan|Appears as physical device|Special enterprise setups|

For most backend projects, you'll mainly use **bridge**.

---

# Default Bridge Network

Check existing networks:

```bash
docker network ls
```

Example:

```
NETWORK ID      NAME      DRIVER
abc123          bridge    bridge
def456          host      host
ghi789          none      null
```

Docker automatically creates the default bridge network.

---

# Creating a Custom Network

Instead of using the default bridge, create your own.

```bash
docker network create backend-network
```

Verify:

```bash
docker network ls
```

Output:

```
backend-network
```

---

# Why Custom Networks?

Imagine:

```
Express

↓

backend-network

↓

MongoDB
```

Containers on the same network can communicate using **container names**.

This is one of Docker's most useful features.

---

# Running Containers on a Network

Start MongoDB.

```bash
docker run -d \
  --name mongodb \
  --network backend-network \
  mongo
```

Start Express (example image).

```bash
docker run -d \
  --name backend \
  --network backend-network \
  node:22
```

Both are now connected.

---

# Docker DNS

Docker automatically creates DNS entries.

Instead of:

```
192.168.1.15
```

Use:

```
mongodb
```

Your Express app connects like this:

```jsx
const uri = "mongodb://mongodb:27017/mydb";
```

Notice:

```
mongodb
```

is the **container name**, not an IP address.

This is one of Docker's best features.

---

# Why Not Use IP Addresses?

Bad:

```
mongodb://172.18.0.5:27017
```

IPs change.

Good:

```
mongodb://mongodb:27017
```

Container names remain stable within the network.

# Exposing Ports

Inside the Docker network:

```
backend → mongodb
```

No exposed ports needed.

Outside (browser):

```
Browser

↓

localhost:3000

↓

backend
```

Expose only what users need.

Example:

```bash
docker run -p 3000:3000 my-api
```

---

# Internal vs External Ports

```
Host

3000
 │
 ▼
Container

3000
```

Or:

```bash
docker run -p 8080:80 nginx
```

Meaning:

```
Host 8080

↓

Container 80
```

---

# Inspect a Network

```bash
docker network inspect backend-network
```

You'll see:

- Connected containers
- IP addresses
- Gateway
- Driver
- Subnet

---

# Connect Existing Containers

Already running?

```bash
docker network connect backend-network nginx
```

Disconnect:

```bash
docker network disconnect backend-network nginx
```

---

# Remove a Network

Network must be empty.

```bash
docker network rm backend-network
```

Or clean unused networks:

```bash
docker network prune
```

---

# Testing Connectivity

Enter one container.

```bash
docker exec -it backend bash
```

Try reaching MongoDB.

```bash
ping mongodb
```

Or:

```bash
getent hosts mongodb
```

If DNS resolves, networking is working.

> Note: Some minimal images (like Alpine) may not include `ping` by default.

Project structure:

```
project/

├── backend
└── mongo
```

Backend environment:

```
MONGODB_URI=mongodb://mongodb:27017/app
```

No IP address needed.

# Redis Example

Start Redis.

```bash
docker run -d \
  --name redis \
  --network backend-network \
  redis
```

Connect:

```jsx
const redisHost = "redis";
```

Again:

Use the **container name**.

---

# Common Network Layout

```
                Internet
                    │
                    ▼
             Nginx Container
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
   Express API            React App
         │
         ▼
     MongoDB
         │
         ▼
       Redis
```

Only Nginx exposes ports publicly.

Everything else communicates internally.

---

# Development vs Production

Development:

```
React
 │
Express
 │
MongoDB
```

All containers may expose ports for convenience.

Production:

```
Internet
    │
 Nginx
    │
 Express
    │
MongoDB
```

Only Nginx is exposed.

---

# Network Best Practices

### Use Custom Networks

Instead of relying on the default bridge network.

---

### Use Container Names

Good:

```
mongodb
```

Avoid:

```
172.17.0.2
```

---

### Expose Only Required Ports

Example:

Expose:

```
Express
```

Don't expose:

```
MongoDB
Redis
```

Unless absolutely necessary.

---

### Separate Applications

Different projects should use different Docker networks.

---

# Common Mistakes

### Using localhost Inside a Container

Wrong:

```jsx
mongodb://localhost:27017
```

Inside a container, `localhost` refers to **that same container**, not another one.

Correct:

```jsx
mongodb://mongodb:27017
```

---

### Hardcoding IP Addresses

Avoid fixed container IPs.

Use Docker DNS instead.

---

### Exposing Databases Publicly

Avoid:

```bash
docker run -p 27017:27017 mongo
```

Unless you specifically need external access.

# 💡 Backend Engineer Insight

Most production backend systems follow a simple networking pattern:

```
Internet
    │
    ▼
Nginx (public)
    │
    ▼
Express API (private)
    │
 ┌──┴───────────┐
 ▼              ▼
MongoDB      Redis
(private)    (private)
```

Only the **entry point** (such as Nginx or an API gateway) is exposed to the outside world. Databases and caches stay on private Docker networks, reducing attack surface and improving security.
