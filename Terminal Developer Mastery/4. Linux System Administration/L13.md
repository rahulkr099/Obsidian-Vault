# Phase 1 — Prepare the Server

Update packages:

```bash
sudo apt update
sudo apt upgrade -y
```

Install essentials:

```bash
sudo apt install -y \
git \
curl \
wget \
build-essential \
unzip \
nginx \
ufw \
fail2ban
```

---

# Phase 2 — Create a Service User

```bash
sudo adduser --system nodeapp
```

Create application directory:

```bash
sudo mkdir -p /opt/backend
```

Assign ownership:

```bash
sudo chown -R nodeapp:nodeapp /opt/backend
```

Verify:

```bash
ls -ld /opt/backend
```

---

# Phase 3 — Install Node.js

Example using NodeSource (adjust for your desired LTS version):

```bash
curl -fsSL <https://deb.nodesource.com/setup_22.x> | sudo -E bash -
sudo apt install -y nodejs
```

Verify:

```bash
node -v
npm -v
```

---

# Phase 4 — Clone the Project

Become the application user:

```bash
sudo -u nodeapp -H bash
```

Clone:

```bash
cd /opt/backend

git clone YOUR_REPOSITORY_URL app

cd app
```

Install dependencies:

```bash
npm ci
```

Why `npm ci`?

- Faster
- Uses `package-lock.json`
- Better for production
- More reproducible

---

# Phase 5 — Configure Environment Variables

Create:

```
/opt/backend/app/.env
```

Example:

```
PORT=5000

MONGODB_URI=...

JWT_SECRET=...

NODE_ENV=production
```

Secure it:

```bash
chmod 600 .env
```

---

# Phase 6 — Create systemd Service

```bash
sudo nano /etc/systemd/system/backend.service
```

Example:

```
[Unit]
Description=Backend API
After=network.target

[Service]
User=nodeapp
WorkingDirectory=/opt/backend/app
ExecStart=/usr/bin/node server.js
Restart=always
EnvironmentFile=/opt/backend/app/.env

[Install]
WantedBy=multi-user.target
```

Reload:

```bash
sudo systemctl daemon-reload
```

Enable:

```bash
sudo systemctl enable backend
```

Start:

```bash
sudo systemctl start backend
```

Verify:

```bash
systemctl status backend
```

---

# Phase 7 — Verify the Backend

Test locally:

```bash
curl <http://localhost:5000/health>
```

Expected:

```json
{
  "status": "ok"
}
```

If it fails:

```bash
journalctl -u backend -f
```

---

# Phase 8 — Configure Nginx

Create:

```bash
sudo nano /etc/nginx/sites-available/backend
```

Example:

```
server {
    listen 80;

    server_name example.com www.example.com;

    location / {
        proxy_pass <http://127.0.0.1:5000>;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Enable:

```bash
sudo ln -s \
/etc/nginx/sites-available/backend \
/etc/nginx/sites-enabled/
```

Test:

```bash
sudo nginx -t
```

Reload:

```bash
sudo systemctl reload nginx
```

---

# Phase 9 — Enable HTTPS

Install Certbot:

```bash
sudo apt install certbot python3-certbot-nginx
```

Run:

```bash
sudo certbot --nginx
```

Certbot can configure Nginx automatically if your DNS is already pointing to the server.

Verify:

```bash
curl <https://your-domain.com/health>
```

---

# Phase 10 — Configure Firewall

Allow:

```bash
sudo ufw allow OpenSSH

sudo ufw allow "Nginx Full"
```

Enable:

```bash
sudo ufw enable
```

Verify:

```bash
sudo ufw status
```

---

# Phase 11 — Enable Fail2Ban

```bash
sudo systemctl enable --now fail2ban
```

Check:

```bash
sudo fail2ban-client status
```

---

# Phase 12 — Verify Listening Ports

```bash
ss -tulpn
```

Expected:

```
22

80

443
```

Your Node.js app should typically listen on `127.0.0.1:5000`, not on a public interface.

# Interview Scenario

**Question:**

> "Your Express API suddenly returns 502 Bad Gateway from Nginx. How do you troubleshoot it?"

A systematic answer:

1. Check if the backend service is running:
    
    ```bash
    systemctl status backend
    ```
    
2. Review application logs:
    
    ```bash
    journalctl -u backend -n 100
    ```
    
3. Verify the backend responds locally:
    
    ```bash
    curl <http://localhost:5000/health>
    ```
    
4. Test the Nginx configuration:
    
    ```bash
    sudo nginx -t
    ```
    
5. Check Nginx logs:
    
    ```bash
    tail -n 100 /var/log/nginx/error.log
    ```
    
6. Ensure the proxy target (`127.0.0.1:5000`) matches the application's listening address.
    
7. Restart or reload only after identifying the cause.
    

This demonstrates structured troubleshooting rather than guessing.
