# Module 4 — Lesson 2: Linux Users & Groups 👥

> **"Linux is a multi-user operating system. Understanding users and groups is essential for securing servers and running production applications."**

Almost every Linux permission issue comes down to one of these questions:

- **Who** is running this process?
- **Who** owns this file?
- **Which groups** does this user belong to?

Master these concepts, and Linux administration becomes much easier.

# Why Users Matter

Imagine a production server running:

- Nginx
- Node.js API
- MongoDB
- Redis
- PostgreSQL

Should all of them run as `root`?

**No.**

Each service should run as its own user to reduce risk.

---

```
Linux Server

├── root
├── rahul
├── nginx
├── mongodb
├── redis
└── postgres
```

Each user has:

- Own files
- Own permissions
- Own processes
- Own home directory

# The Root User

The most powerful account:

```
root
```

Root can:

- Read any file
- Delete any file
- Kill any process
- Install software
- Create users
- Change passwords
- Reboot the machine

Check current user:

```bash
whoami
```

Example:

```
rahul
```

---

# Your User Identity

Current username:

```bash
whoami
```

Current user ID:

```bash
id
```

Example:

```
uid=1000(rahul)

gid=1000(rahul)

groups=1000(rahul),27(sudo),999(docker)
```

Meaning:

- User ID (UID)
- Primary Group ID (GID)
- All group memberships

---

# Understanding UID and GID

Every user has a unique number.

Example:

```
User

↓

rahul

↓

UID 1000
```

Groups also have IDs.

```
developers

↓

GID 1010
```

Linux internally works with IDs rather than names.

---

View your account:

Examples:

# Create a User

Ubuntu/Mint (recommended):

```bash
sudo adduser alice
```

You'll be prompted for:

- Password
- Full name (optional)
- Other details (optional)

---

Alternative:

```bash
sudo useradd -m alice
```

The `-m` flag creates the home directory.

---

# Verify User

```bash
id alice
```

---

# Switch Users

Temporarily:

```bash
su alice
```

Better:

```bash
su - alice
```

The `-` loads the target user's environment (like their home directory and shell settings).

Exit:

```bash
exit
```

---

# Run One Command as Another User

```bash
sudo -u alice whoami
```

Output:

```
alice
```

Very useful for testing permissions.

---

# Delete a User

Keep files:

```bash
sudo userdel alice
```

Delete home directory too:

```bash
sudo userdel -r alice
```

Be careful with `-r`.

---

# Change Password

Own password:

```bash
passwd
```

Another user's password:

```bash
sudo passwd alice
```

---

# Lock an Account

Prevent login:

```bash
sudo passwd -l alice
```

Unlock:

```bash
sudo passwd -u alice
```

Useful for temporarily disabling accounts.

---

# Groups

Groups simplify permission management.

Example:

```
developers

↓

Rahul

Aman

Priya
```

Instead of granting permissions individually, grant them to the group.

---

# View Groups

Current user:

```bash
groups
```

Or:

```bash
id
```

---

# View Group Database

```bash
cat /etc/group
```

Example:

```
developers:x:1001:rahul,aman
```

---

# Create a Group

```bash
sudo groupadd developers
```

---

# Add User to Group

```bash
sudo usermod -aG developers alice
```

Flags:

- `a` → append
- `G` → supplementary groups

⚠️ Never omit `-a` when adding groups, or you may replace the user's existing supplementary groups.

---

# Verify Group Membership

```bash
groups alice
```

Or:

```bash
id alice
```

---

# Remove User from Group

```bash
sudo gpasswd -d alice developers
```

---

# Primary vs Supplementary Groups

Primary:

```
alice
```

Supplementary:

```
developers

docker

sudo
```

One primary group.

Many supplementary groups.

---

# Change Primary Group

```bash
sudo usermod -g developers alice
```

---

# Understanding sudo

Instead of logging in as root:

```bash
sudo apt update
```

Linux temporarily grants administrative privileges.

Advantages:

- Safer
- Logged
- Limited in scope

---

# Who Can Use sudo?

Check:

```bash
groups
```

Look for:

```
sudo
```

If present:

You can use administrative commands.

---

# Add User to sudo Group

```bash
sudo usermod -aG sudo alice
```

---

# Verify sudo Access

Switch:

```bash
su - alice
```

Test:

```bash
sudo whoami
```

Expected:

```
root
```

# Important Files

Users:

```
/etc/passwd
```

Groups:

```
/etc/group
```

Encrypted password information:

```
/etc/shadow
```

⚠️ `/etc/shadow` is readable only by privileged users.

View (requires root):

```bash
sudo cat /etc/shadow
```

Do not modify it manually.

---

# Default Shell

View:

```bash
echo $SHELL
```

Change:

```bash
chsh -s /bin/zsh
```

Logout and log back in for the change to take effect.

# Best Practices

### Use `sudo`

Avoid logging in directly as `root`.

---

### One Service, One User

Example:

```
Node → nodeapp

MongoDB → mongodb

Redis → redis

Nginx → www-data
```

---

### Use Groups

Don't assign identical permissions user by user.

---

### Lock Unused Accounts

Disable accounts that no longer need access.

---

### Review Group Membership

Periodically verify users don't have unnecessary administrative privileges.

---

# Common Mistakes

❌ Running applications as `root`.

---

❌ Forgetting `-a` with `usermod -aG`.

---

❌ Editing `/etc/passwd` or `/etc/shadow` manually.

---

❌ Giving every developer `sudo` access.

---

❌ Sharing user accounts between multiple people.

# 💡 Senior Backend Engineer Insight

On a production server, a common setup looks like this:

```
root
│
├── deploy      → Owns application files and performs deployments
├── www-data    → Runs Nginx
├── nodeapp     → Runs the Node.js application
├── mongodb     → Runs MongoDB
└── redis       → Runs Redis
```

Notice that **no application runs as `root`**. Each service has its own dedicated account with only the permissions it needs. This follows the **principle of least privilege**, one of the most important security practices in Linux administration.
