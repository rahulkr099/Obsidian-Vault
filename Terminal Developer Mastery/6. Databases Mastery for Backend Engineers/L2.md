# What is SQL?

**SQL = Structured Query Language**

It is the standard language used to communicate with relational databases.

SQL allows you to:

- Create databases
- Create tables
- Insert data
- Read data
- Update data
- Delete data

# Creating a Table

Let's create a `students` table.

```sql
CREATE TABLE students (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100),
    age INTEGER
);
```

Table structure:

```
+----+--------+----------------+-----+
| ID | Name   | Email          | Age |
+----+--------+----------------+-----+
```

---

# Inserting Data

Insert one row:

```sql
INSERT INTO students (name, email, age)
VALUES (
    'Rahul',
    'rahul@example.com',
    22
);
```

Insert multiple rows:

```sql
INSERT INTO students (name, email, age)
VALUES
('Aman', 'aman@example.com', 21),
('Priya', 'priya@example.com', 20),
('Rohan', 'rohan@example.com', 23);
```

---

# SELECT

Retrieve all rows:

```sql

```

Output:

```

| 1  | Rahul  | rahul@example.com | 22  |

| 3  | Priya  | priya@example.com | 20  |
| 4  | Rohan  | rohan@example.com | 23  |
+----+--------+-------------------+-----+
```

# Selecting Specific Columns

Instead of:

```sql
SELECT * FROM students;
```

Retrieve only:

```sql
SELECT name, age
FROM students;
```

Output:

```
Rahul   22
Aman    21
Priya   20
```

---

# WHERE

Filter rows.

Example:

```sql
SELECT *
FROM students
WHERE age = 22;
```

Only Rahul is returned.

---

# Comparison Operators

|Operator|Meaning|
|---|---|
|=|Equal|
|!=|Not equal|
|>|Greater than|
|<|Less than|
|>=|Greater than or equal|
|<=|Less than or equal|

Example:

```sql
SELECT *
FROM students
WHERE age > 21;
```

---

# AND

Multiple conditions.

```sql
SELECT *
FROM students
WHERE age > 20
AND name = 'Rahul';
```

---

# OR

```sql
SELECT *
FROM students
WHERE age = 20
OR age = 23;
```

---

# NOT

```sql
SELECT *
FROM students
WHERE NOT age = 22;
```

---

# ORDER BY

Ascending:

```sql
SELECT *
FROM students
ORDER BY age ASC;
```

Descending:

```sql
SELECT *
FROM students
ORDER BY age DESC;
```

---

# LIMIT

Retrieve only a few rows.

```sql
SELECT *
FROM students
LIMIT 2;
```

---

# OFFSET

Skip rows.

```sql
SELECT *
FROM students
LIMIT 2
OFFSET 2;
```

Useful for pagination.

---

# DISTINCT

Remove duplicates.

Example:

```sql
SELECT DISTINCT age
FROM students;
```

---

# LIKE

Pattern matching.

Names beginning with "R":

```sql
SELECT *
FROM students
WHERE name LIKE 'R%';
```

Ending with "a":

```sql
SELECT *
FROM students
WHERE name LIKE '%a';
```

Contains "oh":

```sql
SELECT *
FROM students
WHERE name LIKE '%oh%';
```

---

# Wildcards

```
%  → Any number of characters

_  → Exactly one character
```

Example:

```sql
SELECT *
FROM students
WHERE name LIKE '_man';
```

Matches:

```
Aman
```

---

# IN

Instead of:

```sql
WHERE age = 20
OR age = 21
OR age = 22
```

Use:

```sql
SELECT *
FROM students
WHERE age IN (20, 21, 22);
```

---

# BETWEEN

```sql
SELECT *
FROM students
WHERE age BETWEEN 20 AND 22;
```

Inclusive.

---

# NULL

`NULL` means:

```
Unknown / Missing Value
```

Not:

```
0

Empty String

False
```

---

# Checking NULL

Correct:

```sql
SELECT *
FROM students
WHERE email IS NULL;
```

Not:

```sql
email = NULL
```

Similarly:

```sql
SELECT *
FROM students
WHERE email IS NOT NULL;
```

---

# Aliases

Rename columns temporarily.

```sql
SELECT
name AS student_name,
age AS student_age
FROM students;
```

Output:

```
student_name

student_age
```

---

# UPDATE

Change data.

```sql
UPDATE students
SET age = 23
WHERE id = 1;
```

Always use `WHERE` unless you intend to update every row.

---

# DELETE

Delete one row:

```sql
DELETE FROM students
WHERE id = 2;
```

Delete all rows:

```sql
DELETE FROM students;
```

---

# TRUNCATE

Remove all rows efficiently:

```sql
TRUNCATE TABLE students;
```

Unlike `DELETE`, `TRUNCATE` removes every row without a `WHERE` clause.

---

# DROP TABLE

Delete the table itself.

```sql
DROP TABLE students;
```

Use carefully.

# Query Execution Order

Although we write:

```sql
SELECT name
FROM students
WHERE age > 20
ORDER BY age;
```

The database logically processes it as:

```
FROM

↓

WHERE

↓

SELECT

↓

ORDER BY

↓

LIMIT
```

Understanding this helps explain many SQL behaviors.

# Common SQL Mistakes

❌ Missing quotes:

```sql
WHERE name = Rahul
```

Correct:

```sql
WHERE name = 'Rahul'
```

---

❌ Forgetting `WHERE`

```sql
UPDATE students
SET age = 50;
```

Updates every row.

---

❌ Using:

```sql
email = NULL
```

Correct:

```sql
email IS NULL
```

# 💡 Senior Backend Engineer Insight

In real backend development, you rarely write queries in isolation. A typical request flows like this:

```
React Frontend
       │
       ▼
Express Route
       │
       ▼
Service Layer
       │
       ▼
Repository / ORM (Prisma, Drizzle, pg)
       │
       ▼
Generated SQL Query
       │
       ▼
PostgreSQL
       │
       ▼
Rows Returned
       │
       ▼
JSON Response
```

Even if you're using an ORM like Prisma or Drizzle, understanding SQL is essential because:

- ORMs generate SQL under the hood.
- Slow APIs often come from inefficient SQL queries.
- Debugging database issues usually requires reading raw SQL.
- Complex reports and analytics frequently need handcrafted SQL.

The strongest backend engineers are comfortable moving between application code and SQL whenever necessary.
