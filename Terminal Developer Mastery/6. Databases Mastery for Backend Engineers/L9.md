# Module 6 — Lesson 9: Redis Deep Dive ⚡

> **"The fastest database query is the one you don't have to send to your primary database."**

```

   │
   ▼
Express API
   │
   ├────────► Redis (Cache)

   ▼

```

Redis sits between your application and database, reducing latency from milliseconds to microseconds and dramatically decreasing database load.

# What is Redis?

Redis stands for:

```
REmote

DIctionary

Server
```

It is an **in-memory data store**.

Unlike PostgreSQL:

```
Disk
↓
Milliseconds
```

Redis stores data in RAM:

```
Memory
↓
Microseconds
```

---

# Why Redis?

Without Redis:

```
Request

↓

PostgreSQL

↓

Response
```

Thousands of requests can overload the database.

With Redis:

```
Request

↓

Redis

↓

Response
```

Database load decreases significantly.

# Redis vs PostgreSQL

|Redis|PostgreSQL|
|---|---|
|Memory|Disk|
|Microseconds|Milliseconds|
|Key-value|Relational|
|Cache|Primary database|
|Extremely fast|Feature rich|

Redis complements databases—it does not replace them.

# Redis Data Structures

Redis supports multiple native data structures.

- Strings
- Hashes
- Lists
- Sets
- Sorted Sets
- Streams
- Bitmaps
- HyperLogLog
- Geospatial indexes

---

# String

Most common.

```bash
SET username "Rahul"
```

Retrieve:

```bash
GET username
```

Output:

```
Rahul
```

---

# Increment Counter

```bash
SET visits 0
```

Increment:

```bash
INCR visits
```

Useful for:

- Page views
- API counters
- Downloads

---

# Expiration

```bash
SET otp "829341"
```

Expire:

```bash
EXPIRE otp 300
```

OTP automatically disappears after 300 seconds.

Or set both at once:

```bash
SET otp "829341" EX 300
```

---

# Hash

Like a JavaScript object.

```bash
HSET user:1 \
name Rahul \
email rahul@example.com \
age 22
```

Retrieve one field:

```bash
HGET user:1 email
```

Retrieve all:

```bash
HGETALL user:1
```

Perfect for user profiles.

---

# List

Ordered collection.

```bash
LPUSH notifications "Welcome"
```

```bash
RPUSH notifications "Profile Updated"
```

Retrieve:

```bash
LRANGE notifications 0 -1
```

Useful for:

- Notifications
- Queues
- Recent activity

---

# Set

Unique values only.

```bash
SADD skills Node
```

```bash
SADD skills MongoDB
```

```bash
SADD skills Node
```

Stored:

```
Node

MongoDB
```

Duplicates removed automatically.

---

# Sorted Set

Stores scores.

```bash
ZADD leaderboard 120 Rahul
```

```bash

```

Retrieve:

```bash
ZREVRANGE leaderboard 0 9 WITHSCORES
```

Perfect for:

- Gaming
- Rankings
- Scores

# Cache Aside Pattern (Lazy Loading)

Most common strategy.

```
Request
   │
   ▼
Redis?
   │
 ┌─┴─────┐
 │        │
Hit      Miss
 │        │
 ▼        ▼
Return  Database
           │
           ▼
      Save to Redis
           │
           ▼
        Return
```

Application manages the cache.

---

# Read Through Cache

```

↓

↓

Database
```

---

# Write Through Cache

```
Application

↓

Redis

↓

Database
```

Cache and database updated together.

---

# Write Back Cache

```
Application

↓

Redis

↓

Later

↓

Database
```

Very fast but more complex because data reaches the database asynchronously.

# Rate Limiting

User:

```
100 Requests

↓

1 Minute
```

Redis:

```bash
INCR api:user:123
```

```bash
EXPIRE api:user:123 60
```

If count exceeds the limit:

```
429 Too Many Requests
```

---

# Distributed Lock

Prevent multiple workers from processing the same task.

```
Worker A

↓

LOCK

↓

Success

↓

Worker B

↓

Wait
```

Common command:

```bash
SET lock:order123 owner NX EX 30
```

- `NX` → only if key doesn't exist
- `EX 30` → auto-expire after 30 seconds

# Persistence

Redis primarily stores data in memory, but it can persist data to disk.

Two main methods:

- RDB snapshots
- AOF (Append Only File)

---

# RDB

Snapshot.

```
RAM

↓

Snapshot

↓

Disk
```

Fast recovery.

Lower durability between snapshots.

---

# AOF

Every write recorded.

```
SET

↓

Append

↓

Disk
```

Higher durability.

Slightly more disk usage.

---

# Eviction Policies

Memory fills up.

Redis removes keys according to a policy.

Examples:

- allkeys-lru
- volatile-lru
- allkeys-random
- noeviction

---

# LRU

Least Recently Used.

```
Old Data

↓

Evicted

↓

New Data Stored
```

Very common for caches.

# Best Practices

### Cache Frequently Read Data

Examples:

- User profiles
- Product catalog
- Trending posts

---

### Always Set TTL

Avoid stale data and unlimited memory growth.

---

### Use Meaningful Keys

Examples:

```
user:42
profile:42
todos:user:42
session:abc123
```

---

### Don't Cache Everything

Cache only data that is expensive to compute or frequently requested.

---

### Monitor Memory Usage

Redis stores data in RAM, which is limited.

---

# Common Mistakes

❌ Using Redis as the only database for critical business data.

---

❌ Forgetting TTL for temporary data.

---

❌ Creating inconsistent key naming conventions.

---

❌ Caching data that changes every second.

---

❌ Ignoring cache invalidation after database updates.

# 💡 Senior Backend Engineer Insight

Redis is **not just a cache**—it's a versatile in-memory data platform. In production systems, it's often responsible for much more than reducing database load.

```
                  Express API
                      │
     ┌────────────────┼────────────────┐
     ▼                ▼                ▼
  PostgreSQL       MongoDB          Redis
 Transactions   Flexible Data   Cache, Sessions,
 Relationships   Analytics      Rate Limits,
                                 Queues,
                                 Leaderboards,
                                 Pub/Sub,
                                 Distributed Locks
```

As you grow as a backend engineer, you'll notice a pattern:

- **PostgreSQL** answers questions that require strong consistency and relationships.
- **MongoDB** stores flexible, document-oriented data.
- **Redis** accelerates applications and coordinates distributed systems.

Many high-traffic APIs can reduce database traffic by **80–95%** through effective Redis caching, while also using Redis for session storage, background job coordination, and rate limiting.
