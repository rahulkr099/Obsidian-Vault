# The Evolution of Linux Firewalls

```text
Netfilter (Kernel)

        ▲

iptables
(Old userspace tool)

        ▲

nftables
(New userspace tool)
```

- **Netfilter** → Kernel packet filtering framework
    
- **iptables** → Older configuration tool
    
- **nftables** → Modern replacement
    

Netfilter still performs the actual packet filtering.

---

# Why Was `nftables` Created?

`iptables` had several limitations:

- Separate tools for IPv4 and IPv6
    
- Complex rule syntax
    
- Duplicate rules
    
- Slower with large rule sets
    

`nftables` solves these problems by providing:

- One unified firewall
    
- Cleaner syntax
    
- Better performance
    
- Easier maintenance
    

---

# iptables vs nftables

|iptables|nftables|
|---|---|
|Older|Modern|
|Separate IPv4/IPv6 tools|Unified|
|Longer syntax|Cleaner syntax|
|More duplication|Less duplication|
|Still common|Increasingly the default|

# How nftables Works

Like `iptables`, `nftables` uses:

- Tables
    
- Chains
    
- Rules
    

But the structure is more flexible.

```text
Table

↓

Chain

↓

Rule

↓

Action
```

---

# Families

Unlike `iptables`, `nftables` supports multiple protocol families.

Common families:

|Family|Purpose|
|---|---|
|`ip`|IPv4|
|`ip6`|IPv6|
|`inet`|IPv4 + IPv6|
|`arp`|ARP packets|
|`bridge`|Ethernet bridges|

The most common family today is:

```text
inet
```

because one rule can handle both IPv4 and IPv6.

Create a table:

```bash
sudo nft add table inet filter
```

```text

```

# Chains

Chains hold firewall rules.

Create an INPUT chain:

```bash
sudo nft add chain inet filter input \
'{ type filter hook input priority 0; policy accept; }'
```

This command tells the kernel:

- Filter incoming packets
    
- Use the INPUT hook
    
- Default policy: accept
    

---

# Hooks

Hooks tell Netfilter where to inspect packets.

Important hooks:

|Hook|Purpose|
|---|---|
|input|Incoming traffic|
|output|Outgoing traffic|
|forward|Forwarded traffic|
|prerouting|Before routing|
|postrouting|After routing|

These are similar to the chains you learned in `iptables`.

# Rules

Allow SSH:

```bash
sudo nft add rule inet filter input tcp dport 22 accept
```

Meaning:

```text
TCP

↓

Destination Port 22

↓

Accept
```

---

Allow HTTP:

```bash
sudo nft add rule inet filter input tcp dport 80 accept
```

---

Allow HTTPS:

```bash
sudo nft add rule inet filter input tcp dport 443 accept
```

---

Drop PostgreSQL

```bash
sudo nft add rule inet filter input tcp dport 5432 drop
```

# Sets

One of the biggest advantages of `nftables` is **sets**.

Instead of:

```text
22

80

443
```

Three separate rules...

You can create one set.

Example:

```bash
sudo nft add set inet filter allowed_ports \
'{ type inet_service; }'
```

Add values:

```bash
sudo nft add element inet filter allowed_ports \
'{22,80,443}'
```

Then use:

```bash
sudo nft add rule inet filter input tcp dport @allowed_ports accept
```

One rule handles multiple ports.

This is faster and easier to maintain.

---

# View Ruleset

```bash
sudo nft list ruleset
```

This is the command you'll use most often.

---

# Flush Rules

Remove all rules:

```bash
sudo nft flush ruleset
```

⚠️ **Warning:** On a remote server, this may remove firewall protections or management access. Use with caution.

---

# Delete Table

```bash
sudo nft delete table inet filter
```

---

# Save Configuration

Rules created manually exist only until reboot unless saved.

Many distributions provide:

```bash
sudo nft list ruleset > rules.nft
```

Later restore:

```bash
sudo nft -f rules.nft
```

Some distributions also include services that automatically load `/etc/nftables.conf` during boot.

# Backend Example

Suppose your server runs:

# iptables Translation

iptables:

```bash
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
```

Equivalent nftables rule:

```bash
sudo nft add rule inet filter input tcp dport 80 accept
```

Notice how the `nftables` syntax is shorter and more readable.

# Common Interview Questions

### 1. What is `nftables`?

`nftables` is the modern Linux firewall framework and the recommended replacement for `iptables`.

---

### 2. Why was `nftables` introduced?

It provides a unified framework, simpler syntax, better performance, and improved support for both IPv4 and IPv6.

---

### 3. What is the `inet` family?

The `inet` family allows a single ruleset to match both IPv4 and IPv6 traffic.

---

### 4. What is a set?

A set is a collection of values (such as ports or IP addresses) that can be matched efficiently with a single firewall rule.

---

### 5. Which command displays the complete firewall configuration?

```bash
sudo nft list ruleset
```

# Key Takeaways

- **Netfilter** is the kernel framework that filters packets.
    
- **`iptables`** is the traditional interface to Netfilter.
    
- **`nftables`** is the modern replacement with cleaner syntax and better scalability.
    
- `inet` lets you manage IPv4 and IPv6 together.
    
- **Sets** make rule management more efficient.
    
- `sudo nft list ruleset` is the primary command for inspecting firewall configuration.
    
- Many modern Linux distributions use `nftables` by default, even when compatibility tools for `iptables` are installed.
