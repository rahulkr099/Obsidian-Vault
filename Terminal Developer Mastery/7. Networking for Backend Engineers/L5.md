# What is Routing?

**Routing** is the process of choosing the path that data packets take from a source to a destination.

Imagine you're driving from your home to another city.

You may have several roads available.

Google Maps chooses the best route.

Similarly, a router chooses the best path for network packets.

---

# Example

Your laptop:

```text
192.168.1.20
```

Google:

```text
142.250.xxx.xxx
```

Packet journey:

```text
Laptop

↓

Home Router

↓

ISP

↓

Regional Router

↓

Internet

↓

Google Router

↓

Google Server
```

Every router makes a routing decision.

---

# What is a Router?

A **router** connects different networks.

Example:

```text
Home Network

↓

Router

↓

Internet
```

The router checks the destination IP and forwards the packet to the next network.

Think of it as a traffic police officer directing vehicles.

---

# Routing Table

Every computer has a **routing table**.

It contains rules that answer:

> "Where should I send this packet?"

Example:

```text
Destination            Gateway
192.168.1.0/24         Local
Default                192.168.1.1
```

---

# Reading the Routing Table

Suppose you want to reach:

```text
192.168.1.50
```

Linux checks:

```text
192.168.1.0/24
```

It matches.

Result:

```text
Send directly
```

No router needed because it's on the same subnet.

---

Now suppose you want:

```text
8.8.8.8
```

Linux checks:

```text
192.168.1.0/24
```

No match.

Then it checks:

```text
Default Route
```

Result:

```text
Send to router
```

---

# Default Route

The **default route** is used when no other route matches.

Think of it as:

> "If you don't know where to go, ask the router."

Example:

```text
default via 192.168.1.1
```

Meaning:

```text
Unknown destination?

↓

Router (192.168.1.1)

↓

Router decides next path.
```

---

# Next Hop

The **next hop** is the next router or gateway that receives the packet.

Example:

```text
Laptop

↓

Home Router

↓

ISP Router

↓

Internet Router

↓

Google
```

Each router only needs to know the next step, not the entire journey.

---

# Routing Decision Example

Your PC:

```text
192.168.1.20
```

Destination:

```text
192.168.1.45
```

Routing table:

```text
192.168.1.0/24 → Local
```

Decision:

```text
Direct delivery
```

No router involved.

---

Now destination:

```text
151.101.1.69
```

Routing table:

```text
default via 192.168.1.1
```

Decision:

```text
Send to router
```

The router forwards it toward the destination.

---

# Route Metrics

Sometimes multiple routes are available.

The system chooses the route with the **lowest metric**.

Example:

```text
Route A

Metric = 100
```

```text
Route B

Metric = 50
```

Linux selects:

```text
Route B
```

because a lower metric generally indicates a more preferred route.

---

# Static Routing

A **static route** is added manually by an administrator.

Example:

```text
Network:
10.0.0.0/24

Gateway:
192.168.1.254
```

Linux will always use that specified gateway for that network.

Advantages:

- Predictable
    
- Simple
    
- Good for small networks
    

Disadvantages:

- Manual maintenance
    
- Doesn't adapt automatically to network changes
    

---

# Dynamic Routing

Large networks use **dynamic routing protocols**.

Routers exchange information and update routes automatically.

Common protocols:

- RIP
    
- OSPF
    
- BGP
    
- EIGRP (Cisco)
    

Cloud providers and Internet backbone routers rely on dynamic routing.

# How a Packet Reaches Google

Suppose:

```text
Laptop:
192.168.1.20
```

You open:

```text
https://google.com
```

Step 1:

DNS returns:

```text
142.250.xxx.xxx
```

↓

Step 2:

Linux checks:

```text
Routing Table
```

↓

Step 3:

No local match.

↓

Step 4:

Uses:

```text
Default Gateway
192.168.1.1
```

↓

Step 5:

Router forwards packet to ISP.

↓

Step 6:

ISP forwards packet to other routers.

↓

Step 7:

Eventually:

```text
Google Router
```

↓

Google Server

# Routing Tables Grow

Your laptop's routing table is usually small.

Example:

```text
Local Network

Default Gateway
```

Internet routers may have hundreds of thousands—or even millions—of routes, depending on the hardware and routing architecture.

---

# Longest Prefix Match

If multiple routes match a destination, routers choose the **most specific** route.

Example routing table:

```text
192.168.0.0/16

192.168.1.0/24
```

Destination:

```text
192.168.1.50
```

Both routes match.

Linux chooses:

```text
192.168.1.0/24
```

because `/24` is more specific than `/16`.

This rule is called **Longest Prefix Match**.

# Linux Commands

## View routing table

```bash
ip route
```

Example:

```text
default via 192.168.1.1 dev wlp2s0

192.168.1.0/24 dev wlp2s0 proto kernel scope link src 192.168.1.20
```

Explanation:

|Part|Meaning|
|---|---|
|`default`|Default route|
|`via 192.168.1.1`|Gateway|
|`dev wlp2s0`|Network interface|
|`192.168.1.0/24`|Local subnet|
|`src 192.168.1.20`|Source IP used for this route|

---

## Show detailed routes

```bash
ip route show
```

This displays the current routing table.

---

## Trace packet path

```bash
traceroute google.com
```

Example output:

```text
1 192.168.1.1

2 ISP Router

3 Regional Router

4 National Router

5 Google
```

Each line represents a **hop**.

> **Note:** If `traceroute` isn't installed, you may need to install it using your distribution's package manager.

---

## Alternative

```bash
tracepath google.com
```

Unlike `traceroute`, `tracepath` often works without root privileges and is commonly preinstalled on many Linux distributions.

---

## Ping a router

```bash
ping 192.168.1.1
```

Tests connectivity to your default gateway.

---

# What is a Hop?

A **hop** is one stop that a packet makes at a router on its journey.

Example:

```text
Laptop

↓

Router 1

↓

Router 2

↓

Router 3

↓

Google
```

This journey has **4 hops** from the laptop to Google (counting each forwarding step shown).

# Real Backend Example

Suppose your backend server is deployed on:

```text
203.0.113.10
```

A client sends:

```text
GET /api/users
```

The request travels:

```text
Client

↓

Home Router

↓

ISP

↓

Internet Routers

↓

Cloud Provider Router

↓

Server
```

The response returns through routing decisions made at each hop. The return path may differ from the forward path, depending on network conditions and routing policies.

# Common Interview Questions

### 1. What is routing?

Routing is the process of selecting a path for packets to travel from a source to a destination across one or more networks.

---

### 2. What is a routing table?

A routing table is a set of rules used by a computer or router to determine where to forward packets.

---

### 3. What is the default route?

The default route is the route used when no more specific route matches the destination.

---

### 4. What is a next hop?

The next hop is the next router or gateway that receives a packet on its way to the final destination.

---

### 5. What is the difference between static and dynamic routing?

|Static Routing|Dynamic Routing|
|---|---|
|Configured manually|Learned automatically|
|Best for small networks|Best for large networks|
|Doesn't adapt automatically|Adjusts when network topology changes|

---

### 6. What is a hop?

A hop is a single forwarding step where a packet passes through a router on its journey to the destination.

# Troubleshooting Tips for Backend Engineers

If your API isn't reachable:

1. Check whether your server is running:
    
    ```bash
    ss -tuln
    ```
    
2. Verify your IP address:
    
    ```bash
    ip addr
    ```
    
3. Check your routing table:
    
    ```bash
    ip route
    ```
    
4. Test local connectivity:
    
    ```bash
    ping <gateway-ip>
    ```
    
5. Trace the network path:
    
    ```bash
    tracepath <server-ip-or-domain>
    ```
    

These steps help determine whether the issue is with the application, the local network, or routing beyond your machine.

---

# Key Takeaways

- **Routing** determines how packets travel between networks.
    
- **Routers** connect different networks and forward packets.
    
- Every system maintains a **routing table**.
    
- The **default route** is used when no specific route matches.
    
- A **next hop** is the next router that receives the packet.
    
- **Static routing** is manually configured, while **dynamic routing** adapts automatically.
    
- **Longest Prefix Match** ensures the most specific route is selected.
    
- Tools like `ip route`, `traceroute`, and `tracepath` are essential for diagnosing network problems.
