# What is DNS?

DNS stands for:

> **Domain Name System**

It translates:

```text
google.com
```

into

```text
142.250.xxx.xxx
```

Computers communicate using IP addresses, while humans prefer domain names.

DNS bridges the gap.

---

# Without DNS

Imagine opening a browser.

Instead of typing:

```text
https://google.com
```

You would need:

```text
https://142.250.xxx.xxx
```

Now imagine remembering the IPs for hundreds of websites.

Clearly, domain names are much easier.

---

# Real Example

When you type:

```text
github.com
```

The browser asks:

> "What IP address belongs to github.com?"

DNS replies:

```text
140.82.xxx.xxx
```

The browser then connects to that IP.

---

# DNS Analogy

Think of your phone.

You save:

```text
Mom
```

instead of

```text
+91XXXXXXXXXX
```

When you tap "Mom", your phone finds the number.

DNS works the same way.

```text
google.com

↓

DNS

↓

142.250.xxx.xxx
```

---

# DNS Flow

Suppose you open:

```text
https://google.com
```

The process is:

```text
Browser

↓

DNS Lookup

↓

IP Address

↓

TCP Connection

↓

HTTPS Request

↓

Google Server
```

Notice:

**DNS happens before the network connection is established.**

---

# What is a DNS Record?

A DNS server stores many kinds of information.

Each piece of information is called a **DNS Record**.

Different record types serve different purposes.

---

# A Record

The most common record.

Maps:

```text
Domain

↓

IPv4 Address
```

Example:

```text
example.com

↓

93.184.216.34
```

If you visit a website over IPv4, you're usually using an **A record**.

---

# AAAA Record

Same idea as an A record.

But for **IPv6**.

Example:

```text
example.com

↓

2606:2800:220:1:248:1893:25c8:1946
```

---

# Difference

|Record|Maps To|
|---|---|
|A|IPv4|
|AAAA|IPv6|

---

# CNAME Record

CNAME means:

> **Canonical Name**

It creates an alias.

Example:

```text
www.example.com

↓

example.com
```

Instead of storing another IP, it points to another hostname.

Another example:

```text
api.example.com

↓

server.example.com
```

Then DNS looks up:

```text
server.example.com
```

to get the final IP.

---

# Why Use CNAME?

Imagine your server's hostname changes.

Without CNAME:

```text
www

↓

IP
```

You'd need to update multiple records.

With CNAME:

```text
www

↓

example.com

↓

IP
```

You update only the main record.

---

# MX Record

MX stands for:

> **Mail Exchange**

It tells email systems where to deliver mail.

Example:

```text
example.com

↓

mail.example.com
```

When someone sends:

```text
user@example.com
```

their mail server checks the MX record first.

---

# TXT Record

TXT stores arbitrary text.

Common uses:

- Domain verification
    
- Email security
    
- SPF
    
- DKIM
    
- DMARC
    
- Cloud service verification
    

Example:

```text
TXT

↓

google-site-verification=abc123
```

Many services ask you to add a TXT record to prove domain ownership.

---

# NS Record

NS means:

> **Name Server**

It tells the Internet:

> "These DNS servers are responsible for this domain."

Example:

```text
example.com

↓

ns1.provider.com

ns2.provider.com
```

---

# TTL

TTL stands for:

> **Time To Live**

Example:

```text
TTL = 3600
```

Meaning:

```text
1 hour
```

DNS resolvers cache the record for one hour before asking again.

---

# Why TTL Matters

Suppose you move your website to a new server.

Old IP:

```text
1.1.1.1
```

New IP:

```text
2.2.2.2
```

If TTL is:

```text
86400
```

(24 hours)

Some users may continue reaching the old server until the cached record expires.

---

# Common DNS Records

|Record|Purpose|
|---|---|
|A|IPv4 address|
|AAAA|IPv6 address|
|CNAME|Alias|
|MX|Mail server|
|TXT|Text information / verification|
|NS|Name servers|

# Linux Commands

## dig

The best DNS debugging tool.

```bash
dig google.com
```

Example:

```text
;; ANSWER SECTION:

google.com.

300

IN

A

142.250.xxx.xxx
```

---

## dig for specific records

A record:

```bash
dig google.com A
```

AAAA record:

```bash
dig google.com AAAA
```

MX:

```bash
dig gmail.com MX
```

TXT:

```bash
dig google.com TXT
```

NS:

```bash
dig google.com NS
```

---

## Short output

```bash
dig +short google.com
```

Example:

```text
142.250.xxx.xxx
```

---

## host

Simple DNS lookup.

```bash
host google.com
```

Example:

```text
google.com has address 142.250.xxx.xxx
```

---

## nslookup

Older DNS tool.

```bash
nslookup google.com
```

Example:

```text
Server:

192.168.1.1

Address:

192.168.1.1#53

Non-authoritative answer:

Name:

google.com

Address:

142.250.xxx.xxx
```

Although still widely available, `dig` is generally preferred because it provides more detailed output.

---

# Compare the Tools

|Tool|Best Use|
|---|---|
|dig|Detailed DNS debugging|
|host|Quick lookups|
|nslookup|Legacy but still useful|

---

# DNS Cache

Your operating system and browser often remember DNS results.

Example:

First visit:

```text
Browser

↓

DNS Lookup

↓

IP
```

Second visit:

```text
Browser

↓

Cache

↓

IP
```

No DNS query is needed until the cached entry expires.

---

# Why DNS Caching Helps

Without caching:

Every page load would require a DNS query.

With caching:

- Faster browsing
    
- Lower latency
    
- Reduced DNS server load

# Common Backend Problems

## Problem 1

Wrong DNS record.

```text
api.example.com

↓

Wrong IP
```

Users can't reach your backend.

---

## Problem 2

Old cache.

You changed:

```text
Old Server

↓

New Server
```

But clients still use the cached IP until the TTL expires.

---

## Problem 3

Missing A record.

```text
example.com

↓

No IPv4 address
```

The website becomes unreachable over IPv4.

---

## Problem 4

Wrong MX record.

Emails stop arriving because mail servers don't know where to deliver them.

# Real Backend Example

Suppose your backend is hosted at:

```text
203.0.113.10
```

You create:

```text
api.myapp.com
```

DNS configuration:

```text
A Record

↓

203.0.113.10
```

Now users can access:

```text
https://api.myapp.com
```

instead of:

```text
https://203.0.113.10
```

If you later move the backend to another server, you update the DNS record rather than asking users to use a new IP address.

# Common Interview Questions

### 1. What is DNS?

DNS (Domain Name System) translates human-readable domain names into IP addresses so computers can communicate.

---

### 2. What is an A record?

An A record maps a domain name to an IPv4 address.

---

### 3. What is an AAAA record?

An AAAA record maps a domain name to an IPv6 address.

---

### 4. What is a CNAME record?

A CNAME record creates an alias from one hostname to another hostname.

---

### 5. What is an MX record?

An MX record specifies the mail servers responsible for receiving email for a domain.

---

### 6. What is TTL?

TTL (Time To Live) determines how long a DNS record may be cached before it should be refreshed.

---

### 7. Why is `dig` preferred over `nslookup`?

`dig` provides more detailed information, better formatting, and greater flexibility for troubleshooting DNS issues.

---

# Key Takeaways

- **DNS** converts domain names into IP addresses.
    
- DNS lookups occur **before** a TCP connection is established.
    
- Different DNS records serve different purposes:
    
    - **A** → IPv4
        
    - **AAAA** → IPv6
        
    - **CNAME** → Alias
        
    - **MX** → Email routing
        
    - **TXT** → Verification and email policies
        
    - **NS** → Authoritative name servers
        
- **TTL** controls how long DNS responses are cached.
    
- `dig` is the primary tool for DNS troubleshooting on Linux.
