# What Happens When You Install Nginx?

Installing Nginx does much more than copying one executable.

It also installs:

- The Nginx binary
    
- Configuration files
    
- Default website
    
- Systemd service
    
- Log directories
    
- Cache directories
    
- PID file locations
    

After installation, Linux can automatically start and manage Nginx.

# Installing Nginx (Ubuntu/Linux Mint)

First, update the package list:

```bash
sudo apt update
```

Install Nginx:

```bash
sudo apt install nginx
```

Check the installed version:

```bash
nginx -v
```

Example:

```text
nginx version: nginx/1.24.0
```

To see build information:

```bash
nginx -V
```

This displays:

- Version
    
- Compiler
    
- Modules
    
- SSL support
    
- Configure options

# Understanding systemctl

Since Nginx runs as a **systemd service**, you manage it using `systemctl`.

Common commands:

Start:

```bash
sudo systemctl start nginx
```

Stop:

```bash
sudo systemctl stop nginx
```

Restart:

```bash
sudo systemctl restart nginx
```

Reload configuration:

```bash
sudo systemctl reload nginx
```

Enable at boot:

```bash
sudo systemctl enable nginx
```

Disable automatic startup:

```bash
sudo systemctl disable nginx
```

Check status:

```bash
systemctl status nginx
```

---

# Restart vs Reload

This is a common interview question.

## Restart

```bash
sudo systemctl restart nginx
```

What happens?

- Stops Nginx
    
- Starts it again
    
- Existing connections may be interrupted
    
- New worker processes are created
    

Use when:

- Upgrading Nginx
    
- Major changes
    
- Service problems
    

---

## Reload

```bash
sudo systemctl reload nginx
```

What happens?

- Configuration is re-read
    
- Existing connections continue
    
- New configuration is applied
    
- No downtime
    

Production servers almost always use **reload** after configuration changes.

# Nginx Directory Structure

One of the most important things to learn.

```
/etc/nginx/
├── nginx.conf
├── conf.d/
├── sites-available/
├── sites-enabled/
├── snippets/
├── mime.types
```

Let's understand each.

---

# `/etc/nginx/nginx.conf`

The main configuration file.

Everything begins here.

Think of it as:

> The root configuration.

Example:

```text
nginx.conf

↓

includes

↓

other configuration files
```

---

# `/etc/nginx/sites-available`

Contains website configurations.

Example:

```
myblog

portfolio

api

company
```

These are **available** but not necessarily active.

---

# `/etc/nginx/sites-enabled`

Contains symbolic links to enabled websites.

Example:

```
default

portfolio

api
```

Only files linked here are actually loaded.

This makes enabling and disabling websites very easy.

---

# Enable a Website

Suppose:

```
/etc/nginx/sites-available/myapp
```

Create a symbolic link:

```bash
sudo ln -s \
/etc/nginx/sites-available/myapp \
/etc/nginx/sites-enabled/
```

Now Nginx loads it.

---

# Disable a Website

Remove the symbolic link:

```bash
sudo rm /etc/nginx/sites-enabled/myapp
```

Reload Nginx:

```bash
sudo systemctl reload nginx
```

The configuration still exists in `sites-available`; it's simply inactive.

---

# `conf.d`

Used for additional configuration files.

Example:

```
cache.conf

gzip.conf

proxy.conf
```

Many production setups place reusable configurations here.

---

# `snippets`

Stores reusable configuration fragments.

Example:

```
ssl.conf

security.conf

headers.conf
```

Instead of repeating settings, you include these snippets where needed.

---

# `mime.types`

Maps file extensions to MIME types.

Examples:

```
.html → text/html

.css → text/css

.js → application/javascript

.png → image/png
```

This tells browsers how to interpret downloaded files.

---

# Log Files

Located in:

```
/var/log/nginx/
```

Usually you'll find:

```
access.log

error.log
```

---

# Access Log

Shows every incoming request.

Example:

```
192.168.1.20

GET /

200
```

Useful for:

- Analytics
    
- Debugging
    
- Monitoring traffic
    

---

# Error Log

Stores server errors.

Examples:

```
Permission denied

File not found

Connection refused

Configuration errors
```

This is usually the first place to check when something goes wrong.

---

# View Logs

View access log:

```bash
sudo tail -f /var/log/nginx/access.log
```

View error log:

```bash
sudo tail -f /var/log/nginx/error.log
```

The `-f` option follows the file, showing new log entries in real time.

---

# Testing Configuration

Always test your configuration before reloading.

Command:

```bash
sudo nginx -t
```

Successful output:

```text
syntax is ok

test is successful
```

If there's a mistake, Nginx tells you:

- File name
    
- Line number
    
- Error description
    

This prevents bad configurations from being loaded.

---

# View Complete Configuration

Display the entire active configuration:

```bash
sudo nginx -T
```

This includes:

- Main configuration
    
- Included files
    
- Server blocks
    
- Default settings
    

Useful when troubleshooting complex setups.

---

# Reload Safely

The recommended workflow is:

```bash
sudo nginx -t
```

↓

```bash
sudo systemctl reload nginx
```

Never reload without testing first.

---

# Service Logs

View logs generated by the Nginx service itself:

```bash
journalctl -u nginx
```

Follow new log messages:

```bash
journalctl -u nginx -f
```

These logs are different from `access.log` and `error.log`; they show messages from the systemd service.

# Common Installation Problems

## Port 80 Already in Use

Check:

```bash
sudo ss -tulpn | grep :80
```

Find which process is using port 80 before starting Nginx.

---

## Firewall Blocking Requests

Allow HTTP:

```bash
sudo ufw allow 80
```

Allow HTTPS:

```bash
sudo ufw allow 443
```

Check firewall status:

```bash
sudo ufw status
```

---

## Syntax Errors

Always run:

```bash
sudo nginx -t
```

before reloading.

---

## Permission Problems

Check ownership and permissions:

```bash
ls -l /etc/nginx
```

Configuration files should typically be owned by `root`.

---

# Typical Production Workflow

When updating a website:

```
Edit configuration

↓

sudo nginx -t

↓

sudo systemctl reload nginx

↓

Test website

↓

Monitor logs
```

This sequence minimizes downtime and catches configuration errors early.

# Interview Questions

### 1. What is the main Nginx configuration file?

`/etc/nginx/nginx.conf`

---

### 2. What is the difference between `sites-available` and `sites-enabled`?

- `sites-available` stores all website configurations.
    
- `sites-enabled` contains symbolic links to the configurations that Nginx should actively load.
    

---

### 3. What does `nginx -t` do?

It checks the configuration syntax and verifies that Nginx can load the configuration without errors.

---

### 4. What is the difference between `restart` and `reload`?

- **Restart** stops and starts the service, which can interrupt existing connections.
    
- **Reload** applies configuration changes without stopping the service, allowing existing connections to continue.
    

---

### 5. Where are Nginx logs stored?

Typically in:

```
/var/log/nginx/
```

including:

- `access.log`
    
- `error.log`

# Key Takeaways

- Nginx is installed and managed as a **systemd service**.
    
- The main configuration file is `/etc/nginx/nginx.conf`.
    
- `sites-available` stores configurations, while `sites-enabled` determines which sites are active.
    
- Always run `nginx -t` before reloading configuration changes.
    
- Use `reload` for configuration updates and `restart` only when necessary.
    
- Logs in `/var/log/nginx/` are essential for monitoring and troubleshooting.
