# Lesson 5 — Serving Static Files

One of Nginx's biggest strengths is serving **static files**. It can deliver HTML, CSS, JavaScript, images, videos, PDFs, and downloads much faster than most backend frameworks.

This is why, even when you're using **Node.js/Express**, **Django**, or **Spring Boot**, Nginx is often placed in front of your application.

# What are Static Files?

Static files are files that already exist on disk.

They do **not** need any processing.

Examples:

```
index.html

about.html

style.css

app.js

logo.png

resume.pdf

video.mp4
```

Nginx simply reads the file and sends it to the client.

---

# Static vs Dynamic

Suppose a browser requests:

```
GET /logo.png
```

Static:

```
Browser

↓

Nginx

↓

logo.png

↓

Browser
```

No backend.

No database.

Very fast.

---

Dynamic request:

```
GET /profile
```

```
Browser

↓

Nginx

↓

Node.js

↓

MongoDB

↓

Node.js

↓

Browser
```

More work is required.

---

# Why is Nginx Fast?

Nginx reads files directly from disk.

No application startup.

No JavaScript execution.

No database queries.

Flow:

```
Disk

↓

Nginx

↓

Browser
```

This is much faster than routing every request through a backend application.

# The `root` Directive

The most important directive for serving files is:

```nginx
root /var/www/html;
```

It tells Nginx:

> "Look for files in this directory."

---

Example directory:

```
/var/www/html

├── index.html
├── about.html
├── style.css
├── script.js
├── images
│     └── logo.png
└── downloads
      └── resume.pdf
```

---

Configuration:

```nginx
server {

    listen 80;

    root /var/www/html;

}
```

---

If the browser requests:

```
GET /
```

Nginx looks for:

```
/var/www/html/index.html
```

---

If the browser requests:

```
GET /about.html
```

Nginx looks for:

```
/var/www/html/about.html
```

---

If the browser requests:

```
GET /images/logo.png
```

Nginx reads:

```
/var/www/html/images/logo.png
```

and sends it back.

---

# The `index` Directive

Most websites don't require users to type:

```
index.html
```

Instead:

```
example.com/
```

works.

Configuration:

```nginx
index index.html;
```

When the request is:

```
GET /
```

Nginx automatically searches for:

```
index.html
```

You can define multiple index files:

```nginx
index index.html index.htm home.html;
```

Nginx checks them in order.

---

# Complete Example

```nginx
server {

    listen 80;

    server_name localhost;

    root /var/www/html;

    index index.html;

}
```

Very simple.

Very common.

# MIME Types

How does the browser know a PNG is an image?

Because Nginx sends a **Content-Type** header.

Examples:

|File|MIME Type|
|---|---|
|.html|text/html|
|.css|text/css|
|.js|application/javascript|
|.png|image/png|
|.jpg|image/jpeg|
|.pdf|application/pdf|
|.json|application/json|

Nginx gets this mapping from:

```
/etc/nginx/mime.types
```

# The `try_files` Directive

One of the most useful directives.

Example:

```nginx
location / {

    try_files $uri $uri/ =404;

}
```

Meaning:

1. Look for the requested file.
    
2. If not found, look for a matching directory.
    
3. If still not found, return **404 Not Found**.
    

---

Example:

Browser:

```
GET /photo.png
```

Nginx checks:

```
photo.png
```

Exists?

Yes →

Serve it.

No?

↓

404

# Single Page Applications (SPA)

Frameworks like:

- React
    
- Vue
    
- Angular
    

use client-side routing.

Without special configuration:

```
/dashboard
```

returns:

```
404
```

Instead:

```nginx
location / {

    try_files $uri /index.html;

}
```

Meaning:

If the file isn't found:

↓

Return:

```
index.html
```

React Router then handles the route.

This is the standard production configuration for React applications.

# Directory Indexing

Suppose:

```
files/

movie.mp4

song.mp3

book.pdf
```

By default:

```
GET /files/
```

returns:

```
403 Forbidden
```

because there is no `index.html`.

---

Enable directory listing:

```nginx
location /files {

    autoindex on;

}
```

Now visiting:

```
/files/
```

shows a list of files.

---

Directory listing is useful for:

- Internal servers
    
- File repositories
    
- Development
    

Avoid enabling it on public websites unless you intentionally want users to browse files.

---

# Cache Headers

Browsers cache static files to avoid downloading them again.

Example:

```
logo.png
```

Without caching:

Every page refresh downloads the image again.

With caching:

Browser uses the local copy.

Website loads faster.

---

Configuration:

```nginx
location ~* \.(jpg|jpeg|png|gif|css|js)$ {

    expires 30d;

}
```

Meaning:

Cache these files for **30 days**.

---

Another example:

```nginx
expires 1y;
```

Browser caches the file for one year.

This works well for versioned assets (for example, `app.8f3d2.js`) because the filename changes whenever the content changes.

---

# Cache-Control Header

A more explicit approach:

```nginx
add_header Cache-Control "public";
```

Or:

```nginx
add_header Cache-Control "public, max-age=86400";
```

Meaning:

Cache for **1 day**.

---

# Performance Benefits

Without caching:

```
100 users

↓

Download logo.png

100 times
```

With caching:

```
100 users

↓

Download once

↓

Reuse cached copy
```

Benefits:

- Less bandwidth
    
- Faster page loads
    
- Reduced server load

# Permissions

Nginx runs as the `www-data` user on Ubuntu/Linux Mint.

It must be able to read your files.

Example:

```bash
sudo chmod -R 755 /var/www/mywebsite
```

Owner:

```bash
sudo chown -R $USER:www-data /var/www/mywebsite
```

This allows you to edit the files while letting Nginx read them.

---

# Common Errors

## 403 Forbidden

Possible causes:

- Incorrect permissions
    
- Missing `index.html`
    
- Directory listing disabled
    

---

## 404 Not Found

Possible causes:

- File doesn't exist
    
- Wrong `root`
    
- Incorrect path in the URL
    

---

## Wrong MIME Type

Symptoms:

- CSS doesn't load
    
- JavaScript downloads instead of executing
    
- Images don't display
    

Usually caused by a missing or incorrect `mime.types` configuration.

# Interview Questions

### 1. What is a static file?

A static file is a pre-existing file, such as HTML, CSS, JavaScript, an image, or a PDF, that Nginx can serve directly without backend processing.

---

### 2. What does the `root` directive do?

It specifies the directory on the filesystem where Nginx looks for files to serve.

---

### 3. What does the `index` directive do?

It defines the default file Nginx serves when a client requests a directory, such as `index.html`.

---

### 4. What does `try_files` do?

It checks whether requested files or directories exist and serves them if found. If not, it follows the fallback you specify, such as returning `404` or `index.html`.

---

### 5. Why are cache headers important?

They allow browsers to reuse previously downloaded static assets, reducing bandwidth usage, speeding up page loads, and decreasing server load.

# Best Practices

- Keep all static files under a dedicated web root (for example, `/var/www/mywebsite`).
    
- Always use `try_files` to handle missing files safely.
    
- Enable caching for CSS, JavaScript, images, and fonts.
    
- Do **not** enable `autoindex` on public websites unless it's intentional.
    
- Keep static content separate from backend application code.
    

---

# Key Takeaways

- Nginx is highly optimized for serving static files.
    
- The `root` directive defines where files are stored.
    
- The `index` directive specifies the default file for directory requests.
    
- `try_files` provides safe file lookup and is essential for SPAs like React.
    
- Cache headers significantly improve performance by reducing repeated downloads.
    
- Proper file permissions are required for Nginx to access and serve content.
