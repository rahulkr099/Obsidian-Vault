# Lesson 6 — Server Blocks (Virtual Hosts)

This lesson introduces one of Nginx's most powerful features: **Server Blocks**, also known as **Virtual Hosts**.

Server blocks allow a **single Nginx server** to host **multiple websites or applications** using the same IP address.

This is how cloud providers, hosting companies, and production servers run many websites on one machine.

# What is a Server Block?

A **server block** is a configuration section that defines how Nginx should respond to requests for a specific domain, IP, or port.

Example:

```nginx
server {

}
```

Think of a server block as:

> One website = One server block

---

# Basic Server Block

```nginx
server {

    listen 80;

    server_name example.com;

    root /var/www/example;

}
```

Let's understand each directive.

---

# The `listen` Directive

```nginx
listen 80;
```

This tells Nginx:

> Listen for HTTP traffic on port **80**.

Examples:

```nginx
listen 80;
```

HTTP

---

```nginx
listen 443 ssl;
```

HTTPS

---

```nginx
listen 8080;
```

Custom application port

---

# The `server_name` Directive

Example:

```nginx
server_name example.com;
```

Meaning:

If the browser requests:

```
example.com
```

Use this server block.

---

Multiple names:

```nginx
server_name example.com www.example.com;
```

Now both work.

---

Wildcards:

```nginx
server_name *.example.com;
```

Matches:

```
blog.example.com

api.example.com

shop.example.com
```

---

# Complete Example

```nginx
server {

    listen 80;

    server_name example.com;

    root /var/www/example;

    index index.html;

}
```

Request:

```
GET /
Host: example.com
```

Nginx serves:

```
/var/www/example/index.html
```

# How Does Nginx Know?

Every HTTP request contains a **Host** header.

Example:

```
GET / HTTP/1.1

Host: example.com
```

or

```
Host: blog.com
```

Nginx compares this value with each `server_name`.

If it finds a match, it uses that server block.

# Default Server

Suppose someone visits:

```
unknownwebsite.com
```

There is no matching server block.

Which website should Nginx show?

The answer is the **default server**.

Example:

```nginx
listen 80 default_server;
```

This server block becomes the fallback.

---

Example:

```nginx
server {

    listen 80 default_server;

    server_name _;

    return 404;

}
```

Now unknown domains receive:

```
404 Not Found
```

instead of your main website.

---

# Why Use a Default Server?

Benefits:

- Better security
    
- Cleaner configuration
    
- Prevents accidental exposure
    
- Handles invalid domains gracefully
    

---

# Multiple Ports

One server block can listen on multiple ports.

Example:

```nginx
server {

    listen 80;

    listen 8080;

}
```

Requests arriving on either port use the same configuration.

---

# Multiple Domains

Example:

```nginx
server_name

example.com

www.example.com

example.org;
```

One website.

Many domains.

---

# Redirect WWW to Non-WWW

Example:

```
www.example.com

↓

example.com
```

Configuration:

```nginx
server {

    listen 80;

    server_name www.example.com;

    return 301 http://example.com$request_uri;

}
```

We'll learn redirects in detail in Lesson 8.

# Organizing Server Blocks

Ubuntu/Linux Mint stores website configurations in:

```
/etc/nginx/sites-available/
```

Example:

```
sites-available/

example

blog

api

shop
```

Enable them:

```
sites-enabled/

example

blog
```

Each file usually contains **one server block**.

---

# Enable a Website

```bash
sudo ln -s \
/etc/nginx/sites-available/blog \
/etc/nginx/sites-enabled/
```

---

# Disable a Website

```bash
sudo rm \
/etc/nginx/sites-enabled/blog
```

Then reload:

```bash
sudo systemctl reload nginx
```

---

# Testing Configuration

Always check:

```bash
sudo nginx -t
```

If successful:

```

test is successful
```

Reload:

```bash
sudo systemctl reload nginx
```

# Common Mistakes

## Missing `server_name`

Wrong:

```nginx
server {

    listen 80;

}
```

This may work, but requests might not be routed as you expect.

---

## Same Domain Twice

Wrong:

```nginx
server_name example.com;
```

appearing in two different server blocks.

Nginx won't know which one you intended.

---

## Wrong Root Directory

Example:

```nginx
root /var/www/blog;
```

But your files are actually in:

```
/var/www/blogsite
```

Result:

```
404 Not Found
```

---

## Forgetting Reload

After editing:

```bash
sudo systemctl reload nginx
```

Otherwise, Nginx continues using the old configuration.

---

# Best Practices

- One server block per website or application.
    
- Keep each site's configuration in its own file.
    
- Use meaningful filenames (`api`, `blog`, `portfolio`).
    
- Always specify `server_name`.
    
- Configure a `default_server`.
    
- Test with `nginx -t` before reloading.

# Interview Questions

### 1. What is a Server Block?

A server block is a configuration block that tells Nginx how to handle requests for a specific domain, IP address, or port.

---

### 2. What is a Virtual Host?

A virtual host allows multiple websites or applications to run on the same server by routing requests based on the domain name or port.

---

### 3. What does the `server_name` directive do?

It specifies which domain names should be handled by a particular server block.

---

### 4. What is the purpose of `listen 80;`?

It tells Nginx to accept HTTP requests on TCP port 80.

---

### 5. What is a default server?

A default server handles requests that don't match any configured `server_name`.

# Hands-on Practice

## Step 1: Create two website directories

```bash
sudo mkdir -p /var/www/site1
sudo mkdir -p /var/www/site2
```

---

## Step 2: Create simple pages

```bash
echo "<h1>Welcome to Site 1</h1>" | sudo tee /var/www/site1/index.html

echo "<h1>Welcome to Site 2</h1>" | sudo tee /var/www/site2/index.html
```

---

## Step 3: Create two server block files

```bash
sudo nvim /etc/nginx/sites-available/site1
```

```nginx
server {
    listen 80;
    server_name site1.local;

    root /var/www/site1;
    index index.html;
}
```

Now create:

```bash
sudo nvim /etc/nginx/sites-available/site2
```

```nginx
server {
    listen 80;
    server_name site2.local;

    root /var/www/site2;
    index index.html;
}
```

---

## Step 4: Enable them

```bash
sudo ln -s /etc/nginx/sites-available/site1 /etc/nginx/sites-enabled/

sudo ln -s /etc/nginx/sites-available/site2 /etc/nginx/sites-enabled/
```

---

## Step 5: Test

```bash
sudo nginx -t
```

---

## Step 6: Reload

```bash
sudo systemctl reload nginx
```

---

## Step 7: Verify

On a local machine, you can temporarily map `site1.local` and `site2.local` to `127.0.0.1` in your `/etc/hosts` file, then visit:

```
http://site1.local

http://site2.local
```

Each should display its own page.

# Key Takeaways

- A **Server Block** defines how Nginx serves a website or application.
    
- **Virtual Hosts** let one server host many websites.
    
- `listen` specifies the port to accept connections on.
    
- `server_name` matches the request's `Host` header.
    
- `default_server` handles unmatched requests.
    
- A common Linux layout is `sites-available` for configurations and `sites-enabled` for active sites.
    
- Always test with `nginx -t` before reloading Nginx.
