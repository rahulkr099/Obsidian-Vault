# 1. What Is Grafana? ⭐⭐⭐⭐⭐

Grafana Labs develops Grafana, an open-source visualization and observability platform.

Think of the relationship like this:

```text
Prometheus
    ↓
Collects + stores metrics
    ↓
Grafana
    ↓
Visualizes metrics
```

Prometheus is the **metrics engine**.

Grafana is the **visualization layer**.

---

# 2. Why Do We Need Grafana?

Imagine Prometheus has these numbers:

```text
CPU = 82
Memory = 74
Disk = 91
Requests = 1520
Errors = 32
Latency = 480
```

That's useful.

But imagine seeing:

```text
CPU
100% ┤                   ╭──╮
 80% ┤              ╭────╯  ╰─
 60% ┤        ╭─────╯
 40% ┤────────╯
 20% ┤
     └─────────────────────────
       10:00  10:15  10:30  10:45
```

Now you can immediately see:

> CPU has been increasing over time.

That's the power of visualization.

# 3. Grafana Architecture

The basic architecture:

```text
                 ┌───────────────┐
                 │    Grafana    │
                 └───────┬───────┘
                         │
                   Query metrics
                         │
                         ▼
                 ┌───────────────┐
                 │  Prometheus   │
                 └───────┬───────┘
                         │
                       Scrape
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
       Node Exporter   Node.js        Nginx
```

Grafana doesn't normally collect the metrics itself.

It asks Prometheus:

> "Give me the data for this time range."

# 4. Grafana Is Not the Metrics Database

This distinction is important.

```text
Prometheus
→ Metrics storage/query

→ Visualization/dashboard
```

You can think:

```text

   ↓
Prometheus

Frontend
   ↓
Grafana
```

Grafana is effectively the **frontend for your observability data**.

# 30. CPU Dashboard

Once Node Exporter is installed, you can query CPU metrics.

A common approach is based on:

```text
node_cpu_seconds_total
```

For example, CPU utilization can be calculated from idle CPU time.

A common PromQL pattern is:

```promql
100 * (
  1 - avg by (instance) (
    rate(node_cpu_seconds_total{mode="idle"}[5m])
  )
)
```

Conceptually:

```text
100%
  -
idle CPU %
  =
CPU utilization %
```

---

# 31. Why We Don't Just Plot `node_cpu_seconds_total`

Because:

```text
node_cpu_seconds_total
```

is a cumulative counter.

We need to calculate its recent rate:

```promql
rate(...)
```

Then convert that into utilization.

This is a perfect example of why understanding PromQL is important.

---

# 32. Memory Dashboard

A useful memory utilization query can be based on:

```text
node_memory_MemTotal_bytes
node_memory_MemAvailable_bytes
```

Conceptually:

```promql
100 * (
  1 -
  node_memory_MemAvailable_bytes
  /
  node_memory_MemTotal_bytes
)
```

This gives approximate memory utilization.

---

# 33. Disk Dashboard

You can monitor filesystem usage using metrics such as:

```text
node_filesystem_size_bytes
node_filesystem_avail_bytes
```

Conceptually:

```promql
100 * (
  1 -
  node_filesystem_avail_bytes
  /
  node_filesystem_size_bytes
)
```

You would usually filter out special/pseudo filesystems.

For example, in a real dashboard you might add filters based on:

```text
fstype
mountpoint
device
```

You can calculate traffic rate using:

```promql

```

and:

```promql

```

Now Grafana can display:


# 35. API Request Rate

For your Node.js backend, imagine:

```text
http_requests_total
```

Use:

```promql
sum(rate(http_requests_total[5m]))
```

This gives an overall request rate.

You can visualize:

```text
Requests/sec
```

as a time-series graph.

---

# 36. API Error Rate

Suppose your application exposes:

```text
http_requests_total{
  status="500"
}
```

You could calculate:

```text
sum(rate(http_requests_total{status=~"5.."}[5m]))
```

This estimates the rate of 5xx responses.

You can then compare:

```text
Total requests
vs
5xx requests
```

to calculate an error percentage.

---

# 37. API Latency

Suppose you expose:

```text
http_request_duration_seconds
```

using a histogram.

You can eventually query percentiles such as p95.

A common pattern is:

```promql
histogram_quantile(
  0.95,
  sum by (le) (
    rate(http_request_duration_seconds_bucket[5m])
  )
)
```

This estimates:

> p95 request latency.

In other words:

> About 95% of requests are at or below this latency during the selected period.

---

# 38. Why p95 Is Useful

Suppose:

```text
Average = 100ms
```

Sounds excellent.

But:

```text
p95 = 900ms
p99 = 2.5s
```

Now you know a meaningful portion of users are experiencing much slower requests.

This is why professional backend dashboards often track:

```text
p50
p95
p99
```

instead of only average latency.

# 48. Dashboard Refresh vs Scrape Interval

These are different.

Prometheus:

```text
scrape_interval = 15s
```

means Prometheus collects metrics every ~15 seconds.

Grafana:

```text
refresh = 30s
```

means Grafana refreshes the dashboard every ~30 seconds.

So:

```text
Target
 ↓ 15 sec
Prometheus
 ↓ 30 sec
Grafana
```

These settings should be chosen based on your needs.

# 57. Mini Challenge 4

You have:

```text
user_id
```

as a Prometheus label.

Why is this dangerous?

### Answer:

Because user IDs can have enormous cardinality.

That can create:

```text
Huge number of time series
        ↓
High memory usage
        ↓
Large storage requirements
        ↓
Poor Prometheus performance
```

Use bounded labels instead.

Avoid these.

### ❌ Everything on one dashboard

```text
100 panels
```

### ❌ No units

```text

```

### ❌ Meaningless titles

```text

Graph 2
```

### ❌ High-cardinality labels

```text

request_id
```

### ❌ Only current values

You need trends too.

### ❌ Only infrastructure metrics

CPU may be fine while your API returns 30% errors.


# 67. Interview Questions ⭐⭐⭐⭐⭐

### Q1. What is Grafana?

> Grafana is an observability and visualization platform used to query and visualize data from sources such as Prometheus.

---

### Q2. What is a Grafana data source?

> A data source is the backend from which Grafana retrieves data, such as Prometheus, Loki, PostgreSQL, or Elasticsearch.

---

### Q3. What's the relationship between Prometheus and Grafana?

> Prometheus collects and stores metrics, while Grafana queries those metrics and visualizes them through dashboards.

---

### Q4. What is a Grafana panel?

> A panel is an individual visualization on a dashboard, such as a time-series graph, stat, gauge, or table.

---

### Q5. Why are Grafana variables useful?

> Variables allow a dashboard to dynamically switch between things like servers, services, environments, or regions without creating separate dashboards.

---

### Q6. Why are dashboards important during incidents?

> They allow engineers to quickly see changes and correlations in traffic, errors, latency, resource usage, and dependencies over time.
