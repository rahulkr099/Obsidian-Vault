# 3. Why Docker Compose?

You could install everything directly on Linux.

But for this learning project, Docker Compose gives us:

```text
Prometheus
Grafana
Alertmanager
Loki
Node Exporter
```

in a reproducible environment.

Instead of:

```text
Install manually
Configure
Configure again
Break something
```

we can use:

```text
docker compose up -d
```

and recreate the environment when necessary.

# 6. Docker Compose

Create:

```bash
nano docker-compose.yml
```

A learning-oriented starting point:

```yaml
services:

  prometheus:
    image: prom/prometheus
    container_name: prometheus
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - ./prometheus/rules:/etc/prometheus/rules:ro
    command:
      - "--config.file=/etc/prometheus/prometheus.yml"
    restart: unless-stopped

  grafana:
    image: grafana/grafana
    container_name: grafana
    ports:
      - "3000:3000"
    restart: unless-stopped

  alertmanager:
    image: prom/alertmanager
    container_name: alertmanager
    ports:
      - "9093:9093"
    volumes:
      - ./alertmanager/alertmanager.yml:/etc/alertmanager/alertmanager.yml:ro
    command:
      - "--config.file=/etc/alertmanager/alertmanager.yml"
    restart: unless-stopped

  node-exporter:
    image: prom/node-exporter
    container_name: node-exporter
    ports:
      - "9100:9100"
    restart: unless-stopped
```

This is our first version.

We'll add centralized logging after the basic monitoring pipeline works.

# 9. Prometheus Configuration

Create:

```bash
nano prometheus/prometheus.yml
```

Start with:

```yaml
global:
  scrape_interval: 15s

rule_files:
  - "/etc/prometheus/rules/*.yml"

alerting:
  alertmanagers:
    - static_configs:
        - targets:
            - "alertmanager:9093"

scrape_configs:

  - job_name: "prometheus"
    static_configs:
      - targets:
          - "prometheus:9090"

  - job_name: "node-exporter"
    static_configs:
      - targets:
          - "node-exporter:9100"
```

Notice something important:

```text
alertmanager:9093
```

not:

```text
localhost:9093
```

Why?

Because Prometheus is running **inside a Docker network**.

Docker service names can be used as hostnames.

```promql

    rate(node_cpu_seconds_total{mode="idle"}[5m])
  )
```

# 15. Memory Usage Query

```promql
100 * (
  1 -
  node_memory_MemAvailable_bytes
  /
  node_memory_MemTotal_bytes
)
```

This gives approximate memory utilization.

---

# 16. Disk Usage Query

One useful filesystem query is:

```promql
100 * (
  1 -
  node_filesystem_avail_bytes{
    fstype!~"tmpfs|overlay"
  }
  /
  node_filesystem_size_bytes{
    fstype!~"tmpfs|overlay"
  }
)
```

For production, you'd refine this to ignore pseudo-filesystems and select the actual filesystems you care about.

# 27. Alert Rules

Create:

```bash
nano prometheus/rules/system-alerts.yml
```

Example:

```yaml
groups:

  - name: system-alerts

    rules:

      - alert: NodeExporterDown
        expr: up{job="node-exporter"} == 0
        for: 2m

        labels:
          severity: critical
          service: infrastructure

        annotations:
          summary: "Node Exporter is down"
          description: "Node Exporter has been unavailable for more than 2 minutes."

      - alert: HighCPUUsage
        expr: |
          100 * (
            1 - avg by (instance) (
              rate(node_cpu_seconds_total{mode="idle"}[5m])
            )
          ) > 85

        for: 5m

        labels:
          severity: warning
          service: infrastructure

        annotations:
          summary: "High CPU usage"
          description: "CPU usage has remained above 85% for 5 minutes."

      - alert: HighMemoryUsage
        expr: |
          100 * (
            1 -
            node_memory_MemAvailable_bytes
            /
            node_memory_MemTotal_bytes
          ) > 85

        for: 5m

        labels:
          severity: warning
          service: infrastructure

        annotations:
          summary: "High memory usage"
          description: "Memory usage has remained above 85% for 5 minutes."
```

---

# 28. Important Alert Design

Notice:

```yaml
for: 5m
```

We don't alert immediately when CPU briefly reaches 86%.

Instead:

```text
CPU = 86%
   ↓
wait
   ↓
still high after 5 min
   ↓
alert
```

This reduces noise.

# 39. Add Node.js to Prometheus

Update:

```text
prometheus/prometheus.yml
```

Add:

```yaml
  - job_name: "node-api"
    static_configs:
      - targets:
          - "host.docker.internal:5000"
```

On Linux, `host.docker.internal` may require special Docker configuration depending on your Docker setup. A more production-like approach is to put the API into the same Compose network and scrape it by its service name.

For example, if your API becomes a Compose service:

```yaml
  api:
    build: ./app
    ports:
      - "5000:5000"
```

then Prometheus can use:

```yaml
  - job_name: "node-api"
    static_configs:
      - targets:
          - "api:5000"
```

That's cleaner.

# 45. Why Loki?

Without centralized logging:

```text
Server 1
  └── app.log

Server 2
  └── app.log

Server 3
  └── app.log
```

You have to SSH into each server.

With centralized logging:

```text
Server 1 ─┐
Server 2 ─┼──→ Loki
Server 3 ─┘      ↓
               Grafana
```

Much easier.

# 47. Log Collection

Loki itself doesn't magically read every application log file.

You need a log collector/agent.

Historically this could be:

```text
Promtail
```

but Grafana's current logging ecosystem also includes newer collection approaches such as Grafana Alloy.

For this module, understanding the pipeline is more important than tying the project to one specific agent:

```text
Application logs
      ↓
Log collector
      ↓
Loki
      ↓
Grafana
```

# 48. Structured JSON Logs

Your Node.js application should produce logs like:

```json
{
  "timestamp": "2026-08-15T10:30:00Z",
  "level": "error",
  "service": "api",
  "request_id": "abc123",
  "method": "GET",
  "route": "/api/orders",
  "status": 500,
  "message": "Database query failed"
}
```

This is much better than:

```text
Something went wrong
```

# 75. Metric Cardinality ⚠️

Suppose you create a metric label:

# 89. Interview Question — Why Both Logs and Metrics?
