# 1. What is `curl`?

`curl` stands for **Client URL**.

It is a command-line tool used to communicate with servers using URLs.

Think of it as a **web browser without a graphical interface**.

Instead of clicking buttons, you type commands.

For example, when you open Chrome and visit:

```
<https://google.com>
```

Chrome sends an HTTP request to Google's server.

`curl` does exactly the same thing.

Example:

```bash
curl <https://google.com>
```

---

# 2. Why Backend Developers Love `curl`

Backend developers constantly need to:

- Test APIs
- Debug servers
- Check HTTP responses
- Test authentication
- Inspect headers
- Download files
- Automate requests

Instead of opening Postman every time, they often use `curl`.

Example:

```bash
curl <http://localhost:3000/api/users>
```

This tests your local backend instantly.

# 3. Client and Server

Imagine ordering food online.

```
You
 ↓
Restaurant
 ↓
Food comes back
```

In web development:

```
Client
 ↓
Server
 ↓
Response
```

The **client** makes a request.

The **server** processes it.

The **server** sends a response.

---

## Real Example

```
Chrome
   │
   │ GET /
   ▼
Express Server
   │
   │ JSON
   ▼
Chrome
```

Or using `curl`:

```
curl
   │
   │ GET /
   ▼
Node.js Server
   │
   │ JSON
   ▼
Terminal
```

# 4. What Happens When You Visit a Website?

Suppose you visit:

```
<https://github.com>
```

Your browser sends:

```
GET /
Host: github.com
```

GitHub receives it.

GitHub prepares the page.

GitHub sends back:

- HTML
- CSS
- JavaScript
- Images
- Headers

Your browser displays everything.

With `curl`, you only see the server's response.

---

# 5. HTTP Request Lifecycle

```
You
 │
 │ curl <https://example.com>
 ▼
Internet
 ▼
Server
 ▼
Process Request
 ▼
Response
 ▼
Terminal
```

Everything on the internet works using this request-response cycle.

---

# 6. Your First `curl` Command

Run:

```bash
curl <https://httpbin.org/get>
```

Expected output (formatted for readability):

```json
{
  "args": {},
  "headers": {
    "Accept": "*/*",
    "Host": "httpbin.org"
  },
  "origin": "YOUR_IP",
  "url": "<https://httpbin.org/get>"
}
```

---

# 7. Understanding the Response

The server sends JSON.

Example:

```json
{
  "origin": "203.0.113.10",
  "url": "<https://httpbin.org/get>"
}
```

Meaning:

- `origin` → Your public IP address.
- `url` → The URL that received your request.

---

# 8. Another Example

Try:

```bash
curl <https://api.github.com>
```

GitHub responds with information about its API.

Notice that you're not downloading a webpage—you are talking directly to GitHub's server.

---

# 9. Local Server Example

Suppose your Express app is running on port `3000`.

```bash
curl <http://localhost:3000>
```

If your Express code is:

```jsx
app.get("/", (req, res) => {
  res.send("Hello World");
});
```

You'll see:

```
Hello World
```

No browser needed.

# 10. Common Uses of `curl`

- Test REST APIs
- Download files
- Check server health
- Debug authentication
- View response headers
- Upload files
- Test webhooks
- Automate API calls in shell scripts

# 🧠 Key Terms

|Term|Meaning|
|---|---|
|Client|Sends the request|
|Server|Receives and processes the request|
|HTTP|Protocol used for web communication|
|Request|Message sent by the client|
|Response|Message returned by the server|
|URL|Address of a resource|
|API|Interface for software communication|
