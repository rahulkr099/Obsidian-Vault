# 1. General Syntax

A `curl` command usually looks like this:

```bash
curl [OPTIONS] URL
```

Example:

```bash
curl <https://httpbin.org/get>
```

Here:

|Part|Meaning|
|---|---|
|`curl`|The program|
|`https://httpbin.org/get`|The URL to request|

---

# 2. A More Complete Example

```bash
curl \
-X POST \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

This may look complicated, but it has only five parts.

```
curl
 │
 ├── -X POST
 │
 ├── -H "Content-Type: application/json"
 │
 ├── -d '{"name":"Rahul"}'
 │
 └── URL
```

---

# 3. Part 1 — `curl`

This is simply the program you're running.

You can verify it's installed:

```bash
curl --version
```

Example output:

```
curl 8.16.0
Protocols: http https ftp ftps ...
Features: SSL IPv6 HTTP2 ...
```

---

# 4. Part 2 — The URL

Every request needs a destination.

```bash
curl <https://example.com>
```

The URL tells `curl`:

> "Send this request to this server."

Examples:

```bash
curl <https://httpbin.org/get>
```

```bash
curl <https://api.github.com>
```

```bash
curl <http://localhost:3000>
```

---

# 5. Part 3 — Options (Flags)

Everything beginning with `-` or `--` is an option.

Examples:

```bash
-X
```

```bash
-H
```

```bash
-d
```

```bash
-v
```

```bash
-L
```

Options change how `curl` behaves.

Without options:

```bash
curl <https://httpbin.org/get>
```

With options:

```bash
curl -v <https://httpbin.org/get>
```

Now `curl` prints additional debugging information.

---

# 6. Short vs. Long Options

Most options have two forms.

Short:

```bash
-X
```

Long:

```bash
--request
```

Both mean the same thing.

Example:

```bash
curl -X POST <https://httpbin.org/post>
```

is identical to

```bash
curl --request POST <https://httpbin.org/post>
```

Here are some common pairs:

|Short|Long|
|---|---|
|`-X`|`--request`|
|`-H`|`--header`|
|`-d`|`--data`|
|`-v`|`--verbose`|
|`-L`|`--location`|
|`-o`|`--output`|

Most developers use the short versions because they're faster to type.

---

# 7. What Does `X` Do?

- `X` specifies the HTTP request method.

```bash
curl -X GET <https://httpbin.org/get>
```

```bash
curl -X POST <https://httpbin.org/post>
```

```bash
curl -X DELETE <https://httpbin.org/delete>
```

Without `-X`, `curl` usually sends a **GET** request.

---

# 8. What Does `H` Do?

- `H` adds an HTTP header.

Example:

```bash
curl \
-H "Content-Type: application/json" \
<https://httpbin.org/get>
```

Headers provide extra information to the server.

You can send multiple headers:

```bash
curl \
-H "Authorization: Bearer TOKEN" \
-H "Accept: application/json" \
<https://httpbin.org/get>
```

---

# 9. What Does `d` Do?

- `d` sends data in the request body.

Example:

```bash
curl \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

This sends:

```json
{
  "name": "Rahul"
}
```

When you use `-d`, `curl` automatically switches the request method to **POST** unless you specify another method with `-X`.

---

# 10. Why the Quotes?

Consider:

```bash
-H "Content-Type: application/json"
```

The quotes tell the shell to treat everything inside as one argument.

Similarly:

```bash
-d '{"name":"Rahul"}'
```

The quotes keep the JSON together as a single value.

Without quotes, the shell would split the text incorrectly.

---

# 11. Why the Backslashes?

This:

```bash
curl \
-X POST \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

is exactly the same as:

```bash
curl -X POST -H "Content-Type: application/json" -d '{"name":"Rahul"}' <https://httpbin.org/post>
```

The backslash (`\`) simply tells the shell:

> "Continue this command on the next line."

It improves readability.

---

# 12. Order of Options

These are equivalent:

```bash
curl -X POST -H "Content-Type: application/json" <https://httpbin.org/post>
```

```bash
curl -H "Content-Type: application/json" -X POST <https://httpbin.org/post>
```

The order of most options does **not** matter.

A common style is:

1. Command
2. Method
3. Headers
4. Data
5. URL

because it's easier to read.

---

# 13. Reading a curl Command

Can you understand this?

```bash
curl \
-X POST \
-H "Authorization: Bearer abc123" \
-H "Content-Type: application/json" \
-d '{"title":"Learn curl"}' \
<https://example.com/api/todos>
```

Break it down:

|Part|Meaning|
|---|---|
|`curl`|Run the program|
|`-X POST`|Use POST method|
|`-H "Authorization: Bearer abc123"`|Send authentication token|
|`-H "Content-Type: application/json"`|Body is JSON|
|`-d ...`|Send JSON data|
|URL|Destination server|

# 💡 Pro Tip

You don't need to memorize every option. Two commands are enough to explore `curl` whenever you're unsure:

```bash
curl --help
```

For a full reference:

```bash
man curl
```

Learning to read the manual (`man`) is an important Linux skill that applies to many commands, not just `curl`.
