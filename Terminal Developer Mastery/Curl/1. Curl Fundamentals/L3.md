# 1. What is a GET Request?

A **GET** request asks a server to **send data**.

Think of it as asking a librarian:

> "Please give me this book."

You are **reading** information, not changing anything.

Examples:

- View a profile
- Read a blog post
- Get product details
- Search for users
- Fetch weather information

All of these usually use **GET**.

---

# 2. The Simplest GET Request

```bash
curl <https://httpbin.org/get>
```

Output:

```json
{
  "args": {},
  "headers": {
    ...
  },
  "origin": "YOUR_IP",
  "url": "<https://httpbin.org/get>"
}
```

Notice:

```json
"args": {}
```

No query parameters were sent.

---

# 3. Do We Need `X GET`?

You _can_ write:

```bash
curl -X GET <https://httpbin.org/get>
```

But it's unnecessary.

Because:

```bash
curl <https://httpbin.org/get>
```

already means:

```
GET <https://httpbin.org/get>
```

**Best Practice:**

✔️ Write:

```bash
curl <https://httpbin.org/get>
```

instead of

```bash
curl -X GET <https://httpbin.org/get>
```

unless you're doing it for clarity or scripting consistency.

---

# 4. Query Parameters

Many APIs accept extra information in the URL.

Example:

```
<https://example.com/search?q=linux>
```

Everything after the `?` is called the **query string**.

Structure:

```
URL?key=value
```

Example:

```bash
curl "<https://httpbin.org/get?name=Rahul>"
```

Output:

```json
{
  "args": {
    "name": "Rahul"
  }
}
```

The server received:

```
name = Rahul
```

---

# 5. Multiple Query Parameters

You separate parameters with `&`.

```bash
curl "<https://httpbin.org/get?name=Rahul&age=21>"
```

Output:

```json
{
  "args": {
    "name": "Rahul",
    "age": "21"
  }
}
```

Notice:

Everything is received as a **string**.

```
21
```

is not automatically a number.

---

# 6. More Examples

Search:

```bash
curl "<https://httpbin.org/get?search=nodejs>"
```

Pagination:

```bash
curl "<https://httpbin.org/get?page=2>"
```

Sorting:

```bash
curl "<https://httpbin.org/get?sort=desc>"
```

Filtering:

```bash
curl "<https://httpbin.org/get?role=admin>"
```

Real APIs use these constantly.

---

# 7. Combining Parameters

Example:

```bash
curl "<https://httpbin.org/get?search=express&page=3&limit=10>"
```

The server receives:

```json
{
  "search":"express",
  "page":"3",
  "limit":"10"
}
```

This is exactly how your Express backend will receive query parameters.

---

# 8. Express Example

Imagine this Express route:

```jsx
app.get("/users", (req, res) => {
  res.json(req.query);
});
```

Run:

```bash
curl "<http://localhost:3000/users?city=Bokaro&age=21>"
```

Response:

```json
{
  "city":"Bokaro",
  "age":"21"
}
```

`req.query` contains all query parameters.

# 9. Understanding the URL

Example:

```
<https://example.com/users?page=2&limit=20>
```

Break it down:

```
https://
│
Protocol
```

```
example.com
│
Domain
```

```
/users
│
Path
```

```
?page=2
│
Query starts
```

```
&limit=20
│
Another parameter
```

# 10. URL Encoding

Not every character is allowed directly in a URL.

For example:

```
Rahul Kumar
```

contains a space.

Incorrect:

```
?name=Rahul Kumar
```

Correct:

```
?name=Rahul%20Kumar
```

Space becomes:

```
%20
```

Example:

```bash
curl "<https://httpbin.org/get?name=Rahul%20Kumar>"
```

Output:

```json
{
  "args":{
    "name":"Rahul Kumar"
  }
}
```

---

# 11. Common URL Encodings

|Character|Encoded|
|---|---|
|Space|`%20`|
|`@`|`%40`|
|`#`|`%23`|
|`&`|`%26`|
|`/`|`%2F`|
|`?`|`%3F`|

Example:

Email:

```
rahul@gmail.com
```

becomes

```
rahul%40gmail.com
```

---

# 12. Pretty-print the Response

Instead of:

```bash
curl <https://httpbin.org/get>
```

Use:

```bash
curl <https://httpbin.org/get> | jq
```

Only show query parameters:

```bash
curl "<https://httpbin.org/get?name=Rahul>" | jq '.args'
```

Output:

```json
{
  "name":"Rahul"
}
```

Only show headers:

```bash
curl <https://httpbin.org/get> | jq '.headers'
```

Only show URL:

```bash
curl <https://httpbin.org/get> | jq '.url'
```

# 13. Real API Example

GitHub API:

```bash
curl <https://api.github.com/users/octocat> | jq
```

Only the username:

```bash
curl <https://api.github.com/users/octocat> | jq '.login'
```

Followers:

```bash
curl <https://api.github.com/users/octocat> | jq '.followers'
```

Public repositories:

```bash
curl <https://api.github.com/users/octocat> | jq '.public_repos'
```

This is a common pattern when scripting with APIs.

---

# 14. GET vs POST

|GET|POST|
|---|---|
|Read data|Create data|
|Query parameters|Request body|
|Usually no body|Usually has a body|
|Safe to repeat|May change server state|

Example:

Read users:

```bash
curl <https://example.com/users>
```

Create user:

```bash
curl \
-X POST \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://example.com/users>
```

# 💡 Pro Tip

When a URL contains special characters like `?`, `&`, or spaces, wrap the entire URL in **double quotes**:

```bash
curl "<https://httpbin.org/get?name=Rahul&city=Bokaro>"
```

Without quotes, your shell may interpret characters like `&` as shell operators instead of part of the URL.
