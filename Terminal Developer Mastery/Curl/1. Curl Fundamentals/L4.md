# 1. What are HTTP Headers?

When a client sends a request, it sends **two things**:

1. **The actual request**
2. **Extra information about the request**

That extra information is called **headers**.

Think of headers as the envelope around a letter.

```
┌──────────────────────────────┐
│ Request Line                 │
│ GET /users HTTP/1.1          │
├──────────────────────────────┤
│ Headers                      │
│ Host: api.example.com        │
│ Accept: application/json     │
│ User-Agent: curl/8.16.0      │
├──────────────────────────────┤
│ Body (optional)              │
└──────────────────────────────┘
```

---

# 2. Request vs Response Headers

There are **two kinds** of headers.

## Request Headers

Sent by the client.

```
You
 ↓
Headers
 ↓
Server
```

Example:

```
Accept: application/json
Authorization: Bearer TOKEN
```

---

## Response Headers

Sent by the server.

```
Server
 ↓
Headers
 ↓
You
```

Example:

```
Content-Type: application/json
Content-Length: 452
Server: nginx
```

---

# 3. The `H` Flag

Syntax:

```bash
curl -H "Header-Name: Value" URL
```

Example:

```bash
curl \
-H "Accept: application/json" \
<https://httpbin.org/get>
```

The server receives:

```
Accept: application/json
```

---

# 4. Viewing the Headers You Sent

Run:

```bash
curl \
-H "Accept: application/json" \
<https://httpbin.org/get> | jq '.headers'
```

Example output:

```json
{
  "Accept": "application/json",
  "Host": "httpbin.org",
  "User-Agent": "curl/8.16.0"
}
```

Notice your custom header appears in the response.

---

# 5. The Most Important Headers

Let's learn the ones you'll use every day.

---

## A. `Content-Type`

Tells the server:

> "This is the format of the body I'm sending."

Example:

```bash
curl \
-X POST \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

Without it, many servers won't know how to interpret the request body.

Common values:

```
application/json
```

```
application/xml
```

```
text/plain
```

```
multipart/form-data
```

```
application/x-www-form-urlencoded
```

---

## B. `Accept`

Tells the server:

> "I'd like the response in this format."

Example:

```bash
curl \
-H "Accept: application/json" \
<https://httpbin.org/get>
```

Common values:

```
application/json
```

```
text/html
```

```
application/xml
```

The server may respond differently depending on this header.

---

## C. `Authorization`

Used for authentication.

Example:

```bash
curl \
-H "Authorization: Bearer YOUR_TOKEN" \
<https://api.example.com/profile>
```

Server:

```
Authorization
 ↓
Verify Token
 ↓
Allow or Reject
```

You'll use this constantly with Express and JWT authentication.

---

## D. `User-Agent`

Every browser identifies itself.

Chrome:

```
Mozilla/5.0 ...
```

curl:

```
curl/8.16.0
```

See yours:

```bash
curl <https://httpbin.org/user-agent>
```

Output:

```json
{
  "user-agent":"curl/8.16.0"
}
```

Override it:

```bash
curl \
-H "User-Agent: RahulBrowser/1.0" \
<https://httpbin.org/user-agent>
```

---

## E. `Host`

Automatically added.

Example:

```
Host: httpbin.org
```

Normally you never set it manually.

---

# 6. Multiple Headers

You can use multiple `-H` options.

```bash
curl \
-H "Accept: application/json" \
-H "Authorization: Bearer TOKEN" \
-H "User-Agent: RahulBrowser/1.0" \
<https://httpbin.org/get>
```

Every `-H` adds one header.

---

# 7. Inspecting Response Headers

Show **only headers**:

```bash
curl -I <https://httpbin.org/get>
```

Example:

```
HTTP/2 200

content-type: application/json

content-length: 278
```

---

Headers + body:

```bash
curl -i <https://httpbin.org/get>
```

Output:

```
HTTP/2 200

Content-Type: application/json

...

{
   JSON BODY
}
```

---

# 8. Verbose Mode

```bash
curl -v <https://httpbin.org/get>
```

This shows:

```
> GET /get HTTP/2
```

Request headers:

```
> User-Agent: curl/8.16.0
```

Response headers:

```
< HTTP/2 200
```

```
< Content-Type: application/json
```

The symbols are important:

|Symbol|Meaning|
|---|---|
|`>`|Sent by your client|
|`<`|Received from the server|

---

# 9. Express Example

Express:

```jsx
app.get("/hello", (req, res) => {
    console.log(req.headers);
    res.send("Hello");
});
```

Request:

```bash
curl \
-H "City: Bokaro" \
-H "Language: English" \
<http://localhost:3000/hello>
```

Console:

```jsx
{
  city: "Bokaro",
  language: "English",
  host: "localhost:3000",
  user-agent: "curl/8.16.0"
}
```

Express stores request headers in:

```jsx
req.headers
```

---

# 10. Real Authentication Example

Imagine your Todo API.

Without token:

```bash
curl <http://localhost:3000/api/todos>
```

Server:

```
401 Unauthorized
```

With token:

```bash
curl \
-H "Authorization: Bearer eyJhbGc..." \
<http://localhost:3000/api/todos>
```

Now Express middleware can verify the token.

---

# 11. Common Headers Every Backend Developer Should Know

|Header|Purpose|
|---|---|
|`Content-Type`|Format of request body|
|`Accept`|Desired response format|
|`Authorization`|Authentication|
|`User-Agent`|Client identity|
|`Host`|Destination server|
|`Cookie`|Session information|
|`Accept-Encoding`|Compression support|
|`Origin`|Used by browsers for CORS|
|`Referer`|Previous page|
|`Cache-Control`|Caching rules|

You don't need to memorize them all today, but these are the ones you'll encounter most often.

# 💡 Pro Tip

When you're debugging APIs, `curl -v` is often the first command to reach for. It lets you see:

- The exact request sent.
- Every request header.
- The HTTP status line.
- Every response header.

This makes it much easier to diagnose issues like missing authentication, incorrect content types, redirects, or server errors.
