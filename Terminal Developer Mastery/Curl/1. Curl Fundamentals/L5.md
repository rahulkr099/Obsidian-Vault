# 1. What is an HTTP Method?

An **HTTP method** tells the server **what action you want to perform**.

Think of it like giving instructions to a waiter.

```
Customer
   │
   ▼
"I want to..."
   │
   ├── Read the menu
   ├── Place an order
   ├── Change my order
   ├── Cancel my order
   ▼
Restaurant
```

Similarly:

```
Client
   │
   ▼
GET
POST
PUT
PATCH
DELETE
HEAD
OPTIONS
   │
   ▼
Server
```

---

# 2. The Most Important HTTP Methods

|Method|Purpose|Changes Server?|
|---|---|---|
|GET|Read data|❌ No|
|POST|Create data|✅ Yes|
|PUT|Replace data|✅ Yes|
|PATCH|Update part of data|✅ Yes|
|DELETE|Remove data|✅ Yes|
|HEAD|Get headers only|❌ No|
|OPTIONS|Ask what methods are allowed|❌ No|

These seven methods cover almost everything you'll use in REST APIs.

---

# 3. GET — Read Data

Use GET when you want information.

Example:

```
GET /users
```

Meaning:

> "Give me all users."

Using curl:

```bash
curl <https://httpbin.org/get>
```

Express:

```jsx
app.get("/users", (req, res) => {
    res.json(users);
});
```

Examples:

- View profile
- Read blog
- Search products
- List todos

GET should **not modify data**.

---

# 4. POST — Create Data

POST creates something new.

Example:

```
POST /users
```

Meaning:

> "Create a new user."

Using curl:

```bash
curl \
-X POST \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

Express:

```jsx
app.post("/users", (req, res) => {
    res.json(req.body);
});
```

Real examples:

- Register user
- Login
- Create todo
- Upload image
- Submit form

---

# 5. PUT — Replace Everything

PUT replaces the entire resource.

Suppose your user is:

```json
{
    "name":"Rahul",
    "age":21,
    "city":"Bokaro"
}
```

You send:

```json
{
    "name":"Rahul Kumar",
    "age":22,
    "city":"Ranchi"
}
```

The old resource is completely replaced.

Curl:

```bash
curl \
-X PUT \
-H "Content-Type: application/json" \
-d '{"name":"Rahul Kumar","age":22,"city":"Ranchi"}' \
<https://httpbin.org/put>
```

Express:

```jsx
app.put("/users/:id", (req, res) => {
    res.json(req.body);
});
```

---

# 6. PATCH — Update Part of a Resource

PATCH updates only the fields you provide.

Original:

```json
{
    "name":"Rahul",
    "age":21,
    "city":"Bokaro"
}
```

Request:

```json
{
    "city":"Ranchi"
}
```

Result:

```json
{
    "name":"Rahul",
    "age":21,
    "city":"Ranchi"
}
```

Only the city changed.

Curl:

```bash
curl \
-X PATCH \
-H "Content-Type: application/json" \
-d '{"city":"Ranchi"}' \
<https://httpbin.org/patch>
```

Express:

```jsx
app.patch("/users/:id", (req, res) => {
    res.json(req.body);
});
```

---

# 7. PUT vs PATCH

Imagine a profile form.

Current profile:

```json
{
    "name":"Rahul",
    "age":21,
    "city":"Bokaro"
}
```

### PUT

You send:

```json
{
    "name":"Rahul Kumar",
    "age":22,
    "city":"Ranchi"
}
```

Everything is replaced.

---

### PATCH

You send:

```json
{
    "city":"Ranchi"
}
```

Only one field changes.

---

## Easy Way to Remember

```
PUT
──────────────
Replace whole object

PATCH
──────────────
Update only changes
```

# 8. DELETE — Remove Data

DELETE removes a resource.

Example:

```
DELETE /users/5
```

Meaning:

> "Delete user 5."

Curl:

```bash
curl \
-X DELETE \
<https://httpbin.org/delete>
```

Express:

```jsx
app.delete("/users/:id", (req, res) => {
    res.json({
        message: "Deleted"
    });
});
```

---

# 9. HEAD — Headers Only

HEAD is similar to GET.

Difference:

```
GET

Headers
+
Body
```

```
HEAD

Headers only
```

Example:

```bash
curl -I <https://httpbin.org/get>
```

Useful for:

- Checking if a page exists
- Checking file size
- Checking content type
- Checking cache information

---

# 10. OPTIONS — What Can I Do?

OPTIONS asks:

> "Which HTTP methods are allowed here?"

Example:

```bash
curl -X OPTIONS <https://httpbin.org/get>
```

Possible response:

```
Allow:
GET
HEAD
OPTIONS
```

Browsers also use OPTIONS automatically for many CORS preflight requests.

# 13. Express Example

```jsx
app.get("/todos", controller.getTodos);

app.post("/todos", controller.createTodo);

```

Notice how each HTTP method maps to a different operation.

# 14. Common Beginner Mistakes

### ❌ Using POST for everything

Bad:

```
POST /getUsers
```

Better:

```
GET /users
```

---

### ❌ Using PUT for a small update

Bad:

```
PUT /users/1
```

Body:

```json
{
    "city":"Delhi"
}
```

Better:

```
PATCH /users/1
```

---

### ❌ Sending a body with GET

Bad:

```bash
curl \
-X GET \
-d '{"name":"Rahul"}'
```

Most servers ignore GET request bodies.

Use query parameters instead:

```bash
curl "<https://example.com/users?name=Rahul>"
```

# 💡 Pro Tips

### 1. You don't always need `X`

These are equivalent:

```bash
curl <https://httpbin.org/get>
```

```bash
curl -X GET <https://httpbin.org/get>
```

`curl` uses **GET** by default.

---

### 2. `d` automatically uses POST

These are equivalent:

```bash
curl \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

```bash
curl \
-X POST \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

If you use `-d` without `-X`, `curl` automatically changes the method to **POST**.

---

### 3. RESTful APIs are predictable

A well-designed API usually follows this pattern:

|URL|Method|Action|
|---|---|---|
|`/users`|GET|List users|
|`/users/1`|GET|Get one user|
|`/users`|POST|Create user|
|`/users/1`|PATCH|Update user|
|`/users/1`|DELETE|Delete user|

Once you understand this pattern, you'll be able to work with most modern APIs.
