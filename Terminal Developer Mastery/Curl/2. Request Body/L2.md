# 1. What is JSON?

**JSON (JavaScript Object Notation)** is the most common format used by APIs to exchange data.

Example:

```json
{
  "name": "Rahul",
  "age": 21,
  "student": true
}
```

When you create a user, login, or create a todo, you're usually sending JSON.

---

# 2. Sending JSON with `curl`

The most common pattern is:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

Notice something?

There is **no `-X POST`**.

That's because when you use `-d`, **curl automatically changes the method from GET to POST**.

These are equivalent:

```bash
curl \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

```bash
curl \
-X POST \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

---

# 3. The `d` Option

Syntax:

```bash
-d 'JSON'
```

Example:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"city":"Bokaro"}' \
<https://httpbin.org/post>
```

Response:

```json
{
  "json": {
    "city": "Bokaro"
  }
}
```

The JSON was successfully received.

---

# 4. `d` vs `-data`

These are exactly the same.

Short version:

```bash
-d '{"name":"Rahul"}'
```

Long version:

```bash
--data '{"name":"Rahul"}'
```

Most developers use:

```bash
-d
```

because it's shorter.

---

# 5. `-data-raw`

Example:

```bash
curl \
--data-raw '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

For JSON APIs, `--data-raw` behaves almost the same as `-d`.

The main difference is:

- `d` has special handling for values starting with `@`.
- `-data-raw` treats everything literally.

Example:

```bash
-d @user.json
```

means:

> Read data from the file `user.json`.

But:

```bash
--data-raw @user.json
```

sends the literal text:

```
@user.json
```

---

# 6. `-data-binary`

Used when sending **raw binary data**.

Example:

```bash
curl \
--data-binary @image.png \
<https://example.com/upload>
```

This preserves the data exactly as it exists in the file.

You'll mainly use this when uploading raw files or sending binary payloads.

For JSON APIs, you usually **don't need it**.

# 7. JSON Data Types

JSON supports six main data types.

---

## String

```json
{
  "name": "Rahul"
}
```

Send:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

---

## Number

```json
{
  "age": 21
}
```

Notice:

```json
21
```

is **not inside quotes**.

---

## Boolean

```json
{
  "student": true
}
```

Correct:

```json
true
false
```

Wrong:

```json
"true"
```

because that's a string.

---

## Null

```json
{
  "phone": null
}
```

Used when a value intentionally has no data.

---

## Array

```json
{
  "skills": [
    "JavaScript",
    "Node.js",
    "MongoDB"
  ]
}
```

---

## Object

```json
{
  "address": {
    "city": "Bokaro",
    "state": "Jharkhand"
  }
}
```

# 11. Pretty Printing with `jq`

Instead of:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post>
```

Use:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post> | jq
```

Only show the JSON you sent:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<https://httpbin.org/post> | jq '.json'
```

# 12. Express Example

Express server:

```jsx
app.use(express.json());

app.post("/register", (req, res) => {
    console.log(req.body);

    res.json(req.body);
});
```

Request:

```bash
curl \
-H "Content-Type: application/json" \
-d '{
"name":"Rahul",
"email":"rahul@example.com"
}' \
<http://localhost:3000/register>
```

Console:

```jsx
{
  name: "Rahul",
  email: "rahul@example.com"
}
```

# 13. Common Mistakes

## ❌ Forgetting Quotes Around Keys

Wrong:

```json
{
name: "Rahul"
}
```

Correct:

```json
{
"name":"Rahul"
}
```

---

## ❌ Single Quotes Inside JSON

Wrong:

```json
{
'name':'Rahul'
}
```

JSON requires **double quotes** for keys and string values.

---

## ❌ Numbers as Strings

Wrong:

```json
{
"age":"21"
}
```

Correct:

```json
{
"age":21
}
```

Use numbers unless the API specifically expects strings.

---

## ❌ Boolean as String

Wrong:

```json
{
"student":"true"
}
```

Correct:

```json
{
"student":true
}
```

---

## ❌ Missing Content-Type

Some servers won't parse the request correctly if you omit:

```
Content-Type: application/json
```

Always include it when sending JSON.

# 💡 Pro Tips

### 1. Use single quotes around JSON in Bash

On Linux and macOS, this is usually the easiest:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}'
```

This avoids the shell interpreting the double quotes inside your JSON.

---

### 2. Validate JSON with `jq`

Before sending a large JSON payload, you can check if it's valid:

```bash
echo '{"name":"Rahul"}' | jq
```

If the JSON is invalid, `jq` will report an error.

---

### 3. Use a file for large payloads

When your JSON grows beyond a few lines, it's cleaner to save it to a file and send it with:

```bash
curl \
-H "Content-Type: application/json" \
-d @user.json \
<https://httpbin.org/post>
```

You'll learn this in the next lesson.
