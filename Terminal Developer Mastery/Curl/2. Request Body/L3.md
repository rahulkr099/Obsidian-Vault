# 1. What is Nested JSON?

So far, you've sent simple JSON like:

```json
{
  "name": "Rahul",
  "age": 21
}
```

But real APIs rarely use such simple data.

They usually send **objects inside objects** and **arrays inside objects**.

This is called **nested JSON**.

---

# 2. JSON Refresher

JSON is made up of:

- Objects (`{}`)
- Arrays (`[]`)
- Strings
- Numbers
- Booleans
- `null`

Example:

```json
{
  "name": "Rahul",
  "age": 21,
  "student": true,
  "skills": [
    "JavaScript",
    "Node.js"
  ]
}
```

---

# 3. Nested Objects

An object can contain another object.

Example:

```json
{
  "user": {
    "name": "Rahul",
    "age": 21
  }
}
```

Visual representation:

```
user
├── name
└── age
```

Send it:

```bash
curl \
-H "Content-Type: application/json" \
-d '{
  "user": {
    "name": "Rahul",
    "age": 21
  }
}' \
<https://httpbin.org/post> | jq '.json'
```

Response:

```json
{
  "user": {
    "name": "Rahul",
    "age": 21
  }
}
```

# 4. Multiple Nested Objects


# 6. Arrays of Objects

This is one of the most common API structures.

```json
{
  "users": [
    {
      "name": "Rahul",
      "age": 21
    },
    {
      "name": "Amit",
      "age": 24
    }
  ]
}
```

Tree:

```
users
├── User 1
│   ├── name
│   └── age
└── User 2
    ├── name
    └── age
```

Send:

```bash
curl \
-H "Content-Type: application/json" \
-d '{
  "users": [
    {
      "name": "Rahul",
      "age": 21
    },
    {
      "name": "Amit",
      "age": 24
    }
  ]
}' \
<https://httpbin.org/post> | jq '.json'
```

# 7. Objects Inside Arrays Inside Objects

Real APIs often go one level deeper.

Example:

```json
{
  "team": {
    "name": "Backend",
    "members": [
      {
        "name": "Rahul",
        "role": "Developer"
      },
      {
        "name": "Amit",
        "role": "Tester"
      }
    ]
  }
}
```

Tree:

```
team
├── name
└── members
    ├── Rahul
    └── Amit
```

# 8. Express Example

Express route:

```jsx
app.post("/profile", (req, res) => {
    console.log(req.body);
    res.json(req.body);
});
```

Request:

```bash
curl \
-H "Content-Type: application/json" \
-d '{
  "user": {
    "name": "Rahul",
    "skills": [
      "Node.js",
      "MongoDB"
    ]
  }
}' \
<http://localhost:3000/profile>
```

Server receives:

```jsx
{
  user: {
    name: "Rahul",
    skills: [
      "Node.js",
      "MongoDB"
    ]
  }
}
```

---

# 9. Accessing Nested Data in Express

Suppose:

```jsx
req.body = {
  user: {
    name: "Rahul",
    address: {
      city: "Bokaro"
    }
  }
};
```

Access values like this:

```jsx
req.body.user.name
```

```jsx
req.body.user.address.city
```

For arrays:

```jsx
req.body.user.skills[0]
```

Example:

```jsx
req.body = {
  user: {
    skills: [
      "Node.js",
      "MongoDB"
    ]
  }
};
```

Access:

```jsx
req.body.user.skills[1]
```

Output:

```
MongoDB
```

# 11. Valid vs Invalid JSON

## ✅ Correct

```json
{
  "skills": [
    "Node.js",
    "Express"
  ]
}
```

---

## ❌ Missing comma

```json
{
  "name": "Rahul"
  "age": 21
}
```

---

## ❌ Trailing comma

```json
{
  "name": "Rahul",
}
```

---

## ❌ Unquoted key

```json
{
  name: "Rahul"
}
```

# 12. Debugging with `jq`

Pretty-print:

```bash
curl \
-H "Content-Type: application/json" \
-d @user.json \
<https://httpbin.org/post> | jq
```

Show only the JSON:

```bash
curl \
-H "Content-Type: application/json" \
-d @user.json \
<https://httpbin.org/post> | jq '.json'
```

Extract a nested field:

```bash
curl \
-H "Content-Type: application/json" \
-d @user.json \
<https://httpbin.org/post> | jq '.json.user.name'
```

Output:

```
"Rahul"
```

# 💡 Pro Tips

### 1. Indent your JSON

Readable JSON:

```json
{
  "user": {
    "name": "Rahul"
  }
}
```

is much easier to maintain than a single long line.

---

### 2. Save complex JSON in files

Instead of embedding a large payload directly in your command:

```bash
-d @profile.json
```

is cleaner, reusable, and easier to edit.

---

### 3. Validate JSON before sending

If you're unsure whether your JSON is valid:

```bash
cat profile.json | jq
```

If `jq` formats it nicely, it's valid JSON. If not, it will point out the syntax error.
