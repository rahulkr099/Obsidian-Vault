# 1. What is Form Data?

Before JSON became popular, HTML forms submitted data like this:

```html
<form action="/login" method="POST">
  <input name="email">
  <input name="password" type="password">
</form>
```

When the user clicks **Submit**, the browser sends:

```
email=rahul@example.com&password=secret123
```

This format is called:

```
application/x-www-form-urlencoded
```

---

# 2. Form Data vs JSON

### JSON

```json
{
  "email": "rahul@example.com",
  "password": "secret123"
}
```

---

### Form Data

```
email=rahul@example.com&password=secret123
```

Same information, different format.

---

# 3. Content-Type

When sending form data, use:

```
Content-Type: application/x-www-form-urlencoded
```

When sending JSON, use:

```
Content-Type: application/json
```

The server uses the **Content-Type** header to decide how to parse the body.

---

# 4. Your First Form Request

```bash
curl \
-X POST \
-H "Content-Type: application/x-www-form-urlencoded" \
-d "email=rahul@example.com&password=secret123" \
<https://httpbin.org/post>
```

Pretty-print the response:

```bash
curl \
-X POST \
-H "Content-Type: application/x-www-form-urlencoded" \
-d "email=rahul@example.com&password=secret123" \
<https://httpbin.org/post> | jq
```

Notice this part of the response:

```json
{
  "form": {
    "email": "rahul@example.com",
    "password": "secret123"
  }
}
```

Unlike JSON requests (which appear under `.json`), form fields appear under **`.form`**.

---

# 5. `d` Automatically URL-Encodes Data

You can write:

```bash
curl \
-d "name=Rahul Kumar"
<https://httpbin.org/post>
```

A space becomes:

```
Rahul%20Kumar
```

This is called **URL encoding**.

Other common encodings:

|Character|Encoded|
|---|---|
|Space|`%20` or `+`|
|`@`|`%40`|
|`&`|`%26`|
|`=`|`%3D`|

Example:

```
email=rahul%40example.com
```

means:

```
email=rahul@example.com
```

---

# 6. Multiple Fields

```bash
curl \
-H "Content-Type: application/x-www-form-urlencoded" \
-d "name=Rahul&age=21&city=Bokaro" \
<https://httpbin.org/post>
```

Response:

```json
{
  "form": {
    "name": "Rahul",
    "age": "21",
    "city": "Bokaro"
  }
}
```

Notice:

> Form values are received as **strings**.

Even:

```
age=21
```

becomes:

```
"21"
```

unless your application converts it.

---

# 7. Express Example

Enable URL-encoded parsing:

```jsx
import express from "express";

const app = express();

app.use(express.urlencoded({ extended: true }));

app.post("/login", (req, res) => {
    console.log(req.body);
    res.json(req.body);
});
```

Request:

```bash
curl \
-H "Content-Type: application/x-www-form-urlencoded" \
-d "email=rahul@example.com&password=secret123" \
<http://localhost:3000/login>
```

Console:

```jsx
{
  email: "rahul@example.com",
  password: "secret123"
}
```

---

# 8. What Does `extended: true` Mean?

```jsx
app.use(express.urlencoded({
    extended: true
}));
```

### `extended: false`

Supports only simple key-value pairs.

```
name=Rahul
age=21
```

---

### `extended: true`

Supports nested objects and arrays.

Example:

```
user[name]=Rahul
user[city]=Bokaro
```

becomes:

```jsx
{
  user: {
    name: "Rahul",
    city: "Bokaro"
  }
}
```

For modern Express applications, **`extended: true`** is usually recommended.

---

# 9. Sending Nested Form Data

```bash
curl \
-H "Content-Type: application/x-www-form-urlencoded" \
-d "user[name]=Rahul&user[city]=Bokaro" \
<https://httpbin.org/post>
```

`httpbin` simply echoes the fields, but an Express app with `extended: true` parses them into nested objects.

---

# 10. JSON vs Form Data

|Feature|JSON|Form Data|
|---|---|---|
|Content-Type|`application/json`|`application/x-www-form-urlencoded`|
|Nested Objects|✅ Excellent|⚠️ Limited|
|Arrays|✅ Native|⚠️ Possible but awkward|
|Browser HTML Forms|❌ Not by default|✅ Yes|
|Modern REST APIs|✅ Most common|⚠️ Less common|
|Express Middleware|`express.json()`|`express.urlencoded()`|

---

# 11. When Should You Use Form Data?

Use form data when:

- Traditional HTML forms
- Older APIs
- OAuth token endpoints (many use URL-encoded data)
- Legacy applications

Use JSON when:

- REST APIs
- Node.js backends
- React, Vue, Angular frontends
- Mobile apps
- Microservices

# 13. Common Mistakes

## ❌ Sending JSON with the Wrong Content-Type

```bash
curl \
-H "Content-Type: application/x-www-form-urlencoded" \
-d '{"name":"Rahul"}'
```

The server may treat the JSON as a plain string instead of parsing it.

---

## ✅ Correct JSON

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}'
```

---

## ❌ Forgetting `express.urlencoded()`

Without:

```jsx
app.use(express.urlencoded({ extended: true }));
```

`req.body` may be empty for form submissions.

---

## ❌ Mixing Formats

Don't send:

```
name=Rahul
```

with:

```
Content-Type: application/json
```

Keep the body format and `Content-Type` consistent.

---

# 14. Compare JSON and Form Data

## JSON

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul","age":21}' \
<https://httpbin.org/post> | jq '.json'
```

---

## Form Data

```bash
curl \
-H "Content-Type: application/x-www-form-urlencoded" \
-d "name=Rahul&age=21" \
<https://httpbin.org/post> | jq '.form'
```

Notice the different response fields:

- JSON → `.json`
- Form data → `.form`

# 💡 Pro Tips

### 1. You don't always need `X POST`

Just like JSON, using `-d` automatically makes the request a **POST**.

```bash
curl \
-d "name=Rahul" \
<https://httpbin.org/post>
```

---

### 2. Use `jq '.form'`

When testing with `httpbin`, remember:

```bash
curl ... | jq '.form'
```

instead of:

```bash
jq '.json'
```

---

### 3. Modern APIs Prefer JSON

Unless the API documentation specifically asks for:

```
application/x-www-form-urlencoded
```

you'll usually send JSON instead.
