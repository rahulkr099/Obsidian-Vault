# 1. Why Can't We Use JSON for Files?

Suppose you want to upload:

- A profile picture
- A PDF resume
- A ZIP archive
- A video

JSON is designed for **text data**, not binary files.

This won't work well:

```json
{
  "name": "Rahul",
  "photo": "profile.jpg"
}
```

The server only receives the filename, **not the file itself**.

Instead, browsers use:

```
multipart/form-data
```

---

# 2. What is Multipart Form Data?

Imagine sending a package.

Instead of putting everything into one envelope, you use separate compartments.

```
Package
│
├── Name
├── Email
├── Resume.pdf
├── Photo.jpg
└── Cover Letter
```

Each part has its own headers and content.

That's exactly how `multipart/form-data` works.

---

# 3. The `F` Option

`curl` uses:

```bash
-F
```

or

```bash
--form
```

to send multipart form data.

General syntax:

```bash
curl \
-F "field=value" \
URL
```

---

# 4. Upload Your First File

Suppose:

```
photo.jpg
```

exists in your current directory.

Run:

```bash
curl \
-F "photo=@photo.jpg" \
<https://httpbin.org/post>
```

Notice:

```
@photo.jpg
```

The `@` tells `curl`:

> Read the file and upload its contents.

---

# 5. Inspect the Response

Pretty-print:

```bash
curl \
-F "photo=@photo.jpg" \
<https://httpbin.org/post> | jq
```

You'll see something similar to:

```json
{
  "files": {
    "photo": "..."
  }
}
```

Uploaded files appear under:

```
.files
```

# 6. Upload Text Fields

Multipart isn't only for files.

You can send text too.

```bash
curl \
-F "name=Rahul" \
-F "city=Bokaro" \
<https://httpbin.org/post>
```

Response:

```json
{
  "form": {
    "name": "Rahul",
    "city": "Bokaro"
  }
}
```

---

# 7. Upload Text + File Together

Very common example:

```bash
curl \
-F "name=Rahul" \
-F "email=rahul@example.com" \
-F "photo=@photo.jpg" \
<https://httpbin.org/post>
```

Response:

```json
{
  "form": {
    "name": "Rahul",
    "email": "rahul@example.com"
  },
  "files": {
    "photo": "..."

}
```

# 13. Express Example with Multer

Install Multer:

```bash
npm install multer
```

Server:

```jsx
import express from "express";
import multer from "multer";

const app = express();

const upload = multer({
  dest: "uploads/"
});

app.post("/upload", upload.single("photo"), (req, res) => {
  console.log(req.file);
  console.log(req.body);

  res.json({
    message: "Upload successful"
  });
});
```

# 15. What Does `req.file` Look Like?

Example:

```jsx
{
  fieldname: "photo",
  originalname: "photo.jpg",
  mimetype: "image/jpeg",
  destination: "uploads/",
  filename: "8fd73a9d",
  size: 254321
}
```

Useful fields:

|Property|Meaning|
|---|---|
|`originalname`|Original filename|
|`mimetype`|MIME type|
|`size`|File size (bytes)|
|`destination`|Upload folder|
|`filename`|Stored filename|

---

# 16. Multiple Files in Express

Single file:

```jsx
upload.single("photo")
```

Multiple files:

```jsx
upload.array("photos", 5)
```

Up to five files can be uploaded.

Access them with:

```jsx
req.files
```

# 17. MIME Types

Common MIME types:

|File|MIME Type|
|---|---|
|JPG|`image/jpeg`|
|PNG|`image/png`|
|PDF|`application/pdf`|
|ZIP|`application/zip`|
|MP4|`video/mp4`|
|JSON|`application/json`|
|TXT|`text/plain`|

Multer provides the MIME type in:

```jsx

```

# 18. Common Mistakes

## ❌ Using `d` for Files

Wrong:

```bash
curl \
-d @photo.jpg
```

This sends the raw file as the request body instead of a multipart upload.

---

## ✅ Correct

```bash
curl \
-F "photo=@photo.jpg"
```

---

## ❌ Forgetting the `@`

Wrong:

```bash
curl \
-F "photo=photo.jpg"
```

This sends the literal text:

```
photo.jpg
```

---

## ✅ Correct

```bash
curl \
-F "photo=@photo.jpg"
```

---

## ❌ Wrong Field Name

Suppose Express expects:

```jsx
upload.single("avatar")
```

But you send:

```bash
-F "photo=@photo.jpg"
```

The upload won't match because the field names differ.

Correct:

```bash
-F "avatar=@photo.jpg"
```

# 💡 Pro Tips

### 1. Don't manually set the `Content-Type`

Avoid this:

```bash
curl \
-H "Content-Type: multipart/form-data" \
-F "photo=@photo.jpg"
```

When you use `-F`, **`curl` automatically generates the correct `Content-Type` header with the required boundary**. Manually setting it often breaks uploads.

---

### 2. Check what was uploaded

With `httpbin`:

```bash
curl \
-F "photo=@photo.jpg" \
<https://httpbin.org/post> | jq '.files'
```

For text fields:

```bash
curl \
-F "name=Rahul" \
-F "photo=@photo.jpg" \
<https://httpbin.org/post> | jq '.form'
```

---

### 3. Validate uploads on the server

Never trust uploaded files blindly. In Express/Multer, validate:

- File size
- MIME type
- Allowed extensions
- Maximum number of files

before saving or processing them.
