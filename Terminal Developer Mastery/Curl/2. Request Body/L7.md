# 1. The Journey of an HTTP Request

When you send:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<http://localhost:3000/users>
```

The request goes through several steps before your route runs.

```
curl
   │
   ▼
TCP Connection
   │
   ▼
Express Server
   │
   ▼
Middleware
   │
   ▼
Body Parser
   │
   ▼
Route Handler
   │
   ▼
Response
```

The important part is the **Body Parser**.

Without it:

```jsx
req.body === undefined
```

---

# 2. What Does `express.json()` Actually Do?

Suppose the client sends:

```
POST /users
Content-Type: application/json

{
  "name":"Rahul"
}
```

The raw request body arrives as bytes.

```
7B 22 6E 61 6D 65 ...
```

Express does **not** automatically know that those bytes represent JSON.

When you write:

```jsx
app.use(express.json());
```

Express:

1. Reads the raw bytes.
2. Converts them to text.
3. Calls `JSON.parse()`.
4. Stores the resulting object in:

```jsx
req.body
```

---

# 3. Without `express.json()`

Server:

```jsx
import express from "express";

const app = express();

app.post("/users", (req, res) => {
    console.log(req.body);

    res.send("Done");
});
```

Request:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
<http://localhost:3000/users>
```

Console:

```jsx
undefined
```

Because nothing parsed the body.

---

# 4. With `express.json()`

```jsx
import express from "express";

const app = express();

app.use(express.json());

app.post("/users", (req, res) => {
    console.log(req.body);

    res.json(req.body);
});
```

Now:

```jsx
{
  name: "Rahul"
}
```

---

# 5. Middleware Execution Order

Express executes middleware **top to bottom**.

Correct:

```jsx
app.use(express.json());

app.post("/users", controller);
```

Execution:

```
Request
   │
   ▼
express.json()
   │
   ▼
controller
```

---

Wrong:

```jsx
app.post("/users", controller);

app.use(express.json());
```

Execution:

```
Request
   │
   ▼
controller
   │
   ▼
express.json()
```

The controller runs first.

Result:

```jsx
req.body === undefined
```

---

# 6. Multiple Middleware

Example:

```jsx
app.use(logger);

app.use(express.json());

app.use(authMiddleware);

app.use(rateLimiter);

app.use(routes);
```

Execution order:

```
Request
   │
   ▼
Logger
   │
   ▼
JSON Parser
   │
   ▼
Authentication
   │
   ▼
Rate Limiter
   │
   ▼
Routes
```

Each middleware receives:

```jsx
(req, res, next)
```

and must call:

```jsx
next();
```

to continue.

# 7. How `express.urlencoded()` Works

Suppose the browser submits:

```
email=rahul@example.com&password=1234
```

Without:

```jsx
app.use(express.urlencoded());
```

Result:

```jsx
req.body
```

is empty or `undefined`.

With:

```jsx
app.use(express.urlencoded({
    extended: true
}));
```

You get:

```jsx
{
    email: "rahul@example.com",
    password: "1234"
}
```

# 8. JSON vs URL-Encoded vs Multipart

## JSON

```
Content-Type:
application/json
```

Middleware:

```jsx
express.json()
```

---

## URL-Encoded

```
Content-Type:
application/x-www-form-urlencoded
```

Middleware:

```jsx
express.urlencoded()
```

---

## Multipart

```
multipart/form-data
```

Middleware:

```jsx
multer()
```

---

Summary:

|Request Type|Middleware|
|---|---|
|JSON|`express.json()`|
|Form|`express.urlencoded()`|
|File Upload|Multer|

# 9. Why Doesn't `express.json()` Parse Multipart?

Suppose the request contains:

```
Photo.jpg
Resume.pdf
Profile Name
```

This isn't JSON.

It's a binary multipart stream.

Express intentionally doesn't parse it.

Instead, Multer reads the stream and separates:

```jsx
req.file
```

and

```jsx
req.body
```

---

# 10. Request Size Limits

Default:

```jsx
express.json()
```

accepts roughly **100 KB** of JSON.

Large request?

```
413 Payload Too Large
```

Increase limit:

```jsx
app.use(express.json({
    limit: "10mb"
}));
```

Other examples:

```jsx
limit: "1mb"

limit: "50mb"

limit: "500kb"
```

---

# 11. Parsing URL-Encoded Limits

```jsx
app.use(express.urlencoded({
    extended: true,
    limit: "5mb"
}));
```

Useful when forms contain many fields.

---

# 12. Invalid JSON

Request:

```json
{
"name":"Rahul",
}
```

Invalid JSON.

Express returns:

```
400 Bad Request
```

before your route executes.

Reason:

```jsx
JSON.parse()
```

throws an error.

---

# 13. Wrong Content-Type

Suppose you send:

```bash
curl \
-H "Content-Type: text/plain" \
-d '{"name":"Rahul"}'
```

Express expects:

```
application/json
```

Result:

```jsx
req.body
```

may be empty because the JSON parser ignores `text/plain`.

Always send the correct `Content-Type`.

---

# 14. Debugging `req.body`

If `req.body` is `undefined`, check:

### ✅ Did you register middleware?

```jsx
app.use(express.json());
```

---

### ✅ Is middleware above routes?

Correct:

```jsx
app.use(express.json());

app.use(routes);
```

---

### ✅ Correct Content-Type?

```
application/json
```

---

### ✅ Valid JSON?

Validate:

```bash
echo '{"name":"Rahul"}' | jq
```

---

### ✅ Multipart?

If uploading files:

```jsx
multer()
```

not:

```jsx
express.json()
```

# 17. Common Beginner Mistakes

## ❌ Middleware after routes

```jsx
app.post("/users", controller);

app.use(express.json());
```

---

## ✅ Correct

```jsx
app.use(express.json());

app.post("/users", controller);
```

---

## ❌ Missing `next()`

```jsx
app.use((req, res, next) => {

    console.log("Hello");

});
```

Request hangs forever.

---

## ✅ Correct

```jsx
app.use((req, res, next) => {

    console.log("Hello");

    next();

});
```

---

## ❌ Wrong parser

Uploading image?

Don't use:

```jsx
express.json()
```

Use:

```jsx
upload.single("photo")
```

# 💡 Pro Tips

### 1. Register parsers near the top of `app.js`

A common pattern is:

```jsx
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// Authentication
// Logging
// Routes
```

This ensures all routes can access parsed request bodies.

---

### 2. Use reasonable size limits

Avoid setting extremely large limits unless necessary.

Examples:

- JSON APIs: `1mb`–`10mb`
- File uploads: Handle with Multer rather than increasing `express.json()` limits.

---

### 3. Validate request bodies

Parsing only converts the request into a JavaScript object—it **does not validate** the data.

For example:

```json
{
  "email": "not-an-email",
  "age": -5
}
```

is valid JSON, but probably invalid application data. Always validate fields (using libraries like Joi or Zod) after parsing.
