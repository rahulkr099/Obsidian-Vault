# 3. Health Check

`health.sh`

```bash
#!/usr/bin/env bash

source config.sh

curl \
--fail \
--connect-timeout 3 \
--max-time 10 \
-o /dev/null \
-s \
"$API/health"

if [ $? -eq 0 ]
then
    success "API Healthy"
else
    error "API Down"
fi
```

# 7. Performance Report

```bash
curl \
-o /dev/null \
-s \
-w "
DNS: %{time_namelookup}
Connect: %{time_connect}
TLS: %{time_appconnect}
TTFB: %{time_starttransfer}
Total: %{time_total}
Download: %{size_download}
Speed: %{speed_download}
HTTP: %{http_code}
" \
"$API/users"

Sample output:

```

)

    echo "Testing $endpoint"

# 18. Exit Codes

Capture both the HTTP status and the shell exit code.

```bash
STATUS=$(
curl \
-o /dev/null \
-s \
-w "%{http_code}" \
"$API/users"
)

EXIT=$?

echo "$STATUS"

echo "$EXIT"
```

Remember:

- HTTP status tells you what the **server** returned.
- Exit code tells you whether **curl itself** succeeded (network, DNS, TLS, etc.).

# 22. Common Production Checklist

Before reporting "the API is broken," verify:

|Check|Command|
|---|---|
|Health|`curl --fail /health`|
|Status code|`-w "%{http_code}"`|
|Headers|`curl -I`|
|TLS|`curl -Iv`|
|Redirects|`curl -Lv`|
|Compression|`curl --compressed -v`|
|Cache|`curl -I`|
|Response time|`-w "%{time_total}"`|
|Authentication|`-H "Authorization: Bearer ..."`|
|Cookies|`-b cookies.txt`|
