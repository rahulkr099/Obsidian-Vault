# Authentication vs Authorization

These are different concepts.

## Authentication

**Who are you?**

Example:

```
Username: rahul
Password: ********
```

The server verifies your identity.

---

## Authorization

**What are you allowed to do?**

Example:

```
Rahul

✓ Read Todos
✓ Create Todos
✗ Delete Users
✗ Access Admin Panel
```

Authentication happens first.

Authorization happens second.

# Common Authentication Methods

|Method|Common Usage|
|---|---|
|Basic Auth|Internal APIs, legacy systems|
|Bearer Token (JWT)|REST APIs|
|API Key|Third-party APIs|
|Cookie Session|Traditional web apps|
|OAuth 2.0|Google, GitHub, Microsoft login|

# 1. Basic Authentication

Basic Auth is one of the oldest HTTP authentication methods.

Instead of sending:

```
Username
Password
```

separately,

they are combined like:

```
rahul:secret123
```

Base64 encoded:

```
cmFodWw6c2VjcmV0MTIz
```

Then sent as:

```
Authorization: Basic cmFodWw6c2VjcmV0MTIz
```

---

# Using curl

The easy way:

```bash
curl \
-u rahul:secret123 \
<https://httpbin.org/basic-auth/rahul/secret123>
```

`curl` automatically creates:

```
Authorization: Basic xxxxxxxxx
```

---

# Manual Basic Header

You can also do it manually.

Create Base64:

```bash
echo -n "rahul:secret123" | base64
```

Output:

```
cmFodWw6c2VjcmV0MTIz
```

Send:

```bash
curl \
-H "Authorization: Basic cmFodWw6c2VjcmV0MTIz" \
<https://httpbin.org/basic-auth/rahul/secret123>
```

---

# When is Basic Auth Used?

- Jenkins
- Elasticsearch
- Older internal APIs
- Routers
- Network devices

Always use it over **HTTPS**, because Base64 is **encoding**, not encryption.

---

# 2. Bearer Token Authentication (JWT)

Modern REST APIs usually use Bearer tokens.

Login request:

```
Email
Password
```

↓

Server verifies credentials

↓

Returns JWT

↓

Client stores JWT

↓

Every request includes:

```
Authorization: Bearer eyJhbGciOi...
```

---

# curl Example

```bash
curl \
-H "Authorization: Bearer $TOKEN" \
<http://localhost:3000/api/profile>
```

---

# Express Example

```jsx
const token = req.headers.authorization;
```

Typical value:

```
Bearer eyJhbGciOi...
```

Usually you'll remove the prefix:

```jsx
const jwt = token.split(" ")[1];
```

---

# 3. API Key Authentication

Many APIs use API keys instead of user accounts.

Example:

```
abc123xyz456
```

---

## Header-Based API Key

```bash
curl \
-H "X-API-Key: abc123xyz456" \
<https://httpbin.org/headers>
```

---

## Authorization Header

Some APIs use:

```
Authorization: ApiKey abc123xyz456
```

Example:

```bash
curl \
-H "Authorization: ApiKey abc123xyz456"
```

---

## Query Parameter

Some services still use:

```
?api_key=abc123
```

Example:

```bash
curl \
"<https://example.com/users?api_key=abc123>"
```

This works but is generally discouraged because query parameters may appear in logs or browser history.

---

# 4. Cookie Authentication

Traditional web apps often use cookies.

Login:

```bash
curl \
-c cookies.txt \
-d "email=rahul@example.com&password=secret123" \
<http://localhost:3000/login>
```

Protected route:

```bash
curl \
-b cookies.txt \
<http://localhost:3000/profile>
```

---

# JWT vs Cookies

|JWT|Cookie|
|---|---|
|Stored by client|Stored by browser|
|Sent manually|Sent automatically|
|Good for APIs|Good for websites|
|Stateless|Usually stateful|

---

# 5. OAuth 2.0 (Overview)

OAuth lets users log in using another service without sharing their password.

Example:

```
Your App

↓

Login with Google

↓

Google authenticates user

↓

Google returns access token

↓

Your app uses token
```

You'll see this with:

- Google
- GitHub
- Microsoft
- Discord
- LinkedIn

Testing a full OAuth flow usually requires a browser because it involves redirects and user interaction.

# 6. Combining Authentication with curl

Authenticated POST request:

```bash
curl \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/json" \
-d @payloads/todo.json \
<http://localhost:3000/api/todos>
```

---

# 7. Saving Tokens

Capture automatically:

```bash
TOKEN=$(
curl -s \
-H "Content-Type: application/json" \
-d @payloads/login.json \
<http://localhost:3000/api/auth/login> \
| jq -r '.accessToken'
)
```

Now:

```bash
echo "$TOKEN"
```

---

# 8. Debugging Authentication

Always start with:

```bash
curl -v ...
```

Check:

- Authorization header present?
- Correct scheme?
- Token expired?
- Correct endpoint?

---

# 9. Common Authentication Errors

## 400 Bad Request

Malformed request.

---

## 401 Unauthorized

Authentication failed.

Examples:

- Missing token
- Invalid token
- Wrong password

---

## 403 Forbidden

Authenticated successfully.

But permission denied.

Example:

```
User

↓

DELETE /admin/users

↓

403 Forbidden
```

---

# 10. Expired Tokens

Typical JWT response:

```json
{
  "message": "Token expired"
}
```

Solution:

- Refresh the token
- Log in again

---

# 11. Refresh Tokens

Typical flow:

```
Login

↓

Access Token (15 min)

↓

Refresh Token (7 days)

↓

Access Token expires

↓

Use Refresh Token

↓

Receive new Access Token
```

This reduces how often users need to sign in.

---

# 12. Authentication Debug Checklist

If authentication fails:

✅ Correct URL

✅ Correct HTTP method

✅ Correct Authorization header

✅ Valid token

✅ Token not expired

✅ User has permission

✅ Correct Content-Type

✅ Server logs

# 13. Security Best Practices

## Never hardcode tokens

❌

```bash
TOKEN=eyJhbGc...
```

Better:

```bash
TOKEN=$(cat token.txt)
```

or:

```bash
source .env
```

---

## Don't commit secrets

`.gitignore`

```
.env
token.txt
cookies.txt
```

---

## Use HTTPS

Never send:

- Passwords
- Tokens
- API keys

over plain HTTP in production.

---

## Don't print secrets unnecessarily

Avoid:

```bash
echo "$TOKEN"
```

on shared terminals or in logs.

# 14. Real Backend Example

Login:

```bash
TOKEN=$(
curl -s \
-H "Content-Type: application/json" \
-d @payloads/login.json \
<http://localhost:3000/api/auth/login> \
| jq -r '.accessToken'
)
```

Create todo:

```bash
curl \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/json" \
-d @payloads/todo.json \
<http://localhost:3000/api/todos>
```

Read todos:

```bash
curl \
-H "Authorization: Bearer $TOKEN" \
<http://localhost:3000/api/todos>
```

Update:

```bash
curl \
-X PATCH \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/json" \
-d @payloads/update.json \
<http://localhost:3000/api/todos/123>
```

Delete:

```bash
curl \
-X DELETE \
-H "Authorization: Bearer $TOKEN" \
<http://localhost:3000/api/todos/123>
```

# 15. Choosing the Right Method

|Scenario|Best Choice|
|---|---|
|REST API|JWT Bearer Token|
|Traditional Website|Cookies|
|Internal Admin Tool|Basic Auth (over HTTPS)|
|Third-Party Service|API Key|
|"Login with Google"|OAuth 2.0|

# 💡 Pro Tips

### 1. Prefer environment variables

```bash
export API_KEY="your-api-key"
export TOKEN="your-jwt-token"
```

Then:

```bash
curl \
-H "Authorization: Bearer $TOKEN"
```

This keeps secrets out of your shell history and scripts.

---

### 2. Verify what you're sending

When debugging:

```bash
curl -v \
-H "Authorization: Bearer $TOKEN" \
<http://localhost:3000/profile>
```

Check the request headers before assuming the server is wrong.

---

### 3. Match the API documentation

Some APIs expect:

```
Authorization: Bearer TOKEN
```

Others expect:

```
X-API-Key: TOKEN
```

or

```
Authorization: ApiKey TOKEN
```

Always follow the API's documented authentication scheme.
