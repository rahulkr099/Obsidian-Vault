---

# 1. Basic Download

The simplest form:

```bash
curl <https://example.com/file.txt>
```

Problem:

The file is printed to the terminal instead of being saved.

---

# 2. Save to a File (`o`)

Use `-o` to specify the output filename.

```bash
curl -o notes.txt <https://example.com/file.txt>
```

Result:

```
Current Directory

↓

notes.txt
```

The downloaded content is saved as `notes.txt` regardless of the original filename.

---

# 3. Save Using the Server's Filename (`O`)

Sometimes you want the original filename.

```bash
curl -O <https://example.com/file.txt>
```

Result:

```
URL

<https://example.com/file.txt>

↓

Saved As

file.txt
```

- `O` extracts the last part of the URL path.

---

# 4. Difference Between `o` and `O`

|Option|Filename|
|---|---|
|`-o report.pdf`|Your chosen filename|
|`-O`|Original filename from the URL|

Example:

```bash
curl -o ubuntu.iso <https://releases.ubuntu.com/24.04/ubuntu.iso>
```

vs.

```bash
curl -O <https://releases.ubuntu.com/24.04/ubuntu.iso>
```

---

# 5. Respect the Server's Suggested Filename (`OJ`)

Some servers return:

```
Content-Disposition: attachment; filename="report.pdf"
```

Use:

```bash
curl -OJ <https://example.com/download>
```

Meaning:

- `O` → Save to a file.
- `J` → Use the filename provided in the `Content-Disposition` header.

This is common for:

- Report exports
- Invoice downloads
- Backup downloads

---

# 6. View Headers Before Downloading

Sometimes you want to inspect the response first.

```bash
curl -I <https://example.com/download>
```

Look for:

```
Content-Type: application/pdf

Content-Length: 284193

Content-Disposition: attachment; filename="guide.pdf"
```

This tells you:

- File type
- File size
- Suggested filename

---

# 7. Follow Redirects While Downloading

Many download URLs redirect to another location.

Without following redirects:

```bash
curl -O <http://example.com/download>
```

You might download a tiny redirect response instead of the actual file.

Correct:

```bash
curl -LO <http://example.com/download>
```

- `L` follows the redirect before downloading.

---

# 8. Download Multiple Files

```bash
curl -O <https://example.com/file1.txt> \
     -O <https://example.com/file2.txt> \
     -O <https://example.com/file3.txt>
```

Result:

```
file1.txt

file2.txt

file3.txt
```

---

# 9. Download Sequentially Using a Loop

```bash
for file in file1 file2 file3
do
    curl -O "<https://example.com/$file.txt>"
done
```

Useful when downloading many similarly named files.

---

# 10. Show the Progress Meter

By default, `curl` displays progress.

Example:

```
  % Total    % Received % Xferd
```

Useful information:

- Download percentage
- Speed
- Time remaining

---

# 11. Silent Downloads

Suppress output:

```bash
curl -s -O <https://example.com/file.txt>
```

Useful in scripts.

---

# 12. Silent but Show Errors

A common production choice:

```bash
curl -sS -O <https://example.com/file.txt>
```

Options:

- `s` → Silent
- `S` → Still show errors

---

# 13. Show a Progress Bar

Instead of the default meter:

```bash
curl --progress-bar -O <https://example.com/file.zip>
```

Produces a cleaner progress display.

---

# 14. Limit Download Speed

Avoid consuming all available bandwidth.

```bash
curl \
--limit-rate 500K \
-O \
<https://example.com/archive.zip>
```

Examples:

|Value|Meaning|
|---|---|
|`100K`|100 KB/s|
|`1M`|1 MB/s|
|`10M`|10 MB/s|

---

# 15. Fail on HTTP Errors

Suppose the server returns:

```
404 Not Found
```

Without `--fail`, you may save the HTML error page as a file.

Instead:

```bash
curl \
--fail \
-O \
<https://example.com/file.zip>
```

The download stops if the HTTP request fails.

---

# 16. Save to Another Directory

```bash
curl \
-o downloads/report.pdf \
<https://example.com/report.pdf>
```

Ensure the `downloads/` directory already exists.

---

# 17. Verify the Download

Check that the file exists:

```bash
ls -lh report.pdf
```

Determine its type:

```bash
file report.pdf
```

Example output:

```
PDF document, version 1.7
```

---

# 18. Download a Linux ISO

A real-world example:

```bash
curl \
-L \
-O \
<https://releases.ubuntu.com/24.04/ubuntu-24.04-desktop-amd64.iso>
```

Explanation:

- `L` → Follow redirects
- `O` → Preserve the filename

---

# 19. Download a GitHub Release Asset

Many GitHub release assets redirect.

```bash
curl \
-L \
-O \
<https://github.com/sharkdp/bat/releases/latest/download/bat-musl-amd64.tar.gz>
```

Without `-L`, the download may fail or retrieve only the redirect response.

---

# 20. Production Download Command

A robust command:

```bash
curl \
--fail \
--location \
--remote-name \
--progress-bar \
--connect-timeout 5 \
--max-time 300 \
<https://example.com/archive.tar.gz>
```

Equivalent options:

- `-location` = `L`
- `-remote-name` = `O`

# 💡 Pro Tips

### 1. Prefer `LO` for release downloads

Many software releases (GitHub, GitLab, package mirrors) redirect to the actual file.

```bash
curl -LO URL
```

This combination is one you'll use frequently.

---

### 2. Always use `-fail` in automation

Without it, a failed download may silently save an HTML error page instead of the file you expected.

```bash
curl --fail -LO URL
```

---

### 3. Verify before trusting

After downloading important files:

```bash
file filename
ls -lh filename
```

In the next lesson, you'll learn to verify downloads cryptographically using SHA-256 checksums.
