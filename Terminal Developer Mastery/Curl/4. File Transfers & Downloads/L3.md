# 3. HTTP PUT vs POST

|PUT|POST|
|---|---|
|Replace or create a specific resource|Submit new data|
|Usually idempotent|Usually not idempotent|
|Client often knows the destination URL|Server decides what to create|

Example:

PUT

```
PUT /files/report.pdf
```

POST

```
POST /upload
```

---

# 4. Upload with PUT (`T`)

The easiest upload command:

```bash
curl \
-T report.pdf \
<https://example.com/uploads/report.pdf>
```

- `T` means:

```
Transfer this file
```

Equivalent long option:

```bash
curl \
--upload-file report.pdf \
<https://example.com/uploads/report.pdf>
```

---

# 5. What Happens Internally?

Your request becomes:

```
PUT /uploads/report.pdf

Content-Length: 284931

(binary file...)
```

The server stores the uploaded file.

---

# 6. Upload to a Local Express Server

Suppose your API accepts:

```
PUT /uploads/report.pdf
```

Command:

```bash
curl \
-T report.pdf \
<http://localhost:3000/uploads/report.pdf>
```

---

# 7. Upload Using POST

Some APIs expect uploads through POST instead of PUT.

Example:

```bash
curl \
-X POST \
--data-binary @report.pdf \
<https://example.com/upload>
```

Here:

```
@report.pdf
```

means:

> Read the contents of `report.pdf` and send them as the request body.

---

# 8. `-data-binary` vs `d`

Text data:

```bash
curl \
-d "hello"
```

Binary data:

```bash
curl \
--data-binary @image.png
```

Why?

- `d` may modify line endings or apply URL encoding.
- `-data-binary` sends the file exactly as-is.

---

# 9. Set Content-Type

Always tell the server what you're sending when required.

Example:

PDF

```bash
curl \
-T report.pdf \
-H "Content-Type: application/pdf" \
URL
```

Image

```bash
curl \
-T image.png \
-H "Content-Type: image/png" \
URL
```

JSON file

```bash
curl \
-T users.json \
-H "Content-Type: application/json" \
URL
```

---

# 10. Upload with Authentication

Bearer token:

```bash
curl \
-T backup.tar.gz \
-H "Authorization: Bearer $TOKEN" \
URL
```

Basic authentication:

```bash
curl \
-u username:password \
-T backup.tar.gz \
URL
```

# 11. Upload Progress

By default, `curl` shows upload progress.

```
100%
Uploaded
```

Cleaner progress bar:

```bash
curl \
--progress-bar \
-T backup.tar.gz \
URL
```

---

# 12. Silent Upload

Automation:

```bash
curl \
-sS \
-T backup.tar.gz \
URL
```

Useful for scripts and cron jobs.

---

# 13. Upload and Save Response

Some servers return JSON:

```json
{
  "id": 51,
  "url": "/uploads/report.pdf"
}
```

Save it:

```bash
curl \
-T report.pdf \
-o response.json \
URL
```

Pretty-print:

```bash
cat response.json | jq
```

---

# 14. Upload Timeouts

Large uploads may take time.

```bash
curl \
-T backup.tar.gz \
--connect-timeout 5 \
--max-time 600 \
URL
```

---

# 15. Retry Uploads

Temporary network issue?

```bash
curl \
-T backup.tar.gz \
--retry 3 \
--retry-delay 2 \
URL
```

Be careful:

Only retry automatically when the upload endpoint is **idempotent**, or when the server supports **idempotency keys**.

---

# 16. Upload Multiple Files

Sequential example:

```bash
for file in *.pdf
do
    curl \
    -T "$file" \
    "<https://example.com/uploads/$file>"
done
```

---

# 17. Verify Upload

Server returns:

```
201 Created
```

or

```
200 OK
```

Check status:

```bash
curl \
-o /dev/null \
-s \
-w "%{http_code}\n" \
-T report.pdf \
URL
```

# 19. Common Upload Errors

## 400 Bad Request

Wrong request format.

---

## 401 Unauthorized

Missing or invalid credentials.

---

## 403 Forbidden

Authenticated, but not allowed.

---

## 404 Not Found

Wrong upload endpoint.

---

## 413 Payload Too Large

File exceeds server limit.

---

## 415 Unsupported Media Type

Wrong `Content-Type`.

---

## 500 Internal Server Error

Server-side failure.

# 20. Debug Uploads

Verbose mode:

```bash
curl \
-v \
-T report.pdf \
URL
```

Inspect:

- Request headers
- Response headers
- Status code
- Content-Length
- Content-Type

---

# 21. Production Upload Command

```bash
curl \
--fail \
--location \
--upload-file backup.tar.gz \
--retry 5 \
--retry-all-errors \
--connect-timeout 5 \
--max-time 1800 \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/gzip" \
<https://backup.example.com/backups/latest.tar.gz>
```

This combines reliability, authentication, and proper content typing.

# 💡 Pro Tips

### 1. Prefer `T` for PUT uploads

If the API expects a raw file at a specific URL:

```bash
curl -T file.zip URL
```

It's cleaner than manually constructing the request body.

---

### 2. Use `-data-binary` for raw POST uploads

Avoid using `-d` for binary files.

```bash
curl --data-binary @image.png URL
```

This preserves the file exactly.

---

### 3. Always verify the result

Don't assume an upload succeeded.

Use:

```bash
curl \
-o /dev/null \
-s \
-w "%{http_code}\n" \
-T file.zip \
URL
```

or inspect the JSON response returned by the server.
