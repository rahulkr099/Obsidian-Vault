# 1. Why `multipart/form-data`?

Suppose a user updates their profile.

They submit:

- Name
- Email
- Profile picture

A browser sends:

```
Name: Rahul

Email: rahul@example.com

Photo: profile.jpg
```

A normal JSON request **cannot** directly contain a binary file.

Instead, browsers use:

```
Content-Type: multipart/form-data
```

---

# 2. What Does Multipart Mean?

Instead of one big body:

```
JSON

↓

One Piece
```

the request becomes:

```
Part 1

↓

Name

↓

Part 2

↓

Email

↓

Part 3

↓

Photo
```

Each part has its own headers and content.

---

# 3. HTTP Multipart Structure

Simplified request:

```
POST /upload

Content-Type: multipart/form-data; boundary=abc123

--abc123

Content-Disposition: form-data; name="name"

Rahul

--abc123

Content-Disposition: form-data; name="photo"; filename="profile.jpg"

(binary image)

--abc123--
```

The **boundary** separates each part.

---

# 4. Upload One File

The simplest multipart upload:

```bash
curl \
-F "file=@photo.jpg" \
<http://localhost:3000/upload>
```

Meaning:

```
Field Name

↓

file

↓

Value

↓

Contents of photo.jpg
```

`@` tells `curl` to upload the file's contents.

---

# 5. Upload a File + Text Fields

```bash
curl \
-F "name=Rahul" \
-F "email=rahul@example.com" \
-F "photo=@profile.jpg" \
<http://localhost:3000/profile>
```

This closely matches what a browser submits from an HTML form.

---

# 6. Multiple Files

```bash
curl \
-F "files=@photo1.jpg" \
-F "files=@photo2.jpg" \
-F "files=@photo3.jpg" \
<http://localhost:3000/gallery>
```

The server receives three files under the same field name (`files`).

---

# 7. Different Field Names

```bash
curl \
-F "avatar=@avatar.png" \
-F "resume=@resume.pdf" \
-F "coverLetter=@cover.txt" \
<http://localhost:3000/apply>
```

Each field is handled separately by the server.

---

# 8. Setting MIME Types

`curl` usually detects MIME types automatically.

You can override them:

```bash
curl \
-F "file=@report.pdf;type=application/pdf" \
URL
```

Image:

```bash
curl \
-F "image=@photo.png;type=image/png" \
URL
```

Useful if the server validates MIME types.

---

# 9. Changing the Uploaded Filename

Local filename:

```
my-photo.png
```

Server should receive:

```
avatar.png
```

Command:

```bash
curl \
-F "photo=@my-photo.png;filename=avatar.png" \
URL
```

The uploaded filename is changed without renaming the local file.

---

# 10. File + JSON Metadata

Some APIs expect metadata alongside a file.

```bash
curl \
-F 'metadata={"title":"Vacation","year":2026};type=application/json' \
-F "photo=@beach.jpg" \
URL
```

This sends:

- A JSON part
- A file part

in the same request.

---

# 11. Upload Entire Directory?

`curl` cannot upload a directory directly.

Instead:

```bash
tar -czf project.tar.gz project/
```

Then upload:

```bash
curl \
-F "backup=@project.tar.gz" \
URL
```

---

# 12. Upload From Standard Input

Generate content on the fly:

```bash
echo "Hello World" | curl \
-F "file=@-;filename=hello.txt" \
URL
```

`@-` means:

```
Read file contents

↓

STDIN
```

---

# 13. Authentication

Bearer token:

```bash
curl \
-H "Authorization: Bearer $TOKEN" \
-F "file=@backup.tar.gz" \
URL
```

Basic Auth:

```bash
curl \
-u username:password \
-F "file=@backup.tar.gz" \
URL
```

---

# 14. Upload Progress

Default:

```bash
curl \
-F "file=@movie.mp4" \
URL
```

Cleaner:

```bash
curl \
--progress-bar \
-F "file=@movie.mp4" \
URL
```

---

# 15. Save Server Response

```bash
curl \
-F "file=@report.pdf" \
-o response.json \
URL
```

Pretty-print:

```bash
jq . response.json
```

# 16. How Express Parses Multipart

Unlike JSON:

```jsx
app.use(express.json());
```

Express **cannot** parse multipart requests by itself.

You need:

```bash
npm install multer
```

---

# 17. Multer Example

```jsx
import multer from "multer";

const upload = multer({
    dest: "uploads/"
});

app.post(
    "/upload",
    upload.single("file"),
    (req, res) => {

        console.log(req.file);

        res.json({
            success: true
        });

    }
);
```

The field name must match:

```bash
-F "file=@photo.jpg"
```

---

# 18. Multiple Files in Express

```jsx
upload.array("files", 10)
```

Matches:

```bash
curl \
-F "files=@a.jpg" \
-F "files=@b.jpg" \
-F "files=@c.jpg" \
URL
```

`req.files` contains an array of uploaded files.

---

# 19. Mixed Form Data

Example:

```bash
curl \
-F "username=rahul" \
-F "age=22" \
-F "avatar=@profile.png" \
URL
```

Express receives:

```
req.body

↓

username

age
```

and

```
req.file

↓

avatar
```

# 20. Common Errors

## 400 Bad Request

Wrong field names.

---

## 401 Unauthorized

Missing authentication.

---

## 413 Payload Too Large

Upload exceeds server limit.

Increase limits if appropriate.

---

## 415 Unsupported Media Type

Unexpected file type.

---

## Empty `req.file`

Usually caused by mismatched field names.

Example:

Client:

```bash
-F "image=@cat.jpg"
```

Server:

```jsx
upload.single("file")
```

These names **must** match.

---

# 21. Debug Multipart Requests

Verbose mode:

```bash
curl \
-v \
-F "file=@photo.jpg" \
URL
```

Inspect:

- Request headers
- `Content-Type`
- Boundary
- Response headers
- HTTP status

# 22. Production Upload Command

```bash
curl \
--fail \
--location \
--retry 3 \
--retry-all-errors \
--connect-timeout 5 \
--max-time 1800 \
--progress-bar \
-H "Authorization: Bearer $TOKEN" \
-F "backup=@backup.tar.gz" \
-F "environment=production" \
<https://backup.example.com/upload>
```

Suitable for many production backup workflows.

# 💡 Pro Tips

### 1. Don't set the multipart `Content-Type` header manually

Avoid this:

```
Content-Type: multipart/form-data
```

When you use `-F`, **curl automatically generates the correct `Content-Type` and boundary**. If you set it manually, the boundary may be missing and the server won't be able to parse the request.

---

### 2. Match field names exactly

Client:

```bash
-F "avatar=@profile.png"
```

Server:

```jsx
upload.single("avatar")
```

A mismatch is one of the most common causes of empty uploads.

---

### 3. Use multipart for browser-style forms

Choose:

- `F` → HTML forms, profile pictures, documents, mixed fields.
- `T` → Raw file upload to a known destination.
- `-data-binary` → Raw request body uploads.

Selecting the correct upload method makes your client compatible with the server's expectations.
