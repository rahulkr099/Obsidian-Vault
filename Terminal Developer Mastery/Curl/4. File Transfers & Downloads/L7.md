# 1. What is Streaming?

Normally:

```
Server
   │
   ▼
Download File
   │
   ▼
Save to Disk
   │
   ▼
Read Again
```

Streaming skips the "save then read" step:

```
Server
   │
   ▼
curl
   │
   ▼
Another Program
```

The data flows continuously.

---

# 2. Why Stream?

Without streaming:

```
Download 20 GB Backup

↓

Store 20 GB

↓

Extract

↓

Delete
```

Problems:

- Uses disk space
- Slower
- More I/O
- Extra cleanup

With streaming:

```
Download

↓

Extract Immediately

↓

Done
```

# 3. curl Writes to STDOUT

By default:

```bash
curl <https://example.com/file.txt>
```

prints the response to:

```
STDOUT
```

That's why you can pipe it.

---

# 4. Understanding Pipes (`|`)

A pipe sends one command's output to another.

```
Command A

↓

|

↓

Command B
```

Example:

```bash
echo "Hello" | wc -c
```

Output:

```
6
```

---

# 5. Download and View

Instead of saving:

```bash
curl <https://example.com>
```

Pipe it:

```bash
curl <https://example.com> | less
```

Useful for:

- HTML
- JSON
- Logs
- Documentation

---

# 6. Pretty Print JSON

Without formatting:

```bash
curl <https://httpbin.org/json>
```

Better:

```bash
curl <https://httpbin.org/json> | jq
```

Now JSON becomes readable.

---

# 7. Search Downloaded Content

Instead of saving first:

```bash
curl <https://example.com> | grep "Example"
```

Useful for:

- Logs
- HTML
- Configuration files

---

# 8. Count Lines

```bash
curl URL | wc -l
```

Example:

```bash
curl <https://example.com> | wc -l
```

---

# 9. Download and Extract Immediately

Instead of:

```
Download tar.gz

↓

Extract
```

Do both together:

```bash
curl -L URL.tar.gz | tar -xz
```

Meaning:

```
Download

↓

Extract

↓

Finished
```

No temporary archive is created.

---

# 10. Save While Streaming (`tee`)

Sometimes you want both:

```
Download

↓

Save

↓

Continue Processing
```

Use:

```bash
curl URL | tee copy.txt
```

Now:

- File is saved.
- Output continues through the pipeline.

---

# 11. Stream Into gzip

Compress while downloading:

```bash
curl URL | gzip > backup.gz
```

---

Decompress while downloading:

```bash
curl URL.gz | gunzip
```

---

# 12. Stream Into tar

Compressed archive:

```bash
curl -L URL.tar.gz | tar -xz
```

Uncompressed archive:

```bash
curl -L URL.tar | tar -x
```

---

# 13. Upload From STDIN

Normally:

```bash
curl -T backup.tar.gz URL
```

Streaming:

```bash
tar -cz project/ | curl -T - URL
```

- `T -`

means:

```
Upload

↓

Read From STDIN
```

No archive is written to disk.

---

# 14. Stream Database Backups

Example PostgreSQL:

```bash
pg_dump mydb | gzip | curl -T - URL
```

Pipeline:

```
Database

↓

Dump

↓

Compress

↓

Upload
```

No temporary files.

---

# 15. Restore While Downloading

```bash
curl URL/database.sql.gz \
| gunzip \
| psql mydb
```

Pipeline:

```
Download

↓

Decompress

↓

Restore
```

# 20. Streaming vs Downloading

|Save First|Stream|
|---|---|
|Uses disk|Minimal disk usage|
|Multiple reads|One pass|
|Slower|Faster|
|Easier to inspect later|Better for automation|

# 21. Production Backup Pipeline

```bash
tar -cz /var/www \
| curl \
--fail \
--retry 3 \
-T - \
<https://backup.example.com/site.tar.gz>
```

Workflow:

```
Files

↓

Compress

↓

Upload

↓

Done
```

---

# 22. Production Restore Pipeline

```bash
curl \
--fail \
-L \
<https://backup.example.com/site.tar.gz> \
| tar -xz
```

# 23. Stream with Authentication

Bearer token:

```bash

```

Upload:

```bash

```

---

# 24. Error Handling in Pipelines

By default:

```bash
curl URL | tar -xz
```

If `curl` fails, `tar` may still run and produce confusing errors.

A safer approach:

```bash
set -o pipefail

curl --fail -L URL | tar -xz
```

`pipefail` causes the pipeline to fail if any command in it fails.

---

# 25. Production Streaming Command

```bash
set -o pipefail

curl \
--fail \
-L \
--retry 5 \
--retry-all-errors \
--connect-timeout 5 \
URL \
| tar -xz
```

Reliable for deployment and automation scripts.

# 💡 Pro Tips

### 1. Use streams for large data

Instead of:

```
Download

↓

Save

↓

Read Again
```

Prefer:

```
Download

↓

Process Immediately
```

This reduces disk usage and speeds up automation.

---

### 2. Enable `pipefail` in scripts

At the top of production Bash scripts:

```bash
set -o pipefail
```

This prevents hidden failures inside pipelines.

---

### 3. Think in Unix pipelines

One of the biggest productivity gains in Linux is combining small tools:

```bash
curl URL \
| jq '.items[]' \
| sort \
| uniq \
| wc -l
```

Each tool performs one task well, and together they create powerful workflows.
