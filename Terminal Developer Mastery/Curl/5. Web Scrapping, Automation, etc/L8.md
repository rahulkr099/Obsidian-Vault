# What is Website Monitoring?

Website monitoring is the process of checking whether a website is:

- Reachable
- Responding correctly
- Fast enough
- Returning the expected HTTP status

Basic workflow:

```
Website
    │
    ▼
curl Request
    │
    ▼
Receive Response
    │
    ▼
Analyze
    │
 ┌──┴───────┐
 │          │
Healthy   Problem
```

# Check if a Website is Online

The simplest check:

```bash
curl -I <https://example.com>
```

Output:

```
HTTP/2 200
content-type: text/html
...
```

A `200` status generally means the website is available.

---

# Get Only the Status Code

```bash
curl -s -o /dev/null -w "%{http_code}\n" <https://example.com>
```

Output:

```
200
```

---

# Understanding Common Status Codes

|Code|Meaning|Healthy?|
|---|---|---|
|200|OK|✅|
|201|Created|✅|
|204|No Content|✅|
|301|Permanent Redirect|Usually ✅|
|302|Temporary Redirect|Usually ✅|
|400|Bad Request|❌|
|401|Unauthorized|Depends|
|403|Forbidden|Depends|
|404|Not Found|❌|
|500|Internal Server Error|❌|
|502|Bad Gateway|❌|
|503|Service Unavailable|❌|

# Simple Health Check Script

```bash
#!/bin/bash

URL="<https://example.com>"

STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$URL")

if [ "$STATUS" = "200" ]
then
    echo "Website is UP"
else
    echo "Website is DOWN (HTTP $STATUS)"
fi
```

Example output:

```
Website is UP
```

# Measure Response Time

```bash
curl -s \
-o /dev/null \
-w "%{time_total}\n" \
<https://example.com>
```

Output:

```
0.183
```

Meaning the request took **0.183 seconds**.

---

# Response Time Guidelines

|Response Time|Interpretation|
|---|---|
|< 0.2 sec|Excellent|
|0.2–0.5 sec|Good|
|0.5–1 sec|Acceptable|
|1–2 sec|Slow|
|> 2 sec|Needs investigation|

These are general guidelines; acceptable times depend on the application.

# Detect Downtime

```bash
#!/bin/bash

URL="<https://example.com>"

if curl --fail -s "$URL" >/dev/null
then
    echo "UP"
else
    echo "DOWN"
fi
```

- `-fail` makes `curl` return a failure status for HTTP 4xx and 5xx responses.

---

# Monitor Multiple Websites

```bash
#!/bin/bash

for site in \
<https://example.com> \
<https://example.org> \
<https://example.net>
do
    STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$site")

    echo "$site -> $STATUS"
done
```

Example output:

```
<https://example.com> -> 200
<https://example.org> -> 200
<https://example.net> -> 404
```

# Check Redirects

Some websites redirect HTTP to HTTPS.

```bash
curl -I -L <http://example.com>
```

Options:

- `I` → Fetch headers only.
- `L` → Follow redirects.

---

# Check Final URL

```bash
curl -s \
-o /dev/null \
-w "%{url_effective}\n" \
-L <http://example.com>
```

Example output:

```
<https://example.com/>
```

Useful for confirming where redirects end.

---

# Monitor Content Changes

Download the homepage:

```bash
curl -s <https://example.com> > current.html
```

Compare with a previous copy:

```bash
diff previous.html current.html
```

If different:

```
Website content changed
```

Update the stored copy:

```bash
mv current.html previous.html
```

---

# Monitor File Size

```bash
curl -s <https://example.com> > page.html

wc -c page.html
```

Output:

```
1256 page.html
```

A sudden drop to a very small size might indicate an error page instead of the expected content.

---

# Complete Monitoring Script

```bash
#!/bin/bash

URL="<https://example.com>"

STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$URL")

TIME=$(curl -s -o /dev/null -w "%{time_total}" "$URL")

echo "$(date): Status=$STATUS Time=${TIME}s"

if [ "$STATUS" != "200" ]
then
    echo "ALERT: Website problem!"
fi
```

Example output:

```
Mon Jul 27 15:45 Status=200 Time=0.142s
```

# Useful `curl` Variables

|Variable|Description|
|---|---|
|`%{http_code}`|HTTP status|
|`%{time_total}`|Total request time|
|`%{url_effective}`|Final URL|
|`%{size_download}`|Downloaded bytes|
|`%{content_type}`|MIME type|
|`%{remote_ip}`|Connected server IP|

Example:

```bash
curl -s \
-o /dev/null \
-w "Status=%{http_code} Size=%{size_download}\n" \
<https://example.com>
```

# Common Mistakes

❌ Ignoring redirects.

Many websites automatically redirect HTTP to HTTPS.

Use:

```bash
curl -L
```

when appropriate.

---

❌ Only checking status codes.

A page can return `200` but still display an application error.

Sometimes it's useful to inspect the content or specific text on the page.

---

❌ No timeout.

Always consider:

```bash
curl --max-time 10
```

to avoid hanging scripts.

---

❌ Overwriting logs.

Using:

```bash
>
```

replaces the file.

Using:

```bash
>>
```

appends to the existing log.

# Real-World Backend Example

Imagine monitoring your own backend service:

```
<https://api.myapp.com/health>
```

Every minute, your script:

1. Sends a request.
2. Measures response time.
3. Checks the status code.
4. Records the result in a log.
5. Alerts if the service becomes unavailable.

This is a simplified version of the monitoring performed by tools like Prometheus, Grafana, and Uptime Kuma.

---

# Best Practices

- Use `-fail` in scripts to detect HTTP errors.
- Set reasonable timeouts with `-max-time`.
- Log timestamps for every check.
- Monitor both availability and performance.
- Start with simple shell scripts before adopting full monitoring platforms.

## 💡 Backend Engineer Tip

When monitoring websites, it's often more efficient to collect multiple metrics in **one** request instead of making separate `curl` calls:

```bash
curl -s -o /dev/null \
-w "Status: %{http_code}\nTime: %{time_total}s\nSize: %{size_download} bytes\nIP: %{remote_ip}\n" \
<https://example.com>
```

This reduces network requests and is a common optimization in production monitoring scripts.
