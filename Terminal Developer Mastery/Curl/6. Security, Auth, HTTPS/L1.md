# What is HTTP?

**HTTP (HyperText Transfer Protocol)** is the standard protocol for communication between a client and a web server.

Example:

```
Browser
    │
HTTP Request
    │
    ▼
Server
    │
HTTP Response
    ▼
Browser
```

Example request:

```
GET /users HTTP/1.1
Host: example.com
```

Problem:

> Everything is sent in **plain text**.

Anyone on the network could potentially read or modify it.

---

# Why HTTP Is Insecure

Imagine logging in over HTTP:

```
Username: rahul
Password: mypassword123
```

Since HTTP doesn't encrypt data, someone intercepting the traffic could read it.

This is why login forms, banking, and APIs should use HTTPS.

---

# What is HTTPS?

**HTTPS (HyperText Transfer Protocol Secure)** is simply:

```
HTTPS = HTTP + TLS
```

HTTP is still used for requests and responses.

TLS adds:

- Encryption
- Authentication
- Data integrity

---

# HTTP vs HTTPS

|Feature|HTTP|HTTPS|
|---|---|---|
|Encryption|❌|✅|
|Authentication|❌|✅|
|Integrity|❌|✅|
|Default Port|80|443|
|Safe for passwords|❌|✅|

---

# What Does HTTPS Protect?

HTTPS provides three important guarantees.

## 1. Confidentiality

Only the client and server can read the transmitted data.

---

## 2. Integrity

The data cannot be silently modified while in transit.

If someone changes the message, TLS detects it.

---

## 3. Authentication

The client can verify it's talking to the intended server (for example, `github.com`) and not an attacker pretending to be it.

---

# What is Encryption?

Encryption converts readable data into unreadable data.

Plain text:

```
hello
```

Encrypted:

```
8F91AB2C...
```

Without the proper key, the encrypted data cannot be understood.

---

# Two Types of Encryption

## Symmetric Encryption

One key is used for both encryption and decryption.

```
Client
   │
Shared Secret Key
   │
Server
```

Advantages:

- Very fast
- Efficient

Disadvantage:

- How do you securely share the key?

---

## Asymmetric Encryption

Uses a **key pair**:

- Public Key
- Private Key

```
Public Key
     ↓
Encrypt
     ↓
Internet
     ↓
Private Key
     ↓
Decrypt
```

Advantages:

- No need to share the private key.

Disadvantages:

- Slower than symmetric encryption.

---

# Public vs Private Key

Imagine a special mailbox:

- Anyone can drop a letter in (public key).
- Only the owner can open it (private key).

```
Public Key
     │
Encrypt
     │
Internet
     ▼
Private Key
     │
Decrypt
```

The public key can be shared with everyone.

The private key must remain secret.

---

# Why Doesn't HTTPS Use Only Public-Key Encryption?

Asymmetric encryption is computationally expensive.

Instead:

1. Use public-key cryptography to establish a secure connection.
2. Generate a temporary shared secret.
3. Use fast symmetric encryption for the rest of the session.

This combination provides both security and performance.

---

# What is a Certificate?

A certificate is like a digital ID card for a website.

It contains information such as:

- Domain name
- Public key
- Issuer
- Expiration date
- Digital signature

Example:

```
Subject:
example.com

Issuer:
Let's Encrypt

Expires:
2027-01-01
```

---

# Certificate Authority (CA)

A **Certificate Authority** is a trusted organization that verifies website ownership and signs certificates.

Examples include:

- Let's Encrypt
- DigiCert
- GlobalSign

Your operating system and browser contain a list of trusted CAs.

---

# Why Can't Anyone Create a Certificate?

Anyone _can_ create a certificate.

The important question is:

> **Will your computer trust it?**

If the certificate isn't signed by a trusted CA (or another trusted authority in its chain), browsers and `curl` will warn you.

---

# Certificate Chain

A typical trust chain looks like this:

```
Root CA
   │
Intermediate CA
   │
Website Certificate
```

Your system trusts the Root CA.

The Root CA trusts the Intermediate CA.

The Intermediate CA signs the website certificate.

---

# The TLS Handshake

Before encrypted communication begins, the client and server perform a handshake.

Simplified flow:

```
Client
   │
Hello
   │
────────────►

Server
   │
Hello
Certificate
Public Key
◄────────────

Client
Verify Certificate
Generate Shared Secret
────────────►

Server
Decrypt Secret
────────────►

Encrypted Communication Starts
```

After the handshake, all HTTP data is encrypted.

---

# What Happens When You Visit a Website?

```
Browser
   │
DNS Lookup
   │
Connect
   │
TLS Handshake
   │
Encrypted HTTP Request
   │
Encrypted HTTP Response
   ▼
Page Loaded
```

# SSL vs TLS

You may hear both names.

|SSL|TLS|
|---|---|
|Older protocol|Modern protocol|
|Obsolete|Current standard|
|Insecure|Secure|

Today, when people say "SSL certificate," they almost always mean a TLS certificate.

# How `curl` Uses HTTPS

A simple request:

```bash
curl <https://example.com>
```

Internally, `curl`:

1. Resolves the domain.
2. Connects to port 443.
3. Performs the TLS handshake.
4. Verifies the certificate.
5. Negotiates encryption.
6. Sends the HTTP request securely.
7. Receives the encrypted response.
8. Decrypts it before displaying the output.

---

# View TLS Details

Use verbose mode:

```bash
curl -v <https://example.com>
```

You'll see details such as:

- TLS version
- Cipher suite
- Certificate information
- HTTP request
- HTTP response

We'll explore this in Lesson 2.

# Common Misconceptions

❌ **"HTTPS encrypts only passwords."**

No. HTTPS encrypts the entire HTTP request and response (except metadata such as the destination IP address and, in many cases, the domain name via SNI—though newer technologies like ECH aim to improve this).

---

❌ **"SSL and TLS are the same."**

TLS replaced SSL. "SSL" is mostly historical terminology now.

---

❌ **"HTTPS makes websites completely secure."**

HTTPS protects data **in transit**. It does not protect against insecure application code, SQL injection, XSS, malware, or weak passwords.

---

# Best Practices

- Always prefer HTTPS over HTTP.
- Keep your operating system's trusted CA store updated.
- Avoid bypassing certificate verification.
- Use modern TLS versions.
- Renew certificates before they expire.
- Verify certificates when connecting to APIs.

---

# Key Takeaways

- HTTPS is HTTP protected by TLS.
- TLS provides confidentiality, integrity, and authentication.
- Public-key cryptography establishes trust; symmetric encryption secures the session efficiently.
- Certificates prove a server's identity.
- Certificate Authorities establish trust.
- `curl` automatically performs TLS negotiation and certificate validation for HTTPS requests.
