# What is a Repository?

A **repository (repo)** is a project that Git manages.

Think of it as:

> **Your project + complete history of every change.**

Example project:

```text
todo-api/
├── src/
├── package.json
├── README.md
└── .git/
```

The `.git/` folder is what makes this a Git repository.

Without `.git`, it's just a normal folder.

---

# Local vs Remote Repository

There are two kinds of repositories.

## Local Repository

Stored on your computer.

Example:

```text
~/Projects/todo-api
```

You can work completely offline.

---

## Remote Repository

Stored on services like GitHub.

Example:

```text
GitHub
   │
   ▼
github.com/rahul/todo-api
```

Multiple developers can collaborate through the remote repository.

# Initialize Git

Run:

```bash
git init
```

Output:

```text
Initialized empty Git repository in /home/rahul/git-practice/backend-api/.git/
```

Congratulations!

Your folder is now a Git repository.

---

# Check the Directory

Normally:

```bash
ls
```

Output:

```text
(nothing)
```

You won't see `.git` because it's hidden.

---

# Show Hidden Files

Run:

```bash
ls -a
```

Example:

```text
.
..
.git
```

The `.git` directory is hidden because its name starts with a dot (`.`).

---

# What is Inside `.git`?

Run:

```bash
ls .git
```

Example:

```text
HEAD
branches
config
description
hooks
info
objects
refs
```

These files are Git's internal database.

# Explore the Structure

Use the `tree` command (install it if needed):

```bash

```

Example:

```text
.git
├── HEAD
├── config
├── description
├── hooks
├── info
├── objects
└── refs
```

You don't need to understand every file yet—we'll cover them later.

# What Does `git init` Actually Do?

It does **not** upload anything.

It does **not** create a GitHub repository.

It simply creates the `.git` directory.

```text
Before

backend-api/
```

↓

```text
After

backend-api/
└── .git/
```

That's all.

Run:


# Find the Repository Root

Suppose you're deep inside a project:

```text
backend-api/
└── src/
    └── routes/
```

Run:

```bash
git rev-parse --show-toplevel
```

Output:

```text
/home/rahul/git-practice/backend-api
```

Very useful in large projects.

# Check the `.git` Directory

Run:

```bash
git rev-parse --git-dir
```

Output:

```text
.git
```

Or:

```text
/home/rahul/git-practice/backend-api/.git
```

# Repository Configuration

Every repository has its own configuration file.

View it:

```bash
cat .git/config
```

Example:

```ini
[core]
    repositoryformatversion = 0
    filemode = true
    bare = false
    logallrefupdates = true
```

Later, remotes and repository-specific settings will also appear here.

---

# Repository vs Project Folder

Example:

```text
backend-api/
├── src/
├── package.json
├── README.md
└── .git/
```

Everything except `.git` is **your project**.

`.git` is **Git's data**.

Never manually edit files inside `.git` unless you know exactly what you're doing.

---

# `git init` vs `git clone`

## `git init`

Creates a brand-new Git repository.

```bash
git init
```

Use when starting a new project.

---

## `git clone`

Downloads an existing repository.

```bash
git clone https://github.com/user/project.git
```

Use when joining an existing project.

# Deleting a Repository

Want to remove Git tracking?

Delete the `.git` directory.

Linux/macOS:

```bash
rm -rf .git
```

Windows PowerShell:

```powershell
Remove-Item -Recurse -Force .git
```

After that, the folder is just a normal directory again.

> **Be careful:** This permanently removes the repository history from your local copy.

---

# Common Mistakes

## Running `git init` Multiple Times

Usually safe.

Git will respond:

```text
Reinitialized existing Git repository...
```

---

## Initializing the Wrong Folder

Bad:

```text
Projects/
├── project1/
├── project2/
├── project3/
```

If you run:

```bash
git init
```

inside `Projects/`, Git will track **all three projects together**, which is usually not what you want.

Instead:

```text
Projects/
└── project1/
    └── .git
```

Each project should have its own repository.

---

# Best Practices

- Create one Git repository per project.
    
- Always verify your location with `pwd` before running `git init`.
    
- Use `ls -a` to confirm `.git` exists.
    
- Never edit files inside `.git` manually.
    
- Use `git clone` for existing projects instead of downloading ZIP files.
