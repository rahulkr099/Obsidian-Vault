# Module 11 — GitHub Features

# Lesson 55 — Dependabot

> **Goal:** Learn how GitHub's **Dependabot** automatically keeps your project's dependencies secure and up to date by creating update pull requests and reporting security vulnerabilities.

# Why Dependabot Exists

Imagine your Express backend uses these packages:

```text
express
mongoose
jsonwebtoken
bcrypt
dotenv
helmet
cors
```

Everything works fine.

But after six months:

- A security vulnerability is found in one package.
    
- A bug is fixed in another.
    
- A new version improves performance.
    

If you never update your dependencies, your application becomes outdated and potentially insecure.

This is where Dependabot helps.

---

# What is Dependabot?

Dependabot is a GitHub service that automatically:

- Detects outdated dependencies
    
- Finds known security vulnerabilities
    
- Creates Pull Requests to update packages
    
- Notifies repository maintainers
    

Instead of manually checking every package:

```text
Developer

↓

Check npm website

↓

Check GitHub

↓

Update package

↓

Test

↓

Repeat
```

Dependabot automates the checking process.

---

# How Dependabot Works

```text
GitHub Repository

↓

Reads dependency files

↓

Checks latest package versions

↓

Compares versions

↓

Creates Pull Request (if needed)
```

---

# Dependency Files It Understands

Dependabot supports many ecosystems.

For backend development, common examples include:

|Language|Dependency File|
|---|---|
|Node.js|`package.json`|
|Python|`requirements.txt`, `pyproject.toml`|
|Java|`pom.xml`|
|Go|`go.mod`|
|Rust|`Cargo.toml`|
|Docker|`Dockerfile` (base image updates)|
|GitHub Actions|Workflow action versions|

# Example Node.js Project

Suppose your `package.json` contains:

```json
{
  "dependencies": {
    "express": "^5.0.0",
    "mongoose": "^8.0.0"
  }
}
```

A few weeks later:

- Express releases `5.1.0`
    

Dependabot detects the newer version and creates a Pull Request.

---

# Example Pull Request

Dependabot opens a PR like:

```text
Bump express from 5.0.0 to 5.1.0
```

Inside the PR you'll typically see:

- Current version
    
- New version
    
- Release notes (when available)
    
- Changelog links
    
- Security information (if applicable)

# Dependabot Configuration

Dependabot is configured using:

```text
.github/

dependabot.yml
```

Example:

```text
project/

.github/

dependabot.yml
```

---

# Simple Configuration

```yaml
version: 2

updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
```

This tells GitHub:

- Monitor npm packages
    
- Look in the repository root
    
- Check once every week
    

---

# Understanding the Configuration

## Version

```yaml
version: 2
```

Current configuration format.

---

## Package Ecosystem

```yaml
package-ecosystem: "npm"
```

Dependabot knows which package manager to use.

Other examples:

```text
pip
maven
gomod
cargo
docker
github-actions
```

---

## Directory

```yaml
directory: "/"
```

The location of the dependency file.

For example:

```text
package.json
```

located in the project root.

---

## Schedule

```yaml
schedule:
  interval: "weekly"
```

Possible values:

```text
daily

weekly

monthly
```

# Multiple Ecosystems

A backend project may use both npm and Docker.

Example:

```yaml
updates:
  - package-ecosystem: "npm"
    directory: "/"

  - package-ecosystem: "docker"
    directory: "/"
```

Dependabot checks both.

# Dependabot + GitHub Actions

```text

↓

↓

GitHub Actions

├── Install

├── Test

├── Lint

├── Build

↓

↓

Review

↓

```

Automation helps ensure updates don't break the application.

---

# Dependabot + Protected Branches

Protected branches prevent automatic merging into `main`.

Workflow:

```text
Dependabot PR

↓

GitHub Actions

↓

Reviewer Approval

↓

Merge
```

The update still follows your normal review process.

---

# What Should You Review?

Never merge blindly.

Before approving a Dependabot PR, check:

- Release notes
    
- Changelog
    
- Breaking changes
    
- Test results
    
- CI status
    

Even minor updates can occasionally introduce unexpected behavior.

---

# Version Updates

Dependabot may suggest:

### Patch Update

```text
1.2.3

↓

1.2.4
```

Usually bug fixes.

---

### Minor Update

```text
1.2.3

↓

1.3.0
```

Often adds new features while remaining backward compatible.

---

### Major Update

```text
1.2.3

↓

2.0.0
```

May contain breaking changes.

These deserve extra attention before merging.

Dependabot helps you:

- Keep dependencies current
    
- Receive security alerts
    
- Reduce manual maintenance
    
- Integrate updates into normal code reviews
    
- Improve project security
    

---

# Best Practices

- Enable Dependabot on every repository.
    
- Review each update instead of merging automatically.
    
- Let GitHub Actions validate dependency updates.
    
- Read release notes for major version upgrades.
    
- Keep updates frequent—small updates are easier than catching up after a year.
    
- Update both application dependencies and GitHub Actions versions.
    

---

# Common Mistakes

❌ Ignoring Dependabot Pull Requests for months

❌ Merging major version upgrades without testing

❌ Disabling security alerts

❌ Treating all updates as equally urgent

❌ Assuming automation replaces human review
