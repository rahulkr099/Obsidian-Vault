# Module 13 — Git Recovery

# Lesson 61 — Recover Deleted Branches

> **Goal:** Learn how to recover accidentally deleted Git branches using `reflog`, understand when recovery is possible, and safely restore lost work.

---

# Why This Matters

Imagine you've been working for three days on a new authentication feature.

Your branch looks like this:

```text
main

A──B──C

         \
          D──E──F  feature/auth
```

You merge another feature, clean up branches, and accidentally run:

```bash
git branch -D feature/auth
```

The branch disappears.

You panic.

> "Did I lose three days of work?"

In most cases, **no**.

Git usually still knows where those commits are.

---

# What Happens When You Delete a Branch?

A branch is just a **pointer** to a commit.

Example:

```text
feature/auth

↓

Commit F
```

When you delete the branch:

```bash
git branch -D feature/auth
```

Git removes only the pointer.

```text
Commit F

(still exists)
```

The commits remain in the repository until Git eventually cleans up unreachable objects.

---

# Example

Before deletion:

```text
main

A──B──C

         \
          D──E──F
               ↑
         feature/auth
```

After deletion:

```text
main

A──B──C

         \
          D──E──F
```

The commits still exist.

Only the label is gone.

---

# Safe vs Force Delete

## Safe Delete

```bash
git branch -d feature/auth
```

Git checks whether the branch has already been merged.

If not:

```text
error:

The branch is not fully merged.
```

Git protects you.

---

## Force Delete

```bash
git branch -D feature/auth
```

Deletes the branch immediately.

Use it only when you're sure.

---

# How Git Remembers Deleted Branches

Git keeps a history of where `HEAD` and branch references pointed.

This history is called the **reflog**.

View it with:

```bash
git reflog
```

Example:

```text
abc123 HEAD@{0}: checkout: moving to main

def456 HEAD@{1}: commit: Add JWT middleware

789abc HEAD@{2}: checkout: moving to feature/auth
```

Even though the branch is gone, Git still remembers those commits.

---

# Finding the Lost Commit

Suppose:

```bash
git reflog
```

returns:

```text
7f3d21a HEAD@{0}: checkout: moving to main

4ab91de HEAD@{1}: commit: Add login validation

12fe881 HEAD@{2}: commit: Create auth controller
```

The last commit on the deleted branch is:

```text
4ab91de
```

That commit still exists.

---

# Recover the Branch

Simply create a new branch pointing to that commit.

```bash
git branch feature/auth 4ab91de
```

Or switch directly:

```bash
git switch -c feature/auth 4ab91de
```

Now:

```text
main

A──B──C

         \
          D──E──F
               ↑
         feature/auth
```

The branch is back.

---

# Using `git log`

Sometimes you already know the commit hash.

Example:

```bash
git log --all
```

Output:

```text
commit 4ab91de

Author:

Rahul

Message:

Add login validation
```

Recover:

```bash
git switch -c feature/auth 4ab91de
```

---

# Recover After Accidental Cleanup

Suppose you run:

```bash
git branch -D feature/payment

git branch -D feature/cache

git branch -D feature/auth
```

Later you realize:

```text
feature/auth

should not have been deleted.
```

Use:

```bash
git reflog
```

Locate the final commit.

Restore:

```bash
git switch -c feature/auth <commit-hash>
```

---

# Recover a Remote Branch

Suppose another teammate deleted a remote branch.

First, fetch updates:

```bash
git fetch origin
```

If you know the commit:

```bash
git switch -c feature/auth <commit-hash>
```

Push it again:

```bash
git push origin feature/auth
```

The remote branch is restored.

---

# What If I Don't Know the Commit?

Use:

```bash
git reflog
```

or

```bash
git log --all --graph --oneline
```

These commands help locate orphaned commits.

---

# When Recovery Fails

Recovery becomes difficult if:

- Git garbage collection removes unreachable commits.
    
- The repository has been aggressively cleaned.
    
- The commits never existed locally.
    

Fortunately, Git doesn't remove unreachable commits immediately.

This gives you time to recover.

# Backend Example

You're working on an Express API.

Branch:

```text
feature/jwt-refresh
```

Contains:

- Refresh token logic
    
- Middleware
    
- Tests
    

You accidentally delete it:

```bash
git branch -D feature/jwt-refresh
```

Recover:

```bash
git reflog
```

Find:

```text
8df231c

Add refresh token support
```

Restore:

```bash
git switch -c feature/jwt-refresh 8df231c
```

Nothing is lost.

# Best Practices

- Prefer `git branch -d` over `-D`.
    
- Delete branches only after confirming they are merged or no longer needed.
    
- Learn `git reflog` before working on production repositories.
    
- Keep feature branches pushed to GitHub as a backup.
    
- Avoid running aggressive cleanup commands unless you understand their effects.
    

---

# Common Mistakes

❌ Assuming deleted branches mean deleted commits

❌ Using `git branch -D` without checking

❌ Panicking before checking `git reflog`

❌ Forgetting to push important work to a remote repository

❌ Running cleanup commands before attempting recovery

---

# Commands You'll Use Most

|Purpose|Command|
|---|---|
|View reflog|`git reflog`|
|View all commits|`git log --all --graph --oneline`|
|Create branch from commit|`git switch -c <branch> <commit>`|
|Create branch (older syntax)|`git branch <branch> <commit>`|
|Push restored branch|`git push origin <branch>`|
