# Module 13 — Git Recovery

# Lesson 62 — Recover Deleted Files

> **Goal:** Learn how to recover accidentally deleted files in different Git states—working directory, staging area, committed history, and previous commits—without losing unrelated work.

---

# Why This Matters

Imagine you're working on a backend project.

Your project looks like this:

```text
backend/

├── server.js
├── package.json
├── routes/
├── controllers/
├── middleware/
├── config/
└── .env
```

While cleaning up your project, you accidentally delete:

```text
controllers/authController.js
```

You immediately think:

> "Did I just lose hundreds of lines of code?"

In most cases, **Git can recover it.**

The recovery method depends on **where the file was deleted**.

---

# Understanding File States

Before learning recovery, remember Git's three main areas:

```text
Working Directory

↓

Staging Area (Index)

↓

Repository (Commits)
```

A file can be deleted from any of these stages.

---

# Case 1 — Deleted Before Staging

Suppose:

```bash
rm controllers/authController.js
```

Git status:

```bash
git status
```

Output:

```text
deleted: controllers/authController.js
```

The deletion is **not staged**.

---

## Recover It

Simply restore the file:

```bash
git restore controllers/authController.js
```

Result:

```text
File restored from last commit.
```

No commit is required.

---

# Visual Example

Before:

```text
Working Directory

authController.js ✓
```

Delete:

```bash
rm authController.js
```

Recover:

```bash
git restore authController.js
```

Everything is back.

---

# Case 2 — Deleted and Staged

Suppose:

```bash
rm authController.js

git add .
```

Now:

```bash
git status
```

Output:

```text
Changes to be committed:

deleted: authController.js
```

The deletion is now in the staging area.

---

## Step 1 — Remove from Staging

```bash
git restore --staged authController.js
```

Now Git says:

```text
deleted:

not staged
```

---

## Step 2 — Restore the File

```bash
git restore authController.js
```

Recovered.

---

# Visual Workflow

```text
Deleted

↓

git add

↓

Deletion Staged

↓

git restore --staged

↓

git restore

↓

Recovered
```

---

# Case 3 — Deleted and Committed

Suppose:

```bash
rm authController.js

git add .

git commit -m "Remove auth controller"
```

The deletion is now part of Git history.

---

# Recover from Previous Commit

Find the commit that still contained the file.

```bash
git log -- authController.js
```

Example:

```text
commit 4ab91de

Add authentication controller
```

Restore the file:

```bash
git restore --source=4ab91de authController.js
```

The file returns to your working directory.

Commit it again if you want to keep it.

---

# Alternative Method

Older syntax:

```bash
git checkout 4ab91de -- authController.js
```

Modern Git recommends:

```bash
git restore --source
```

---

# Case 4 — Restore from HEAD

Suppose the last commit contains the file.

Restore directly:

```bash
git restore authController.js
```

Git copies the version from:

```text
HEAD
```

into your working directory.

---

# Case 5 — Restore Entire Directory

Deleted:

```text
controllers/

middleware/
```

Recover everything:

```bash
git restore controllers/

git restore middleware/
```

Or recover all deleted files:

```bash
git restore .
```

Be careful:

```bash
git restore .
```

discards **all uncommitted changes**, not just deleted files.

---

# Recover Using `git log`

View file history:

```bash
git log -- authController.js
```

Output:

```text
Commit A

↓

Commit B

↓

Commit C
```

Choose the version you need.

---

# Recover a Specific Version

Suppose:

```text
Commit A

Original

Commit B

Modified

Commit C

Current
```

Restore version from Commit A:

```bash
git restore --source=<commit-A> authController.js
```

Useful when you want an older version rather than the latest one.

Restore:

```text

```

Command:


# Recover an Entire Commit's Version

Suppose you want your project exactly as it was in:

```text
Commit:

ab123cd
```

You can restore selected files:

```bash
git restore --source=ab123cd src/
```

Only the specified directory changes.

---

# What `git restore` Does

It copies a version of a file from:

- HEAD (default)
    
- another commit (`--source`)
    
- the staging area
    

into your working directory.

It **does not delete Git history**.

---

# Common Recovery Commands

|Situation|Command|
|---|---|
|Restore deleted file|`git restore file`|
|Unstage deletion|`git restore --staged file`|
|Restore old version|`git restore --source=<commit> file`|
|View file history|`git log -- file`|
|Restore all files|`git restore .`|

---

# Best Practices

- Run `git status` before taking recovery actions.
    
- Use `git restore` instead of the older `git checkout` syntax for restoring files.
    
- Restore only the files you need whenever possible.
    
- Commit recovered files immediately if they should remain in the project.
    
- Review changes with `git diff` before committing.
    

---

# Common Mistakes

❌ Using `git restore .` without realizing it discards **all** uncommitted changes.

❌ Forgetting to unstage a deletion before restoring.

❌ Restoring the wrong commit.

❌ Assuming committed deletions are permanent.

❌ Mixing unrelated recovered files into the same commit.

---

# `git restore` vs `git reset`

|`git restore`|`git reset`|
|---|---|
|Restores file contents|Moves branch or changes staging state|
|Works with files|Often works with commits or staging|
|Safe for file recovery|More powerful and easier to misuse|
|Modern command|Older command with multiple purposes|

For recovering deleted files, `git restore` is usually the preferred tool.
