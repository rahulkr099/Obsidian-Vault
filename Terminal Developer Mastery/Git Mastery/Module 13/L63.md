# Module 13 — Git Recovery

# Lesson 63 — Recover Lost Commits

> **Goal:** Learn how to recover commits that appear to be "lost" after operations like `git reset`, `git rebase`, branch switching, or an accidental `HEAD` move using `git reflog`.

---

# Why This Matters

One of the biggest fears Git users have is:

> "I lost my commit."

Fortunately, in most cases, **the commit still exists**.

Git rarely deletes commits immediately. Most "lost" commits are simply **no longer referenced by a branch**.

---

# What Is a Lost Commit?

Imagine this history:

```text
A──B──C──D  main
```

Commit **D** is the latest commit.

Now you accidentally run:

```bash
git reset --hard HEAD~1
```

History becomes:

```text
A──B──C  main
```

Commit **D** seems to have disappeared.

Did Git delete it?

**No.**

Git only moved the `main` branch pointer.

```text
A──B──C  main

     \
      D   (still exists)
```

---

# Branches Are Just Pointers

Remember:

```text
main

↓

Commit D
```

After reset:

```text
main

↓

Commit C
```

Commit **D** still exists in Git's object database.

---

# The Hero: `git reflog`

The **reflog** records where `HEAD` and branch references have been.

Run:

```bash
git reflog
```

Example:

```text
a1b2c3d HEAD@{0}: reset: moving to HEAD~1

d4e5f6g HEAD@{1}: commit: Add JWT refresh token

9a8b7c6 HEAD@{2}: commit: Create auth middleware
```

Even though the branch moved, Git remembers the previous location.

---

# Recover After `git reset --hard`

Suppose:

```text
Before

A──B──C──D
```

You run:

```bash
git reset --hard HEAD~1
```

Now:

```text
A──B──C
```

Run:

```bash
git reflog
```

Output:

```text
HEAD@{0}: reset: moving to HEAD~1

HEAD@{1}: commit: Add JWT refresh token
```

Commit:

```text
d4e5f6g
```

is your lost commit.

---

# Restore the Commit

Option 1: Create a recovery branch

```bash
git switch -c recovery d4e5f6g
```

Now:

```text
A──B──C

     \
      D  recovery
```

Your work is safe again.

---

# Move `main` Back

If you actually want `main` to point to the lost commit:

```bash
git reset --hard d4e5f6g
```

History:

```text
A──B──C──D  main
```

Be careful: rewriting branch history like this is safe only if you understand the implications, especially if the branch has been shared.

---

# Recover After an Accidental Rebase

Suppose:

Before:

```text
A──B──C──D
```

You perform a rebase incorrectly.

After:

```text
A──B──X──Y
```

Where did **C** and **D** go?

Check:

```bash
git reflog
```

Example:

```text
HEAD@{2}: rebase finished

HEAD@{3}: commit: Add payment API

HEAD@{4}: commit: Add JWT middleware
```

Recover by creating a branch:

```bash
git switch -c old-history <commit-hash>
```

Now you can compare the histories before deciding how to proceed.

---

# Recover After an Accidental Checkout

Suppose you were experimenting.

You check out an old commit:

```bash
git switch --detach HEAD~5
```

You make a commit:

```bash
git commit -m "Experiment"
```

Then:

```bash
git switch main
```

Git warns:

```text
You are leaving 1 commit behind.
```

Many beginners ignore this warning.

---

# Find the Detached Commit

Use:

```bash
git reflog
```

Example:

```text
HEAD@{3}: commit: Experiment
```

Recover:

```bash
git switch -c experiment <commit-hash>
```

The detached commit now belongs to a branch.

---

# Recover Using `git fsck`

Sometimes you need to find dangling commits.

Run:

```bash
git fsck --lost-found
```

Example:

```text
dangling commit d4e5f6g
```

Inspect it:

```bash
git show d4e5f6g
```

If it's the commit you need:

```bash
git switch -c recovery d4e5f6g
```

> `git fsck` is a more advanced recovery tool. In most day-to-day situations, `git reflog` is the first place to look.

---

# Backend Example

Imagine you're working on a Node.js authentication API.

Recent commits:

```text
A Add Express

B JWT Login

C Refresh Tokens

D Email Verification
```

You accidentally run:

```bash
git reset --hard HEAD~2
```

History now appears as:

```text
A

B
```

Run:

```bash
git reflog
```

Output:

```text
HEAD@{1}: commit: Email Verification

HEAD@{2}: commit: Refresh Tokens
```

Recover:

```bash
git switch -c auth-recovery <email-verification-commit>
```

Your authentication work is restored.

```text
↓

↓

```

# When Recovery Is Possible

Recovery is usually possible if:

- The commit existed locally.
    
- Git hasn't garbage-collected the commit.
    
- The commit appears in `git reflog` or `git fsck`.
    

Recovery becomes much harder after aggressive cleanup or long periods during which unreachable commits are garbage-collected.

---

# `git reflog` vs `git log`

|`git log`|`git reflog`|
|---|---|
|Shows commit history reachable from current references|Shows movements of `HEAD` and branch references|
|Doesn't show unreachable commits|Often shows "lost" commits|
|Used for normal history|Used for recovery|

---

# Common Recovery Commands

|Situation|Command|
|---|---|
|View reflog|`git reflog`|
|Show lost commit|`git show <hash>`|
|Create recovery branch|`git switch -c recovery <hash>`|
|Move current branch back|`git reset --hard <hash>`|
|Find dangling commits|`git fsck --lost-found`|

---

# Best Practices

- Use `git reflog` before assuming work is gone.
    
- Create a recovery branch before experimenting with resets.
    
- Read Git's warnings when leaving detached `HEAD`.
    
- Push important work to a remote repository regularly.
    
- Verify recovered commits with `git show` before resetting branches.
    

---

# Common Mistakes

❌ Assuming `git reset --hard` permanently deletes commits

❌ Ignoring detached `HEAD` warnings

❌ Running cleanup commands before attempting recovery

❌ Resetting `main` without confirming the correct commit

❌ Forgetting that `git reflog` is local to your repository

---

# Real Production Scenario

A backend engineer accidentally runs:

```bash
git reset --hard HEAD~3
```

on a local feature branch.

Instead of rewriting code, they:

1. Run `git reflog`
    
2. Find the missing commit hash
    
3. Create a recovery branch
    
4. Verify the recovered code
    
5. Continue development
    

What could have taken hours to recreate is recovered in minutes.
