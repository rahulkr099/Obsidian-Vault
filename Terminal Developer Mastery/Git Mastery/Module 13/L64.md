# Module 13 — Git Recovery

# Lesson 64 — Undo Mistakes with `git revert`

> **Goal:** Learn how to safely undo commits using `git revert`, understand why it's the preferred method for shared branches, and know when to use `git revert` instead of `git reset`.

---

# Why `git revert` Exists

Imagine you've pushed a bug to your team's repository.

History:

```text
A──B──C──D  main
```

Commit **D** introduced a bug.

Your teammates have already pulled this commit.

Should you run?

```bash
git reset --hard HEAD~1
```

**No!**

`git reset` rewrites history, which can cause problems for anyone who has already pulled the branch.

Instead, use:

```bash
git revert <commit-hash>
```

This creates a **new commit** that reverses the changes made by the target commit.

---

# What Does `git revert` Do?

Suppose:

```text
A──B──C──D  main
```

Where:

- `D` = Added buggy authentication logic
    

Run:

```bash
git revert D
```

Git creates a new commit:

```text
A──B──C──D──E  main
             ↑
      Reverts D
```

Notice:

- Commit **D** still exists.
    
- History is preserved.
    
- The bug is undone.

# Basic Usage

Revert the latest commit:

```bash
git revert HEAD
```

Git:

1. Creates a reverse patch.
    
2. Opens your editor for a commit message.
    
3. Creates the revert commit.
    

Default message:

```text
Revert "Add JWT authentication"
```

---

# Revert a Specific Commit

View history:

```bash
git log --oneline
```

Example:

```text
d4e5f6 Add JWT authentication

c3d4e5 Add login route

b2c3d4 Initial API
```

Revert:

```bash
git revert d4e5f6
```

History becomes:

```text
b2c3d4

↓

c3d4e5

↓

d4e5f6

↓

f7g8h9  Revert "Add JWT authentication"
```

# Example Backend Project

Suppose you accidentally committed:

```javascript
console.log(process.env.JWT_SECRET);
```

This is a security issue.

Instead of rewriting history:

```bash
git revert HEAD
```

Git creates:

```text
Revert "Log JWT secret"
```

The logging statement is removed while keeping the history intact.

---

# Reverting Multiple Commits

Suppose:

```text
A──B──C──D──E
```

Both `D` and `E` need to be undone.

Revert them one at a time:

```bash
git revert E

git revert D
```

Result:

```text
A──B──C──D──E──F──G
```

Where:

- `F` reverts `E`
    
- `G` reverts `D`
    

> A good rule is to revert from the newest commit toward the oldest to reduce the chance of conflicts.

---

# Reverting Without Auto-Committing

Sometimes you want to inspect the changes first.

Use:

```bash
git revert --no-commit HEAD
```

Git applies the reverse changes but **does not create a commit**.

You can:

```bash
git diff
```

Review everything.

Then:

```bash
git commit -m "revert(auth): remove experimental login flow"
```

---

# Reverting Merge Commits

Merge commits have **two parents**, so Git needs to know which parent should be considered the main line of development.

Example history:

```text
        D──E
       /    \
A──B──C──────M
```

To revert merge commit `M`:

```bash
git revert -m 1 M
```

Where:

- `-m 1` means **keep the first parent** (usually the branch you merged _into_, such as `main`).
    

Merge reverts can be confusing, so verify the result carefully before pushing.

---

# What Happens Internally?

Original commit:

```text
+ Add JWT middleware
```

Revert commit:

```text
- Remove JWT middleware
```

Git stores **both** commits.

Nothing is deleted.

---

# `git revert` vs `git reset`

|`git revert`|`git reset`|
|---|---|
|Creates a new commit|Moves the branch pointer|
|Preserves history|Rewrites history|
|Safe for shared branches|Better for local cleanup|
|Recommended after pushing|Recommended before pushing (when appropriate)|

---

# When Should You Use `git revert`?

Use it when:

- The commit has already been pushed.
    
- Others may have pulled the branch.
    
- You want a clear audit trail.
    
- You want to preserve project history.
    

---

# When Should You Use `git reset`?

Use it when:

- Cleaning up your own local branch.
    
- Removing unpushed commits.
    
- Reorganizing commits before opening a Pull Request.

# Common Revert Conflicts

Sometimes later commits depend on the commit you're reverting.

Example:

```text
A──B──C──D──E
```

If `E` modifies code introduced in `D`, reverting `D` may cause conflicts.

Git will pause and ask you to resolve them.

After fixing the conflicts:

```bash
git add .

git revert --continue
```

---

# Cancel an In-Progress Revert

If you decide not to continue:

```bash
git revert --abort
```

Your repository returns to the state before the revert started.

---

# Best Practices

- Use `git revert` for commits that have already been shared.
    
- Run your tests after every revert.
    
- Read the generated commit message before committing.
    
- Revert one logical change at a time.
    
- Push the revert promptly if it's fixing a production issue.
    

---

# Common Mistakes

❌ Using `git reset` on a shared branch instead of `git revert`

❌ Reverting the wrong commit

❌ Forgetting to test after reverting

❌ Reverting commits in a confusing order

❌ Ignoring merge conflicts during a revert

---

# Frequently Used Commands

|Purpose|Command|
|---|---|
|Revert latest commit|`git revert HEAD`|
|Revert specific commit|`git revert <hash>`|
|Apply revert without committing|`git revert --no-commit <hash>`|
|Continue after resolving conflicts|`git revert --continue`|
|Cancel a revert|`git revert --abort`|
