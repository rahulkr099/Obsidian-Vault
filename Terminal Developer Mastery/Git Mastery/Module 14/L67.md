# Module 13 — Git Recovery

# Lesson 67 — Detached `HEAD` Recovery

> **Goal:** Understand what a detached `HEAD` is, why it happens, how to work safely in that state, and how to recover commits made while detached.

---

# What is `HEAD`?

Before understanding a detached `HEAD`, let's review what `HEAD` normally is.

In Git:

```text
HEAD
```

is a special pointer that represents:

> **"Where am I currently working?"**

Normally:

```text
HEAD
 │
 ▼
main
 │
 ▼
Commit D
```

`HEAD` points to a **branch**, and the branch points to a commit.

---

# Normal State

Suppose your repository looks like this:

```text
A──B──C──D  main
            ▲
          HEAD
```

When you make a commit:

```bash
git commit -m "Add login API"
```

Git moves both:

- `main`
    
- `HEAD`
    

Result:

```text
A──B──C──D──E  main
               ▲
             HEAD
```

Everything behaves normally.

---

# What is a Detached `HEAD`?

A detached `HEAD` means:

> `HEAD` points **directly to a commit**, not to a branch.

Example:

```text
A──B──C──D  main
      ▲
    HEAD
```

Notice:

- `HEAD` points to commit `C`
    
- `main` still points to `D`
    

You're **not on any branch**.

---

# How Does It Happen?

The most common way:

```bash
git switch --detach HEAD~2
```

or

```bash
git checkout <commit-hash>
```

Example:

```bash
git switch --detach a1b2c3d
```

Git responds:

```text
HEAD is now at a1b2c3d
```

You are now in detached `HEAD` mode.

---

# Verify Your State

Run:

```bash
git status
```

Output:

```text
HEAD detached at a1b2c3d
```

Git clearly tells you that you're detached.

---

# Why Would You Use Detached `HEAD`?

It is useful for:

- Exploring old commits
    
- Testing historical versions
    
- Debugging bugs
    
- Comparing versions
    
- Running experiments
    

Example:

```bash
git switch --detach v1.0.0
```

Now you're viewing exactly what the project looked like at release `v1.0.0`.

---

# The Danger

Suppose:

```text
A──B──C──D  main
      ▲
    HEAD
```

You create a commit:

```bash
git commit -m "Experiment"
```

History becomes:

```text
      E
     /
A──B──C──D  main
      ▲
    HEAD
```

Notice:

- Branch `main` did **not** move.
    
- Only detached `HEAD` points to `E`.
    

---

# What Happens Next?

You switch back:

```bash
git switch main
```

Git warns:

```text
Warning:

You are leaving 1 commit behind.
```

Now:

```text
A──B──C──D  main
            ▲
          HEAD

      E
```

Commit `E` has no branch pointing to it.

It is now an **unreachable commit** (though it can usually still be recovered).

---

# How to Avoid Losing Work

If you intentionally created useful commits:

Create a branch immediately.

```bash
git switch -c experiment
```

Now:

```text
      E  experiment
     /
A──B──C──D  main
            ▲
          HEAD
```

Nothing is lost.

---

# Recover Detached `HEAD` Work

Suppose you already switched away.

Run:

```bash
git reflog
```

Example:

```text
HEAD@{0}: checkout: moving to main

HEAD@{1}: commit: Experiment

HEAD@{2}: checkout: moving to a1b2c3d
```

Locate:

```text
Experiment
```

Commit hash:

```text
f7a8b9c
```

Recover:

```bash
git switch -c experiment f7a8b9c
```

Your work is restored.

---

# Visual Recovery Workflow

```text
Detached HEAD

↓

Create Commit

↓

Switch Branch

↓

Commit Appears Lost

↓

git reflog

↓

Find Commit

↓

git switch -c recovery <hash>

↓

Recovered
```

# Example Backend Scenario

Suppose you're debugging an old release.

Current project:

```text
v2.3.0
```

You switch:

```bash
git switch --detach v2.1.0
```

You discover a bug.

You fix it:

```bash
git commit -m "Fix authentication bug"
```

Don't switch back immediately.

Instead:

```bash
git switch -c hotfix/v2.1-auth
```

Now the fix belongs to a branch.

You can later:

- Cherry-pick it
    
- Merge it
    
- Open a Pull Request
    

---

# Detached `HEAD` During Bisect

Later you'll learn:

```bash
git bisect
```

Git automatically enters detached `HEAD` mode while searching for bugs.

This is normal.

Don't panic if you see:

```text
HEAD detached
```

during a bisect session.

---

# Detached `HEAD` with Tags

Example:

```bash
git switch --detach v1.2.0
```

Tags are **not branches**.

So Git enters detached `HEAD`.

Perfectly normal.

---

# How to Return to Normal

Simply switch to a branch.

```bash
git switch main
```

Now:

```text
HEAD

↓

main

↓

Latest Commit
```

Detached `HEAD` is gone.

---

# How to See Where `HEAD` Is

Useful commands:

```bash
git status
```

or

```bash
git branch
```

Output:

```text
* (HEAD detached at a1b2c3d)

main

feature/login
```

The `*` indicates your current position.

---

# Common Detached `HEAD` Commands

View old commit:

```bash
git switch --detach HEAD~3
```

Create branch:

```bash
git switch -c recovery
```

Recover using reflog:

```bash
git reflog
```

Return:

```bash
git switch main
```

---

# Real Production Example

Suppose production reports a bug in:

```text
Release:

v2.4.0
```

You inspect:

```bash
git switch --detach v2.4.0
```

You identify the bug.

Fix it.

Immediately:

```bash
git switch -c hotfix/v2.4
```

Now your hotfix is safely stored on a branch and can be merged or released.

---

# Detached `HEAD` vs Branch

|Branch|Detached `HEAD`|
|---|---|
|`HEAD` points to a branch|`HEAD` points directly to a commit|
|New commits move the branch|New commits are not attached to any branch|
|Normal development|Temporary exploration or debugging|
|Safe for ongoing work|Safe if you create a branch before leaving|

---

# Best Practices

- Detached `HEAD` is not an error—it's a valid Git state.
    
- Create a branch if your detached work becomes valuable.
    
- Use `git reflog` if you accidentally leave commits behind.
    
- Use detached `HEAD` for exploration, testing, and debugging.
    
- Read Git's warnings before switching branches.
    

---

# Common Mistakes

❌ Ignoring the message:

```text
You are leaving 1 commit behind
```

❌ Assuming detached `HEAD` means the repository is broken.

❌ Creating multiple commits and switching away without creating a branch.

❌ Forgetting that tags also produce detached `HEAD`.

❌ Panicking instead of checking `git reflog`.

---

# Frequently Used Commands

|Purpose|Command|
|---|---|
|Enter detached `HEAD`|`git switch --detach <commit>`|
|Check status|`git status`|
|Create branch from detached state|`git switch -c <branch>`|
|Recover lost detached commit|`git reflog`|
|Return to main|`git switch main`|
