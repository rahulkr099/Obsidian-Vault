# Module 13 — Git Recovery

# Lesson 68 — Git Stash Recovery

> **Goal:** Learn how to temporarily save unfinished work with `git stash`, recover it later, manage multiple stashes, and safely switch tasks without losing progress.

---

# Why `git stash` Exists

Imagine you're working on a new authentication feature.

Your project contains uncommitted changes:

```text
server.js
authController.js
authRoutes.js
```

Suddenly your team lead says:

> "There's a production bug. Please fix it immediately."

You try:

```bash
git switch main
```

Git responds:

```text
error: Your local changes would be overwritten by checkout.
```

You don't want to:

- Commit unfinished work ❌
    
- Lose your changes ❌
    

Instead, use:

```bash
git stash
```

Git safely stores your unfinished work and restores your working directory to a clean state.

---

# What is a Stash?

A stash is like a temporary shelf for your changes.

```text
Working Directory

↓

git stash

↓

Hidden Storage

↓

Clean Working Directory
```

Your changes are **not deleted**.

They're simply stored for later.

---

# Basic Example

Suppose:

```bash
git status
```

Output:

```text
Modified:

server.js

authController.js
```

Save everything:

```bash
git stash
```

Output:

```text
Saved working directory and index state
```

Now:

```bash
git status
```

Output:

```text
Working tree clean
```

Your changes are safely stored.


After:

# View Stashes

List all saved stashes:

```bash
git stash list
```

Example:

```text
stash@{0}

WIP on feature/auth

stash@{1}

WIP on feature/login

stash@{2}

WIP on main
```

Newest stash:

```text
stash@{0}
```

Oldest stash:

```text
stash@{2}
```

---

# Restore a Stash

Apply the latest stash:

```bash
git stash apply
```

Your changes return.

The stash **still exists**.

---

# Apply a Specific Stash

Suppose:

```text
stash@{0}

stash@{1}

stash@{2}
```

Restore:

```bash
git stash apply stash@{1}
```

Only that stash is applied.

---

# Apply vs Pop

## Apply

```bash
git stash apply
```

Result:

```text
Changes Restored

↓

Stash Still Exists
```

---

## Pop

```bash
git stash pop
```

Result:

```text
Changes Restored

↓

Stash Deleted
```

Use `pop` only when you're sure you no longer need the saved copy.

---

# Drop a Stash

Delete one stash:

```bash
git stash drop stash@{1}
```

Now:

```text
stash@{1}

gone
```

---

# Delete All Stashes

```bash
git stash clear
```

All stashes disappear.

Use carefully.

---

# Stashing Staged Changes

Suppose:

```bash
git add server.js
```

and:

```bash
git status
```

shows:

```text
Changes to be committed
```

Running:

```bash
git stash
```

stores:

- Staged changes
    
- Unstaged changes
    

Both are restored later.

---

# Stashing Untracked Files

Normally:

```bash
git stash
```

does **not** include untracked files.

Suppose:

```text
newFile.js
```

is untracked.

Use:

```bash
git stash -u
```

or:

```bash
git stash --include-untracked
```

Now untracked files are also stored.

---

# Name Your Stash

Instead of:

```bash
git stash
```

Use:

```bash
git stash push -m "JWT refresh token experiment"
```

Now:

```bash
git stash list
```

Output:

```text
stash@{0}

JWT refresh token experiment
```

Much easier to identify later.

# Backend Example

You're building:

```text
Refresh Tokens
```

Halfway through:

Production bug appears.

Run:

```bash
git stash push -m "Refresh token WIP"
```

Switch:

```bash
git switch main
```

Fix production.

Return:

```bash
git switch feature/auth
```

Restore:

```bash
git stash pop
```

Continue where you left off.

# Stash Conflicts

Sometimes:

Current branch:

```javascript
const PORT = 3000;
```

Stash contains:

```javascript
const PORT = 8080;
```

Git cannot combine them automatically.

You'll see:

```text
CONFLICT
```

Resolve it just like a merge conflict.

Then:

```bash
git add .

git commit
```

---

# Create a Branch From a Stash

Very useful.

Suppose:

```bash
git stash list
```

shows:

```text
stash@{0}
```

Create a branch:

```bash
git stash branch feature/experiment stash@{0}
```

Git:

- Creates a branch
    
- Applies the stash
    
- Removes the stash (if successful)
    

Perfect for experiments that deserve their own branch.

---

# Stash vs Commit

|`git stash`|`git commit`|
|---|---|
|Temporary storage|Permanent history|
|Not shared|Can be shared by pushing|
|Good for unfinished work|Good for completed work|
|Usually local only|Part of project history|

---

# Common Stash Commands

|Purpose|Command|
|---|---|
|Save stash|`git stash`|
|Named stash|`git stash push -m "message"`|
|Include untracked files|`git stash -u`|
|View stashes|`git stash list`|
|Apply stash|`git stash apply`|
|Pop stash|`git stash pop`|
|Delete stash|`git stash drop stash@{0}`|
|Delete all|`git stash clear`|
|Create branch from stash|`git stash branch <branch>`|

---

# Best Practices

- Name important stashes.
    
- Prefer short-lived stashes; don't leave them for weeks.
    
- Use `apply` if you're unsure—you'll keep a backup.
    
- Use `pop` after verifying the restored changes.
    
- Create a branch if a stash grows into a larger feature.
    

---

# Common Mistakes

❌ Forgetting that untracked files are not stashed by default

❌ Running:

```bash
git stash clear
```

accidentally

❌ Keeping dozens of unnamed stashes

❌ Forgetting to restore the stash after switching back

❌ Using stash as long-term storage instead of branches
