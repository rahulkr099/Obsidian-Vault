# Module 13 — Git Recovery

# Lesson 70 — Emergency Recovery Toolkit

> **Goal:** Build a practical recovery playbook for real-world Git emergencies. By the end of this lesson, you'll know exactly what to do when something goes wrong, instead of panicking.

---

# Why You Need an Emergency Toolkit

Every developer eventually experiences situations like:

- "I accidentally deleted a branch!"
    
- "I lost my last commit!"
    
- "I ran `git reset --hard`!"
    
- "My merge has conflicts!"
    
- "I'm stuck in a detached `HEAD`!"
    
- "I accidentally stashed my work!"
    

The important thing is not avoiding every mistake—it's knowing how to recover calmly and methodically.

---

# Golden Rule

## 🚨 Stop and Don't Panic

When something goes wrong:

❌ Don't keep running random Git commands.

❌ Don't delete the `.git` directory.

❌ Don't clone the repository again immediately.

Instead:

```text
Stop

↓

Inspect

↓

Understand

↓

Recover
```

Many "lost" changes are still recoverable.

---

# Step 1 — Check Your Repository State

Always start with:

```bash
git status
```

Example:

```text
On branch feature/auth

Changes not staged

Unmerged paths

Detached HEAD
```

`git status` often tells you exactly what the problem is.

---

# Step 2 — Check Recent History

View commit history:

```bash
git log --oneline --graph --all
```

Example:

```text
* 8ab2f1 Add JWT middleware

* 4d91ef Login API

* c921fe Initial commit
```

This helps determine whether commits are actually missing or just on another branch.

---

# Step 3 — Check the Reflog

If anything seems lost:

```bash
git reflog
```

Example:

```text
HEAD@{0}: reset

HEAD@{1}: commit: Add refresh token

HEAD@{2}: checkout: feature/auth
```

Remember:

> **`git reflog` is your best recovery tool.**

---

# Emergency 1 — Deleted Branch

Problem:

```bash
git branch -D feature/auth
```

Recovery:

```bash
git reflog
```

Find:

```text
abc123 Add authentication
```

Restore:

```bash
git switch -c feature/auth abc123
```

Done.

---

# Emergency 2 — Lost Commit After Reset

Problem:

```bash
git reset --hard HEAD~1
```

Recovery:

```bash
git reflog
```

Find:

```text
HEAD@{1}

Commit:

abc123
```

Restore:

```bash
git reset --hard abc123
```

Or:

```bash
git switch -c recovery abc123
```

---

# Emergency 3 — Detached HEAD

Problem:

```text
HEAD detached
```

Solution:

If you've created useful commits:

```bash
git switch -c experiment
```

Already switched away?

Recover:

```bash
git reflog
```

Then:

```bash
git switch -c recovery <hash>
```

---

# Emergency 4 — Merge Conflict

Git reports:

```text
CONFLICT
```

Workflow:

```text
Open File

↓

Read Both Versions

↓

Choose Correct Code

↓

Remove Markers

↓

git add

↓

git commit
```

If you don't want to continue:

```bash
git merge --abort
```

---

# Emergency 5 — Rebase Conflict

Resolve the conflicted file.

Then:

```bash
git add .
```

Continue:

```bash
git rebase --continue
```

Or abort:

```bash
git rebase --abort
```

---

# Emergency 6 — Accidentally Stashed Work

View stashes:

```bash
git stash list
```

Restore:

```bash
git stash pop
```

Or:

```bash
git stash apply
```

Forgot the stash name?

Check:

```bash
git stash list
```

---

# Emergency 7 — Deleted File

Recover latest version:

```bash
git restore filename.js
```

Recover from an older commit:

```bash
git restore --source=<commit> filename.js
```

---

# Emergency 8 — Wrong Commit Message

Undo without losing changes:

```bash
git reset --soft HEAD~1
```

Recommit:

```bash
git commit -m "Better message"
```

---

# Emergency 9 — Committed to the Wrong Branch

Suppose:

You accidentally committed to:

```text
main
```

Instead of:

```text
feature/login
```

Recovery:

Create the correct branch:

```bash
git switch -c feature/login
```

Return to `main`:

```bash
git switch main
```

If the commit should not remain on `main`, reset or revert it depending on whether it has already been shared.

---

# Emergency 10 — Accidentally Pushed Bad Code

If others may already have pulled the commit, avoid rewriting shared history.

Preferred approach:

```bash
git revert <commit>
```

This creates a new commit that undoes the changes.

If the branch is private and no one else is using it, you may choose a history-rewriting approach (such as `git reset` followed by a force push), but coordinate with your team first.

# Recovery Decision Tree

```text
Problem?

│

├── Lost Commit
│      ↓
│   git reflog
│
├── Deleted Branch
│      ↓
│   git switch -c
│
├── Merge Conflict
│      ↓
│   Resolve + git add
│
├── Detached HEAD
│      ↓
│   Create Branch
│
├── Deleted File
│      ↓
│   git restore
│
├── Bad Commit
│      ↓
│   git revert
│
└── Stash Issue
       ↓
   git stash list
```

Imagine you're deploying an Express API.

Everything goes wrong.

```text
Wrong commit pushed

↓

Hotfix branch deleted

↓

Merge conflict

↓

Reset mistake

↓

Detached HEAD
```

Recovery:

```text
git status

↓

git log

↓

git reflog

↓

Recover Commit

↓

Create Recovery Branch

↓

Fix Merge

↓

Push Correct Code
```

This systematic approach avoids making the situation worse.

# Recovery Command Cheat Sheet

|Problem|Command|
|---|---|
|Check repository|`git status`|
|View history|`git log --oneline --graph --all`|
|Recover lost commits|`git reflog`|
|Restore deleted file|`git restore <file>`|
|Recover deleted branch|`git switch -c <branch> <hash>`|
|Recover after reset|`git reset --hard <hash>` or `git switch -c <branch> <hash>`|
|Abort merge|`git merge --abort`|
|Abort rebase|`git rebase --abort`|
|Continue rebase|`git rebase --continue`|
|Apply stash|`git stash apply`|
|Pop stash|`git stash pop`|
|Verify repository|`git fsck`|
|Run maintenance|`git gc`|

# Mental Checklist

Before running any recovery command, ask:

```text
Is the work committed?

↓

Is it in another branch?

↓

Is it in reflog?

↓

Is it stashed?

↓

Can I recover without rewriting history?
```

This checklist helps you choose the safest recovery method.

---

# Best Practices

- Read the output of `git status` before taking action.
    
- Use `git reflog` as your first recovery tool for missing commits.
    
- Prefer `git revert` over `git reset` on shared branches.
    
- Create a recovery branch before experimenting.
    
- Make frequent, meaningful commits.
    
- Push important work to a remote repository regularly.
    

---

# Common Mistakes

❌ Running multiple recovery commands without understanding the problem.

❌ Force-pushing to shared branches without team coordination.

❌ Ignoring Git's warnings.

❌ Forgetting to check `git reflog`.

❌ Deleting recovery branches too quickly.
