# A Typical Backend Repository

Imagine a project with several branches:

```text
main
develop
feature/login
feature/payment
feature/profile
bugfix/jwt
hotfix/security
docs/api
```

As features are completed, many of these branches become unnecessary.

Professional teams clean them up regularly.

# List Local Branches

The basic command:

```bash
git branch
```

Example:

```text
bugfix/jwt
feature/login
feature/payment
* main
```

The `*` indicates your current branch.

---

# Show the Current Branch

Option 1:

```bash
git branch
```

Option 2 (recommended):

```bash
git status
```

Example:

```text
On branch feature/login
```

Another quick option:

```bash
git branch --show-current
```

Output:

```text
feature/login
```

This is useful in scripts and terminal prompts.

---

# List Branches with More Information

```bash
git branch -v
```

Example:

```text
feature/login   4f2ab91 Add login validation
feature/payment d93ae67 Add Stripe integration
* main          8d9f4e3 Merge payment feature
```

This shows:

- Branch name
    
- Latest commit hash
    
- Latest commit message
    

---

# Show Merged Branches

```bash
git branch --merged
```

Example:

```text
feature/login
feature/profile
* main
```

These branches have already been merged into the current branch and are generally safe to delete.

---

# Show Unmerged Branches

```bash
git branch --no-merged
```

Example:

```text
feature/payment
bugfix/jwt
```

These branches still contain work that hasn't been merged.

---

# Rename the Current Branch

Suppose you're on:

```text
feature/login
```

Rename it:

```bash
git branch -m feature/authentication
```

Now:

```bash
git branch
```

Output:

```text
feature/authentication
* main
```

---

# Rename Another Branch

Without switching:

```bash
git branch -m feature/login feature/auth
```

Old name → New name.

---

# Delete a Branch Safely

Suppose you've merged:

```text
feature/login
```

Delete it:

```bash
git branch -d feature/login
```

Git checks whether the branch has already been merged.

If yes:

Deleted successfully.

---

# Why `-d` Is Safe

Suppose:

```text
main

↓

Merge feature/login
```

Now:

```bash
git branch -d feature/login
```

Only the branch pointer is removed.

The commits remain in `main`.

No work is lost.

---

# Force Delete

Suppose a branch hasn't been merged.

Git refuses:

```text
error: The branch is not fully merged.
```

If you're absolutely sure:

```bash
git branch -D feature/old-work
```

⚠️ `-D` ignores the safety check.

Use it carefully.

---

# Branches Are Just Pointers

Imagine:

```text
Commit A

↓

Commit B ← main
          ↑
     feature/login
```

Delete:

```bash
git branch -d feature/login
```

Result:

```text
Commit A

↓

Commit B ← main
```

The commit history remains.

Only the pointer disappears.

---

# Delete Multiple Branches

```bash
git branch -d feature/login feature/payment docs/api
```

Useful after completing several pull requests.

```bash

```

This is uncommon but available.

# Remote-Tracking Branches

When working with GitHub, you'll see:

```text
main
feature/login

origin/main
origin/feature/login
```

Important distinction:

- `main` → Local branch
    
- `origin/main` → Remote-tracking branch
    

We'll cover this in detail in the GitHub module.

---

# List Remote Branches

```bash
git branch -r
```

Example:

```text
origin/main
origin/develop
origin/feature/login
```

---

# List All Branches

```bash
git branch -a
```

Output:

```text
* main
feature/payment
origin/main
origin/feature/payment
```

Very useful in team environments.

# Real Team Workflow

Morning:

```bash
git switch feature/payment
```

Complete feature.

Commit.

Merge.

Delete:

```bash
git branch -d feature/payment
```

Start next feature:

```bash
git switch -c feature/email
```

Repeat.

Professional development is a cycle of:

```text
Create

↓

Develop

↓

Merge

↓

Delete

↓

Repeat
```

# Common Mistakes

## Mistake 1

Never deleting old branches.

After a year:

```text
feature1
feature2
feature3
feature-old
test
temp
backup
copy
new
latest
```

The repository becomes difficult to navigate.

---

## Mistake 2

Force deleting without checking.

Always try:

```bash
git branch -d
```

first.

Only use:

```bash
git branch -D
```

when you're certain.

---

## Mistake 3

Using meaningless names.

Bad:

```text
test123
branch1
temp
```

Good:

```text
feature/order-history
bugfix/login-timeout
docs/openapi
```

---

# Best Practices

- Delete merged branches regularly.
    
- Keep branch names descriptive.
    
- Use `git branch -v` to quickly inspect branches.
    
- Use `git branch --merged` before cleanup.
    
- Prefer `-d` over `-D`.

# Cheat Sheet

|Command|Purpose|
|---|---|
|`git branch`|List local branches|
|`git branch -v`|List branches with latest commit|
|`git branch --show-current`|Show current branch|
|`git branch --merged`|List merged branches|
|`git branch --no-merged`|List unmerged branches|
|`git branch -m new-name`|Rename current branch|
|`git branch -m old new`|Rename another branch|
|`git branch -d branch`|Delete merged branch|
|`git branch -D branch`|Force delete branch|
|`git branch -r`|List remote branches|
|`git branch -a`|List all branches|

## Professional Tip

Most experienced backend engineers finish every feature with this sequence:

```bash
git switch main
git pull
git branch -d feature/my-feature
git switch -c feature/next-task
```

This keeps the repository clean, reduces confusion, and ensures each new task starts from an up-to-date `main` branch.
