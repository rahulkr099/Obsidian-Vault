# Git vs GitHub

This is one of the most common interview questions.

## Git

Git is a **version control system**.

It runs on your computer.

It tracks:

- Files
    
- Commits
    
- Branches
    
- History
    

Example:

```text
Laptop

↓

Git Repository
```

Git works **without the Internet**.

---

## GitHub

GitHub is a **cloud hosting platform for Git repositories**.

Think of it as:

```text
Google Drive

+

Git

+

Developer Collaboration
```

GitHub stores Git repositories online.

---

# Simple Analogy

Imagine writing a book.

Git:

```text
Microsoft Word

↓

Save versions
```

GitHub:

```text
Google Docs

↓

Share with others
```

Git manages versions.

GitHub manages collaboration.

---

# Git Works Without GitHub

You can use Git forever without GitHub.

Example:

```bash
git init

git add .

git commit -m "Initial commit"
```

Everything works.

No GitHub required.

---

# GitHub Uses Git

GitHub is built around Git.

When you push code:

```text
Laptop

↓

Git

↓

GitHub
```

GitHub stores the repository exactly as Git created it.


# What is a Remote?

A **remote** is simply a reference to another Git repository.

Example:

```text
origin

↓

https://github.com/rahul/notes-api.git
```

Git remembers this location.

Later you'll run:

```bash
git push origin main
```

Git knows exactly where to send the commits.

---

# The Name `origin`

Almost every Git repository contains:

```text
origin
```

It is **not** a keyword.

It's just the default name Git uses for the primary remote.

You could call it:

```text
github

production

backup

office
```

But almost everyone uses:

```text
origin
```

---

# Local and Remote Branches

Example:

```text
Local

main
feature/login
feature/payment
```

GitHub:

```text
origin/main
origin/feature/login
origin/feature/payment
```

Notice:

Local:

```text
main
```

Remote tracking:

```text
origin/main
```

These are different references.

# Remote Doesn't Replace Local

A common misconception:

> "After pushing to GitHub, I no longer have the project locally."

Wrong.

You have **two copies**:

```text
Laptop

+

GitHub
```

They are synchronized using Git commands.

# Common Mistakes

## Mistake 1

Thinking GitHub **is** Git.

Git:

- Software
    

GitHub:

- Hosting platform
    

Different things.

---

## Mistake 2

Working only on GitHub's web editor.

Professional development happens primarily:

```text
Local Machine

↓

Git

↓

GitHub
```

---

## Mistake 3

Never pushing code.

If your laptop fails:

No backup.

Push regularly.

---

# Best Practices

- Commit locally, push regularly.
    
- Treat GitHub as the source of collaboration.
    
- Keep your local repository clean before pushing.
    
- Use descriptive repository names.
    
- Never commit secrets (API keys, passwords, `.env` files).
