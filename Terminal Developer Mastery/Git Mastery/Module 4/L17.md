# Step 1 — Create a GitHub Repository

Go to GitHub and click:

```text
New Repository
```

Example:

```text
Repository Name:

notes-api
```

Choose:

- ✅ Public (for open source or portfolio)
    
- ✅ Private (for personal/company work)
    

**Important:**

If your project already exists locally, **do not** initialize the GitHub repository with:

- README
    
- `.gitignore`
    
- License
    

Leave those unchecked.

Why?

Because your local repository already contains its own history.

# Step 2 — Your Local Repository

Example:

```text
notes-api/

├── src/
├── package.json
├── README.md
└── .git/
```

Your project is ready.

Check:

```bash
git status
```

Make sure:

```text
working tree clean
```

# Step 3 — Copy the Repository URL

GitHub provides two URLs.

HTTPS:

```text
https://github.com/rahul/notes-api.git
```

SSH:

```text
git@github.com:rahul/notes-api.git
```

Both point to the same repository.

---

# HTTPS vs SSH

## HTTPS

```text
Laptop

↓

HTTPS

↓

GitHub
```

Example:

```text
https://github.com/user/project.git
```

Pros:

- Easy to understand
    
- Works immediately
    
- No SSH key setup
    

Cons:

- May require authentication (today usually via Personal Access Token rather than a password)
    

---

## SSH

```text
Laptop

↓

SSH Key

↓

GitHub
```

Example:

```text
git@github.com:user/project.git
```

Pros:

- More convenient after setup
    
- No repeated authentication prompts
    
- Preferred by many professional developers
    

Cons:

- Requires SSH key configuration
    

> **Recommendation:** Since you've already completed the SSH module, use **SSH** for your own projects.

# Step 4 — Add the Remote

Using SSH:

```bash
git remote add origin git@github.com:rahul/notes-api.git
```

Or HTTPS:

```bash
git remote add origin https://github.com/rahul/notes-api.git
```

Breakdown:

```text
git remote add

↓

Create a remote

origin

↓

Name

git@github.com:rahul/notes-api.git

↓

Remote repository address
```

---

# Verify the Remote

Run:

```bash
git remote -v
```

Example:

```text
origin  git@github.com:rahul/notes-api.git (fetch)
origin  git@github.com:rahul/notes-api.git (push)
```

Git stores separate URLs for:

- Fetching
    
- Pushing
    

Usually they're the same.

---

# Understanding `origin`

Remember:

```text
origin
```

is **just a nickname**.

Git stores something like:

```text
origin

↓

git@github.com:rahul/notes-api.git
```

Later, when you run:

```bash
git push origin main
```

Git replaces `origin` with the stored URL.

---

# Push Your Code

Upload your `main` branch:

```bash
git push origin main
```

Meaning:

```text
Push

↓

Remote: origin

↓

Branch: main
```

Git uploads:

- Commits
    
- Branches
    
- Tags (when requested)
    

It does **not** upload uncommitted changes.

---

# First Push with Upstream

The first time you push a branch, use:

```bash
git push -u origin main
```

What does `-u` do?

It sets an **upstream branch**.

After this, instead of typing:

```bash
git push origin main
```

you can simply type:

```bash
git push
```

Git already knows where `main` should go.

The same applies to:

```bash
git pull
```

---

# What Is an Upstream Branch?

Think of it as a permanent relationship.

```text
Local

main

↓

Tracks

↓

origin/main
```

Git remembers this mapping.

You can inspect it with:

```bash
git branch -vv
```

Example:

```text
* main 8d9f4e3 [origin/main] Initial commit
```

---

# Verify on GitHub

Refresh the repository page.

You should now see:

```text
README.md
package.json
src/
```

along with the commit history.

Your local repository and GitHub repository are now synchronized.

---

# Pushing Again

Suppose you make a new change:

```bash
echo "// health check" >> src/server.js
git add src/server.js
git commit -m "Add health check endpoint"
```

Now:

```bash
git push
```

Because the upstream is configured, Git knows exactly where to send the commit.

# Inspect Your Remotes

View remotes:

```bash
git remote
```

Output:

```text
origin
```

Verbose:

```bash
git remote -v
```

Output:

```text
origin  git@github.com:rahul/notes-api.git (fetch)
origin  git@github.com:rahul/notes-api.git (push)
```

Detailed information:

```bash
git remote show origin
```

Example output:

```text
Fetch URL: git@github.com:rahul/notes-api.git
Push  URL: git@github.com:rahul/notes-api.git
HEAD branch: main
Local branch configured for 'git pull':
  main merges with remote main
```

This command is useful when debugging remote configuration.

---

# Changing a Remote URL

Suppose you rename your GitHub repository.

Update the remote:

```bash
git remote set-url origin git@github.com:rahul/new-notes-api.git
```

Verify:

```bash
git remote -v
```

---

# Removing a Remote

Sometimes you need to disconnect a repository.

```bash
git remote remove origin
```

Check:

```bash
git remote -v
```

No output means there are no configured remotes.

---

# Adding Multiple Remotes

Professional developers sometimes use multiple remotes.

Example:

```text

```

# Common Errors

## Error 1

```text
remote origin already exists
```

Why?

You already added it.

Check:

```bash
git remote -v
```

---

## Error 2

```text
Repository not found
```

Possible causes:

- Wrong repository URL
    
- Repository deleted
    
- No permission
    
- Typo in username or repository name
    

---

## Error 3

```text
Permission denied (publickey)
```

Cause:

SSH authentication failed.

Check your SSH setup:

```bash
ssh -T git@github.com
```

If you've completed the SSH module, this should authenticate successfully.

---

## Error 4

```text
src refspec main does not match any
```

Usually means:

- You have not made your first commit.
    
- Or your default branch is named `master` instead of `main`.
    

Check:

```bash
git branch
```

---

# Best Practices

- Make at least one commit before connecting to GitHub.
    
- Use SSH for long-term development.
    
- Use `git push -u` on the first push.
    
- Verify your remote with `git remote -v`.
    
- Push regularly to back up your work.
    

---

# Cheat Sheet

|Command|Purpose|
|---|---|
|`git remote add origin <url>`|Add a remote|
|`git remote -v`|View remotes|
|`git remote show origin`|Inspect remote details|
|`git push origin main`|Push a branch|
|`git push -u origin main`|Push and set upstream|
|`git remote set-url origin <url>`|Change remote URL|
|`git remote remove origin`|Remove a remote|
|`git branch -vv`|Show upstream tracking|

## Professional Tip

Before every push, many backend engineers quickly run:

```bash
git status
git log --oneline -3
git push
```

This helps ensure:

- Your working tree is clean.
    
- You're pushing the expected commits.
    
- Nothing accidental is included.
