# What is a GitHub Issue?

A **GitHub Issue** is a ticket used to track work in a repository.

An issue can represent:

- 🐞 A bug
    
- ✨ A new feature
    
- 📚 Documentation work
    
- ⚡ Performance improvements
    
- 🔒 Security issues
    
- 🛠️ Refactoring
    
- ❓ Questions or discussions
    

Think of an Issue as a **task card** for developers.

---

# Why Do Teams Use Issues?

Imagine a team without Issues.

```text
Developer A:
"I found a bug."

Developer B:
"I'll remember it."

Developer C:
"We also need dark mode."

Developer D:
"I forgot."
```

Soon, everyone loses track of what needs to be done.

With GitHub Issues:

```text
Issue #12
Fix Login Bug

↓

Assigned

↓

In Progress

↓

Closed
```

Everything is organized and visible.

# Example Project

# Writing Good Issue Titles

Bad:

```text
Bug
```

Bad:

```text
Problem
```

Bad:

```text
Fix
```

Good:

```text
Login endpoint returns 500 on invalid password
```

Good:

```text
Add password reset email feature
```

Good:

```text
Improve MongoDB query performance
```

Be specific.

---

# Writing Good Issue Descriptions

Poor:

```text
App broken.
```

Better:

```markdown
## Problem

Login API returns HTTP 500.

## Expected

Should return HTTP 401.

## Steps

1. Login
2. Enter wrong password
3. Submit

## Result

Internal Server Error

## Environment

Node 22
MongoDB Atlas
Ubuntu 24.04
```

Good descriptions save debugging time.

# Milestones

Milestones group Issues into releases.

Example:

```text
Version 1.0

↓

Authentication

↓

Documentation

↓

Deployment

↓

Testing
```

When all related Issues are closed, the milestone is complete.

---

# Issue Comments

Developers discuss solutions directly on the Issue.

Example:

```text
Developer A:

I found the problem.
```

```text
Developer B:

I'll submit a PR.
```

```text
Developer C:

Fixed in PR #41.
```

Issues become the history of the work.

---

# Closing Issues

When work is finished:

```text
Issue

↓

Closed
```

Or automatically by mentioning it in a Pull Request:

```text
Fixes #15
```

or

```text
Closes #15
```

When that PR is merged, GitHub automatically closes **Issue #15**.

---

# Linking Pull Requests

Example:

Issue:

```text
#18 Add User Profile API
```

PR:

```text
Add User Profile API

Fixes #18
```

Result:

```text
Issue #18

↓

Merged

↓

Closed Automatically
```

This creates a clear connection between the task and the code.

# Good First Issues

Open-source projects often mark beginner-friendly tasks with:

```text
good first issue
```

These tasks usually involve:

- Small bug fixes
    
- Documentation
    
- Minor UI changes
    
- Simple tests
    

They're a great way to start contributing.

---

# Help Wanted

Projects may label tasks as:

```text
help wanted
```

Meaning:

> The maintainers are looking for contributors to work on this issue.

---

# Duplicate Issues

Sometimes the same bug is reported twice.

Instead of creating another task:

```text
Issue #45

↓

Duplicate of #12

↓

Close
```

Keeping one canonical issue avoids confusion.

---

# Security Issues

Never publicly report serious security vulnerabilities.

Instead:

- Follow the project's security policy.
    
- Contact the maintainers privately if requested.
    

Avoid posting exploit details in a public Issue.

# Best Practices

✅ One Issue for one task

✅ Clear title

✅ Detailed description

✅ Add labels

✅ Assign an owner

✅ Link related PRs

✅ Close completed Issues

✅ Search before creating a new Issue to avoid duplicates

# Common Mistakes

❌ Vague titles like "Bug"

❌ No reproduction steps

❌ Mixing multiple problems into one Issue

❌ Forgetting to assign the Issue

❌ Leaving completed Issues open

❌ Reporting security vulnerabilities publicly

# Interview Questions

### 1. What is a GitHub Issue?

A GitHub Issue is a task or discussion used to track bugs, features, documentation, and other work in a repository.

---

### 2. What information should a good bug report include?

- Clear title
    
- Problem description
    
- Steps to reproduce
    
- Expected behavior
    
- Actual behavior
    
- Environment details
    
- Screenshots or logs (if helpful)
    

---

### 3. What are labels used for?

Labels categorize and prioritize Issues, making them easier to filter and manage.

---

### 4. What is the purpose of milestones?

Milestones group related Issues into releases or project goals.

---

### 5. What does `Fixes #25` do in a Pull Request?

When the PR is merged, GitHub automatically closes **Issue #25** and links it to the merged work.
