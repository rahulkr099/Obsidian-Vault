# Lesson 33 — Git Stash (Temporarily Save Your Work)

> **Goal:** Learn how to temporarily save unfinished work using `git stash`, switch branches without making unnecessary commits, and restore your work later.

---

# What is Git Stash?

`git stash` temporarily saves your **uncommitted changes** and restores your working directory to a clean state.

Think of it as putting your unfinished work into a **temporary drawer**.

Instead of making a "Work in Progress" commit:

```text
Feature Branch

↓

Unfinished Code

↓

git stash

↓

Clean Working Directory
```

Later, you can take your work back from the stash.

---

# Why Use Stash?

Imagine you're working on a feature:

```text
Feature Branch

↓

JWT Authentication

↓

Half Finished
```

Suddenly, your manager says:

> "There's a production bug. Please fix it immediately."

Git won't let you switch branches if your changes would conflict.

Instead of creating a meaningless commit:

```text
WIP

Still Working

Don't Merge
```

Use:

```bash
git stash
```

Now you can switch branches safely.

---

# Example Scenario

Current branch:

```text
feature/auth
```

Files:

```text
app.js

middleware.js

auth.js
```

You modify:

```text
app.js
```

```text
auth.js
```

Git status:

```bash
git status
```

Output:

```text
modified: app.js

modified: auth.js
```

---

# Basic Stash

Save everything:

```bash
git stash
```

Git says:

```text
Saved working directory and index state
```

Now:

```bash
git status
```

Output:

```text
nothing to commit, working tree clean
```

Your changes are safely stored.

---

# Where Does the Stash Go?

Git stores it in a special stack.

Example:

```text
Top

↓

Stash 2

↓

Stash 1

↓

Stash 0
```

Newest stash is always on top.

---

# List Stashes

View all stashes:

```bash
git stash list
```

Example:

```text
stash@{0}

stash@{1}

stash@{2}
```

Each stash has an index.

---

# Restore Latest Stash

Use:

```bash
git stash apply
```

or

```bash
git stash apply stash@{0}
```

Your changes return.

The stash **still exists**.

---

# Pop a Stash

Instead of:

```bash
git stash apply
```

Use:

```bash
git stash pop
```

Difference:

- Restores changes
    
- Removes the stash
    

Think of it as:

```text
Take Work

↓

Delete Drawer
```

---

# Apply vs Pop

|Command|Restores Changes|Deletes Stash|
|---|---|---|
|`git stash apply`|✅|❌|
|`git stash pop`|✅|✅|

If you're unsure, use `apply` first.

---

# Named Stashes

Instead of anonymous entries:

```text
stash@{0}
```

Give them names:

```bash
git stash push -m "JWT Authentication"
```

Another:

```bash
git stash push -m "Payment API"
```

Now:

```bash
git stash list
```

Output:

```text
stash@{0}

Payment API

stash@{1}

JWT Authentication
```

Much easier to recognize.

---

# Stashing Specific Files

Instead of everything:

```bash
git stash push app.js
```

Or:

```bash
git stash push src/auth.js
```

Only those files are stashed.

---

# Stash Including Untracked Files

Normally:

```bash
git stash
```

does **not** stash new untracked files.

Use:

```bash
git stash -u
```

or

```bash
git stash --include-untracked
```

Now Git also saves:

```text
newFile.js
```

---

# Include Ignored Files

Rarely needed.

```bash
git stash -a
```

or

```bash
git stash --all
```

This includes:

- ignored files
    
- untracked files
    
- tracked files
    

---

# Show Stash Contents

View summary:

```bash
git stash show
```

Example:

```text
2 files changed

15 insertions

4 deletions
```

---

# Show Full Changes

```bash
git stash show -p
```

Displays the complete patch.

Useful when you can't remember what you stashed.

---

# Delete One Stash

Remove:

```bash
git stash drop stash@{0}
```

That stash disappears.

---

# Delete All Stashes

```bash
git stash clear
```

Be careful.

Everything is removed.

---

# Create a Branch From a Stash

Very useful.

Imagine:

You started coding on the wrong branch.

Instead of:

```text
main

↓

Half Finished Feature
```

Run:

```bash
git stash
```

Then:

```bash
git stash branch feature/login
```

Git:

- Creates a new branch
    
- Applies the stash
    
- Removes the stash
    

Perfect for moving unfinished work.

---

You're working on:


Halfway through:


```bash

```


# What Gets Stashed?

By default:

|Item|Stashed?|
|---|---|
|Modified tracked files|✅|
|Staged changes|✅|
|Untracked files|❌|
|Ignored files|❌|

With:

```bash
git stash -u
```

Untracked files are included.

With:

```bash
git stash -a
```

Ignored files are also included.

---

# Common Mistakes

❌ Forgetting you have stashes

❌ Using `git stash clear` accidentally

❌ Popping the wrong stash

❌ Never naming important stashes

❌ Assuming untracked files are included by default

---

# Best Practices

✅ Name important stashes

```bash
git stash push -m "JWT Authentication"
```

---

✅ Use `git stash list` regularly.

---

✅ Use `git stash apply` if you're unsure.

---

✅ Delete old stashes.

---

✅ Keep stash temporary—not permanent storage.

---

# Stash vs Commit

## Commit

```text
History

↓

Permanent
```

Everyone can eventually see it if pushed.

---

## Stash

```text
Temporary

↓

Local Only
```

Never pushed to GitHub.

---

# Stash vs Branch

|Branch|Stash|
|---|---|
|Long-term work|Temporary work|
|Can be shared|Local only|
|Visible in history|Hidden from history|
|Used for features|Used for interruptions|

# Interview Questions

### 1. What is `git stash`?

`git stash` temporarily saves uncommitted changes and restores the working directory to a clean state.

---

### 2. What is the difference between `git stash apply` and `git stash pop`?

- `apply` restores changes but keeps the stash.
    
- `pop` restores changes and removes the stash.
    

---

### 3. How do you view all stashes?

```bash
git stash list
```

---

### 4. How do you stash untracked files?

```bash
git stash -u
```

or

```bash
git stash --include-untracked
```

---

### 5. Are stashes shared with GitHub?

No. Stashes exist only in your local repository unless you manually recreate or commit the changes.

---

# Useful Commands Summary

|Command|Purpose|
|---|---|
|`git stash`|Stash current changes|
|`git stash push -m "message"`|Create a named stash|
|`git stash list`|List all stashes|
|`git stash apply`|Restore latest stash|
|`git stash pop`|Restore and remove latest stash|
|`git stash show`|Show summary of stash|
|`git stash show -p`|Show full patch|
|`git stash drop stash@{0}`|Delete one stash|
|`git stash clear`|Delete all stashes|
|`git stash branch feature-name`|Create a branch from a stash|

## 💡 Backend Engineer Tip

As a backend developer, you'll use **`git stash`** whenever you're interrupted by:

- 🚑 Emergency production bugs
    
- 🔄 Context switching between features
    
- 🧪 Testing code on another branch
    
- 🔍 Reviewing someone else's Pull Request
    
- ⚡ Quickly switching tasks without making incomplete commits
    

It's one of the most practical Git commands you'll use throughout your career.
