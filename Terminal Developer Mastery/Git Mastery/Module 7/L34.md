# Lesson 34 — Git Bisect (Find Bugs Automatically)

> **Goal:** Learn how to use `git bisect` to quickly find the exact commit that introduced a bug by using a binary search through your commit history.

---

# What is Git Bisect?

`git bisect` is Git's **automatic bug finder**.

Instead of checking every commit one by one, Git performs a **binary search** to locate the commit that introduced a bug.

Imagine you have:

```text
A ─ B ─ C ─ D ─ E ─ F ─ G ─ H
```

Everything worked at:

```text
C
```

The bug exists at:

```text
H
```

Which commit introduced the bug?

Without `git bisect`, you might test:

```text
D

E

F

G

H
```

Five manual tests.

With `git bisect`, Git intelligently narrows the search.

---

# Why Use Git Bisect?

Suppose:

Yesterday:

```text
Everything Works
```

Today:

```text
Login API Broken
```

Your project has:

```text
450 commits
```

Which commit caused it?

Checking one by one could take hours.

`git bisect` often finds the culprit in just a few tests.

---

# Binary Search

Git Bisect uses the same algorithm as **Binary Search** in DSA.

Instead of checking:

```text
1

2

3

4

5

6

7

8
```

Git checks the middle:

```text
4
```

Then only half the commits remain.

Again:

```text
6
```

Again:

```text
5
```

Each test cuts the search space roughly in half.

# Starting Bisect

Begin:

```bash
git bisect start
```

Tell Git the **bad** commit:

```bash
git bisect bad
```

Usually this is your current `HEAD`.

Tell Git the **good** commit:

```bash
git bisect good <commit-hash>
```

Example:

```bash
git bisect good a1b2c3d
```

Git now checks out a commit in the middle.

---

# Testing Each Commit

Git prints something like:

```text
Bisecting: 24 revisions left to test
```

Run your application.

Example:

```bash
npm test
```

or

```bash
npm run dev
```

or manually verify the bug.

If the bug exists:

```bash
git bisect bad
```

If everything works:

```bash
git bisect good
```

Git selects the next commit.

Repeat until finished.

# Reset After Bisect

Very important.

When finished:

```bash
git bisect reset
```

Git returns you to your original branch.

Never forget this step.

# Automated Bisect

Suppose you already have a test:

```bash
npm test
```

If:

Exit code:

```text
0
```

means:

```text
Good
```

and:

```text
1
```

means:

```text
Bad
```

Run:

```bash
git bisect run npm test
```

Git automatically:

- checks out commits
    
- runs tests
    
- marks commits good/bad
    
- finds the culprit
    

No manual typing required.

---

# Using Custom Scripts

Example:

```bash
git bisect run ./test-login.sh
```

Your script should:

Return:

```text
0
```

when successful.

Return:

```text
1
```

when the bug exists.

This is common in CI pipelines and large projects.

---

# Skip Commits

Sometimes a commit doesn't build.

Example:

```text
Compilation Failed
```

Tell Git:

```bash
git bisect skip
```

Git ignores that commit and continues.

---

# Viewing Current Bisect Status

Run:

```bash
git bisect log
```

Example:

```text
good C

bad H

good E

bad F
```

Useful if you need to review or replay your bisect session.

---

# Replay a Bisect

You can save the bisect log and replay it later:

```bash
git bisect replay bisect.log
```

This is useful for documenting investigations or reproducing them on another machine.

# Common Mistakes

❌ Forgetting the last known good commit

❌ Marking commits incorrectly

❌ Forgetting:

```bash
git bisect reset
```

❌ Testing inconsistently

❌ Ignoring failing tests unrelated to the bug

---

# Best Practices

✅ Know one good commit and one bad commit before starting.

✅ Use automated tests whenever possible.

✅ Test consistently.

✅ Always reset when finished.

✅ Keep your test deterministic (same result every run).

# Bisect vs Manual Search

Manual:

```text
Commit 1

Commit 2

Commit 3

Commit 4

Commit 5

...
```

Time complexity:

```text
O(n)
```

Bisect:

```text
Middle

↓

Half

↓

Quarter

↓

...
```

Time complexity:

```text
O(log n)
```

Exactly like Binary Search in DSA.

# Useful Commands Summary

|Command|Purpose|
|---|---|
|`git bisect start`|Start bisect session|
|`git bisect good <commit>`|Mark a known good commit|
|`git bisect bad`|Mark current commit as bad|
|`git bisect skip`|Skip an untestable commit|
|`git bisect run <command>`|Automate testing|
|`git bisect log`|Show bisect history|
|`git bisect reset`|End bisect and return to original branch|

# Interview Questions

### 1. What is `git bisect`?

`git bisect` is a Git tool that uses binary search to identify the commit that introduced a bug.

---

### 2. What algorithm does Git Bisect use?

It uses the **Binary Search** algorithm, reducing the number of commits to test from **O(n)** to **O(log n)**.

---

### 3. What information do you need before starting a bisect?

You need:

- One **known good** commit
    
- One **known bad** commit
    

---

### 4. How do you automate Git Bisect?

```bash
git bisect run npm test
```

Git automatically runs the test command at each selected commit.

---

### 5. Why should you run `git bisect reset`?

It exits the bisect session and returns your repository to the branch and commit you were on before starting.

## 💡 Backend Engineer Tip

`git bisect` is one of Git's most underrated tools. In large backend services with thousands of commits, it can reduce hours of debugging to just a few minutes. Combined with a reliable automated test suite, it's an incredibly effective way to pinpoint when a regression was introduced.
