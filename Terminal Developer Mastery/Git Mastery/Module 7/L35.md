# Lesson 35 — Git Reflog (Recover "Lost" Commits)

> **Goal:** Learn how to use `git reflog` to recover commits, branches, and other Git states that seem "lost." By the end of this lesson, you'll understand why `git reflog` is considered Git's safety net.

---

# What is Git Reflog?

`git reflog` records **every movement of HEAD** in your local repository.

Think of it as Git's **activity history**.

While `git log` shows **commit history**, `git reflog` shows **where your HEAD has been**.

```text
You

↓

checkout

↓

commit

↓

rebase

↓

reset

↓

merge

↓

checkout
```

Every one of these actions is recorded.

---

# Why is Reflog Important?

Imagine this situation:

```text
Oops!

↓

git reset --hard

↓

My commits disappeared!
```

Most beginners think:

> "My work is gone forever."

Usually, it isn't.

If Git knows about the commit, `git reflog` can often help you recover it.

---

# Git Log vs Git Reflog

## Git Log

Shows reachable commits.

```text
A ─ B ─ C ─ D
```

Command:

```bash
git log
```

---

## Git Reflog

Shows HEAD history.

Example:

```text
HEAD@{0}

HEAD@{1}

HEAD@{2}

HEAD@{3}
```

Even if commits disappear from `git log`, they may still appear in `git reflog`.

---

# Viewing the Reflog

Run:

```bash
git reflog
```

Example output:

```text
f8a1234 HEAD@{0}: commit: Fix login validation

e7b5678 HEAD@{1}: checkout: moving from main to feature

d6c4321 HEAD@{2}: reset: moving to HEAD~1

c5d9876 HEAD@{3}: commit: Add JWT middleware
```

Each entry records an action involving `HEAD`.

---

# Understanding Reflog Entries

Example:

```text
HEAD@{0}
```

Means:

Current position.

---

```text
HEAD@{1}
```

Means:

Previous position.

---

```text
HEAD@{2}
```

Means:

Two actions ago.

Git stores these positions locally.

---

# Recovering a Lost Commit

Suppose you accidentally run:

```bash
git reset --hard HEAD~2
```

History before:

```text
A ─ B ─ C ─ D
```

After reset:

```text
A ─ B
```

Looks like:

```text
C

D

Gone
```

Run:

```bash
git reflog
```

Output:

```text
HEAD@{1}

Commit D
```

Recover it:

```bash
git reset --hard HEAD@{1}
```

Everything returns.

---

# Recover Using Commit Hash

Instead of:

```text
HEAD@{1}
```

Use:

```bash
git reset --hard a1b2c3d
```

where `a1b2c3d` is the commit hash shown in the reflog.

---

# Recover Deleted Branch

Suppose:

```bash
git branch -D feature/auth
```

Oops.

Branch deleted.

Run:

```bash
git reflog
```

Find the last commit:

```text
7f9ab12

Add authentication
```

Create branch again:

```bash
git checkout -b feature/auth 7f9ab12
```

Branch restored.

---

# Recover After Rebase

Suppose:

```bash
git rebase
```

went wrong.

Reflog:

```text
HEAD@{3}

Before rebase
```

Return:

```bash
git reset --hard HEAD@{3}
```

Back to the original history.

---

# Recover After Merge

Bad merge?

Reflog:

```text
HEAD@{2}

Before merge
```

Restore:

```bash
git reset --hard HEAD@{2}
```

Merge undone.

---

# Recover After Checkout

Suppose:

```bash
git checkout main
```

Then:

```bash
git checkout feature
```

Forgot where you were?

Run:

```bash
git reflog
```

Output:

```text
checkout

main

↓

feature
```

Helpful for retracing your steps.

---

# Recover After Cherry-pick

Suppose:

```bash
git cherry-pick
```

created unexpected results.

Reflog:

```text
Before cherry-pick
```

Restore:

```bash
git reset --hard HEAD@{1}
```

---

# Recover After Commit Amend

Suppose:

```bash
git commit --amend
```

Accidentally removed something.

Reflog still contains:

```text
Original Commit
```

Recover:

```bash
git checkout <old-commit-hash>
```

or create a new branch from it.

---

# Recover Detached HEAD Work

Imagine:

```bash
git checkout a1b2c3d
```

You are now in a **detached HEAD** state.

You make a commit:

```text
Temporary Fix
```

Later:

```bash
git checkout main
```

Git warns:

```text
Leaving 1 commit behind
```

You ignore it.

The commit disappears from normal history.

Run:

```bash
git reflog
```

Find the commit:

```text
HEAD@{4}

Temporary Fix
```

Recover it:

```bash
git checkout -b recovered-work <commit-hash>
```

Your work is saved.

---

# Reflog Expiration

Reflog entries don't last forever.

Typically:

- Reachable entries: about **90 days**
    
- Unreachable entries: about **30 days**
    

After garbage collection, very old entries may be removed.

This is why you should recover lost work as soon as possible.

You are working on:

History:

# Reflog vs Log

|Git Log|Git Reflog|
|---|---|
|Commit history|HEAD movement history|
|Shared history|Local history only|
|Shows reachable commits|Shows current and previous HEAD positions|
|Same for everyone|Different on every developer's machine|

---

# Reflog vs Stash

|Reflog|Stash|
|---|---|
|Tracks repository actions|Stores uncommitted work|
|Used for recovery|Used for temporary context switching|
|Automatic|Manual|
|Local only|Local only|

# Best Practices

✅ Run `git reflog` before panicking.

✅ Create a recovery branch before experimenting:

✅ Learn `git reset --hard` only after understanding reflog.

# Useful Commands Summary

|Command|Purpose|
|---|---|
|`git reflog`|Show HEAD history|
|`git reset --hard HEAD@{1}`|Return to a previous HEAD position|
|`git reset --hard <commit>`|Recover using a commit hash|
|`git checkout -b recovery <commit>`|Create a branch from a recovered commit|
|`git log --reflog`|View commits using reflog references|

# Interview Questions

### 1. What is `git reflog`?

`git reflog` records the history of where `HEAD` has pointed in your local repository, making it possible to recover many seemingly lost commits.

---

### 2. What is the difference between `git log` and `git reflog`?

- `git log` shows the commit history that is currently reachable.
    
- `git reflog` shows local `HEAD` movements, including commits that may no longer appear in `git log`.
    

---

### 3. Can `git reflog` recover deleted commits?

Yes, as long as the commits haven't been permanently removed by Git's garbage collection.

---

### 4. Is `git reflog` shared with GitHub?

No. Reflog exists **only on your local machine** and is not pushed to remote repositories.

---

### 5. What should you do after finding a lost commit in the reflog?

Create a recovery branch or reset to the commit, depending on what you need.

Example:

```bash
git checkout -b recovery <commit-hash>
```

## 💡 Backend Engineer Tip

Many experienced developers have a simple rule:

> **Before assuming your work is lost, run `git reflog`.**

It has saved countless hours of work after accidental resets, rebases, deleted branches, and detached HEAD mistakes. While it's not a replacement for backups or remote repositories, it's one of the most valuable recovery tools available in Git.
