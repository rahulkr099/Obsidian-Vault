# What is Version Control?

Imagine you're writing a backend API for a Todo application.

At first, everything works perfectly.

Then you add authentication.

Suddenly, nothing works.

So you create copies of your project:

```text
todo-api/
todo-api-final/
todo-api-final-final/
todo-api-final-final-v2/
todo-api-working/
todo-api-working-new/
```

A week later...

You have no idea which folder is the correct one.

This is exactly the problem **Version Control** solves.

---

# Definition

**Version Control** is a system that records changes made to files over time, allowing you to:

- track every change
    
- restore older versions
    
- collaborate with others
    
- know who changed what
    
- experiment safely
    

Git is the world's most popular version control system.

# Centralized Version Control

Older systems used one central server.

```text
Developer A ----\
Developer B ----- Server
Developer C ----/
```

Problems:

- Internet required
    
- Server failure affects everyone
    
- Limited offline work
    

Examples:

- SVN
    
- CVS
    

---

# Distributed Version Control

Git uses a distributed model.

Every developer has a complete copy of the project history.

```text
Developer A
Complete History

Developer B
Complete History

Developer C
Complete History
```

Even if GitHub is unavailable, you can still:

- view history
    
- create commits
    
- create branches
    
- compare versions
    

---

# Git vs GitHub

Many beginners think Git and GitHub are the same.

They are different.

## Git

Git is software installed on your computer.

It manages your project history locally.

Examples:

```bash
git init
git add
git commit
```

Everything above works **without GitHub**.

---

## GitHub

GitHub is a cloud platform that hosts Git repositories.

It allows you to:

- share code
    
- collaborate
    
- review code
    
- manage issues
    
- automate workflows
    

Think of it like this:

```text
Git
↓

Creates history

GitHub
↓

Shares history
```

# What Git Actually Tracks

Git tracks changes in files.

Example:

Before:

```javascript
app.listen(3000);
```

After:

```javascript
app.listen(5000);
```

Git records:

```text
Changed:

3000

↓

5000
```

It doesn't create a new project—it records the change.


# Key Terms

|Term|Meaning|
|---|---|
|Version Control|Keeps history of file changes|
|Repository (Repo)|A project managed by Git|
|Commit|A saved snapshot of your project|
|Branch|A separate line of development|
|Merge|Combining changes from branches|
|Remote|An online copy of your repository (e.g., GitHub)|
|Clone|Download a Git repository|
|Push|Upload local commits to a remote repository|
|Pull|Download changes from a remote repository|

---

# Best Practices

- Commit your work regularly.
    
- Write meaningful commit messages.
    
- Never copy projects into folders like `final-final-v3`.
    
- Keep one Git repository per project.
    
- Learn Git from the terminal before relying on graphical tools.
