# What is Docker Compose?

Docker Compose is a tool for defining and running **multi-container applications**.

Instead of:

```
docker run MongoDB

docker run Redis

docker run Backend

docker run Frontend
```

You write:

```
compose.yaml
```

Then:

```bash
docker compose up
```

Everything starts together.

---

# Networks

Compose automatically creates a network.

Example:

```

```

Meaning:

```

↓

↓
```

# Dependencies

Suppose backend needs MongoDB.

```yaml
depends_on:

  - mongodb
```

Compose starts MongoDB first.

**Important:**

`depends_on` controls startup order **only**. It does **not** guarantee MongoDB is ready to accept connections. Your application should still retry database connections if the database is still starting.

# Complete MERN Example

```yaml
services:

  mongodb:

    image: mongo

    volumes:

      - mongo-data:/data/db

  redis:

    image: redis

  backend:

    build: ./backend

    ports:

      - "5000:5000"

    environment:

      MONGODB_URI: mongodb://mongodb:27017/app

      REDIS_URL: redis://redis:6379

    depends_on:

      - mongodb

      - redis

  frontend:

    build: ./frontend

    ports:

      - "3000:3000"

    depends_on:

      - backend

volumes:

  mongo-data:
```

One file.

Entire stack.

# Best Practices

### One Service Per Container

Good:

```
Backend

MongoDB

Redis
```

Separate responsibilities.

---

### Keep Secrets in `.env`

Don't hardcode credentials in `compose.yaml`.

---

### Use Named Volumes

Especially for databases.

---

### Don't Hardcode IP Addresses

Use service names.

---

### Keep `compose.yaml` Readable

Group related settings together and use comments where helpful.

# Common Mistakes

❌ Using `localhost` between services.

Wrong:

```
mongodb://localhost:27017
```

Correct:

```
mongodb://mongodb:27017
```

---

❌ Forgetting volumes.

Database disappears when the container is removed.

---

❌ Assuming `depends_on` means "ready."

It only controls startup order.

---

❌ Running every service manually.

Compose exists to automate this.

# Production-Ready Example

```yaml
services:
  backend:
    build: ./backend
    ports:
      - "5000:5000"
    environment:
      NODE_ENV: production
      MONGODB_URI: mongodb://mongodb:27017/app
      REDIS_URL: redis://redis:6379
    depends_on:
      - mongodb
      - redis
    restart: unless-stopped

  mongodb:
    image: mongo:8
    volumes:
      - mongo-data:/data/db
    restart: unless-stopped

  redis:
    image: redis:8
    restart: unless-stopped

volumes:
  mongo-data:
```

# 💡 Backend Engineer Insight

In modern backend development, you'll rarely run a single container manually. Most teams keep a `compose.yaml` in the project root so every developer can start the entire development environment with one command:

```bash
docker compose up -d
```

For local development, Docker Compose is often the standard workflow. In production, many organizations move to orchestrators like Kubernetes, but the concepts you learned here—services, networks, volumes, environment variables, and containerized applications—remain the same.
