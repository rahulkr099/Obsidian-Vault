# Docker Architecture

Docker consists of several components working together.

```
                You
                 │
                 ▼
         docker CLI (Client)
                 │
                 ▼
         Docker Engine (Daemon)
          ├─────────────┐
          ▼             ▼
      Images        Containers
          │             │
          └──────┬──────┘
                 ▼
             Host Kernel
```

Each part has a specific responsibility.

---

# 1. Docker CLI (Client)

The CLI is what you interact with.

Example:

```
dockerps
docker run
docker build
docker images
```

The CLI **doesn't** run containers itself.

Instead, it sends requests to the Docker Engine.

---

# 2. Docker Engine (Daemon)

The Docker Engine (`dockerd`) is the brain of Docker.

It is responsible for:

- Building images
- Creating containers
- Starting containers
- Stopping containers
- Managing volumes
- Managing networks

You usually don't interact with it directly.

The CLI communicates with it through a Unix socket:

```
/var/run/docker.sock
```

---

# 3. Images

Images are **read-only templates**.

Example:

```
node:22

ubuntu:24.04

nginx:latest

mongo:8
```

They contain:

- Base filesystem
- Installed software
- Configuration
- Metadata

---

# 4. Containers

Containers are **running instances of images**.

Think of it this way:

```
Image
   │
   ▼
Container
```

One image can create many containers.

Example:

```
node:22
│
├── Container A
├── Container B
└── Container C
```

---

# 5. Docker Registry

A registry stores Docker images.

Popular registries include:

- Docker Hub
- GitHub Container Registry (GHCR)
- Amazon ECR
- Google Artifact Registry

Example:

```
Docker Hub
     │
     ▼
node:22
```

When you run:

```
docker runnode:22
```

Docker downloads the image if it's not already present.

# Installing Docker (Linux Mint / Ubuntu)

Since you're using **Linux Mint**, use the official Docker repository instead of the older distribution package. This ensures you get the latest stable version.

## Step 1 — Remove old packages (if any)

```
sudo apt remove docker docker-engine docker.io containerd runc
```

---

## Step 2 — Update package index

```
sudo apt update
```

---

## Step 3 — Install prerequisites

```
sudo apt install ca-certificatescurl gnupg
```

---

## Step 4 — Create the keyring directory

```
sudo install-m0755-d /etc/apt/keyrings
```

---

## Step 5 — Add Docker's GPG key

```
curl-fsSL <https://download.docker.com/linux/ubuntu/gpg> | \sudo gpg--dearmor-o /etc/apt/keyrings/docker.gpg
```

---

## Step 6 — Add the Docker repository

```
echo \"deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \<https://download.docker.com/linux/ubuntu> \
$(. /etc/os-release && echo${UBUNTU_CODENAME}) stable" | \sudotee /etc/apt/sources.list.d/docker.list > /dev/null
```

---

## Step 7 — Install Docker

```
sudo apt updatesudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

# Run Your First Container

```
sudo docker run hello-world
```

What happens?

1. Docker looks for the `hello-world` image locally.
2. If it's missing, Docker downloads it.
3. Docker creates a container.
4. The container runs.
5. It prints a success message and exits.

---

# Run Docker Without `sudo`

Add your user to the `docker` group:

```
sudo usermod-aG docker"$USER"
```

Then **log out and log back in**, or reboot.

Verify:

```
groups
```

You should see:

```
docker
```

Now this should work:

```
dockerps
```

without `sudo`.

# Docker Root Directory

Docker stores data under:

```
/var/lib/docker
```

It contains:

```
containers/
images/
volumes/
networks/
overlay2/
```

You generally shouldn't modify files here manually.

# Common Installation Problems

## Permission Denied

Example:

```
permission denied while trying to connect to the Docker daemon socket
```

Usually caused by not being in the `docker` group or the Docker service not running.

---

## Docker Service Not Running

Check:

```
systemctl status docker
```

Start it:

```
sudo systemctlstart docker
```

---

## Command Not Found

Example:

```
docker: command not found
```

Verify the installation:

```
which docker
```

If it's not found, revisit the installation steps.

## 💡 Backend Engineer Insight

Whenever you type:

```
docker runnode:22
```

you're triggering a chain of events:

1. The **Docker CLI** sends a request.
2. The **Docker Engine** checks whether the image exists locally.
3. If necessary, it downloads the image from a registry.
4. It creates a writable container from that image.
5. It starts the container's main process.
6. When that process exits, the container stops.

Understanding this flow will make debugging much easier in later lessons.

In **Lesson 3**, we'll dive deeper into **Images, Containers, and Registries**, including image layers, tags, Docker Hub, and how Docker caches builds to make them fast.
