# What is a Network?

A **network** is a collection of devices that communicate with each other.

Examples:

- Laptop ↔ Router
- Phone ↔ Wi-Fi
- Browser ↔ Backend API
- Backend ↔ Database

Simple diagram:

```
Laptop
   │
   ▼
Router
   │
   ▼
Internet
   │
   ▼
Server
```

---

# IP Address

Every device on a network has an address.

Example:

```
192.168.1.15
```

Like a house address.

Without it, data wouldn't know where to go.

---

# Private IP Ranges

```
10.0.0.0/8

172.16.0.0 – 172.31.255.255

192.168.0.0/16
```

These are not directly reachable from the public internet.

---

# Public IP

Assigned by your ISP or cloud provider.

Example:

```
34.120.xxx.xxx
```

Reachable over the internet.

---

# Localhost

```
127.0.0.1
```

Means:

"My own computer."

When you run:

```
<http://localhost:5000>
```

your browser communicates with your own machine.

---

# Hostname

Humans prefer:

```
google.com
```

Computers use:

```
142.250.x.x
```

DNS translates between them.

---

# Ports

One computer can run many services.

Ports identify **which application** should receive incoming traffic.

Example:

```
Computer

│

├── Port 22 → SSH

├── Port 80 → HTTP

├── Port 443 → HTTPS

├── Port 3000 → React Dev Server

├── Port 5000 → Express API

└── Port 27017 → MongoDB
```

---

# Analogy

Think of an apartment building.

```
Building = IP Address

Apartment = Port
```

The delivery person needs **both** the building and apartment number.

---

# Socket

A **socket** is:

```
IP Address + Port
```

Example:

```
127.0.0.1:5000
```

Your Express server listens on a socket.

---

# Packets

Large data isn't sent all at once.

It's split into **packets**.

Example:

```
Large File

↓

Packet 1

Packet 2

Packet 3

Packet 4
```

The receiving device reassembles them.

# Best Practices

### Learn the Flow, Not Just Commands

Understand **why** requests move the way they do.

---

### Think in Layers

Every request passes through multiple components before reaching your code.

---

### Verify Before Assuming

Use tools like:

```bash
ping
doggo
curl
ss
```

to isolate problems.

---

### Keep Local and Production Separate

Your local environment (`localhost`) behaves differently from a public server behind DNS, HTTPS, and firewalls.

# 💡 Senior Backend Engineer Insight

When debugging networking issues, experienced engineers follow a layered approach instead of guessing:

```
Application
      │
      ▼
Is the server running?
      │
      ▼
Is it listening on the correct port?
      │
      ▼
Can localhost reach it?
      │
      ▼
Can another machine reach it?
      │
      ▼
Does DNS resolve correctly?
      │
      ▼
Is the firewall allowing traffic?
      │
      ▼
Is the reverse proxy forwarding correctly?
```

This systematic process helps you identify the exact layer where the problem occurs.
