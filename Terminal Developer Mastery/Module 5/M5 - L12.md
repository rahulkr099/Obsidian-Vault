# Tool 1 — ping

Tests basic network reachability using ICMP (note that some servers intentionally block ICMP).

```bash
ping google.com
```

Example:

```text
64 bytes from ...

time=18 ms
```

Stop:

```text
Ctrl+C
```

---

# Understanding Ping

Output:

```text
Packets Sent

Packets Received

Packet Loss

Average Time
```

Healthy:

```text
0% packet loss
```

High latency:

```text
250 ms
```

Could indicate network congestion or long geographic distance.

---

# Tool 2 — traceroute

Shows every router ("hop") between your computer and the destination.

Install (Ubuntu/Debian):

```bash
sudo apt install traceroute
```

Run:

```bash
traceroute google.com
```

Output:

```text
Hop 1

Hop 2

Hop 3
```

Useful for locating where packets stop.

---

# Tool 3 — mtr

Combines `ping` and `traceroute`.

Install:

```bash
sudo apt install mtr
```

Run:

```bash
mtr google.com
```

Shows:

- Packet loss
    
- Latency
    
- Every hop
    

Excellent for diagnosing intermittent network problems.

---

# Tool 4 — doggo (Your Preferred DNS Tool)

You've already installed **doggo**, so we'll use it instead of `dog`.

Query:

```bash
doggo google.com
```

Specific record:

```bash
doggo A github.com
```

MX record:

```bash
doggo MX gmail.com
```

TXT:

```bash
doggo TXT google.com
```

Reverse lookup:

```bash
doggo -x 8.8.8.8
```

---

# Tool 5 — dig

Still widely available on Linux servers.

```bash
dig google.com
```

Useful sections:

```text
ANSWER SECTION

AUTHORITY SECTION

ADDITIONAL SECTION
```

---

# Tool 6 — nslookup

Simple DNS lookup.

```bash
nslookup github.com
```

Quick verification.

---

# Tool 7 — curl

Probably the most important backend networking tool.

Basic:

```bash
curl https://api.github.com
```

Headers only:

```bash
curl -I https://example.com
```

Verbose:

```bash
curl -v https://example.com
```

Follow redirects:

```bash
curl -L https://example.com
```

POST request:

```bash
curl -X POST \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
http://localhost:5000/users
```

---

# Tool 8 — wget

Download files.

```bash
wget https://example.com/file.zip
```

Useful for:

- Backups
    
- Testing downloads
    
- Mirrors
    

---

# Tool 9 — ss

Modern replacement for `netstat`.

Show listening ports:

```bash
ss -tuln
```

Established connections:

```bash
ss -tan
```

Process information:

```bash
ss -tulpn
```

---

# Tool 10 — lsof

Find which process owns a port.

Example:

```bash
sudo lsof -i :5000
```

Output:

```text
node

PID

5000
```

Extremely useful when a port is already in use.

---

# Tool 11 — netstat

Legacy but still encountered.

```bash
netstat -tulnp
```

Prefer `ss` on modern Linux systems.

---

# Tool 12 — nc (Netcat)

The "Swiss Army knife" of networking.

Test a TCP port:

```bash
nc -vz localhost 5000
```

Output:

```text
Connection succeeded
```

Quickly confirms whether a service is accepting TCP connections.

---

# Tool 13 — OpenSSL

Inspect TLS.

```bash
openssl s_client \
-connect github.com:443
```

Check:

- Certificate
    
- TLS version
    
- Cipher suite
    

---

# Tool 14 — tcpdump

Capture packets.

```bash
sudo tcpdump -i any port 80
```

Capture HTTPS:

```bash
sudo tcpdump -i any port 443
```

Write capture:

```bash
sudo tcpdump -w capture.pcap
```

Open later in Wireshark.

---

# Tool 15 — Wireshark

GUI packet analyzer.

Inspect:

- DNS
    
- TCP
    
- TLS
    
- HTTP
    
- Retransmissions
    
- Packet loss
    

One of the best tools for deep network analysis.

---

# Tool 16 — iperf3

Measure network throughput.

Server:

```bash
iperf3 -s
```

Client:

```bash
iperf3 -c SERVER_IP
```

Shows:

- Bandwidth
    
- Packet retransmissions
    
- Transfer rate
    

---

# Tool 17 — nmap

Port scanner.

Install:

```bash
sudo apt install nmap
```

Scan:

```bash
nmap localhost
```

Specific ports:

```bash
nmap -p 22,80,443 localhost
```

Useful for auditing exposed services that you own or are authorized to test.

# Debugging a MERN Application

Suppose:

```text
https://api.example.com
```

doesn't work.

Step 1:

```bash
doggo api.example.com
```

DNS?

---

Step 2:

```bash
ping api.example.com
```

Reachable? (Remember some servers block ICMP.)

---

Step 3:

```bash
nc -vz api.example.com 443
```

Port open?

---

Step 4:

```bash
curl -v https://api.example.com
```

HTTP?

---

Step 5:

```bash
openssl s_client \
-connect api.example.com:443
```

TLS?

---

Step 6:

```bash
sudo journalctl -u nginx
```

Nginx?

---

Step 7:

```bash
sudo journalctl -u backend
```

Express?

# 🏆 Challenge Project

Your Express API on **port 5000** suddenly stops responding.

Investigate using only terminal tools.

### Requirements

1. Confirm the process is running (`systemctl`, `ps`, or `lsof`).
    
2. Verify port `5000` is listening (`ss`).
    
3. Test local connectivity (`nc`).
    
4. Send requests with `curl -v`.
    
5. Check Nginx logs.
    
6. Check backend logs.
    
7. Verify DNS if using a domain.
    
8. Verify TLS if using HTTPS.
    
9. Benchmark after fixing with `autocannon`.
    
10. Write a short incident report including:
    
    - Root cause
        
    - Evidence
        
    - Fix applied
        
    - Verification steps
        

**Bonus:**

Create a Bash script called `health-check.sh` that:

- Checks if your backend process is running.
    
- Verifies port `5000` is listening.
    
- Sends a `curl` request to `/health`.
    
- Reports **PASS** or **FAIL** for each check.

# 💡 Senior Backend Engineer Insight

Professional backend engineers don't memorize hundreds of commands—they memorize a **debugging sequence**.

```text
        User Reports Problem
                │
                ▼
        Reproduce the Issue
                │
                ▼
        DNS (doggo/dig)
                │
                ▼
        Network (ping/mtr)
                │
                ▼
        Port (ss/nc/lsof)
                │
                ▼
        HTTP (curl)
                │
                ▼
        TLS (openssl)
                │
                ▼
        Reverse Proxy (Nginx Logs)
                │
                ▼
        Application Logs
                │
                ▼
        Database
                │
                ▼
        Root Cause Identified
                │
                ▼
        Fix → Verify → Monitor
```

This structured workflow is far more valuable than memorizing command syntax. It helps you troubleshoot Linux servers, Docker containers, cloud deployments, Kubernetes pods, and production MERN applications with confidence.
