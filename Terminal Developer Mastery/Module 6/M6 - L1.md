# What is Data?

Data is simply **information**.

Example:

```text
Rahul
22
rahul@example.com
9876543210
```

Without organization, data quickly becomes difficult to search, update, and maintain.

---

# What is a Database?

A **database** is an organized collection of data that allows you to:

- Store data
    
- Retrieve data
    
- Update data
    
- Delete data
    
- Search efficiently
    
- Maintain consistency
    

Instead of:

```text
users.txt

Rahul
Aman
Priya
Rohan
```

We use:

```text
Database

↓

Users Table
```

---

# Why Not Store Everything in Files?

Imagine a file:

```text
users.txt

Rahul
Aman
Priya
```

Problems:

❌ Slow searching

❌ Duplicate data

❌ Difficult updates

❌ No relationships

❌ No security

❌ Poor scalability

Databases solve these problems.

# What is a DBMS?

**DBMS = Database Management System**

It is software that manages databases.

Responsibilities:

- Store data
    
- Retrieve data
    
- Security
    
- Backup
    
- Transactions
    
- Concurrency
    
- Query processing
    

Examples:

- PostgreSQL
    
- MySQL
    
- MongoDB
    
- SQLite
    
- Redis

# What is an RDBMS?

**RDBMS = Relational Database Management System**

Data is stored in **tables**.

Example:

```text
Users

+----+--------+-----+
| ID | Name   | Age |
+----+--------+-----+
| 1  | Rahul  | 22  |
| 2  | Aman   | 20  |
+----+--------+-----+
```

Examples:

- PostgreSQL
    
- MySQL
    
- MariaDB
    
- Oracle Database
    
- Microsoft SQL Server

# Data Types

Every column has a type.

Examples:

|Type|Example|

# Primary Key

Every row should have a unique identifier.

Example:


- Not NULL
    
- Identifies one row

Imagine:

```text

```

Instead:

```text

3
```

# SQL vs MongoDB

SQL:

```text
Users Table

ID

Name

Age
```

MongoDB:

```json
{
    "_id": "...",
    "name": "Rahul",
    "age": 22
}
```

Documents don't have to look like tables, though consistent schemas are still a good practice.

---

# SQL vs NoSQL Comparison

|SQL|NoSQL|
|---|---|
|Tables|Documents/Key-Value/Graph/etc.|
|Fixed schema (typically)|Flexible schema (often)|
|JOINs|Embedding or references|
|ACID transactions|Varies by database (many support transactions)|
|Best for structured data|Good for evolving or specialized data models|

# 💡 Senior Backend Engineer Insight

Modern backend systems rarely rely on **just one database**. They often combine multiple technologies, each chosen for its strengths.

```text
                    React
                      │
                      ▼
                 Express API
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
 PostgreSQL        Redis        MongoDB
(Relational)    (Cache/Queue) (Documents)
        │             │             │
 Orders, Users    Sessions      Logs, Analytics
 Payments         Rate Limits   Flexible Data
```

Instead of asking **"Which database is the best?"**, experienced engineers ask:

- Which data model fits this problem?
    
- Do I need strong consistency?
    
- Is the data highly relational?
    
- Will I benefit from caching?
    
- How will this system scale over time?
    

Choosing the right storage technology is an architectural decision that can significantly influence performance, maintainability, and scalability.
