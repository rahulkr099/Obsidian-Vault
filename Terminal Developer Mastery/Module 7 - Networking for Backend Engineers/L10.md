# What is a Network Namespace?

A **network namespace** is an isolated networking environment.

Each namespace has its own:

- Network interfaces
    
- IP addresses
    
- Routing table
    
- ARP table
    
- Firewall rules
    
- Listening ports
    

Think of it as giving each application its own mini computer's networking stack.

---

# Without Namespaces

Imagine every application shared the same network stack.

```text
Host

├── Node App
├── PostgreSQL
├── Redis
└── Nginx
```

Everything shares:

- One routing table
    
- One interface list
    
- One port space
    

This can lead to conflicts.

---

# With Namespaces

Now imagine:

```text
Host

├── Namespace A
│     └── Nginx
│
├── Namespace B
│     └── Redis
│
└── Namespace C
      └── PostgreSQL
```

Each namespace behaves like a separate machine from a networking perspective.

---

# Real Docker Example

Suppose you run:

```bash
docker run nginx
```

Docker creates:

```text
Container

↓

New Network Namespace
```

Inside the container:

```bash
ip addr
```

You might see:

```text
lo

eth0
```

Even though the host already has:

```text
lo

wlp2s0

docker0
```

The container sees only its own interfaces.

---

# Namespace Isolation

Host:

```text
Interfaces

lo

wlp2s0

docker0
```

Container:

```text
Interfaces

lo

eth0
```

The container cannot directly access the host's interfaces unless explicitly configured.

---

# Every Namespace Has Its Own IP

Host:

```text
192.168.1.20
```

Container:

```text
172.17.0.2
```

Another container:

```text
172.17.0.3
```

Each namespace has its own IP address.

---

# Separate Routing Tables

Host routing table:

```text
default via 192.168.1.1
```

Container routing table:

```text
default via 172.17.0.1
```

They are independent.

---

# Separate Listening Ports

Host:

```text
Port 80
```

Container:

```text
Port 80
```

Another container:

```text
Port 80
```

No conflict!

Why?

Because each namespace has its own networking stack.

# Viewing Namespaces

List namespaces:

```bash
ip netns list
```

Example:

```text
ns1

ns2
```

Docker does not normally register its namespaces here automatically, so this command mainly shows namespaces you've created manually.

---

# Create a Namespace

```bash
sudo ip netns add ns1
```

Check again:

```bash
ip netns list
```

Output:

```text
ns1
```

---

# Delete a Namespace

```bash
sudo ip netns delete ns1
```

---

# Execute Commands Inside a Namespace

Example:

```bash
sudo ip netns exec ns1 ip addr
```

Output:

```text
lo
```

Initially, only the loopback interface exists.

---

# Why Can't It Reach the Internet?

A new namespace has:

```text
lo
```

Only.

No Ethernet.

No Wi-Fi.

No default route.

No IP.

It is completely isolated.

---

# Virtual Ethernet (veth)

A **veth pair** acts like a virtual network cable.

```text
vethA

========

vethB
```

Anything sent into one end comes out the other.

---

# One End in Host

```text
Host

↓

veth-host
```

Other end:

```text
Namespace

↓

veth-ns
```

This connects the namespace to the host.

---

# Creating a veth Pair

```bash
sudo ip link add veth-host type veth peer name veth-ns
```

Now you have two connected virtual interfaces.

---

# Move One End into the Namespace

```bash
sudo ip link set veth-ns netns ns1
```

Now:

Host:

```text
veth-host
```

Namespace:

```text
veth-ns
```

---

# Assign IP Addresses

Host:

```bash
sudo ip addr add 10.0.0.1/24 dev veth-host
```

Namespace:

```bash
sudo ip netns exec ns1 ip addr add 10.0.0.2/24 dev veth-ns
```

---

# Bring Interfaces Up

Host:

```bash
sudo ip link set veth-host up
```

Namespace:

```bash
sudo ip netns exec ns1 ip link set lo up
```

```bash
sudo ip netns exec ns1 ip link set veth-ns up
```

Now the interfaces are ready to communicate.

---

# Test Connectivity

From the namespace:

```bash
sudo ip netns exec ns1 ping 10.0.0.1
```

Expected:

```text
64 bytes from 10.0.0.1
```

You now have networking between the namespace and the host.

---

# Linux Bridge

Suppose you create multiple namespaces.

```text
ns1

ns2

ns3
```

Instead of connecting each pair directly:

```text
ns1

↓

Bridge

↑

ns2

↑

ns3
```

Use a Linux bridge.

A bridge acts like a virtual network switch.

---

# Creating a Bridge

```bash
sudo ip link add br0 type bridge
```

Enable it:

```bash
sudo ip link set br0 up
```

---

# Connect veth to the Bridge

```bash
sudo ip link set veth-host master br0
```

Now the namespace is connected to the bridge.

---

# Docker's Bridge

Docker creates:

```text
docker0
```

It is simply a Linux bridge.

Example:

```text
Container A

↓

veth

↓

docker0

↓

veth

↓

Container B
```

Containers communicate through this bridge.

---

# How Docker Networking Works

Suppose:

```bash
docker run nginx
```

Docker performs these steps:

```text
Create Namespace

↓

Create veth Pair

↓

Move One End into Container

↓

Attach Host End to docker0

↓

Assign IP

↓

Configure Route

↓

Start Container
```

All automatically.

## 1. Create a namespace

```bash
sudo ip netns add lab1
```

Verify:

```bash

```

---

## 2. Inspect the namespace

```bash
sudo ip netns exec lab1 ip addr
```

Notice that only `lo` exists.

---

## 3. Create a veth pair

```bash
sudo ip link add veth-host type veth peer name veth-lab
```

---

## 4. Move one end

```bash
sudo ip link set veth-lab netns lab1
```

---

## 5. Configure IPs

Host:

```bash
sudo ip addr add 10.10.10.1/24 dev veth-host
sudo ip link set veth-host up
```

Namespace:

```bash
sudo ip netns exec lab1 ip addr add 10.10.10.2/24 dev veth-lab
sudo ip netns exec lab1 ip link set lo up
sudo ip netns exec lab1 ip link set veth-lab up
```

---

## 6. Test connectivity

```bash
sudo ip netns exec lab1 ping 10.10.10.1
```

If everything is configured correctly, the ping should succeed.

---

## 7. Clean up

```bash
sudo ip netns delete lab1
```

Deleting the namespace removes the interfaces inside it as well.

# Real Backend Example

Imagine you start two Node.js containers:

```bash
docker run -d --name api1 nginx
docker run -d --name api2 nginx
```

Internally:

```text
Host
│
├── docker0 (Bridge)
│
├── vethA ── Namespace(api1)
│             └── eth0 (172.17.0.2)
│
└── vethB ── Namespace(api2)
              └── eth0 (172.17.0.3)
```

Both containers can listen on **port 80** without conflicting because each container has its own network namespace.

# Common Interview Questions

### 1. What is a network namespace?

A network namespace is an isolated networking environment with its own interfaces, IP addresses, routing table, firewall rules, and sockets.

---

### 2. Why does Docker use network namespaces?

Docker uses network namespaces to isolate each container's networking so that containers behave like separate machines.

---

### 3. What is a veth pair?

A veth (Virtual Ethernet) pair is two connected virtual interfaces. Packets entering one interface immediately appear on the other.

---

### 4. What is a Linux bridge?

A Linux bridge is a virtual Layer 2 switch that connects multiple interfaces, allowing them to communicate on the same network.

---

### 5. What is `docker0`?

`docker0` is Docker's default Linux bridge that connects containers to each other and to the host.

---

### 6. Why can multiple containers use port 80?

Because each container has its own network namespace and therefore its own independent port space.

---

# Backend Debugging Tips

If a container cannot reach another container:

1. Check the container's IP:
    
    ```bash
    docker inspect <container-name>
    ```
    
2. Verify the bridge network:
    
    ```bash
    ip link show docker0
    ```
    
3. Check routes inside the container:
    
    ```bash
    docker exec <container-name> ip route
    ```
    
4. Test connectivity:
    
    ```bash
    docker exec <container-name> ping <other-container-ip>
    ```
    

Understanding namespaces and bridges makes these checks much easier to interpret.

# Key Takeaways

- A **network namespace** provides complete network isolation.
    
- Every namespace has its own:
    
    - Interfaces
        
    - IP addresses
        
    - Routing table
        
    - Firewall rules
        
    - Port space
        
- **veth pairs** connect namespaces to the host or a bridge.
    
- A **Linux bridge** acts like a virtual network switch.
    
- Docker builds its default networking using:
    
    - Network namespaces
        
    - veth pairs
        
    - The `docker0` bridge
