# Module 7 — Lesson 11: `iptables` Firewall 🔥

Welcome to Lesson 11!

A server connected to the Internet can receive **millions of network packets** every day.

Not every packet should be allowed.

Some packets should be:

- ✅ Allowed
    
- ❌ Blocked
    
- 🚫 Logged
    
- 🔄 Forwarded
    

The Linux kernel uses a firewall to make these decisions.

One of the oldest and most influential firewall systems on Linux is **iptables**.

> **Note:** Many modern Linux distributions now use **nftables** as the underlying firewall framework, and tools like **UFW** often configure `iptables` or `nftables` behind the scenes depending on the distribution. Learning `iptables` is still valuable because you'll encounter it on many servers, in tutorials, and in interviews.

# What is a Firewall?

A **firewall** decides what network traffic is allowed to enter or leave a system.

Think of it as a security guard.

```text
Internet

↓

Firewall

↓

Linux Server
```

Every packet is checked before it reaches your application.

---

# Why Use a Firewall?

Suppose your server runs:

- SSH → Port 22
    
- Nginx → Port 80
    
- HTTPS → Port 443
    
- PostgreSQL → Port 5432
    

Do you want PostgreSQL accessible from the Internet?

Usually **No**.

Instead:

```text
22     ✓

80     ✓

443    ✓

5432   ✗
```

The firewall blocks unwanted access.

---

# Netfilter

The Linux firewall is implemented by a kernel framework called **Netfilter**.

```text
Internet

↓

Netfilter

↓

Application
```

`iptables` is a user-space tool for configuring Netfilter.

# Packet Flow

Incoming traffic:


# Tables

`iptables` organizes rules into **tables**.

The most common are:

|Table|Purpose|
|---|---|
|`filter`|Allow or block packets|
|`nat`|Network Address Translation|
|`mangle`|Modify packet headers|
|`raw`|Low-level packet processing|

The **filter** table is the default and the one you'll use most often.

---

# Chains

Each table contains **chains**.

The three most important chains are:

|Chain|Purpose|
|---|---|
|`INPUT`|Incoming traffic to this machine|
|`OUTPUT`|Outgoing traffic from this machine|
|`FORWARD`|Traffic passing through this machine|

---

# INPUT Chain

Example:

```text
Internet

↓

INPUT

↓

Node.js Server
```

The `INPUT` chain decides whether incoming packets destined for the local machine are accepted or blocked.

---

# OUTPUT Chain

```text
Node.js

↓

OUTPUT

↓

Internet
```

Used when your server initiates outbound connections.

Example:

- Calling an external API
    
- Downloading updates
    
- Sending email
    

---

# FORWARD Chain

Used when Linux acts as a router.

```text
Network A

↓

FORWARD

↓

Network B
```

Typical uses:

- Routers
    
- VPN gateways
    
- Docker bridge forwarding
    
- Kubernetes nodes
    

---

# Rules

Each chain contains **rules**.

Example:

```text
INPUT

↓

Allow SSH

↓

Allow HTTP

↓

Allow HTTPS

↓

Drop Everything Else
```

Rules are checked **from top to bottom**.

The first matching rule is applied.

---

# Targets

When a rule matches, it performs an action called a **target**.

The most common targets are:

|Target|Meaning|
|---|---|
|`ACCEPT`|Allow the packet|
|`DROP`|Silently discard the packet|
|`REJECT`|Reject and notify the sender|
|`LOG`|Log the packet|

---

# ACCEPT

```text
Packet

↓

Firewall

↓

ACCEPT

↓

Application
```

The packet is allowed.

---

# DROP

```text
Packet

↓

Firewall

↓

DROP

↓

Nothing
```

The sender receives no reply.

This often makes the destination appear unreachable.

---

# REJECT

```text
Packet

↓

Firewall

↓

REJECT

↓

Error Response
```

Unlike `DROP`, the sender receives an immediate failure response.

---

# LOG

```text
Packet

↓

Firewall

↓

LOG

↓

System Log
```

Useful for debugging or security monitoring.

Often combined with another rule, such as `DROP`.

---

# Rule Matching

Suppose the rules are:

```text
1. Allow SSH

2. Allow HTTP

3. Drop Everything
```

Incoming packet:

```text
Port 22
```

Matches Rule 1.

Firewall stops checking further rules.

---

Incoming packet:

```text
Port 80
```

Matches Rule 2.

---

Incoming packet:

```text
Port 5432
```

Matches Rule 3.

Blocked.

---

# Viewing Rules

List rules:

```bash
sudo iptables -L
```

Example:

```text
Chain INPUT

ACCEPT tcp -- anywhere anywhere tcp dpt:ssh

ACCEPT tcp -- anywhere anywhere tcp dpt:http
```

---

# Numeric Output

```bash
sudo iptables -L -n
```

Instead of:

```text
http
```

You'll see:

```text
80
```

This avoids hostname and service-name lookups.

---

# Verbose Output

```bash
sudo iptables -L -v -n
```

Example:

```text
Packets

Bytes

Target

Protocol

Port
```

The packet and byte counters help identify which rules are actually being used.

---

# Add a Rule

Allow SSH:

```bash
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

Explanation:

|Option|Meaning|
|---|---|
|`-A`|Append rule|
|`INPUT`|INPUT chain|
|`-p tcp`|TCP protocol|
|`--dport 22`|Destination port 22|
|`-j ACCEPT`|Jump to ACCEPT target|

---

# Allow HTTP

```bash
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
```

---

# Allow HTTPS

```bash
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
```

---

# Block a Port

Example:

```bash
sudo iptables -A INPUT -p tcp --dport 5432 -j DROP
```

Now PostgreSQL cannot be reached from the network (assuming no earlier rule accepts the traffic).

---

# Delete a Rule

First list rules with numbers:

```bash
sudo iptables -L --line-numbers
```

Example:

```text
1 ACCEPT tcp 22

2 ACCEPT tcp 80

3 DROP tcp 5432
```

Delete Rule 3:

```bash
sudo iptables -D INPUT 3
```

---

# Default Policy

Every chain has a default policy.

View it:

```bash
sudo iptables -L
```

Example:

```text
Chain INPUT (policy ACCEPT)
```

Change the default policy:

```bash
sudo iptables -P INPUT DROP
```

This means:

```text
No matching rule

↓

DROP
```

⚠️ **Be very careful** when changing default policies on a remote server. If you don't first allow SSH (or your management access), you can lock yourself out.

# Common Backend Problems

## Problem 1

Your API isn't reachable.

Check:

```bash
ss -tuln
```

If your app is listening, then inspect the firewall:

```bash
sudo iptables -L -n
```

A firewall rule may be blocking the port.

---

## Problem 2

SSH stopped working.

Possible cause:

```text
INPUT policy DROP
```

without an allow rule for port 22.

---

## Problem 3

Docker networking issues.

Docker automatically creates firewall rules to allow container networking and port publishing.

Listing rules can help identify how Docker has configured packet forwarding.

# `iptables` vs `nftables`

|`iptables`|`nftables`|
|---|---|
|Older interface|Modern replacement|
|Multiple separate tables|Unified rule framework|
|Widely documented|Simpler and more flexible syntax|
|Common in interviews|Default on many modern distributions|

Understanding `iptables` makes learning `nftables` much easier.

---

# Common Interview Questions

### 1. What is `iptables`?

`iptables` is a user-space utility used to configure the Linux kernel's Netfilter firewall.

---

### 2. What is Netfilter?

Netfilter is the Linux kernel framework that filters, modifies, and forwards network packets.

---

### 3. What is the difference between `INPUT`, `OUTPUT`, and `FORWARD`?

|Chain|Purpose|
|---|---|
|`INPUT`|Incoming packets destined for the local machine|
|`OUTPUT`|Outgoing packets generated by the local machine|
|`FORWARD`|Packets routed through the machine|

---

### 4. What is the difference between `DROP` and `REJECT`?

- **DROP:** Silently discards the packet.
    
- **REJECT:** Rejects the packet and sends an error response to the sender.
    

---

### 5. Why are rule order and default policies important?

Rules are evaluated from top to bottom, and the first matching rule is applied. If no rule matches, the chain's default policy determines whether the packet is accepted or dropped.

---

# Essential `iptables` Commands Cheat Sheet

|Command|Purpose|
|---|---|
|`sudo iptables -L`|List firewall rules|
|`sudo iptables -L -n`|List rules with numeric ports/IPs|
|`sudo iptables -L -v -n`|Verbose rule listing with counters|
|`sudo iptables -L --line-numbers`|Show numbered rules|
|`sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT`|Allow SSH|
|`sudo iptables -D INPUT <number>`|Delete a rule by number|
|`sudo iptables -P INPUT DROP`|Set default INPUT policy|

# Key Takeaways

- A **firewall** controls which network traffic is allowed or blocked.
    
- **Netfilter** is the Linux kernel's packet-filtering framework.
    
- **`iptables`** configures Netfilter.
    
- The most important chains are:
    
    - `INPUT`
        
    - `OUTPUT`
        
    - `FORWARD`
        
- Common targets include:
    
    - `ACCEPT`
        
    - `DROP`
        
    - `REJECT`
        
    - `LOG`
        
- Rules are processed **top to bottom**, and the **first match wins**.
    
- Always be cautious when modifying firewall rules on remote systems.
