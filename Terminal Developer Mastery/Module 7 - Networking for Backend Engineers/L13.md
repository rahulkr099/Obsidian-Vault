# What is Packet Capture?

Every message sent across a network is broken into **packets**.

For example:

```text
Browser

↓

HTTP Request

↓

TCP Packets

↓

Network

↓

Server
```

Packet capture lets you inspect those packets as they travel.

---

# What is `tcpdump`?

`tcpdump` is a command-line tool that captures and displays network packets.

Think of it as a **network microscope**.

Instead of guessing what is happening, you can see the actual traffic.

---

# Where Does `tcpdump` Capture?

It listens on a network interface.

```text
Internet

↓

Network Interface

↓

tcpdump

↓

Linux Kernel

↓

Application
```

It can capture packets before they reach your application.

# List Interfaces

Before capturing, identify the interface:

```bash
ip link
```

Example:

```text
1: lo
2: wlp2s0
3: docker0
```

Common choices:

|Interface|Purpose|
|---|---|
|`lo`|Localhost traffic|
|`eth0` / `enp...`|Ethernet|
|`wlp...`|Wi-Fi|
|`docker0`|Docker bridge|

---

# Capture All Packets

```bash
sudo tcpdump
```

This starts capturing on the default interface.

Example output:

```text
12:30:01 IP 192.168.1.20.52344 > 142.250.183.206.443: Flags [S]
```

Press:

```text
Ctrl + C
```

to stop.

---

# Capture on a Specific Interface

Example:

```bash
sudo tcpdump -i wlp2s0
```

Loopback:

```bash
sudo tcpdump -i lo
```

Docker:

```bash
sudo tcpdump -i docker0
```

---

# Don't Resolve Names

By default, `tcpdump` tries to resolve IP addresses and service names.

Use:

```bash
sudo tcpdump -n
```

Example:

Without `-n`:

```text
google.com:https
```

With `-n`:

```text
142.250.xxx.xxx:443
```

This is faster and usually preferred for debugging.

---

# Capture Only TCP

```bash
sudo tcpdump -i wlp2s0 tcp
```

Only TCP packets will be displayed.

# Capture Only UDP

```bash
sudo tcpdump -i wlp2s0 udp
```

# Capture DNS Traffic

DNS usually uses port **53**.

```bash
sudo tcpdump -i wlp2s0 port 53
```

Example:

```text
Client

↓

DNS Query

↓

Resolver
```

Try this while running:

```bash
dig google.com
```

You'll see the DNS request and response.

# Capture HTTP Traffic

HTTP uses:

```text
80
```

Capture:

```bash
sudo tcpdump -i wlp2s0 port 80
```

---

# Capture HTTPS Traffic

HTTPS:

```text
443
```

Capture:

```bash
sudo tcpdump -i wlp2s0 port 443
```

> **Important:** `tcpdump` can capture encrypted HTTPS packets, but it **cannot decrypt** the HTTPS payload by itself. You'll still be able to see metadata such as IP addresses, ports, and TCP flags.

# Capture Traffic for One Host

Example:

```bash

```

Only packets to or from:

```text
8.8.8.8
```

---

# Capture Source Host

```bash

```

Only packets originating from that host.

---

# Capture Destination Host

```bash
sudo tcpdump dst host 192.168.1.20
```

Only packets going to that destination.

---

# Capture One Port

Example:

```bash

```

Useful for Express applications.

---

# Capture Multiple Ports

```bash
sudo tcpdump 'port 80 or port 443'
```

Notice the quotes to prevent the shell from interpreting the expression.

---

# Filter by Network

Example:

```bash
sudo tcpdump net 192.168.1.0/24
```

Capture only traffic for that subnet.

---

# Read Packet Output

Example:

```text
12:15:20.123456 IP 192.168.1.20.50000 > 192.168.1.30.3000: Flags [S]
```

Breakdown:

|Part|Meaning|
|---|---|
|`12:15:20`|Timestamp|
|`IP`|Protocol family|
|`192.168.1.20.50000`|Source IP and port|
|`>`|Direction|
|`192.168.1.30.3000`|Destination IP and port|
|`Flags [S]`|TCP SYN packet|

---

# TCP Flags

Common TCP flags:

|Flag|Meaning|
|---|---|
|`S`|SYN (start connection)|
|`SA`|SYN-ACK|
|`A`|ACK|
|`F`|FIN (close connection)|
|`R`|RST (reset connection)|
|`P`|PSH (push data)|

---

# TCP Three-Way Handshake

When a browser connects to your server:

```text
Client

↓

SYN

↓

Server

↓

SYN-ACK

↓

Client

↓

ACK
```

In `tcpdump`, you'll see:

```text
Flags [S]

Flags [S.]

Flags [.]
```

The dot (`.`) represents the ACK flag.

---

# Save Capture to a File

Instead of printing packets:

```bash
sudo tcpdump -w capture.pcap
```

This creates:

```text
capture.pcap
```

A `.pcap` file can later be analyzed using tools like Wireshark.

---

# Read a Saved Capture

```bash
sudo tcpdump -r capture.pcap
```

---

# Limit Number of Packets

Capture only 20 packets:

```bash
sudo tcpdump -c 20
```

Very useful during testing.

---

# Increase Detail

```bash
sudo tcpdump -vv
```

Even more detail:

```bash
sudo tcpdump -vvv
```

```text
ACK

↓
```

# Common Debugging Scenarios

## Problem 1: API Not Reachable

Check:

```bash
sudo tcpdump port 3000
```

If **no packets appear**, the request isn't reaching the server.

Possible causes:

- Wrong IP address
    
- Firewall blocking traffic
    
- Client sending to the wrong host
    

---

## Problem 2: DNS Failure

```bash
sudo tcpdump port 53
```

No DNS packets?

Possible issues:

- DNS server misconfiguration
    
- Network connectivity problem
    

---

## Problem 3: TCP Handshake Never Completes

You see:

```text
SYN

SYN

SYN
```

but never:

```text
SYN-ACK
```

Possible causes:

- Server is down
    
- Firewall is blocking traffic
    
- Wrong destination IP

# Common Interview Questions

### 1. What is `tcpdump`?

`tcpdump` is a command-line packet analyzer used to capture and inspect network traffic on Linux.

---

### 2. Why use `-n`?

`-n` disables DNS and service-name resolution, making captures faster and easier to read.

---

### 3. What is a `.pcap` file?

A `.pcap` file stores captured network packets for later analysis.

---

### 4. Can `tcpdump` read HTTPS data?

It can capture HTTPS packets, but it cannot decrypt encrypted HTTPS payloads by itself.

---

### 5. How do you capture traffic for port 3000?

```bash
sudo tcpdump -i any port 3000
```

Using `-i any` captures packets across all interfaces, which is often convenient when you're unsure which interface the traffic uses.

# Essential `tcpdump` Commands Cheat Sheet

|Command|Purpose|
|---|---|
|`tcpdump`|Start capturing packets|
|`tcpdump -i <iface>`|Capture on a specific interface|
|`tcpdump -n`|Disable name resolution|
|`tcpdump tcp`|Capture TCP traffic|
|`tcpdump udp`|Capture UDP traffic|
|`tcpdump port 53`|Capture DNS traffic|
|`tcpdump port 3000`|Capture traffic on port 3000|
|`tcpdump host <IP>`|Capture traffic to/from a host|
|`tcpdump -c 20`|Stop after 20 packets|
|`tcpdump -w file.pcap`|Save packets to a file|
|`tcpdump -r file.pcap`|Read a saved capture|
|`tcpdump -vv`|Display more packet details|

---

# Key Takeaways

- `tcpdump` lets you inspect network packets directly from the command line.
    
- Always identify the correct interface before capturing traffic.
    
- The `-n` option speeds up captures by disabling name resolution.
    
- You can filter traffic by interface, host, network, protocol, or port.
    
- `.pcap` files allow captures to be saved and analyzed later.
    
- Watching the TCP handshake (`SYN → SYN-ACK → ACK`) is a fundamental debugging technique.
    
- `tcpdump` is one of the most important tools for diagnosing backend networking problems.
