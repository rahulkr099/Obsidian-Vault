# What is `ping`?

`ping` checks whether another machine is reachable over a network.

It also measures:

- Round-trip time (RTT)
    
- Packet loss
    
- Network stability
    

Example:

```text
Laptop

↓

ping

↓

Server
```

---

# How `ping` Works

`ping` uses the **ICMP (Internet Control Message Protocol)**.

Flow:

```text
Laptop

↓

ICMP Echo Request

↓

Server

↓

ICMP Echo Reply

↓

Laptop
```

If the reply comes back, the destination is reachable.

---

# Basic Syntax

```bash
ping google.com
```

Example output:

```text
64 bytes from 142.250.xxx.xxx: icmp_seq=1 ttl=116 time=18.2 ms
```

The command keeps running until you stop it with:

```text
Ctrl + C
```

---

# Understanding the Output

Example:

```text
64 bytes from 142.250.183.206: icmp_seq=5 ttl=116 time=21.4 ms
```

|Field|Meaning|
|---|---|
|`64 bytes`|Size of reply|
|`icmp_seq=5`|Packet sequence number|
|`ttl=116`|Remaining Time To Live|
|`time=21.4 ms`|Round-trip latency|

---

# Round-Trip Time (RTT)

RTT measures the time taken for a packet to travel:

```text
Your Computer

↓

Server

↓

Back

↓

Your Computer
```

Measured in:

```text
Milliseconds (ms)
```

Typical values:

|RTT|Interpretation|
|---|---|
|1–5 ms|Same machine or LAN|
|10–30 ms|Nearby city|
|30–80 ms|Same country|
|100–250 ms|Different continent|
|300+ ms|Slow or congested network|

---

# Packet Loss

Example summary:

```text
10 packets transmitted

10 received

0% packet loss
```

Good.

Another example:

```text
10 transmitted

8 received

20% packet loss
```

Not good.

Packet loss may indicate:

- Wi-Fi interference
    
- Congested network
    
- Firewall filtering ICMP
    
- Hardware problems
    

---

# Limit Number of Pings

Instead of running forever:

```bash
ping -c 4 google.com
```

Example:

```text
4 packets transmitted

4 received
```

Very useful in scripts.

---

# Flood Ping

```bash
sudo ping -f 192.168.1.1
```

Sends packets as fast as possible.

Primarily used for stress testing or diagnosing performance problems.

⚠️ Use only on systems and networks you own or are authorized to test.

# Ping Localhost

```bash
ping localhost
```

or

```bash
ping 127.0.0.1
```

Expected latency:

```text
<1 ms
```

If this fails, there's likely a problem with the local networking stack.

---

# Ping Your Router

Example:

```bash
ping 192.168.1.1
```

Checks:

- Wi-Fi/Ethernet
    
- Local network
    
- Router connectivity
    

---

# Ping a Public IP

Example:

```bash
ping 8.8.8.8
```

If this works but:

```bash
ping google.com
```

fails,

the problem is probably **DNS**, not Internet connectivity.

---

# What is TTL?

TTL stands for:

```text
Time To Live
```

It limits how many routers a packet can pass through.

Example:

```text
TTL = 64
```

Each router decreases TTL by 1.

Example:

```text
Computer

↓

Router

TTL 64 → 63

↓

Router

63 → 62

↓

Destination
```

If TTL reaches 0, the packet is discarded.

This prevents packets from looping forever.

---

# What is `traceroute`?

`traceroute` discovers the path packets take through the network.

Example:

```text
Laptop

↓

Router

↓

ISP

↓

Regional Router

↓

Google
```

It shows each intermediate hop.

---

# Basic Syntax

```bash
traceroute google.com
```

Example output:

```text
1 192.168.1.1

2 ISP Gateway

3 Regional Router

...

10 google.com
```

Each numbered line represents one router (hop).

---

# How `traceroute` Works

It sends packets with increasing TTL values.

Example:

Packet 1:

```text
TTL = 1
```

Dies at:

```text
Router 1
```

Packet 2:

```text
TTL = 2
```

Dies at:

```text
Router 2
```

Packet 3:

```text
TTL = 3
```

Dies at:

```text
Router 3
```

Eventually:

```text
Destination reached
```

This reveals the complete route.

---

# Reading `traceroute`

Example:

```text
1 192.168.1.1

2 10.5.0.1

3 103.21.x.x

4 142.250.x.x
```

Interpretation:

- Hop 1 → Home router
    
- Hop 2 → ISP
    
- Hop 3 → Internet backbone
    
- Hop 4 → Destination
    

---

# What Does `* * *` Mean?

Example:

```text
7 * * *
```

Possible reasons:

- Router blocks traceroute probes
    
- Firewall
    
- Rate limiting
    
- Temporary network issue
    

It doesn't always mean the path is broken.

---

# What is `tracepath`?

`tracepath` is similar to `traceroute`.

Advantages:

- Usually doesn't require root privileges
    
- Simpler output
    
- Automatically discovers path MTU
    

Example:

```bash
tracepath google.com
```

---

# Path MTU Discovery

Different networks support different maximum packet sizes.

Example:

```text
1500 bytes

↓

1400 bytes

↓

1300 bytes
```

`tracepath` helps identify the largest packet size that can traverse the path without fragmentation.

---

# Compare the Tools

|Tool|Purpose|
|---|---|
|`ping`|Reachability + latency|
|`traceroute`|Discover packet path|
|`tracepath`|Discover path + MTU|

# Backend Debugging Workflow

Suppose:

```text
Frontend

↓

Backend API

↓

Database
```

API unreachable.

Step 1:

```bash
ping api.example.com
```

Reachable?

---

Step 2:

```bash
traceroute api.example.com
```

Find where packets stop.

---

Step 3:

```bash
ss -tuln
```

Check if the service is listening.

---

Step 4:

```bash
sudo tcpdump port 443
```

See whether packets actually arrive.

---

Step 5:

```bash
sudo nft list ruleset
```

Inspect firewall rules.

This layered approach helps isolate whether the issue is DNS, routing, firewall, or the application itself.

# Real Backend Example

Suppose your Express API is deployed at:

```text
api.myapp.com
```

Users report:

```text
The API is down.
```

You investigate:

```bash
ping api.myapp.com
```

Works.

Then:

```bash
ss -tuln | grep 443
```

Nothing is listening.

Conclusion:

The **network is healthy**, but the web server or application is not running on port 443.

# Common Interview Questions

### 1. What protocol does `ping` use?

`ping` uses the Internet Control Message Protocol (ICMP), specifically Echo Request and Echo Reply messages.

---

### 2. What is RTT?

RTT (Round-Trip Time) is the total time taken for a packet to travel to the destination and back.

---

### 3. What is TTL?

TTL (Time To Live) limits the number of network hops a packet can traverse before it is discarded.

---

### 4. How does `traceroute` work?

`traceroute` sends packets with gradually increasing TTL values to reveal each router along the path to the destination.

---

### 5. When would you use `tracepath`?

Use `tracepath` when you want to examine the network path or discover the path MTU, especially on systems where `traceroute` requires elevated privileges.

|---|---|
|`ping google.com`|Check connectivity|
|`ping -c 4 google.com`|Send 4 ICMP requests|
|`ping localhost`|Test local networking|
|`ping 8.8.8.8`|Test Internet connectivity|

|`tracepath google.com`|Show routing path and path MTU|

# Key Takeaways

- `ping` verifies connectivity and measures latency using ICMP.
    
- RTT indicates how responsive a network path is.
    
- Packet loss often points to congestion, hardware problems, or filtering.
    
- TTL prevents packets from looping indefinitely.
    
- `traceroute` maps the routers between your machine and the destination.
    
- `tracepath` provides similar functionality and can also reveal path MTU.
    
- Combining `ping`, `traceroute`, `ss`, `tcpdump`, and firewall inspection creates a powerful troubleshooting workflow.
