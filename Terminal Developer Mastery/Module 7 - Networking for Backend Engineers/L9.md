# What is a Socket?

A **socket** is one endpoint of a network communication.

Think of it as a telephone line.

Example:

```text
Browser

↓

Socket

↓

Express Server
```

Both the browser and the server have their own sockets.

Communication happens between these sockets.

---

# Real Example

Suppose your Express server runs on:

```javascript
app.listen(5000);
```

Your browser opens:

```text
http://localhost:5000
```

Connection:

```text
Browser Socket

↓

TCP

↓

Server Socket
```

The socket allows both sides to send and receive data.

---

# A Socket is Identified By

A TCP socket is commonly identified by:

```text
IP Address

+

Port

+

Protocol
```

Example:

```text
192.168.1.20:5000
```

Protocol:

```text
TCP
```

---

# Server Socket vs Client Socket

Server:

```text
Express

↓

Listening

↓

Port 5000
```

Client:

```text
Browser

↓

Random Port

↓

Connects
```

The client usually uses a temporary **ephemeral port** assigned by the operating system.

Example:

```text
Browser

192.168.1.20:52341

↓

Server

192.168.1.30:5000
```

---

# Socket States

Sockets can be in different states.

The most important ones are:

- LISTEN
    
- ESTABLISHED
    
- TIME-WAIT
    
- CLOSE-WAIT
    

We'll cover each.

---

# LISTEN

A server waiting for incoming connections.

Example:

```text
Express

↓

LISTEN

↓

5000
```

The server is ready but no client is connected yet.

---

# ESTABLISHED

An active connection exists.

Example:

```text
Browser

↓

TCP Connection

↓

Express
```

Both sides can exchange data.

---

# TIME-WAIT

The connection has been closed, but the operating system waits briefly before fully releasing the socket.

Why?

To ensure delayed packets from the old connection are discarded.

This is a normal TCP behavior.

---

# CLOSE-WAIT

The remote side has closed the connection, but the local application hasn't finished closing its side yet.

Seeing many sockets stuck in `CLOSE-WAIT` may indicate an application bug where sockets aren't being closed properly.

---

# The `ss` Command

Basic usage:

```bash
ss
```

Shows active sockets.

Usually you'll use options to filter the output.

---

# Show Listening Ports

```bash
ss -l
```

Example:

```text
State   Local Address:Port

LISTEN  0.0.0.0:22

LISTEN  127.0.0.1:5432
```

Meaning:

- SSH listens on port 22
    
- PostgreSQL listens on port 5432
    

---

# Show TCP Listening Ports

```bash
ss -tl
```

Only TCP listening sockets.

---

# Show UDP Listening Ports

```bash
ss -ul
```

Only UDP sockets.

---

# The Most Important Command

```bash
ss -tuln
```

This is one of the most frequently used Linux networking commands.

Meaning:

```text
-t

TCP

-u

UDP

-l

Listening

-n

Numeric output
```

Example:

```text
Netid State   Local Address:Port

tcp   LISTEN  0.0.0.0:22

tcp   LISTEN  127.0.0.1:5432

tcp   LISTEN  0.0.0.0:3000
```

---

# Why Use `-n`?

Without `-n`:

```text
https
```

With `-n`:

```text
443
```

Numeric output is:

- Faster
    
- Easier to debug
    
- Avoids DNS/service-name lookups
    

---

# Understanding the Output

Example:

```text
tcp

LISTEN

0.0.0.0:3000
```

Meaning:

Protocol:

```text
TCP
```

State:

```text
LISTEN
```

Address:

```text
0.0.0.0
```

Port:

```text
3000
```

---

# What Does `0.0.0.0` Mean?

Suppose:

```text
0.0.0.0:5000
```

It means:

> Listen on **all IPv4 network interfaces**.

Example:

```text
lo

wlp2s0

docker0

↓

Express
```

The server accepts connections through any interface (subject to firewall rules).

---

# What About `127.0.0.1`?

Example:

```text
127.0.0.1:5000
```

Only local applications can connect.

Other computers cannot.

---

# View Active Connections

```bash
ss -t
```

Example:

```text
ESTAB

192.168.1.20:5000

192.168.1.30:52341
```

This shows an active TCP connection.

---

# Show Processes

```bash
sudo ss -tp
```

Example:

```text
ESTAB

users:(("node",pid=5432,fd=20))
```

Now you know:

- Process
    
- PID
    
- File descriptor
    

---

# Show Listening Processes

```bash
sudo ss -tulpn
```

This is one of the best commands for backend debugging.

Example:

```text
LISTEN

0.0.0.0:3000

users:(("node",pid=4321))
```

Now you know exactly which process owns the port.

---

# Socket Summary

```bash
ss -s
```

Example:

```text
Total: 350

TCP: 120

UDP: 18
```

Useful for getting a quick overview of socket usage.

---

# Filter by Port

Suppose your API uses:

```text
5000
```

Run:

```bash
ss -tuln | grep 5000
```

Example:

```text
tcp LISTEN 0.0.0.0:5000
```

This confirms the service is listening.

---

# Filter by State

Show only established connections:

```bash
ss state established
```

Show only listening sockets:

```bash
ss state listening
```

---

# Real Backend Example

Suppose:

```javascript
app.listen(5000);
```

Check:

```bash
ss -tuln
```

Output:

```text
LISTEN

0.0.0.0:5000
```

Good.

Now open:

```text
http://localhost:5000
```

Run:

```bash
ss -tp
```

Output:

```text
ESTAB

127.0.0.1:5000

127.0.0.1:53780

users:(("node"))
```

You can see the browser connected to your Node.js server.

# Common Backend Debugging

## Problem 1

Browser says:

```text
Connection Refused
```

Check:

```bash
ss -tuln
```

No port 5000?

Your application probably isn't running or isn't listening on the expected port.

---

## Problem 2

Port already in use.

Start Express:

```text
Error:

EADDRINUSE
```

Check:

```bash
sudo ss -tulpn | grep 5000
```

Another process already owns the port.

---

## Problem 3

API works locally but not from another computer.

Check:

```bash
ss -tuln
```

If you see:

```text
127.0.0.1:5000
```

The server is listening only on the loopback interface.

To allow LAN access, your application should listen on an appropriate address such as `0.0.0.0` (while also considering firewall and security requirements).

|`ss`|`netstat`|
|---|---|
|Modern|Legacy|
|Faster|Slower|
|Default on most Linux distributions|May require installing `net-tools`|
|More detailed|Less detailed|

# Common Interview Questions

### 1. What is a socket?

A socket is one endpoint of a network communication between two applications.

---

### 2. What is the difference between LISTEN and ESTABLISHED?

|LISTEN|ESTABLISHED|
|---|---|
|Waiting for incoming connections|Active connection between two endpoints|

---

### 3. What does `ss -tuln` do?

It displays all listening TCP and UDP sockets using numeric addresses and port numbers.

---

### 4. What does `0.0.0.0:5000` mean?

The application is listening on port `5000` on **all IPv4 network interfaces**.

---

### 5. Why use `sudo ss -tulpn`?

It shows the process names and PIDs associated with listening sockets, making it easier to identify which application owns a port.

# Essential `ss` Commands Cheat Sheet

|Command|Purpose|
|---|---|
|`ss`|Show sockets|
|`ss -l`|Listening sockets|
|`ss -t`|TCP sockets|
|`ss -u`|UDP sockets|
|`ss -tuln`|Listening TCP/UDP sockets (numeric)|
|`sudo ss -tulpn`|Listening sockets with owning processes|
|`ss -tp`|TCP connections with process information|
|`ss -s`|Socket summary|
|`ss state established`|Established connections only|
|`ss state listening`|Listening sockets only|

# Key Takeaways

- A **socket** is one endpoint of a network connection.
    
- **Servers** create listening sockets; **clients** create outbound sockets.
    
- The most important socket states are:
    
    - `LISTEN`
        
    - `ESTABLISHED`
        
    - `TIME-WAIT`
        
    - `CLOSE-WAIT`
        
- `ss` is the modern tool for inspecting sockets.
    
- `ss -tuln` is one of the most useful commands for backend engineers.
    
- `sudo ss -tulpn` helps identify which process is using a specific port.
    
- Knowing how to read socket information is essential for debugging APIs and servers.
