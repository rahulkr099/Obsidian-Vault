# Lesson 7 — Location Blocks

This is one of the **most important Nginx lessons**.

When a request reaches a **Server Block**, Nginx must answer another question:

> **"Which rule inside this server block should handle this URL?"**

The answer is **Location Blocks**.

Almost every production Nginx configuration uses them.

# Where Do Location Blocks Fit?

A request goes through two stages.

```text
Incoming Request
       │
       ▼
Server Block Selected
       │
       ▼
Location Block Selected
       │
       ▼
Serve File / Proxy / Redirect
```

Server Block decides:

> Which website?

Location Block decides:

> What should happen for this URL?

---

# What is a Location Block?

A location block tells Nginx:

> "When this URL is requested, perform these actions."

Basic syntax:

```nginx
location / {

}
```

General form:

```nginx
location <modifier> <pattern> {

    directives...

}
```

---

# Example Website

Imagine your website:

```text
example.com

├── /
├── /images
├── /css
├── /js
├── /api
├── /downloads
└── /admin
```

Each path can behave differently.

# Simple Location

```nginx
location / {

    root /var/www/html;

}
```

Meaning:

For every request beginning with `/`, serve files from:

```text
/var/www/html
```

---

Browser requests:

```text
GET /
```

Nginx:

```text
location /

↓

Serve Homepage
```

---

Request:

```text
GET /about.html
```

Nginx:

```text
location /

↓

Serve about.html
```

# Location Matching Types

Nginx supports several matching methods.

|Type|Example|
|---|---|
|Prefix|`location /images/`|
|Exact|`location = /login`|
|Regex|`location ~ \.php$`|
|Case-insensitive Regex|`location ~* .(jpg|
|Prefix (no regex override)|`location ^~ /static/`|

We'll learn each.

---

# 1. Prefix Matching

The most common type.

Example:

```nginx
location /images/ {

}
```

Meaning:

Any URL starting with:

```text
/images/
```

Examples:

```text
/images/logo.png

/images/photo.jpg

/images/icons/menu.svg
```

All match.

---

Another example:

```nginx
location /api/ {

}
```

Matches:

```text
/api/users

/api/login

/api/products
```

---

# Longest Prefix Wins

Suppose:

```nginx
location / {

}
```

and

```nginx
location /api/ {

}
```

Request:

```text
/api/users
```

Matches both.

Which one wins?

```text
/api/
```

because it is the **longest matching prefix**.

---

Example:

```nginx
location / {

}

location /images/ {

}

location /images/icons/ {

}
```

Request:

```text
/images/icons/logo.svg
```

Chosen location:

```text
/images/icons/
```

because it's the most specific prefix.

---

# 2. Exact Matching

Syntax:

```nginx
location = /login {

}
```

The `=` means:

Only this exact path.

Matches:

```text
/login
```

Does NOT match:

```text
/login/

/login/user
```

---

Example:

```nginx
location = /robots.txt {

}
```

Only:

```text
/robots.txt
```

---

# Why Use Exact Matching?

It is faster because Nginx doesn't need additional pattern checks.

Common examples:

```text
/favicon.ico

/robots.txt

/health

/login
```

---

# 3. Regular Expression Matching

Regex allows advanced pattern matching.

Syntax:

```nginx
location ~ \.php$ {

}
```

Meaning:

Any URL ending with:

```text
.php
```

Examples:

```text
index.php

login.php

admin.php
```

---

Another example:

```nginx
location ~ \.txt$ {

}
```

Matches:

```text
notes.txt

readme.txt
```

---

# Case-Insensitive Regex

Use:

```nginx
location ~* \.(jpg|png|gif)$ {

}
```

The `~*` means:

Ignore uppercase/lowercase.

Matches:

```text
photo.JPG

logo.Png

banner.GIF
```

---

Without `*`:

```nginx
location ~ \.jpg$ {

}
```

Would **not** match:

```text
PHOTO.JPG
```

---

# 4. `^~` Prefix Matching

Example:

```nginx
location ^~ /static/ {

}
```

Meaning:

If this prefix matches:

Don't check regex locations afterward.

Useful for:

- CSS
    
- JavaScript
    
- Images
    
- Static assets
    

It improves efficiency when you know regex rules shouldn't apply.

---

# Location Matching Priority

This is a favorite interview question.

Suppose:

```nginx
location = /login {

}
```

```nginx
location / {

}
```

```nginx
location /api/ {

}
```

```nginx
location ~ \.php$ {

}
```

Which one wins?

The order is:

```text
1. Exact (=)

↓

2. ^~

↓

3. Longest Prefix

↓

4. Regular Expressions (~, ~*)

↓

5. Default Prefix (/)
```

Remember this order.

location /images/ {

Request:

```text
/images/logo.png
```

Result:

```text
/images/
```

# Example 2

Configuration:

```nginx
location = /login {

}

location / {

}
```

Request:

```text
/login
```

Result:

```text
Exact Match
```

---

# Example 3

Configuration:

```nginx
location ~ \.jpg$ {

}

location /images/ {

}
```

Request:

```text
/images/photo.jpg
```

Nginx first finds the longest prefix (`/images/`), but because it isn't marked with `^~`, it then evaluates regex locations. The regex `~ \.jpg$` matches, so **the regex location is selected**.

If the prefix were:

```nginx
location ^~ /images/ {

}
```

then the regex would be skipped, and `/images/` would handle the request.

# URI Handling

Suppose:

```nginx
location /downloads/ {

    root /var/www/files;

}
```

Request:

```text
/downloads/resume.pdf
```

Nginx looks for:

```text
/var/www/files/downloads/resume.pdf
```

Notice that the request path is appended to the `root` directory.

---

# `root` vs `alias`

This is another popular interview topic.

### Using `root`

```nginx
location /images/ {

    root /var/www;
}
```

Request:

```text
/images/logo.png
```

Nginx reads:

```text
/var/www/images/logo.png
```

The location path remains part of the filesystem path.

---

### Using `alias`

```nginx
location /images/ {

    alias /var/www/assets/;
}
```

Request:

```text
/images/logo.png
```

Nginx reads:

```text
/var/www/assets/logo.png
```

The matched location (`/images/`) is **replaced** by the alias path.

---

## Comparison

|Request|`root /var/www;`|`alias /var/www/assets/;`|
|---|---|---|
|`/images/logo.png`|`/var/www/images/logo.png`|`/var/www/assets/logo.png`|

Use `root` when the URL structure matches the directory structure.

Use `alias` when they are different.

# Nested Locations

Nginx allows nested location blocks in limited cases, but they can make configurations harder to read and maintain.

Instead of:

```nginx
location /api/ {

    location /admin/ {

    }

}
```

Prefer separate location blocks:

```nginx
location /api/ {

}
```

```nginx
location /api/admin/ {

}
```

This is clearer and follows common production practices.

---

# Real Production Example

```nginx
server {

    listen 80;

    server_name example.com;

    location / {

        root /var/www/html;

    }

    location /images/ {

        expires 30d;

    }

    location /api/ {

        proxy_pass http://localhost:3000;

    }

    location = /health {

        return 200 "OK";

    }

}
```

Different URLs perform different tasks.

# Common Mistakes

## Missing Trailing Slash

```nginx
location /images {

}
```

and

```nginx
location /images/ {

}
```

These are different.

Be consistent, especially when working with directories.

---

## Confusing `root` and `alias`

Many beginners accidentally use:

```nginx
alias /var/www;
```

when they actually need:

```nginx
root /var/www;
```

Always think about the final filesystem path.

---

## Too Many Regex Locations

Regex is powerful but slower than simple prefix matching.

Prefer prefix locations whenever possible.

---

# Best Practices

- Use **exact matches (`=`)** for single files like `/robots.txt`.
    
- Use **prefix matches** for most directories.
    
- Use **`^~`** for static asset directories when you don't want regex evaluation.
    
- Use **regex** only when pattern matching is truly required.
    
- Prefer `root` over `alias` unless the URL and directory structures differ.
    
- Keep location rules simple and easy to understand.

# Interview Questions

### 1. What is a Location Block?

A location block defines how Nginx handles requests for a specific URL path or pattern.

---

### 2. What is the difference between `root` and `alias`?

- `root` appends the request path to the specified directory.
    
- `alias` replaces the matched location path with the specified directory.
    

---

### 3. What does `location = /login` mean?

It matches **only** the exact path `/login`.

---

### 4. What is the difference between `~` and `~*`?

- `~` performs a **case-sensitive** regular expression match.
    
- `~*` performs a **case-insensitive** regular expression match.
    

---

### 5. What is the location matching priority?

1. Exact (`=`)
    
2. `^~` prefix
    
3. Longest prefix
    
4. Regular expressions (`~`, `~*`)
    
5. Default prefix (`/`)

# Hands-on Practice

## Step 1: Create directories

```bash
sudo mkdir -p /var/www/nginx-demo/images
sudo mkdir -p /var/www/nginx-demo/downloads
```

---

## Step 2: Create sample files

```bash
echo "<h1>Home Page</h1>" | sudo tee /var/www/nginx-demo/index.html

echo "Sample file" | sudo tee /var/www/nginx-demo/downloads/readme.txt
```

---

## Step 3: Configure Nginx

```nginx
server {
    listen 80;
    server_name localhost;

    root /var/www/nginx-demo;
    index index.html;

    location = /health {
        return 200 "Healthy\n";
    }

    location /downloads/ {
        autoindex on;
    }

    location /api/ {
        return 200 "API endpoint\n";
    }

    location ~* \.(txt)$ {
        add_header X-File-Type "Text";
    }
}
```

# Key Takeaways

- A **Location Block** determines how Nginx handles a specific URL.
    
- Prefix matching is the most common type.
    
- Exact matching (`=`) is ideal for single, fixed URLs.
    
- Regular expressions provide flexible pattern matching but should be used sparingly.
    
- `root` and `alias` behave differently and are not interchangeable.
    
- Understanding location matching priority is essential for writing predictable Nginx configurations.
