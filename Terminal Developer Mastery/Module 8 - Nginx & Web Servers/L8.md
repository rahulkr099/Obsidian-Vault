# Lesson 8 — URL Rewriting & Redirects

This lesson teaches one of the most useful Nginx features: **redirecting and rewriting URLs**.

Every large website uses redirects.

Examples:

- You type `http://github.com`
    
- It automatically becomes `https://github.com`
    

or

- `example.com`
    
- becomes
    
- `www.example.com`
    

or

- `/old-blog`
    
- becomes
    
- `/blog`
    

These are all handled by redirects.

---

# Learning Objectives

By the end of this lesson, you'll understand:

- What redirects are
    
- 301 Redirects
    
- 302 Redirects
    
- Rewrite rules
    
- Permanent redirects
    
- Temporary redirects
    
- Pretty URLs
    
- SEO considerations
    
- Best practices
    

---

# Why Redirect?

Imagine you moved to a new house.

Someone visits your old address.

Instead of saying:

> "House not found"

you place a sign saying:

> "I moved to my new address."

That's exactly what a redirect does.

---

# Without Redirect

```text
Browser

↓

GET /old-page

↓

404 Not Found
```

User gets an error.

---

# With Redirect

```text
Browser

↓

GET /old-page

↓

Redirect

↓

GET /new-page

↓

200 OK
```

User reaches the correct page.

---

# What is a Redirect?

A redirect tells the browser:

> "The resource you're looking for is somewhere else."

The browser automatically makes another request.

---

# How Redirect Works

Suppose:

```text
https://example.com/old
```

Browser sends:

```http
GET /old
```

Server replies:

```http
301 Moved Permanently

Location: /new
```

Browser automatically requests:

```http
GET /new
```

The user usually doesn't notice the extra request.

---

# HTTP Status Codes

Common redirect status codes:

|Code|Meaning|
|---|---|
|301|Permanent Redirect|
|302|Temporary Redirect|
|307|Temporary Redirect (method preserved)|
|308|Permanent Redirect (method preserved)|

In Nginx, you'll most often use **301** and **302**.

---

# 301 Redirect

Meaning:

> This page has moved permanently.

Configuration:

```nginx
return 301 /new-page;
```

Request:

```text
GET /old-page
```

Response:

```text
301 Moved Permanently
```

Browser goes to:

```text
/new-page
```

---

# When to Use 301

Use it when:

- Page permanently moved
    
- Domain changed
    
- HTTPS migration
    
- URL restructuring
    
- SEO preservation
    

Examples:

```text
/about-us

↓

/about
```

or

```text
http://

↓

https://
```

---

# Example

```nginx
location = /old-page {

    return 301 /new-page;

}
```

Now:

```text
/old-page

↓

/new-page
```

---

# Redirect to Another Website

Example:

```nginx
location / {

    return 301 https://google.com;

}
```

Every request goes to Google.

---

# Redirect Entire Domain

Suppose:

Old:

```text
oldcompany.com
```

New:

```text
newcompany.com
```

Configuration:

```nginx
server {

    server_name oldcompany.com;

    return 301 https://newcompany.com$request_uri;

}
```

Notice:

```nginx
$request_uri
```

preserves the path.

Example:

```text
oldcompany.com/blog/post1
```

↓

```text
newcompany.com/blog/post1
```

---

# HTTP to HTTPS Redirect

One of the most common production configurations.

```nginx
server {

    listen 80;

    server_name example.com;

    return 301 https://$host$request_uri;

}
```

Flow:

```text
Browser

↓

HTTP

↓

301 Redirect

↓

HTTPS

↓

Website
```

We'll configure HTTPS fully in Lesson 15.

---

# WWW Redirect

Redirect:

```text
www.example.com

↓

example.com
```

Configuration:

```nginx
server {

    server_name www.example.com;

    return 301 https://example.com$request_uri;

}
```

---

Reverse direction:

```text
example.com

↓

www.example.com
```

Configuration:

```nginx
return 301 https://www.example.com$request_uri;
```

---

# 302 Redirect

Meaning:

> This move is temporary.

Configuration:

```nginx
return 302 /maintenance;
```

Browser redirects, but search engines do **not** treat it as a permanent move.

---

# When to Use 302

Examples:

- Maintenance page
    
- Temporary promotions
    
- A/B testing
    
- Temporary migration
    
- Seasonal landing pages
    

---

# 301 vs 302

|301|302|
|---|---|
|Permanent|Temporary|
|Browser may cache|Usually not cached permanently|
|Search engines update URLs|Search engines keep original URL|
|SEO value transferred|SEO value generally stays with original URL|

---

# The `return` Directive

Most redirects use:

```nginx
return
```

Example:

```nginx
return 301 https://example.com;
```

Simple.

Fast.

Easy to read.

---

# The `rewrite` Directive

Another way to change URLs.

Syntax:

```nginx
rewrite pattern replacement;
```

Example:

```nginx
rewrite ^/old$ /new permanent;
```

Request:

```text
/old
```

↓

```text
/new
```

---

# Rewrite Flags

Common flags:

|Flag|Meaning|
|---|---|
|last|Restart location search|
|break|Stop processing rewrites|
|redirect|302 redirect|
|permanent|301 redirect|

Example:

```nginx
rewrite ^/old$ /new permanent;
```

Equivalent to:

```text
301 Redirect
```

---

# Why Prefer `return`?

Simple redirect:

```nginx
return 301 /new;
```

is generally preferred over:

```nginx
rewrite ^ /new permanent;
```

because:

- Easier to read
    
- Faster
    
- Less error-prone
    

Use `rewrite` when pattern matching is required.

---

# Pretty URLs

Users prefer:

```text
/blog/hello-world
```

instead of:

```text
/blog?id=123
```

Nginx can rewrite requests into formats your application understands.

---

Example:

User requests:

```text
/blog/python
```

Application internally receives:

```text
/blog.php?article=python
```

The user still sees the clean URL.

---

# Removing File Extensions

Instead of:

```text
/about.html
```

You may want:

```text
/about
```

Configuration:

```nginx
rewrite ^/about$ /about.html last;
```

Now users access:

```text
/about
```

while Nginx serves:

```text
/about.html
```

---

# Redirect Old URLs

Suppose:

Old:

```text
/products/laptop1
```

New:

```text
/store/laptop1
```

Configuration:

```nginx
rewrite ^/products/(.*)$ /store/$1 permanent;
```

Request:

```text
/products/macbook
```

↓

```text
/store/macbook
```

The captured part `(.*)` is reused with `$1`.

---

# Redirect Trailing Slash

Example:

```text
/about/

↓

/about
```

Configuration:

```nginx
rewrite ^/(.*)/$ /$1 permanent;
```

This creates a consistent URL style.

---

# Redirect Without Changing URL

Sometimes you don't want the browser to know.

Example:

```text
/about

↓

Internally

↓

about.html
```

Configuration:

```nginx
try_files $uri $uri.html =404;
```

The browser still displays:

```text
/about
```

No visible redirect occurs.

This is called an **internal rewrite**.

---

# Real Production Example

```nginx
server {

    listen 80;

    server_name example.com;

    location = /old {

        return 301 /new;

    }

    location / {

        try_files $uri $uri/ /index.html;

    }

}
```

---

# SEO Considerations

Search engines prefer:

- 301 for permanent changes
    
- Stable URLs
    
- Avoid redirect chains
    
- Avoid redirect loops
    

Good:

```text
Old

↓

New
```

Bad:

```text
Old

↓

Page A

↓

Page B

↓

Page C
```

Each extra redirect slows down the user and search engines.

---

# Redirect Loop

Incorrect configuration:

```text
A

↓

B

↓

A

↓

B

↓

A
```

Browser eventually reports:

```text
ERR_TOO_MANY_REDIRECTS
```

You've encountered this error before while deploying applications—it's often caused by conflicting redirect rules.

---

# Test Redirects

Use `curl`:

```bash
curl -I http://example.com
```

Example output:

```text
HTTP/1.1 301 Moved Permanently

Location: https://example.com/
```

Follow redirects automatically:

```bash
curl -L http://example.com
```

---

# Common Mistakes

## Using 302 Instead of 301

If the move is permanent:

Use:

```text
301
```

not:

```text
302
```

---

## Infinite Redirect

Bad:

```text
http

↓

https

↓

http

↓

https
```

Always test redirect rules carefully.

---

## Losing Query Parameters

Bad:

```nginx
return 301 /new;
```

If preserving the original request path and query is important, use variables like:

```nginx
return 301 https://$host$request_uri;
```

---

# Best Practices

- Use **301** for permanent URL changes.
    
- Use **302** only for temporary redirects.
    
- Prefer `return` for simple redirects.
    
- Use `rewrite` only when you need pattern matching.
    
- Preserve request paths with `$request_uri` when appropriate.
    
- Avoid redirect chains and loops.
    
- Test redirects using `curl -I` before deploying.
    

---

# Interview Questions

### 1. What is the difference between a 301 and a 302 redirect?

A **301** indicates a permanent move and is used for long-term URL changes. A **302** indicates a temporary move and tells clients and search engines that the original URL is still valid.

---

### 2. When should you use `return` instead of `rewrite`?

Use `return` for straightforward redirects because it's simpler and more efficient. Use `rewrite` when you need pattern matching or more advanced URL transformations.

---

### 3. What does `$request_uri` do?

It contains the original request URI, including the path and query string, allowing redirects to preserve the user's requested URL.

---

### 4. Why are redirect loops dangerous?

They cause browsers to repeatedly request URLs until they stop with errors like **ERR_TOO_MANY_REDIRECTS**, making the website inaccessible.

---

### 5. How can you verify a redirect from the command line?

Use:

```bash
curl -I http://example.com
```

to inspect the response headers, or:

```bash
curl -L http://example.com
```

to automatically follow redirects.

# Hands-on Practice

## Step 1: Create a test server block

```nginx
server {
    listen 80;
    server_name localhost;

    root /var/www/html;

    location = /old-page {
        return 301 /new-page;
    }

    location = /new-page {
        return 200 "Welcome to the new page!\n";
    }

    location = /maintenance {
        return 200 "Maintenance Mode\n";
    }

    location = /temp {
        return 302 /maintenance;
    }
}
```

---

## Step 2: Test the configuration

```bash
sudo nginx -t
```

---

## Step 3: Reload Nginx

```bash
sudo systemctl reload nginx
```

---

## Step 4: Test with `curl`

Check the permanent redirect:

```bash
curl -I http://localhost/old-page
```

Follow the redirect:

```bash
curl -L http://localhost/old-page
```

Test the temporary redirect:

```bash
curl -I http://localhost/temp
```

---

## Step 5: Observe the headers

Look for:

```text
HTTP/1.1 301 Moved Permanently
Location: /new-page
```

or:

```text
HTTP/1.1 302 Found
Location: /maintenance
```

Understanding these headers will help you debug deployments and API gateways.

---

# Key Takeaways

- Redirects send users from one URL to another.
    
- **301** is for permanent moves; **302** is for temporary ones.
    
- `return` is the preferred directive for simple redirects.
    
- `rewrite` is useful for pattern-based URL transformations.
    
- Pretty URLs improve readability and user experience.
    
- Avoid redirect loops and unnecessary redirect chains.
    
- `curl -I` and `curl -L` are essential tools for testing redirect behavior.
