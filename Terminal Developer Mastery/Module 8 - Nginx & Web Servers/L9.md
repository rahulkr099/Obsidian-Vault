# Lesson 9 — Reverse Proxy Fundamentals

This lesson is where Nginx becomes much more than a web server.

In modern backend development, Nginx is **rarely used only to serve HTML**.

Instead, it usually sits **in front of your backend application** and forwards requests to it.

If you've deployed an **Express.js**, **Django**, **Flask**, **Spring Boot**, or **ASP.NET** application, you've likely used a reverse proxy—even if you didn't realize it.

# What is a Reverse Proxy?

A reverse proxy is a server that:

- Receives client requests
    
- Forwards them to backend servers
    
- Receives backend responses
    
- Sends those responses back to the client
    

The client never talks directly to the backend.

```text
↓
```

In reality:

Nginx is communicating with another server behind the scenes.

---

# Why is it Called "Reverse"?

To understand this, first learn about a **Forward Proxy**.

---

# Forward Proxy

A forward proxy sits **in front of clients**.

```text
Client

↓

Forward Proxy

↓

Internet
```

Examples:

- Company internet proxy
    
- School network
    
- Library network
    

Purpose:

- Hide clients
    
- Filter websites
    
- Cache downloads
    
- Monitor traffic
    

The destination server sees the proxy—not the original client.

---

# Reverse Proxy

A reverse proxy sits **in front of servers**.

```text
Client

↓

Reverse Proxy

↓

Backend Servers
```

Purpose:

- Hide backend servers
    
- Improve performance
    
- Add security
    
- Distribute traffic
    

Clients don't know how many backend servers exist.

---

# Forward vs Reverse Proxy

|Forward Proxy|Reverse Proxy|
|---|---|
|Protects clients|Protects servers|
|Used by users|Used by websites|
|Client chooses proxy|Website owner deploys proxy|
|Accesses many websites|Serves one or more backend services|

# Why Not Expose Node.js Directly?

Suppose:

```text

↓

Port 3000
```

Users visit:

```text

```

Problems:

- Port exposed
    
- No HTTPS

```text

↓

↓
```

# Basic Reverse Proxy Configuration

```nginx
server {

    listen 80;

    server_name example.com;

    location / {

        proxy_pass http://localhost:3000;

    }

}
```

This is one of the most common Nginx configurations.

---

# Understanding `proxy_pass`

This directive tells Nginx:

> "Forward this request to another server."

Example:

```nginx
proxy_pass http://localhost:3000;
```

Flow:

```text
Browser

↓

Nginx

↓

localhost:3000

↓

Response

↓

Browser
```

---

# Example Request

Browser:

```http
GET /users
```

Nginx receives:

```http
GET /users
```

Nginx forwards:

```http
GET /users
```

to:

```text
localhost:3000
```

Express handles the request and responds.

Nginx sends the response back to the browser.

---

# Multiple Services

Modern applications often have several backend services.

```text
Users

↓

Nginx

├── API

├── Authentication

├── Payments

└── Dashboard
```

Example configuration:

```nginx
location /api/ {

    proxy_pass http://localhost:3000;

}

location /auth/ {

    proxy_pass http://localhost:4000;

}

location /payments/ {

    proxy_pass http://localhost:5000;

}
```

Each path routes to a different application.

# Static + Dynamic Content

A common production setup:

```text
Users

↓

├── HTML
├── CSS
├── JavaScript
├── Images

↓

Node.js API
```

Static files are served directly by Nginx.

Only API requests reach Node.js.

This reduces backend workload.

# Reverse Proxy with React + Express

Suppose:

Frontend:

```text
React Build
```

Backend:

```text
Express API
```

Architecture:

```text
Users

↓

Nginx

├── React Static Files

└── Express API
```

Example:

```nginx
server {

    listen 80;

    server_name example.com;

    root /var/www/react;

    location / {

        try_files $uri /index.html;

    }

    location /api/ {

        proxy_pass http://localhost:3000;

    }

}
```

Requests:

```text
/

↓

React
```

Requests:

```text
/api/users
```

↓

```text
Express
```

This is a very common deployment architecture for MERN applications.

# Benefits of a Reverse Proxy

## 1. Hide Backend Servers

Users only see:

```text
example.com
```

They never see:

```text
localhost:3000
```

---

## 2. HTTPS Termination

Nginx handles SSL/TLS.

Backend applications can continue using plain HTTP internally.

```text
Browser

↓

HTTPS

↓

Nginx

↓

HTTP

↓

Node.js
```

---

## 3. Load Balancing

Instead of:

```text
One Node.js Server
```

Use:

```text
Nginx

↓

Node 1

Node 2

Node 3
```

We'll cover this in Lesson 12.

---

## 4. Compression

Nginx compresses responses before sending them to clients.

Smaller responses mean faster downloads.

---

## 5. Caching

Nginx can cache responses.

Repeated requests may never reach the backend.

---

## 6. Security

Nginx can:

- Block suspicious requests
    
- Limit request rates
    
- Hide backend details
    
- Add security headers
    

---

## 7. Logging

Nginx records every request.

This helps with:

- Debugging
    
- Monitoring
    
- Analytics

# Common Mistakes

## Backend Not Running

Nginx forwards:

```text
localhost:3000
```

But nothing is listening.

Result:

```text
502 Bad Gateway
```

---

## Wrong Port

Configuration:

```nginx
proxy_pass http://localhost:4000;
```

But Express runs on:

```text
3000
```

Result:

```text
502 Bad Gateway
```

---

## Firewall Issues

If the backend isn't reachable because of firewall rules or binding to the wrong interface, Nginx cannot forward requests.

---

## Missing Reload

After editing:

```bash
sudo nginx -t
```

Then:

```bash
sudo systemctl reload nginx
```

# Interview Questions

### 1. What is a reverse proxy?

A reverse proxy is a server that receives client requests, forwards them to backend servers, receives the backend responses, and returns those responses to the client.

---

### 2. What is the difference between a forward proxy and a reverse proxy?

A forward proxy sits in front of clients and hides them from destination servers. A reverse proxy sits in front of servers and hides backend infrastructure from clients.

---

### 3. Why is Nginx commonly used as a reverse proxy?

Because it provides high performance, HTTPS termination, load balancing, caching, compression, security features, and efficient request routing.

---

### 4. What does `proxy_pass` do?

It forwards matching requests to another server, such as a Node.js or Django application.

---

### 5. Why shouldn't users connect directly to a Node.js server?

Using Nginx in front of Node.js improves security, simplifies HTTPS, enables caching and load balancing, and keeps backend ports hidden from the public.

# Hands-on Practice

## Step 1: Create a simple Express application

```javascript
const express = require("express");

const app = express();

app.get("/", (req, res) => {
    res.send("Hello from Express!");
});

app.listen(3000, () => {
    console.log("Server running on port 3000");
});
```

Run it:

```bash
node app.js
```

---

## Step 2: Configure Nginx

```nginx
server {
    listen 80;
    server_name localhost;

    location / {
        proxy_pass http://localhost:3000;
    }
}
```

---

## Step 3: Test the configuration

```bash
sudo nginx -t
```

---

## Step 4: Reload Nginx

```bash
sudo systemctl reload nginx
```

---

## Step 5: Test with `curl`

Request through Nginx:

```bash
curl http://localhost
```

You should receive:

```text
Hello from Express!
```

Although the browser connected to **Nginx**, the response actually came from **Express**.

---

## Step 6: Verify the backend is listening

```bash
ss -tulpn | grep 3000
```

You should see your Express application listening on port `3000`.

---

# Key Takeaways

- A reverse proxy sits between clients and backend servers.
    
- Nginx receives requests and forwards them using `proxy_pass`.
    
- Backend applications remain hidden from users.
    
- Nginx adds HTTPS, caching, compression, security, and logging without changing backend code.
    
- Serving static files directly from Nginx while proxying only dynamic requests is a standard production pattern.
    
- Reverse proxies are the foundation for load balancing, high availability, and scalable backend architectures.
