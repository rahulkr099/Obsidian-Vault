# What is a VPS?

**VPS** stands for **Virtual Private Server**.

Think of it as:

> **A Linux computer running in someone else's data center that you control remotely.**

Popular providers include:

- DigitalOcean
- AWS EC2
- Google Cloud
- Azure
- Linode
- Vultr
- Hetzner

Instead of sitting next to the computer, you manage it through SSH.

---

# What Information Do You Need?

To connect, you usually need four things:

```
IP Address
Username
SSH Port
Authentication Method
```

Example:

```
IP Address:
203.0.113.10

Username:
ubuntu

Port:
22

Authentication:
SSH Key
```

|Distribution|Default Username|
|---|---|
|Ubuntu|`ubuntu`|
|Debian|`debian`|
|Amazon Linux|`ec2-user`|
|CentOS|`centos`|
|Fedora Cloud|`fedora`|
|Rocky Linux|`rocky`|

Always check your cloud provider's documentation.

# Basic SSH Connection

Example:

```bash
ssh ubuntu@203.0.113.10
```

Breakdown:

```
ssh
 │
 ▼
Client Program

ubuntu
 │
 ▼
Remote Username

203.0.113.10
 │
 ▼
Remote Server
```

---

# Connecting on a Different Port

If SSH runs on port **2222**:

```bash
ssh -p 2222 ubuntu@203.0.113.10
```

---

# Using an SSH Key

Many VPS providers disable password login.

Instead:

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@203.0.113.10
```

Here:

- `i` → identity file (private key)
- `ubuntu` → remote username
- `203.0.113.10` → server IP

---

# First Login

The first connection usually shows:

```
The authenticity of host
'203.0.113.10'
can't be established.

ED25519 key fingerprint is
SHA256:...

Are you sure you want to continue connecting?
```

If you've verified the fingerprint:

```
yes
```

SSH stores it in:

```
~/.ssh/known_hosts
```

---

# Successful Login

You'll typically see something like:

```
Welcome to Ubuntu 24.04 LTS

Last login:
...

ubuntu@server:~$
```

Congratulations!

You're now controlling a Linux computer somewhere in the world.

# First Commands to Run

These are safe information commands.

Who am I?

```bash
whoami
```

Hostname:

```bash
hostname
```

Operating system:

```bash
cat /etc/os-release
```

Current directory:

```bash
pwd
```

Current time:

```bash
date
```

System uptime:

```bash
uptime
```

Memory usage:

```bash
free -h
```

Disk usage:

```bash
df -h
```

These commands help you quickly understand the server you're connected to.

# How to Know You're Remote

Sometimes the prompt changes:

```
ubuntu@web-server:~$
```

instead of:

```
rahul@mint:~$
```

You can always verify with:

```bash
hostname
```

# Logging Out

When finished:

```bash
exit
```

or press:

```
Ctrl + D
```

You'll return to your local terminal.

# Real Backend Workflow

Imagine you've deployed your Express backend.

Connect:

```bash
ssh ubuntu@203.0.113.10
```

Update your code:

```bash
git pull
```

Install dependencies:

```bash
npm install
```

Restart your application:

```bash
pm2 restart backend
```

Check that it's running:

```bash
pm2 status
```

Exit:

```bash
exit
```

This is a very common deployment workflow for Node.js backend developers.

# Common Connection Errors

## Wrong Username

```
Permission denied
```

Example:

```bash
ssh rahul@203.0.113.10
```

But the server expects:

```bash
ssh ubuntu@203.0.113.10
```

---

## Wrong Key

```
Permission denied (publickey)
```

Specify the correct key:

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@203.0.113.10
```

---

## Wrong Port

```
Connection refused
```

Try:

```bash
ssh -p 2222 ubuntu@203.0.113.10
```

if the server uses a custom port.

---

## Firewall Blocking SSH

```
Connection timed out
```

Possible causes:

- Port 22 blocked
- Security group misconfigured
- Firewall rules incorrect

# Key Takeaways

- A VPS is a remote Linux machine that you control over SSH.
- You need the **IP address**, **username**, **port**, and **authentication method**.
- Different Linux distributions use different default usernames.
- After connecting, verify the server with commands like `hostname` and `whoami`.
- Always log out when you're finished.
