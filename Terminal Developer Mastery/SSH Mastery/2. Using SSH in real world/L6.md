# SSH Mastery — Module 2, Lesson 6

# Running Commands Remotely

Until now, you've been doing this:

```bash
ssh ubuntu@203.0.113.10
```

↓

```bash
uptime
```

↓

```bash
exit
```

Today you'll learn something much more powerful.

You can execute commands on a remote server **without opening an interactive shell**.

This is one of the most useful SSH features for backend developers and DevOps engineers.

---

# Learning Objectives

By the end of this lesson, you'll know how to:

- Run one command remotely
- Run multiple commands remotely
- Pass quoted commands correctly
- Capture remote command output
- Use SSH in scripts and automation

---

# Basic Syntax

Instead of:

```bash
ssh ubuntu@203.0.113.10
```

followed by:

```bash
uptime
```

You can combine everything into one command:

```bash
ssh ubuntu@203.0.113.10 uptime
```

SSH will:

1. Connect
2. Run `uptime`
3. Print the output
4. Disconnect automatically

---

# How It Works

```
Your Laptop
      │
      ▼
ssh server uptime
      │
      ▼
SSH Connection
      │
      ▼
Run "uptime"
      │
      ▼
Send Output Back
      │
      ▼
Disconnect
```

No interactive shell is opened.

# Running Multiple Commands

Use quotes:

```bash
ssh ubuntu@203.0.113.10 "pwd && ls -la"
```

SSH executes:

```bash
pwd
```

then:

```bash
ls -la
```

---

# Another Example

```bash
ssh ubuntu@203.0.113.10 "hostname && uptime && free -h"
```

This returns:

- Hostname
- Uptime
- Memory usage

in one connection.

---

# Why Quotes Matter

Without quotes:

```bash
ssh server pwd && ls
```

What happens?

Your local shell interprets it as:

```
ssh server pwd

AND THEN

run ls on YOUR computer
```

That is **not** what you intended.

---

With quotes:

```bash
ssh server "pwd && ls"
```

Everything inside the quotes runs on the **remote server**.

# Git Deployment Example

Update code:

```bash
ssh ubuntu@203.0.113.10 "cd app && git pull"
```

---

Restart application:

```bash
ssh ubuntu@203.0.113.10 "pm2 restart backend"
```

---

Or combine them:

```bash
ssh ubuntu@203.0.113.10 \
"cd app && git pull && npm install && pm2 restart backend"
```

One SSH connection.

Four commands.

Store remote output locally:



# Exit Status

Remote commands return an exit code, just like local commands.

Example:

```bash
ssh ubuntu@203.0.113.10 "true"

echo $?
```

Output:

```
0
```

If the remote command fails:

```bash
ssh ubuntu@203.0.113.10 "false"

echo $?
```

Output:

```
1
```

This is useful in deployment scripts.

# Real Backend Workflow

Imagine your production API isn't responding.

Instead of opening a shell, you quickly check:

```bash
ssh production "pm2 status"
```

Need logs?

```bash
ssh production "pm2 logs --lines 50"
```

Need disk usage?

```bash
ssh production "df -h"
```

Need memory?

```bash
ssh production "free -h"
```

Each command connects, runs, returns output, and disconnects automatically.

# Common Mistakes

## ❌ Forgetting Quotes

```bash
ssh server pwd && ls
```

`ls` runs on your **local machine**.

---

## ✅ Correct

```bash
ssh server "pwd && ls"
```

Both commands run remotely.

---

## ❌ Wrong Directory

```bash
ssh server "git pull"
```

If you're not in your project directory, Git will fail.

Instead:

```bash
ssh server "cd /var/www/app && git pull"
```

# Key Takeaways

- You can run a remote command directly with `ssh host command`.
- Use quotes when executing multiple remote commands.
- Remote commands automatically disconnect after finishing.
- This feature is widely used in deployment scripts, monitoring, and CI/CD.
- Exit codes from remote commands can be used to automate success/failure handling.

## Pro Tip ⭐

Most CI/CD systems (such as GitHub Actions, GitLab CI, and Jenkins) use this exact pattern behind the scenes. A deployment step often looks like:

```bash

"cd /var/www/app && git pull && npm install && pm2 restart backend"
```

Once you're comfortable with remote commands, you'll recognize this pattern in deployment pipelines and automation scripts everywhere.
