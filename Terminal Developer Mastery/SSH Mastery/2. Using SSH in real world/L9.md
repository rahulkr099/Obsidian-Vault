# Why Do SSH Sessions Disconnect?

Your SSH session travels through several devices:

```
Laptop
   │
Home Router
   │
ISP
   │
Internet
   │
Cloud Firewall
   │
Server
```

Some of these devices automatically close **idle** connections to save resources.

If you don't type anything for a while:

```
No activity
     │
Idle timeout
     │
Connection closed
```

SSH itself may still be fine—the network in between ended the connection.

# Solution: Keep-Alive Messages

SSH can periodically send tiny packets that say:

> "I'm still here."

These packets don't run commands.

They simply keep the connection active.

---

# `ServerAliveInterval`

This option tells the **SSH client** to send a keep-alive message every _N_ seconds.

Example:

```bash
ssh -o ServerAliveInterval=60 ubuntu@203.0.113.10
```

Meaning:

```
Every 60 seconds:

"Server, are you still there?"
```

This usually prevents idle timeouts.

---

# `ServerAliveCountMax`

Suppose the server stops responding.

Should SSH wait forever?

No.

Use:

```bash
ssh \
-o ServerAliveInterval=60 \
-o ServerAliveCountMax=3 \
ubuntu@203.0.113.10
```

Meaning:

- Send a keep-alive every 60 seconds.
- If **3** consecutive replies are missed, disconnect.

Timeline:

```
0 sec   → Send keep-alive ✓
60 sec  → Send keep-alive ✗
120 sec → Send keep-alive ✗
180 sec → Send keep-alive ✗

Disconnect
```

This helps detect broken connections instead of hanging indefinitely.

---

# `TCPKeepAlive`

Another option:

```bash
ssh -o TCPKeepAlive=yes server
```

Default:

```
yes
```

Difference:

|Option|Managed By|
|---|---|
|`ServerAliveInterval`|SSH client|
|`TCPKeepAlive`|Operating system (TCP layer)|

For most users, `ServerAliveInterval` is the more useful setting for preventing idle disconnects.

---

# Temporary vs Permanent Settings

### Temporary

Only for this command:

```bash
ssh \
-o ServerAliveInterval=60 \
server
```

---

### Permanent

In your SSH configuration file:

```
~/.ssh/config
```

Example:

```
Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3
```

Now every SSH connection uses these settings automatically.

We'll cover `~/.ssh/config` in detail in **Lesson 10**.

---

# Checking Your Current Configuration

View the effective configuration:

```bash
ssh -G localhost
```

Search for:

```
serveraliveinterval
```

or use:

```bash
ssh -G localhost | grep -i alive
```

Example:

```
serveraliveinterval 0
serveralivecountmax 3
tcpkeepalive yes
```

A value of `0` means no client keep-alive messages are being sent.

# Long Deployments

Suppose you're running:

```bash
npm install
```

or

```bash
docker compose pull
```

These operations may take several minutes.

Using keep-alives helps reduce the chance that an idle network device drops the connection while you're waiting.

> **Note:** If you're performing critical long-running tasks, tools like **tmux** or **screen** provide even better protection because they keep your session running even if your SSH connection is lost. You'll learn about those later.

# Common Mistakes

## ❌ Setting the Interval Too Low

Example:

```bash
ServerAliveInterval 1
```

Sending a keep-alive every second is unnecessary for most environments and creates extra network traffic.

Values like **30** or **60** seconds are common.

---

## ❌ Assuming Keep-Alives Prevent Every Disconnect

Keep-alives help with idle timeouts.

They cannot fix:

- Wi-Fi failures
- Power outages
- Server crashes
- ISP outages

---

## ❌ Confusing ServerAlive with TCPKeepAlive

Remember:

|Option|Layer|
|---|---|
|ServerAliveInterval|SSH|
|TCPKeepAlive|TCP|

# Key Takeaways

- SSH sessions often disconnect because intermediate network devices close idle connections.
- `ServerAliveInterval` sends periodic keep-alive messages from the SSH client.
- `ServerAliveCountMax` controls how many missed responses are allowed before disconnecting.
- `TCPKeepAlive` operates at the TCP layer and serves a different purpose.
- For critical long-running work, use **tmux** or **screen** in addition to keep-alive settings.
