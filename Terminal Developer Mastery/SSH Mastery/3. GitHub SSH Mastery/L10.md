# GitHub SSH Troubleshooting ⭐⭐⭐⭐⭐

Every developer eventually sees an SSH error.

The difference between a beginner and an experienced developer isn't that they never get errors—it's that they know **how to debug them systematically**.

By the end of this lesson, you'll be able to diagnose most GitHub SSH problems in just a few minutes.

---

# Learning Objectives

You'll learn to troubleshoot:

- `Permission denied (publickey)`
- `Repository not found`
- `Host key verification failed`
- `Agent has no identities`
- `Too many authentication failures`
- Wrong SSH key being used
- DNS and network issues

You'll also master:

```bash
ssh -v
ssh -vv

```

# The Troubleshooting Flow

Don't guess.

Follow this order every time:

```
Problem
   │
   ▼
Is SSH working?
   │
   ▼
Is the correct key loaded?
   │
   ▼
Is GitHub using the correct account?
   │
   ▼
Does the repository exist?
   │
   ▼
Do I have permission?
```

This logical sequence saves a lot of time.

# Error 1 — Permission denied (publickey)

Example:

```
git@github.com: Permission denied (publickey).
fatal: Could not read from remote repository.
```

This is the **most common SSH error**.

It means:

- GitHub didn't accept any of the SSH keys your computer offered.

---

## Step 1 — Check Your SSH Connection

Run:

```bash
ssh -T git@github.com
```

If this fails, fix SSH before trying Git commands.

---

## Step 2 — Check Loaded Keys

```bash
ssh-add -l
```

Good:

```
256 SHA256:ABC123... (ED25519)
```

Bad:

```
The agent has no identities.
```

Solution:

```bash
ssh-add ~/.ssh/id_ed25519
```

---

## Step 3 — Check That the Key Exists

```bash
ls ~/.ssh
```

Example:

```
id_ed25519
id_ed25519.pub
```

If they're missing, you'll need to generate a key.

---

## Step 4 — Verify GitHub Has Your Public Key

Display it:

```bash
cat ~/.ssh/id_ed25519.pub
```

Compare it with the key stored in your GitHub account.

Even a one-character difference means it's a different key.

---

# Error 2 — Repository not found

Example:

```
ERROR: Repository not found.
fatal: Could not read from remote repository.
```

Possible reasons:

- Repository name is wrong.
- Repository is private.
- You're authenticated as the wrong GitHub account.
- You don't have access.

---

## Check the Remote URL

```bash
git remote -v
```

Example:

```
origin git@github.com:rahul/backend-api.git
```

Confirm:

- Username/organization is correct.
- Repository name is correct.

---

# Error 3 — Host Key Verification Failed

Example:

```
Host key verification failed.
```

This usually happens when:

- GitHub's host key changed.
- Your `known_hosts` entry is outdated.
- The `known_hosts` file was copied from another machine.

---

## Fix

Remove GitHub's stored entry:

```bash
ssh-keygen -R github.com
```

Reconnect:

```bash
ssh -T git@github.com
```

SSH will ask you to trust GitHub again.

---

# Error 4 — Too Many Authentication Failures

Example:

```
Received disconnect from github.com:
Too many authentication failures
```

Why?

SSH tries many keys automatically.

GitHub disconnects after several unsuccessful attempts.

---

## Check Which Keys Are Loaded

```bash
ssh-add -l
```

If many keys are listed, SSH may be offering them all.

---

## Force a Specific Key

```bash
ssh -i ~/.ssh/id_ed25519 -T git@github.com
```

Or configure:

```
Host github.com
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

`IdentitiesOnly yes` tells SSH to use only the specified key.

---

# Error 5 — Wrong GitHub Account

Suppose:

```
Personal:
rahul123
```

```
Work:
acme-rahul
```

SSH authenticates successfully...

But as the wrong account.

Check:

```bash
ssh -T git@github.com
```

Output:

```
Hi rahul123!
```

If you expected:

```
Hi acme-rahul!
```

You're using the wrong key.

Solution:

Configure `~/.ssh/config` with separate aliases and identity files (from Lesson 8).

---

# Error 6 — Could Not Resolve Hostname

Example:

```
ssh: Could not resolve hostname github.com
```

Meaning:

Your computer can't find GitHub's IP address.

---

## Test DNS

```bash
ping github.com
```

Or:

```bash
nslookup github.com
```

Or:

```bash
getent hosts github.com
```

If these fail, check your network or DNS configuration.

---

# Error 7 — Connection Timed Out

Example:

```
Connection timed out
```

Possible causes:

- Internet connection is down.
- Firewall restrictions.
- Proxy or VPN issues.
- Temporary network outage.

Test general connectivity:

```bash
ping 8.8.8.8
```

If that works but GitHub doesn't, the issue is likely DNS or network policy.

# Debug Like a Professional

## Basic Debug

```bash
ssh -vT git@github.com
```

Shows:

- Configuration file used
- Keys being offered
- Authentication progress

---

## More Debug

```bash
ssh -vvT git@github.com
```

More detailed information.

---

## Maximum Debug

```bash
ssh -vvvT git@github.com
```

Everything SSH is doing.

This is the command you'll often use when asking for help.

---

# Important Debug Lines

Look for:

```
Offering public key:
```

Example:

```
Offering public key:
/home/rahul/.ssh/id_ed25519
```

Good.

SSH found your key.

---

Later:

```
Server accepts key
```

Perfect.

Authentication succeeded.

---

Or:

```
Authentications that can continue:
publickey
```

SSH is still trying.

If it never reaches "Server accepts key", GitHub didn't accept the offered keys.

---

# Check the Effective SSH Configuration

```bash
ssh -G github.com
```

Useful output:

```
identityfile ~/.ssh/id_ed25519
```

This tells you which private key SSH plans to use.

# Real Debugging Example

Problem:

```
git push
```

Fails.

Step 1:

```bash
ssh -T git@github.com
```

Fails.

Step 2:

```bash
ssh-add -l
```

Output:

```
The agent has no identities.
```

Step 3:

```bash
ssh-add ~/.ssh/id_ed25519
```

Step 4:

```bash
ssh -T git@github.com
```

Output:

```
Hi rahul!
```

Problem solved.

# Common Mistakes

### ❌ Assuming every Git error is an SSH problem

Sometimes the issue is simply:

- Wrong repository name
- No access to the repository
- Incorrect branch name

Always read the full error message.

---

### ❌ Ignoring `ssh -vvv`

Many developers jump straight to internet searches.

Instead:

```bash
ssh -vvvT git@github.com
```

Often tells you exactly what's wrong.

---

### ❌ Forgetting the SSH alias

If your `~/.ssh/config` contains:

```
Host github-work
```

but your remote URL is:

```
git@github.com:company/repo.git
```

SSH won't use the `github-work` configuration.

It should be:

```
git@github-work:company/repo.git
```

# Key Takeaways

- Troubleshoot in a logical order instead of guessing.
- `ssh -T` tests authentication.
- `ssh-add -l` checks loaded keys.
- `git remote -v` verifies the repository URL.
- `ssh -vvvT` is your most powerful debugging tool.
- `ssh -G` shows the SSH configuration that will actually be used.

# Practical Assignment ⭐

Using one of your GitHub projects:

1. Verify the remote:

```bash
git remote -v
```

1. Test authentication:

```bash
ssh -T git@github.com
```

1. Check loaded keys:

```bash
ssh-add -l
```

1. Inspect the effective configuration:

```bash
ssh -G github.com | grep -E "identityfile|identitiesonly"
```

1. If something doesn't work, run:

```bash
ssh -vvvT git@github.com
```

Read through the output and identify:

- Which key SSH offered
- Whether GitHub accepted it
- Where the authentication process failed (if it did)
