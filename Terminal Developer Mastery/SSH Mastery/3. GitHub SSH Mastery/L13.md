# Step 1 — Generate an SSH Key

Create a new key:

```bash
ssh-keygen -t ed25519 -C "rahul@example.com"
```

Save it:

```
~/.ssh/id_ed25519
```

---

# Step 2 — Start `ssh-agent`

```bash
eval "$(ssh-agent -s)"
```

---

# Step 3 — Load the Key

```bash
ssh-add ~/.ssh/id_ed25519
```

Unlock it once.

---

# Step 4 — Upload the Public Key

View it:

```bash
cat ~/.ssh/id_ed25519.pub
```

Copy the output.

Upload it to:

```
GitHub

Settings

SSH and GPG Keys

New SSH Key
```

---

# Step 5 — Test Authentication

```bash
ssh -T git@github.com
```

Expected:

```
Hi YOUR_USERNAME!
You've successfully authenticated,
but GitHub does not provide shell access.
```

You're ready.

---

# Step 6 — Clone the Project

Example:

```bash
git clone git@github.com:company/backend-api.git
```

Move inside:

```bash
cd backend-api
```

---

# Step 7 — Check Repository Status

```bash
git status
```

Example:

```
On branch main

nothing to commit
```

---

# Step 8 — Verify Remote

```bash
git remote -v
```

Expected:

```
origin git@github.com:company/backend-api.git
```

---

# Step 9 — Synchronize First

Never start coding immediately.

Always update:

```bash
git pull
```

Now you're working with the latest code.

---

# Step 10 — Create a Feature Branch

Example:

```bash
git checkout -b feature/login-validation
```

Verify:

```bash
git branch
```

Output:

```
* feature/login-validation
```

---

# Step 11 — Write Code

Example:

```
controllers/

services/

routes/

tests/
```

Make your changes.

---

# Step 12 — Review Changes

Check:

```bash
git status
```

Example:

```
modified:
authController.js
```

View differences:

```bash
git diff
```

Always review before committing.

---

# Step 13 — Stage Files

Everything:

```bash
git add .
```

Or one file:

```bash
git add controllers/authController.js
```

---

# Step 14 — Commit

Example:

```bash
git commit -m "Validate email before login"
```

If SSH commit signing is enabled:

The commit will be signed automatically.

---

# Step 15 — Push

First push:

```bash
git push -u origin feature/login-validation
```

Later pushes:

```bash
git push
```

---

# Step 16 — Open a Pull Request

Typical workflow:

```
GitHub

↓

Compare & Pull Request

↓

Review

↓

Approval

↓

Merge
```

Never push directly to `main` unless your team's workflow explicitly allows it.

---

# Step 17 — After Merge

Switch back:

```bash
git checkout main
```

Update:

```bash
git pull
```

Delete local feature branch:

```bash
git branch -d feature/login-validation
```

Optionally remove the remote branch:

```bash
git push origin --delete feature/login-validation
```

# Common Mistakes

## ❌ Working Directly on `main`

Wrong:

```bash
git checkout main
```

Write code...

Instead:

```bash
git checkout -b feature/new-feature
```

---

## ❌ Forgetting `git pull`

Always synchronize before starting work.

---

## ❌ Blindly Using `git add .`

Before:

```bash
git status
```

Review what's being staged.

---

## ❌ Skipping `git diff`

Always inspect your changes.

Unexpected edits happen more often than people realize.

---

## ❌ Huge Commits

Bad:

```
Updated everything
```

Good:

```
Validate JWT expiration
```

Keep commits focused on a single logical change.

# Key Takeaways

- SSH setup is usually a one-time task per machine.
- Create a new branch for every feature or bug fix.
- Pull before starting work.
- Review changes before committing.
- Push feature branches instead of working directly on `main`.
- Pull Requests are the standard way to merge code in professional teams.

## Pro Tip ⭐

Use descriptive branch names that communicate intent. Common conventions include:

```
feature/user-profile
bugfix/login-timeout
hotfix/payment-crash
refactor/auth-service
docs/api-guide
test/user-controller
```

Good branch names make collaboration and code reviews much easier.
