# Scenario

Imagine it's your **first day at a backend startup**.

Your manager says:

> "Clone the backend project, create a feature branch, make a small documentation update, push it, and open a Pull Request."

You have a fresh Linux installation.

Let's complete the entire workflow.

---

# Phase 1 — Verify Git

Check Git:

```bash
git --version
```

Expected:

```
git version 2.x.x
```

---

# Phase 2 — Check Existing SSH Keys

```bash
ls -la ~/.ssh
```

If no key exists:

Generate one.

---

# Phase 3 — Generate SSH Key

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

Save as:

```
~/.ssh/id_ed25519
```

Add a strong passphrase.

---

# Phase 4 — Start the SSH Agent

```bash
eval "$(ssh-agent -s)"
```

Example:

```
Agent pid 14281
```

---

# Phase 5 — Load Your Key

```bash
ssh-add ~/.ssh/id_ed25519
```

Verify:

```bash
ssh-add -l
```

Expected:

```
256 SHA256:...
```

---

# Phase 6 — Upload Public Key

Display it:

```bash
cat ~/.ssh/id_ed25519.pub
```

Copy the output and upload it to GitHub:

```
Settings
→ SSH and GPG Keys
→ New SSH Key
```

---

# Phase 7 — Test Authentication

```bash
ssh -T git@github.com
```

Expected:

```
Hi YOUR_USERNAME!
You've successfully authenticated,
but GitHub does not provide shell access.
```

---

# Phase 8 — Clone Repository

```bash
git clone git@github.com:YOUR_USERNAME/backend-api.git
```

Enter:

```bash
cd backend-api
```

---

# Phase 9 — Verify Repository

```bash
git status
```

```bash
git remote -v
```

Expected:

```
origin git@github.com:YOUR_USERNAME/backend-api.git
```

---

# Phase 10 — Update Local Repository

```bash
git checkout main
```

```bash
git pull
```

Always begin with the latest code.

---

# Phase 11 — Create Feature Branch

```bash
git checkout -b feature/ssh-lab
```

Verify:

```bash
git branch
```

Output:

```
* feature/ssh-lab
```

---

# Phase 12 — Make a Change

Edit `README.md`.

Example:

```markdown
## SSH Practice

Completed GitHub SSH workflow successfully.
```

---

# Phase 13 — Review Changes

```bash
git status
```

```bash
git diff
```

Never skip reviewing your work.

---

# Phase 14 — Stage Files

```bash
git add README.md
```

---

# Phase 15 — Commit

```bash
git commit -m "Add SSH workflow documentation"
```

If SSH commit signing is enabled, the commit will be signed automatically.

---

# Phase 16 — Push

First push:

```bash
git push -u origin feature/ssh-lab
```

Later pushes:

```bash
git push
```

---

# Phase 17 — Open Pull Request

On GitHub:

```
Compare & Pull Request
```

Write a clear title:

```
Add SSH workflow documentation
```

Description:

```
- Added SSH practice section
- Verified workflow
- Documentation update only
```

Update:

Commit:

# Phase 19 — Merge

After approval:

```
Merge Pull Request
```

# Phase 20 — Clean Up

Update local repository:

```bash
git checkout main
```

```bash
git pull
```

Delete feature branch:

```bash
git branch -d feature/ssh-lab
```

Delete remote branch:

```bash
git push origin --delete feature/ssh-lab
```

Project complete.

# Troubleshooting Checkpoint

If `git push` fails:

Test authentication:

```bash
ssh -T git@github.com
```

Check loaded keys:

```bash
ssh-add -l
```

Check remote:

```bash
git remote -v
```

Maximum debug:

```bash
ssh -vvvT git@github.com
```

---

# Security Audit

Before finishing, verify:

```bash
ls -l ~/.ssh
```

Correct permissions:

```
drwx------ ~/.ssh
-rw------- id_ed25519
-rw-r--r-- id_ed25519.pub
```

If needed:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub
```

# Common Mistakes

### ❌ Working on `main`

Always create a feature branch.

---

### ❌ Forgetting `git pull`

Always synchronize first.

---

### ❌ Not Reviewing Changes

Use:

```bash
git diff
```

before committing.

---

### ❌ Pushing Without Testing SSH

Run:

```bash
ssh -T git@github.com
```

if authentication issues occur.

---

### ❌ Leaving Old SSH Keys on GitHub

Regularly remove keys for devices you no longer use.
