# SSH Key Pair Recap

When you generate an SSH key, you actually create **two files**.

Example:

```
~/.ssh/

id_ed25519
id_ed25519.pub
```

They have different purposes.

|File|Purpose|Share?|
|---|---|---|
|`id_ed25519`|Private key|❌ Never|
|`id_ed25519.pub`|Public key|✅ Yes|

A good way to remember it:

> **Public key = lock**
> 
> **Private key = the only key that opens that lock**

---

# How GitHub Uses Your Key

When you run:

```bash
git push
```

The process looks like this:

```
Git
 │
 ▼
SSH
 │
 ▼
Private Key
 │
 ▼
GitHub
 │
 ▼
Matches Public Key?
 │
 ├── Yes → Push succeeds
 └── No  → Permission denied
```

Your **private key never leaves your computer**.

id_ed25519

# Ed25519 vs RSA

Today, **Ed25519** is the recommended choice for most users.

|Feature|Ed25519|RSA|
|---|---|---|
|Security|Excellent|Excellent (with large keys)|
|Key Size|Small|Larger|
|Speed|Faster|Slower|
|Recommended Today|✅ Yes|Sometimes for compatibility|

Unless you need compatibility with very old systems, choose **Ed25519**.

# Generate a New SSH Key

Command:

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

Explanation:

- `t ed25519` → key type
- `C` → comment (usually your email to help identify the key)

Example:

```bash
ssh-keygen -t ed25519 -C "rahul@example.com"
```

---

# What You'll See

```
Generating public/private ed25519 key pair.
```

Then:

```
Enter file in which to save the key
```

Press **Enter** to accept the default:

```
~/.ssh/id_ed25519
```

Or provide another filename if you want multiple keys.

---

# Choosing a Passphrase

Next you'll see:

```
Enter passphrase:
```

You have two options.

### Option 1 — Use a Passphrase ✅

Pros:

- Protects the private key if someone copies the file.
- Stronger security.

Con:

- You'll type it when first using the key (or use `ssh-agent` later).

---

### Option 2 — Leave It Empty

Just press Enter twice.

Pros:

- Convenient.

Cons:

- If someone steals the private key file, they can immediately use it.

For personal development machines, a passphrase is generally recommended.

# View Your Public Key

Display it:

```bash
cat ~/.ssh/id_ed25519.pub
```

Example:

```
ssh-ed25519 AAAAC3... your_email@example.com
```

This is the file you'll upload to GitHub in the next lesson.

---

# Never Display Your Private Key

Avoid commands like:

```bash
cat ~/.ssh/id_ed25519
```

The private key should remain confidential.

---

# Multiple Keys

Many developers use more than one key.

Example:

```
~/.ssh/

id_ed25519
id_ed25519.pub

work_ed25519
work_ed25519.pub
```

One for:

- Personal GitHub

Another for:

- Company GitHub

We'll configure this later using `~/.ssh/config`.

---

# File Permissions

SSH expects secure permissions.

Directory:

```bash
chmod 700 ~/.ssh
```

Private key:

```bash
chmod 600 ~/.ssh/id_ed25519
```

Public key:

```bash
chmod 644 ~/.ssh/id_ed25519.pub
```

---

# Verify Your Key Fingerprint

You can inspect your public key fingerprint:

```bash
ssh-keygen -lf ~/.ssh/id_ed25519.pub
```

Example output:

```
256 SHA256:AbCdEf... your_email@example.com (ED25519)
```

Fingerprints help identify keys without displaying the entire public key.

---

# Real Backend Example

Imagine:

Personal laptop:

```
id_ed25519
```

Work laptop:

```
work_ed25519
```

GitHub stores the matching public keys.

Each machine authenticates using its own private key.

If one laptop is lost, you can remove just that public key from GitHub without affecting the other.

# Common Mistakes

## ❌ Sharing the Private Key

Safe:

```
id_ed25519.pub
```

Never share:

```
id_ed25519
```

---

## ❌ Using Weak Permissions

Incorrect:

```
-rw-rw-rw-
```

Correct:

```
-rw-------
```

---

## ❌ Generating Unnecessary Keys

Before creating a new key, check:

```bash
ls ~/.ssh
```

You may already have a suitable Ed25519 key.

# Key Takeaways

- SSH authentication uses a **public/private key pair**.
- GitHub stores only your **public key**.
- The **private key never leaves your computer**.
- Ed25519 is the recommended key type for most users.
- Protect your private key with secure permissions and, ideally, a passphrase.

## Pro Tip ⭐

Before generating a new SSH key, always check whether you already have one.

Many developers accidentally create multiple unused keys, making it harder to know which one GitHub is using. A quick:

```bash
ls -la ~/.ssh
```

can save a lot of confusion.
