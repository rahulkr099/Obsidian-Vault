# SSH Mastery — Module 3, Lesson 3

# Adding Your SSH Public Key to GitHub

In the previous lesson, you created (or verified) your SSH key pair.

Now it's time to tell **GitHub** about your **public key**.

Once this is done, GitHub can recognize your computer whenever you use Git over SSH.

> **Remember:** You upload **only the public key** (`.pub` file). Your private key always stays on your computer.

---

# Learning Objectives

By the end of this lesson, you'll know how to:

- Copy your public key
- Add it to GitHub
- Name your SSH keys properly
- Verify the uploaded key
- Avoid common mistakes

---

# Before You Begin

Make sure you have:

- ✅ A GitHub account
- ✅ An SSH key

Verify your key exists:

```bash
ls ~/.ssh
```

Example:

```
id_ed25519
id_ed25519.pub
```

---

# Step 1 — View Your Public Key

Display the public key:

```bash
cat ~/.ssh/id_ed25519.pub
```

Example output:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIB... rahul@example.com
```

This is what you'll copy.

---

# Copy the Entire Line

A public key is **one long line**.

Correct:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIB... rahul@example.com
```

Incorrect:

```
ssh-ed25519 AAAAC3...
```

Do **not** copy only part of the key.

---

# Easier Copy Commands

Depending on your Linux desktop:

### X11

```bash
xclip -selection clipboard < ~/.ssh/id_ed25519.pub
```

### Wayland

```bash
wl-copy < ~/.ssh/id_ed25519.pub
```

If those utilities aren't installed, simply use:

```bash
cat ~/.ssh/id_ed25519.pub
```

and copy it manually.

---

# Step 2 — Open GitHub

Log in to your GitHub account.

Navigate to:

```
Settings
   ↓
SSH and GPG keys
```

You'll see a page listing your existing SSH keys (if any).

---

# Step 3 — Add a New SSH Key

Click:

```
New SSH key
```

You'll see two important fields.

---

## Field 1 — Title

This is just a label to help **you** identify the key.

Examples:

```
Rahul Laptop
```

```
Lenovo Mint
```

```
Office Desktop
```

Choose something descriptive.

---

## Field 2 — Key

Paste the **entire** contents of:

```
id_ed25519.pub
```

GitHub will validate the format automatically.

---

# Step 4 — Save

Click:

```
Add SSH key
```

GitHub may ask you to confirm your password or use two-factor authentication.

After confirmation, your key is stored in your GitHub account.

---

# What GitHub Stores

GitHub stores only the public key.

```
GitHub
 │
 ▼
id_ed25519.pub
```

Your private key remains on your machine:

```
Your Computer
 │
 ▼
id_ed25519
```

GitHub never receives your private key.

---

# Multiple Computers

Suppose you own:

```
Laptop

Desktop

Work PC
```

Each computer should have its **own SSH key pair**.

GitHub can store multiple public keys for the same account.

Example:

```
Rahul Laptop

Office Desktop

Home PC
```

If one device is lost, you can remove **only that device's public key**.

---

# Checking Existing Keys

On GitHub, you'll see something similar to:

```
Rahul Laptop

Last used:
Today
```

GitHub records when a key was last used, making it easier to identify active and unused keys.

---

# Why Use Separate Keys?

Imagine your work laptop is stolen.

Instead of replacing every device's key:

Simply remove:

```
Work Laptop
```

from GitHub.

Your personal laptop continues working normally.

---

# Common Mistakes

## ❌ Uploading the Private Key

Wrong:

```
id_ed25519
```

Correct:

```
id_ed25519.pub
```

Always upload the **`.pub`** file.

---

## ❌ Copying Only Part of the Key

GitHub expects the complete line.

Don't omit:

- `ssh-ed25519`
- the encoded key
- the comment at the end (optional but recommended)

---

## ❌ Giving Every Key the Same Name

Avoid:

```
Laptop
Laptop
Laptop
```

Better:

```
Rahul Mint Laptop

Office Ubuntu

Desktop Fedora
```

Descriptive names make future maintenance much easier.

## Pro Tip ⭐

If you replace your laptop or reinstall Linux, **generate a new SSH key** for the new installation instead of copying your old private key around. This keeps each device independent and makes it easy to revoke access if one device is ever lost or compromised.
