# What is Cloning?

Cloning means:

> **Creating a complete local copy of a remote Git repository.**

When you clone, Git downloads:

- All commits
- All branches
- All tags
- The project files
- The Git history

---

# Repository Example

Suppose this repository exists:

```
<https://github.com/octocat/Hello-World>
```

GitHub provides two clone URLs:

HTTPS:

```
<https://github.com/octocat/Hello-World.git>
```

SSH:

```
git@github.com:octocat/Hello-World.git
```

Both point to the same repository.

---

# Finding the SSH URL

On a GitHub repository page:

1. Click the green **Code** button.
2. Select **SSH**.
3. Copy the URL.

It will look like:

```
git@github.com:USERNAME/REPOSITORY.git
```

Example:

```
git@github.com:rahul/backend-api.git
```

---

# Clone Using SSH

Run:

```bash
git clone git@github.com:USERNAME/REPOSITORY.git
```

Example:

```bash
git clone git@github.com:rahul/backend-api.git
```

Git connects to GitHub using your SSH key.

---

# What Happens Internally?

When you run:

```bash
git clone git@github.com:rahul/backend-api.git
```

Git performs these steps:

```
Git Clone
      │
      ▼
SSH Authentication
      │
      ▼
GitHub verifies your key
      │
      ▼
Repository downloaded
      │
      ▼
New local folder created
```

If authentication succeeds, cloning begins automatically.

---

# Example

Before cloning:

```
Projects/
```

Run:

```bash
git clone git@github.com:rahul/backend-api.git
```

After:

```
Projects/
└── backend-api/
```

Now enter the project:

```bash
cd backend-api
```

---

# What Gets Created?

Inside:

```
backend-api/
```

You'll see:

```
backend-api/
├── .git/
├── package.json
├── src/
├── README.md
└── ...
```

The hidden `.git/` directory contains:

- Commit history
- Branches
- Configuration
- Remote information

---

# Verify the Remote

Inside the project:

```bash
git remote -v
```

Example output:

```
origin  git@github.com:rahul/backend-api.git (fetch)
origin  git@github.com:rahul/backend-api.git (push)
```

This confirms the repository is using SSH.

---

# Compare with HTTPS

HTTPS:

```
origin <https://github.com/rahul/backend-api.git>
```

SSH:

```
origin git@github.com:rahul/backend-api.git
```

This single line determines how Git authenticates.

# Clone a Private Repository

Private repositories work exactly the same way:

```bash
git clone git@github.com:company/private-api.git
```

If your GitHub account has permission:

✅ Clone succeeds.

If not:

```
ERROR: Repository not found.
```

Remember:

This often means **authorization**, not necessarily authentication.


Creates:

# Shallow Clone

Sometimes you only need the latest commit.

```bash
git clone --depth=1 git@github.com:rahul/backend-api.git
```

Benefits:

- Faster
- Less data downloaded

Trade-off:

- Limited Git history

This is common in CI/CD pipelines.

---

# Clone a Specific Branch

Instead of downloading the default branch:

```bash
git clone --branch develop git@github.com:rahul/backend-api.git
```

Useful when working with long-lived development branches.

# Common Mistakes

## ❌ Using the Wrong URL

Wrong:

```
git@github.com/rahul/backend-api.git
```

Notice the `/` after `github.com`.

Correct:

```
git@github.com:rahul/backend-api.git
```

SSH uses a **colon (`:`)** after the hostname.

---

## ❌ Cloning Without Permission

Private repositories require access.

Authentication alone isn't enough.

---

## ❌ Forgetting Where You Cloned

Before cloning:

```bash
pwd
```

Know your current directory.

Many beginners accidentally clone projects into unexpected locations.

---

## ❌ Assuming Clone Means Deploy

Cloning only downloads the code.

You still need to install dependencies:

```bash
npm install
```

or:

```bash
npm ci
```

# Useful Commands

Clone:

```bash
git clone git@github.com:user/repo.git
```

Clone into another directory:

```bash
git clone git@github.com:user/repo.git my-project
```

Clone a branch:

```bash
git clone --branch develop git@github.com:user/repo.git
```

Shallow clone:

```bash
git clone --depth=1 git@github.com:user/repo.git
```

Show remotes:

```bash
git remote -v
```

Show current directory:

```bash
pwd
```

---

# Key Takeaways

- Clone repositories using the SSH URL:
    
    ```
    git@github.com:user/repo.git
    ```
    
- `git clone` downloads the complete repository and its history.
    
- Use `git remote -v` to verify whether SSH is configured.
    
- Private repositories require both successful authentication and proper access permissions.
    
- SSH URLs use a **colon (`:`)** after `github.com`, not a slash.
