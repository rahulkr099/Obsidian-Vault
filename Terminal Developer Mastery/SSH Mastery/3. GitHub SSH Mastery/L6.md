# The Big Picture

Imagine you're working with a remote GitHub repository.

```
        GitHub
           ▲
           │
      Push │ Pull
           │
           ▼
      Your Computer
```

Three commands keep everything synchronized:

- `git fetch`
- `git pull`
- `git push`

---

# Understanding `git fetch`

Command:

```bash
git fetch
```

What it does:

- Contacts GitHub
- Downloads new commits
- Updates remote tracking branches
- **Does not** modify your working files

Think of it as:

> "Tell me what's new, but don't change my work."

---

## Example

Your teammate pushes 5 new commits.

You run:

```bash
git fetch
```

Git downloads those commits.

But your files stay exactly the same.

You decide later when to merge them.

---

# Understanding `git pull`

Command:

```bash
git pull
```

This is equivalent to:

```bash
git fetch
git merge
```

It:

1. Downloads new commits
2. Merges them into your current branch

Your files may change immediately.

---

## Example

GitHub:

```
main
 │
 ├── Commit A
 ├── Commit B
 └── Commit C
```

Your local copy:

```
main
 │
 └── Commit A
```

Run:

```bash
git pull
```

Result:

```
main
 │
 ├── Commit A
 ├── Commit B
 └── Commit C
```

Now you're up to date.

---

# Understanding `git push`

Command:

```bash
git push
```

This sends **your commits** to GitHub.

Example:

```
Your Computer

Commit D
Commit E
```

Run:

```bash
git push
```

GitHub becomes:

```
Commit A
Commit B
Commit C
Commit D
Commit E
```

# How SSH Fits In

When you run:

```bash
git push
```

Git internally does this:

```
git push
      │
      ▼
SSH
      │
      ▼
Private Key
      │
      ▼
GitHub
      │
      ▼
Authentication
      │
      ▼
Repository Updated
```

SSH authentication happens automatically if your keys are configured correctly.

# Push vs Pull

|Command|Direction|
|---|---|
|`git push`|Local → GitHub|
|`git pull`|GitHub → Local|

Easy way to remember:

- **Push** → Send your work
- **Pull** → Get others' work

---

# What About `git fetch`?

Many experienced developers prefer:

```bash
git fetch
```

first.

Why?

Because it lets them inspect incoming changes before merging.

Example:

```bash
git fetch
git log HEAD..origin/main --oneline
```

This shows commits on `origin/main` that you don't yet have.

If everything looks good:

```bash
git merge origin/main
```

or, if you're on the tracked branch:

```bash
git pull
```

# Common Errors

## Error 1

```
Permission denied (publickey)
```

Meaning:

SSH authentication failed.

Possible reasons:

- Wrong SSH key
- Key not uploaded to GitHub
- Wrong GitHub account

---

## Error 2

```
Everything up-to-date
```

Good news!

Nothing needs to be pushed.

---

## Error 3

```
Updates were rejected because the remote contains work that you do not have locally.
```

Someone pushed changes before you.

Solution:

```bash
git pull
```

Resolve any merge conflicts if needed, then:

```bash
git push
```

# Key Takeaways

- `git fetch` downloads updates without changing your working files.
- `git pull` downloads and integrates remote changes into your current branch.
- `git push` uploads your local commits to GitHub.
- With SSH configured, authentication is automatic during these operations.
- `git push -u origin <branch>` makes future pushes simpler by setting the upstream branch.

## Pro Tip ⭐

A good habit before starting work each day is:

```bash
git checkout main
git pull
```

Starting from an up-to-date `main` branch helps reduce merge conflicts and keeps your feature branch based on the latest code.
