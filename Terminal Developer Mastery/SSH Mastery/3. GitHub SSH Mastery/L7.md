# SSH Mastery — Module 3, Lesson 7

# Converting an Existing Repository from HTTPS to SSH

Many developers start with HTTPS because it's the default option on GitHub. Later, they decide to use SSH to avoid repeated authentication prompts.

The good news is:

> **You do NOT need to clone the repository again.**

You can simply change the repository's remote URL.

---

# Learning Objectives

By the end of this lesson, you'll know how to:

- Check the current remote URL
- Identify whether it uses HTTPS or SSH
- Change the remote from HTTPS to SSH
- Verify the change
- Test that everything still works

---

# The Problem

Suppose you cloned your project months ago using HTTPS.

Your repository currently looks like this:

```
Local Repository
        │
        ▼
<https://github.com/rahul/backend-api.git>
        │
        ▼
GitHub
```

Every push uses HTTPS authentication.

You want this instead:

```
Local Repository
        │
        ▼
git@github.com:rahul/backend-api.git
        │
        ▼
GitHub
```

---

# Step 1 — Go to Your Repository

```bash
cd ~/Projects/backend-api
```

Verify you're inside a Git repository:

```bash
git status
```

Example:

```
On branch main
nothing to commit, working tree clean
```

---

# Step 2 — Check the Current Remote

Run:

```bash
git remote -v
```

Example output:

```
origin  <https://github.com/rahul/backend-api.git> (fetch)
origin  <https://github.com/rahul/backend-api.git> (push)
```

This tells us:

- Remote name = `origin`
- Authentication = HTTPS

---

# Understanding `origin`

When you clone a repository, Git automatically creates a remote called:

```
origin
```

You can think of it as a nickname.

Instead of remembering:

```
<https://github.com/rahul/backend-api.git>
```

Git simply remembers:

```
origin
```

---

# Step 3 — Get the SSH URL

Open your repository on GitHub.

Click:

```
Code
```

Choose:

```
SSH
```

Copy something like:

```
git@github.com:rahul/backend-api.git
```

---

# Step 4 — Change the Remote

Run:

```bash
git remote set-url origin git@github.com:rahul/backend-api.git
```

Let's break it down:

|Part|Meaning|
|---|---|
|`git remote`|Manage remotes|
|`set-url`|Change the URL|
|`origin`|Remote name|
|`git@github.com:...`|New SSH URL|

---

# Step 5 — Verify the Change

Run:

```bash
git remote -v
```

Now you'll see:

```
origin  git@github.com:rahul/backend-api.git (fetch)
origin  git@github.com:rahul/backend-api.git (push)
```

Congratulations!

Your repository now uses SSH.

---

# Test the Configuration

Fetch updates:

```bash
git fetch
```

Or:

```bash
git pull
```

Or:

```bash
git push
```

If everything is configured correctly, Git authenticates using your SSH key.

# Changing SSH Back to HTTPS

You can always reverse the process.

Example:

```bash
git remote set-url origin <https://github.com/rahul/backend-api.git>
```

Git doesn't care which protocol you use.

---

# Multiple Remotes

Some repositories have more than one remote.

Example:

```bash
git remote -v
```

Output:

```
origin    git@github.com:rahul/backend-api.git
upstream  git@github.com:opensource/project.git
```

Meaning:

```
origin
```

Your fork.

```
upstream
```

Original project.

This is common in open-source development.

---

# Renaming a Remote

List remotes:

```bash
git remote
```

Rename:

```bash
git remote rename origin github
```

Now:

```
github
```

becomes the remote name.

Most teams keep the default name `origin`.

---

# Removing a Remote

Delete:

```bash
git remote remove origin
```

Be careful.

This removes the remote configuration.

It **does not** delete your code.

---

# Adding a Remote Again

Example:

```bash
git remote add origin git@github.com:rahul/backend-api.git
```

Useful if you accidentally removed it.

---

# Common Mistakes

## ❌ Wrong SSH URL

Wrong:

```
git@github.com/rahul/backend-api.git
```

Correct:

```
git@github.com:rahul/backend-api.git
```

Remember:

SSH uses a **colon (`:`)** after `github.com`.

---

## ❌ Editing `.git/config` Manually

You _can_ edit `.git/config`, but it's safer and simpler to let Git do it:

```bash
git remote set-url origin git@github.com:rahul/backend-api.git
```

---

## ❌ Forgetting to Verify

Always check:

```bash
git remote -v
```

Don't assume the change worked.

---

# Real Backend Example

Imagine you're hired by a startup.

You cloned the project six months ago using HTTPS.

The team decides to standardize on SSH.

Instead of recloning the repository:

```bash
git remote set-url origin git@github.com:company/backend-api.git
```

Done in seconds.

No files are lost.

No Git history disappears.

# Key Takeaways

- A Git remote is simply a saved shortcut to a repository URL.
- `origin` is the default remote created by `git clone`.
- `git remote set-url` changes a repository from HTTPS to SSH (or vice versa).
- Verify changes with `git remote -v`.
- Switching protocols does **not** affect your commits, branches, or project files.

## Pro Tip ⭐

A quick way to inspect all your repositories is:

```bash
find ~/Projects -name ".git" -type d
```

Then check each one:

```bash
git -C /path/to/repo remote -v
```

This is handy when migrating several projects from HTTPS to SSH.
