# SSH Mastery — Module 3, Lesson 8

# Managing Multiple GitHub Accounts with SSH ⭐⭐⭐⭐⭐

This is one of the most valuable SSH skills you'll learn.

Many developers have:

- 👤 A personal GitHub account
- 🏢 A work GitHub account
- 🌍 An open-source organization account

Without proper configuration, SSH may use the wrong key, causing confusing authentication errors.

By the end of this lesson, you'll know how to use **multiple GitHub accounts on the same computer** without conflicts.

---

# Learning Objectives

You'll learn:

- Why multiple SSH keys are useful
- How SSH chooses a key
- Create separate keys for each account
- Configure `~/.ssh/config`
- Clone repositories for the correct account
- Troubleshoot common issues

---

# The Problem

Suppose you have two GitHub accounts:

```
Personal:
rahul-personal

Work:
rahul-company
```

You generate only one SSH key:

```
~/.ssh/id_ed25519
```

Now you add it to your personal GitHub account.

Later, you clone a company repository.

When you push:

```bash
git push
```

GitHub authenticates you as:

```
rahul-personal
```

instead of

```
rahul-company
```

Result:

```
ERROR: Repository not found.
```

or

```
Permission denied.
```

---

# The Solution

Use **one SSH key per identity**.

Example:

```
~/.ssh/

id_ed25519_personal
id_ed25519_personal.pub

id_ed25519_work
id_ed25519_work.pub
```

Each GitHub account gets its own public key.

---

# Step 1 — Generate Personal Key

```bash
ssh-keygen -t ed25519 -C "rahul.personal@example.com"
```

Save as:

```
~/.ssh/id_ed25519_personal
```

---

# Step 2 — Generate Work Key

```bash
ssh-keygen -t ed25519 -C "rahul@company.com"
```

Save as:

```
~/.ssh/id_ed25519_work
```

---

# Your SSH Folder

After both keys:

```
~/.ssh/

id_ed25519_personal
id_ed25519_personal.pub

id_ed25519_work
id_ed25519_work.pub

known_hosts

config
```

---

# Add Both Public Keys

Personal GitHub:

Upload

```
id_ed25519_personal.pub
```

Work GitHub:

Upload

```
id_ed25519_work.pub
```

Each account knows only its own public key.

---

# The Magic File

Now create:

```
~/.ssh/config
```

Example:

```
Host github-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_personal

Host github-work
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_work
```

Let's understand each line.

---

## Host

```
Host github-personal
```

This is **your alias**.

It can be anything:

```
github-main

github-office

github-home
```

SSH only cares that it's unique.

---

## HostName

```
HostName github.com
```

The real server.

---

## User

Always:

```
User git
```

Never:

```
User rahul
```

GitHub always expects the SSH user to be `git`.

---

## IdentityFile

Example:

```
IdentityFile ~/.ssh/id_ed25519_work
```

This tells SSH exactly which private key to use.

---

# How It Works

Instead of cloning with:

```
git@github.com:company/backend-api.git
```

Use your alias:

```
git@github-work:company/backend-api.git
```

Notice:

```
github-work
```

is your alias—not a real hostname.

SSH reads:

```
Host github-work
```

then automatically connects to:

```
github.com
```

using the correct key.

# Common Mistakes

## ❌ Using One Key Everywhere

This works until:

- Work account
- Personal account

need different identities.

---

## ❌ Wrong Alias

Config:

```
Host github-work
```

Clone:

```
git@github-office:company/api.git
```

Aliases must match exactly.

---

## ❌ Forgetting to Upload the Public Key

Each GitHub account needs its corresponding `.pub` file.

---

## ❌ Wrong IdentityFile

Incorrect:

```
IdentityFile ~/.ssh/id_ed25519
```

when you meant:

```
IdentityFile ~/.ssh/id_ed25519_work
```

# Key Takeaways

- Use **one SSH key per GitHub identity**.
- Configure aliases in `~/.ssh/config`.
- `IdentityFile` tells SSH which private key to use.
- Clone repositories using the appropriate alias (for example, `github-work`).
- Test each account independently with `ssh -T`.

Create a sample `~/.ssh/config` (even if you only have one GitHub account today):

```
Host github-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_personal

    HostName github.com
    User git

```

> **Note:** If you currently have only one GitHub account (which is common), you **don't need multiple keys yet**. Learn this pattern now so you're ready when you join a company or maintain separate personal and work accounts.

## Pro Tip ⭐

Instead of naming keys generically, use descriptive names such as:

```
id_ed25519_github_personal
id_ed25519_github_work
id_ed25519_gitlab_work
```

As you use more Git hosting services over your career, descriptive names make your SSH configuration much easier to understand and maintain.
