# Module 4 — Lesson 12: Troubleshooting File Transfers

No matter how experienced you become, **file transfers will occasionally fail**.

The difference between a beginner and an experienced Linux engineer isn't that they never encounter errors—it's that they know **how to diagnose them quickly**.

This lesson teaches a systematic approach to troubleshooting `ssh`, `scp`, `sftp`, and `rsync`.

---

# Learning Objectives

By the end of this lesson, you'll be able to:

- Diagnose SSH connection issues
- Fix authentication failures
- Solve permission errors
- Debug `scp`, `sftp`, and `rsync`
- Understand common network problems
- Use verbose/debug modes effectively
- Follow a step-by-step troubleshooting workflow

---

# The Troubleshooting Mindset

Instead of guessing, ask these questions in order:

```
1. Can I reach the server?
        ↓
2. Can I authenticate?
        ↓
3. Do I have permission?
        ↓
4. Is my command correct?
        ↓
5. Is the destination correct?
        ↓
6. Check logs/output
```

Never change five things at once. Test one thing at a time.

# Problem 1 — Connection Refused

Example:

```bash
ssh user@server
```

Output:

```
ssh: connect to host server port 22: Connection refused
```

Meaning:

Your computer reached the server, but nothing is accepting SSH connections on that port.

Possible causes:

- SSH server isn't running
- Wrong port
- Firewall blocking access

---

## Check the SSH Service

On the server:

```bash
sudo systemctl status ssh
```

If it's stopped:

```bash
sudo systemctl start ssh
```

Enable it at boot:

```bash
sudo systemctl enable ssh
```

---

# Problem 2 — Connection Timed Out

Output:

```
Connection timed out
```

Usually means:

- Wrong IP address
- Server offline
- Firewall
- Network issue

---

## Test Connectivity

```bash
ping server-ip
```

Example:

```bash
ping 192.168.1.20
```

If `ping` fails:

- Verify the server is running.
- Confirm you're using the correct IP or hostname.
- Check VPN or network connectivity.

---

# Problem 3 — Hostname Not Found

```bash
ssh myserver
```

Output:

```
Could not resolve hostname
```

Cause:

DNS cannot resolve the hostname.

Try:

```bash
ssh user@192.168.1.20
```

Or inspect DNS:

```bash
nslookup myserver
```

---

# Problem 4 — Permission Denied (Publickey)

```
Permission denied (publickey)
```

Possible causes:

- Wrong SSH key
- Public key missing from `authorized_keys`
- Incorrect file permissions

---

## Verify Your Key

```bash
ls ~/.ssh
```

Example:

```
id_ed25519
id_ed25519.pub
```

Connect explicitly:

```bash
ssh -i ~/.ssh/id_ed25519 user@server
```

---

## Check `authorized_keys`

On the server:

```bash
cat ~/.ssh/authorized_keys
```

Ensure your public key is present.

---

# Problem 5 — Wrong File Permissions

SSH is strict about permissions.

Correct:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chmod 600 ~/.ssh/id_ed25519
```

Incorrect permissions can cause SSH to reject your key.

---

# Problem 6 — Wrong Username

Example:

```bash
ssh admin@server
```

But the actual user is:

```
rahul
```

Correct:

```bash
ssh rahul@server
```

Always verify the account name.

---

# Problem 7 — SCP: No Such File or Directory

```bash
scp file.txt user@server:/home/user/docs/
```

Output:

```
No such file or directory
```

Possible causes:

- Local file doesn't exist
- Destination directory doesn't exist
- Typo in the path

---

## Verify

Local:

```bash
ls file.txt
```

Remote:

```bash
ssh user@server "ls -ld /home/user/docs"
```

---

# Problem 8 — Permission Denied During Copy

Example:

```bash
scp file.txt user@server:/root/
```

Output:

```
Permission denied
```

Reason:

Regular users usually can't write to `/root`.

Instead:

```bash
scp file.txt user@server:/home/user/
```

Then move it with `sudo` if necessary.

---

# Problem 9 — SFTP Upload Fails

Inside SFTP:

```
put app.js
```

Output:

```
Couldn't open remote file
```

Check your location:

```
pwd
```

List files:

```
ls
```

Navigate to a writable directory:

```
cd project
```

Retry the upload.

---

# Problem 10 — `rsync` Permission Denied

```bash
rsync -av project/ user@server:/var/www/
```

Output:

```
Permission denied
```

The destination may require elevated privileges.

Copy to your home directory first:

```bash
rsync -av project/ user@server:~/project/
```

Then move it on the server with appropriate privileges if needed.

---

# Problem 11 — Trailing Slash Mistakes

Suppose:

```
project/
```

Command:

```bash
rsync -av project backup/
```

Creates:

```
backup/
└── project/
```

But:

```bash
rsync -av project/ backup/
```

Creates:

```
backup/
├── app.js
└── package.json
```

Always verify whether you intend to copy the directory itself or only its contents.

---

# Problem 12 — Host Key Changed

Output:

```
WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!
```

Possible reasons:

- Server reinstalled
- SSH host keys changed
- IP now belongs to another machine

Inspect the old entry:

```bash
ssh-keygen -F server
```

Remove the outdated key:

```bash
ssh-keygen -R server
```

Reconnect and verify the new fingerprint before accepting it.

# Using Verbose Mode

Verbose output is one of your best debugging tools.

SSH:

```bash
ssh -v user@server
```

More detail:

```bash
ssh -vv user@server
```

Maximum detail:

```bash
ssh -vvv user@server
```

You'll see:

- Key negotiation
- Authentication attempts
- Connection details

---

# Verbose `scp`

```bash
scp -v file.txt user@server:/tmp/
```

Useful for authentication and transfer issues.

---

# Verbose `rsync`

```bash
rsync -avv project/ backup/
```

Or:

```bash
rsync -av --progress project/ backup/
```

Watch exactly which files are transferred.

---

# Check Disk Space

Transfers can fail if the destination disk is full.

On the server:

```bash
df -h
```

Example:

```
Filesystem      Size Used Avail
/dev/sda1        50G  49G   1G
```

Only 1 GB remains.

---

# Check Directory Permissions

```bash
ls -ld /var/www
```

Example:

```
drwxr-xr-x root root
```

This tells you:

- Owner
- Group
- Permissions

---

# Test SSH Without Running Commands

Useful for checking connectivity:

```bash
ssh user@server exit
```

If it returns without errors:

- SSH works
- Authentication works

---

# Verify an `rsync` Command First

Instead of immediately copying:

```bash
rsync -av --delete project/ server:/project/
```

Preview:

```bash
rsync -av --delete --dry-run project/ server:/project/
```

This helps avoid accidental deletions.

---

# Useful Diagnostic Commands

|Purpose|Command|
|---|---|
|Test network|`ping server-ip`|
|Check DNS|`nslookup hostname`|
|SSH debug|`ssh -vvv user@server`|
|SCP debug|`scp -v file user@server:/tmp/`|
|View permissions|`ls -l`|
|View metadata|`stat file`|
|Check disk space|`df -h`|
|Check current directory|`pwd`|
|Check current user|`whoami`|

# Real Troubleshooting Example

Command:

```bash
rsync -avz ./ user@server:/var/www/my-app/
```

Output:

```
Permission denied
```

Step-by-step:

1. Verify SSH:

```bash
ssh user@server
```

✅ Works.

1. Check destination:

```bash
ls -ld /var/www/my-app
```

Owned by:

```
root root
```

1. Upload to your home directory:

```bash
rsync -avz ./ user@server:~/my-app/
```

1. Move files on the server with the necessary privileges.

Problem solved.

# Common Beginner Mistakes

❌ Wrong username

```bash
ssh root@server
```

Use the correct user account instead.

---

❌ Wrong path

```bash
scp app.js server:/projects
```

Verify the destination path exists.

---

❌ Missing recursive option

```bash
scp project server:/home/user/
```

Correct:

```bash
scp -r project server:/home/user/
```

---

❌ Forgetting custom SSH port

If your server uses port **2222**:

```bash
scp -P 2222 file.txt user@server:/tmp/
```

For `rsync`:

```bash
rsync -av -e "ssh -p 2222" project/ user@server:/tmp/
```

---

❌ Copying into a protected directory

Upload to your home directory first, then move files with the appropriate privileges if required.

---

# Troubleshooting Checklist

Before asking for help, verify:

- ✅ Internet/network connectivity
- ✅ Correct IP address or hostname
- ✅ Correct username
- ✅ SSH service running
- ✅ Correct SSH port
- ✅ Correct SSH key
- ✅ Correct file and directory permissions
- ✅ Sufficient disk space
- ✅ Correct source and destination paths
- ✅ Test with verbose mode (`v`, `vv`, or `vvv`)
