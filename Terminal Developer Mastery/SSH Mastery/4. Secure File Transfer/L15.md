# Step 1 — Configure SSH Keys

Generate a key if you don't already have one:

```bash
ssh-keygen -t ed25519
```

Copy the public key to the server:

```bash
ssh-copy-id deploy@server
```

Test login:

```bash
ssh deploy@server
```

You should log in without entering the server password (unless your private key is protected by a passphrase).

---

# Step 2 — Test the Application Locally

Before deploying:

```bash
npm test
```

If you don't have tests:

```bash
npm run lint
```

or

```bash
npm start
```

Never deploy code you haven't verified locally.

---

# Step 3 — Build (If Needed)

React:

```bash
npm run build
```

Node.js backend:

Usually no build is required unless you're using TypeScript or another build step.

---

# Step 4 — Backup the Current Server Version

On the server:

```bash
mkdir -p ~/backups
```

Create a timestamped backup:

```bash
rsync -av \
~/my-api/ \
~/backups/my-api-$(date +%F-%H%M)/
```

Example:

```
backups/

my-api-2026-07-29-1930/
```

Now you can recover if deployment fails.

---

# Step 5 — Create the Deployment Script

Create:

```bash
nano deploy.sh
```

Contents:

```bash
#!/bin/bash

set -e

SERVER="deploy@server"
REMOTE_DIR="/home/deploy/my-api"

echo "Starting deployment..."

rsync -avz \
  --delete \
  --exclude=node_modules \
  --exclude=.git \
  --exclude=.env \
  ./ \
  "$SERVER:$REMOTE_DIR"

ssh "$SERVER" <<'EOF'
cd /home/deploy/my-api

echo "Installing dependencies..."
npm ci

echo "Restarting PM2..."
pm2 restart my-api

echo "Health check..."
curl <http://localhost:3000/health>
EOF

echo "Deployment complete!"
```

---

# Step 6 — Make the Script Executable

```bash
chmod +x deploy.sh
```

Run:

```bash
./deploy.sh
```

# Step 7 — Understand What Happens

The script performs these steps:

```
Local

↓

rsync

↓

Server

↓

npm ci

↓

pm2 restart

↓

curl health endpoint

↓

Done
```

No manual login is required during deployment.

# Step 8 — Verify the Deployment

Check PM2:

```bash
pm2 status
```

View logs:

```bash
pm2 logs my-api
```

Health endpoint:

```bash
curl <http://localhost:3000/health>
```

Expected:

```json
{
  "status": "ok"
}
```

---

# Step 9 — Check Permissions

Ensure deployment files have the expected permissions:

```bash
ls -l
```

Example:

```
-rwxr-xr-x deploy.sh
-rw-r--r-- package.json
```

If a script isn't executable:

```bash
chmod +x deploy.sh
```

---

# Step 10 — Simulate a Failed Deployment

Imagine a deployment introduces a bug.

You notice:

```
Health check failed
```

Don't panic.

---

# Step 11 — Roll Back

Restore the previous backup:

```bash
rsync -av \
~/backups/my-api-2026-07-29-1930/ \
~/my-api/
```

Restart:

```bash
pm2 restart my-api
```

Verify:

```bash
curl <http://localhost:3000/health>
```

Application restored.

---

# Step 12 — Improve the Script

Add a dry-run option:

```bash

--dry-run \
-av \
./ \
"$SERVER:$REMOTE_DIR"
```

Preview changes before the actual deployment.

```bash

--exclude=.git
--exclude=.env
--exclude=coverage
```

# Bonus — Deployment with Git

Instead of copying files:

```
Laptop

↓

GitHub

↓

Server

git pull
```

Commands:

```bash
ssh deploy@server

cd ~/my-api

git pull

npm ci

pm2 restart my-api
```

Many teams use this approach because Git tracks every change.

---

# Bonus — Release-Based Deployment

Instead of replacing files:

```
releases/

20260728/
20260729/
20260730/

current ->
```

Workflow:

```
Upload New Release

↓

Verify

↓

Switch current

↓

Restart PM2
```

Rollback:

```
current -> previous release
```

Fast and safe.
