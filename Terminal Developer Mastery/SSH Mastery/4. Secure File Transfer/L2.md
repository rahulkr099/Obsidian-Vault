# Module 4 — Lesson 2: Copying Files to Remote Servers

In Lesson 1, you learned what `scp` is. Now we'll use it to **upload files from your local Linux machine to a remote server**.

This is one of the most common tasks you'll perform as a backend developer or DevOps engineer.

# Basic Upload Syntax

```bash
scp source_file user@host:destination_path
```

General format:

```
scp
│
├── source file (your computer)
│
└── destination (remote server)
```

Example:

```bash
scp notes.txt rahul@192.168.1.100:/home/rahul/
```

Meaning:

- Copy `notes.txt`
- To user `rahul`
- On server `192.168.1.100`
- Inside `/home/rahul/`

---

# Upload a Single File

Suppose your current directory contains:

```
project/
notes.txt
README.md
```

Upload `README.md`:

```bash
scp README.md user@server:/home/user/
```

After upload:

```
Remote Server

/home/user/

README.md
```

---

# Upload Multiple Files

SCP accepts multiple source files.

```bash
scp file1.txt file2.txt file3.txt user@server:/home/user/
```

Example:

```bash
scp README.md package.json app.js user@server:/home/user/project/
```

All three files are uploaded in one command.

---

# Upload Using Wildcards

Upload every JavaScript file:

```bash
scp *.js user@server:/home/user/project/
```

Upload all text files:

```bash
scp *.txt user@server:/tmp/
```

Upload all images:

```bash
scp *.png user@server:/images/
```

---

# Upload to Different Directories

## Home directory

```bash
scp file.txt user@server:~
```

`~` means the remote user's home directory.

Equivalent to:

```
/home/user/
```

---

## Current remote directory

```bash
scp file.txt user@server:.
```

Here, `.` refers to the **current directory on the remote side** (usually your login directory when using SCP).

---

## Absolute path

```bash
scp app.js user@server:/var/www/html/
```

Starts from the root directory `/`.

---

## Relative path

```bash
scp app.js user@server:projects/demo/
```

This path is relative to the remote user's home directory.

---

# Absolute vs Relative Paths

Absolute:

```
/var/www/html/app.js
```

Always starts with `/`.

Relative:

```
projects/demo/
```

Starts from:

```
/home/user/
```

---

# Upload Using an IP Address

Instead of a hostname:

```bash
scp app.js rahul@192.168.10.5:/home/rahul/
```

This is common in local networks and cloud servers.

---

# Upload Using a Domain Name

```bash
scp app.js rahul@example.com:/home/rahul/
```

The domain resolves to the server's IP address.

---

# Upload Using a Custom SSH Port

By default, SSH uses port `22`.

If your server uses port `2222`:

```bash
scp -P 2222 app.js user@server:/home/user/
```

Remember:

```
-P
```

Uppercase `P`.

Lowercase `-p` preserves timestamps and permissions.

---

# Upload Using an SSH Key

If your key is the default (`~/.ssh/id_ed25519`), SCP usually finds it automatically.

If you're using a different key:

```bash
scp -i ~/.ssh/my_key app.js user@server:/home/user/
```

This is common when managing multiple servers.

---

# Combine Options

Example:

```bash
scp -P 2222 -i ~/.ssh/prod_key app.js user@server:/var/www/
```

This command:

- Uses port `2222`
- Uses a specific SSH key
- Uploads `app.js`

---

# Verify the Upload

Log in:

```bash
ssh user@server
```

Check the file:

```bash
ls -l /home/user/
```

Or verify directly:

```bash
ssh user@server "ls -l /home/user/"
```

You can also inspect the file:

```bash
ssh user@server "cat /home/user/README.md"
```

# Common Upload Examples

## Upload a Node.js application file

```bash
scp server.js user@server:/home/user/app/
```

---

## Upload a Docker Compose file

```bash
scp docker-compose.yml user@server:/home/user/
```

---

## Upload an Nginx configuration

```bash
scp nginx.conf user@server:/etc/nginx/sites-available/
```

> Note: Writing to system directories like `/etc/nginx` often requires appropriate permissions. A common approach is to upload to your home directory first, then move the file with `sudo` after logging in.

---

## Upload a backup

```bash
scp backup.sql user@server:/backups/
```

---

## Upload environment variables

```bash
scp .env user@server:/home/user/project/
```

Be careful with `.env` files because they often contain secrets.

# Common Errors

## Error 1

```
No such file or directory
```

Cause:

```bash
scp abc.txt user@server:/home/user/
```

But `abc.txt` doesn't exist locally.

Check:

```bash
ls
```

---

## Error 2

```
Permission denied
```

Possible reasons:

- Wrong username
- Wrong SSH key
- No permission to write to the destination directory

---

## Error 3

```
Connection refused
```

Possible reasons:

- SSH service isn't running
- Wrong IP address
- Wrong port
- Firewall blocking the connection

---

## Error 4

```
Could not resolve hostname
```

Cause:

```bash
scp file.txt user@myserver
```

But `myserver` isn't a resolvable hostname.

Try:

```bash
ping myserver
```

Or use the server's IP address.

# Real-World MERN Deployment Example

Imagine your project structure:

```
my-app/
├── server.js
├── package.json
├── .env
└── src/
```

A simple workflow:

1. Upload the project directory:
    
    ```bash
    scp -r my-app user@server:/home/user/
    ```
    
2. Log into the server:
    
    ```bash
    ssh user@server
    ```
    
3. Install dependencies:
    
    ```bash
    cd ~/my-app
    npm install
    ```
    
4. Start the application (or use a process manager such as PM2 if you've set one up).
    

> Later in this module, you'll learn how `rsync` makes repeated deployments much faster by transferring only changed files.

---

# Best Practices

- Use SSH keys instead of passwords whenever possible.
- Double-check the destination path before uploading.
- Keep sensitive files (like `.env`) secure.
- Test with a small file before transferring large directories.
- Use descriptive filenames to avoid confusion.
