# Module 4 — Lesson 3: Copying Files from Remote Servers

In the previous lesson, you learned how to **upload** files to a server.

Now you'll learn the opposite: **downloading files from a remote Linux server to your local computer**.

This is something backend developers do constantly—downloading logs, database backups, configuration files, SSL certificates, and application artifacts.

---

# Learning Objectives

By the end of this lesson, you'll be able to:

- Download a single file
- Download multiple files
- Download directories
- Save files to a specific local folder
- Use wildcards
- Download using SSH keys
- Download using custom SSH ports
- Troubleshoot common download errors

---

# Basic Syntax

The only difference from uploading is that the **source** is now on the remote server.

```bash
scp user@host:/remote/path/file.txt local_destination
```

General format:

```
Remote Server
      │
      │ Source
      ▼
Local Computer
      │
      │ Destination
      ▼
Downloaded File
```

---

# Download a Single File

Suppose the server has:

```
/home/rahul/

report.pdf
```

Download it:

```bash
scp rahul@server:/home/rahul/report.pdf .
```

The `.` means:

> Save it in the current local directory.

---

# Example

Current local directory:

```
Downloads/
```

Run:

```bash
scp user@server:/home/user/report.pdf .
```

Now:

```
Downloads/

report.pdf
```

---

# Download to Another Directory

Instead of saving in the current directory:

```bash
scp user@server:/home/user/report.pdf ~/Documents/
```

Result:

```
~/Documents/report.pdf
```

---

# Rename While Downloading

You can change the filename during download.

```bash
scp user@server:/var/log/nginx/access.log nginx-log.txt
```

Local file:

```
nginx-log.txt
```

The original server file remains unchanged.

---

# Download Multiple Files

Download several files in one command.

```bash
scp user@server:/home/user/file1.txt \
    user@server:/home/user/file2.txt \
    .
```

Or on one line:

```bash
scp user@server:/home/user/file1.txt user@server:/home/user/file2.txt .
```

---

# Download Using Wildcards

Download every log file:

```bash
scp user@server:/var/log/*.log .
```

Download every text file:

```bash
scp user@server:/tmp/*.txt .
```

Download every image:

```bash
scp user@server:/images/*.png .
```

> **Note:** Wildcards are expanded by the remote shell. If your shell tries to expand them locally, quote the remote path:
> 
> ```bash
> scp 'user@server:/var/log/*.log' .
> ```

---

# Download with an SSH Key

Default SSH key:

```
~/.ssh/id_ed25519
```

SCP usually uses it automatically.

Specify another key:

```bash
scp -i ~/.ssh/prod_key user@server:/backup.sql .
```

---

# Download from a Custom SSH Port

Default port:

```
22
```

Custom port:

```bash
scp -P 2222 user@server:/backup.sql .
```

Remember:

```
-P
```

Uppercase `P`.

---

# Combine Options

Example:

```bash
scp -P 2222 -i ~/.ssh/prod_key user@server:/backup.sql .
```

This:

- Uses SSH port 2222
- Uses the specified SSH key
- Downloads `backup.sql`

---

# Download a Large Backup

Example:

```bash
scp user@server:/backups/database.sql .
```

Now you have:

```
database.sql
```

on your local computer.

---

# Download Configuration Files

Example:

```bash
scp user@server:/etc/nginx/nginx.conf .
```

You now have:

```
nginx.conf
```

for inspection or backup.

---

# Download Logs

One of the most common tasks.

```bash
scp user@server:/var/log/nginx/error.log .
```

or

```bash
scp user@server:/var/log/nginx/access.log .
```

This is useful when investigating production issues.

---

# Download SSL Certificates

```bash
scp user@server:/etc/ssl/certs/site.crt .
```

Or:

```bash
scp user@server:/etc/letsencrypt/live/example.com/fullchain.pem .
```

> Access to these files usually requires appropriate permissions on the server.

---

# Download Application Builds

Example:

```bash
scp user@server:/var/www/app.zip .
```

Now you have a copy for backup or testing.

---

# Save to a Different Local Folder

Current folder:

```
~/Downloads
```

Save somewhere else:

```bash
scp user@server:/backup.sql ~/Desktop/backups/
```

Result:

```
Desktop/
└── backups/
    └── backup.sql
```

---

# Verify the Download

Check that the file exists:

```bash
ls -lh
```

Or inspect its contents:

```bash
cat backup.sql
```

Or compare file sizes:

```bash
du -h backup.sql
```

# Common Errors

## Error 1

```
No such file or directory
```

Cause:

The remote file doesn't exist.

Check:

```bash
ssh user@server "ls -l /path/file"
```

---

## Error 2

```
Permission denied
```

Possible reasons:

- Wrong username
- Wrong SSH key
- No permission to read the remote file

---

## Error 3

```
Connection refused
```

Possible causes:

- SSH server isn't running
- Wrong IP address
- Wrong SSH port
- Firewall issue

---

## Error 4

```
Host key verification failed
```

This means the server's SSH identity doesn't match what your computer expects.

Inspect your SSH known hosts:

```bash
cat ~/.ssh/known_hosts
```

If the server was legitimately rebuilt or its SSH keys changed, verify the new fingerprint with the server administrator before updating your `known_hosts` file.

# Best Practices

- Verify the remote path before downloading.
- Keep backups organized in dedicated folders.
- Use SSH keys instead of passwords.
- Protect downloaded secrets like `.env` files and certificates.
- Confirm downloads using `ls -lh` or checksums if integrity matters.
