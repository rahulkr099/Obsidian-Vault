# Module 4 — Lesson 5: SFTP Interactive Mode

In the previous lessons, you used **`scp`**, where each transfer requires a separate command.

Now you'll learn **SFTP (SSH File Transfer Protocol)**, which lets you open an **interactive file transfer session**. You connect once, then browse directories, upload files, download files, create folders, and more—all without reconnecting.

> Think of it like an FTP client, but secured with SSH.

- Exiting an SFTP session

# What is SFTP?

**SFTP (SSH File Transfer Protocol)** is a protocol that allows you to:

- Browse remote files
- Upload files
- Download files
- Rename files
- Delete files
- Create directories
- Navigate folders

All over an **encrypted SSH connection**.

---

# SCP vs SFTP

## SCP

One command = One transfer

```bash
scp app.js user@server:/home/user/
```

After the file is copied:

✔ Connection closes.

---

## SFTP

One connection = Many operations

```bash
sftp user@server
```

Now you stay connected.

Example:

```
sftp> ls
sftp> cd project
sftp> put app.js
sftp> put package.json
sftp> mkdir uploads
sftp> get logs.txt
sftp> exit
```

Much more convenient for working with many files.

---

# How SFTP Works

```
Local Computer
       │
       │
Encrypted SSH Connection
       │
       ▼
Remote Linux Server
```

Exactly like SSH.

---

# SFTP Uses SSH

SFTP uses:

- SSH encryption
- SSH authentication
- SSH keys
- SSH ports

If SSH works:

```bash
ssh user@server
```

then SFTP usually works:

```bash
sftp user@server
```

---

# Starting an SFTP Session

Basic command:

```bash
sftp user@server
```

Example:

```bash
sftp rahul@192.168.1.20
```

Output:

```
Connected to 192.168.1.20.

sftp>
```

Now you're inside the SFTP shell.

---

# The SFTP Prompt

You'll see:

```
sftp>
```

This is similar to:

```bash
$
```

in a normal shell.

Except:

You're now using **SFTP commands**, not regular Linux commands.

---

# Authentication

## Password

```bash
sftp user@server
```

Prompt:

```
Password:
```

Enter your password.

---

## SSH Key

If you've configured an SSH key:

```bash
sftp user@server
```

No password is needed.

Specify another key:

```bash
sftp -i ~/.ssh/prod_key user@server
```

---

# Custom SSH Port

Default:

```
22
```

Custom:

```bash
sftp -P 2222 user@server
```

Notice:

Uppercase:

```
-P
```

Same as `scp`.

---

# Verbose Mode

Useful for debugging.

```bash
sftp -v user@server
```

You'll see details about:

- Authentication
- SSH negotiation
- Encryption
- Connection

---

# Remote Working Directory

After login:

```
sftp> pwd
```

Example:

```
Remote working directory:
/home/rahul
```

This shows where you are on the **remote server**.

---

# Local Working Directory

SFTP also keeps track of your **local** directory.

Check it:

```
sftp> lpwd
```

Example:

```
Local working directory:
/home/rahul/projects
```

Notice:

- `pwd` → Remote
- `lpwd` → Local

The `l` stands for **local**.

---

# Changing Remote Directory

Move to another remote folder:

```
sftp> cd project
```

Now:

```
pwd
```

shows:

```
/home/rahul/project
```

---

# Changing Local Directory

Move locally:

```
sftp> lcd ~/Downloads
```

Check:

```
sftp> lpwd
```

Output:

```
/home/rahul/Downloads
```

---

# Listing Files

Remote:

```
sftp> ls
```

Output:

```
app.js
package.json
README.md
```

---

Local:

```
sftp> lls
```

Output:

```
Downloads
Desktop
Pictures
```

Again:

- `ls` → Remote
- `lls` → Local

---

# Session Example

Connect:

```bash
sftp rahul@server
```

Inside SFTP:

```
sftp> pwd
/home/rahul

sftp> lpwd
/home/rahul/projects

sftp> ls

project
logs
backup.sql

sftp> cd project

sftp> pwd
/home/rahul/project

sftp> lcd ~/Downloads

sftp> lpwd
/home/rahul/Downloads
```

Notice:

You're navigating **both** systems independently.

---

# Exit SFTP

Several ways:

```
exit
```

or

```
bye
```

or

```
quit
```

Example:

```
sftp> exit
```

Connection closes.

# Real-World Example

Imagine you're fixing a production bug.

Instead of:

```bash
scp app.js ...

```

You simply do:

```bash
sftp user@server
```

Then:

```

put app.js

get logs.txt

```

One connection.

Multiple operations.

# Common Connection Errors

## Connection Refused

```
ssh: connect to host server port 22:
Connection refused
```

Possible causes:

- SSH service is not running
- Wrong IP address
- Wrong port
- Firewall blocking access

---

## Permission Denied

```
Permission denied (publickey,password)
```

Possible reasons:

- Wrong username
- Wrong password
- Wrong SSH key
- Public key not installed on the server

---

## Host Key Verification Failed

```
Host key verification failed
```

The server's SSH identity doesn't match what your computer expects.

Verify the server's new host key before updating your `~/.ssh/known_hosts` file.

---

# Best Practices

- Use SSH keys instead of passwords.
- Keep only one SFTP session open per server unless you need multiple.
- Confirm your current directory with `pwd` and `lpwd` before transferring files.
- Use `v` if you're troubleshooting connection problems.
- Log out with `exit`, `bye`, or `quit` when you're finished.
