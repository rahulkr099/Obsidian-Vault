# What is `rsync`?

`rsync` stands for **Remote Sync**.

It is a tool that synchronizes files and directories between two locations.

Those locations can be:

- Local → Local
- Local → Remote
- Remote → Local
- Remote → Remote (via SSH or other methods)

Unlike `scp`, `rsync` is designed to copy **only what has changed**.

---

# Why was `rsync` created?

Imagine your MERN project:

```
my-app/

server.js
package.json
src/
public/
node_modules/
```

Size:

```
500 MB
```

You deploy it:

```bash
scp -r my-app user@server:/home/user/
```

Everything is copied.

---

Next day:

You change only:

```
server.js
```

Size:

```
5 KB
```

Using `scp` again:

```bash
scp -r my-app user@server:/home/user/
```

Uploads:

```
500 MB
```

again.

Very inefficient.

---

Using `rsync`:

```bash
rsync -av my-app/ user@server:/home/user/my-app/
```

Uploads:

```
server.js

5 KB
```

Only the changed file.

Huge difference.

---

# How `rsync` Works

```
Local Folder
      │
      │
Compare
      │
      ▼
Remote Folder
      │
      │
Only Differences
      ▼
Transferred
```

Instead of blindly copying everything, `rsync`:

- compares files
- checks sizes
- checks timestamps (by default)
- transfers only differences

---

# Basic Syntax

```bash
rsync [options] source destination
```

Example:

```bash
rsync file.txt backup/
```

Works like:

```bash
cp file.txt backup/
```

But much smarter.

---

# Local → Local

Copy a directory:

```bash
rsync -av project backup/
```

Result:

```
backup/

project/
```

---

# Local → Remote

```bash
rsync -av project/ user@server:/home/user/project/
```

Uses SSH automatically when the destination is remote.

---

# Remote → Local

```bash
rsync -av user@server:/home/user/project/ .
```

Downloads the project.

---

# Remote → Remote

Possible:

```bash
rsync -av user1@server1:/backup/ \
user2@server2:/backup/
```

This may require additional SSH setup depending on the servers.

---

# Understanding the Important Options

---

## `a`

Archive mode.

This is the most commonly used option.

```bash
rsync -a project/ backup/
```

Archive mode preserves:

- directory structure
- file permissions
- timestamps
- symbolic links
- recursive copying
- ownership (when permitted)
- group information (when permitted)

Think:

> Copy everything while keeping important metadata intact.

---

## `v`

Verbose mode.

```bash
rsync -av project/ backup/
```

Output:

```
sending incremental file list

server.js
package.json

sent 4,000 bytes
received 100 bytes
```

Useful for seeing what is happening.

---

## `z`

Compression.

```bash
rsync -avz project/ user@server:/home/user/
```

Before sending:

```
Files
↓
Compressed
↓
Transferred
↓
Decompressed
```

Great for slower network connections.

---

# The Famous Combination

Almost every Linux engineer knows this command:

```bash
rsync -avz source destination
```

It means:

- archive
- verbose
- compress

You'll use it frequently.

---

# Dry Run

Probably the safest option.

```bash
rsync -av --dry-run project/ server:/project/
```

Nothing is copied.

Instead:

```
Would transfer:

server.js
package.json
README.md
```

Perfect before syncing important directories.

---

# Understanding Trailing Slashes

This is the biggest beginner mistake.

Suppose:

```
project/

app.js
```

---

## Without Slash

```bash
rsync -av project backup/
```

Result:

```
backup/

project/
    app.js
```

The **directory** is copied.

---

## With Slash

```bash
rsync -av project/ backup/
```

Result:

```
backup/

app.js
```

Only the **contents** are copied.

This small slash changes the result completely.

---

# Practical Example

Suppose:

```
my-app/

server.js
package.json
src/
```

Deploy:

```bash
rsync -avz my-app/ user@server:/home/user/my-app/
```

First deployment:

```
Transferred

server.js
package.json
src/
```

---

Later:

Only:

```
server.js
```

changed.

Run the same command again.

Output:

```
sending incremental file list

server.js
```

Only the modified file is transferred.

# Using SSH

`rsync` uses SSH with the `-e` option.

Default SSH:

```bash
rsync -avz project/ user@server:/home/user/
```

Custom SSH port:

```bash
rsync -avz -e "ssh -p 2222" project/ user@server:/home/user/
```

Different SSH key:

```bash
rsync -avz \
-e "ssh -i ~/.ssh/prod_key" \
project/ \
user@server:/home/user/
```

Both:

```bash
rsync -avz \
-e "ssh -p 2222 -i ~/.ssh/prod_key" \
project/ \
user@server:/home/user/
```

# Viewing Progress

For large transfers:

```bash
rsync -av --progress project/ backup/
```

Output:

```
server.js

2,540,000 100%
```

Useful for big backups.

# SCP vs `rsync`

|Feature|`scp`|`rsync`|
|---|---|---|
|One-time copy|✅|✅|
|Incremental transfer|❌|✅|
|Preserve metadata|Limited|✅ (`-a`)|
|Compression|✅ (`-C`)|✅ (`-z`)|
|Progress display|Limited|✅ (`--progress`)|
|Dry run|❌|✅ (`--dry-run`)|
|Efficient for deployments|❌|✅|

# Common Mistakes

## Forgetting the trailing slash

```bash
rsync -av project backup/
```

copies:

```
backup/
└── project/
```

But:

```bash
rsync -av project/ backup/
```

copies:

```
backup/
├── app.js
└── package.json
```

Always double-check what you intend.

---

## Forgetting archive mode

```bash
rsync project backup/
```

Without `-a`, important metadata such as permissions, timestamps, and recursive directory handling won't behave as expected.

---

## Not using `-dry-run`

When syncing important data:

```bash
rsync -av --dry-run project/ server:/project/
```

Review the output before performing the real transfer.

---

# Best Practices

- Use `a` for almost all directory synchronizations.
- Add `v` while learning or troubleshooting.
- Use `z` for transfers over slower networks.
- Test with `-dry-run` before syncing important directories.
- Pay close attention to trailing slashes—they change the destination layout.
- Prefer `rsync` over `scp` for repeated deployments.

|Local → Local|`rsync -av src/ dest/`|
|Local → Remote|`rsync -avz src/ user@server:/path/`|
