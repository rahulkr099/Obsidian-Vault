# Module 4 — Lesson 8: Efficient Synchronization with `rsync`

In Lesson 7, you learned the basics of `rsync`.

Now we'll learn the features that make `rsync` the **industry standard** for deployments, backups, and server synchronization.

By the end of this lesson, you'll understand why companies rarely deploy applications with `scp`.

---

# Learning Objectives

You'll learn how to:

- Delete removed files (`-delete`)
- Exclude files and folders (`-exclude`)
- Include specific files (`-include`)
- Compare files using checksums (`-checksum`)
- Skip newer files (`-update`)
- Ignore existing files (`-ignore-existing`)
- Limit bandwidth (`-bwlimit`)
- Build fast deployment workflows

# How `rsync` Synchronizes

Suppose:

Local project:

```
project/
├── app.js
├── package.json
├── README.md
```

Remote server:

```
project/
├── app.js
├── package.json
├── README.md
```

Everything is synchronized.

---

You edit only:

```
app.js
```

Run:

```bash
rsync -av project/ user@server:/home/user/project/
```

Result:

```
Transferred:

app.js
```

Only the changed file moves.

---

# `-delete`

One of the most important options.

Suppose:

Local:

```
project/

app.js
package.json
```

Remote:

```
project/

app.js
package.json
old.js
```

You deleted:

```
old.js
```

locally.

Without:

```
--delete
```

Remote becomes:

```
app.js
package.json
old.js
```

`old.js` stays forever.

---

Using:

```bash
rsync -av --delete project/ user@server:/home/user/project/
```

Result:

```
Remote

app.js
package.json
```

`old.js` is removed.

---

## Why is this useful?

Imagine deploying a React app.

Yesterday:

```
main.12345.js
```

Today:

```
main.98765.js
```

Without:

```
--delete
```

the server contains:

```
main.12345.js
main.98765.js
```

Unused files accumulate.

- `-delete` keeps the destination matching the source.

---

## Be Careful

Never use:

```bash
rsync -av --delete
```

unless you're certain the source directory is correct.

A typo in the source path can delete many files on the destination.

Always test first:

```bash
rsync -av --delete --dry-run project/ server:/project/
```

# `-exclude`

Ignore files or directories.

Example:

```bash
rsync -av \
--exclude=node_modules \
project/ backup/
```

Result:

```
Copied

app.js
package.json
src/
```

Ignored:

```
node_modules/
```

---

## Exclude Multiple Items

```bash
rsync -av \
--exclude=node_modules \
--exclude=.git \
--exclude=.env \
project/ server:/project/
```

Ignored:

- `node_modules`
- `.git`
- `.env`

---

## Exclude Log Files

```bash
rsync -av \
--exclude="*.log" \
project/ backup/
```

Skipped:

```
error.log
access.log
```

---

# `-include`

Transfer only matching files.

Example:

```bash
rsync -av \
--include="*.js" \
--exclude="*" \
project/ backup/
```

Copied:

```
app.js
server.js
config.js
```

Skipped:

```
README.md
logo.png
```

---

# `-checksum`

Normally `rsync` compares:

- file size
- modification time

Sometimes timestamps are unreliable.

Use:

```bash
rsync -av --checksum source/ backup/
```

Now `rsync` compares the actual file contents.

This is slower but more accurate.

---

# `-update`

Skip files that are newer on the destination.

Example:

```bash
rsync -av --update source/ backup/
```

Useful when the destination contains newer edits you don't want to overwrite.

---

# `-ignore-existing`

Copy only files that don't already exist.

Example:

```bash
rsync -av --ignore-existing source/ backup/
```

Suppose:

Source:

```
A
B
C
```

Destination:

```
A
```

Result:

```
Copied

B
C
```

`A` remains unchanged.

---

# `-existing`

The opposite behavior.

```bash
rsync -av --existing source/ backup/
```

Only updates files already present.

New files are skipped.

---

# `-progress`

Show live transfer progress.

```bash
rsync -av --progress source/ backup/
```

Output:

```
video.mp4

210 MB
54%
```

Useful for large backups.

---

# `-bwlimit`

Limit bandwidth usage.

Example:

```bash
rsync -av \
--bwlimit=1000 \
source/ backup/
```

Approximately:

```
1000 KB/s
```

Useful when syncing over a shared internet connection.

---

# `-stats`

Display a transfer summary.

```bash
rsync -av --stats source/ backup/
```

Example:

```
Number of files: 245

Transferred: 3

Deleted: 1

Total size: 150 MB
```

Great for backup reports.

---

# `-human-readable`

Makes sizes easier to read.

Instead of:

```
104857600
```

You'll see:

```
100M
```

Example:

```bash
rsync -avh source/ backup/
```

The `-h` flag enables human-readable output.

---

# Combining Options

Professional deployments often combine several options:

```bash
rsync -avzh \
--delete \
--progress \
project/ \
user@server:/var/www/project/
```

Meaning:

- Archive mode
- Verbose output
- Compression
- Human-readable sizes
- Delete removed files
- Show progress

# MERN Deployment Example

Suppose:

```
study-notion/

client/
server/
node_modules/
.git/
.env
```

Deploy:

```bash
rsync -avz \
--delete \
--exclude=node_modules \
--exclude=.git \
--exclude=.env \
study-notion/ \
rahul@server:/home/rahul/study-notion/
```

Result:

Uploaded:

```
client/
server/
package.json
```

Skipped:

```
node_modules/
.git/
.env
```

Deleted:

Files removed locally are also removed remotely.

This is a common deployment pattern.

This keeps the web server in sync with your latest build.

# Common Mistakes

## Forgetting `-delete`

Old files remain on the destination and may cause confusion or unexpected behavior.

---

## Syncing `node_modules`

Avoid:

```bash
rsync -av project/ server:/project/
```

if it includes `node_modules`.

Instead:

```bash
rsync -av \
--exclude=node_modules \
project/ server:/project/
```

Install dependencies on the server with:

```bash
npm install
```

or:

```bash
npm ci
```

---

## Forgetting `-dry-run`

Before using:

```bash
--delete
```

always preview:

```bash
rsync -av --delete --dry-run project/ server:/project/
```

---

## Forgetting the Trailing Slash

Remember:

```bash
rsync -av project backup/
```

Copies:

```
backup/project/
```

While:

```bash
rsync -av project/ backup/
```

Copies:

```
backup/
├── app.js
└── package.json
```

---

# Best Practices

- Always preview destructive synchronizations with `-dry-run`.
- Exclude `node_modules`, `.git`, and other unnecessary directories during deployments.
- Use `-delete` only when you want the destination to exactly match the source.
- Add `h` and `-progress` for easier monitoring.
- Use `-checksum` only when you truly need content-based verification because it is slower.

---

# Quick Reference

|Task|Command|
|---|---|
|Delete removed files|`rsync -av --delete src/ dest/`|
|Preview changes|`rsync -av --dry-run src/ dest/`|
|Exclude a folder|`rsync -av --exclude=node_modules src/ dest/`|
|Exclude logs|`rsync -av --exclude="*.log" src/ dest/`|
|Include only JS files|`rsync -av --include="*.js" --exclude="*" src/ dest/`|
|Compare by checksum|`rsync -av --checksum src/ dest/`|
|Skip newer destination files|`rsync -av --update src/ dest/`|
|Show progress|`rsync -av --progress src/ dest/`|
|Human-readable output|`rsync -avh src/ dest/`|
|Limit bandwidth|`rsync -av --bwlimit=1000 src/ dest/`|

# Summary

You now know how to:

- Keep two directories perfectly synchronized
- Remove outdated files with `-delete`
- Exclude unnecessary files and folders
- Transfer only selected files with `-include`
- Compare file contents with `-checksum`
- Protect newer destination files with `-update`
- Preview changes safely using `-dry-run`
- Build efficient deployment and backup workflows

These options are the reason `rsync` is trusted for production deployments.
