# Module 4 — Lesson 9: Preserving Permissions and Timestamps

One of the biggest differences between **copying files** and **deploying applications** is **metadata**.

A file is more than just its contents. It also has:

- Permissions
- Owner
- Group
- Timestamps
- Symbolic links
- Extended attributes (optional)
- ACLs (optional)

If these are copied incorrectly, applications may stop working even though all the files are present.

# What is File Metadata?

Every Linux file contains two parts:

```
File
├── Content
└── Metadata
```

Example:

```
File: app.js

Content:
console.log("Hello");
```

Metadata:

```
Owner: rahul
Group: developers
Permissions: rw-r--r--
Modified: July 29
```

When copying files, you may want to preserve both the content and the metadata.

---

# Viewing Metadata

Use:

```bash
ls -l
```

Example:

```
-rwxr-xr-x 1 rahul developers 1245 Jul 29 app.js
```

Breakdown:

```
-rwxr-xr-x

│
├── File type
├── Owner permissions
├── Group permissions
└── Others permissions
```

---

# Understanding Permissions

Example:

```

```

Meaning:

```

Write

```

```
Group

Read
Execute
```

```
Others

Read
```

# Why Permissions Matter

Suppose:

```
deploy.sh
```

Permissions:

```
-rwxr-xr-x
```

Run:

```bash
./deploy.sh
```

Works.

---

Now suppose the execute permission is lost:

```
-rw-r--r--
```

Run:

```bash
./deploy.sh
```

Output:

```
Permission denied
```

The file is present—but it isn't executable.

# File Ownership

Every Linux file has:

```
Owner
Group
```

Example:

```
-rw-r--r-- rahul developers app.js
```

Owner:

```
rahul
```

Group:

```
developers
```

---

# Why Ownership Matters

Suppose:

```
/var/www/app
```

belongs to:

```
www-data
```

But after copying:

```
Owner

rahul
```

Now your web server may not have the expected ownership, which can cause permission problems depending on how it's configured.

---

# Timestamps

Linux stores several timestamps.

View them:

```bash
stat app.js
```

Example:

```
Access:
Modify:
Change:
Birth:
```

The most important is:

```
Modify
```

This tells you when the file content was last changed.

---

# Why Timestamps Matter

Many tools rely on modification time.

Examples:

- `make`
- build systems
- incremental backups
- `rsync`
- deployment tools

Changing timestamps unnecessarily can trigger unnecessary rebuilds or transfers.

---

# Preserving Metadata with `scp`

By default:

```bash
scp file.txt user@server:/tmp/
```

copies the file, but timestamps and permissions may not be preserved.

Use:

```bash
scp -p file.txt user@server:/tmp/
```

- `p`

Preserves:

- modification time
- access time
- file mode (permissions)

---

# Preserving Metadata with `rsync`

Use archive mode:

```bash
rsync -a source/ backup/
```

Archive mode preserves:

- permissions
- timestamps
- symbolic links
- recursive directories
- device files (where applicable)
- owner (when permitted)
- group (when permitted)

---

# The Meaning of `a`

- `a` is equivalent to:

```
-rlptgoD
```

Meaning:

|Option|Purpose|
|---|---|
|`-r`|Recursive|
|`-l`|Preserve symbolic links|
|`-p`|Preserve permissions|
|`-t`|Preserve modification times|
|`-g`|Preserve group|
|`-o`|Preserve owner (requires appropriate privileges)|
|`-D`|Preserve device and special files|

Most of the time, you can simply use:

```bash
rsync -a
```

---

# Symbolic Links

Suppose:

```
current -> release-5
```

This is a symbolic link.

Without preserving links, it may be copied as the linked file or directory instead of remaining a link.

With:

```bash
rsync -a
```

the symbolic link remains:

```
current -> release-5
```

Project:

```

```

# Common Permission Problems

## Problem 1

```
Permission denied
```

Cause:

Script isn't executable.

Fix:

```bash
chmod +x deploy.sh
```

---

## Problem 2

```
Permission denied
```

when writing.

Check:

```bash
ls -ld /destination
```

You may not have write permission.

---

## Problem 3

Application cannot read a file.

Check:

```bash
ls -l
```

The permissions may be too restrictive.

---

## Problem 4

Wrong owner.

Example:

```
rahul
```

Instead of:

```
www-data
```

If you have the required privileges, fix it with:

```bash
sudo chown -R www-data:www-data /var/www/my-app
```

---

# `chmod` Review

Numeric:

```bash
chmod 755 deploy.sh
```

Readable:

```bash
chmod +x deploy.sh
```

Remove execute:

```bash
chmod -x deploy.sh
```

---

# `chown` Review

Change owner:

```bash
sudo chown rahul app.js
```

Owner and group:

```bash
sudo chown rahul:developers app.js
```

Recursive:

```bash
sudo chown -R rahul:developers project/
```

---

# `chgrp` Review

Change group:

```bash
chgrp developers app.js
```

# When Should You Preserve Metadata?

|Scenario|Preserve Metadata?|
|---|---|
|Deploying applications|✅ Yes|
|Backups|✅ Yes|
|Syncing servers|✅ Yes|
|Copying personal documents|Usually yes|
|Sharing files with different ownership requirements|Depends on the destination|

---

# Best Practices

- Use `rsync -a` for most deployments and backups.
- Use `scp -p` when you want to preserve timestamps and permissions.
- Check permissions with `ls -l` after deployment.
- Use `stat` to inspect timestamps when troubleshooting.
- Grant only the permissions required—avoid making everything executable.

---

# Quick Reference

|Task|Command|
|---|---|
|Preserve metadata with `scp`|`scp -p file.txt user@server:/path/`|

|Change owner and group|`sudo chown user:group file`|
|Change group|`chgrp group file`|
