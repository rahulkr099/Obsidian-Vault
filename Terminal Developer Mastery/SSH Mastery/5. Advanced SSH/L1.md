# Module 5 — Advanced SSH

# Lesson 1: `ssh-agent` — SSH Authentication Without Repeated Passphrase Entry

Until now, you've been using SSH keys directly.

This lesson introduces **`ssh-agent`**, a small background program that securely stores your decrypted SSH keys in memory, so you don't have to type your passphrase every time you use `ssh`, `scp`, `sftp`, or `rsync`.

This is one of the first tools professional Linux developers configure on a new machine.

---

# Learning Objectives

By the end of this lesson, you'll understand:

- What `ssh-agent` is

# The Problem Without `ssh-agent`

Suppose your private key is protected by a passphrase.

```
~/.ssh/

id_ed25519
id_ed25519.pub
```

Every SSH command prompts for it:

```bash
ssh server
```

```
Enter passphrase for key '/home/rahul/.ssh/id_ed25519':
```

Now imagine you run:

```bash
ssh server
scp file server:/tmp
git push
rsync project server:/app
```

You may have to enter the passphrase **four times**.

---

# What Is `ssh-agent`?

`ssh-agent` is a **background process** that securely stores unlocked SSH keys **in memory (RAM)**.

Once a key is added:

```
SSH Agent

↓

Stores unlocked key

↓

SSH uses it automatically
```

You enter the passphrase once, then the agent handles future authentication requests during that session.

---

# How `ssh-agent` Works

Without the agent:

```
SSH

↓

Private Key

↓

Ask Passphrase

↓

Connect
```

With the agent:

```
SSH

↓

ssh-agent

↓

Unlocked Key

↓

Connect
```

The private key never leaves your machine; the agent simply proves you possess it.

---

# Check if an Agent Is Running

Run:

```bash
echo "$SSH_AUTH_SOCK"
```

If you see something like:

```
/tmp/ssh-XXXXXX/agent.12345
```

an agent is available.

If you get:

```
(blank output)
```

there is no active agent for your current shell session.

---

# Start `ssh-agent`

Run:

```bash
eval "$(ssh-agent -s)"
```

Example output:

```
Agent pid 13542
```

The `eval` command sets environment variables (such as `SSH_AUTH_SOCK`) in your current shell so SSH knows how to talk to the agent.

Verify:

```bash
echo "$SSH_AUTH_SOCK"
```

---

# Check Loaded Keys

Initially:

```bash
ssh-add -l
```

Output:

```
The agent has no identities.
```

This means the agent is running, but it doesn't have any keys yet.

---

# Add a Key

```bash
ssh-add ~/.ssh/id_ed25519
```

You'll be prompted:

```
Enter passphrase for ~/.ssh/id_ed25519:
```

After entering it correctly:

```
Identity added:
```

The agent now remembers the unlocked key.

---

# Confirm the Key

Run:

```bash
ssh-add -l
```

Example:

```
256 SHA256:abc123... id_ed25519 (ED25519)
```

Your key is loaded and ready to use.

---

# Test It

First connection:

```bash
ssh user@server
```

You should **not** be prompted for the key's passphrase again (unless your agent no longer has the key). If the remote server still requires a login password, you'll still need to enter that unless you've configured key-based login.

Try:

```bash
scp README.md user@server:/tmp/
```

```bash
git push
```

```bash
rsync -av project/ user@server:/project/
```

The same loaded key can be used by all of these tools.

---

# Where Are Keys Stored?

**Not on disk.**

After you add a key:

```
Private Key File

↓

Unlocked

↓

Stored in RAM
```

If you reboot or end the agent session, you'll need to add the key again.

---

# Multiple Keys

Many developers use different keys.

Example:

```
~/.ssh/

id_personal
id_work
id_github
id_server
```

Load them:

```bash
ssh-add ~/.ssh/id_personal
```

```bash
ssh-add ~/.ssh/id_work
```

```bash
ssh-add ~/.ssh/id_server
```

The agent can manage multiple identities simultaneously.

---

# List All Keys

```bash
ssh-add -l
```

Example:

```
256 SHA256:...
256 SHA256:...
256 SHA256:...
```

To see file paths as well:

```bash
ssh-add -L
```

- `L` prints the public keys currently held by the agent.

---

# Remove One Key

```bash
ssh-add -d ~/.ssh/id_work
```

Now only the remaining keys stay loaded.

---

# Remove All Keys

```bash
ssh-add -D
```

Output:

```
All identities removed.
```

Useful when:

- Sharing a computer
- Finishing work
- Security policies require clearing credentials

---

# Stop the Agent

Terminate it:

```bash
ssh-agent -k
```

Example:

```
Agent pid 13542 killed.
```

The agent and its loaded keys are removed from memory.

---

# Verify Automatic Authentication

After loading a key:

```bash
ssh-add ~/.ssh/id_ed25519
```

Run:

```bash
ssh user@server
```

If the key is accepted by the server, SSH authenticates using the agent without asking for the key's passphrase again.

---

# Common Errors

## Error

```
Could not open a connection to your authentication agent.
```

Fix:

```bash
eval "$(ssh-agent -s)"
```

Then:

```bash
ssh-add ~/.ssh/id_ed25519
```

---

## Error

```
The agent has no identities.
```

Solution:

```bash
ssh-add ~/.ssh/id_ed25519
```

---

## Error

```
Bad permissions
```

Fix:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
```

# Real-World Workflow

A backend developer starts work:

```bash
eval "$(ssh-agent -s)"
```

Load the key:

```bash
ssh-add ~/.ssh/id_ed25519
```

Throughout the day:

```bash
git pull
git push

ssh production

scp backup.sql production:/tmp

rsync project production:/app

ssh staging
```

The passphrase is entered only once when the key is added to the agent.

---

# Security Notes

`ssh-agent` improves convenience, but keep these practices in mind:

- Protect your private keys with strong passphrases.
- Lock or log out of your computer when you leave it unattended.
- Remove keys (`ssh-add -D`) or stop the agent (`ssh-agent -k`) on shared systems.
- Never copy or share your private key.

---

# Best Practices

- Use `ssh-agent` with passphrase-protected keys.
- Load only the keys you need.
- Clear the agent on shared machines.
- Combine `ssh-agent` with a properly configured `~/.ssh/config` file for a smoother workflow.
