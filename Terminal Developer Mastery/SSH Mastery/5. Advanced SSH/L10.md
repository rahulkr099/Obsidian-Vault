# What Is `~/.ssh/config`?

SSH looks for configuration in:

```
~/.ssh/config
```

Instead of typing:

```bash
ssh -i ~/.ssh/id_work \
-p 2222 \
deploy@server.company.com
```

You can simply type:

```bash
ssh production
```

The configuration file supplies the details.

---

# Basic Structure

```
Host production
    HostName server.company.com
    User deploy
```

Now connect:

```bash
ssh production
```

SSH automatically expands it to:

```bash
ssh deploy@server.company.com
```

# Specify the SSH Key

Example:

```
Host production
    HostName production.company.com
    User deploy
    IdentityFile ~/.ssh/id_production
```

SSH always uses that key for this host.

---

# Multiple Keys

Suppose:

```
~/.ssh/

id_personal
id_work
id_production
```

Configuration:

```
Host github-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_personal

Host github-work
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_work

Host production
    HostName production.company.com
    User deploy
    IdentityFile ~/.ssh/id_production
```

Each host uses the correct key automatically.

---

# `IdentitiesOnly`

Sometimes your SSH agent has many keys loaded.

Without:

```
IdentityFile ~/.ssh/id_work
```

SSH may still try additional identities from the agent before using the configured key.

Add:

```
Host production
    IdentityFile ~/.ssh/id_production
    IdentitiesOnly yes
```

Now SSH uses only the configured identity for that host, reducing unnecessary authentication attempts.

---

# Keep Connections Alive

Sometimes firewalls disconnect idle SSH sessions.

Use:

```
Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3
```

Meaning:

Every:

```
60 seconds
```

SSH sends a keepalive message.

After:

```
3 missed replies
```

SSH disconnects.

---

# Connection Timeout

Specify how long SSH waits while connecting:

```
Host *
    ConnectTimeout 10
```

SSH gives up after 10 seconds if the server doesn't respond.

---

# Enable Compression

For slower networks:

```
Host *
    Compression yes
```

This can improve performance for text-heavy transfers, though it may not help already-compressed data such as ZIP archives or videos.

---

# ProxyJump

Example:

```
Host bastion
    HostName bastion.company.com
    User deploy

Host production
    HostName 10.0.1.20
    User deploy
    ProxyJump bastion
```

Now:

```bash
ssh production
```

automatically connects through the bastion.

---

# Local Port Forwarding

You can make tunnels automatic:

```
Host database
    HostName db.company.com
    User deploy
    LocalForward 5432 localhost:5432
```

Now:

```bash
ssh database
```

also creates the PostgreSQL tunnel.

---

# Dynamic Port Forwarding

Example:

```
Host office-proxy
    HostName vpn.company.com
    User deploy
    DynamicForward 1080
```

Now:

```bash
ssh office-proxy
```

creates a SOCKS proxy.

---

# Remote Port Forwarding

Example:

```
Host demo
    HostName demo.company.com
    User deploy
    RemoteForward 9000 localhost:3000
```

A reverse SSH tunnel is established automatically.

---

# SSH Multiplexing

Recommended configuration:

```
Host *
    ControlMaster auto
    ControlPath ~/.ssh/cm/%C
    ControlPersist 15m
```

Fast reconnects.

Fast `scp`.

Fast `rsync`.

Common settings:

```

    ServerAliveInterval 60
    ServerAliveCountMax 3
    Compression yes
    ControlMaster auto
    ControlPath ~/.ssh/cm/%C
    ControlPersist 15m

# Include Other Files

Instead of one huge config:

```
~/.ssh/config
```

Split it:

```
Include ~/.ssh/config.d/*
```

Directory:

```
~/.ssh/

config
config.d/

github.conf
servers.conf
lab.conf
aws.conf
```

Much easier to maintain.

```

    ServerAliveInterval 60
    ServerAliveCountMax 3

# Common Mistakes

## Wrong Permissions

Fix:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/config
```

---

## Wrong Key Used

Use:

```
IdentitiesOnly yes
```

and specify the correct `IdentityFile`.

---

## Alias Not Working

Check:

```bash
ssh -G production
```

This prints the effective configuration SSH will use, which is very useful for debugging.

---

## Configuration Syntax Error

Test:

```bash
ssh -T production
```

or:

```bash
ssh -v production
```

Verbose mode helps identify parsing or connection issues.

---

# Best Practices

- Use meaningful aliases (`production`, `staging`, `db`).
- Use separate keys for work and personal accounts.
- Keep defaults under `Host *`.
- Split large configs with `Include`.
- Use `IdentitiesOnly yes` for hosts with dedicated keys.
- Use `%C` for `ControlPath`.
- Protect `~/.ssh` permissions.

# Interview Questions

### 1. What is the purpose of `~/.ssh/config`?

It stores per-host and global SSH client settings, allowing you to use simple aliases instead of long command lines.

---

### 2. What does `IdentitiesOnly yes` do?

It tells SSH to use only the identities explicitly configured for that host, preventing extra keys from being offered.

---

### 3. Why use `Include`?

To organize large SSH configurations into smaller, easier-to-maintain files.

---

### 4. What command shows the final configuration SSH will use?

```bash
ssh -G production
```

---

### 5. Which options are commonly placed under `Host *`?

- `ServerAliveInterval`
- `ServerAliveCountMax`
- `ControlMaster`
- `ControlPath`
- `ControlPersist`
- `Compression`
