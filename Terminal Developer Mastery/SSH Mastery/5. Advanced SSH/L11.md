# Module 5 — Advanced SSH

# Lesson 11: SSH Tunnels for Databases — Secure Production Database Access

One of the most common tasks for backend developers is accessing production databases.

**Never expose your production database directly to the Internet just because you need to connect to it.**

Instead, use an **SSH tunnel**.

This is the standard practice in startups and large companies alike.

# The Wrong Way

Many beginners configure databases like this:

```
Internet
     │
     ▼
PostgreSQL
Port 5432
(Public)
```

Problems:

- Anyone can attempt to connect.
- Brute-force attacks become possible.
- Firewall complexity increases.
- Higher security risk.

---

# The Correct Way

```
Internet
     │
     ▼
SSH (22)
     │
     ▼
Application Server
     │
──────── Private Network ────────
     │
     ▼
PostgreSQL
(No Public IP)
```

Only SSH is exposed.

The database stays private.

---

# What Is an SSH Database Tunnel?

Suppose your database listens on:

```
Server

localhost:5432
```

Create a tunnel:

```bash
ssh -L 5432:localhost:5432 deploy@server
```

Now your laptop has:

```
Laptop

localhost:5432
```

which securely forwards to:

```
Server

localhost:5432
```

---

# PostgreSQL Example

Create the tunnel:

```bash
ssh -L 5432:localhost:5432 deploy@server
```

Connect:

```bash
psql \
-h localhost \
-p 5432 \
-U postgres
```

To `psql`, it looks like the database is running locally.

# Multiple Database Tunnels

Instead of one:

```bash
ssh -L 5432:localhost:5432 deploy@server
```

Use several:

```bash
ssh \
-L 5432:localhost:5432 \
-L 6379:localhost:6379 \
-L 27017:localhost:27017 \
deploy@server
```

Now you can access:

- PostgreSQL
- Redis
- MongoDB

through one SSH session.

---

# Background Tunnels

Instead of occupying your terminal:

```bash
ssh -f -N \
-L 5432:localhost:5432 \
deploy@server
```

Options:

- `f` → background
- `N` → no remote shell

# Using a Bastion Host

Architecture:

```
Laptop

↓

Bastion

↓

Production

↓

PostgreSQL
```

Tunnel:

```bash
ssh \
-J bastion \
-L 5432:localhost:5432 \
production
```

The tunnel is established through the bastion.

---

# SSH Config Example

Instead of typing long commands:

```
Host prod-db
    HostName db.internal
    User deploy
    ProxyJump bastion
    LocalForward 5432 localhost:5432
```

Connect:

```bash
ssh prod-db
```

The tunnel is created automatically.

# Common Errors

## Error

```
bind: Address already in use
```

Check:

```bash
ss -ltn
```

If port `5432` is already in use locally, choose another local port:

```bash
ssh \
-L 15432:localhost:5432 \
deploy@server
```

Then connect to:

```
localhost:15432
```

---

## Error

```
Connection refused
```

Possible causes:

- Database isn't running
- Wrong destination port
- Wrong destination hostname

Check on the server:

```bash
ss -ltn
```

or, for PostgreSQL:

```bash
sudo systemctl status postgresql
```

---

## Error

Tunnel Created but GUI Cannot Connect

Verify the tunnel:

```bash
ss -ltn | grep 5432
```

Expected:

```
127.0.0.1:5432
```

If nothing is listening, the tunnel isn't active.

# Security Best Practices

✅ Keep databases on private networks.

✅ Prefer SSH tunnels over opening database ports.

✅ Use bastion hosts for production access.

✅ Close tunnels when finished.

```bash
pkill -f "ssh.*5432"
```

Or, if you're using multiplexing:

```bash
ssh -O exit prod-db
```

✅ Use least-privilege database accounts rather than administrative accounts for everyday work.

# Interview Questions

### 1. Why shouldn't production databases have public IP addresses?

Because exposing them directly increases the attack surface. SSH tunnels let administrators access them securely without making the database reachable from the public internet.

---

### 2. What does this command do?

```bash
ssh -L 5432:localhost:5432 deploy@server
```

It forwards your local port `5432` to port `5432` on the remote server through an encrypted SSH connection.

---

### 3. Can GUI tools like pgAdmin or MongoDB Compass use SSH tunnels?

Yes. They simply connect to `localhost` on the forwarded port, or some clients can establish the SSH tunnel internally using their built-in SSH support.

---

### 4. How do you tunnel through a bastion host?

For example:

```bash
ssh \
-J bastion \
-L 5432:localhost:5432 \
production
```

---

### 5. What is the advantage of forwarding multiple ports in one SSH session?

It allows access to multiple private services (such as PostgreSQL, Redis, and MongoDB) over a single encrypted SSH connection.
