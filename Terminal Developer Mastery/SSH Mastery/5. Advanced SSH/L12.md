# Module 5 — Advanced SSH

# Lesson 12: SSHFS (SSH Filesystem) — Mount Remote Servers Like Local Folders

Imagine editing files on a remote Linux server **without** repeatedly using `scp`, `rsync`, or `vim` over SSH.

With **SSHFS (SSH Filesystem)**, a remote directory appears as a normal local folder on your computer.

You can:

- Open remote files in Neovim
- Browse them in your file manager
- Use VS Code (or another editor) directly
- Copy, rename, and delete files normally

SSHFS uses SSH, so all communication is encrypted.

# What Is SSHFS?

SSHFS stands for:

```
SSH File System
```

It uses the Linux **FUSE (Filesystem in Userspace)** framework to mount remote directories over SSH.

Instead of:

```
Laptop

↓

scp

↓

Server
```

You get:

```
Laptop

↓

SSHFS

↓

Remote Folder

↓

Looks Like Local Folder
```

---

# Traditional Workflow

Without SSHFS:

```bash
scp config.json server:/etc/app/
```

Need another file?

```bash
scp nginx.conf server:/etc/nginx/
```

Need to edit?

```bash
ssh server
vim /etc/nginx/nginx.conf
```

Many separate steps.

---

# SSHFS Workflow

Mount once:

```bash
sshfs deploy@server:/var/www ~/server
```

Now:

```
~/server
```

behaves like:

```
A Normal Local Directory
```

Open it with:

- Neovim
- VS Code
- Nano
- File Manager

No additional copying required.

# Create a Mount Point

A mount point is an empty local directory.

Example:

```bash
mkdir -p ~/server
```

---

# Mount a Remote Directory

General syntax:

```bash
sshfs user@host:/remote/path /local/mount
```

Example:

```bash
sshfs deploy@server:/var/www ~/server
```

Now:

```
~/server

↓

Remote

/var/www
```

---

# Verify the Mount

Run:

```bash
mount | grep sshfs
```

or:

```bash
df -h
```

You should see an SSHFS mount.

---

# Browse Files

```bash
cd ~/server
```

List files:

```bash
ls
```

Edit:

```bash
nvim app.js
```

The changes are written directly to the remote server.

---

# Copy Files

```bash
cp config.json ~/server/
```

The file is copied through SSH automatically.

---

# Rename Files

```bash
mv old.conf new.conf
```

SSHFS performs the rename on the remote server.

---

# Delete Files

```bash
rm ~/server/test.txt
```

The file is removed remotely.

Be careful—there is no local copy unless you've made one.

---

# Unmount

When finished:

Linux:

```bash
fusermount3 -u ~/server
```

If your system uses an older version:

```bash
fusermount -u ~/server
```

On macOS (with macFUSE):

```bash
umount ~/server
```

The remote filesystem disappears from the local mount point.

---

# Using SSH Config

Suppose:

```
Host production
    HostName production.company.com
    User deploy
```

Instead of:

```bash
sshfs deploy@production.company.com:/var/www ~/server
```

Use:

```bash
sshfs production:/var/www ~/server
```

SSHFS uses your SSH configuration automatically.

---

# Using a Bastion Host

Suppose:

```
Laptop

↓

Bastion

↓

Production
```

Your SSH config:

```
Host bastion
    HostName bastion.company.com
    User deploy

Host production
    HostName 10.0.1.20
    User deploy
    ProxyJump bastion
```

Mount:

```bash
sshfs production:/var/www ~/server
```

SSHFS automatically goes through the bastion.

---

# Read-Only Mount

Sometimes you only want to inspect files.

```bash
sshfs \
-o ro \
deploy@server:/etc \
~/server
```

Now you cannot accidentally modify remote files.

---

# Automatic Reconnection

If the network drops:

```bash
sshfs \
-o reconnect \
deploy@server:/var/www \
~/server
```

SSHFS attempts to reconnect automatically.

---

# Cache Options

Improve responsiveness:

```bash
sshfs \
-o cache=yes \
deploy@server:/var/www \
~/server
```

Useful when working with many small files.

---

# Keepalive

Prevent idle disconnects:

```bash
sshfs \
-o ServerAliveInterval=30 \
deploy@server:/var/www \
~/server
```

---

# Using an Alternate SSH Port

Example:

```bash
sshfs \
-p 2222 \
deploy@server:/var/www \
~/server
```

Or configure the port in `~/.ssh/config` and simply use the host alias.

# Real MERN Workflow

Production server:

```
/var/www/app

├── package.json
├── server.js
├── routes/
├── controllers/
└── config/
```

Mount:

```bash
sshfs production:/var/www/app ~/production-app
```

Open:

```bash
cd ~/production-app
nvim server.js
```

Changes are saved directly on the server.

> **Note:** Editing production code directly should generally be reserved for emergencies. Normal deployments should go through version control and a deployment pipeline.

# Common Errors

## Error

```
mountpoint is not empty
```

Use an empty directory or unmount the previous filesystem.

---

## Error

```
Transport endpoint is not connected
```

The SSH connection has been lost.

Unmount:

```bash
fusermount3 -u ~/server
```

or:

```bash
fusermount -u ~/server
```

Then mount again.

---

## Error

```
Permission denied
```

Verify:

```bash
ssh production
```

If normal SSH login fails, SSHFS will fail too.

---

## Error

```
Connection timed out
```

Check:

- SSH connectivity
- Firewall
- Bastion configuration
- `ProxyJump`
- Network connectivity

# SSHFS vs SCP vs RSYNC

|Tool|Best For|
|---|---|
|`scp`|One-time file copy|
|`rsync`|Synchronizing directories efficiently|
|SSHFS|Interactive editing and browsing|
|SFTP|Manual file transfers via an interactive session|

---

# Security Best Practices

- Use SSH keys instead of passwords.
- Use SSH config aliases.
- Mount only what you need.
- Unmount when finished.
- Prefer read-only mounts when reviewing sensitive files.
- Avoid editing production systems directly except when necessary.

---

# Performance Tips

For many small files:

```bash
sshfs \
-o reconnect \
-o cache=yes \
production:/var/www \
~/server
```

If you frequently access the same server, combine SSHFS with SSH multiplexing (`ControlMaster`) from the previous lesson for faster connection setup.

# Interview Questions

### 1. What is SSHFS?

SSHFS is a filesystem that mounts remote directories over SSH using FUSE, making them appear as local directories.

---

### 2. How is SSHFS different from `scp`?

`scp` copies files. SSHFS lets you interact with remote files in place without copying them first.

---

### 3. Can SSHFS use `~/.ssh/config`?

Yes. It honors your SSH configuration, including host aliases, `IdentityFile`, `ProxyJump`, ports, and other SSH client settings.

---

### 4. Can SSHFS work through a bastion host?

Yes. If `ProxyJump` is configured in your SSH config, SSHFS uses it automatically.

---

### 5. When should you use SSHFS?

When you need to browse or edit remote files interactively as though they were stored locally.
