# Module 5 — Advanced SSH

# Lesson 13: `rsync` over SSH — Professional File Synchronization

If you've ever copied an entire project with:

```bash
scp -r myapp/ deploy@server:/var/www/
```

you've probably noticed two problems:

- It copies **everything**, even unchanged files.
- Large projects take longer than necessary.

Professional Linux administrators and backend engineers almost always use **`rsync` over SSH** because it transfers **only the differences** between the source and destination.

This makes deployments, backups, and server synchronization much faster.

By the end of this lesson, you'll be able to:

# What is `rsync`?

`rsync` (Remote Sync) is a file synchronization tool.

Unlike `scp`, it compares the source and destination and transfers only the changed portions.

Example:

```
Laptop

myapp/
├── app.js
├── routes.js
└── package.json

↓

Only Changed Files

↓

Server
```

---

# Why `rsync` Instead of `scp`?

Suppose your project contains:

```
myapp/

1000 files
```

You modify:

```
app.js
```

### `scp`

Copies:

```
1000 files
```

### `rsync`

Copies:

```
1 changed file
```

Huge time savings.

---

# Basic Syntax

```bash
rsync [OPTIONS] SOURCE DESTINATION
```

Remote example:

```bash
rsync -av ./myapp/ deploy@server:/var/www/myapp/
```

---

# Understanding Common Options

|Option|Meaning|
|---|---|
|`-a`|Archive mode (preserves metadata)|
|`-v`|Verbose output|
|`-z`|Compress data|
|`-h`|Human-readable numbers|
|`--delete`|Remove destination files missing from source|
|`--progress`|Show transfer progress|
|`--dry-run`|Preview without copying|

A common combination is:

```bash
rsync -avzh
```

---

# Archive Mode (`a`)

Archive mode preserves:

- Permissions
- Ownership (when possible)
- Symlinks
- Modification times
- Directory structure

Example:

```bash
rsync -a project/ server:/backup/
```

---

# Verbose Mode (`v`)

```bash
rsync -av project/ server:/backup/
```

Displays every transferred file.

Useful for debugging.

---

# Compression (`z`)

```bash
rsync -avz project/ server:/backup/
```

Compresses data while transferring.

Helpful on slower networks.

---

# Human Readable (`h`)

Instead of:

```
104857600 bytes
```

You see:

```
100M
```

---

# Progress Display

```bash
rsync -av --progress project/ server:/backup/
```

Example output:

```
server.js

 52%  3.2MB/s
```

Great for large files.

---

# Dry Run

One of the safest features.

```bash
rsync \
-av \
--dry-run \
project/ \
server:/backup/
```

Nothing is copied.

You only see what **would** happen.

Always use this before destructive operations.

---

# Delete Removed Files

Suppose:

Laptop:

```
app.js
```

Server:

```
app.js
old.js
```

Run:

```bash
rsync \
-av \
--delete \
project/ \
server:/backup/
```

Result:

```
old.js

↓

Deleted
```

**Warning:** `--delete` removes files from the destination that no longer exist in the source.

---

# Copying from Server to Laptop

Reverse direction:

```bash
rsync \
-av \
deploy@server:/var/log/ \
~/logs/
```

Useful for:

- Log collection
- Backups
- Database dumps

# SSH Transport

By default, `rsync` uses SSH when the destination looks like:

```
user@host:path
```

Example:

```bash
rsync \
-av \
project/ \
deploy@server:/var/www/
```

Everything is encrypted.

---

# Custom SSH Port

Suppose SSH runs on port:

```
2222
```

Use:

```bash
rsync \
-av \
-e "ssh -p 2222" \
project/ \
deploy@server:/var/www/
```

The `-e` option specifies the remote shell command.

---

# Using SSH Config

Suppose your SSH config contains:

```
Host production
    HostName production.company.com
    User deploy
```

Then simply run:

```bash
rsync \
-av \
project/ \
production:/var/www/
```

No need to specify usernames or hostnames.

---

# Using a Bastion Host

If `ProxyJump` is configured:

```
Host production
    ProxyJump bastion
```

Then:

```bash
rsync \
-av \
project/ \
production:/var/www/
```

works automatically through the bastion.

If you're not using `ProxyJump`, you can specify SSH options directly:

```bash
rsync \
-av \
-e "ssh -J bastion" \
project/ \
production:/var/www/
```

---

# Excluding Files

Don't upload:

```
node_modules/
```

Example:

```bash
rsync \
-av \
--exclude node_modules \
project/ \
production:/var/www/
```

Common exclusions:

```
.git/
node_modules/
dist/
.env
coverage/
```

---

# Exclude File

Create:

```
.rsyncignore
```

Example:

```
node_modules
.git
.env
coverage
```

Then:

```bash
rsync \
-av \
--exclude-from=.rsyncignore \
project/ \
production:/var/www/
```

# Real MERN Deployment

Project:

```
backend/

controllers/
routes/
package.json
```

Deploy:

```bash
rsync \
-avz \
--delete \
--exclude node_modules \
./backend/ \
production:/var/www/backend/
```

Then SSH into the server:

```bash
ssh production
```

Run:

```bash
npm install
pm2 restart backend
```

A common deployment workflow.

---

# Backup Example

Backup remote logs:

```bash
rsync \
-av \
production:/var/log/ \
~/backups/logs/
```

Nightly backups often use this pattern.

# Synchronizing Two Servers

Suppose:

```
Server A

↓

Server B
```

Run from Server A:

```bash
rsync \
-av \
/data/ \
user@serverB:/backup/
```

Useful for replication and migrations.

# Common Errors

## Permission Denied

```
Permission denied (publickey)
```

Verify:

```bash
ssh production
```

If SSH doesn't work, `rsync` won't either.

---

## Wrong Directory

Consider:

```bash
rsync project production:/var/www/
```

versus:

```bash
rsync project/ production:/var/www/
```

The trailing slash changes behavior.

### Without `/`

```
project/

↓

/var/www/project
```

### With `/`

```
project/*

↓

/var/www/
```

This is one of the most common `rsync` mistakes.

---

## Delete Accidentally Removes Files

Always preview first:

```bash
rsync \
-av \
--delete \
--dry-run \
project/ \
production:/var/www/
```

---

# Performance Tips

For large deployments:

```bash
rsync \
-avz \
--progress \
project/ \
production:/var/www/
```

Combine with SSH multiplexing (`ControlMaster`) for even faster repeated deployments.

# `scp` vs `rsync`

|Feature|`scp`|`rsync`|
|---|---|---|
|Incremental transfer|❌|✅|
|Compression|Basic|Excellent|
|Resume interrupted transfers|Limited|Better support|
|Delete removed files|❌|✅|
|Dry run|❌|✅|
|Progress reporting|Basic|Detailed|
|Deployment-friendly|❌|✅|

---

# Security Best Practices

- Use SSH keys instead of passwords.
- Test with `-dry-run` before large syncs.
- Be careful with `-delete`.
- Exclude sensitive files such as `.env` unless they are intentionally managed that way.
- Keep backups before destructive synchronizations.

# Interview Questions

### 1. Why is `rsync` preferred over `scp`?

Because it transfers only changed data, making deployments and backups much faster and more efficient.

---

### 2. What does the `a` option do?

It enables archive mode, preserving metadata such as permissions, timestamps, symlinks, and directory structure.

---

### 3. What is the purpose of `-dry-run`?

It previews the synchronization without making any changes, helping prevent accidental mistakes.

---

### 4. Why should you be careful with `-delete`?

It removes files from the destination that don't exist in the source, which can unintentionally delete important data if used incorrectly.

---

### 5. What is the significance of a trailing slash in `rsync`?

- `rsync project/ destination/` copies the **contents** of `project`.
- `rsync project destination/` copies the **project directory itself**.

Understanding this distinction is essential to avoid syncing to the wrong location.
