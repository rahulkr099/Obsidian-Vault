# What Does `ssh-add` Do?

Think of it as a manager for `ssh-agent`.

```
             ssh-add
                 │
                 ▼
           ssh-agent
                 │
     ┌───────────┴───────────┐
     ▼           ▼           ▼
 Personal     Work       Production
```

`ssh-add`:

- Adds keys
- Removes keys
- Lists keys
- Sets key lifetime
- Requires confirmation
- Locks/unlocks the agent

---

# Basic Syntax

```bash
ssh-add [options] [key-file]
```

Example:

```bash
ssh-add ~/.ssh/id_ed25519
```

---

# List Loaded Keys

Fingerprints:

```bash
ssh-add -l
```

Example:

```
256 SHA256:abc123... id_ed25519 (ED25519)
```

---

## Display Public Keys

```bash
ssh-add -L
```

Example:

```
ssh-ed25519 AAAAC3Nza...
```

This prints the **public keys**, not your private keys.

---

# Add Multiple Keys

Suppose:

```
~/.ssh/

id_personal
id_work
id_server
```

Load all three:

```bash
ssh-add ~/.ssh/id_personal
ssh-add ~/.ssh/id_work
ssh-add ~/.ssh/id_server
```

Now verify:

```bash
ssh-add -l
```

Output:

```
Personal
Work
Production
```

(You'll actually see fingerprints, not these labels.)

---

# Add Every Default Key

If your keys use standard names:

```bash
ssh-add
```

It tries common key files such as:

```
id_rsa
id_ecdsa
id_ed25519
```

---

# Remove One Key

```bash
ssh-add -d ~/.ssh/id_work
```

Remaining:

```
Personal
Production
```

---

# Remove Every Key

```bash
ssh-add -D
```

Useful when:

- Leaving work
- Shared computer
- Security audit

---

# Add a Key with a Lifetime

You can make a key expire automatically.

Example:

```bash
ssh-add -t 1h ~/.ssh/id_ed25519
```

After one hour:

```
Key automatically removed
```

Other examples:

```bash
ssh-add -t 30m ~/.ssh/id_work
```

```bash
ssh-add -t 8h ~/.ssh/id_work
```

```bash
ssh-add -t 1d ~/.ssh/id_server
```

This reduces the chance of a forgotten key remaining available all day.

---

# Require Confirmation Before Every Use

Add a key:

```bash
ssh-add -c ~/.ssh/id_ed25519
```

Now every authentication requires confirmation.

Example:

```
Allow use of key?

Yes
```

This helps prevent software from silently using your key.

---

# Combine Options

Example:

```bash
ssh-add -c -t 4h ~/.ssh/id_work
```

Meaning:

- Confirmation required
- Automatically expires after four hours

---

# Lock the Agent

Temporarily lock all loaded keys:

```bash
ssh-add -x
```

You'll create a password for the agent.

When someone tries to use a key:

```
Agent locked
```

---

# Unlock the Agent

```bash
ssh-add -X
```

Enter the agent password.

Keys become usable again.

---

# Multiple GitHub Accounts

Example:

```
~/.ssh/

github_personal
github_work
```

Load both:

```bash
ssh-add ~/.ssh/github_personal
```

```bash
ssh-add ~/.ssh/github_work
```

Configure `~/.ssh/config`:

```
Host github-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/github_personal

Host github-work
    HostName github.com
    User git
    IdentityFile ~/.ssh/github_work
```

Clone repositories with the matching host alias:

```bash
git clone git@github-personal:username/project.git
```

```bash
git clone git@github-work:company/project.git
```

---

# Production Server Keys

Example:

```
~/.ssh/

production
staging
testing
```

Load only what you need:

```bash
ssh-add ~/.ssh/production
```

or

```bash
ssh-add ~/.ssh/staging
```

Avoid loading every key if you don't need them.

# View Fingerprints

```bash
ssh-add -l
```

Example:

```

256 SHA256:X9Y8Z7...
```

Fingerprints uniquely identify each key.

# Common Errors

## Error

```
Could not open a connection to your authentication agent.
```

Fix:

```bash
eval "$(ssh-agent -s)"
```

Then:

```bash
ssh-add ~/.ssh/id_ed25519
```

---

## Error

```
No such file or directory
```

Check:

```bash
ls ~/.ssh
```

Verify the filename.

---

## Error

```
Bad permissions
```

Fix:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
```

---

## Error

```
The agent has no identities.
```

Load a key:

```bash
ssh-add ~/.ssh/id_ed25519
```

---

# Professional Workflow

Morning:

```bash
eval "$(ssh-agent -s)"
```

Load work key for the day:

```bash
ssh-add -t 8h ~/.ssh/id_work
```

Optionally require confirmation for production:

```bash
ssh-add -c ~/.ssh/production
```

Now you can:

```bash
git push
```

```bash
ssh production
```

```bash
rsync project production:/app
```

without repeatedly entering passphrases.

Evening:

```bash
ssh-add -D
```

---

# Security Best Practices

✔ Use passphrase-protected keys.

✔ Set time limits for sensitive keys.

```bash
ssh-add -t 4h
```

✔ Require confirmation for production keys.

```bash
ssh-add -c
```

✔ Remove keys when finished.

```bash
ssh-add -D
```

✔ Don't load unnecessary keys.

# Interview Questions

### 1. What is the difference between `ssh-agent` and `ssh-add`?

**Answer:** `ssh-agent` is the background process that stores unlocked SSH keys in memory. `ssh-add` is the utility used to add, remove, list, and manage those keys.

---

### 2. Why would you use `ssh-add -t`?

**Answer:** To automatically remove a key after a specified time, reducing the risk of leaving sensitive credentials loaded indefinitely.

---

### 3. What does `ssh-add -c` do?

**Answer:** It requires user confirmation each time the agent uses that key for authentication.

---

### 4. How do you remove all identities from the agent?

```bash
ssh-add -D
```

---

### 5. How can you see which keys are currently loaded?

```bash
ssh-add -l
```
