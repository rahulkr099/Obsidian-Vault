# Lesson 4: Local Port Forwarding (`ssh -L`) — Securely Access Remote Services

One of SSH's most powerful features is **port forwarding**, also called **SSH tunneling**.

It lets you securely access services running on a remote machine **without exposing those services to the Internet**.

This is used every day by backend developers, DevOps engineers, database administrators, and cloud engineers.

# What Is Local Port Forwarding?

Local port forwarding creates a secure tunnel from **your local machine** to a **remote service** through an SSH connection.

Instead of connecting directly:

```
Browser
    │
    ▼
Internet
    │
    ▼
Database
```

You connect like this:

```
Browser
    │
localhost:8080
    │
SSH Tunnel
    │
Remote Server
    │
Internal Service
```

Everything inside the tunnel is encrypted.

---

# Why Use It?

Imagine a production database:

```
Production Server

PostgreSQL

Port 5432
```

Security policy:

❌ Not accessible from the Internet.

Good!

But now developers need access.

Instead of opening port **5432** publicly:

Use SSH.

---

# Real Example

Server:

```
server.example.com
```

Database:

```
localhost:5432
```

Your laptop:

```
localhost
```

Create a tunnel:

```bash
ssh -L 5432:localhost:5432 user@server.example.com
```

---

# Understanding the Syntax

General form:

```bash
ssh -L LOCAL_PORT:REMOTE_HOST:REMOTE_PORT user@server
```

Example:

```bash
ssh -L 5432:localhost:5432 deploy@server
```

Meaning:

```
Local Machine

localhost:5432

↓

SSH Tunnel

↓

Server

localhost:5432
```

Now your local port **5432** connects securely to PostgreSQL on the server.

---

# How the Tunnel Works

Without forwarding:

```
Application

↓

Database

❌ Blocked
```

With forwarding:

```
Application

↓

localhost:5432

↓

SSH Tunnel

↓

Remote Database
```

Your application thinks it's talking to a local database.

SSH secretly forwards everything.

# Forward to Another Host

The destination doesn't have to be the SSH server itself.

Example:

```bash
ssh -L 5432:db.internal:5432 deploy@bastion
```

Diagram:

```
Laptop

↓

SSH

↓

Bastion

↓

db.internal:5432
```

The bastion host can reach the internal database, even though your laptop cannot.

---

# Keep the Tunnel Open Only

Sometimes you only want the tunnel.

Don't start a shell:

```bash
ssh -N -L 5432:localhost:5432 deploy@server
```

Options:

- `N` → don't execute a remote command
- `L` → create a local tunnel

This is common for long-running database tunnels.

---

# Run the Tunnel in the Background

Instead of keeping the terminal occupied:

```bash
ssh -f -N -L 5432:localhost:5432 deploy@server
```

Options:

- `f` → move to background
- `N` → no shell

Now the tunnel continues running.

---

# Forward Multiple Ports

Example:

```bash
ssh \
-L 5432:localhost:5432 \
-L 6379:localhost:6379 \
deploy@server
```

Now both PostgreSQL and Redis are available locally.

---

# Using `~/.ssh/config`

Instead of typing a long command every time:

```
Host production-db
    HostName server.example.com
    User deploy
    LocalForward 5432 localhost:5432
```

Now simply run:

```bash
ssh production-db
```

The tunnel is created automatically.

# Common Errors

## Error

```
bind: Address already in use
```

Meaning:

The local port is already occupied.

Check:

```bash
ss -ltn
```

Choose another local port:

```bash
ssh -L 15432:localhost:5432 deploy@server
```

---

## Error

```
Connection refused
```

Possible causes:

- Database isn't running
- Wrong destination port
- Wrong destination hostname

Check on the server:

```bash
ss -ltn
```

or

```bash
systemctl status postgresql
```

---

## Error

Tunnel created, but the application can't connect.

Verify the tunnel:

```bash
ss -ltn
```

Example output:

```
LISTEN

127.0.0.1:5432
```

If the port isn't listening, the tunnel wasn't created successfully.

---

# Best Practices

- Use `N` when only creating a tunnel.
- Use `f` for background tunnels.
- Keep databases private; don't expose them publicly unless necessary.
- Prefer SSH tunnels over temporarily opening firewall ports.
- Close unused tunnels when finished.

# Interview Questions

### 1. What does `ssh -L` do?

It creates a **local port forwarding tunnel**, allowing a local port to securely connect to a remote host and port over SSH.

---

### 2. What does this command do?

```bash
ssh -L 8080:localhost:80 user@server
```

It forwards your local port **8080** to port **80** on the remote server. Opening `http://localhost:8080` accesses the remote web service.

---

### 3. Why use `N`?

- `N` tells SSH not to start a remote shell, making it ideal for tunnel-only sessions.

---

### 4. Why use SSH tunneling for databases?

It keeps database ports private while allowing secure administrative access through an encrypted SSH connection.

---

### 5. How do you forward multiple ports?

Specify `-L` multiple times:

```bash
ssh \
-L 5432:localhost:5432 \
-L 6379:localhost:6379 \
user@server
```
