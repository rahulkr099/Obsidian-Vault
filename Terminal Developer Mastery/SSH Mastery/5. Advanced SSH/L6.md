# Module 5 — Advanced SSH

# Lesson 6: Dynamic Port Forwarding (`ssh -D`) — Creating a SOCKS Proxy with SSH

So far you've learned:

- **`ssh -L`** → Local Port Forwarding (Local → Remote)
- **`ssh -R`** → Remote Port Forwarding (Remote → Local)

Now you'll learn the third major type:

- **`ssh -D`** → Dynamic Port Forwarding (SOCKS Proxy)

This is one of the most versatile SSH features. Instead of forwarding **one specific port**, it creates a **SOCKS proxy** that can forward **many different TCP connections** through a single encrypted SSH tunnel.

# What Is a SOCKS Proxy?

A SOCKS proxy acts as an intermediary between your application and the internet.

Without a proxy:

```
Browser
   │
   ▼
Internet
   │
   ▼
Website
```

With a SOCKS proxy:

```
Browser
   │
localhost:1080
   │
SSH Tunnel
   │
Remote Server
   │
Internet
   │
Website
```

Your browser sends traffic to the SOCKS proxy, and SSH forwards it securely through the remote server.

---

# Why Use Dynamic Port Forwarding?

Unlike `-L`, where you choose one destination:

```
localhost:5432
      │
      ▼
Remote Database
```

With `-D`:

```
Browser
Git
curl
VS Code
Package Manager
API Client
```

All can use the same SOCKS proxy (if configured to do so), allowing connections to many different destinations.

---

# Basic Syntax

```bash
ssh -D LOCAL_PORT user@server
```

Example:

```bash
ssh -D 1080 user@server.example.com
```

This creates a SOCKS proxy on:

```
localhost:1080
```

---

# What Happens Internally?

```
Laptop

Browser

↓

SOCKS Proxy

↓

SSH Tunnel

↓

Remote Server

↓

Destination Website
```

The SSH server makes the outbound connection on behalf of your browser.

---

# Using `N`

If you only need the proxy:

```bash
ssh -N -D 1080 user@server
```

No shell session is started.

---

# Running in the Background

```bash
ssh -f -N -D 1080 user@server
```

Options:

- `f` → background
- `N` → no shell
- `D` → dynamic forwarding

# Configuring Google Chrome

Chrome relies on your operating system's proxy settings.

On Linux, you can also launch Chrome with:

```bash
google-chrome \
--proxy-server="socks5://127.0.0.1:1080"
```

(Replace `google-chrome` with your browser command if needed.)

---

# Using `curl`

Recent versions of `curl` support SOCKS proxies directly:

```bash
curl --socks5 localhost:1080 <https://example.com>
```

Or:

```bash
curl --proxy socks5://localhost:1080 <https://example.com>
```

---

# Git Through SOCKS

Configure Git temporarily:

```bash
git config --global http.proxy socks5://127.0.0.1:1080
```

Remove it later:

```bash
git config --global --unset http.proxy
```

(SSH-based Git operations use SSH directly and are configured differently.)

# Difference Between `L` and `D`

## Local Port Forwarding

```bash
ssh -L 5432:localhost:5432 user@server
```

One destination.

Only PostgreSQL.

---

## Dynamic Port Forwarding

```bash
ssh -D 1080 user@server
```

Many destinations.

Any SOCKS-aware application.

---

# Using `~/.ssh/config`

Instead of remembering the command:

```
Host socks-server
    HostName server.example.com
    User deploy
    DynamicForward 1080
```

Connect:

```bash
ssh socks-server
```

The SOCKS proxy starts automatically.

# Security Benefits

Without SSH:

```
Application

↓

Public Network

↓

Website
```

With SSH:

```
Application

↓

SOCKS Proxy

↓

Encrypted SSH Tunnel

↓

Remote Server

↓

Website
```

Traffic between your laptop and the SSH server is encrypted.

**Important:** Traffic from the SSH server to the final destination depends on the protocol. HTTPS remains encrypted end-to-end. Plain HTTP is still unencrypted beyond the SSH server.

# Common Errors

## Error

```
bind: Address already in use
```

Another process is using port **1080**.

Check:

```bash
ss -ltn
```

Use another port:

```bash
ssh -D 1081 user@server
```

---

## Browser Doesn't Use the Proxy

Verify:

- SOCKS version is **5**
- Port matches (`1080`)
- SSH session is still running

---

## SSH Disconnects

The proxy stops because it depends on the SSH connection.

For long-lived sessions, consider:

```bash
ssh \
-o ServerAliveInterval=60 \
-o ServerAliveCountMax=3 \
-D 1080 \
user@server
```

This sends keepalive messages to reduce idle disconnects.

---

# Security Best Practices

- Only use trusted SSH servers.
- Use key-based authentication.
- Close the proxy when you're finished.
- Don't leave background tunnels running unnecessarily.
- Prefer HTTPS websites when possible.

---

# Comparing SSH Forwarding Modes

|Option|Purpose|Typical Use|
|---|---|---|
|`-L`|Local → Remote|Databases, internal web apps|
|`-R`|Remote → Local|Share local apps, remote support|
|`-D`|Dynamic (SOCKS)|Browsing, APIs, internal networks|

# Interview Questions

### 1. What does `ssh -D` do?

It creates a local **SOCKS proxy** that forwards TCP traffic through an encrypted SSH tunnel.

---

### 2. When would you choose `D` instead of `L`?

When you need to access **multiple destinations** through one SSH connection instead of forwarding a single port.

---

### 3. Does `ssh -D` require applications to support SOCKS?

Yes. Applications must either support SOCKS directly or use the operating system's proxy settings.

---

### 4. What does `N` do with `ssh -D`?

It creates the proxy without opening an interactive shell.

---

### 5. Is traffic always encrypted end-to-end?

No. The connection between your laptop and the SSH server is encrypted. Beyond the SSH server, encryption depends on the application protocol (for example, HTTPS vs. HTTP).
