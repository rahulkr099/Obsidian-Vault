# Module 5 — Advanced SSH

# Lesson 7: Jump Hosts (`ProxyJump`) — Access Private Servers Securely

As infrastructure grows, production servers are **not directly accessible from the Internet**.

Instead, organizations place a **Jump Host** (also called a **Bastion Host**) in front of private servers.

SSH's **ProxyJump (`-J`)** feature lets you securely connect to those private servers through the bastion using a single SSH command.

This is the standard approach in AWS, Azure, Google Cloud, DigitalOcean, and many on-premises environments.

# The Problem

Suppose you have this network:

```
Internet

↓

Production Server
```

Anyone on the internet could try to connect to your production server.

This increases the attack surface.

---

# Better Architecture

Instead:

```
Internet

↓

Bastion Host

↓

Private Network

↓

Production Server
```

Now:

- Only the bastion is publicly accessible.
- Production servers remain private.

---

# What Is a Jump Host?

A Jump Host is a server whose only purpose is to provide secure SSH access to machines inside a private network.

Example:

```
Laptop

↓

SSH

↓

Bastion

↓

SSH

↓

Production
```

The bastion acts as a gateway.

---

# Without `ProxyJump`

You first connect to the bastion:

```bash
ssh user@bastion
```

Then:

```bash
ssh user@production
```

Two commands.

Two authentication steps.

---

# With `ProxyJump`

One command:

```bash
ssh -J user@bastion user@production
```

SSH automatically:

```
Laptop

↓

Bastion

↓

Production
```

You log directly into the production server.

---

# Understanding the Syntax

General form:

```bash
ssh -J jump_host destination_host
```

Example:

```bash
ssh -J deploy@bastion deploy@production
```

Meaning:

```
Laptop

↓

deploy@bastion

↓

deploy@production
```

---

# How It Works Internally

```
Laptop

↓

Encrypted SSH Connection

↓

Bastion

↓

Encrypted SSH Connection

↓

Production
```

Your SSH client creates both connections automatically.

You don't manually log into the bastion first.

---

# SSH Config Example

Instead of remembering long commands:

```
Host bastion
    HostName bastion.example.com
    User deploy

Host production
    HostName 10.0.1.20
    User deploy
    ProxyJump bastion
```

Now:

```bash
ssh production
```

SSH performs:

```
Laptop

↓

Bastion

↓

Production
```

Automatically.

Example:


# Combining with Port Forwarding

You can use `ProxyJump` together with local forwarding:

```bash
ssh \
-J deploy@bastion \
-L 5432:localhost:5432 \
deploy@production
```

Now:

```
Laptop

↓

SSH Tunnel

↓

Production PostgreSQL
```

through the bastion.

---

# Combining with Agent Forwarding

```bash
ssh \
-A \
-J deploy@bastion \
deploy@production
```

Flow:

```
Laptop

SSH Agent

↓

Bastion

↓

Production
```

Your private key remains on your laptop.

Suppose:

```

    User deploy

    HostName 10.0.1.10
```


```bash

```

# How `ProxyJump` Differs from `ProxyCommand`

Older SSH versions often used:

```
ProxyCommand ssh bastion -W %h:%p
```

Modern OpenSSH provides:

```
ProxyJump bastion
```

`ProxyJump` is easier to read and maintain, and it internally uses similar mechanisms.

# Common Errors

## Error

```
Could not resolve hostname production
```

Check:

```bash
cat ~/.ssh/config
```

Ensure the host alias and `HostName` are correct.

---

## Error

```
Permission denied (publickey)
```

Verify:

```bash
ssh-add -l
```

Confirm that your SSH key is loaded and authorized on both the bastion and the destination server (if applicable).

---

## Error

```
Connection timed out
```

Possible causes:

- Bastion unreachable
- Wrong private IP
- Firewall/security group rules
- SSH service not running

---

# Best Practices

- Never expose production servers directly unless necessary.
- Use a dedicated bastion host.
- Prefer `ProxyJump` over manually SSHing through intermediate hosts.
- Use SSH keys instead of passwords.
- Combine with `ssh-agent` and agent forwarding when appropriate.
- Keep your `~/.ssh/config` organized with descriptive host aliases.

# Interview Questions

### 1. What is a Jump Host?

A Jump Host (or Bastion Host) is a publicly reachable server that provides controlled SSH access to servers inside a private network.

---

### 2. What does `ssh -J` do?

It automatically connects through one or more intermediate SSH hosts before reaching the final destination.

---

### 3. Why use a bastion host?

To reduce the attack surface by keeping internal servers off the public internet while still allowing administrative access.

---

### 4. What is the difference between `ProxyJump` and `ProxyCommand`?

`ProxyJump` is the modern, simpler configuration option for SSH jump hosts. `ProxyCommand` is the older, more flexible mechanism that can accomplish the same goal but requires more configuration.

---

### 5. Can `ProxyJump` be combined with other SSH features?

Yes. It works with:

- Agent forwarding (`A`)
- Local port forwarding (`L`)
- Remote port forwarding (`R`)
- Dynamic port forwarding (`D`)
- SSH configuration files
