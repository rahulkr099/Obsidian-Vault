# Module 5 — Advanced SSH

# Lesson 9: SSH Multiplexing (`ControlMaster`) — Reuse SSH Connections Like a Pro

Every time you run:

```bash
ssh server
```

or

```bash
scp file.txt server:/tmp
```

or

```bash
rsync -av ./app server:/var/www
```

SSH performs the full connection process:

- DNS lookup
- TCP connection
- SSH handshake
- Key exchange
- Encryption negotiation
- Authentication

This process may only take a second or two, but when you perform dozens or hundreds of SSH operations each day, the delay adds up.

**SSH Multiplexing** solves this by allowing multiple SSH sessions to share a single underlying connection.

# What Is SSH Multiplexing?

Normally:

```
Laptop

↓

SSH

↓

Server
```

Every command creates a **new** SSH connection.

With multiplexing:

```
Laptop

↓

Master SSH Connection

├── SSH Session
├── SCP
├── RSYNC
├── Git
└── SFTP
```

Everything shares the same encrypted connection.

---

# Without Multiplexing

Suppose you execute:

```bash
ssh production
```

Then:

```bash
scp backup.sql production:/tmp
```

Then:

```bash
rsync app/ production:/var/www
```

Then:

```bash
git push
```

Four separate SSH handshakes occur.

---

# With Multiplexing

The first command creates the master connection.

The remaining commands reuse it.

```
Master Connection

↓

SSH

↓

Server
```

Result:

- Faster
- Less CPU usage
- Better user experience

---

# The Three Main Options

SSH multiplexing is controlled by three configuration options.

|Option|Purpose|
|---|---|
|`ControlMaster`|Enables a master connection|
|`ControlPath`|Specifies where the control socket is stored|
|`ControlPersist`|Keeps the master connection alive after the first session exits|

---

# ControlMaster

Example:

```
Host production
    ControlMaster auto
```

Meaning:

```
If a master connection exists

↓

Reuse it

Otherwise

↓

Create one
```

Values include:

|Value|Meaning|
|---|---|
|`no`|Disable multiplexing|
|`yes`|Always become master|
|`auto`|Reuse existing master or create one|
|`ask`|Ask before sharing|

`auto` is the most common choice.

---

# ControlPath

SSH needs a Unix socket for communication.

Example:

```
ControlPath ~/.ssh/control-%r@%h:%p
```

Variables:

|Variable|Meaning|
|---|---|
|`%r`|Remote user|
|`%h`|Host|
|`%p`|Port|

Example:

```
~/.ssh/control-deploy@server.example.com:22
```

Each host gets its own control socket.

---

# ControlPersist

Without it:

```
SSH Session Ends

↓

Master Connection Closes
```

With:

```
ControlPersist 10m
```

The master connection remains open for 10 minutes after the last session exits.

Values can be:

```
5m
30m
1h
yes
```

`yes` means "keep it alive indefinitely until manually closed."

---

# Complete Configuration

Edit:

```
~/.ssh/config
```

Add:

```
Host *
    ControlMaster auto
    ControlPath ~/.ssh/control-%r@%h:%p
    ControlPersist 15m
```

Now every SSH host can use multiplexing.

---

# Create the Socket Directory

Some systems don't already have a suitable directory.

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
```

If you prefer a dedicated directory:

```bash
mkdir -p ~/.ssh/controlmasters
chmod 700 ~/.ssh/controlmasters
```

Then update:

```
ControlPath ~/.ssh/controlmasters/%r@%h:%p
```

# Using rsync

Without multiplexing:

```bash

```

SSH negotiates a new connection.

With multiplexing:

It immediately reuses the existing master connection.

# Closing the Master Connection

```bash

```

Output:


# Stopping Individual Sessions

Closing one SSH terminal:

```bash

```

does **not** necessarily close the master connection if `ControlPersist` is active.

# Common Errors

## Error

```
Control socket connect(...): No such file or directory
```

Create the directory:

```bash
mkdir -p ~/.ssh/controlmasters
```

Update:

```
ControlPath ~/.ssh/controlmasters/%r@%h:%p
```

---

## Error

```
Too long for Unix domain socket
```

The socket path exceeds your operating system's maximum length.

Use a shorter path:

```
ControlPath ~/.ssh/cm/%C
```

`%C` creates a hashed filename and is the recommended modern approach.

---

## Error

```
Master is not running
```

Simply reconnect:

```bash
ssh production
```

A new master connection will be created.

---

# Security Considerations

- Use multiplexing only on trusted machines.
- Protect your `~/.ssh` directory:

```bash
chmod 700 ~/.ssh
```

- Protect your SSH configuration:

```bash
chmod 600 ~/.ssh/config
```

- Use `ControlPersist` with a reasonable timeout rather than leaving connections open indefinitely on shared computers.

---

# Best Practices

- Use `ControlMaster auto`.
- Use `%C` in `ControlPath` to avoid long socket paths:

```
ControlPath ~/.ssh/cm/%C
```

- Use `ControlPersist 10m` or `15m` for interactive work.
- Close idle master connections when you're done:

```bash
ssh -O exit production
```

# Interview Questions

### 1. What is SSH multiplexing?

It allows multiple SSH-based sessions and tools to reuse a single SSH connection instead of creating a new connection each time.

---

### 2. What does `ControlMaster auto` do?

It creates a master connection if one doesn't exist and reuses it for subsequent connections.

---

### 3. What is `ControlPersist`?

It keeps the master connection alive for a specified period after the last client disconnects.

---

### 4. Why is `%C` recommended for `ControlPath`?

It generates a short hashed filename, helping avoid Unix socket path length limits and filename collisions.

---

### 5. Which tools benefit from SSH multiplexing?

- `ssh`
- `scp`
- `sftp`
- `rsync`
- Git over SSH
