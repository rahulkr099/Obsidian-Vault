# Module 6 — SSH Security

# Lesson 1: `authorized_keys` — The Foundation of SSH Key Authentication

Every time you log in to a Linux server without entering a password, the server checks one file:

```
~/.ssh/authorized_keys
```

This file determines **who is allowed to log in** using SSH public keys.

Understanding `authorized_keys` is one of the most important SSH security skills.

---

# Learning Objectives

By the end of this lesson, you'll be able to:

- Understand what `authorized_keys` is
- Know how SSH public key authentication works
- Add and remove SSH keys
- Manage multiple keys safely
- Understand file permissions
- Troubleshoot common authentication problems

# What is `authorized_keys`?

`authorized_keys` is a text file that contains **public SSH keys** that are allowed to authenticate to a specific user account.

Example:

```
/home/rahul/.ssh/authorized_keys
```

or

```
~/.ssh/authorized_keys
```

Only the user who owns this account can log in using the corresponding private key.

---

# How SSH Key Authentication Works

Imagine you have:

On your laptop:

```
~/.ssh/

id_ed25519        ← Private key
id_ed25519.pub    ← Public key
```

On the server:

```
~/.ssh/

authorized_keys
```

Authentication flow:

```
Laptop
│
├── Private Key
│
▼
SSH Connection
│
▼
Server
│
├── authorized_keys
│
▼
Does the matching public key exist?
│
├── Yes → Login Allowed ✅
└── No  → Login Denied ❌
```

---

# Private Key vs Public Key

|Private Key|Public Key|
|---|---|
|Secret|Safe to share|
|Stays on your laptop|Stored on the server|
|Never upload publicly|Added to `authorized_keys`|
|Used to prove your identity|Used to verify your identity|

A simple rule:

> **Never share your private key.**

# Where is `authorized_keys`?

For user `rahul`:

```
/home/rahul/.ssh/authorized_keys
```

For root:

```
/root/.ssh/authorized_keys
```

Check it:

```bash
ls -la ~/.ssh
```

Example:

```
authorized_keys
known_hosts
config
```

---

# Viewing the File

```bash
cat ~/.ssh/authorized_keys
```

Example:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIHQ3...
```

Each line represents **one authorized public key**.

---

# File Format

A typical line looks like:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIB9R2Sx... rahul@laptop
```

It contains:

```
Algorithm

↓

ssh-ed25519

↓

Public Key

↓

Comment
```

---

# Understanding the Parts

Example:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIG5L... office-laptop
```

|Part|Meaning|
|---|---|
|`ssh-ed25519`|Key algorithm|
|`AAAAC3...`|Public key data|
|`office-laptop`|Comment (optional label)|

---

# Multiple Keys

A server can trust multiple devices.

Example:

```
ssh-ed25519 AAAA... office-laptop

ssh-ed25519 AAAA... home-desktop

ssh-ed25519 AAAA... macbook

ssh-ed25519 AAAA... work-laptop
```

Each key allows login independently.

---

# Adding a New Key

Generate a key on your laptop:

```bash
ssh-keygen -t ed25519
```

Copy the public key:

```bash
cat ~/.ssh/id_ed25519.pub
```

Append it to the server's `authorized_keys`.

The easiest method:

```bash
ssh-copy-id user@server
```

Or manually:

```bash
cat ~/.ssh/id_ed25519.pub | ssh user@server "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

---

# Verify the New Key

Log in:

```bash
ssh user@server
```

If configured correctly, SSH authenticates using the private key and you won't be prompted for the server account's password (unless your private key itself is protected by a passphrase).

---

# Removing a Key

Open the file:

```bash
nano ~/.ssh/authorized_keys
```

or

```bash
nvim ~/.ssh/authorized_keys
```

Delete the unwanted line.

Save.

That key immediately loses access.

---

# Check Which Keys Are Installed

```bash
wc -l ~/.ssh/authorized_keys
```

Output:

```
4
```

Meaning:

```
4 Authorized Public Keys
```

---

# Search for a Specific Device

```bash
grep office ~/.ssh/authorized_keys
```

Example:

```
ssh-ed25519 AAAA... office-laptop
```

Useful for finding a specific key among many.

---

# Back Up Before Editing

```bash
cp ~/.ssh/authorized_keys \
~/.ssh/authorized_keys.backup
```

If something goes wrong:

```bash
mv ~/.ssh/authorized_keys.backup \
~/.ssh/authorized_keys
```

---

# Correct Permissions

SSH is strict about permissions.

Directory:

```bash
chmod 700 ~/.ssh
```

File:

```bash
chmod 600 ~/.ssh/authorized_keys
```

Verify:

```bash
ls -ld ~/.ssh
ls -l ~/.ssh/authorized_keys
```

Expected:

```
drwx------ .ssh
-rw------- authorized_keys
```

---

# Common Mistakes

## Wrong Permissions

Bad:

```
777
```

Good:

```
700
600
```

---

## Public Key in the Wrong Place

Incorrect:

```
known_hosts
```

Correct:

```
authorized_keys
```

---

## Uploading the Private Key

Never copy:

```
id_ed25519
```

Only copy:

```
id_ed25519.pub
```

---

## Editing as the Wrong User

This:

```
/root/.ssh/authorized_keys
```

is different from:

```
/home/rahul/.ssh/authorized_keys
```

Always edit the correct user's file.

---

# Troubleshooting

## Permission denied (publickey)

Check:

```bash
ls -ld ~/.ssh
ls -l ~/.ssh/authorized_keys
```

Verify your public key is actually present:

```bash
grep "$(cut -d' ' -f2 ~/.ssh/id_ed25519.pub)" ~/.ssh/authorized_keys
```

---

## Wrong Key Being Offered

See which keys the SSH client is trying:

```bash
ssh -v user@server
```

Look for lines such as:

```
Offering public key:
```

---

## SSH Agent Has No Keys

List loaded keys:

```bash
ssh-add -l
```

Add one if needed:

```bash
ssh-add ~/.ssh/id_ed25519
```

---

# Best Practices

- Use **Ed25519** keys for new deployments.
- Keep one key per device.
- Use meaningful comments such as `rahul-work-laptop`.
- Remove keys for devices you no longer use.
- Protect private keys with a passphrase.
- Review `authorized_keys` periodically and remove stale entries.

# Interview Questions

### 1. What is `authorized_keys`?

It is a file that stores the public SSH keys allowed to authenticate to a user account on a server.

---

### 2. Where is `authorized_keys` located?

Typically at:

```
~/.ssh/authorized_keys
```

for the target user.

---

### 3. Can one user have multiple public keys?

Yes. Each line in `authorized_keys` is a separate authorized public key, allowing multiple devices or users to authenticate.

---

### 4. What happens if you delete a key from `authorized_keys`?

The corresponding private key can no longer be used to log in to that account.

---

### 5. Why are file permissions important?

OpenSSH refuses to use insecurely permissioned SSH files because they could be modified or read by unauthorized users.
