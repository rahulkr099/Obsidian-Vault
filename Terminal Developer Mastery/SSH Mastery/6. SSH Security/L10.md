# Module 6 — SSH Security

# Lesson 10: SSH Logging & Auditing — Monitoring and Investigating SSH Activity

A secure SSH server isn't just about preventing attacks—it's also about **knowing who connected, when they connected, and what happened**.

If someone gains unauthorized access, your **logs are the first place you'll investigate**.

This lesson teaches you how Linux administrators audit SSH activity in production.

---

# Learning Objectives

By the end of this lesson, you'll be able to:

- Monitor successful SSH logins
- Investigate failed login attempts
- View SSH logs with `journalctl`
- Use `last`, `lastb`, and `who`
- Audit active SSH sessions
- Detect suspicious login activity
- Investigate SSH security incidents

---

# Where Does SSH Store Logs?

The location depends on your Linux distribution.

|Distribution|Log Source|
|---|---|
|Ubuntu/Debian|`journalctl -u ssh` and often `/var/log/auth.log`|
|RHEL/CentOS|`journalctl -u sshd` and often `/var/log/secure`|

Modern Linux systems increasingly use **systemd-journald**, so `journalctl` works on most distributions.

---

# Viewing SSH Logs

Ubuntu/Debian:

```bash
sudo journalctl -u ssh
```

RHEL/CentOS:

```bash
sudo journalctl -u sshd
```

Example:

```
Jul 29 09:10 sshd[1021]: Accepted publickey for rahul
Jul 29 09:15 sshd[1043]: Failed password for root
Jul 29 09:17 sshd[1056]: Connection closed
```

---

# Show Recent SSH Activity

Last hour:

```bash
sudo journalctl -u ssh --since "1 hour ago"
```

Today:

```bash
sudo journalctl -u ssh --since today
```

Yesterday:

```bash
sudo journalctl -u ssh --since yesterday
```

Specific time:

```bash
sudo journalctl -u ssh --since "2026-07-29 08:00"
```

---

# Follow Logs Live

Like `tail -f`:

```bash
sudo journalctl -u ssh -f
```

Open another terminal and SSH into the server.

You'll immediately see new log entries.

---

# Authentication Logs

Ubuntu/Debian:

```bash
sudo tail -f /var/log/auth.log
```

RHEL/CentOS:

```bash
sudo tail -f /var/log/secure
```

Typical output:

```
Accepted publickey for rahul
```

or

```
Failed password for root
```

---

# Successful Login

Example:

```
Accepted publickey for rahul from 203.0.113.25 port 51432 ssh2
```

This tells you:

|Information|Value|
|---|---|
|User|rahul|
|Authentication|Public Key|
|Source IP|203.0.113.25|
|Port|51432|

---

# Failed Login

Example:

```
Failed password for invalid user admin from 198.51.100.12
```

Meaning:

- Someone attempted login
- Username didn't exist
- Login failed

Repeated messages often indicate automated scanning.

---

# Invalid User Detection

Example:

```
Invalid user oracle from 198.51.100.20
```

Bots commonly try usernames such as:

```
root
admin
oracle
postgres
ubuntu
git
mysql
```

Seeing these occasionally on Internet-facing servers is common.

---

# Search Only Failed Logins

```bash
sudo journalctl -u ssh | grep "Failed"
```

Or:

```bash
sudo grep "Failed" /var/log/auth.log
```

---

# Search Successful Logins

```bash
sudo journalctl -u ssh | grep "Accepted"
```

Example:

```
Accepted publickey for deploy
Accepted publickey for rahul
```

---

# Search by IP Address

Suppose:

```
203.0.113.25
```

Search:

```bash
sudo journalctl -u ssh | grep "203.0.113.25"
```

Useful when investigating a specific client.

---

# Login History — `last`

View recent successful logins:

```bash
last
```

Example:

```
rahul pts/0 203.0.113.25
deploy pts/1 198.51.100.20
```

Shows:

- User
- Source IP
- Login time
- Logout time
- Session duration

---

# Failed Login History — `lastb`

```bash
sudo lastb
```

Example:

```
root ssh:notty 198.51.100.11
admin ssh:notty 198.51.100.20
```

Displays failed login attempts (if the system records them).

---

# Who Is Logged In?

Current users:

```bash
who
```

Example:

```
rahul pts/0
deploy pts/1
```

---

# Detailed Session Information

```bash
w
```

Example:

```
USER   TTY  FROM
rahul  pts/0 203.0.113.25
```

Shows:

- Logged-in user
- Source IP
- Idle time
- Current command

---

# Active SSH Connections

List SSH-related TCP connections:

```bash
ss -tnp | grep ssh
```

Example:

```
ESTAB
203.0.113.25:51432
```

This helps identify active SSH sessions.

---

# Verify the SSH Service

Ubuntu/Debian:

```bash
systemctl status ssh
```

RHEL/CentOS:

```bash
systemctl status sshd
```

Verify:

```
Active: active (running)
```

---

# Investigating a Suspicious Login

Suppose someone reports:

```
"I think someone logged into my server."
```

A typical investigation might be:

### Step 1

Check recent logins:

```bash
last
```

---

### Step 2

Search SSH logs:

```bash
sudo journalctl -u ssh --since yesterday
```

---

### Step 3

Search the suspicious IP:

```bash
sudo journalctl -u ssh | grep "198.51.100.20"
```

---

### Step 4

Check active sessions:

```bash
who
```

---

### Step 5

Review failed attempts:

```bash
sudo lastb
```

This provides a timeline of authentication activity.

---

# Signs of an Attack

Watch for:

- Hundreds of failed logins
- Many username guesses
- Logins from unexpected countries or networks
- Successful login after many failures
- Root login attempts
- Repeated attempts against service accounts

---

# Real-World Example

Normal:

```
Accepted publickey for deploy
```

Suspicious:

```
Failed password for root
Failed password for root
Failed password for root
Failed password for root
Failed password for root
```

This pattern suggests a brute-force attack.

Fail2Ban should respond by banning the attacking IP after the configured threshold.

---

# Helpful Search Commands

Failed logins:

```bash
sudo journalctl -u ssh | grep Failed
```

Accepted logins:

```bash
sudo journalctl -u ssh | grep Accepted
```

Invalid users:

```bash
sudo journalctl -u ssh | grep "Invalid user"
```

Specific user:

```bash
sudo journalctl -u ssh | grep rahul
```

---

# Security Best Practices

- Review SSH logs regularly.
- Investigate repeated failed logins.
- Enable Fail2Ban.
- Use SSH keys instead of passwords.
- Disable root login.
- Archive logs for long-term auditing.
- Monitor logs with centralized logging tools in larger environments.

# Interview Questions

### 1. How do you view SSH logs on a modern Linux system?

Use:

```bash
sudo journalctl -u ssh
```

or on some distributions:

```bash
sudo journalctl -u sshd
```

---

### 2. What command shows successful login history?

```bash
last
```

---

### 3. What command shows failed login history?

```bash
sudo lastb
```

---

### 4. How do you see who is currently logged in?

```bash
who
```

or for more detail:

```bash
w
```

---

### 5. How would you investigate a suspected SSH intrusion?

A structured approach is:

1. Review recent logins with `last`.
2. Examine SSH logs using `journalctl`.
3. Search for the relevant IP address or username.
4. Review failed attempts with `lastb`.
5. Check active sessions using `who`, `w`, and `ss`.
6. If necessary, revoke access (for example, remove compromised keys), rotate credentials, and preserve logs for further analysis.
