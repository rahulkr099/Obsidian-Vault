# Lesson 13: Bastion Hosts & Jump Servers — Secure Access to Private Infrastructure

In small setups, you might SSH directly into a server:

```
Laptop
   │
   ▼
Production Server
```

This works for one or two servers.

But in a company with hundreds of production machines, **direct Internet access to every server is a security risk**.

Instead, organizations use a **bastion host** (also called a **jump server**).

# What is a Bastion Host?

A **bastion host** is a hardened server that acts as the **single entry point** into a private network.

Instead of connecting directly to every server:

```
Internet

↓

Production Servers
```

Users connect like this:

```
Laptop

↓

Bastion Host

↓

Private Servers
```

---

# Why Use a Bastion Host?

Imagine this environment:

```
Web Server
API Server
Database Server
Redis Server
Monitoring Server
```

If every server has a public IP:

```
Internet
   │
   ├── Web
   ├── API
   ├── DB
   ├── Redis
   └── Monitoring
```

Every server becomes a possible attack target.

Instead:

```
Internet
   │
   ▼
Bastion
   │
   ├── Web
   ├── API
   ├── DB
   ├── Redis
   └── Monitoring
```

Only the bastion is exposed publicly.

---

# Example Architecture

```
                    Internet
                        │
                 Public IP Address
                        │
                +----------------+
                | Bastion Host   |
                +----------------+
                   │    │    │
        ┌──────────┘    │    └──────────┐
        ▼               ▼               ▼
   Web Server      API Server      DB Server
  (Private IP)    (Private IP)    (Private IP)
```

The application servers only have **private IP addresses**.

---

# Benefits

A bastion host provides:

- One public entry point
- Centralized authentication
- Easier logging
- Simpler auditing
- Reduced attack surface
- Better network isolation

---

# Private Network Example

```
10.0.0.10  Web
10.0.0.20  API
10.0.0.30  Database
10.0.0.40  Redis
```

These addresses are **not routable over the public Internet**.

Only the bastion can reach them.

---

# Connecting Without a Bastion

```bash
ssh web@203.0.113.10
```

```bash
ssh api@203.0.113.11
```

```bash
ssh db@203.0.113.12
```

Problems:

- Many exposed servers
- More firewall rules
- Harder auditing
- Larger attack surface

---

# Connecting Through a Bastion

First connect:

```bash
ssh admin@bastion.example.com
```

Then:

```bash
ssh web@10.0.0.10
```

or:

```bash
ssh db@10.0.0.30
```

---

# Using `ProxyJump`

Modern OpenSSH supports jumping through the bastion automatically.

Example:

```bash
ssh -J admin@bastion.example.com web@10.0.0.10
```

Meaning:

```
Laptop

↓

Bastion

↓

Web Server
```

You only run one command.

---

# Configure `~/.ssh/config`

Instead of typing `-J` every time:

```
Host bastion
    HostName bastion.example.com
    User admin
    IdentityFile ~/.ssh/id_ed25519

Host web
    HostName 10.0.0.10
    User web
    ProxyJump bastion

Host api
    HostName 10.0.0.20
    User api
    ProxyJump bastion

Host db
    HostName 10.0.0.30
    User db
    ProxyJump bastion
```

Now you can simply run:

```bash
ssh web
```

SSH automatically connects through the bastion.

---

# How `ProxyJump` Works

```
Laptop

↓

SSH Connection

↓

Bastion

↓

New SSH Connection

↓

Target Server
```

The traffic remains encrypted end-to-end between your client and the destination server.

# Logging and Auditing

Since everyone enters through the bastion:

Logs show:

```
09:00 Rahul logged in

09:02 Connected to Web

09:15 Connected to Database

09:30 Logged out
```

This provides a central audit trail.

# Restricting the Bastion

A bastion should be more secure than ordinary servers.

Typical controls include:

- SSH keys only
- No password authentication
- No root login
- Fail2Ban enabled
- Regular updates
- Minimal installed software
- Restricted administrator access

---

# Firewall Example

Allow SSH only to the bastion:

```
Internet

↓

TCP 22

↓

Bastion
```

Internal servers:

```
SSH

↓

Private Network Only
```

The database server should reject direct Internet connections.

# High Availability

Large organizations often deploy multiple bastion hosts.

```
          Load Balancer
               │
      ┌────────┴────────┐
      ▼                 ▼
 Bastion 1         Bastion 2
      │                 │
      └────────┬────────┘
               ▼
       Private Network
```

This improves availability if one bastion becomes unavailable.

---

# File Copy Through a Bastion

Modern OpenSSH also supports jumping with file transfer tools.

Copy a file:

```bash
scp -J admin@bastion.example.com backup.sql db@10.0.0.30:/tmp/
```

Or synchronize a directory:

```bash
rsync -e "ssh -J admin@bastion.example.com" -av ./app/ web@10.0.0.10:/var/www/app/
```

# Common Mistakes

## Exposing Every Server

Wrong:

```
Internet

↓

Web
API
DB
Redis
```

Correct:

```
Internet

↓

Bastion

↓

Private Network
```

---

## Weak Bastion Security

Never configure:

```
PermitRootLogin yes
PasswordAuthentication yes
```

A compromised bastion can expose the entire private network.

---

## Shared Administrator Accounts

Avoid everyone logging in as:

```
admin
```

Instead:

- Give each administrator an individual account.
- Use SSH keys or SSH certificates.
- Use `sudo` for privileged actions.

This improves accountability.

---

## Poor Logging

If you don't monitor bastion logs:

```
Who Logged In?

Unknown
```

Centralized logging is one of the biggest advantages of a bastion.

---

# Security Best Practices

- Expose only the bastion to the Internet.
- Keep internal servers on private IP addresses.
- Use SSH keys or certificates.
- Enable multi-factor authentication (MFA) if your environment supports it.
- Monitor bastion logs continuously.
- Patch and harden the bastion frequently.
- Restrict which users can access the bastion.
- Limit outbound access from the bastion to only necessary internal systems.

---

# Real-World Examples

Many cloud and enterprise environments use a bastion or an equivalent secure access layer:

- AWS VPC private subnets
- Azure Virtual Networks
- Google Cloud VPCs
- Corporate data centers
- Kubernetes management clusters

Some organizations are also moving toward alternatives such as VPN-based access, identity-aware proxies, or zero-trust access platforms, but the underlying principle remains the same: **don't expose every server directly to the Internet**.

# Interview Questions

### 1. What is a bastion host?

A bastion host is a hardened server that acts as the single controlled entry point to systems in a private network.

---

### 2. Why use a bastion instead of exposing every server?

It reduces the attack surface, centralizes authentication and logging, and keeps internal servers inaccessible from the public Internet.

---

### 3. What does `ProxyJump` do?

It allows an SSH client to automatically connect to a destination server through an intermediate SSH server (the bastion).

---

### 4. Why should internal servers use private IP addresses?

Private IP addresses are not directly reachable from the Internet, reducing exposure and requiring access through approved network paths.

---

### 5. How should a bastion host be secured?

- SSH keys or certificates
- No root login
- Password authentication disabled (where practical)
- Fail2Ban or similar protections
- Regular patching
- Comprehensive logging and monitoring
- Access limited to authorized administrators
