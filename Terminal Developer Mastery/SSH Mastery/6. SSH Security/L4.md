# Module 6 — SSH Security

# Lesson 4: Password Authentication Security — Moving from Passwords to SSH Keys

Password authentication is the oldest way to log in to an SSH server.

It works—but it is also one of the biggest security risks.

Modern production servers typically disable password authentication entirely and require **SSH key authentication** instead.

---

# How Password Authentication Works

When you run:

```bash
ssh rahul@server
```

SSH asks:

```
Password:
```

The process is:

```
Laptop
   │
Username + Password
   │
   ▼
SSH Server
   │
Checks password
   │
 ┌──────────┐
 │ Correct? │
 └────┬─────┘
      │
 Yes  ▼  No
 Login   Denied
```

This method is simple but vulnerable to password guessing and brute-force attacks.

---

# The Problem with Passwords

Attackers can automate millions of login attempts.

Example:

```
root
admin
ubuntu
test
deploy
```

combined with:

```
password123
admin123
welcome
qwerty
123456
```

Bots scan the Internet continuously for SSH servers using weak passwords.

---

# How SSH Keys Work

Instead of:

```
Username

+

Password
```

SSH keys use:

```
Private Key

↓

Cryptographic Verification

↓

Server
```

The server never receives your private key.

Only proof that you own it.

---

# Password vs SSH Key

|Password|SSH Key|
|---|---|
|Can be guessed|Cannot realistically be guessed|
|Easy to brute-force|Extremely difficult to brute-force|
|Often reused|Unique per device|
|Typed manually|Used automatically|
|Lower security|Higher security|

---

# SSH Authentication Order

A typical SSH client tries methods in this order:

1. Public key
2. Keyboard-interactive (if enabled)
3. Password (if enabled)

If a valid SSH key is found, you're often logged in without ever seeing a password prompt.

---

# `PasswordAuthentication`

Server setting:

```
PasswordAuthentication yes
```

Meaning:

```
Passwords Allowed
```

Disable it:

```
PasswordAuthentication no
```

Meaning:

```
Passwords Rejected
```

---

# `PubkeyAuthentication`

Server setting:

```
PubkeyAuthentication yes
```

This enables SSH key authentication.

Most production systems keep it enabled.

Turning it off would disable SSH key logins.

---

# `KbdInteractiveAuthentication`

Another authentication method:

```
KbdInteractiveAuthentication yes
```

This is commonly used with:

- Multi-factor authentication (MFA)
- One-time passwords (OTP)
- External authentication systems

It is different from normal password authentication.

---

# Example Secure Configuration

A common production configuration:

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
KbdInteractiveAuthentication no
PermitEmptyPasswords no
```

Meaning:

- Root login disabled
- Passwords disabled
- SSH keys required
- Interactive prompts disabled
- Empty passwords rejected

---

# Checking Current Settings

View the effective configuration:

```bash
sudo sshd -T | grep passwordauthentication
```

Example:

```
passwordauthentication no
```

Check public key authentication:

```bash
sudo sshd -T | grep pubkeyauthentication
```

Example:

```
pubkeyauthentication yes
```

---

# Editing the Configuration

Open:

```bash
sudo nvim /etc/ssh/sshd_config
```

or:

```bash
sudo nano /etc/ssh/sshd_config
```

Example configuration:

```
PasswordAuthentication no
PubkeyAuthentication yes
PermitEmptyPasswords no
```

---

# Validate Before Restarting

Always test:

```bash
sudo sshd -t
```

If no output appears:

```
Configuration OK
```

Restart:

Ubuntu/Debian:

```bash
sudo systemctl restart ssh
```

RHEL/CentOS:

```bash
sudo systemctl restart sshd
```

---

# Never Lock Yourself Out

Wrong sequence:

```
Disable Password Login

↓

Restart SSH

↓

No SSH Key

↓

Locked Out
```

Correct sequence:

```
Create SSH Key

↓

Install Public Key

↓

Test SSH Key Login

↓

Disable Password Login

↓

Restart SSH
```

---

# Verify Key Authentication

Before disabling passwords:

```bash
ssh rahul@server
```

If you're logged in without the server account password, key authentication is working.

For detailed diagnostics:

```bash
ssh -v rahul@server
```

Look for:

```
Offering public key:
```

and:

```
Authenticated with public key.
```

---

# Real-World Deployment

Most cloud providers (AWS, Azure, Google Cloud, DigitalOcean, etc.) encourage or default to SSH key authentication for Linux virtual machines.

A common production setup is:

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
```

This significantly reduces exposure to automated password attacks.

---

# Common Mistakes

## Disabling Passwords Too Early

If you disable password authentication before confirming SSH key access, you may lose remote access.

Always test key login first.

---

## Forgetting to Restart SSH

Editing:

```
/etc/ssh/sshd_config
```

does nothing until the SSH service is reloaded or restarted.

---

## Disabling Public Key Authentication

Bad:

```
PubkeyAuthentication no
```

This prevents SSH key authentication entirely.

---

## Not Validating Configuration

Always run:

```bash
sudo sshd -t
```

before restarting the SSH service.

---

# Security Best Practices

- Disable password authentication on production servers.
- Use Ed25519 SSH keys for new deployments.
- Protect private keys with passphrases.
- Use one key pair per device.
- Remove unused public keys from `authorized_keys`.
- Consider MFA for high-security environments.

# Interview Questions

### 1. Why are SSH keys more secure than passwords?

SSH keys use asymmetric cryptography and are not practical to brute-force. The private key never leaves the client machine.

---

### 2. What does `PasswordAuthentication no` do?

It disables password-based SSH logins, requiring users to authenticate using another enabled method, typically SSH keys.

---

### 3. What is `PubkeyAuthentication`?

It enables authentication using SSH public/private key pairs.

---

### 4. Why should you test key login before disabling passwords?

To ensure you can still access the server remotely and avoid accidentally locking yourself out.

---

### 5. What is `KbdInteractiveAuthentication` commonly used for?

It supports interactive authentication methods such as one-time passwords (OTP) and multi-factor authentication (MFA).
