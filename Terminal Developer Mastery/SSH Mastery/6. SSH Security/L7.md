# Lesson 7: Fail2Ban — Protecting SSH Against Brute-Force Attacks

Imagine your server is connected to the Internet.

Within minutes, bots begin trying to log in:

```
root
admin
ubuntu
test
oracle
git
postgres
```

using passwords like:

```
123456
password
admin123
qwerty
welcome
```

This is called a **brute-force attack**.

**Fail2Ban** automatically detects these attacks and temporarily blocks the attacker's IP address.

It is one of the first security tools installed on production Linux servers.

# What is a Brute-Force Attack?

An attacker repeatedly tries different passwords.

Example:

```
Attempt 1

root / admin

↓

Failed

↓

Attempt 2

root / password

↓

Failed

↓

Attempt 3

root / qwerty

↓

Failed

↓

...
```

Without protection:

```
Millions of Login Attempts
```

---

# How Fail2Ban Works

Fail2Ban watches SSH logs.

When it detects too many failed logins:

```
Client IP

↓

5 Failed Logins

↓

Fail2Ban

↓

Firewall Rule Added

↓

IP Blocked
```

The attacker can no longer connect.

---

# Components of Fail2Ban

|Component|Purpose|
|---|---|
|Filter|Detects suspicious log entries|
|Jail|Defines what action to take|
|Backend|Reads log files or systemd journal|
|Action|Blocks the IP using the firewall|

---

# What is a Jail?

A **jail** combines:

- A filter
- A log source
- Ban rules
- Firewall actions

Example:

```
[sshd]
enabled = true
```

This protects the SSH service.

# Configuration Files

Main file:

```
/etc/fail2ban/jail.conf
```

**Do not edit this file directly.**

Instead create:

```
/etc/fail2ban/jail.local
```

This survives package upgrades.

---

# Basic SSH Configuration

Example:

```
[sshd]
enabled = true
```

This enables SSH protection.

---

# Recommended SSH Jail

Example:

```
[sshd]
enabled = true
port = ssh

maxretry = 5

findtime = 10m

bantime = 1h
```

Meaning:

|Option|Meaning|
|---|---|
|maxretry|5 failed attempts|
|findtime|within 10 minutes|
|bantime|banned for 1 hour|

---

# Understanding the Settings

Suppose:

```
maxretry = 5
```

If someone fails:

```
1

2

3

4

5
```

within:

```
10 minutes
```

they are banned.

If the sixth attempt happens after the `findtime` window has passed, the counter starts over.

# Whitelisting Trusted IPs

Suppose your office IP is:

```
203.0.113.25
```

In `jail.local`:

```
ignoreip = 127.0.0.1/8 ::1 203.0.113.25
```

Now Fail2Ban will never ban that address.

Use this carefully—whitelisting removes protection for that IP.

---

# Typical Production Configuration

```
[DEFAULT]

ignoreip = 127.0.0.1/8

bantime = 1h

findtime = 10m

maxretry = 5

[sshd]

enabled = true
```

This is a solid starting point for many servers.

---

# Common Mistakes

## Editing `jail.conf`

Wrong:

```
/etc/fail2ban/jail.conf
```

Correct:

```
/etc/fail2ban/jail.local
```

---

## Forgetting to Restart

After editing:

```
jail.local
```

restart:

```bash
sudo systemctl restart fail2ban
```

---

## Setting `maxretry` Too Low

Bad:

```
maxretry = 1
```

A single typing mistake could ban legitimate users.

---

## Setting `bantime` Too Long

Bad:

```
bantime = 365d
```

If you accidentally ban yourself, recovery becomes inconvenient.

Start with moderate values such as 1 hour and adjust as needed.

---

# Security Best Practices

- Enable the `sshd` jail.
- Use SSH keys instead of passwords.
- Disable root login.
- Disable password authentication when possible.
- Keep Fail2Ban updated.
- Review ban logs periodically.
- Whitelist only trusted administrative IPs when appropriate.

# Interview Questions

### 1. What is Fail2Ban?

Fail2Ban is a security tool that monitors logs for repeated authentication failures and temporarily blocks offending IP addresses using firewall rules.

---

### 2. What is a Fail2Ban jail?

A jail combines a filter, a log source, and actions that determine when and how an IP address is banned.

---

### 3. What does `maxretry` control?

It specifies the maximum number of failed authentication attempts allowed within the configured `findtime` before an IP is banned.

---

### 4. Why use `jail.local` instead of `jail.conf`?

`jail.local` overrides the default configuration and is preserved during package updates, while `jail.conf` may be replaced.

---

### 5. Does Fail2Ban replace good SSH security practices?

No. It complements them. You should still:

- Use SSH keys
- Disable root login
- Disable password authentication where appropriate
- Keep systems updated
- Limit which users can log in
