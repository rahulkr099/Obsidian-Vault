# SSH Mastery — Module 2, Lesson 8

# Essential SSH Command-Line Options

So far you've used the simplest form:

```bash
ssh ubuntu@203.0.113.10
```

But professional backend developers rarely use SSH with only the defaults.

Today you'll learn the most useful SSH options that you'll use throughout your career.

---

# Learning Objectives

By the end of this lesson, you'll know how to use:

- `i` — Identity file (private key)
- `p` — Custom port
- `l` — Login username
- `v`, `vv`, `vvv` — Debugging
- `C` — Compression
- `N` — No remote shell
- `T` — Disable pseudo-terminal
- `o` — Set SSH options on the command line

---

# General Syntax

```bash
ssh [OPTIONS] user@host
```

Example:

```bash
ssh -i ~/.ssh/id_ed25519 -p 2222 ubuntu@203.0.113.10
```

Multiple options can be combined.

---

# Option 1 — `i` (Identity File)

Use a specific private key.

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@203.0.113.10
```

Without `-i`, SSH tries default key locations like:

```
~/.ssh/id_ed25519
~/.ssh/id_rsa
```

---

## When You'll Use It

Suppose you have:

```
~/.ssh/
├── personal_key
├── company_key
├── aws_key
└── github_key
```

Connect to AWS:

```bash
ssh -i ~/.ssh/aws_key ubuntu@203.0.113.10
```

Connect to a company server:

```bash
ssh -i ~/.ssh/company_key dev@server.company.com
```

---

# Option 2 — `p` (Port)

If SSH listens on a different port:

```bash
ssh -p 2222 ubuntu@203.0.113.10
```

Instead of the default:

```
22
```

Some organizations change the SSH port for operational reasons, although it is **not** a substitute for proper security.

---

# Option 3 — `l` (Login Name)

Instead of:

```bash
ssh ubuntu@203.0.113.10
```

You can write:

```bash
ssh -l ubuntu 203.0.113.10
```

Both commands are equivalent.

---

# Option 4 — `v`

Show debug information.

```bash
ssh -v localhost
```

Example output:

```
OpenSSH_9.x
debug1: Reading configuration data...
debug1: Connecting...
debug1: Authentication succeeded.
```

This helps diagnose connection problems.

---

# More Verbose

```bash
ssh -vv localhost
```

Even more details.

Maximum verbosity:

```bash
ssh -vvv localhost
```

This is often requested when debugging SSH issues.

---

# When to Use `vvv`

If you see:

```
Permission denied (publickey)
```

Run:

```bash
ssh -vvv ubuntu@203.0.113.10
```

You'll see:

- Which keys SSH tried
- Which authentication methods were offered
- Why authentication failed

---

# Option 5 — `C` (Compression)

Enable compression.

```bash
ssh -C ubuntu@203.0.113.10
```

Useful when:

- Slow internet
- Large text output
- Log files

Not usually beneficial for already compressed data such as ZIP files, videos, or images.

---

# Option 6 — `N`

Do **not** execute a remote command or open a shell.

```bash
ssh -N ubuntu@203.0.113.10
```

This is mainly used for:

- SSH tunnels
- Port forwarding

We'll cover those in a later module.

---

# Option 7 — `T`

Disable pseudo-terminal allocation.

Example:

```bash
ssh -T git@github.com
```

This is common for Git operations because Git doesn't need an interactive shell.

Typical output:

```
Hi username! You've successfully authenticated...
```

No shell is started.

---

# Option 8 — `o`

Set SSH configuration options directly on the command line.

Example:

```bash
ssh -o ConnectTimeout=5 ubuntu@203.0.113.10
```

Meaning:

> Give up after 5 seconds if the server doesn't respond.

Another example:

```bash
ssh -o StrictHostKeyChecking=no localhost
```

⚠️ This skips host key verification and is **not recommended** for normal production use. It may be acceptable in short-lived test environments or controlled automation where you understand the security trade-off.

---

# Combining Options

Example:

```bash
ssh \
-i ~/.ssh/company_key \
-p 2222 \
-v \
dev@203.0.113.10
```

SSH will:

- Use `company_key`
- Connect to port 2222
- Show debug information
- Log in as `dev`

# Reading the Manual

Every option is documented.

Open the manual:

```bash
man ssh
```

Search inside:

```
/type option name
```

Example:

```
/-i
```

Next match:

```
n
```

Quit:

```
q
```

Learning to navigate `man` pages is a valuable Linux skill.

# Common Mistakes

## ❌ Wrong Key

```bash
ssh -i wrong_key server
```

Result:

```
Permission denied (publickey)
```

---

## ❌ Wrong Port

```bash
ssh -p 2200 server
```

when the server listens on:

```
22
```

Result:

```
Connection refused
```

---

## ❌ Too Much Debug Output

- `vvv` produces a lot of information.

Use it only when troubleshooting.

Using localhost:

Show debug information:


# Quick Reference

|Option|Purpose|
|---|---|
|`-i`|Specify private key|
|`-p`|Custom SSH port|
|`-l`|Login username|
|`-v`|Debug output|
|`-vv`|More debugging|
|`-vvv`|Maximum debugging|
|`-C`|Enable compression|
|`-N`|No shell or command|
|`-T`|Disable pseudo-terminal|
|`-o`|Set SSH configuration option|

---

# Key Takeaways

- `i` selects the private key to use.
- `p` connects to non-default SSH ports.
- `l` provides the username without using `user@host`.
- `v`, `vv`, and `vvv` are invaluable for debugging.
- `N` and `T` are especially useful for automation and Git.
- `o` lets you customize SSH behavior without editing configuration files.

## Pro Tip ⭐

Many experienced backend engineers avoid typing long SSH commands repeatedly by using an SSH configuration file (`~/.ssh/config`). Instead of:

```bash
ssh -i ~/.ssh/company_key -p 2222 ubuntu@203.0.113.10
```

they simply type:

```bash
ssh production
```

You'll learn how to create these convenient aliases in **Module 2, Lesson 10**, making your daily workflow much faster and less error-prone.
