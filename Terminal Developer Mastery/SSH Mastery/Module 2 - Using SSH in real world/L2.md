# SSH Mastery — Module 2, Lesson 2

# Installing and Configuring an SSH Server

In Module 1, you learned:

- SSH Client → starts the connection
- SSH Server (`sshd`) → accepts the connection

Today, we'll install and configure the SSH server on your **Linux Mint** machine so you can SSH into your own computer.

---

# Learning Objectives

By the end of this lesson, you'll know how to:

- Install `openssh-server`
- Start and stop the SSH service
- Enable it at boot
- Verify it's running
- Check if it's listening on port 22
- Read SSH service logs

---

# Step 1 — Check if OpenSSH Server is Installed

Run:

```bash
dpkg -l | grep openssh-server
```

### If Installed

You'll see something similar to:

```
ii  openssh-server   1:9.6p1-3ubuntu13
```

The `ii` means the package is installed.

---

### If Not Installed

You won't see any output.

No problem—we'll install it.

---

# Step 2 — Update Package Lists

Always refresh package information first:

```bash
sudo apt update
```

This downloads the latest package index.

> **It does not upgrade your system.** It only updates the list of available packages.

---

# Step 3 — Install OpenSSH Server

Run:

```bash
sudo apt install openssh-server
```

APT downloads and installs:

- `sshd`
- Configuration files
- Systemd service
- Host keys (generated automatically if needed)

Typical output ends with:

```
Setting up openssh-server...
Created symlink ...
```

---

# Step 4 — Check the Service Status

Run:

```bash
systemctl status ssh
```

Example:

```
● ssh.service - OpenBSD Secure Shell server
     Loaded: loaded
     Active: active (running)
```

The important line is:

```
Active: active (running)
```

That means your SSH server is accepting connections.

---

# Understanding Service States

|Status|Meaning|
|---|---|
|active (running)|SSH server is running|
|inactive (dead)|Installed but stopped|
|failed|Service crashed or configuration problem|
|not found|Not installed|

---

# Step 5 — Start the Service

If it's stopped:

```bash
sudo systemctl start ssh
```

Check again:

```bash
systemctl status ssh
```

---

# Step 6 — Stop the Service

Sometimes you need to stop SSH.

```bash
sudo systemctl stop ssh
```

Verify:

```bash
systemctl status ssh
```

It should show:

```
inactive (dead)
```

Start it again:

```bash
sudo systemctl start ssh
```

---

# Step 7 — Restart the Service

When you change SSH configuration, restart it:

```bash
sudo systemctl restart ssh
```

This reloads the service with new settings.

---

# Step 8 — Enable SSH at Boot

Without enabling it, SSH may not start automatically after a reboot.

Enable it:

```bash
sudo systemctl enable ssh
```

Example:

```
Created symlink ...
```

Now SSH starts every time Linux boots.

---

# Step 9 — Verify It's Enabled

Run:

```bash
systemctl is-enabled ssh
```

Expected output:

```
enabled
```

---

# Step 10 — Check if SSH Is Listening

A running service should listen on a network port.

Check with:

```bash
ss -tln | grep :22
```

Example:

```
LISTEN 0 128 0.0.0.0:22
LISTEN 0 128 [::]:22
```

Meaning:

- SSH is listening on IPv4
- SSH is listening on IPv6

---

# Understanding the Output

```
0.0.0.0:22
```

means:

> Accept SSH connections on **all IPv4 network interfaces**.

---

```
[::]:22
```

means:

> Accept SSH connections on **all IPv6 network interfaces**.

---

# Step 11 — Test Local SSH

Now try:

```bash
ssh localhost
```

If prompted:

```
Are you sure you want to continue connecting?
```

Type:

```
yes
```

Authenticate with your password or SSH key.

If successful:

```
rahul@mint:~$
```

You're now connected to your own computer through SSH.

---

# Step 12 — Exit

Leave the SSH session:

```bash
exit
```

or press:

```
Ctrl + D
```

---

# Step 13 — View Recent SSH Logs

System logs are invaluable for troubleshooting.

View recent SSH service logs:

```bash
journalctl -u ssh --no-pager
```

To see only the latest entries:

```bash
journalctl -u ssh -n 20 --no-pager
```

You'll find information such as:

- Service start
- Service stop
- Login attempts
- Errors
- Configuration issues

---

# Step 14 — Check if Port 22 Is Open

Another way:

```bash
sudo ss -tulpn | grep ssh
```

Example:

```
tcp LISTEN 0 128 0.0.0.0:22
```

This also shows which process owns the listening socket.

# Real Backend Example

Imagine you've deployed your Node.js backend on a VPS.

The SSH service is running.

You connect:

```bash
ssh ubuntu@203.0.113.10
```

The server:

- Accepts the TCP connection on port 22
- Authenticates you


The same process works locally with `ssh localhost`.

# Common Problems

## SSH Service Not Found

```
Unit ssh.service could not be found
```

Fix:

```bash
sudo apt install openssh-server
```

---

## SSH Not Running

```
inactive (dead)
```

Fix:

```bash
sudo systemctl start ssh
```

---

## Connection Refused

```
ssh: connect to host localhost port 22:
Connection refused
```

Possible causes:

- SSH service stopped
- Firewall blocking port 22
- Wrong port configured

---

## Permission Denied

```
Permission denied
```

Possible causes:

- Wrong username
- Wrong password
- SSH key mismatch

# Key Takeaways

- `openssh-server` provides the `sshd` service.
- `systemctl` is used to manage the SSH service.
- A healthy SSH server is **active (running)** and listening on **port 22**.
- `systemctl enable ssh` starts SSH automatically after boot.
- `journalctl` is your first stop when troubleshooting SSH service issues.

## Pro Tip ⭐

Whenever you troubleshoot an SSH problem, follow this quick checklist:

1. Is the package installed?
2. Is the service **running**?
3. Is it **enabled** at boot?
4. Is it **listening on the expected port**?
5. What do the **logs** say?

Following these five steps will solve a large percentage of SSH server issues.
