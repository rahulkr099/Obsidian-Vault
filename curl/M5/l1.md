# What is Web Scraping?

**Web scraping** is the process of automatically collecting information from websites.

Instead of manually copying information from a webpage, a program downloads the page and extracts the data you need.

For example, imagine a webpage like this:

```html
<h1>Linux News</h1>

<p>Ubuntu 26.04 Released</p>

<p>Fedora 45 Announced</p>

<p>Docker Desktop Updated</p>
```

A scraper can automatically collect:

```
Ubuntu 26.04 Released
Fedora 45 Announced
Docker Desktop Updated
```

without you copying each line manually.

# Scraping vs APIs

Whenever possible, **use an API instead of scraping**.

|API|Web Scraping|
|---|---|
|Structured data|HTML pages|
|Stable|Layout can change|
|Faster|Often slower|
|Easier to parse|Harder to parse|
|Official|Sometimes unofficial|
|Preferred|Last resort if no API exists|

Example:

API response:

```json
{
  "temperature": 32,
  "city": "Delhi"
}
```

Easy to read.

Website:

```html
<div class="weather">
    <span>32°C</span>
</div>
```

You first need to find the correct HTML element before extracting the temperature.

# How curl Helps

`curl` downloads the raw HTML of a webpage.

Example:

```bash
curl https://example.com
```

Output:

```html
<!doctype html>
<html>

<head>
<title>Example Domain</title>

...
```

`curl` **does not** understand HTML—it simply retrieves it. We'll use other Linux tools later to extract the specific information we need.

---

# Viewing Only Part of a Page

Large webpages can contain thousands of lines.

Use `head` to view the beginning:

```bash
curl -s https://example.com | head
```

Example output:

```html
<!doctype html>

<html>

<head>

<title>Example Domain</title>
```

Use `tail` to view the end:

```bash
curl -s https://example.com | tail
```

---

# Save HTML to a File

Instead of displaying HTML in the terminal:

```bash
curl https://example.com -o page.html
```

Now inspect it:

```bash
cat page.html
```

or

```bash
less page.html
```

---

# Viewing the Page Source

A browser shows a rendered webpage, but `curl` retrieves the original HTML source.

Example:

Browser:

```
Welcome Rahul!
```

Source:

```html
<h1>Welcome Rahul!</h1>
```

Scrapers work with the **HTML source**, not the rendered page.

---

# Static vs Dynamic Websites

This is one of the most important concepts in web scraping.

## Static Website

The server sends the complete HTML.

```
Browser
     ↓
Server
     ↓
Full HTML
```

Example:

```html
<h1>Today's News</h1>
```

`curl` receives the full content.

---

## Dynamic Website

Many modern websites use JavaScript to load data after the page is displayed.

```
Browser
      ↓
HTML
      ↓
JavaScript runs
      ↓
API request
      ↓
Content appears
```

Example:

Initial HTML:

```html
<div id="news"></div>
```

JavaScript later loads:

```html
<div id="news">

Ubuntu Released

</div>
```

`curl` only downloads the initial HTML, so it won't see the content loaded later by JavaScript.

---

# How to Tell if a Website is Dynamic

Run:

```bash
curl -s https://website.com
```

If you mostly see:

```html
<div id="root"></div>
```

or

```html
<div id="app"></div>
```

the website is likely a React, Vue, or Angular application where JavaScript loads most of the content.

---

# Common Challenges

Web scraping can be affected by:

- HTML layout changes
    
- JavaScript-rendered content
    
- Rate limiting
    
- CAPTCHAs
    
- Login requirements
    
- Anti-bot protections
    

A scraper that works today might need updates if the website changes its structure.

# Basic Workflow

```
Website
     ↓
curl downloads HTML
     ↓
Inspect HTML
     ↓
Extract needed data
     ↓
Save or process it
```

We'll build this workflow step by step in the coming lessons.

---

# Best Practices

- Prefer official APIs when available.
    
- Respect a website's terms of service.
    
- Avoid sending too many requests in a short time.
    
- Cache results if frequent updates aren't needed.
    
- Test your scraper after website redesigns.

# Key Takeaways

- `curl` downloads the raw HTML of webpages.
    
- Web scraping extracts useful information from that HTML.
    
- APIs are generally easier and more reliable than scraping.
    
- Static websites are straightforward to scrape; dynamic websites often require additional techniques because content is loaded with JavaScript.
    
- Inspecting the HTML source is the first step before extracting data.
