# Error Handling

Your script should detect:

- Missing `curl`
    
- Missing configuration
    
- Missing input files
    
- Invalid URLs
    
- Connection timeouts
    
- Non-200 HTTP responses
    
- Invalid JSON (if `jq` is available)
    

Log errors instead of silently failing.

# Common Mistakes

❌ Calling `curl` multiple times for the same endpoint when one request can return multiple metrics.

❌ Forgetting `--max-time`, causing the script to hang.

❌ Not checking `curl`'s exit status before processing the response.

❌ Hardcoding URLs instead of reading them from configuration files.

❌ Mixing configuration, business logic, and reporting in one large function.

---

# Best Practices Recap

- Start every production Bash script with:
    

```bash
#!/bin/bash
set -euo pipefail
```

- Quote variables (`"$VAR"`).
    
- Keep configuration separate.
    
- Write small, reusable functions.
    
- Log meaningful events with timestamps.
    
- Use timeouts and retries.
    
- Validate inputs.
    
- Test manually before scheduling with cron.
    
- Keep logs and generated reports out of Git using `.gitignore`.
