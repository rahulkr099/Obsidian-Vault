# What is XML?

**XML (eXtensible Markup Language)** is a format used to store and exchange structured data.

Example:

```xml
<person>
    <name>Rahul</name>
    <age>21</age>
    <city>Bokaro</city>
</person>
```

Unlike HTML, XML is designed for **data**, not presentation.

---

# XML vs HTML

|XML|HTML|
|---|---|
|Stores data|Displays webpages|
|User-defined tags|Predefined tags|
|Strict syntax|More forgiving|
|Used in APIs and feeds|Used in browsers|

---

# XML Structure

Example:

```xml
<book>

    <title>Linux Guide</title>

    <author>John</author>

    <price>49.99</price>

</book>
```

Tree view:

```text
book
├── title
├── author
└── price
```

---

# What is RSS?

**RSS (Really Simple Syndication)** is an XML format that allows websites to publish updates automatically.

Instead of visiting many websites, your RSS reader checks all your subscriptions and shows new content.

Example:

```text
News Website
       ↓
RSS Feed
       ↓
curl
       ↓
Automation Script
       ↓
Your Terminal
```

---

# RSS Feed Example

```xml
<rss>

<channel>

<title>Linux News</title>

<item>

<title>Ubuntu Released</title>

<link>https://example.com/news1</link>

</item>

<item>

<title>Fedora Updated</title>

<link>https://example.com/news2</link>

</item>

</channel>

</rss>
```

Each `<item>` usually represents one article or update.

---

# Download XML with `curl`

Example:

```bash
curl -s https://example.com/feed.xml
```

or

```bash
curl -s https://example.com/rss.xml
```

You'll receive XML instead of HTML.

---

# Save XML

```bash
curl -s https://example.com/feed.xml -o feed.xml
```

View it:

```bash
less feed.xml
```

---

# Find Titles

Suppose `feed.xml` contains:

```xml
<title>Ubuntu Released</title>

<title>Fedora Updated</title>

<title>Docker News</title>
```

Extract titles:

```bash
grep "<title>" feed.xml
```

Output:

```xml
<title>Ubuntu Released</title>

<title>Fedora Updated</title>

<title>Docker News</title>
```

---

# Remove XML Tags

Use `sed`:

```bash
grep "<title>" feed.xml |
sed 's/<[^>]*>//g'
```

Output:

```text
Ubuntu Released
Fedora Updated
Docker News
```

---

# Extract Links

Example:

```xml
<link>https://example.com/news1</link>

<link>https://example.com/news2</link>
```

Command:

```bash
grep "<link>" feed.xml |
sed 's/<[^>]*>//g'
```

Output:

```text
https://example.com/news1
https://example.com/news2
```

---

# Count Articles

```bash
grep -c "<item>" feed.xml
```

Output:

```text
12
```

Meaning there are 12 articles in the feed.

---

# Combine `curl`, `grep`, and `sed`

```bash
curl -s https://example.com/feed.xml |
grep "<title>" |
sed 's/<[^>]*>//g'
```

Output:

```text
Linux News
Ubuntu Released
Fedora Updated
Docker News
```

---

# Skip the Channel Title

Most RSS feeds include a channel title before the article titles.

Example output:

```text
Linux News
Ubuntu Released
Fedora Updated
Docker News
```

Remove the first line:

```bash
curl -s https://example.com/feed.xml |
grep "<title>" |
sed 's/<[^>]*>//g' |
tail -n +2
```

Output:

```text
Ubuntu Released
Fedora Updated
Docker News
```

---

# Extract Publication Dates

Example:

```xml

```

Command:

```bash
grep "<pubDate>" feed.xml |
sed 's/<[^>]*>//g'
```

# Creating a Simple Feed Reader

```bash
#!/bin/bash

curl -s https://example.com/feed.xml \
| grep "<title>" \
| sed 's/<[^>]*>//g' \
| tail -n +2
```

Example output:

```text
Ubuntu Released
Fedora Updated
Docker News
```

---

# Save Feed Updates

```bash
curl -s https://example.com/feed.xml \
| grep "<title>" \
| sed 's/<[^>]*>//g' \
> news.txt
```

View:

```bash
cat news.txt
```

---

# Pretty Formatting

```bash
curl -s https://example.com/feed.xml \
| grep "<title>" \
| sed 's/<[^>]*>//g' \
| tail -n +2 \
| awk '{print "-",$0}'
```

Output:

```text
- Ubuntu Released
- Fedora Updated
- Docker News
```

# Why RSS is Useful

RSS is still valuable because:

- No advertisements.
    
- Easy to automate.
    
- Lightweight.
    
- Machine-readable.
    
- Great for terminal tools.
    
- Supported by many blogs, podcasts, and open-source projects.
    

---

# XML Parsing Limitations

Using `grep` and `sed` works well for **simple XML**, but can fail when:

- Tags span multiple lines.
    
- XML contains namespaces.
    
- Elements are nested deeply.
    
- Special characters are encoded.
    

Example:

```xml
<title>

Ubuntu Released

</title>
```

A simple `grep "<title>"` won't capture the title text on the next line.

For complex XML, dedicated parsers are recommended.

---

# Useful XML Tools

For production work, Linux provides specialized XML tools.

|Tool|Purpose|
|---|---|
|`xmllint`|Validate and format XML|
|`xmlstarlet`|Query and edit XML|
|`yq`|YAML/XML processing|
|`xq`|Convert XML to JSON|

Example:

```bash
xmllint --format feed.xml
```

This formats XML with proper indentation.

# Real-World Example

Suppose you want the latest releases from an open-source project that provides an RSS feed.

Every hour:

```text
RSS Feed
     ↓
curl
     ↓
Latest Titles
     ↓
Save to File
     ↓
Compare with Previous Run
     ↓
Notify if New Release Exists
```

This is a common pattern for monitoring software updates and news.

---

# Best Practices

- Use official RSS feeds whenever possible.
    
- Cache results instead of downloading too frequently.
    
- Prefer dedicated XML parsers for complex XML.
    
- Validate XML if your automation depends on it.
    
- Combine `curl`, `grep`, `sed`, and `awk` for lightweight scripts.
    

---

# Key Takeaways

- XML is a structured data format.
    
- RSS is an XML-based format for publishing updates.
    
- `curl` can download XML just like HTML.
    
- `grep` and `sed` are useful for extracting simple XML data.
    
- RSS feeds are excellent for automation and monitoring.
    
- Use dedicated XML tools for more complex parsing tasks.

## 💡 Backend Engineer Tip

For modern backend APIs, **JSON has largely replaced XML**, so you'll often use **`jq`** instead of `grep`/`sed` for parsing API responses. However, XML and RSS are still common in:

- News websites
    
- Podcasts
    
- Legacy enterprise systems
    
- Sitemaps (`sitemap.xml`)
    
- SOAP web services
    
- Some CI/CD and monitoring tools
    

Knowing both JSON and XML parsing makes you much more versatile as a backend engineer.
