# What is Automation?

Automation means making the computer perform repetitive tasks automatically.

Instead of doing this manually every day:

```text
Open browser
     ↓
Visit website
     ↓
Check status
     ↓
Download file
     ↓
Save it
```

You can simply run:

```bash
./monitor.sh
```

or even schedule it with `cron` (coming in the next lesson).

# Functions

Instead of repeating code:

```bash
check_site() {
    curl -s -o /dev/null \
    -w "%{http_code}\n" \
    "$1"
}

check_site https://example.com
```

Functions improve readability and reuse.

---

# Returning Values

Example:

```bash
get_status() {

    curl -s \
    -o /dev/null \
    -w "%{http_code}" \
    "$1"

}
```

Store the output:

```bash
STATUS=$(get_status https://example.com)

echo "$STATUS"
```

---

# While Loop

```bash
COUNT=1

while [ "$COUNT" -le 5 ]
do
    echo "$COUNT"

    COUNT=$((COUNT+1))
done
```

```text

2
3
4
5
```

# Exit Status

Every Linux command returns an exit code.

Check it:

```bash
curl https://example.com

echo $?
```

Typical values:

|Exit Code|Meaning|
|---|---|
|0|Success|
|Non-zero|Error|

---

# Error Handling

Instead of:

```bash
curl "$URL"
```

Use:

```bash
if curl --fail -s "$URL" >/dev/null
then
    echo "Success"
else
    echo "Failed"
fi
```

---

# Check Required Commands

Before using `curl`:

```bash
command -v curl >/dev/null 2>&1
```

Complete example:

```bash
if ! command -v curl >/dev/null 2>&1
then
    echo "curl not installed"

    exit 1
fi
```

This prevents confusing errors later.

# Reusable Monitor

```bash
#!/bin/bash

check() {

    STATUS=$(curl -s \
    -o /dev/null \
    -w "%{http_code}" \
    "$1")

    echo "$1 -> $STATUS"

}

```

# Complete Example

```bash
#!/bin/bash

URL="https://example.com"

LOGFILE="monitor.log"

STATUS=$(curl -s \
-o /dev/null \
-w "%{http_code}" \
"$URL")

echo "$(date): $STATUS" >> "$LOGFILE"

echo "Done."
```

# Common Mistakes

❌ Hardcoding values everywhere.

Instead of:

```bash
curl https://example.com
```

Prefer:

```bash
URL="https://example.com"

curl "$URL"
```

---

❌ Forgetting to quote variables.

Incorrect:

```bash
curl $URL
```

Correct:

```bash
curl "$URL"
```

Quoting prevents problems with spaces and special characters.

---

❌ Ignoring exit codes.

Always check whether important commands succeed before continuing.

---

❌ Writing one huge script.

Break logic into functions to improve readability and maintenance.

- Group configuration at the top.
    
- Write reusable functions.
    
- Quote variables (`"$VAR"`).
    
- Log important events.
    
- Keep scripts modular.
    
- Check exit codes for critical commands.

# 💡 Backend Engineer Tip

As a backend engineer, your Bash scripts should follow the **Unix philosophy**:

- **One script, one responsibility.**
    
- Keep configuration separate from logic.
    
- Prefer small reusable functions.
    
- Exit with meaningful status codes (`0` for success, non-zero for errors).
    
- Write logs that are easy to read and debug.
    

For example, instead of one large 500-line script, organize your project like this:

```text
website-monitor/
├── monitor.sh      # Main script
├── config.sh       # Configuration
├── sites.txt       # Websites to monitor
├── logs/
│   └── monitor.log
└── README.md
```

This structure scales much better as your automation projects become more complex and is similar to how production automation tools are organized.
