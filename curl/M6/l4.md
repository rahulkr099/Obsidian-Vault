# What is Basic Authentication?

Basic Authentication is an HTTP authentication scheme where the client sends:

- Username
    
- Password
    

with every request.

Workflow:

```text
Client
   │
Username + Password
   │
Authorization Header
   │
────────────►
Server
   │
Validate Credentials
   │
200 OK
```

---

# The Authorization Header

The header looks like:

```http
Authorization: Basic dXNlcjpwYXNzd29yZA==
```

Notice:

```text
Basic
```

indicates the authentication scheme.

The remaining value is the Base64-encoded form of:

```text
username:password
```

---

# Base64 Encoding

Suppose:

```text
Username: rahul

Password: secret123
```

Combine them:

```text
rahul:secret123
```

Encode with Base64:

```text
cmFodWw6c2VjcmV0MTIz
```

Final header:

```http
Authorization: Basic cmFodWw6c2VjcmV0MTIz
```

---

# Important Security Note

**Base64 is NOT encryption.**

It is simply an encoding format.

Anyone can decode it:

```bash
echo "cmFodWw6c2VjcmV0MTIz" | base64 --decode
```

Output:

```text
rahul:secret123
```

Therefore:

- ❌ Basic Auth over HTTP is unsafe.
    
- ✅ Basic Auth over HTTPS is acceptable because TLS encrypts the entire HTTP request.
    

---

# Using `curl -u`

The easiest method:

```bash
curl -u rahul:secret123 https://example.com/api
```

`curl` automatically:

- Combines username and password.
    
- Base64 encodes them.
    
- Adds the correct `Authorization` header.
    

---

# Equivalent Manual Header

Instead of `-u`:

```bash
curl \
-H "Authorization: Basic cmFodWw6c2VjcmV0MTIz" \
https://example.com/api
```

Both requests are equivalent.

---

# Encoding Credentials Yourself

Generate the Base64 value:

```bash
echo -n "rahul:secret123" | base64
```

Output:

```text
cmFodWw6c2VjcmV0MTIz
```

Use it:

```bash
curl \
-H "Authorization: Basic cmFodWw6c2VjcmV0MTIz" \
https://example.com/api
```

---

# Prompt for Password

Avoid typing passwords directly into your shell history.

Instead:

```bash
curl -u rahul https://example.com/api
```

`curl` prompts:

```text
Enter host password for user 'rahul':
```

This is safer than placing the password on the command line.

---

# GET Request Example

```bash
curl \
-u rahul:secret123 \
https://example.com/users
```

---

# POST Request Example

```bash
curl \
-u rahul:secret123 \
-X POST \
-H "Content-Type: application/json" \
-d '{"name":"Alice"}' \
https://example.com/users
```

---

# Using Variables

Instead of hardcoding:

```bash
USERNAME="rahul"

PASSWORD="secret123"

curl \
-u "$USERNAME:$PASSWORD" \
https://example.com/api
```

---

# Using Environment Variables

Even better:

```bash
export API_USERNAME="rahul"

export API_PASSWORD="secret123"
```

Use:

```bash
curl \
-u "$API_USERNAME:$API_PASSWORD" \
https://example.com/api
```

This avoids embedding credentials in your scripts.

---

# Successful Authentication

Server response:

```http
HTTP/1.1 200 OK
```

Body:

```json
{
  "message": "Welcome"
}
```

---

# Wrong Password

Response:

```http
HTTP/1.1 401 Unauthorized
```

Meaning:

Authentication failed.

---

# Authentication vs Authorization

These are different concepts.

|Authentication|Authorization|
|---|---|
|Who are you?|What are you allowed to do?|

Example:

```text
Username: rahul

Password: correct
```

Authentication:

✅ Success

Now the server checks permissions.

Can Rahul delete users?

Maybe:

```http
403 Forbidden
```

because Rahul lacks permission.

---

# HTTP Status Codes

|Code|Meaning|
|---|---|
|200|Login successful|
|401|Invalid or missing credentials|
|403|Authenticated, but not permitted|

---

# Viewing Headers

Verbose mode:

```bash
curl \
-v \
-u rahul:secret123 \
https://example.com/api
```

You'll see:

- TLS handshake
    
- Request headers
    
- Response headers
    

For security, `curl` avoids printing sensitive credentials directly.

# Common Mistakes

❌ **Using Basic Auth over HTTP.**

Always use HTTPS so credentials are protected in transit.

---

❌ **Thinking Base64 is encryption.**

Base64 is reversible encoding, not a security mechanism.

---

❌ **Hardcoding credentials in scripts.**

Prefer:

- Environment variables
    
- Secret managers
    
- Prompting for passwords
    

---

❌ **Confusing 401 and 403.**

- **401 Unauthorized** → Authentication failed or missing.
    
- **403 Forbidden** → Authentication succeeded, but access is denied.
    

---

# Best Practices

- Always combine Basic Auth with HTTPS.
    
- Use `curl -u` instead of manually building headers when possible.
    
- Store credentials securely.
    
- Avoid exposing passwords in shell history.
    
- Use least-privilege accounts for automation.

# Real-World Backend Example

Suppose an internal admin API requires Basic Authentication.

Request:

```bash
curl \
-u admin:password123 \
https://internal.example.com/api/users
```

`curl` automatically sends:

```http
Authorization: Basic YWRtaW46cGFzc3dvcmQxMjM=
```

The server:

1. Decodes the credentials.
    
2. Verifies the username and password.
    
3. Returns:
    

```http
HTTP/1.1 200 OK
```

or

```http
HTTP/1.1 401 Unauthorized
```

if the credentials are invalid.

---

# Key Takeaways

- Basic Authentication sends `username:password` encoded with Base64.
    
- Base64 is **encoding**, not encryption.
    
- Always use Basic Auth over HTTPS.
    
- `curl -u` automatically creates the correct `Authorization` header.
    
- `401` indicates authentication failure, while `403` indicates insufficient permissions.

# 💡 Backend Engineer Tip

While Basic Authentication is still common for internal tools and legacy systems, **Bearer tokens (especially JWTs)** are the standard for modern web applications and REST APIs. Understanding Basic Auth first makes it much easier to appreciate why newer authentication methods were developed and how they improve security and flexibility.
