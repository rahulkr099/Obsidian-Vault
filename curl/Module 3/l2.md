# 1. What Are HTTP Headers?

HTTP headers are **metadata** sent along with an HTTP request or response.

Think of them as the label on a package.

```text
Package
│
├── To: Server
├── From: Client
├── Type: JSON
├── Authorization: Bearer xxx
└── Body
```

The headers describe the request. The body contains the actual data.

---

# 2. Request vs Response Headers

## Request Headers

Client → Server

Example:

```http
GET /users HTTP/1.1
Host: api.example.com
User-Agent: curl/8.5.0
Accept: application/json
Authorization: Bearer TOKEN
```

---

## Response Headers

Server → Client

Example:

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 245
Cache-Control: no-cache
```

---

# 3. Viewing Headers

Show request and response details:

```bash
curl -v https://httpbin.org/get
```

Request headers begin with:

```text
>
```

Response headers begin with:

```text
<
```

---

Only response headers:

```bash
curl -I https://httpbin.org/get
```

---

Headers + body:

```bash
curl -i https://httpbin.org/get
```

# 4. Sending Custom Headers

Use:

```bash
-H "Header-Name: value"
```

Example:

```bash
curl \
-H "X-App-Version: 1.0" \
https://httpbin.org/headers
```

Output:

```json
{
  "headers": {
    "X-App-Version": "1.0"
  }
}
```

---

# 5. Multiple Headers

```bash
curl \
-H "X-App-Version: 1.0" \
-H "X-Client: Rahul" \
-H "X-Environment: Development" \
https://httpbin.org/headers
```

You can use as many `-H` options as needed.

---

# 6. Host Header

Every HTTP request includes:

```http
Host: example.com
```

Example:

```bash
curl \
-H "Host: example.com" \
http://93.184.216.34
```

This is mainly useful for testing virtual hosts or reverse proxies.

Normally, **curl sets this automatically**.

---

# 7. User-Agent

Every client identifies itself.

Example:

```http
User-Agent: curl/8.5.0
```

Pretend to be Firefox:

```bash
curl \
-H "User-Agent: Mozilla/5.0" \
https://httpbin.org/user-agent
```

Response:

```json
{
  "user-agent": "Mozilla/5.0"
}
```

---

# 8. Accept Header

Tells the server what formats you prefer.

```http
Accept: application/json
```

Example:

```bash
curl \
-H "Accept: application/json" \
https://httpbin.org/get
```

Other examples:

```text
Accept: text/html
Accept: image/png
Accept: */*
```

`*/*` means:

> "I'll accept any content type."

---

# 9. Content-Type

Very common.

```http
Content-Type: application/json
```

Indicates what format the **request body** uses.

Example:

```bash
curl \
-H "Content-Type: application/json" \
-d '{"name":"Rahul"}' \
https://httpbin.org/post
```

---

# 10. Accept vs Content-Type

Many beginners confuse these.

|Header|Meaning|
|---|---|
|Content-Type|What I'm sending|
|Accept|What I'd like to receive|

Example:

```http
Content-Type: application/json
Accept: application/json
```

One describes the request body.

The other describes the preferred response format.

---

# 11. Authorization Header

JWT APIs use:

```http
Authorization: Bearer eyJ...
```

Example:

```bash
curl \
-H "Authorization: Bearer $TOKEN" \
http://localhost:3000/profile
```

Without this header:

```text
401 Unauthorized
```

---

# 12. Accept-Language

Browsers send:

```http
Accept-Language: en-US
```

Example:

```bash
curl \
-H "Accept-Language: en-US" \
https://httpbin.org/headers
```

Possible values:

```text
en-US
en-GB
hi-IN
fr-FR
ja-JP
```

Servers may localize responses based on this.

---

# 13. Accept-Encoding

Allows compressed responses.

```http
Accept-Encoding: gzip
```

Example:

```bash
curl \
-H "Accept-Encoding: gzip" \
https://httpbin.org/gzip
```

Even easier:

```bash
curl --compressed https://httpbin.org/gzip
```

`curl` advertises supported compression formats and automatically decompresses the response.

---

# 14. Referer Header

Tells the server which page the request came from.

```http
Referer: https://example.com/dashboard
```

Example:

```bash
curl \
-H "Referer: https://google.com" \
https://httpbin.org/headers
```

Some websites use this for analytics or basic access checks.

---

# 15. Origin Header

Common in browser-based APIs and CORS.

```http
Origin: https://example.com
```

Example:

```bash
curl \
-H "Origin: https://myapp.com" \
https://httpbin.org/headers
```

Express applications often inspect this during CORS validation.

---

# 16. X-* Custom Headers

Applications frequently define their own headers.

Examples:

```http
X-Request-ID
X-Trace-ID
X-API-Version
X-Client-ID
```

Example:

```bash
curl \
-H "X-Trace-ID: abc123" \
https://httpbin.org/headers
```

These help with debugging, tracing, or application-specific behavior.

---

# 17. Reading Response Headers

```bash
curl -I https://httpbin.org/get
```

Example:

```http
HTTP/1.1 200 OK

Content-Type: application/json

Content-Length: 305

Server: gunicorn

Date: Mon, 28 Jul 2026 09:10:00 GMT
```

Important response headers:

|Header|Purpose|
|---|---|
|Content-Type|Response format|
|Content-Length|Response size|
|Date|Server time|
|Server|Server software|
|Cache-Control|Caching policy|
|Set-Cookie|Creates cookies|
|Location|Redirect destination|

---

# 18. Header Debugging

If an API fails:

Check:

```bash
curl -v ...
```

Verify:

✅ Authorization

✅ Content-Type

✅ Accept

✅ Cookies

✅ Origin

Small mistakes often cause authentication or parsing failures.

---

# 19. Common Mistakes

## ❌ Misspelled Header

Wrong:

```http
Authorisation
```

Correct:

```http
Authorization
```

---

## ❌ Wrong Content-Type

```http
Content-Type: text/plain
```

instead of:

```http
Content-Type: application/json
```

---

## ❌ Missing Bearer

Wrong:

```http
Authorization: eyJ...
```

Correct:

```http
Authorization: Bearer eyJ...
```

---

## ❌ Extra Spaces

Wrong:

```http
Authorization : Bearer TOKEN
```

Header formatting should be:

```http
Authorization: Bearer TOKEN
```

# 20. Real Backend Example

Typical request:

```bash
curl \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/json" \
-H "Accept: application/json" \
-H "X-Request-ID: test-123" \

```

This resembles production API requests.

# 💡 Pro Tips

### 1. Let `curl` set headers when possible

For example, when you use:

```bash
curl \
-H "Content-Type: application/json" \
-d @payload.json
```

`curl` automatically sets related headers like `Content-Length`. There's usually no need to set them manually.

---

### 2. Save headers separately

Capture response headers without mixing them into the body:

```bash
curl \
-D response-headers.txt \
-o response.json \
https://httpbin.org/get
```

Now you can inspect:

```bash
cat response-headers.txt
```

and:

```bash
jq . response.json
```

independently.

---

### 3. Use unique request IDs

When testing your own APIs, sending an `X-Request-ID` header can make it much easier to correlate a client request with server logs.
