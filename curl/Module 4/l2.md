# 1. The Problem

Imagine you're downloading a **5 GB** Linux ISO.

```text
Download Started

↓

4.8 GB Downloaded

↓

Internet Lost ❌

↓

Download Stops
```

Without resume support:

```text
Delete File

↓

Start Again

↓

Download Another 5 GB 😢
```

That's slow and wastes bandwidth.

---

# 2. The Solution

Resume from where you left off.

```text
Downloaded

4.8 GB

↓

Reconnect

↓

Continue

↓

5 GB Complete ✅
```

This is what `curl -C -` does.

---

# 3. Resume a Download

If the partially downloaded file already exists:

```bash
curl -C - -O https://example.com/archive.zip
```

Meaning:

- `-C` = Continue at an offset
    
- `-` = Automatically detect the correct offset
    

`curl` checks the size of the local file and requests only the missing bytes.

---

# 4. Example Workflow

Start download:

```bash
curl -O https://example.com/video.mp4
```

Interrupt it with:

```text
Ctrl + C
```

Later:

```bash
curl -C - -O https://example.com/video.mp4
```

The download resumes instead of restarting.

---

# 5. How HTTP Resume Works

The client sends:

```http
GET /video.mp4

Range: bytes=104857600-
```

Meaning:

> "Start sending from byte **104857600**."

The server replies:

```http
HTTP/1.1 206 Partial Content
```

instead of:

```http
HTTP/1.1 200 OK
```

---

# 6. Understanding HTTP Status Codes

|Status|Meaning|
|---|---|
|**200 OK**|Entire file sent|
|**206 Partial Content**|Partial file sent|
|**416 Range Not Satisfiable**|Invalid range requested|

---

# 7. Check Whether Resume Is Supported

Inspect headers:

```bash
curl -I https://example.com/file.iso
```

Look for:

```http
Accept-Ranges: bytes
```

If present:

✅ Resume is supported.

---

If you see:

```http
Accept-Ranges: none
```

or no `Accept-Ranges` header at all, the server may not support byte-range requests.

---

# 8. What Happens Internally?

Suppose your file size is:

```text
1 GB
```

Already downloaded:

```text
600 MB
```

`curl` automatically sends:

```http
Range: bytes=629145600-
```

The server sends only:

```text
Remaining

424 MB
```

---

# 9. Manual Resume

Instead of automatic detection:

```bash
curl \
-C 500000 \
-O \
https://example.com/file.zip
```

Meaning:

Resume starting at byte:

```text
500000
```

Usually, `-C -` is the better choice.

---

# 10. Download a Specific Byte Range

You can request only part of a file.

Example:

```bash
curl \
-r 0-999 \
https://example.com/file.txt
```

Downloads only:

```text
First 1000 Bytes
```

---

Download another section:

```bash
curl \
-r 1000-1999 \
https://example.com/file.txt
```

---

# 11. Why Range Requests Are Useful

Range requests are used for:

- Video streaming
    
- Audio streaming
    
- PDF viewers
    
- Download managers
    
- Resume downloads
    
- Large cloud storage systems
    

---

# 12. Resume Large ISO Downloads

Example:

```bash
curl \
-C - \
-L \
-O \
https://releases.ubuntu.com/24.04/ubuntu-24.04-desktop-amd64.iso
```

This is a common real-world use case.

---

# 13. Resume GitHub Releases

```bash
curl \
-C - \
-L \
-O \
https://github.com/sharkdp/bat/releases/latest/download/bat-musl-amd64.tar.gz
```

If the download is interrupted, rerun the same command.

---

# 14. Combine With Timeouts

```bash
curl \
-C - \
--connect-timeout 5 \
--max-time 600 \
-O \
URL
```

Now:

- Resume works
    
- Network hangs are limited
    

---

# 15. Retry + Resume

Excellent production combination:

```bash
curl \
-C - \
--retry 5 \
--retry-delay 2 \
--retry-all-errors \
-O \
URL
```

This handles both interruptions and temporary failures.

---

# 16. Progress During Resume

```bash
curl \
-C - \
--progress-bar \
-O \
URL
```

The progress bar reflects only the remaining transfer.

---

# 17. Verify the Final File

Check size:

```bash
ls -lh archive.zip
```

Check type:

```bash
file archive.zip
```

In the next lessons, you'll verify integrity with cryptographic checksums.

---

# 18. Detect Resume Failure

Some servers ignore the `Range` header.

Instead of:

```http
206 Partial Content
```

They return:

```http
200 OK
```

This usually means the entire file is being downloaded again.

Use verbose mode:

```bash
curl \
-v \
-C - \
-O \
URL
```

Watch for:

- `Range:` request header
    
- `206 Partial Content` response
    

---

# 19. Resume Into a Custom Filename

```bash
curl \
-C - \
-o backup.tar.gz \
URL
```

Works just like `-O`.

---

# 20. Production Download Command

```bash
curl \
--fail \
--location \
--continue-at - \
--retry 5 \
--retry-all-errors \
--connect-timeout 5 \
--max-time 3600 \
--progress-bar \
--output backup.tar.gz \
URL
```

Equivalent long options:

- `--continue-at -` = `-C -`
    
- `--location` = `-L`
    
- `--output` = `-o`

# 💡 Pro Tips

### 1. Use `-C -` for large downloads

For files larger than a few hundred megabytes, resuming downloads can save significant time and bandwidth.

```bash
curl -C - -LO URL
```

---

### 2. Verify server support

Before relying on resume:

```bash
curl -I URL
```

Look for:

```http
Accept-Ranges: bytes
```

---

### 3. Production-ready download command

A reliable pattern for large downloads:

```bash
curl \
--fail \
-L \
-C - \
--retry 5 \
--retry-all-errors \
--connect-timeout 5 \
--max-time 3600 \
--progress-bar \
-O URL
```

This combines redirect handling, resume support, retries, timeouts, and clear progress reporting.
