# 1. Why Verification Matters

Suppose you download:

```text
ubuntu.iso
```

The download appears successful.

But:

- Internet disconnected briefly
    
- Disk error occurred
    
- Proxy corrupted the file
    
- Someone tampered with the file
    

Without verification:

```text
Download

↓

Looks Fine

↓

Actually Corrupted ❌
```

---

# 2. What is a Checksum?

A checksum (hash) is a unique fingerprint of a file.

Example:

```text
hello.txt

↓

SHA-256

↓

7f83b1657ff1fc53...
```

If **one byte changes**, the checksum changes dramatically.

---

# 3. Hash Algorithms

|Algorithm|Secure?|Typical Use|
|---|---|---|
|MD5|❌ No|Legacy compatibility|
|SHA-1|❌ No|Legacy systems|
|SHA-256|✅ Yes|Software downloads|
|SHA-512|✅ Yes|High-security verification|

Today, **SHA-256** is the most commonly used for download verification.

---

# 4. Generate a SHA-256 Hash

Create a sample file:

```bash
echo "Hello Curl" > hello.txt
```

Generate its checksum:

```bash
sha256sum hello.txt
```

Example:

```text
34c8f...ab91 hello.txt
```

---

# 5. Tiny Change, Huge Difference

Original:

```text
Hello Curl
```

Modified:

```text
Hello curl
```

Only one letter changed.

New checksum:

```text
e91ac...7732
```

Completely different.

This property makes hashes excellent for integrity checks.

---

# 6. Verify a Download

Publisher provides:

```text
ubuntu.iso

ubuntu.iso.sha256
```

Download both:

```bash
curl -LO https://example.com/ubuntu.iso

curl -LO https://example.com/ubuntu.iso.sha256
```

Verify:

```bash
sha256sum -c ubuntu.iso.sha256
```

Output:

```text
ubuntu.iso: OK
```

---

# 7. What Does the Checksum File Look Like?

Example:

```text
3f786850e387550fdab836ed7e6dc881de23001b ubuntu.iso
```

Format:

```text
<Hash><spaces><Filename>
```

`sha256sum -c` reads this format automatically.

---

# 8. Failed Verification

Suppose the file changed.

Output:

```text
ubuntu.iso: FAILED

WARNING: 1 computed checksum did NOT match
```

Do **not** use the file.

Delete it and download again.

# 10. SHA-512

Generate:

```bash
sha512sum backup.tar.gz
```

Verification:

```bash
sha512sum -c backup.sha512
```

---

# 11. MD5 (Legacy)

Generate:

```bash
md5sum archive.zip
```

Verification:

```bash
md5sum -c archive.md5
```

Still found on some older systems, but avoid MD5 for security-sensitive verification.

---

# 12. Verify Linux ISOs

Example workflow:

```bash
curl -LO https://releases.ubuntu.com/24.04/ubuntu.iso

curl -LO https://releases.ubuntu.com/24.04/SHA256SUMS
```

Verify:

```bash
grep ubuntu.iso SHA256SUMS | sha256sum -c
```

Output:

```text
ubuntu.iso: OK
```

---

# 13. Verify Multiple Files

Checksum file:

```text

ghi789 file3.zip
```

Run:

```bash
sha256sum -c SHA256SUMS
```

Output:

```text
file1.zip: OK

file2.zip: OK

file3.zip: OK
```

# 14. Create Your Own Checksum File

Generate:

```bash
sha256sum backup.tar.gz > backup.sha256
```

Contents:

```text
8c5f.... backup.tar.gz
```

Verify later:

```bash
sha256sum -c backup.sha256
```

---

# 15. Verify Before Installing

Never do:

```text
Download

↓

Install Immediately
```

Instead:

```text
Download

↓

Verify Hash

↓

Install
```

This is standard practice for production servers.

---

# 16. Automate Verification

Example Bash script:

```bash
FILE=backup.tar.gz

CHECKSUM=backup.sha256

if sha256sum -c "$CHECKSUM"
then
    echo "Verified"
else
    echo "Corrupted"
fi
```

# 17. Detect Incomplete Downloads

Suppose:

```text
Expected

2 GB
```

Downloaded:

```text
1.3 GB
```

Verification:

```text
FAILED
```

Checksums catch incomplete downloads automatically.

---

# 18. Common Mistakes

### Comparing the Wrong File

Wrong:

```bash
sha256sum image.png
```

Compare against:

```text
video.mp4 checksum
```

Always compare the checksum for the correct file.

---

### Wrong Algorithm

Publisher gives:

```text
SHA-512
```

Don't verify with:

```bash
md5sum
```

Use the same algorithm the publisher provides.

---

### Editing the File

If you modify the file after downloading:

```text
Checksum

↓

Changes
```

The original checksum will no longer match.

# 20. Complete Download Script

```bash
curl \
--fail \
-L \
-C - \
-O \
URL

curl \
--fail \
-L \
-O \
URL.sha256

sha256sum -c file.sha256
```

A reliable workflow for many downloadable artifacts.

---

# 21. Beyond Checksums: Digital Signatures

A checksum proves:

- The file matches the published hash.
    

It **does not** prove:

- Who published the file.
    

For stronger authenticity guarantees, many projects also publish:

- GPG/PGP signatures
    
- Code signing certificates
    

Typical workflow:

```text
Download

↓

Verify Checksum

↓

Verify Digital Signature

↓

Install
```

# 💡 Pro Tips

### 1. Prefer SHA-256

Unless the publisher specifies otherwise, SHA-256 is the standard choice for verifying downloads.

```bash
sha256sum file.iso
```

---

### 2. Verify before using

For installers, backups, container images, or production artifacts:

```text
Download

↓

Verify

↓

Use
```

Skipping verification can leave you using a corrupted or tampered file.

---

### 3. Check the source of the checksum

A matching checksum only proves the file matches the checksum you downloaded. If an attacker can replace **both** the file and the checksum, verification won't help.

For important software:

- Download from the publisher's official site.
    
- Verify digital signatures (GPG/PGP or code signing) when available.
