# 1. Why Backups Matter

Servers fail.

Disks fail.

People make mistakes.

Applications have bugs.

Without backups:

```text
Database Deleted

↓

Data Lost

↓

Business Stops ❌
```

With backups:

```text
Database Deleted

↓

Restore Backup

↓

Business Continues ✅
```

---

# 2. What Should Be Backed Up?

Typical production backups include:

- Databases
    
- Uploaded files
    
- Configuration files
    
- SSL certificates
    
- Environment files
    
- Application logs (if required)
    
- Static assets
    

Avoid backing up:

- Temporary files
    
- Cache directories
    
- `node_modules`
    
- Build artifacts (if reproducible)

# 4. Database Backup (PostgreSQL)

```bash
pg_dump mydb > backup.sql
```

Compress:

```bash
gzip backup.sql
```

Result:

```text
backup.sql.gz
```

---

# 5. Database Backup (MySQL)

```bash
mysqldump -u root -p mydb > backup.sql
```

Compress:

```bash
gzip backup.sql
```

# 6. Backup a Directory

Example:

```bash
tar -czf website.tar.gz /var/www/html
```

Contents:

```text
HTML

CSS

JS

Images

Uploads
```

---

# 7. Generate a Checksum

```bash
sha256sum website.tar.gz > website.tar.gz.sha256
```

Now you have:

```text
website.tar.gz

website.tar.gz.sha256
```

---

# 8. Upload the Backup

Using a Bearer token:

```bash
curl \
--fail \
-T website.tar.gz \
-H "Authorization: Bearer $TOKEN" \
https://backup.example.com/backups/website.tar.gz
```

Upload the checksum too:

```bash
curl \
--fail \
-T website.tar.gz.sha256 \
-H "Authorization: Bearer $TOKEN" \
https://backup.example.com/backups/website.tar.gz.sha256
```

---

# 9. Streaming Backup

Avoid temporary files:

```bash
tar -cz /var/www/html \
| curl \
-T - \
-H "Authorization: Bearer $TOKEN" \
https://backup.example.com/backups/website.tar.gz
```

Pipeline:

```text
Files

↓

Compress

↓

Upload
```

---

# 10. Download Backup

```bash
curl \
--fail \
-L \
-C - \
-O \
https://backup.example.com/backups/website.tar.gz
```

Resume support ensures interrupted downloads continue.

---

# 11. Verify Download

```bash
curl -O https://backup.example.com/backups/website.tar.gz.sha256
```

Verify:

```bash
sha256sum -c website.tar.gz.sha256
```

Expected:

```text
website.tar.gz: OK
```

---

# 12. Restore Files

Extract:

```bash
tar -xzf website.tar.gz
```

Or to a specific location:

```bash
tar -xzf website.tar.gz -C /var/www/html
```

# 21. Backup Script Example

```bash
#!/usr/bin/env bash

set -euo pipefail

DATE=$(date +%F)

BACKUP="backup-$DATE.tar.gz"

tar -czf "$BACKUP" project/

sha256sum "$BACKUP" > "$BACKUP.sha256"

curl --fail \
-T "$BACKUP" \
-H "Authorization: Bearer $TOKEN" \
https://backup.example.com/backups/

curl --fail \
-T "$BACKUP.sha256" \
-H "Authorization: Bearer $TOKEN" \
https://backup.example.com/backups/

echo "Backup completed successfully."
```

---

# 22. Restore Script Example

```bash
#!/usr/bin/env bash

set -euo pipefail

curl \
--fail \
-L \
-C - \
-O https://backup.example.com/backups/latest.tar.gz

curl \
--fail \
-O https://backup.example.com/backups/latest.tar.gz.sha256

sha256sum -c latest.tar.gz.sha256

tar -xzf latest.tar.gz
```

# 24. Common Backup Mistakes

### ❌ Never Testing Restores

A backup is only useful if it can be restored.

---

### ❌ Skipping Verification

Always verify:

```bash
sha256sum -c backup.sha256
```

---

### ❌ Keeping One Backup

Maintain multiple recovery points.

Example:

```text
Daily

Weekly

Monthly
```

---

### ❌ Storing Backup and Original Together

If both are on the same failed disk:

```text
Original ❌

Backup ❌
```

Store backups on separate storage.

# 💡 Pro Tips

### 1. Test restores regularly

A backup you have never restored is an **unverified backup**. Schedule periodic restore tests in a non-production environment.

---

### 2. Follow the 3-2-1 backup rule

A widely used best practice:

- **3** copies of your data
    
- **2** different storage media
    
- **1** copy stored off-site
    

---

### 3. Automate, monitor, and alert

A backup that silently fails is often discovered only when it's needed.

Include:

- Logging
    
- Exit codes
    
- Retry logic
    
- Monitoring
    
- Notifications (email, Slack, etc.)
