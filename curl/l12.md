# Step 7 — Check One Website

```bash
check_site() {

    local url="$1"

    local status
    local time

    status=$(curl \
        --max-time "$TIMEOUT" \
        -s \
        -o /dev/null \
        -w "%{http_code}" \
        "$url")

    time=$(curl \
        --max-time "$TIMEOUT" \
        -s \
        -o /dev/null \
        -w "%{time_total}" \
        "$url")

    echo "$status|$time"

}
```

# Step 8 — Read Websites

```bash
while read -r SITE
do

    echo "$SITE"

```

---

# Step 9 — Process Each Website

```bash
while read -r SITE
do

    RESULT=$(check_site "$SITE")

    STATUS=$(echo "$RESULT" | cut -d'|' -f1)

    TIME=$(echo "$RESULT" | cut -d'|' -f2)

    echo "$SITE"

    echo "$STATUS"

    echo "$TIME"

done < sites.txt
```

# Common Mistakes

❌ Making two separate `curl` requests for each website.

Earlier, we used one request for the status code and another for response time. That works, but it's inefficient.

A better approach is to collect both metrics in **one** request:

```bash
curl -s -o /dev/null \
  -w "%{http_code}|%{time_total}" \
  "$url"
```

Then split the output once.

---

❌ Not setting a timeout.

Always include:

```bash
--max-time 10
```

to prevent the script from hanging indefinitely.

---

❌ Ignoring `curl` failures.

If DNS lookup fails or the connection times out, `curl` may not return a normal HTTP status. Check its exit status and log those failures clearly.

---

❌ Hardcoding websites.

Keep the monitored URLs in `sites.txt` so they can be updated without modifying the script.

# Best Practices

- Use **one `curl` request** to gather multiple metrics.
    
- Keep configuration in `config.sh`.
    
- Store websites in `sites.txt`.
    
- Write reusable functions.
    
- Log every execution.
    
- Generate reports for historical analysis.
    
- Test manually before scheduling with cron.

This project is intentionally written using only **Bash and `curl`** to strengthen your Linux automation skills.

In production, similar monitoring systems are often built with tools such as:

- **Prometheus** for metrics collection
    
- **Grafana** for dashboards and visualization
    
- **Uptime Kuma** for uptime monitoring
    
- **Nagios** or **Zabbix** for infrastructure monitoring
    

Learning the Bash implementation first helps you understand the underlying concepts before moving to these more advanced tools.
