# 1. What is a Redirect?

A redirect tells the client:

> **"The resource you're looking for has moved. Please request a different URL."**

Example:

```text
Client
   │
GET /login
   │
   ▼
Server
   │
302 Found
Location: /signin
   │
   ▼
Client requests /signin
```

---

# 2. Why Redirects Exist

Common reasons:

- Website moved
    
- HTTP → HTTPS
    
- Login required
    
- URL renamed
    
- Domain changed
    
- API version migration
    

Example:

```text
http://example.com

↓

https://example.com
```

---

# 3. Common Redirect Status Codes

|Status|Meaning|Method Preserved?|Typical Use|
|---|---|---|---|
|**301**|Moved Permanently|Usually changes POST to GET in older clients|Permanent move|
|**302**|Found (Temporary)|Often changes POST to GET|Temporary redirect|
|**303**|See Other|Always GET|Redirect after form submission|
|**307**|Temporary Redirect|✅ Yes|Temporary move|
|**308**|Permanent Redirect|✅ Yes|Permanent move|

---

# 4. Example Redirect

Server:

```http
HTTP/1.1 301 Moved Permanently

Location: https://example.com
```

Client then requests:

```http
GET https://example.com
```

---

# 5. Viewing Redirects

Without following them:

```bash
curl -I http://httpbin.org/redirect-to?url=https://example.com
```

Output:

```http
HTTP/1.1 302 Found

Location: https://example.com
```

Notice that `curl` **does not** follow redirects by default.

---

# 6. Follow Redirects

Use:

```bash
curl -L http://httpbin.org/redirect-to?url=https://example.com
```

Now `curl` automatically follows the `Location` header.

---

# 7. See Every Redirect

Use verbose mode:

```bash
curl -Lv http://httpbin.org/redirect/3
```

You'll see something like:

```text
GET /redirect/3

↓

302

↓

GET /redirect/2

↓

302

↓

GET /redirect/1

↓

302

↓

200 OK
```

This is very useful for debugging redirect chains.

---

# 8. Redirect Loops

Bad configuration:

```text
/page1

↓

/page2

↓

/page1

↓

/page2
```

This creates an infinite loop.

`curl` eventually stops with an error similar to:

```text
Maximum (50) redirects followed
```

---

# 9. Limit Redirects

Example:

```bash
curl \
-L \
--max-redirs 5 \
http://example.com
```

Now `curl` stops after 5 redirects.

---

# 10. Relative vs Absolute Redirects

## Relative

```http
Location: /login
```

Browser converts it to:

```text
https://example.com/login
```

---

## Absolute

```http
Location: https://example.com/login
```

Both are valid.

# 11. Query Parameters

Example URL:

```text
https://example.com/search?q=linux&page=2
```

Breakdown:

|Part|Value|
|---|---|
|Path|`/search`|
|Query|`q=linux&page=2`|

---

# 12. Multiple Query Parameters

```text
https://api.example.com/users?

page=2

&limit=10

&sort=name
```

Equivalent single-line URL:

```text
https://api.example.com/users?page=2&limit=10&sort=name
```

---

# 13. URL Encoding

Some characters cannot appear directly in URLs.

Example:

```text
Rahul Kumar
```

Encoded:

```text
Rahul%20Kumar
```

---

Common encodings:

|Character|Encoded|
|---|---|
|Space|`%20`|
|`#`|`%23`|
|`&`|`%26`|
|`?`|`%3F`|
|`/`|`%2F`|
|`=`|`%3D`|
|`+`|`%2B`|

---

# 14. Sending Encoded Data

Instead of manually encoding:

```bash
curl \
"https://example.com?q=Rahul%20Kumar"
```

Let `curl` do it:

```bash
curl \
-G \
--data-urlencode "q=Rahul Kumar" \
https://httpbin.org/get
```

This is safer and avoids encoding mistakes.

---

# 15. Query Parameters with `-G`

Normally:

```bash
curl \
https://httpbin.org/get?name=Rahul
```

Using `-G`:

```bash
curl \
-G \
-d "name=Rahul" \
-d "age=21" \
https://httpbin.org/get
```

Produces:

```text
https://httpbin.org/get?name=Rahul&age=21
```

---

# 16. Fragments (`#`)

Example:

```text
https://example.com/docs#installation
```

The fragment:

```text
#installation
```

is **not sent to the server**.

It is handled entirely by the browser.

So `curl` never sends fragments.

---

# 17. Redirect After Login

Typical flow:

```text
POST /login

↓

302 Found

↓

Location: /dashboard

↓

GET /dashboard
```

Many web applications behave this way after a successful login.

---

# 18. APIs and Redirects

REST APIs usually avoid redirects.

Instead of:

```text
302 Found
```

They often return:

```text
200 OK
```

or

```text
201 Created
```

or

```text
204 No Content
```

Redirects are much more common in websites than in JSON APIs.

---

# 19. Debugging Redirect Problems

Useful commands:

Show headers:

```bash

```

Follow redirects:

```bash
curl -L URL
```

Verbose mode:

```bash

```

Limit redirects:

```bash
curl \
-L \

```

# 💡 Pro Tips

### 1. Prefer `--data-urlencode`

Instead of manually replacing spaces with `%20`, let `curl` handle encoding:

```bash
curl \
-G \
--data-urlencode "search=Node.js & Express" \
https://httpbin.org/get
```

This correctly escapes all special characters.

---

### 2. Be careful with POST redirects

Some redirect codes (`301`, `302`, `303`) may change a `POST` request into a `GET`, while `307` and `308` preserve the original method. Understanding this difference helps explain unexpected server behavior.

---

### 3. Use verbose mode for redirect debugging

```bash
curl -Lv URL
```

Seeing each request and response in the chain is often the fastest way to identify redirect misconfigurations.
